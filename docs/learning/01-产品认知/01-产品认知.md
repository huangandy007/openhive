# 02 · 产品认知：opencode 是什么、解决什么问题

> 对应学习规划「层 0」。目标：不读代码，先建立「它是什么、为什么存在、怎么用」的心智模型。

---

## 一、一句话定义

opencode 是一个**开源的 AI 编程助手（AI coding agent）**。

你可以把它理解为「一位住进你代码仓库里的工程师」：你把它装到电脑上、在一个项目目录里启动，然后用自然语言（说人话）让它帮你读代码、写代码、改 bug、跑命令、解释某段逻辑。

它和 ChatGPT 网页版最大的区别是：**它不是聊天机器人，而是能"动手"的代理**——它真的能打开你的文件、编辑你的代码、执行命令、看到命令的输出结果，再据此继续干活。

---

## 二、它到底解决了什么痛点

想象一下程序员的两类累活：

| 累活 | 传统做法 | opencode 的做法 |
|---|---|---|
| 搞懂一个陌生代码库 | 你一行行读，花几小时 | 直接问：「这个项目的登录流程是怎么走的？」AI 读完秒答 |
| 改一个功能 | 改 → 跑 → 看报错 → 再改，反复循环 | 你说「加一个 xxx 功能」，AI 自己改文件、跑测试、看报错、再修 |
| 查一个 bug | 到处猜、打日志 | 你说症状，AI 顺着代码追根因并修掉 |

关键前提是：AI 必须被**「放进」你的项目环境**——知道有哪些文件、属于哪个 git 仓库、能执行哪些命令、文件在哪个目录。这正是 opencode 做的最核心的一件事：**给 AI 一个「工作目录」作为它的管辖范围和坐标原点**（详见 `01-学习规划.md` 第五节）。

---

## 三、它和同类工具的关系

| 工具 | 开源？ | 一句话定位 |
|---|---|---|
| Claude Code | ❌ 闭源 | Anthropic 的终端 AI 助手 |
| Cursor | ❌ 闭源 | 带 AI 的 IDE |
| **opencode** | ✅ **开源** | 可自由 fork、改造、私有化的 AI coding agent |

对我们来说，「**开源 + 可定制**」是决定性的一点——这正是我们能把它 fork 下来改造成私有产品 **openhive** 的根本原因。如果它是闭源的，一切无从谈起。

---

## 四、它长什么样（多端形态）

opencode 有多个「壳」，但**背后是同一个核心运行时**（`packages/opencode`）：

```
终端 TUI   ← 主要形态，终端里跑（用 opentui 组件库）
桌面应用   ← BETA（Electron 打包）
Web UI     ← 浏览器里跑（SolidJS）
```

理解这个「一个核心、多个壳」的结构很重要：以后你看到 `packages/app`（网页）、`packages/tui`（终端）、`packages/desktop`（桌面），会明白它们都只是**界面层**，真正的大脑在 `packages/opencode`。

---

## 五、三个必须知道的核心概念

用「公司里的员工」做类比，最好记：

### 1. Agent（代理 / 角色）

给 AI 设定的「职位 + 权限」，决定它能干什么、不能干什么。opencode 内置两种，用 `Tab` 键切换：

| Agent | 类比 | 能力 |
|---|---|---|
| **build**（默认） | 全能工程师 | 能读代码、改文件、跑命令，适合实际开发 |
| **plan** | 只读顾问 | 只能看代码、不能改文件，跑命令前要征得你同意，适合先探索再动手 |

另外还有一个 **general** 子代理，负责复杂搜索、多步任务，内部也在用，你可以在消息里输入 `@general` 手动调用它。

> 记住这个概念的分量：**Agent 是「权限」的载体**。后面学权限系统时，你会看到 agent 的规则如何被翻译成「允许/拒绝某个操作」的判断。

### 2. Session（会话）

你和 AI 的一次连续对话。像一条微信聊天记录，有自己的历史、上下文、状态。你每开一个新对话，就是新建一个 session。session 会被**持久化**（存进数据库，见 `01-学习规划.md` 第四节），所以关掉重开还能接着聊。

### 3. Provider（模型供应商）

AI 的「大脑」来源——OpenAI、Anthropic、Google，甚至本地模型。opencode 支持多家，可以切换，也可以为不同任务用不同模型。这层对应代码里的 `packages/llm` 和 `provider` 模块。

## 六、最小上手路径

```bash
# 1. 安装（任选一种）
npm i -g opencode-ai@latest        # npm
brew install anomalyco/tap/opencode # macOS/Linux 推荐
scoop install opencode              # Windows

# 2. 进入任意项目目录，启动
cd 你的项目
opencode

# 3. 直接说需求，AI 开始干活
# 「帮我看看这个项目的目录结构」
# 「加一个用户登录接口」

# 4. 按 Tab 在 build / plan 之间切换
```

> 建议：正式读源码之前，**真的去跑一天**，用它改几个文件、问几个问题。亲手用过之后，后面读代码时你会频繁产生「哦，原来这里就是干那件事的」的顿悟——这比硬读代码快得多。

---

## 七、对我们改造 openhive 的意义

1. opencode 的**架构是分层、可替换的**（界面 / 运行时 / 模型 都是解耦的），这正是我们能低成本改造的前提。
2. 我们所有学习的**终极目标**是「改它」：改名、品牌化、加私有能力。而这一切要建立在「理解它的每一层在干什么」之上。
3. 从产品认知到架构认知，再到改造，是一条完整的路径——本文件就是这条路的起点。
