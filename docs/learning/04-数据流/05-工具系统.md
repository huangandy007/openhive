# 04 · 数据流 · 工具系统（模型的「手」）

> 讲「模型要动手时」：模型返回 tool-call 后，工具如何被执行、结果如何写回会话、超长输出如何被截断。这是 opencode 能「真正改文件、跑命令」的关键。

---

## 一、同样有两套工具系统

和 session 一样，工具系统也有两套并存：

| | 核心 V2（`packages/core/src/tool/`） | opencode 主路径（`packages/opencode/src/tool/`） |
|---|---|---|
| 注册表 | `registry.ts` → `ToolRegistry.Service`（V2） | `registry.ts` → `ToolRegistry.Service` |
| 工具定义 | `tool.ts` 的 `Tool.make()` | `tool.ts` 的 `Tool.define()` / `Tool.init()` |
| 大小限制 | `tool-output-store.ts` | `truncate.ts` |
| 被谁消费 | V2 `session/runner/llm.ts` | 主循环 `session/prompt.ts` + `processor.ts` |

## 二、工具如何定义与注册

### 定义（以核心 V2 为例）

`packages/core/src/tool/tool.ts:71-132` 的 `make()`，运行时核心是 `settle()`（`:91-129`）：

1. `Schema.decodeUnknownEffect(config.input)` 校验入参（`:92`）
2. `config.execute(input, context)` 真正执行（`:95`）
3. `Schema.encodeEffect(config.output)` 编码输出（`:97`）

内置工具（read/write/edit/bash/glob/grep/webfetch/websearch/skill/todowrite/apply-patch/question）在 `builtins.ts:31-48` 组合注册，每个工具在自己的 `Layer.effectDiscard` 里 `tools.register({ [name]: Tool.make({...}) })`。例如 `read.ts:38-53`、`bash.ts:106-122`。

### 注册表（`registry.ts`）

- `register()`（`:85-105`）：校验名字 → 存入 `local: Map<name, Array<...>>`（同名工具用数组叠层，`at(-1)` 取最新）
- `materialize()`（`:106-122`）：合并内置 + 本地注册，按 `permission()` 过滤被 deny 的工具，产出 `definitions` 和 `settle` 闭包

## 三、执行入口：settleWith

`registry.ts:50-82` 的 `settleWith()` 是工具执行的编排入口：

1. 按 `call.name` 找注册，找不到/过期返回 `Stale/Unknown tool` 错误
2. 调 `settle(registration.tool, call, context)` 执行
3. 捕获 `LLM.ToolFailure` 转为 error result
4. 结果交给 `resources.bound(...)` 做**大小限制**
5. `ToolOutput.toResultValue(...)` 得到模型结果，组装 `Settlement`

---

## 四、模型返回 tool-call 后，如何对接

V2 路径（`runner/llm.ts`）：

1. `:203` `tools.materialize(...)` → `:212` 把 definitions 塞进 `LLM.request({ tools })`
2. `:232-275` 流式处理，遇到 `tool-call` 事件（`:243`）→ `toolMaterialization.settle(...)`（`:252-257`）
3. settle 结果通过 `publish(LLMEvent.toolResult(...))` 发布（`:259-268`）

opencode 主路径（`session/tools.ts:92-134`）类似：把工具转成 AI SDK 的 `tool({ description, inputSchema, execute })`，AI SDK 回调里（`:111`）真正执行，并触发 `tool.execute.before` / `tool.execute.after` 插件钩子。

## 五、结果如何写回会话

主路径的完整链：

```
模型返回 tool-call
  → AI SDK 调 tools[id].execute（session/tools.ts:99）
  → Tool.Def.execute（tool.ts:130）
  → truncate.output(...) 截断/写托管文件（truncate.ts:85）
  → 产出 tool-result 流事件（ai-sdk.ts:234）
  → SessionProcessor.handleEvent 的 tool-result 分支（processor.ts:383）
  → completeToolCall（processor.ts:160）
  → session.updatePart（session.ts:637）发布 PartUpdated 事件
  → 事件投影写回会话历史
```

## 六、大小限制 + 托管文件（Managed Tool Output File）

这是 `03-核心概念` 里「Model Tool Output / Managed Tool Output File」的落地：

`packages/core/src/tool-output-store.ts`：
- 常量：`MAX_LINES = 2_000`、`MAX_BYTES = 50 * 1024`（约 50KB）、`RETENTION = 7 天`、目录 `tool-output`（`:13-17`）
- `bound()`（`:138-174`）：超限则 `write()` 写托管文件（文件名 `tool_${Identifier.ascending()}`），生成「头部 + 尾部」预览，marker 提示「... output truncated; full content saved to <path> ...」
- `cleanup()`（`:176-189`）：每小时清理超过 7 天的文件

`packages/opencode/src/tool/truncate.ts` 是主路径的同款实现，逻辑几乎一致（`MAX_LINES=2000`、`MAX_BYTES=50*1024`）。

> 通俗理解：工具输出（比如 `cat` 一个巨大日志文件）如果完整塞进会话历史，会撑爆上下文。所以**历史里只留「头尾预览 + 文件路径」**，完整内容存临时文件，7 天后自动清理。

---

## 七、小结

工具系统是 opencode「能动手」的核心：

```
模型说「我要用 read 读某文件」
  → 注册表按名字找到工具 + 按权限过滤
  → settleWith 校验入参 → 执行 → 编码输出
  → 结果超限则截断 + 存托管文件
  → 结果作为 tool-result 事件流回 session
  → 写回会话历史，模型继续下一轮
```

至此，「层 3 数据流」的完整闭环已经走通：**输入 → 准入/唤醒 → drain → provider turn → 工具执行 → 结果写回 → 下一轮**。
