# 03 · 核心概念 · 工作目录（Location / Project / Workspace）

> 这是 opencode 数据模型最底层的三个概念，回答一个根本问题：**「AI 在哪个目录、哪个仓库、哪个隔离区干活？」** 它是理解权限、数据归属、会话定位的钥匙。

---

## 一、三个概念，一张图

```
Location（位置）    ── 一个请求「发生在哪个目录」   { directory, workspaceID? }
   │  解析：project.resolve(directory)
   ▼
Project（项目）     ── 该目录属于哪个 git 仓库      { worktree, vcs }
   │  隔离：workspace
   ▼
Workspace（工作区） ── 仓库内哪个分支/沙箱          { type, branch, directory }
```

---

## 二、逐层拆解

### 1. Location（位置）—— 最底层的「坐标」

代码：`packages/schema/src/location.ts` + `packages/core/src/location.ts`

```ts
Location.Ref  = { directory: 绝对路径, workspaceID?: string }
Location.Info = { directory, workspaceID?, project: { id, directory } }
```

核心逻辑在 `core/src/location.ts:24`：`project.resolve(ref.directory)` —— **给定一个目录，解析出它属于哪个 project**。

Location 是「作用域」（scope）：AGENTS.md 明确要求 session 运行器、工具注册表、权限、文件系统全部 **Location-scoped**。也就是说，同样一个操作，在不同的 Location 下，它的权限、可访问的文件、所属项目都不同。

### 2. Project（项目）—— 数据归属的锚点

一个 git 仓库 = 一个 project。核心字段（`core/src/project/sql.ts`）：

- `worktree`：git 仓库根目录
- `vcs`：版本控制系统（git）
- 其它：name、icon、sandboxes、commands

**Project 是数据模型的锚点**：`session`、`permission`、`workspace` 表都 `references project`，一切数据都挂在某个 project 下。`project_directory` 表还支持一个 project 映射多个目录（`main`/`root`/`git_worktree` 三种类型）。

### 3. Workspace（工作区）—— project 内的隔离单元

`core/src/control-plane/workspace.sql.ts`：

- `type`、`name`、`branch`、`directory`、`project_id`

Workspace 是 project 内更细的隔离：不同分支、不同沙箱环境各是一个 workspace。session 表同时有 `project_id` 和 `workspace_id` 两列，说明一次会话既属于某个项目，也属于该项目下的某个隔离区。

---

## 三、为什么必须有「工作目录」

AI 编程工具的本质是「AI 替你在某个代码仓库里干活」，所以必须回答四个问题：

| 问题 | 答案靠什么 |
|---|---|
| ① **权限边界**：AI 能读写哪些文件？ | `directory`/`project` 决定，权限按 `project_id` 存 |
| ② **git 归属**：改动落到哪个仓库/分支？ | `worktree`（project）+ `branch`（workspace） |
| ③ **数据归属**：这段对话算谁的？ | session 用 `project_id` + `workspace_id` + `directory` 三列锚定 |
| ④ **上下文正确性**：「打开 src/index.ts」是哪个项目的？ | Location 是相对路径的解析基准 |

一句话：**工作目录 = AI 的「管辖范围」和「坐标原点」。** 没有它，AI 就不知道自己在哪个仓库、能碰什么、产出归谁。

## 四、落到代码/数据库的证据

| 概念 | 代码/表 |
|---|---|
| Location 解析 | `core/src/location.ts:24` 的 `project.resolve(directory)` |
| Project | `project` 表（`core/src/project/sql.ts`）+ `project_directory` 表 |
| Workspace | `workspace` 表（`core/src/control-plane/workspace.sql.ts`） |
| Session 锚定 | `session` 表三列：`project_id`、`workspace_id`、`directory` |
| HTTP 层落地 | `workspace-routing.ts` 中间件（每个请求先路由到所属 workspace） |

> 关联阅读：`04-数据流/02-入口与HTTP路由.md` 里的 WorkspaceRoutingMiddleware，就是这里的概念在 HTTP 层的落地。
