# 探讨（Discussions）

本目录存放**专题探讨类文档**——区别于 `specs/` 里的正式设计文档，这里记录的是对某个设计点的**深入答疑、机制推敲、误区纠正**。

## 与 specs/ 的区别

| | `specs/`（正式设计） | `探讨/`（本目录） |
|---|---|---|
| 性质 | 成体系的设计结论，可执行 | 针对单点的深入探讨、答疑、纠错 |
| 语气 | 结论式 | 推敲式（问→答→修正） |
| 落点 | 直接指导实现 | 沉淀后，实质性修正会回写进 specs |

## 分门别类（按主题建子目录）

用到哪个主题就建哪个子目录，不预先铺空目录：

| 子目录 | 内容 |
|---|---|
| `对标研究/` | 竞品分析、开源项目拆解、行业对标 |
| `视觉规范/` | 蜂巢自己的设计规范、品牌色、字体、组件样式 |
| `知识沉淀/` | 老民警经验如何沉淀为 skill、分析记录、组织增智 |
| `产品定位/` | 平台定位、范式纠偏、全流程 vs 单环节 |
| `架构技术/` | 多租户、沙箱、模型网关、capability 等 |
| `前端交互/` | 三栏心智、中栏内容工作区、交付层交互 |
| `数据安全/` | 数据接入、脱敏、RBAC/RLS、审计 |
| `资产治理/` | Skill/MCP/知识库的治理、生命周期、审核 |

## 命名规范

`YYYY-MM-DD-<主题>-<一句话>.md`，例如 `2026-09-06-老民警经验如何沉淀为skill.md`。
