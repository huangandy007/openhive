# 老民警经验如何沉淀为 skill：一条链路的四个坎

- **日期**：2026-09-06
- **状态**：探讨记录（实质性修正已回写总体设计 §10 / §11.4 / §11.5）
- **主题**：总体设计里「分析思路/分析结论是一等公民，老民警的思路能沉淀供新人对照」——这句话听起来对，但「老民警 → 分析思路 → 结论 → 方法 → skill → 上线授权」这条链路上，藏着四个未经审视的坎
- **触发问题**：谁是老民警？怎么知道他是怎么分析的？他的结论就一定正确吗？如何沉淀成方法？如何做成 skill、上线、管理、授权？

---

## 0. 总体判断

「分析记录 → 沉淀为 skill → 供新人复用」这条链路，**方向对（这是护城河），但机制上有一个危险的乐观假设——「好经验会自动浮现、且会自动正确」**。

下面的四个坎，前四个的难度远大于「做成 skill」这一步。做成 skill 反而是最成熟的（已有 §11 治理框架）。

---

## 1. 谁是「老民警」？——资历不是质量标签

「老民警」这个词隐含一个错误前提：**存在一个天然可识别的、经验必然可靠的人群**。

真实情况：
- 「老民警」只能作为**候选池的筛选条件**（资历深 → 大概率有货），**不能作为「经验可信」的充分条件**。
- 资历深 ≠ 分析对。有些老民警是「熟练的错」，有些是「只会一套老办法」。

**结论**：真正的问题不是「谁是老民警」，而是「什么算值得沉淀的好分析」。而公安研判里，「好」的验证是滞后、稀疏的。

## 2. 他的结论一定正确吗？——不，而且常常无法验证

这是最凶险的一步。

- 研判结论的「正确性」在多数场景下**没有即时反馈**：破了 ≠ 分析对（可能是运气），没破 ≠ 分析错（可能是资源/时机）。
- 如果「以结论正确来 gate 经验」，会陷入两个陷阱：
  1. **幸存者偏差**——沉淀下来的都是「恰好破了的」，但破的原因未必是分析好；
  2. **错把个案当规律**——一次蒙对，被当成可复用的方法。

**结论**：结论正确性**不能作为沉淀的门槛**。能作为门槛的是——过程质量（分析是否完整、自洽）、同行评议（懂行同事认不认）、使用反馈（出错率、被纠错次数）。

> 一句话：**别问「他结论对不对」，要问「这个套路经不经得起同行和反复使用」。**

## 3. 怎么知道他是怎么分析的？——AI 捕获不到脑内思考（最大的坑）

这是整条链路里最脆弱的一环。

**AI 只能捕获「可观测的行为」，捕获不了「脑内的思考」。**

- 可观测（AI 拿得到）：勾了哪些数据、用了哪个 skill、问了 AI 什么、AI 回了什么、人把 AI 结论改成了什么样、最终定稿是什么。
- 不可观测（AI 拿不到）：他为什么**先看通话频次而不是先看资金**、瞥到某个数据时心里那个「不对劲」的判断、否掉 AI 某个结论时真正的理由。

**「AI 边分析边归纳分析思路」在「自动归纳」的意义上是危险的**——AI 归纳出来的是「行为痕迹的合理猜测」，不是「人的真实思路」。这条路走下去，沉淀出的会是「看似有理、实则是 AI 脑补」的伪经验。

**真正的「分析思路」必须由人主动讲出来**，通过一个轻量的「复盘」动作：

> 结案 / 告一段落时，让民警用三句话讲清楚：① 我先看了什么、为什么先看它；② 我发现了什么关键点；③ 我据此得出了什么判断、还差什么没查。

这三句话，AI 只负责**结构化、补充、归档**，**源头必须是人**。这才是「组织增智」的真实抓手——老民警的脑子在表达，而不是被 AI 猜测。

## 4. 如何沉淀成方法？——个案 ≠ 方法，隔着一道「抽象」的坎

一份分析记录是**个案**，skill 需要的是**可泛化的套路**。

- 「8·17 专案先查了主叫频次」是**案例**；
- 「遇到电信诈骗话单，先锁定高频主叫、再追资金、再串同伙」是**方法**。

**单案例直接变 skill 是错的。** 正确路径：

> 积累 N 个同类案例 → 提炼共性（需要人的专业判断，AI 辅助）→ 人确认「这个套路可泛化」→ 才做成 skill。

「一键沉淀为 skill」可以保留，但它产出的是**草稿候选**，不是成品 skill——候选要经过「有没有同类案例支撑」这道抽象检验，才谈得上发布。

## 5. 如何做成 skill、上线、管理、授权？——最成熟的一步，但补两个关键点

前四道坎过了，这一步总体设计 §11 已有完整机制（三种制作方式、状态机、三级空间、四类权限、业务审核与 IT 分离、启用=授权）。**但要补两个缺失的关键点**：

1. **skill 必须有「不确定性标注」**：每个 skill 的说明页明确写「AI 可能在哪些地方不准、必须人工复核什么」。老民警的方法不是真理，skill 更不能当真理发布——要把「哪里会错」显式写出来，而不是给新人一个「一键出正确结论」的幻觉。

2. **skill 必须有「纠错通道」**：发布后若发现会误导，要能快速下线、标记、迭代。使用数据（出错率、被纠错次数、低分反馈）反过来决定 skill 的存废。**一个 skill 的「权威性」是挣来的，不是发布时就有的。**

---

## 6. 结论：这条链路的正确打开方式

关键翻转：**从「AI 自动把老民警的经验榨出来」，翻转为「老民警主动讲、AI 辅助结构化、同行评议把关、使用数据反哺」**。「老民警」的角色不是「被抽取的对象」，而是「主动的知识贡献者 + 审核者」。

```
人主动复盘（讲思路，不是 AI 猜）
   → AI 结构化归档为「分析记录」
   → 积累多个同类案例
   → 人工提炼共性 → 确认「可泛化」
   → 生成 skill 草稿候选
   → 业务专家审内容 + IT 审技术 → 发布
   → 带「不确定性标注」上架
   → 授权使用 → 使用反馈/纠错 → 迭代或下线
```

---

## 7. 回写总体设计的实质修正（4 点）

1. 「老民警」从「质量标签」改为「候选池标签」；
2. 「AI 自动归纳分析思路」改为「人主动复盘 + AI 结构化」；
3. 「一键沉淀 skill」改为「多案例归纳 + 人工确认才发布，单案例只出草稿候选」；
4. 补「不确定性标注」和「纠错通道」两个机制。
