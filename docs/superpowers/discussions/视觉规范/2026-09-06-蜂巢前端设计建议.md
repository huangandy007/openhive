# 蜂巢 OpenHive 前端设计建议

- **日期**：2026-09-06
- **状态**：存档
- **主题**：综合 Cloudflare OS（专业克制）与千问办公（对话优先）两对标，落到蜂巢自己的前端设计规范
- **关联**：`对标研究/2026-09-06-cloudflare-os 前端设计风格拆解.md`、`对标研究/2026-09-06-千问办公 前端设计风格拆解.md`

---

## 0. 一句话定位

**取 Cloudflare 的「专业克制」，取千问的「对话优先」，用「蜂蜜金 + 六边形」立蜂巢自己的识别度，面向不懂代码的民警，做「政务专业感」。**

| 来源 | 借鉴什么 | 为什么适合蜂巢 |
|---|---|---|
| Cloudflare OS | 六边形品牌、暖白底、单一品牌色纪律、克制圆角 | 政务专业、稳重、可信 |
| 千问办公 | 对话优先（Hero 输入）、冷启动引导、阴影分层 | 民警不懂代码，要「让他开口」而非「给他工具」 |
| 蜂巢自己 | 蜂蜜金品牌色、六边形蜂巢 logo、深色登录背景 | 品牌识别度、命名呼应 |

---

## 1. 设计哲学

蜂巢的用户是**民警（非技术）**，场景是**公安全流程工作平台**，调性介于两者之间：

- 不能像 Cloudflare 那么「工程师硬朗」（民警看不懂 Workers/KV）；
- 不能像千问那么「纯亲和」（政务场景要专业、可信）；
- 落点 = **政务专业感**：稳重、可信、克制，但入口友好、对话优先。

---

## 2. 品牌色：蜂蜜金（不是 Cloudflare 橙，也不是千问的无色）

蜂巢 = 蜂蜜 = **琥珀金**，这是命名自带的天赋，必须用上，这也是「识别度」的来源。

| 用途 | 色值 | 说明 |
|---|---|---|
| **主品牌色（logo/图标/高亮/链接）** | `#D97706`（amber-600） | 蜂蜜金，呼应「蜂巢」 |
| 品牌深金（渐变端点/hover） | `#B45309`（amber-700） | 深一档，增强层级 |
| 品牌浅金（高亮底/选中态） | `#F59E0B`（amber-500） | 做浅底、标签 |
| 主背景 | `#FCFCFC`（暖白） | 借 Cloudflare 的暖白，专业 |
| 主文字 | `#1C1A18`（暖黑） | 借 Cloudflare，高对比 |

**关键决策——CTA 别用金色底白字**：

Cloudflare 橙底白字对比度只有 3.3:1（拆解里标过这是它的 Cons）。金色比橙色更亮，白字对比度更低。所以：

- **主 CTA 按钮用暖黑底 `#1C1A18` + 白字**（对比度 ≈ 15:1），品牌金只做 logo、图标、高亮、链接、选中态。
- 这样既保住「蜂蜜金」的品牌识别，又规避「金底白字看不清」的坑。

---

## 3. 字体：PingFang / YaHei 系统栈

按用户要求，不用 Google Fonts（内网不通）、不用纯拉丁字体（不管中文）：

```css
font-family: -apple-system, "PingFang SC", "Microsoft YaHei",
             "Noto Sans CJK SC", "Source Han Sans SC", sans-serif;
```

- macOS 落苹方，Windows 落微软雅黑，内网零加载成本。
- **删除 front 里现有的 Google Fonts `@import`**（`index.css` 第 1 行），那是内网死代码。

---

## 4. Logo 定稿

> 本节为已定稿的 logo 规范，三个 SVG 文件与本目录同层：`logo-mark.svg`（图形标）、`logo-light.svg`（浅色底完整版）、`logo-dark.svg`（深色底完整版）。front 里旧的 `OpenHiveLogo.tsx`（六边形 + 网格 + 蜜蜂翅膀线）已被本定稿取代，待替换。

### 4.1 图形标（logo-mark.svg）

- 构成：**外六边形描边 + 中心实心渐变蜂窝**，两个元素，极简。
- 外六边形：蜂蜜金描边 `#D97706`，上下尖朝向（flat-top），**等边六边形，六条边严格等长**。
- 中心蜂窝：渐变填充 `#F59E0B → #B45309`。
- **变形教训（重要）**：六边形顶点必须用程序精确计算（`cos/sin` 按 60° 取点），**不能手写坐标取整**——手写取整（如把 `54.5,19` 写成 `52,17`）会破坏等边、产生肉眼可见的变形。

### 4.2 文字标（logo-light / logo-dark）

- 构成：**「OpenHive」粗体 + 「蜂巢」圆角标签**。
- 「OpenHive」：24px / 700 字重，垂直居中。
- 「蜂巢」标签：圆角背景框（浅金底 `#F59E0B` 低透明度 + 深金字 `#D97706`），**「蜂巢」二字在框内水平 + 垂直居中**。
- **间距规范**：标签框与 OpenHive 末尾字母间隔 **2mm（约 8px）**。
  - ⚠️ SVG 里文字宽度随字体渲染浮动，无法精确保证 2mm；**转 React 组件后必须用 flexbox `gap: 8px` 精确控制**，不再靠 SVG 硬编码坐标。

### 4.3 双色版本（对应 §5 双色策略）

| 文件 | 用途 | 差异 |
|---|---|---|
| `logo-light.svg` | 主界面、浅色背景 | 「OpenHive」暖黑 `#1C1A18`，外六边形描边 `#D97706` |
| `logo-dark.svg` | 登录页、深色背景 | 「OpenHive」白字，外六边形描边 `#F59E0B` |

### 4.4 六边形的延伸使用

1. **登录背景用六边形网格纹理**：登录页深色背景可换成**六边形网格**（重复六边形 outline，低透明度金色），一眼就是「蜂巢」，比通用点阵更有辨识度。
2. **六边形出现在「加载/生成」态**：右栏 AI 生成时用旋转的六边形蜂巢图标。
3. **图标角标/徽章用六边形轮廓**：项目图标、资产图标用六边形轮廓包裹，形成统一的「蜂巢」视觉语言。

## 5. 登录页 vs 主界面：双色策略

| | 登录页 | 主界面 |
|---|---|---|
| 背景 | **深色**（`#0F172A` 深蓝黑 + 六边形网格 + 金色光晕） | **暖白**（`#FCFCFC`） |
| 作用 | 第一印象 = 科技感 + 蜂巢品牌 | 长时间工作不累眼 + 专业 |

**为什么这么分**：登录页只停留几秒，深色能瞬间传达「蜂巢的科技感」；主界面要长时间盯着干活，必须浅色护眼。这是「深色做门面、浅色做工作」的成熟做法。

---

## 6. 主界面三栏

| 栏 | 职责 | 视觉建议 |
|---|---|---|
| 左栏（导航） | 案件/文件树/会话 | 浅灰底或白底，13px 小字，弱化 |
| 中栏（看改：内容工作区） | 看结果、改结果 | **白底卡片 + 柔和阴影**（借千问的阴影分层），内容为主 |
| 右栏（AI 会话） | 让 AI 干活 | 借千问的「对话优先」，输入框做视觉中心 |

**圆角策略**（调和两者）：Cloudflare 8px 太硬、千问 24px 太软，蜂巢取中间——**卡片/输入框用 12~16px 圆角，按钮用 8~10px**。既专业又不生硬。

## 8. 可访问性（借两者的优点，避两者的坑）

| 项 | 目标 |
|---|---|
| 正文对比度 | ≥ 15:1（暖黑对暖白，借两者优点） |
| CTA 对比度 | 用暖黑底白字，避开「金/橙底白字」的低对比坑 |
| 焦点状态 | **补明确的 focus ring**（蜂蜜金描边），避 Cloudflare 的坑 |
| 不依赖颜色 | 状态提示配图标/文字，不只靠颜色 |

## 一句话总结

> **蜂巢 = 蜂蜜金 × 六边形 × 暖白专业风。** 借 Cloudflare 的克制与专业（暖白、单一品牌色、克制圆角），借千问的对话优先与阴影分层（Hero 输入、卡片浮起），再用「蜂蜜金 + 六边形」立起别人抄不走的识别度，面向民警做「政务专业感」。
