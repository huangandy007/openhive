# 事实卡片 P2：资金翻译规则与账户归并 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让表格来源的资金流水第一次产出**卡片层**（`case_event` + 参与者 + 实体 + 别名 + 关系 + 实体属性），使「按账号查、按对手方汇总、银行卡/开户行可答」在库里有数据可读。

**Architecture:** 在现有「明细行」与「读端」之间插入**翻译层**：`翻译资金(明细行) → {卡片, 别名, 属性, 跳过}` 是纯函数（可离线单测），写入走在 `跑表格` 的同一事务里（批量多值 INSERT，一份材料一个事务，500 行一批）。关系不单独记账，**从卡片重建**（§4.0.4）：每次重算受影响的 `(付款方, 收款方)` 对，避免重放算重。映射（哪列填哪格）落 `case_card_template` 的内置行，算法（方向/时间/金额/单位）留在代码里。

**Tech Stack:** Bun 1.4.2 · TypeScript 5.8 · drizzle-orm（`sql` 模板 + `rowsOf`）· PG（auth schema，`packages/auth/src/migrations/*.sql`）· `bun test`（受影响 package 内跑）· oxlint。

**Spec:** `docs/superpowers/specs/2026-11-09-事实卡片抽象/01-事实卡片与数据翻译-设计.md`（§3.2 / §3.3 / §3.5 / §3.7 / §3.8 / §3.9 / §3.10 / §4.0–§4.6 / §12.1 的 P2 行 / §14.1 的 Q13–Q18）。配套过程文档：`过程文档/05-实体属性标记与入库规范.md`。

## Global Constraints

以下每一条对所有任务生效，任务内的要求隐含包含本段。

**数据与安全**
1. **全程明文**：账号、身份证、手机号、姓名、金额一律原样落库，不做掩码、不做脱敏。本系统不产生掩码；源文件**自带**的掩码（`6222****1234`）按第 6 条处理。
2. **单位 / 方向 / 时间一律 fail-closed**（§4.4）：单位换算**不在翻译层做**——非默认单位的列在识别层已被 `单位闸放行` 拒绝（`case-field-registry.ts:290`，`#011-02`），翻译层只消费明细行里已解析好的值。方向不在映射表内 ⇒ 该行不出卡片并计数。时间只认 `case-time.ts` 的 `parseTime` 结果。
3. **金额永远正数**（§4.0.5 坑 2）：方向只体现在参与者的 `role` 上，`case_event.amount` 与 `case_relation.amount` 都不存负号。

**落库与重放**
4. **一份材料一个事务、500 行一批**（§4.0.1 / §6.5）。批量写不许多值一次超过 500 行 × 列数（PG 绑定参数上限 65535）。
5. **实体去重必须走内存 `Map`**（§4.0.3c）：一份材料的同一账号只查库一次。这是硬要求，不是优化。
6. **源文件自带掩码 / 位数不足的账号不建实体**，卡片照出、`mention_text` 保留原文（§4.0.5 坑 1）。判据是归一化后不满足 `/^\d{6,32}$/`。
7. **关系从卡片重建**（§4.0.4）：只重算本次受影响的 `(付款方, 收款方)` 对；先删机器态（`自动抽取`/`存疑`）再按卡片聚合，**不累加**。已有 `已确认`/`已修正` 的关系对整对跳过（防人工结论被机器行叠加成双份）。
8. **重放清理顺序**（`#007-02`、`case-fact-store.ts:160`）：`删除本材料的事实` → 参与者按事件级联 → 别名按 `material_id` 撤销 → 卡片/参与者/出处重写 → 关系重建 → 属性按内嵌 `出处` 前缀剥离后重写。反序会留下孤儿或按已删事实找不到该清的行。

**A 档拍板（§14.1 Q13–Q18，结论带进计划，不改设计文档）**

9. **Q13 卡片 id 去版本**：`id = Hash.sha256([project_id, material_id, sheet, String(row_no), 槽].join("\u0000")).slice(0, 32)`。版本不进 id，进 `case_event.template_id` 与模板行 `version`。重放靠 `case_citation(material_id, locator)` 定位人工结论（P3 卡片读端才有人工结论可迁，本期只保证 id 稳定）。
10. **Q14 来源键总规**：凡「由某材料产生」的行都必须能按材料清除——别名按 `material_id` 撤销（`revoked_at`），参与者随事件级联，`case_entity.attrs` 按内嵌 `出处` 前缀 `<material_id>#` 过滤。
11. **Q15 模板闸落字段**：`case_event.template_id text`，代码规则填内置模板行 id `内置:资金/v1`（该行 `verified_at` 非空 = 已验证）。AI 默认查询的过滤属 P4，本期不写查询侧。
12. **Q17 事件类型词表**：新增第四份代码常量词表 `case-event-types.ts`（资金交易 / 通话 / 消费 / 乘车 / 乘机 / 住宿 / 见面 / 抓获 / 其他）。不写数据库 CHECK——与角色词表同一条纪律（§3.3：会增长的业务集合不进迁移）。
13. **Q18 槽位种类硬校验**：`校验槽位种类()` 在保存前判「哪个槽能收哪类字段」，返回错误清单；「预览前 20 行」只是第二道。本期由内置模板自检 + 单测覆盖，P4 编辑器复用它。

**本期拍板的实现细节（设计文档未逐字写明，理由随列）**

14. **`case_event.currency`**（新增列，`text NOT NULL DEFAULT 'CNY'`）：Q16 要求外币行不进人民币合计，而卡片层没有任何币种落点；关系聚合若看不到币种，USD 100 会混进 CNY 合计（汇率级静默错，`#011-02` 同一条前提，`#002-06` 同一判据别两处各写）。因此币种随卡片落库，关系只聚合 `currency='CNY'` 的卡片，未计入张数写进 `parse_detail`。
15. **内置模板行按项目懒建**：`case_card_template` 主键是 `(project_id, id)`，全局迁移写不出「每个项目一行」。首次翻译某项目的资金材料时幂等 upsert 一次（`确保内置模板`）。内置行不可由用户改——P4 编辑器按 id 前缀 `内置:` 拒绝，本期没有编辑入口。
16. **跳过原因只有六类**（§4.6 的例子清单被收敛）：`空行` / `合计行` / `小计行` / `方向不明` / `金额无法解析` / `时间无法解析` / `缺本方账号` / `缺对方账号`。**不单独判「重复表头行」**：它必然落进「时间/金额无法解析」，另造一个判据只会制造误判。跳过行号全量落 `parse_detail`（要能点开看是哪几行）。
17. **不新建「事件时序」与「地址归一」**：`case_event_relation`（§3.4）属 P3，`case_ai_proposal` 跨源候选（§4.0.5 坑 4）属 P2.5 之后。
18. **中文命名沿用本目录风格**（`case-rows.ts` / `case-ingest.ts` 的既有做法）：新模块的导出函数、接口、局部变量用中文名，SQL 列名与表名用英文。
19. **不在本包引入新依赖**；夹具用 `xlsx`（已在 devDependencies）或纯 JSON。

**测试与门禁**
20. 每个任务在 `packages/opencode` 内跑**具名测试文件**；根目录 `bun test` 禁止。每条命令都带 `timeout 300`，退出码 124 = BLOCKED，**不自动重跑**。
21. 收尾门禁（在仓库根）：`bun run typecheck` ＋ 受影响测试 ＋ `bun run lint`（oxlint）。三条都要有实际输出。
22. 变异验证按 `#003-03` 记录：拆掉修复后哪条用例红、红在什么断言上。

```ts
export type 属性归属 = (typeof 属性归属们)[number]

  归属: 属性归属
  键: string

/**

 * 全角写法不进属性、进「未认出」——用户看得见、能改，不会静默丢。
 */
const 属性列形状 = /^属性:(对方|本方):(.+)$/

export function 解析属性列(表头: string | null): 属性列 | undefined {
  const m = 属性列形状.exec((表头 ?? "").trim())
  if (m === null) return undefined
  const 键 = (m[2] ?? "").trim()
  if (键 === "") return undefined
  return { 归属: m[1] as 属性归属, 键 }
}

export function 是属性列(表头: string | null): boolean {
  return 解析属性列(表头) !== undefined
}
```

```ts
/**
 * 槽 → 允许的字段种类（Q18）。
 *
 * - `何时` / `何时止` 只收时间类：时间列放进别的槽，等于绕过 `parseTime` 的精度与
 *   UTC+8 处理（§4.4）；放进「其他」同样不行，见 `其他拒收种类`。
 * - `多少钱` 只收金额类：余额（`balance`）塞进来就是把余额当金额（§4.7.5 最后一行）。
 * - `何地` 只收地点类：商户归「组织 / 地点」有判据（§3.5），`merchant` 不是地点。
 * - `谁` / `和谁` 收标识类（账号 / 号码 / 户名 / 文本），`和谁` 另收 `商户`：§3.5 的类型 × 九格表
 *   明列「订餐：和谁 = 组织（商户）」「扫码支付：和谁 = 账户 / 商户」，漏了它 Q18 硬校验会把
 *   设计自己的订餐模板挡在保存前。
 *
 * `其他` 恒为空数组（类型上不能省），判定见 `其他拒收种类`。
 */
const 槽允许种类: { readonly [K in 槽]: readonly 字段种类[] } = {
  谁: ["账号", "号码", "户名", "文本"],
  和谁: ["账号", "号码", "户名", "文本", "商户"],
  何时: ["时间"],
  何时止: ["时间"],
  何地: ["地点"],
  多少钱: ["金额"],
  其他: [],
}

/**
 * 「其他」拒收的算法类字段（§4.7.5 的四类不许配里，落「其他」会坏事的三种）。
 *
 * - `时间`：绕过 `parseTime` 的精度与 UTC+8（Q18 的证据原话就是这一条）。
 * - `方向`：借贷方向丢失，收付判反（§4.7.5 第二行）。
 * - `金额`：汇总只读 `case_event.amount`，落「其他」= 静默不进任何合计（§4.3.1 C2）。
 *
 * **`时长` 与 `余额` 刻意放行**，不是漏了：
 * - 设计 §4.7.2 的话单模板示例写的就是 `"其他": { "时长": "durationSec" }`——`durationSec`
 *   落标准列。按「只收 extras」判会把它判成非法，等于否掉设计自己的示例；
 * - 内置资金模板把 `balance` 放「其他」，只展示、不参与合计，不会像放进「多少钱」那样
 *   被当金额（§4.7.5 最后一行）。
 * - 单位闸（`单位闸放行`）在**识别层**按字段判，与槽位无关，所以这两个字段进「其他」
 *   不会绕过单位换算。
 *
 * 判据按**字段种类**而不是落点：`address` 落 extras 却是地点类、`balance` 落标准列却要
 * 进「其他」，只看落点两头都判错。
 */
const 其他拒收种类: readonly 字段种类[] = ["金额", "时间", "方向"]

function 填法们(值: 槽填法 | readonly 槽填法[] | null | undefined): readonly 槽填法[] {
  if (值 === null || 值 === undefined) return []
  // 用 `in` 判单值形态：`Array.isArray` 不把 readonly 数组从联合里摘掉，false 分支仍需强转，
  // 会触发 `no-unsafe-type-assertion`。槽填法的判别键就是 `字段`，`in` 恰好能收窄。
  return "字段" in 值 ? [值] : 值
}

/** 返回错误清单（空数组 = 通过）。错误串带槽名与字段名，直接能展示给配置的人。 */
export function 校验槽位种类(槽位: 模板槽位): string[] {
  const 错: string[] = []
  for (const 槽名 of 九格们) {
    for (const 填 of 填法们(槽位[槽名])) {
      const 字段 = 填.字段
      if (!是识别字段(字段)) {
        错.push(`「${槽名}」的字段 ${String(字段)} 不在字段词表里`)
        continue
      }
      const 种类 = 字段目录[字段].种类
      if (槽名 === "其他") {
        if (其他拒收种类.includes(种类)) 错.push(`「其他」不收 ${种类} 类字段（${字段}）`)
        continue
      }
      if (!槽允许种类[槽名].includes(种类))
        错.push(`「${槽名}」不收 ${字段目录[字段].种类} 类字段（${字段}）`)
    }
  }
  return 错
}

/**

 * 判断「这批卡片是哪版映射产的」（Q13：版本不进卡片 id，进模板行）。
 * `verified_at` 一经写定不覆盖——内置行天然已验证，别让重跑把它清空。
 */
export async function 确保内置模板(db: Queryable, projectId: string): Promise<string> {
  const 槽位 = JSON.stringify(资金模板插槽)
  const 必需 = [...资金模板必需槽]
  await db.execute(sql`
    insert into auth.case_card_template
      (id, project_id, name, event_type, slots, required, version, verified_at, hit_count, created_at)
    values (${资金模板id}, ${projectId}, '资金（内置）', '资金交易',
            ${槽位}::text::jsonb, ${sql`array(${sql.join(必需.map((r) => sql`${r}`), sql`, `)})`},
            1, ${nowSeconds()}, 0, ${nowSeconds()})
    on conflict (project_id, id) do update
       set slots      = excluded.slots,
           required   = excluded.required,
           version    = auth.case_card_template.version
                        + case when auth.case_card_template.slots is distinct from excluded.slots then 1 else 0 end,
           verified_at = coalesce(auth.case_card_template.verified_at, excluded.verified_at)
  `)
  return 资金模板id
}

/** 读回模板行（P4 编辑器与验收要用；本期只有测试用）。 */

        from auth.case_card_template
       where project_id = ${projectId} and id = ${id}
    `),
  )

}
```

```ts
 * **纯函数**：不碰库、不读时钟、不调模型。所有「能不能建实体」「方向怎么映射」「时间认不认」

export const 跳过原因们 = [
  "空行",

  "小计行",
  "方向不明",
  "金额无法解析",

/**
 * 卡片 id（Q13：**去版本**）。
 *
 * 原来 §3.7 写「id 含规则版本与模板版本」，那会让每次改规则都换一批 id，而人工确认过的
 * 旧卡不在 `删除本材料的事实` 的删除范围（它按 `fact_id` 判、只删机器态）⇒ 同一行材料
 * 留下两张卡。拍板改为：id 只由来源键（材料 + 表 + 行号 + 槽）决定，版本进
 * `case_event.template_id` 与模板行 `version`；重放靠 `case_citation(material_id, locator)`
 * 定位人工结论。槽是给「一行多卡」的类型（住宿的入住/退房合成）留的判别位。
 */
export function 卡片id(projectId: string, materialId: string, sheet: string, rowNo: number, 槽: string): string {
  return Hash.sha256([projectId, materialId, sheet, String(rowNo), 槽].join("\u0000")).slice(0, 32)
}

/**
 * 实体缓存键：`账户\u0000<规范值>`。
 *
 * 三处要用（写入器建 Map、关系重建取 id、属性按实体分组）——**只此一份**（`#002-06`）。
 * 各写一遍字面量，改了键格式却漏改一处，表现是「实体建了但关系/属性静默丢失」，
 * 而且测试各自只覆盖自己那条路径，谁也发现不了。
 */
export function 账户键(规范值: string): string {
  return `账户\u0000${规范值}`
}

/** 合计/小计行：银行导出的这类行把标记写在对户名或备注里。整格匹配，不做子串匹配。 */
const 合计形状 = /^(合\s*计|本页合计|合\s*计金额)/
const 小计形状 = /^(小\s*计|本页小\s*计)/

function 文本值(row: FactRowInput): string[] {
  const 值: (string | null | undefined)[] = [
    row.caller,
    row.callee,
    row.counterparty,
    row.counterpartyName,
    row.ownerAccount,
    ...Object.values(row.extras ?? {}).filter((v): v is string => typeof v === "string"),
  ]
  return 值.filter((v): v is string => typeof v === "string" && v.trim() !== "")
}

function 是空行(row: FactRowInput): boolean {
  return (
    row.startedAt == null &&
    row.amount == null &&
    row.balance == null &&
    row.durationSec == null &&
    文本值(row).length === 0
  )
}

function 户名字段(row: FactRowInput): string {
  const v = row.extras?.["ownerName"]
  return typeof v === "string" ? v.trim() : ""
}

export function 翻译资金(input: 翻译资金输入): 翻译结果 {
  const 卡片们: 卡片草稿[] = []
  const 别名们: 别名观察[] = []
  const 属性们: 属性观察[] = []
  const 跳过们: 跳过[] = []
  /** 同键同值只留一条、出处取首次（05 §5.1-3）。 */
  const 别名已见 = new Set<string>()
  const 属性已见 = new Set<string>()

  for (const row of input.rows) {
    const 出处 = `${input.materialId}#${row.sheet}#${row.rowNo}`

    if (是空行(row)) {
      跳过们.push({ rowNo: row.rowNo, 原因: "空行" })
      continue
    }
    const 文本 = 文本值(row)
    if (文本.some((v) => 小计形状.test(v.trim()))) {
      跳过们.push({ rowNo: row.rowNo, 原因: "小计行" })
      continue
    }
    if (文本.some((v) => 合计形状.test(v.trim()))) {
      跳过们.push({ rowNo: row.rowNo, 原因: "合计行" })
      continue
    }
    // 方向必须在映射表内：映射之外的取值 = 不知道该谁付谁，宁可不出卡片（§4.4）。
    if (row.direction !== "收" && row.direction !== "付") {
      跳过们.push({ rowNo: row.rowNo, 原因: "方向不明" })
      continue
    }
    if (row.amount == null) {
      跳过们.push({ rowNo: row.rowNo, 原因: "金额无法解析" })
      continue
    }
    if (row.startedAt == null) {
      跳过们.push({ rowNo: row.rowNo, 原因: "时间无法解析" })
      continue
    }
    const 本方原 = (row.ownerAccount ?? "").trim()
    if (本方原 === "") {
      跳过们.push({ rowNo: row.rowNo, 原因: "缺本方账号" })
      continue
    }
    const 对方原 = (row.counterparty ?? "").trim()
    if (对方原 === "") {
      跳过们.push({ rowNo: row.rowNo, 原因: "缺对方账号" })
      continue
    }

    const 本方 = 归一化值("ownerAccount", 本方原)
    const 对方 = 归一化值("counterparty", 对方原)
    const 本方可建 = 是账户形状(本方)
    const 对方可建 = 是账户形状(对方)
    const 主体角色 = row.direction === "付" ? "付款方" : "收款方"
    const 对手角色 = row.direction === "付" ? "收款方" : "付款方"

    const attrs: Record<string, unknown> = {}
    if (row.balance != null) attrs["余额"] = row.balance

    卡片们.push({
      id: 卡片id(input.projectId, input.materialId, row.sheet, row.rowNo, "资金"),
      type: "资金交易",
      occurredAt: row.startedAt,
      occurredRaw: row.startedRaw ?? "",
      precision: row.precision ?? "到日",
      amount: row.amount,
      currency: row.currency ?? "CNY",
      attrs,
      participants: [
        { 规范值: 本方, 角色: 主体角色, 提及: 本方原, ordinal: 0, 实体: 本方可建 },
        { 规范值: 对方, 角色: 对手角色, 提及: 对方原, ordinal: 1, 实体: 对方可建 },
      ],
      sheet: row.sheet,
      rowNo: row.rowNo,
    })

    const 本户 = 户名字段(row)
    if (本方可建 && 本户 !== "" && !别名已见.has(`${本方}\u0000${本户}`)) {
      别名已见.add(`${本方}\u0000${本户}`)
      别名们.push({ 规范值: 本方, 值: 本户, 出处 })
    }
    const 对户 = (row.counterpartyName ?? "").trim()
    if (对方可建 && 对户 !== "" && !别名已见.has(`${对方}\u0000${对户}`)) {
      别名已见.add(`${对方}\u0000${对户}`)
      别名们.push({ 规范值: 对方, 值: 对户, 出处 })
    }

    for (const [键, 原始] of Object.entries(row.extras ?? {})) {
      const 属性 = 解析属性列(键)
      if (属性 === undefined) continue
      if (typeof 原始 !== "string") continue
      const 值 = 原始.trim()
      if (值 === "") continue
      if (属性.归属 === "本方" && !本方可建) continue
      if (属性.归属 === "对方" && !对方可建) continue
      const 去重键 = `${属性.归属}\u0000${属性.键}\u0000${值}`
      if (属性已见.has(去重键)) continue
      属性已见.add(去重键)
      属性们.push({ 归属: 属性.归属, 键: 属性.键, 值, 出处 })
    }
  }

  return { 卡片们, 别名们, 属性们, 跳过们 }
}
```

```ts
export * as OpenhiveCaseTranslateStore from "./case-translate-store"

import { sql } from "drizzle-orm"
import { Hash } from "@opencode-ai/core/util/hash"
import { nowSeconds } from "@opencode-ai/auth/time"
import { rowsOf } from "@opencode-ai/auth/migrate"
import {
  addCitations,
  deleteCitationsOfMaterial,
  insertEvents,
  insertParticipants,
  upsertEntity,
  删除本材料的事实,
  type Queryable,
} from "./case-fact-store"
import type { CitationInput } from "./case-store"
import { 账户键, type 翻译结果 } from "./case-translate"

/**
 * 翻译结果落库（01 §4.0 的「⑤ 落库」）。
 *
 * 顺序不能换（Global Constraints 8）：
 * 清机器事实 → 参与者级联 → 别名撤销 → 实体归并 → 卡片/参与者/出处 → 别名 → 关系重建 → 属性。
 * 反序会留下孤儿参与者，或按已删事实找不到该清的行（`#007-02`）。
 */

function 事实id(...parts: (string | number)[]): string {
  return Hash.sha256(parts.join("\u0000")).slice(0, 32)
}

export interface 写入翻译输入 {
  projectId: string
  materialId: string
  templateId: string
  翻译: 翻译结果
}

export async function 清本材料翻译(tx: Queryable, projectId: string, materialId: string): Promise<void> {
  await 删除本材料的事实(tx, projectId, materialId)
  // 参与者没有 material_id：它的归属只能从事件反推 ⇒ 事件删掉后按「孤儿」清（Q14）。
  await tx.execute(sql`
    delete from auth.case_event_participant p
     where p.project_id = ${projectId}
       and not exists (
         select 1 from auth.case_event e
          where e.project_id = p.project_id and e.id = p.event_id
       )
  `)
  // 别名按 material_id 撤销（不硬删：有效期语义要留痕，重写时把 revoked_at 清回 null）。
  await tx.execute(sql`
    update auth.case_entity_alias
       set revoked_at = ${nowSeconds()}
     where project_id = ${projectId} and material_id = ${materialId} and revoked_at is null
  `)
  await deleteCitationsOfMaterial(tx, projectId, materialId)
}

export async function 写入翻译结果(
  tx: Queryable,
  input: 写入翻译输入,
): Promise<{ 卡片数: number; 别名数: number; 属性实体数: number }> {
  const { projectId, materialId, templateId, 翻译 } = input
  const 出处前缀 = `${materialId}#`

  // ① 实体归并：内存 Map 缓存「账户\u0000规范值 → entityId」（§4.0.3c，硬要求）。
  const 实体缓存 = new Map<string, string>()
  for (const 卡 of 翻译.卡片们) {
    for (const p of 卡.participants) {
      if (!p.实体) continue
      const 键 = 账户键(p.规范值)
      if (实体缓存.has(键)) continue
      const id = await upsertEntity(tx, {
        projectId,
        id: 事实id(projectId, "账户", p.规范值),
        type: "账户",
        canonicalValue: p.规范值,
        aliases: [],
      })
      实体缓存.set(键, id)
    }
  }

  // ② 卡片 + 参与者 + 出处（一份材料 2×N 行参与者，必须批量）
  const 引用们: CitationInput[] = []
  const 事件们 = 翻译.卡片们.map((卡) => ({
    projectId,
    id: 卡.id,
    type: 卡.type,
    occurredAt: 卡.occurredAt,
    occurredRaw: 卡.occurredRaw,
    precision: 卡.precision,
    // 金额必须映射：漏了这一行，`事件写入.amount` 有字段也永远是 null，
    // T7 的 `sum(e.amount)` 会恒为 0 且**不报错**。
    amount: 卡.amount,
    participants: 卡.participants.map((p) => p.规范值),
    summary: null,
    trustState: "自动抽取" as const,
    attrs: 卡.attrs,
    currency: 卡.currency,
    templateId,
  }))
  for (const 卡 of 翻译.卡片们) {
    引用们.push({
      id: 事实id(projectId, "event", 卡.id, materialId),
      projectId,
      factType: "event",
      factId: 卡.id,
      materialId,
      locator: { sheet: 卡.sheet, row: 卡.rowNo },
      extractMethod: "机器",
    })
  }
  await insertEvents(tx, 事件们)
  await addCitations(tx, 引用们)

  const 参与者们 = 翻译.卡片们.flatMap((卡) =>
    卡.participants.map((p) => ({
      projectId,
      id: 事实id(projectId, "participant", 卡.id, String(p.ordinal)),
      eventId: 卡.id,
      entityId: p.实体 ? (实体缓存.get(账户键(p.规范值)) ?? null) : null,
      role: p.角色,
      mentionText: p.提及,
      citationId: 引用们.find((c) => c.factId === 卡.id)?.id ?? null,
      ordinal: p.ordinal,
    })),
  )
  await insertParticipants(tx, 参与者们)

  // ③ 别名（kind='户名'，挂账户）：id 由 (材料, 实体, 值) 决定，重放时把 revoked_at 清回 null。
  for (const a of 翻译.别名们) {
    const entityId = 实体缓存.get(账户键(a.规范值))
    if (entityId === undefined) continue
    await tx.execute(sql`
      insert into auth.case_entity_alias
        (id, project_id, entity_id, kind, value, raw_value, source_kind, material_id, created_at, revoked_at)
      values (${事实id(projectId, "alias", entityId, a.值, materialId)}, ${projectId}, ${entityId},
              '户名', ${a.值}, ${a.值}, '表格', ${materialId}, ${nowSeconds()}, null)
      on conflict (project_id, id) do update
         set value = excluded.value, raw_value = excluded.raw_value, revoked_at = null
    `)
  }

  // ④ 关系重建、⑤ 属性写入在 Task 7 / Task 8 接入；本任务先只做上面的骨架。
  return { 卡片数: 翻译.卡片们.length, 别名数: 翻译.别名们.length, 属性实体数: 0 }
}
```

⚠️ 别名逐条 INSERT 在这里是可接受的（一份材料的**不同户名**数量远小于行数）；如果真出现上万条，与参与者同法改批量——先测出问题再优化，别提前造批量接口。

```ts
export interface 关系对 {
  fromId: string
  toId: string
}

/**
 * 从卡片重建关系（§4.0.4：卡片是唯一事实，关系是对卡片的聚合）。
 *
 * 为什么不能「按材料增量累加」：同一对账户常出现在双方各自导出的流水里。增量累加会在
 * 重放时算重（`#007-02` 的同款形态），`on conflict do nothing` 又会让后到材料的笔数
 * 静默丢失。唯一正确的做法是：删掉这一对的机器态，再从 `case_event` + 参与者重新聚合。
 *
 * 人工结论优先：该对已有 `已确认`/`已修正` 行时整对跳过——机器行与人工行并存会被
 * 求和逻辑算成两笔。
 */
export async function 重建关系(tx: Queryable, projectId: string, 对们: readonly 关系对[]): Promise<number> {
  if (对们.length === 0) return 0
  let written = 0
  for (let i = 0; i < 对们.length; i += INSERT_CHUNK_PAIRS) {
    const chunk = 对们.slice(i, i + INSERT_CHUNK_PAIRS)
    const 值 = sql.join(chunk.map((p) => sql`(${p.fromId}, ${p.toId})`), sql`, `)

    // 人工结论存在就对整对放手：**不写**机器行（机器行仍清掉，两者不得并存）。
    //
    // `已排除` 也算人工结论：`case-fact-store.ts:305-321` 把 `已排除` 与 `已确认/已修正`
    // 并列，作为跨重放保留的关系状态。不放行的话，重放会再插一条 `自动抽取` 把排除撤销。
    const 人工 = rowsOf(
      await tx.execute(sql`
        select distinct r.from_id, r.to_id
          from auth.case_relation r
         where r.project_id = ${projectId} and r.type = '转账'
           and r.trust_state in ('已确认', '已修正', '已排除')
           and (r.from_id, r.to_id) in (values ${值})
      `),
    )
    const 保护 = new Set(人工.map((r) => `${String(r.from_id)}\u0000${String(r.to_id)}`))

    // 只删**本函数自己那条**（id 由 `事实id` 确定性生成），不能按「type + 信任态 + 对」
    // 整片删：`case-ingest.ts:745-767` 从笔录抽出的关系也是 `type='转账'` +
    // `自动抽取`/`存疑`，只是 `source_kind='human'`、id 里带材料与原文。整片删会把它连
    // 它的 `fact_type='relation'` 出处一起打成悬空引用，且清理只清当前材料的引用。
    const 机器id们 = chunk.map((p) => 事实id(projectId, "转账", p.fromId, p.toId))
    await tx.execute(sql`
      delete from auth.case_relation
       where project_id = ${projectId}
         and id = any(${文本数组(机器id们)})
         and trust_state in ('自动抽取', '存疑')
    `)

    const 聚合 = rowsOf(
      await tx.execute(sql`
        select 付.entity_id as from_id, 收.entity_id as to_id,
               count(*)::int as times,
               coalesce(sum(e.amount) filter (where e.currency = 'CNY'), 0)::numeric(18,2)::text as amount,
               min(e.occurred_at) as first_at, max(e.occurred_at) as last_at,
               case when bool_or(e.precision = '到日') then '到日'
                    when bool_or(e.precision = '到分') then '到分'
                    else '到秒' end as precision
          from auth.case_event e
          join auth.case_event_participant 付
            on 付.project_id = e.project_id and 付.event_id = e.id and 付.role = '付款方'
          join auth.case_event_participant 收
            on 收.project_id = e.project_id and 收.event_id = e.id and 收.role = '收款方'
         where e.project_id = ${projectId}
           and e.type = '资金交易'
           and e.trust_state <> '已排除'
           and 付.entity_id is not null and 收.entity_id is not null
           and (付.entity_id, 收.entity_id) in (values ${值})
         group by 1, 2
      `),
    )

    for (const 行 of 聚合) {
      const fromId = String(行.from_id)
      const toId = String(行.to_id)
      if (保护.has(`${fromId}\u0000${toId}`)) continue
      // `::text` 聚合列按字符串回读；判型失败就**抛**，不要兜底成 `"0.00"`——把一笔真实
      // 金额静默写成 0，比当场炸更难发现。
      if (typeof 行.amount !== "string") throw new Error(`关系聚合金额不是字符串：${String(行.amount)}`)
      const 写入 = rowsOf(
        await tx.execute(sql`
          insert into auth.case_relation
            (id, project_id, from_id, to_id, type, first_at, last_at, precision, times, amount,
             basis, source_kind, trust_state, created_at)
          values (${事实id(projectId, "转账", fromId, toId)}, ${projectId}, ${fromId}, ${toId}, '转账',
                  ${行.first_at ?? null}, ${行.last_at ?? null}, ${行.precision ?? null},
                  ${Number(行.times ?? 0)}, ${行.amount}, null, 'data', '自动抽取',
                  ${nowSeconds()})
          on conflict (project_id, id) do nothing
          returning id
        `),
      )
      written += 写入.length
    }
  }
  return written
}
```

```ts
async function 本材料关系对(tx: Queryable, projectId: string, materialId: string): Promise<关系对[]> {
  return rowsOf(
    await tx.execute(sql`
      select distinct 付.entity_id as from_id, 收.entity_id as to_id
        from auth.case_event e
        join auth.case_event_participant 付
          on 付.project_id = e.project_id and 付.event_id = e.id and 付.role = '付款方'
        join auth.case_event_participant 收
          on 收.project_id = e.project_id and 收.event_id = e.id and 收.role = '收款方'
       where e.project_id = ${projectId}
         and e.id in (select fact_id from auth.case_citation
                       where project_id = ${projectId} and material_id = ${materialId} and fact_type = 'event')
         and 付.entity_id is not null and 收.entity_id is not null
    `),
  ).map((r) => ({ fromId: String(r.from_id), toId: String(r.to_id) }))
```

```ts
export * as OpenhiveCaseEntityAttrs from "./case-entity-attrs"

import { 账户键, type 属性观察, type 卡片草稿 } from "./case-translate"

/**
 * `case_entity.attrs` 的形状与合并（01 §3.10 / 05 §5）。
 *
 * 形状：`{ "<键>": [{ "值": "...", "出处": "<material_id>#<sheet>#<row_no>" }, ...] }`。
 * `subtype` 是**唯一的标量键**（材料里明确写出的细类），语义保持「新值覆盖旧值」。
 *
 * 为什么必须替换掉 `attrs || excluded.attrs`（`case-fact-store.ts:73`）：jsonb 的 `||`
 * 是**键级覆盖**。两家材料给出不同开户行时，后写的那条把前一条整键抹掉——证据丢了，
 * 而且没人知道丢过（A16 要的是「两条都在」）。
 */

export type 实体属性 = Record<string, unknown>

export function 读jsonb(值: unknown): 实体属性 {
  if (值 === null || 值 === undefined) return {}
  if (typeof 值 === "string") {
    try {
      const 解析 = JSON.parse(值)
      return typeof 解析 === "object" && 解析 !== null ? (解析 as 实体属性) : {}
    } catch {
      return {}
    }
  }
  return typeof 值 === "object" ? (值 as 实体属性) : {}
}

interface 观察 { 值: string; 出处: string }

function 是观察数组(值: unknown): 值 is 观察[] {
  return (
    Array.isArray(值) &&
    值.every(
      (x) =>
        typeof x === "object" &&
        x !== null &&
        typeof (x as 观察).值 === "string" &&
        typeof (x as 观察).出处 === "string",
    )
  )
}

/** 按 key 合并：观察数组按 `值` 去重（保留首次出处）；其余（标量）新值覆盖。 */
export function 合并属性(旧: 实体属性, 新: 实体属性): 实体属性 {
  const 结果: 实体属性 = { ...旧 }
  for (const [键, 新值] of Object.entries(新)) {
    const 旧值 = 结果[键]
    if (是观察数组(新值)) {
      const 已有 = 是观察数组(旧值) ? 旧值 : []
      const 已见值 = new Set(已有.map((x) => x.值))
      const 追加 = 新值.filter((x) => !已见值.has(x.值))
      结果[键] = [...已有, ...追加]
      continue
    }
    结果[键] = 新值
  }
  return 结果
}

/**
 * 剥掉「由这份材料产生」的观察（Q14：来源键总规）。
 *
 * 不做这一步，重放时换过的旧值会永远留在 attrs 里——同键不同值本来就并存，看不出哪条是
 * 上一轮解析的残留。出处前缀 `<material_id>#` 是唯一可靠的归属判据。
 */
export function 剥离本材料出处(旧: 实体属性, materialId: string): 实体属性 {
  const 前缀 = `${materialId}#`
  const 结果: 实体属性 = {}
  for (const [键, 值] of Object.entries(旧)) {
    if (!是观察数组(值)) {
      结果[键] = 值
      continue
    }
    const 留 = 值.filter((x) => !x.出处.startsWith(前缀))
    if (留.length > 0) 结果[键] = 留
  }
  return 结果
}

/**
 * 观察 → 按实体分组的属性（`归属` 只有「对方/本方」，要回到产生它的卡片才知道是哪个实体）。
 *
 * 出处是 `<material_id>#<sheet>#<row_no>`，卡片的 `(sheet, rowNo)` 是它的后缀 ⇒ 先建
 * 「后缀 → 卡片」索引，再按归属取对应参与者。同一行可能既有本方属性又有对方属性，
 * 两条各自找自己的实体。
 */
export function 属性观察表(
  属性们: readonly 属性观察[],
  实体缓存: ReadonlyMap<string, string>,
  卡片们: readonly 卡片草稿[],
): Map<string, 实体属性> {
  const 按出处 = new Map<string, 卡片草稿>()
  for (const 卡 of 卡片们) 按出处.set(`${卡.sheet}#${卡.rowNo}`, 卡)

  const 结果 = new Map<string, 实体属性>()
  for (const a of 属性们) {
    const 卡 = 按出处.get(a.出处.split("#").slice(1).join("#"))
    if (卡 === undefined) continue
    const 参与 = a.归属 === "本方" ? 卡.participants[0] : 卡.participants[1]
    if (!参与.实体) continue
    const entityId = 实体缓存.get(账户键(参与.规范值))
    if (entityId === undefined) continue
    const 现有 = 结果.get(entityId) ?? {}
    结果.set(entityId, 合并属性(现有, { [a.键]: [{ 值: a.值, 出处: a.出处 }] }))
  }
  return 结果
}
```

```ts
}

function 造表(名: string, aoa: string[][]): RawSheet {
  const [表头 = [], ...行们] = aoa
  const 转 = (t: string): RawRow["cells"][number] =>
    t === "" ? { text: null, kind: "empty" } : { text: t, kind: /^-?\d+(\.\d+)?$/.test(t) ? "number" : "text" }
  return {
    name: 名,
    header: 表头.map(转),
    rows: 行们.map((r, i) => ({ rowNo: i + 2, cells: r.map(转) })),
  }
}
```
