# 案件知识与情报体系 · 计划 2：表格导入通路 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让「民警把一个话单/流水 Excel 拖进项目」这件事端到端跑通——文件落盘即入队，后台单 worker 顺序消费，零配置认列，拆成明细行进 `case_fact_row`，认不出的列原样进 `extras`，文件级状态从「未入队」走到「已解析」或「有问题」。

**Architecture:** 五段纯逻辑（读表 / 认列 / 认时间 / 拼行 / 判定材料类型）与两段副作用（入队、消费）分开：纯函数全部可脱离数据库单测，副作用只有 `case-ingest.ts` 一个出口。表格格式按「表头 + 列数据特征」算指纹沉淀在 `case_table_format`，同一格式第二次起零成本。作业队列复用 0031 已有的 `case_ingest_job`，单 worker 顺序消费（设计 §6.5）。

**Tech Stack:** TypeScript / Bun 1.4.2 / SheetJS `xlsx` 0.20.3（**本计划新增的服务端依赖**）/ Drizzle ORM / PostgreSQL（PGlite 作测试夹具）/ Effect 4.0.0-beta.83（worker 层）。

**Spec:** `docs/superpowers/specs/2026-11-05-案件知识与情报体系/design.md`（§5.1–§5.6 入库与流水线、§6.1–§6.5 表格自动识别、§11 判据 A1/A1b/A2/A4/A5/A6）

## Global Constraints

- **项目隔离走应用层，不引入 RLS**（用户 2026-11-06 裁定）。所有 DAO 函数**必须**把 `project_id` 放进 `WHERE`，且 `project_id` 必须出现在每张新表的主键里。
- 迁移文件：`packages/auth/src/migrations/NNNN_name.sql` ＋ 同名 `.down.sql`；本计划编号 **0032**；语句分隔符 **`--> statement-breakpoint`**（单独成行、前后空行）。
- **整轮迁移跑在一个事务里** ⇒ 不许出现 `CREATE INDEX CONCURRENTLY`（`25001`，见 `migrations/README.md` 第 1 条）。
- **已提交的迁移内容冻结**（`migrations/README.md` 第 5 条）：0032 一经提交就不再改内容，要改另起 0033。
- 表一律建在 schema `auth` 下，前缀 `case_`；时间列一律 `integer` Unix 秒（`nowSeconds()`）；金额 `numeric(18,2)`（**JS 侧读出来是 string**）。
- **测试只许在受影响 package 内跑**：`cd packages/opencode && timeout 300 bun test test/server/<file>`。根目录 `bun test` 被 scripts 强制 `exit 1`。
- **`packages/opencode` 起 PG 夹具只有一条路**：`startProductionDb()` ＋ `await migrate(pg.db)`；**不许** `import { PGlite } from "@electric-sql/pglite"`（本包没有这个依赖）。
- **本计划新增依赖 `xlsx`，只加在 `packages/opencode`**，版本与 `packages/app/package.json:104` 完全一致（`https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`）。理由：`packages/app` 那份读表器跑在浏览器/Worker 里，且**会把日期改写成规范串、把数字取格式化后的 `w`**（`sheet-parse-core.ts:109-131`），服务端要的是「单元格显示文本原样」，不能复用。
  - 装完**必须** `git diff --stat bun.lock` 检查镜像污染（`CLAUDE.md`「锁文件污染」）。本机 `~/.npmrc` 指向 npmmirror，装之前用 `npm_config_registry=https://registry.npmjs.org` 压住。
- **时间一律按 Asia/Shanghai（固定 UTC+8）解释**再存 Unix 秒。中国自 1991 年起无夏令时 ⇒ 固定偏移是确定的；用 `Date.UTC(...) / 1000 - 8*3600`，**不许**用 `new Date(string)`（会按进程时区漂）。
- **明细行不写 citation**。引用是「事实 → 原始出处」的链，明细行本身就是原始存放处，「材料 + 工作表 + 行号」已在同一条记录里；给千万行每一行再写一条 citation 只是把同一信息存两遍。抽成实体/关系时再写引用（后续计划）。
- **`fact_row.extras` 的键是原表头文本**，不是列序号；表头为空或重名时用 `第N列`（N 从 1 起）。认不出的列**一律进 extras，一行不丢**（§6.3、判据 A4）。
- 金额 / 时长 / 时间解析**认不出就留 null**，原值仍在 `extras` 或 `started_raw` 里 —— 不许猜。

```sql
--

-- - **fingerprint 是「表头 + 每列数据特征」的摘要，不是文件内容哈希**：
```

### Task 2: 服务端读表 —— 原始文本保真

> **⚠️ 本节实现已在执行期修订过（R9–R13），下面贴的代码是初稿。最终形态以
> `packages/opencode/src/server/openhive/case-sheet.ts`（提交 `5ab42508cb`）为准，
> 契约变化见下方「执行期修订摘要」。重新抽取 brief 前先对照该文件。**
>
> **执行期修订摘要**（细节与理由见 `.superpowers/sdd/2026-11-06-案件情报-计划2-表格导入通路/progress.md`）：
> 1. **非表格字节的判据**：初稿的实现对任意字节都不抛（SheetJS 会退化成纯文本解析），所以加了入口守卫 —— 容器签名（ZIP 三种 ＋ OLE2 **8 字节**）**或**严格 UTF-8 文本。
> 2. **R11 文本只收严格 UTF-8**：GBK 导出会响亮失败并提示另存 UTF-8，**不做**编码自动探测（GB18030 几乎能解码任意字节，回退等于放二进制进来）。
> 3. **R12 不用 `sheetRows`**：它在表头上面有标题行时按绝对行号切、会把数据整片切掉；改为整本解析后按 `range` 精确切行。代价：`maxRowsPerSheet` 只约束返回行数、不约束解析期内存。
> 4. **R10 返回值改成 `ReadResult`**：`{ sheets, skippedSheets, truncatedSheets }`，`RawSheet` 形状不变。截断按**非空行数**判定（CSV 尾部空行不算截断）。
> 5. **R13** 无 `!ref` 的空工作表静默跳过、不进 `skippedSheets`（空表没丢数据）。
> 6. **已知缺口**：表头恒取 `!ref` 首行 —— 上方若有**非空**标题行，标题会被当表头、真表头落进数据行。本计划不做「猜标题行」；真栈验收若遇到这类材料多，单开任务。

```ts
export * as OpenhiveCaseSheet from "./case-sheet"

import * as XLSX from "xlsx"

/**
 * 服务端读表：把工作簿读成「原始文本网格」。
 *
 * ## 为什么不用 `packages/app` 那份读表器
 *
 * 那份（`app/src/center/views/sheet/sheet-parse-core.ts`）是给浏览器看表格用的，
 * 两件事与服务端相反：① 跑在 Worker 里；② `单元格文本`（`:109-131`）会把日期改写成
 * 规范串、把数值取格式化后的 `w`。服务端要的是**单元格显示文本原样**——它就是
 * `case_fact_row.started_raw`，设计 §4.2 要求「原始值从未被改写」（判据 A16）。
 *
 * 因此这里只做一件事：保留 `w`（Excel 里看到的那个样子），另外把「是不是数字」
 * 记成 `kind`，供识别层判断。
 *
 * ## 已知不保真的地方
 *
 * 数值单元格的**底层值**（日期是序列号、金额是 IEEE754 双精度）不保留，只有显示文本。
 * 显示文本正是民警在 Excel 里看到的那个值；真要底层值，另存 `cell.v`，本计划不做。
 */
export type CellKind = "text" | "number" | "empty"

export interface RawCell {
  /** 单元格显示文本；空单元格为 null（不是空串）。 */
  text: string | null
  kind: CellKind
}

export interface RawRow {
  /** **文件里的绝对行号**（表头是第 1 行）；引用要指回原始行，不能用「第几条数据」。 */
  rowNo: number
  cells: RawCell[]
}

export interface RawSheet {
  name: string
  /** 第 1 行。 */
  header: RawCell[]
  rows: RawRow[]
}

export interface ReadLimits {
  maxSheets?: number
  maxRowsPerSheet?: number
}

const DEFAULT_LIMITS: Required<ReadLimits> = { maxSheets: 8, maxRowsPerSheet: 200_000 }

function toRawCell(cell: XLSX.CellObject | undefined): RawCell {
  if (cell === undefined || cell.v === undefined || cell.v === null || cell.v === "") {
    return { text: null, kind: "empty" }
  }
  const text = typeof cell.w === "string" && cell.w.length > 0 ? cell.w : String(cell.v)
  return { text, kind: cell.t === "n" ? "number" : "text" }
}

/**
 * 读全部（上限内）工作表。**抛错**表示这份字节根本不是表格——调用方据此把材料落「有问题」，
 * 不要在这里吞掉。
 */
export function readSheets(bytes: Uint8Array, limits: ReadLimits = {}): RawSheet[] {
  const { maxSheets, maxRowsPerSheet } = { ...DEFAULT_LIMITS, ...limits }
  const wb = XLSX.read(bytes, { type: "array", cellDates: false, cellStyles: false })

  const out: RawSheet[] = []
  for (const name of wb.SheetNames.slice(0, maxSheets)) {
    const ws = wb.Sheets[name]
    if (!ws || !ws["!ref"]) continue
    const range = XLSX.utils.decode_range(ws["!ref"])
    const rowAt = (r: number): RawRow => {
      const cells: RawCell[] = []
      for (let c = range.s.c; c <= range.e.c; c++) {
        cells.push(toRawCell(ws[XLSX.utils.encode_cell({ r, c })] as XLSX.CellObject | undefined))
      }
      return { rowNo: r + 1, cells }
    }

    const header = rowAt(range.s.r).cells
    const rows: RawRow[] = []
    for (let r = range.s.r + 1; r <= range.e.r && rows.length < maxRowsPerSheet; r++) {
      rows.push(rowAt(r))
    }
    out.push({ name, header, rows })
  }
  return out
}
```

```ts
export * as OpenhiveCaseMapping from "./case-mapping"

import { Hash } from "@opencode-ai/core/util/hash"

/**
 * 表格列识别（设计 §6.1 的前两层）。
 *
 * 第三层（模型兜底）**不在本计划**：它要一套 AI 调用与预算控制，属于计划 4。
 * 认不出的列在这里一律进 `unknownColumns`，落库时原样进 `extras`（§6.3）。
 */
export const FACT_FIELDS = [
  "caller",
  "callee",
  "startedAt",
  "durationSec",
  "amount",
  "balance",
  "counterparty",
] as const
export type FactField = (typeof FACT_FIELDS)[number]

export interface MappingResult {
  /** 列下标 → 标准字段。只含认得出的列。 */
  columns: Record<number, FactField>
  method: "词典" | "特征"
  /**
   * 认不出的列下标，**以 `header` 长度为界**。前提：`rows` 不比 `header` 宽
   * （`readSheets` 产出的 `RawSheet` 满足这条——宽度恒等于 `!ref` 的列跨度）。
   * 直接拿别的数据源调本函数时，多出来的数据列既不会进 `columns` 也不会进这里。
   */
  unknownColumns: number[]
}

/** 表头词典。比较前先 `规范化`（去空白、去括号后缀、转小写）。 */
const DICTIONARY: Record<FactField, string[]> = {
  caller: ["主叫号码", "主叫", "主叫号", "呼叫号码", "发起方号码", "本机号码", "通话号码"],
  callee: ["被叫号码", "被叫", "被叫号", "对方号码", "接收方号码", "对方电话"],
  startedAt: ["通话时间", "交易时间", "发生时间", "起始时间", "开始时间", "日期时间", "时间"],
  durationSec: ["通话时长", "时长", "通话秒数", "持续时长"],
  amount: ["交易金额", "金额", "发生额", "交易额", "收入金额", "支出金额"],
  balance: ["余额", "账户余额", "交易后余额", "当前余额"],
  counterparty: ["对方账号", "对方账户", "对方卡号", "交易对方", "对方户名", "对手账号", "对手户名"],
}

/**
 * 认时间用的文本形状：`case-time.ts` 的四种格式里**只认前三种**（到秒/到分/到日）。
 * 紧凑 14 位（`yyyyMMddHHmmss`）**故意不认**：它和长数字串（流水号、账号）在文本上
 * 长得一样，特征层拿它当时间就会把号码列写进 `startedAt`。漏认可接受（进 extras），误认不可接受。
 */
const 时间形状 = /^\d{4}[-/]\d{1,2}[-/]\d{1,2}([ T]\d{1,2}:\d{2}(:\d{2})?)?$/
/** 金额形状：**必须带两位小数**。整数列（号码、行号）因此不会被误认成金额。 */
const 金额形状 = /^-?\d+\.\d{2}$/

/** 去空白（含全角）、去括号后缀、转小写。`"金额（元）"` → `"金额"`。 */
function 规范化(raw: string | null): string {
  return (raw ?? "")
    .replace(/[（(【[].*?[）)】\]]/g, "")
    .replace(/[\s　]/g, "")
    .toLowerCase()
}

/** 非空值里命中 `形状` 的比例。全空 ⇒ 0（不认）。 */
function 命中率(values: (string | null)[], 形状: RegExp): number {
  const filled = values.filter((v): v is string => v !== null && v.trim() !== "")
  if (filled.length === 0) return 0
  const hit = filled.filter((v) => 形状.test(v.trim())).length
  return hit / filled.length
}

function 列(values: (string | null)[][], c: number): (string | null)[] {
  return values.map((row) => row[c] ?? null)
}

export function detectMapping(header: (string | null)[], rows: (string | null)[][]): MappingResult {
  const columns: Record<number, FactField> = {}
  const 已占 = new Set<number>()
  /** 靠**表头词典**认走的列。`method` 靠它判定：有列不在里面 ⇒ 至少用了特征层。 */
  const 词典命中 = new Set<number>()

  // 第一层：表头词典。精确相等优先，其次「以该词结尾且全表唯一」。
  //
  // 为什么是**后缀**而不是包含：中文表头是「修饰语 ＋ 中心词」，中心词在末尾。
  // 「主叫通话时长」按包含会被 caller 的「主叫」抢走（时长列静默变成主叫号码），
  // 按后缀则命中 durationSec 的「通话时长」——修饰语再长也不会改变它是什么列。
  const 规范表头 = header.map(规范化)
  for (const field of FACT_FIELDS) {
    const 词 = DICTIONARY[field].map(规范化)
    let hit = 规范表头.findIndex((h, i) => !已占.has(i) && h !== "" && 词.includes(h))
    if (hit < 0) {
      const 候选 = 规范表头.flatMap((h, i) => (!已占.has(i) && h !== "" && 词.some((w) => h.endsWith(w)) ? [i] : []))
      if (候选.length === 1) hit = 候选[0]
    }
    if (hit >= 0) {
      columns[hit] = field
      已占.add(hit)
      词典命中.add(hit)
    }
  }

  // 第二层：数据特征。只认两种**形状唯一**的列，其余留给计划 4 的模型兜底。
  if (!Object.values(columns).includes("startedAt")) {
    const 候选 = header.flatMap((_, i) => (!已占.has(i) && 命中率(列(rows, i), 时间形状) >= 0.9 ? [i] : []))
    if (候选.length === 1) {
      columns[候选[0]] = "startedAt"
      已占.add(候选[0])
    }
  }
  if (!Object.values(columns).includes("amount")) {
    const 候选 = header.flatMap((_, i) => (!已占.has(i) && 命中率(列(rows, i), 金额形状) >= 0.9 ? [i] : []))
    // 两列都像金额 ⇒ 认不出到底哪列是金额哪列是余额，不猜。
    if (候选.length === 1) {
      columns[候选[0]] = "amount"
      已占.add(候选[0])
    }
  }

  const unknownColumns = header.flatMap((_, i) => (columns[i] === undefined ? [i] : []))
  const method: MappingResult["method"] = Object.keys(columns).every((k) => 词典命中.has(Number(k)))
    ? "词典"
    : "特征"
  return { columns, method, unknownColumns }
}

/** 列的数据形状，用于指纹。只取前 20 行做样本（够区分，也不怕大表）。 */
function 列形状(values: (string | null)[][]): string[] {
  const sample = values.slice(0, 20)
  const width = Math.max(0, ...sample.map((r) => r.length))
  const out: string[] = []
  for (let c = 0; c < width; c++) {
    const v = 列(sample, c).filter((x): x is string => x !== null && x.trim() !== "")
    if (v.length === 0) out.push("空")
    else if (v.every((x) => 时间形状.test(x.trim()))) out.push("时间")
    else if (v.every((x) => 金额形状.test(x.trim()))) out.push("金额")
    else if (v.every((x) => /^-?\d+$/.test(x.trim()))) out.push("整数")
    else out.push("文本")
  }
  return out
}

/**
 * 格式指纹：**表头 ＋ 每列的数据形状**，与具体取值无关（设计 §6.2）。
 * 同一家运营商每个月的文件内容全变，列的形状不变 ⇒ 指纹相同。
 */
export function formatFingerprint(header: (string | null)[], rows: (string | null)[][]): string {
  return Hash.sha256(JSON.stringify([header.map(规范化), 列形状(rows)]))
}

/** 材料类型（`case_material.kind` 偏表格的那三个）。产物与其它类型由调用方给。 */
export function classifyMaterialType(columns: Record<number, FactField>): "话单" | "资金" | "其他" {
  const fields = Object.values(columns)
  if (fields.includes("caller") || fields.includes("callee") || fields.includes("durationSec")) return "话单"
  if (fields.includes("amount") || fields.includes("balance")) return "资金"
  return "其他"
}
```

```ts
export * as OpenhiveCaseTime from "./case-time"

/**
 * 把表格里的时间文本解析成「Unix 秒 ＋ 精度」。
 *
 * ## 时区
 *
 * 一律按 **Asia/Shanghai（固定 UTC+8）** 解释。中国自 1991 年起没有夏令时 ⇒ 固定偏移是
 * 确定的；用 `Date.UTC` 再减 8 小时，**不许**用 `new Date("2026-01-02 03:04:05")`
 * ——那条路按进程时区漂，同一份文件在不同机器上落到不同的秒。
 *
 * ## 为什么只认这几种格式
 *
 * 认得出才写；认不出返回 `undefined`，调用方把**原文**留在 `started_raw` 里（设计 §4.2
 * 「原始值从未被改写」）。宁可少认，不可猜。
 */
export type Precision = "到日" | "到分" | "到秒"

export interface ParsedTime {
  seconds: number
  precision: Precision
}

const TZ_OFFSET_SECONDS = 8 * 3600

const 到秒 = /^(\d{4})[-/](\d{1,2})[-/](\d{1,2})[ T](\d{1,2}):(\d{2}):(\d{2})$/
const 到分 = /^(\d{4})[-/](\d{1,2})[-/](\d{1,2})[ T](\d{1,2}):(\d{2})$/
const 到日 = /^(\d{4})[-/](\d{1,2})[-/](\d{1,2})$/
const 紧凑 = /^(\d{4})(\d{2})(\d{2})(\d{2})(\d{2})(\d{2})$/

/** `Date.UTC` 会自动进位（2 月 31 日变成 3 月 3 日），所以喂进去再读回来逐个字段比。 */
function 组装(
  y: number,
  mo: number,
  d: number,
  h: number,
  mi: number,
  s: number,
  precision: Precision,
): ParsedTime | undefined {
  const ms = Date.UTC(y, mo - 1, d, h, mi, s)
  const t = new Date(ms)
  if (
    t.getUTCFullYear() !== y ||
    t.getUTCMonth() !== mo - 1 ||
    t.getUTCDate() !== d ||
    t.getUTCHours() !== h ||
    t.getUTCMinutes() !== mi ||
    t.getUTCSeconds() !== s
  ) {
    return undefined
  }
  return { seconds: Math.floor(ms / 1000) - TZ_OFFSET_SECONDS, precision }
}

export function parseTime(raw: string): ParsedTime | undefined {
  const text = raw.trim()
  const m秒 = 到秒.exec(text)
  if (m秒) {
    return 组装(+m秒[1]!, +m秒[2]!, +m秒[3]!, +m秒[4]!, +m秒[5]!, +m秒[6]!, "到秒")
  }
  const m分 = 到分.exec(text)
  if (m分) {
    return 组装(+m分[1]!, +m分[2]!, +m分[3]!, +m分[4]!, +m分[5]!, 0, "到分")
  }
  const m日 = 到日.exec(text)
  if (m日) {
    return 组装(+m日[1]!, +m日[2]!, +m日[3]!, 0, 0, 0, "到日")
  }
  const m紧 = 紧凑.exec(text)
  if (m紧) {
    return 组装(+m紧[1]!, +m紧[2]!, +m紧[3]!, +m紧[4]!, +m紧[5]!, +m紧[6]!, "到秒")
  }
  return undefined
}
```

```ts
export * as OpenhiveCaseRows from "./case-rows"

import type { RawSheet } from "./case-sheet"
import { parseTime } from "./case-time"
import type { FactField } from "./case-mapping"
import type { FactRowInput } from "./case-store"

/**
 * 把「映射 ＋ 原始网格」拼成待写入的明细行。
 *
 * ## extras 的键
 *
 * **原表头文本**，不是列序号——民警在界面上看到的是表头，不是下标。
 * 表头为空或与前面重名时用 `第N列`（N 从 1 起，按本行第几列算）。
 *
 * ## 认不出就留 null
 *
 * 金额/时长/时间解析不出来时写 null，**不猜**；原始文本仍在 `started_raw` 或 `extras` 里。
 * 设计 §4.2 的「原始值从未被改写」靠这条守住（判据 A16）。
 */
export interface ToRowsInput {
  projectId: string
  materialId: string
  sheet: RawSheet
  mapping: Record<number, FactField>
}

export function parseAmount(raw: string | null): string | null {
  if (raw === null) return null
  const 干净 = raw.replace(/[\s\u3000,，￥¥$]/g, "")
  if (!/^-?\d+(\.\d{1,2})?$/.test(干净)) return null
  const [整数, 小数 = ""] = 干净.split(".")
  return `${整数}.${(小数 + "00").slice(0, 2)}`
}

export function parseDuration(raw: string | null): number | null {
  if (raw === null) return null
  const 干净 = raw.replace(/[秒\s]/g, "")
  if (/^\d+$/.test(干净)) return Number(干净)
  const 两段 = /^(\d+):([0-5]\d)$/.exec(干净)
  if (两段) return Number(两段[1]) * 60 + Number(两段[2])
  const 三段 = /^(\d+):([0-5]\d):([0-5]\d)$/.exec(干净)
  if (三段) return Number(三段[1]) * 3600 + Number(三段[2]) * 60 + Number(三段[3])
  return null
}

function 表头键(header: RawSheet["header"]): string[] {
  const 已用 = new Set<string>()
  return header.map((cell, i) => {
    const 原 = (cell.text ?? "").trim()
    const 键 = 原 !== "" && !已用.has(原) ? 原 : `第${i + 1}列`
    已用.add(键)
    return 键
  })
}

export function toFactRows(input: ToRowsInput): FactRowInput[] {
  const 键 = 表头键(input.sheet.header)

  const out: FactRowInput[] = []
  for (const row of input.sheet.rows) {
    if (row.cells.every((c) => c.text === null)) continue

    const 值 = (field: FactField): string | null => {
      const 下标 = Object.keys(input.mapping).find((k) => input.mapping[Number(k)] === field)
      if (下标 === undefined) return null
      return row.cells[Number(下标)]?.text ?? null
    }

    const 时间原文 = 值("startedAt")
    const 时间 = 时间原文 === null ? undefined : parseTime(时间原文)
    const 时长 = parseDuration(值("durationSec"))
    const 金额 = parseAmount(值("amount"))
    const 余额 = parseAmount(值("balance"))

    const extras: Record<string, string> = {}
    row.cells.forEach((cell, i) => {
      if (cell.text === null) return
      const field = input.mapping[i]
      if (field !== undefined) {
        // 已映射的列**解析成功**就不进 extras；解析失败的值必须留底 —— 否则它既不在标准列、
        // 也不在 extras 里，原件上写的什么就再也看不到了（Global Constraints：「认不出就留
        // null，原值仍在 extras 或 started_raw 里」）。时间不在此列：它的原文在 started_raw。
        const 解析失败 =
          (field === "durationSec" && 时长 === null) ||
          (field === "amount" && 金额 === null) ||
          (field === "balance" && 余额 === null)
        if (!解析失败) return
      }
      extras[键[i] ?? `第${i + 1}列`] = cell.text
    })

    out.push({
      projectId: input.projectId,
      materialId: input.materialId,
      sheet: input.sheet.name,
      rowNo: row.rowNo,
      caller: 值("caller"),
      callee: 值("callee"),
```

```ts
/** 一块多少行。15 列 × 500 = 7500 个绑定参数，离 PG 上限 65535 有量级余量。 */
const INSERT_CHUNK = 500

export async function insertFactRows(db: Queryable, rows: FactRowInput[]): Promise<number> {
  let written = 0
  for (let i = 0; i < rows.length; i += INSERT_CHUNK) {
    const chunk = rows.slice(i, i + INSERT_CHUNK)
    if (chunk.length === 0) continue
    const values = chunk.map(
      (row) => sql`(${row.projectId}, ${row.materialId}, ${row.sheet}, ${row.rowNo},
                    ${row.caller ?? null}, ${row.callee ?? null}, ${row.startedAt ?? null},
                    ${row.startedRaw ?? null}, ${row.precision ?? null}, ${row.timeType ?? null},
                    ${row.durationSec ?? null}, ${row.amount ?? null}, ${row.balance ?? null},
                    ${row.counterparty ?? null}, ${JSON.stringify(row.extras ?? {})}::jsonb)`,
    )
    const result = rowsOf(
      await db.execute(sql`
        insert into auth.case_fact_row
          (project_id, material_id, sheet, row_no, caller, callee, started_at, started_raw,
           precision, time_type, duration_sec, amount, balance, counterparty, extras)
        values ${sql.join(values, sql`, `)}
        on conflict (project_id, material_id, sheet, row_no) do nothing
        returning row_no
      `),
    )
    written += result.length
  }
  return written
}
```

```ts
 * 多实例部署时再谈锁，别现在提前上（缺口记在计划自检里）。
 *
 * ## 重放为什么是「先删后写」而不是 upsert
 *
 * `insertFactRows` 的 `on conflict do nothing` 只承诺**导入幂等**（见它的 JSDoc）。
 * 映射修正、解析器升级之后要让改动生效，必须真的把旧行删掉——`do nothing` 只会
 * 把老行原样留下，「重放成功」于是成了静默的空操作。
 */
export interface EnqueueInput {
  projectId: string
  /** 项目内路径（落 `case_material.path`，界面用）。 */
  path: string
  /** 沙箱根相对路径（`{userId}/{projectId}/{项目内路径}`），作业靠它读盘。 */
  sourcePath: string
  fileName: string
  fingerprint: string
  /** 人工触发时的操作人（设计 §8.1 留痕）。 */
  by?: string
  /** 强制重解析：已解析的材料也重新排队。 */
  force?: boolean
}

export interface EnqueueResult {
  materialId: string
  enqueued: boolean
}

/**
 * 当前状态 + 是否强制 ⇒ 该发哪个动作；`undefined` = 不排队。
 *
 * 「有问题」不带 force 也重来：民警把同一个文件重新拖进来，意图就是「再试一次」。
 * 「排队中 / 解析中」一律不重排：已经在队列里，再插一条只会让同一份文件被解析两遍。
 */
export function 该走哪个动作(status: ParseStatus, force: boolean): ParseAction | undefined {
  switch (status) {
    case "未入队":
    case "已跳过":
      return "入队"
    case "有问题":
      return "重新解析"
    case "已解析":
      return force ? "重新解析" : undefined
    case "排队中":
    case "解析中":
      return undefined
  }
}

export async function enqueueMaterial(db: Queryable, input: EnqueueInput): Promise<EnqueueResult> {
  const materialId = await createMaterial(db, {
    id: crypto.randomUUID(),
    projectId: input.projectId,
    fileName: input.fileName,
    kind: "其他",
    fingerprint: input.fingerprint,
    path: input.path,
  })
  const current = await getMaterial(db, input.projectId, materialId)
  if (!current) throw new Error(`材料建完却读不到：${materialId}`)

  const action = 该走哪个动作(current.parseStatus, input.force ?? false)
  if (action === undefined) return { materialId, enqueued: false }

  // 先推状态再插作业：反过来的话，作业可能先被 worker 认领、材料却还是「未入队」，
  // `runJob` 里那步「排队中 → 解析中」就推进不动。
  await applyParseAction(db, { projectId: input.projectId, materialId, action, by: input.by })

  await db.execute(sql`
    insert into auth.case_ingest_job
      (id, project_id, material_id, source_path, status, attempts, queued_by, queued_at)
    values (${crypto.randomUUID()}, ${input.projectId}, ${materialId}, ${input.sourcePath},
            '排队中', 0, ${input.by ?? null}, ${nowSeconds()})
  `)
  return { materialId, enqueued: true }
}

export interface ClaimedJob {
  projectId: string
  jobId: string
  materialId: string
  sourcePath: string
}

/** 认领一条排队作业（单 worker：不必加锁）。空队列返回 `undefined`。 */
export async function claimNextJob(db: Queryable): Promise<ClaimedJob | undefined> {
  const rows = rowsOf(
    await db.execute(sql`
      update auth.case_ingest_job
         set status = '运行中', started_at = ${nowSeconds()}, attempts = attempts + 1
       where (project_id, id) in (
         select project_id, id from auth.case_ingest_job
          where status = '排队中'
          order by queued_at, id
          limit 1
       )
      returning project_id, id, material_id, source_path
    `),
  )
  const row = rows[0]
  if (!row) return undefined
  return {
    projectId: String(row.project_id),
    jobId: String(row.id),
    materialId: String(row.material_id),
    sourcePath: String(row.source_path),
  }
}

export interface RunDeps {
  /** 读材料字节。注入而不是直接读盘：作业本身不该知道沙箱根长什么样。 */
  readFile: (sourcePath: string) => Promise<Uint8Array>
}

/**
 * 跑一个已认领的作业。**不抛错**：任何失败都落到「材料有问题 ＋ 作业失败」并返回 `"失败"`，
 * worker 的循环因此不会因为一份坏文件停。
 *
 * ## 顺序是刻意的
 *
 * 读盘 → 读表 → 认列 → **拼出全部待写行** → 删旧行 → 写新行。
 * 删除夹在「算完」与「写入」之间：读表或认列失败时，上一次的结果**原样保留**——
 * 用户要么拿到新的，要么还是旧的，不会两头落空。
 */
export async function runJob(db: Queryable, deps: RunDeps, job: ClaimedJob): Promise<"完成" | "失败"> {
  try {
    const material = await getMaterial(db, job.projectId, job.materialId)
    if (!material) throw new Error(`作业指向的材料不存在：${job.materialId}`)
    if (job.sourcePath === "") throw new Error("作业没有记录文件落点（source_path 为空）")

    if (material.parseStatus === "排队中") {
      await applyParseAction(db, { projectId: job.projectId, materialId: job.materialId, action: "开始" })
    }

    // Task 2 的 R10–R13 裁定：`readSheets` 返回 `ReadResult`，截断不再静默。
    // 表被丢弃或行被截断时**整份材料不落库**、直接落「有问题」——
    // 宁可让用户拆表重导，也不要往库里灌半份话单（半份数据的统计是错的，且看起来像全的）。
    const { sheets, skippedSheets, truncatedSheets } = readSheets(await deps.readFile(job.sourcePath))
    if (skippedSheets.length > 0 || truncatedSheets.length > 0) {
      const 缘由 = [
        skippedSheets.length > 0 ? `工作表超过上限，未解析：${skippedSheets.join("、")}` : "",
        truncatedSheets.length > 0 ? `行数超过上限，已截断：${truncatedSheets.join("、")}` : "",
      ]
        .filter((s) => s !== "")
        .join("；")
      throw new Error(缘由)
    }

    const 待写: FactRowInput[] = []
    let 类型: MaterialKind = "其他"
    for (const sheet of sheets) {
      const header = sheet.header.map((c) => c.text)
      const 样例 = sheet.rows.slice(0, 20).map((r) => r.cells.map((c) => c.text))
      const fingerprint = formatFingerprint(header, 样例)

      // 认过的格式直接取映射（设计 §6.2），没认过就现认一次并沉淀。
      let columns: Record<number, FactField>
      const 缓存 = await 读格式(db, job.projectId, fingerprint)
      if (缓存) {
        columns = 缓存
        await db.execute(sql`
          update auth.case_table_format
             set hit_count = hit_count + 1, updated_at = ${nowSeconds()}
           where project_id = ${job.projectId} and fingerprint = ${fingerprint}
        `)
      } else {
        const 认出 = detectMapping(header, 样例)
        columns = 认出.columns
        await 写格式(db, job.projectId, fingerprint, header, 认出.columns, 认出.method, 认出.unknownColumns.length)
      }

      // ⚠️ 一本工作簿里话单与流水各一张表时，最后一张赢——材料只有一个 kind 字段
      //   （缺口记在计划自检里，不在本计划修）。
      类型 = classifyMaterialType(columns)
      待写.push(
        ...toFactRows({ projectId: job.projectId, materialId: job.materialId, sheet, mapping: columns }),
      )
    }

    // 重放落地：先删后写。放在这里（而不是函数开头）—— 上面任何一步抛错时旧行还在。
    await deleteFactRowsOfMaterial(db, job.projectId, job.materialId)
    await insertFactRows(db, 待写)

    await setMaterialKind(db, job.projectId, job.materialId, 类型)
    await applyParseAction(db, { projectId: job.projectId, materialId: job.materialId, action: "完成" })
    await 收尾(db, job, "完成", null)
    return "完成"
  } catch (error) {
    const reason = error instanceof Error ? error.message : String(error)
    // 收尾失败不能盖掉「返回失败」这件事：作业表写不进去时，材料状态那条还在。
    await applyParseAction(db, {
      projectId: job.projectId,
      materialId: job.materialId,
      action: "出问题",
      detail: { reason },
    }).catch(() => undefined)
    await 收尾(db, job, "失败", reason).catch(() => undefined)
    return "失败"
  }
}

/** 已认过的映射（`columns` 的键是列下标）。 */
async function 读格式(
  db: Queryable,
  projectId: string,
  fingerprint: string,
): Promise<Record<number, FactField> | undefined> {
  const rows = rowsOf(
    await db.execute(sql`
      select mapping from auth.case_table_format
       where project_id = ${projectId} and fingerprint = ${fingerprint}
    `),
  )
  const row = rows[0]
  if (!row) return undefined
  const raw = typeof row.mapping === "string" ? JSON.parse(row.mapping) : row.mapping
  const columns: Record<number, FactField> = {}
  for (const [k, v] of Object.entries(raw as Record<string, FactField>)) columns[Number(k)] = v
  return columns
}

async function 写格式(
  db: Queryable,
  projectId: string,
  fingerprint: string,
  header: (string | null)[],
  columns: Record<number, FactField>,
  method: "词典" | "特征",
  unknownColumns: number,
): Promise<void> {
  const now = nowSeconds()
  await db.execute(sql`
    insert into auth.case_table_format
      (project_id, fingerprint, header, mapping, method, unknown_columns, hit_count, created_at, updated_at)
    values (${projectId}, ${fingerprint}, ${JSON.stringify(header)}::jsonb,
            ${JSON.stringify(columns)}::jsonb, ${method}, ${unknownColumns}, 0, ${now}, ${now})
    on conflict (project_id, fingerprint) do nothing
  `)
}

async function 收尾(db: Queryable, job: ClaimedJob, status: "完成" | "失败", error: string | null) {
  await db.execute(sql`
    update auth.case_ingest_job
       set status = ${status}, finished_at = ${nowSeconds()}, error = ${error}
     where project_id = ${job.projectId} and id = ${job.jobId}
  `)
}
```

```ts
export * as OpenhiveCaseIngestWorker from "./case-ingest-worker"

import { readFile } from "node:fs/promises"
import { join } from "node:path"
import { Cause, Effect, Layer } from "effect"
import { AnchorWorkspace } from "../routes/instance/httpapi/middleware/anchor-workspace"
import { claimNextJob, runJob } from "./case-ingest"
import { OpenhivePg } from "./pg"

/**
 * 单 worker 顺序消费（设计 §6.5）。
 *
 * ## 轮询而不是通知
 *
 * 入队发生在上传请求里、消费发生在后台，两者之间不必耦合。间隔 2 秒——人拖完文件到
 * 看见 ✓ 之间本来就有解析时间，2 秒延迟看不出来，而空转开销只有一条 SQL。
 *
 * ## 形状照 `mcp-config-sync.ts`
 *
 * `Layer.effectDiscard` ＋ `Effect.forkScoped`，在 `server.ts` 的 `Layer.mergeAll` 里挂一次。
 * 一次性起一个循环，不占路由。
 *
 * ## 读盘只用 `沙箱根 + source_path`
 *
 * 项目目录恒为 `{root}/{userId}/{projectId}`，`source_path` 就是这一段相对路径 ——
 * 作业不必反查用户与项目，进程重启后照跑。
 */
export const 轮询间隔ms = 2000

export const layer = Layer.effectDiscard(
  Effect.gen(function* () {
    const pg = yield* OpenhivePg.Service
    const config = yield* AnchorWorkspace.Config

    // 一份坏文件不许把循环打停：`runJob` 自己已经把失败收成「有问题」，
    // 这里再兜一层是防**它之外**的意外（例如库连接当场断）。
    const 跑一个 = Effect.suspend(() =>
      Effect.promise(async () => {
        const db = pg.pg()
        const job = await claimNextJob(db)
        if (job === undefined) return
        await runJob(
          db,
          { readFile: async (sourcePath) => new Uint8Array(await readFile(join(config.root, ...sourcePath.split("/")))) },
          job,
        )
      }),
    ).pipe(
      Effect.catchCause((cause) =>
        // 只记类型名：PG 的 pretty 文本可能带连接串（同 `mcp-config-sync.ts`）。
        Effect.logWarning("表格导入消费跳过", {
          error: Cause.prettyErrors(cause).map((error) => error.name),
        }),
      ),
    )

    yield* Effect.forkScoped(Effect.forever(Effect.sleep(轮询间隔ms).pipe(Effect.andThen(跑一个))))
  }),
)
```

```ts
 *

export async function 入队表格材料(

  input: {
    root: string
    /** 项目目录的绝对路径。 */
    project: string
    /** 文件落点的绝对路径。 */

    bytes: Uint8Array

  if (!可解析扩展名.some((扩展名) => 项目相对.toLowerCase().endsWith(扩展名))) return undefined
```

**2. 占位符扫描**：无 TBD；每个代码步骤都给了可直接粘贴的实现或明确的「先找既有函数、找不到就报告」。

**3. 类型一致性**：`FactField` / `MappingResult` 在 Task 3 定义、Task 5/6 消费；`RawSheet` 在 Task 2 定义、Task 5 消费；`FactRowInput` 沿用计划 1；`Precision` 的取值与迁移里的 CHECK 逐字一致（`到日`/`到分`/`到秒`）。

**4. 已知缺口（不藏）**

- **「日期格式」的单元格只有显示文本**：xlsx 里日期存的是序列号 ＋ 数字格式，没有字面文本。`readSheets` 取 `cell.w`（Excel 里看到的那个样子）；若文件的数字格式是 `m/d/yy` 这类，`started_raw` 就是 `"1/2/26"`，`parseTime` 认不出 ⇒ `startedAt` 为 null，**值仍在 `started_raw` 里**。话单/流水导出一般是文本列，这条多数时候不咬人；真咬到时（计划 3 真栈）再给 `readSheets` 加「日期型单元格按 `yyyy-MM-dd HH:mm:ss` 出文本」，并同步记进 `started_raw` 的口径说明。
- **GBK 编码的 CSV 不支持**：`xlsx` 读文本需要 codepage 模块，本计划只按 UTF-8 解。政务导出里 GBK 很常见，这条会在真栈上咬人——计划 3 之前必须补，或在上传侧统一转码。
- **整本工作簿读进内存**：SheetJS 非流式。10 万行的 xlsx 会占几百 MB。设计 §6.5 的「千万行」靠分批拖入（每次一个文件）分散，但单个大文件仍可能 OOM。流式读取（`xlsx` 的 streaming reader 或换解析器）留给量级任务。
- **多张工作表各自判定类型**：一份工作簿里两张表（话单 + 资金）时，`material.kind` 只能记一个（最后一张赢）。库结构没有「按表的类型」，这是设计层面的粗糙处，记在这里。
- **同一文件换个文件名重拖**：指纹是内容哈希 ⇒ 仍是同一条材料，正确；但 `path` 会被 `createMaterial` 的 `do update set path = excluded.path` 改成新路径——旧路径的文件还在盘上。要不要清理旧副本是**文件层**的事，本计划不碰。
- **`handleUpload` 里那三行调用没有自动化用例**：入队逻辑的判据（扩展名、两层目录、指纹幂等）都在 `入队表格材料` 上验了，但「上传处理函数真的调了它」只有类型检查与既有上传用例保着。真栈上传走查留到计划 3（那时才有界面能拖文件）。
- **作业读盘依赖 `source_path` 与文件系统一致**：文件在上传后被改名/移动，排队中的作业会读不到 ⇒ 落「有问题」并带原因。这是可解释的失败，但不自动修复；「重定位」要等文件移动事件（计划 3 之后）。
- **没有并发保护**：单 worker 是真的单实例假设。如果部署起多个进程（例如多实例负载均衡），两个进程会同时认领作业——`claimNextJob` 的 `update ... where status='排队中'` 在没有行锁的情况下可能都成功。`case_ingest_job` 上加 `attempts` 计数与 `FOR UPDATE SKIP LOCKED` 留给多实例部署时再谈。
- **计划 1 遗留的「引用方向」问题**本计划不碰：本计划不写 citation，所以 `case_citation` 的方向歧义在计划 6 之前不会咬人。
