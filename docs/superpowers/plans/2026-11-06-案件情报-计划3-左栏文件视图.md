# 计划 3：左栏文件视图（状态标记 ＋ 解析右键菜单）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让民警在左栏文件树上直接看见每份材料的解析状态（○ ◐ ✓ !），并通过右键「解析 ▸」触发入队 / 重新解析 / 取消 / 跳过 / 查看。

**Architecture:** 后端新增一个只读出口 `GET /openhive/case/materials`（材料视图：状态、排队位置、事实数、号码数、是否可解析）和一个写出口 `POST /openhive/case/parse`（按**动作**而不是按目标状态推进，复用计划 2 的 `enqueueMaterial` 与 `applyParseAction`）。前端新增一个严格的 API 客户端、一个按项目绑定并轮询的状态容器、一组纯视图规则（标记形状 / 悬停文案 / 目录汇总 / 亮灯原因）、一个状态标记组件，最后接进 `FileTree` 的右键子菜单与 `WorkspaceEntry` 的注入链。

**Tech Stack:** Bun 1.4.2 · TypeScript 5.8.2 · Effect 4.0.0-beta.83 · Hono 4.10.7 · Drizzle 1.0.0-rc.2 · SolidJS 1.9.10 · Tailwind v4 · Kobalte `ContextMenu.Sub/SubTrigger/SubContent` · oxlint 1.60.0 · PGlite（测试用生产驱动夹具）

## Global Constraints

- **仓库**：`D:\project\study\openhive\openhive`，分支 `multi-tenant`。每一次改动以「最小化与官方合并冲突」为前提：新文件优先，改既有文件只加不改。
- **禁止**根目录 `bun test`（根 `package.json` 的 `test` 脚本是 `exit 1`）；只在受影响 package 内跑。
- **前端零新依赖**：不安装任何包；二级菜单只用 `@opencode-ai/ui/context-menu` 已导出的 `Sub/SubTrigger/SubContent`。
- **状态只有一个真相**：前端**不本地推演**解析状态；行标记、菜单亮度、目录汇总全部读服务端 `material.parse_status`，操作成功后只 `reload()`。
- **产物硬边界**：`kind = 产物` 的材料永远不亮「解析入库 / 重新解析 / 跳过」，出口回可解释的 `artifact_not_parseable`。
- **白名单只有一份**：表格扩展名 `.xlsx` / `.xls` / `.csv` 收口到 `case-parseable.ts`；`file.ts` 与解析出口都 import 它。
- **路径闸只有一份**：`file.ts` 的 `inside`（词法）与 `realInside`（真身）导出复用，不另写第二份。
- **人工动作不是目标状态**：出口收 `action ∈ {入队, 重新解析, 取消, 跳过}`，由 `applyParseAction` 的状态机决定落点。
- **测试纪律**：每条改动先写会红的用例；后端用 `startProductionDb()` ＋ 真应用，前端组件测试离线挂载；变异验证必须让新用例红。
- **中文标识符与文案**：与既有 `case-store` / `case-ingest` / `file-tree` 一致；错误文案是给人看的整句，不写 `error-1` 之类。

```ts
/**
 * 左栏一份材料的视图行（设计 §5.2 / §8.1）。
 *
 * ## 为什么 `queueAhead` 不带项目过滤
 *
 * 设计 §6.5 是**单 worker 全局顺序消费**（`claimNextJob` 的 `order by queued_at, id` 没有
 * `project_id`）⇒ 「前面还有几个」必须按**全局**队列算。按项目过滤会把别人项目的作业当不存在，
 * 界面上说「前面还有 0 个」，实际要等 20 个——那就是在骗用户（`#010-05` 同族：顺序要按消费者
 * 真正用的那一份）。
 *
 * ## `parseable` 只按扩展名
 *
 * 它回答的是「计划 2 的解析器认不认这个后缀」，与 `kind` 是两件事。产物的硬边界由
 * `applyParseAction` 的守卫与 `kind = 产物` 的库约束拦，**不靠这个布尔**。
 */
export interface 材料视图行 {
  id: string
  path: string
  kind: MaterialKind
  status: ParseStatus
  detail: unknown
  queueAhead: number
  factCount: number
  numberCount: number
  parseable: boolean
}

export async function 材料视图(db: Queryable, projectId: string): Promise<材料视图行[]> {
  const rows = rowsOf(
    await db.execute(sql`
      with latest as (
        select distinct on (path) id, path, kind, parse_status, parse_detail
          from auth.case_material
         where project_id = ${projectId}
         order by path, created_at desc, id desc
      ),
      facts as (
        select material_id, count(*)::int as n
          from auth.case_fact_row
         where project_id = ${projectId}
         group by material_id
      ),
      numbers as (
        select material_id, count(distinct 号码)::int as n
          from (
            select material_id, caller as 号码
              from auth.case_fact_row
             where project_id = ${projectId} and caller is not null and caller <> ''
            union
            select material_id, callee
              from auth.case_fact_row
             where project_id = ${projectId} and callee is not null and callee <> ''
            union
            select material_id, counterparty
              from auth.case_fact_row
             where project_id = ${projectId} and counterparty is not null and counterparty <> ''
          ) 号码们
         group by material_id
      ),
      first_job as (
        select distinct on (material_id) material_id, queued_at, id
          from auth.case_ingest_job
         where project_id = ${projectId} and status = '排队中'
         order by material_id, queued_at, id
      ),
      ahead as (
        select f.material_id, count(j.id)::int as n
          from first_job f
          left join auth.case_ingest_job j
            on j.status = '排队中'
           and (j.queued_at, j.id) < (f.queued_at, f.id)
         group by f.material_id
      )
      select l.id, l.path, l.kind, l.parse_status, l.parse_detail,
             coalesce(a.n, 0) as queue_ahead,
             coalesce(f.n, 0) as fact_count,
             coalesce(n.n, 0) as number_count
        from latest l
        left join ahead a on a.material_id = l.id
        left join facts f on f.material_id = l.id
        left join numbers n on n.material_id = l.id
       order by l.path, l.id
    `),
  )

  return rows.map((row) => ({
    id: String(row.id),
    path: String(row.path),
    kind: String(row.kind) as MaterialKind,
    status: String(row.parse_status) as ParseStatus,
    detail: typeof row.parse_detail === "string" ? JSON.parse(row.parse_detail) : (row.parse_detail ?? null),
    queueAhead: Number(row.queue_ahead ?? 0),
    factCount: Number(row.fact_count ?? 0),
    numberCount: Number(row.number_count ?? 0),
    parseable: 可解析表格(String(row.path)),
  }))
}
```

```ts
  projectId: string,
```
```ts
  path: string,
```

```ts
      return { 错误: "盘上找不到这个文件", code: "file_missing", status: 404 }

    if (!(yield* realInside(项目, 绝对)))
      return { 错误: LINK_ESCAPE, code: "bad_request", status: 400 }

    const 字节 = yield* Effect.promise(() => readFile(绝对).catch(() => undefined))
    if (字节 === undefined) return { 错误: "盘上找不到这个文件", code: "file_missing", status: 404 }
    return { 绝对, 字节, 文件名: basename(path) }
  })
}

/** 把 `解析冲突` 收成一句话，其余错误照常抛成 500（不吞）。 */
async function 收冲突<T>(fn: () => Promise<T>): Promise<T | 解析冲突> {
  try {
    return await fn()
  } catch (error) {
    if (error instanceof 解析冲突) return error
    throw error
  }
}

function handleParse(request: HttpServerRequest.HttpServerRequest, deps: Deps) {
  return Effect.gen(function* () {
    const user = yield* 身份
    if (Option.isNone(user)) return HttpServerResponse.empty({ status: 401 })

    const body = yield* 读体(request)
    if (body === undefined) return fail(400, "请求体不是 JSON 对象", "bad_request")

    const projectId = body["projectId"]
    const path = body["path"]
    const action = body["action"]
    if (typeof projectId !== "string" || projectId === "" || !User.isSafePathSegment(projectId))
      return fail(400, "projectId 非法", "bad_request")
    if (typeof path !== "string" || !是项目内相对路径(path))
      return fail(400, "path 必须是项目内的相对路径（/ 分隔）", "bad_request")
    if (!是动作(action)) return fail(400, "action 只能是 入队 / 重新解析 / 取消 / 跳过", "bad_request")

    if ((yield* 成员角色(deps, user.value.id, projectId)) === undefined)
      return fail(403, "不是该项目成员", "forbidden")

    // 取消 / 跳过 在下一个任务接线。先明确拒绝，免得半成品看起来「点了没反应」。
    if (action === "取消" || action === "跳过") return fail(400, "这个动作还没接线", "bad_request")

    const 当前 = yield* Effect.promise(() => getMaterialByPath(deps.pg(), projectId, path))

    // 产物硬边界在**状态机之前**：产物连「重新解析」都不该收到，回一句说得清的话。
    // 「取消」不在硬边界里——它不推进解析，产物本来也不会在排队；真点了就交给下面的
    // 状态机回一句 illegal_transition。
    if (当前?.kind === "产物" && action !== "取消")
      return fail(409, "产物只登记不解析", "artifact_not_parseable")
    // ⚠️ `isRunning` 只拦「再排一次」（入队 / 重新解析）。取消**必须**放过排队中与解析中，
    // 否则右键「取消解析」永远回 409——这正是 Task 4 头两条用例要钉的。
    if (
      当前 !== undefined &&
      (action === "入队" || action === "重新解析") &&
      isRunning(当前.parseStatus)
    )
      return fail(409, "这份文件已经在排队或解析中", "already_running")
    if (当前 !== undefined && !该动作可用(当前.parseStatus, action))
      return fail(409, `现在（${当前.parseStatus}）不能「${action}」`, "illegal_transition")
    if (action === "重新解析" && 当前 === undefined)
      return fail(404, "这份文件还没有解析记录", "material_not_found")
    if (!可解析表格(path)) return fail(409, "这类文件的解析在后续计划", "not_parseable")

    const 读 = yield* 读盘文件(deps, user.value.id, projectId, path)
    if ("错误" in 读) return fail(读.status, 读.错误, 读.code)

    const 结果 = yield* Effect.promise(() =>
      收冲突(() =>
        入队表格材料(deps.pg(), {
          root: deps.root,
          project: projectDirectory(deps.root, user.value.id, projectId),
          target: 读.绝对,
          bytes: 读.字节,
          fileName: 读.文件名,
          by: user.value.id,
          ...(action === "重新解析" ? { force: true } : {}),
        }),
      ),
    )
    if (结果 instanceof 解析冲突) return fail(409, 结果.message, 结果.code)
    if (结果 === undefined) return fail(400, "这个文件不在项目沙箱内，无法入队", "bad_request")
    if (!结果.enqueued)
      return fail(409, "这份文件的状态刚被别的作业改掉，请刷新后再试", "state_changed")

    return ok({ ok: true, status: "排队中" })
  })
}
```

```ts
/**
 * 撤掉一份材料**还在排队**的作业行，返回撤了几条。
 *
 * 只碰 `排队中`：运行中的作业归 worker 的 `runJob` 收尾，这里抢着改会与它互相覆盖
 * （`runJob` 用 `(project_id, id)` 定位，它写的是 `完成` / `失败`）。设计 §8.1 的
 * 「解析中取消」是**材料**落「有问题」、已提交切片保留，作业行仍旧跑完。
 *
 * 材料状态的推进由调用方在同一个事务里做——两笔必须一起提交，否则会出现
 * 「材料回未入队、作业却还在排队」⇒ worker 认领后把它又推回解析中。
 */
export async function 取消排队作业(db: Queryable, projectId: string, materialId: string): Promise<number> {
  const rows = rowsOf(
    await db.execute(sql`
      update auth.case_ingest_job
         set status = '已取消', finished_at = ${nowSeconds()}
       where project_id = ${projectId} and material_id = ${materialId} and status = '排队中'
      returning id
    `),
  )
  return rows.length
}
```

```ts
/**
 * 材料视图与解析动作的客户端（计划 3）。
 *
 * 与 `ai-assets/enable-api.ts` 同一套范式：同源相对路径、可注入的 `send`、10 秒超时、
 * **失败不抛**（收成 `{ kind: "error", message, code? }`）。
 *
 * ## 状态是**闭集**，不认识就整份判错
 *
 * 服务端升级出第七种状态时，前端最坏的行为是「把它画成未入队」——那会让用户对一份已解析的
 * 文件再点一次。`#002-02`：不知道 ≠ 空 / ≠ 未入队。故这里宁可整份回包判错。
 */
export const PATH = {
  materials: "/openhive/case/materials",
  parse: "/openhive/case/parse",
} as const

export const TIMEOUT_MS = 10_000

export const 解析状态们 = ["未入队", "排队中", "解析中", "已解析", "有问题", "已跳过"] as const
export type 解析状态 = (typeof 解析状态们)[number]

export const 人工解析动作们 = ["入队", "重新解析", "取消", "跳过"] as const
export type 人工解析动作 = (typeof 人工解析动作们)[number]

export interface 问题切片 {
  readonly range: string
  readonly reason: string
  readonly count: number
}

export interface 材料问题 {
  readonly reason?: string
  readonly slices?: readonly 问题切片[]
}

export interface 材料视图 {
  readonly id: string
  readonly path: string
  readonly kind: string
  readonly status: 解析状态
  readonly detail: 材料问题 | null
  readonly queueAhead: number
  readonly factCount: number
  readonly numberCount: number
  readonly parseable: boolean
}

export interface 材料清单 {
  readonly materials: readonly 材料视图[]
  readonly parseableExtensions: readonly string[]
}

export type 材料清单结果 =
  | { readonly kind: "ok"; readonly value: 材料清单 }
  | { readonly kind: "error"; readonly message: string; readonly code?: string }

export type 解析结果 =
  | { readonly kind: "ok" }
  | { readonly kind: "error"; readonly message: string; readonly code?: string }

export type CaseMaterialsFetch = (input: string, init?: RequestInit) => Promise<Response>

export interface CaseMaterialsApi {
  readonly read: (projectId: string) => Promise<材料清单结果>
  readonly parse: (input: {
    readonly projectId: string
    readonly path: string
    readonly action: 人工解析动作
  }) => Promise<解析结果>
}

async function 默认发送(input: string, init?: RequestInit): Promise<Response> {
  const 控制器 = new AbortController()
  const 定时器 = setTimeout(() => 控制器.abort(), TIMEOUT_MS)
  try {
    return await fetch(input, { ...init, signal: 控制器.signal })
  } finally {
    clearTimeout(定时器)
  }
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null && !Array.isArray(value)
}

const 是状态 = (value: unknown): value is 解析状态 =>
  typeof value === "string" && (解析状态们 as readonly string[]).includes(value)

const 是动作 = (value: unknown): value is 人工解析动作 =>
  typeof value === "string" && (人工解析动作们 as readonly string[]).includes(value)

function 解析问题(value: unknown): 材料问题 | null | undefined {
  if (value === null) return null
  if (!isRecord(value)) return undefined
  if (value["reason"] !== undefined && typeof value["reason"] !== "string") return undefined
  const 原 = value["slices"]
  const 切片: 问题切片[] = []
  if (原 !== undefined) {
    if (!Array.isArray(原)) return undefined
    for (const 项 of 原) {
      if (!isRecord(项)) return undefined
      if (typeof 项["range"] !== "string") return undefined
      if (typeof 项["reason"] !== "string") return undefined
      if (typeof 项["count"] !== "number") return undefined
      切片.push({ range: 项["range"], reason: 项["reason"], count: 项["count"] })
    }
  }
  return {
    ...(value["reason"] === undefined ? {} : { reason: value["reason"] }),
    ...(原 === undefined ? {} : { slices: 切片 }),
  }
}

function 解析清单(body: unknown): 材料清单 | undefined {
  if (!isRecord(body)) return undefined
  const 原 = body["materials"]
  const 扩展名 = body["parseableExtensions"]
  if (!Array.isArray(原) || !Array.isArray(扩展名)) return undefined
  if (!扩展名.every((item): item is string => typeof item === "string")) return undefined

  const 行们: 材料视图[] = []
  for (const 项 of 原) {
    if (!isRecord(项)) return undefined
    if (typeof 项["id"] !== "string" || typeof 项["path"] !== "string" || typeof 项["kind"] !== "string") return undefined
    if (!是状态(项["status"])) return undefined
    const detail = 解析问题(项["detail"])
    if (detail === undefined) return undefined
    for (const key of ["queueAhead", "factCount", "numberCount"] as const) {
      if (typeof 项[key] !== "number" || !Number.isInteger(项[key]) || 项[key] < 0) return undefined
    }
    if (typeof 项["parseable"] !== "boolean") return undefined
    行们.push({
      id: 项["id"],
      path: 项["path"],
      kind: 项["kind"],
      status: 项["status"],
      detail,
      queueAhead: 项["queueAhead"] as number,
      factCount: 项["factCount"] as number,
      numberCount: 项["numberCount"] as number,
      parseable: 项["parseable"],
    })
  }
  return { materials: 行们, parseableExtensions: 扩展名 }
}

async function 读错误(response: Response, body: unknown): Promise<{ message: string; code?: string }> {
  const 值: Record<string, unknown> = isRecord(body) ? body : {}
  const message = typeof 值["error"] === "string" ? 值["error"] : `请求失败（${response.status}）`
  const code = typeof 值["code"] === "string" ? 值["code"] : undefined
  return code === undefined ? { message } : { message, code }
}

export function createCaseMaterialsApi(send: CaseMaterialsFetch = 默认发送): CaseMaterialsApi {
  const 读 = async (projectId: string): Promise<材料清单结果> => {
    let response: Response
    try {
      response = await send(`${PATH.materials}?projectId=${encodeURIComponent(projectId)}`)
    } catch (error) {
      return { kind: "error", message: error instanceof Error ? error.message : "网络请求失败" }
    }
    let body: unknown
    try {
      body = await response.json()
    } catch {
      return { kind: "error", message: `服务端回了非 JSON（${response.status}）` }
    }
    if (!response.ok) return { kind: "error", ...(await 读错误(response, body)) }
    const 清单 = 解析清单(body)
    if (清单 === undefined) return { kind: "error", message: "服务端回包形状不对" }
    return { kind: "ok", value: 清单 }
  }

  const 解析 = async (input: {
    projectId: string
    path: string
    action: 人工解析动作
  }): Promise<解析结果> => {
    let response: Response
    try {
      response = await send(PATH.parse, {
        method: "POST",
        headers: { "content-type": "application/json" },
        body: JSON.stringify({ projectId: input.projectId, path: input.path, action: input.action }),
      })
    } catch (error) {
      return { kind: "error", message: error instanceof Error ? error.message : "网络请求失败" }
    }
    let body: unknown
    try {
      body = await response.json()
    } catch {
      return { kind: "error", message: `服务端回了非 JSON（${response.status}）` }
    }
    if (!response.ok) return { kind: "error", ...(await 读错误(response, body)) }
    if (!isRecord(body) || body["ok"] !== true) return { kind: "error", message: "服务端回包形状不对" }
    return { kind: "ok" }
  }

  return { read: 读, parse: 解析 }
}
```

```ts
import { createEffect, createRoot, createSignal, getOwner, onCleanup, runWithOwner, untrack } from "solid-js"
import {
  createCaseMaterialsApi,
  type CaseMaterialsApi,
  type 解析状态,
  type 材料视图,
  type 解析结果,
} from "./case-materials-api"

/**
 * 「当前项目的材料解析状态」的唯一读取点（计划 3）。
 *
 * ## 服务端权威
 *
 * 行标记、菜单亮度、目录汇总全部读 `rows()`；操作成功后只 `reload()`，**不本地改状态**。
 * 状态机的落点（排队中取消回未入队、解析中取消落有问题）只有服务端知道，前端猜一次就会漂。
 *
 * ## 旧回包按「项目 + 代次」丢弃
 *
 * 同 `enable-state.ts`：连点两次、或两个项目间来回切，回包顺序不保证。`#008-03`。
 *
 * ## 只在有活的时候轮询
 *
 * 队列是单 worker、2 秒一拍；前端 3 秒拉一次够用。没有「排队中 / 解析中」就**不排下一拍**
 * ——空闲项目不该每 3 秒发一条请求。`轮询器` 可注入：测试用手动轮询，产品用 `setTimeout`。
 */
export interface 轮询器 {
  /** 安排一次；返回取消函数。 */
  安排: (fn: () => void, ms: number) => () => void
}

const 默认轮询器: 轮询器 = {
  安排(fn, ms) {
    const id = setTimeout(fn, ms)
    return () => clearTimeout(id)
  },
}

export interface CaseMaterialsOptions {
  readonly 轮询间隔ms?: number
  readonly 轮询器?: 轮询器
}

export interface CaseMaterials {
  readonly projectId: () => string | undefined
  readonly rows: () => readonly 材料视图[]
  readonly parseableExtensions: () => readonly string[]
  readonly loaded: () => boolean
  readonly error: () => string | undefined
  readonly bind: (读: () => string | undefined) => void
  readonly parse: (path: string, action: "入队" | "重新解析" | "取消" | "跳过") => Promise<解析结果>
  readonly reload: () => void
}

const 运行中 = (status: 解析状态) => status === "排队中" || status === "解析中"

export function createCaseMaterials(
  api: CaseMaterialsApi = createCaseMaterialsApi(),
  options: CaseMaterialsOptions = {},
): CaseMaterials {
  const 轮询器 = options.轮询器 ?? 默认轮询器
  const 间隔 = options.轮询间隔ms ?? 3000

  const [项目, set项目] = createSignal<string | undefined>()
  const [行们, set行们] = createSignal<readonly 材料视图[]>([])
  const [扩展名们, set扩展名们] = createSignal<readonly string[]>([])
  const [已读, set已读] = createSignal(false)
  const [错误, set错误] = createSignal<string | undefined>()

  let 代次 = 0
  let 停轮询: (() => void) | undefined

  const 停掉轮询 = () => {
    停轮询?.()
    停轮询 = undefined
  }

  const 清空 = () => {
    代次 += 1
    停掉轮询()
    set行们([])
    set扩展名们([])
    set已读(false)
    set错误(undefined)
  }

  const 排下一拍 = (projectId: string) => {
    停掉轮询()
    if (!行们().some((row) => 运行中(row.status))) return
    停轮询 = 轮询器.安排(() => {
      if (项目() !== projectId) return
      拉(projectId)
    }, 间隔)
  }

  /**
   * 拉一次。
   *
   * `保留错误 = true`：失败后补的那次重拉用它——刚发生的那条操作错误不能被一次成功重拉
   * 抹掉（用户还在看它），也不能被重拉自己的失败盖住（同 `enable-state.ts`）。
   */
  const 拉 = (projectId: string, 保留错误 = false) => {
    const 本次 = ++代次
    停掉轮询()
    void api
      .read(projectId)
      .then((结果) => {
        if (本次 !== 代次 || 项目() !== projectId) return
        set已读(true)
        if (结果.kind === "ok") {
          set行们(结果.value.materials)
          set扩展名们(结果.value.parseableExtensions)
          if (!保留错误) set错误(undefined)
          排下一拍(projectId)
          return
        }
        if (!保留错误) set错误(结果.message)
      })
      .catch(() => {
        if (本次 !== 代次 || 项目() !== projectId) return
        set已读(true)
        if (!保留错误) set错误("加载解析状态失败")
      })
  }

  let 停旧: (() => void) | undefined

  const bind = (读: () => string | undefined) => {
    停旧?.()
    // 同 `enable-state.ts`：`createRoot` 会把 effect 从调用方 owner 上摘下来，必须在调用方
    // owner 上再登记一次清理，组件卸载时才拆得掉。
    const 上级 = getOwner()
    const 拆 = createRoot((dispose) => {
      // 轮询的 `setTimeout` 不在 effect 的清理域里：不显式挂一笔，组件卸载后它还会醒一次、
      // 对着已销毁的 owner 发请求。挂在**内层 root** 上，`bind` 重绑与组件卸载都会走到。
      onCleanup(停掉轮询)
      createEffect(() => {
        const 当前 = 读()
        const 换了项目 = 当前 !== untrack(项目)
        set项目(当前)
        // 换项目必须整体复位：跨项目沿用旧行会让界面把甲的状态画在乙的文件上。
        if (换了项目) 清空()
        if (当前 === undefined) return
        拉(当前)
      })
      return dispose
    })
    停旧 = 拆
    if (上级 !== null) runWithOwner(上级, () => onCleanup(拆))
  }

  const 解析 = async (path: string, action: "入队" | "重新解析" | "取消" | "跳过"): Promise<解析结果> => {
    const projectId = 项目()
    if (projectId === undefined) return { kind: "error", message: "还没有选项目" }
    return api.parse({ projectId, path, action })
  }

  const reload = () => {
    const projectId = 项目()
    if (projectId === undefined) return
    拉(projectId)
  }

  return {
    projectId: 项目,
    rows: 行们,
    parseableExtensions: 扩展名们,
    loaded: 已读,
    error: 错误,
    bind,
    parse: 解析,
    reload,
  }
}
```

```ts
import type { 材料视图, 解析状态 } from "./case-materials-api"

/**
 * 左栏文件视图的**全部纯规则**（计划 3 · 设计 §8.1）。
 *
 * 这一层不碰 Solid、不碰网络：标记形状、悬停文案、目录汇总、菜单亮灯都从这里取。
 * 组件只负责把结果画出来——同一句话在行与菜单里各写一份，迟早只改一处（`#002-06`）。
 */

export type 标记形状 = "half" | "check" | "alert" | undefined

export function 标记形状(status: 解析状态): 标记形状 {
  switch (status) {
    case "排队中":
    case "解析中":
      return "half"
    case "已解析":
      return "check"
    case "有问题":
      return "alert"
    case "未入队":
    case "已跳过":
      return undefined
  }
}

const 运行中 = (status: 解析状态 | undefined) => status === "排队中" || status === "解析中"

export function 可解析路径(path: string, extensions: readonly string[]): boolean {
  const 低 = path.toLowerCase()
  return extensions.some((扩展名) => 低.endsWith(扩展名.toLowerCase()))
}

/**
 * 行标记的悬停 / 读屏文案（用户 2026-11-06 裁定，逐字）。
 *
 * - 已解析：「已解析 · N 条事实 · M 个号码」——号码数由服务端按 caller/callee/counterparty
 *   去重算出；「N 人」等实体计数要等计划 6，这里**不编**。
 * - 排队中：「排队中，前面还有 N 个」。
 * - 有问题：优先说 `reason`；其次说切片段数；都没有就**不编数字**。
 * - 未入队 / 已跳过：不画标记，靠这句话说清是「你跳过的」还是「系统不解析」。
 */
export function 悬停文案(row: 材料视图, extensions: readonly string[]): string {
  switch (row.status) {
    case "已解析":
      return `已解析 · ${row.factCount} 条事实 · ${row.numberCount} 个号码`
    case "排队中":
      return `排队中，前面还有 ${row.queueAhead} 个`
    case "解析中":
      return "正在解析，已提交的结果会保留"
    case "有问题": {
      const reason = row.detail?.reason
      if (typeof reason === "string" && reason !== "") return reason
      const 段数 = row.detail?.slices?.length ?? 0
      if (段数 > 0) return `有 ${段数} 段未通过校验，点击查看`
      return "解析没通过，点击查看"
    }
    case "已跳过":
      return "已跳过 · 你手动跳过了解析"
    case "未入队":
      if (row.kind === "产物" || !可解析路径(row.path, extensions) || !row.parseable)
        return "未入队 · 系统不解析这类文件"
      return "未入队 · 右键「解析」可入库"
  }
}

/** 子菜单触发项右边的当前状态（不是标记；目录说「文件夹」，没接入说「未接入」）。 */
export function 状态文案(input: {
  row?: 材料视图
  isFile: boolean
  loaded: boolean
  接入: boolean
  有对象: boolean
}): string {
  if (!input.接入) return "未接入"
  if (!input.有对象) return ""
  if (!input.isFile) return "文件夹"
  if (!input.loaded) return "读取中"
  return input.row?.status ?? "未入队"
}

export interface 目录汇总 {
  已解析: number
  总数: number
  有问题: number
}

const 空汇总 = (): 目录汇总 => ({ 已解析: 0, 总数: 0, 有问题: 0 })

/**
 * 每个目录（含根 `""`）下**会被解析的材料**汇总。
 *
 * 只算表格扩展名、排除产物：目录行上的 `3/12` 回答的是「这个文件夹里的表格解析了几份」，
 * 把 PDF 或产物算进去会让分母永远对不上用户的理解。
 *
 * ⚠️ 输入必须是**全量清单**（`props.paths`），不是可见行（`行列表`）：搜索 / 折叠时目录
 * 里的文件看不见，但汇总不能说谎（用户要求：即使行不可见，未解析数也必须对）。
 */
export function 汇总全部(
  文件们: readonly string[],
  行们: readonly 材料视图[],
  extensions: readonly string[],
): Map<string, 目录汇总> {
  const 汇 = new Map<string, 目录汇总>()
  const 行表 = new Map(行们.map((row) => [row.path, row]))
  const 见过 = new Set<string>()

  for (const path of 文件们) {
    if (path.endsWith("/")) continue // 目录条目
    if (见过.has(path)) continue
    见过.add(path)
    if (!可解析路径(path, extensions)) continue
    const row = 行表.get(path)
    if (row?.kind === "产物") continue

    const 状态 = row?.status ?? "未入队"
    const 加 = (目录: string) => {
      const 当前 = 汇.get(目录) ?? 空汇总()
      当前.总数 += 1
      if (状态 === "已解析") 当前.已解析 += 1
      if (状态 === "有问题") 当前.有问题 += 1
      汇.set(目录, 当前)
    }

    加("")
    let 段 = ""
    const 片 = path.split("/")
    for (const 名 of 片.slice(0, -1)) {
      段 = 段 === "" ? 名 : `${段}/${名}`
      加(段)
    }
  }
  return 汇
}

/**
 * 右键一个文件夹时**会真正入队**的文件（用户确认弹窗里的 N）。
 *
 * 候选 = 未入队 / 有问题 / 没有材料行（还没登记过）。
 *
 * ⚠️ **「已跳过」不进候选**（2026-11-06 裁定）：设计 §5.2 说跳过是人的意志、系统不再问；
 * 用户逐份跳过的文件，不该被一次「解析这个文件夹」悄悄翻回来。单文件右键仍可对「已跳过」
 * 点「解析入库」——那是对**这一份**的明确动作。因此本函数与服务端的「该走哪个动作」**故意
 * 不一致**：后者见到「已跳过」返回「入队」，这里不选它。服务端不提供批量出口也是这个原因，
 * 别在服务端加一个「按状态全集扫」的批量接口（见 Task 7 注释）。
 *
 * 其余判据与「该走哪个动作」一致：已解析、排队中、解析中不排（`enqueueMaterial` 对它们
 * 返回 `enqueued: false`）。非表格与产物不排。
 */
export function 目录下待入队(
  目录: string,
  文件们: readonly string[],
  行们: readonly 材料视图[],
  extensions: readonly string[],
): readonly string[] {
  const 前缀 = 目录 === "" ? "" : `${目录}/`
  const 行表 = new Map(行们.map((row) => [row.path, row]))
  const 结果: string[] = []
  const 见过 = new Set<string>()

  for (const path of 文件们) {
    if (path.endsWith("/")) continue
    if (path === 目录 || !path.startsWith(前缀)) continue
    if (见过.has(path)) continue
    见过.add(path)
    if (!可解析路径(path, extensions)) continue
    const row = 行表.get(path)
    if (row?.kind === "产物") continue
    if (row !== undefined && (row.status === "已解析" || row.status === "已跳过" || 运行中(row.status))) continue
    结果.push(path)
  }
  return 结果
}

/**
 * 菜单五项亮不亮的**唯一依据**。所有原因函数都先过三句公共闸：接入、有对象、是文件。
 * `undefined` = 亮。
 */
export interface 亮灯依据 {
  readonly path: string
  readonly isFile: boolean
  readonly row: 材料视图 | undefined
  readonly extensions: readonly string[]
  readonly rowsLoaded: boolean
  readonly 接入: boolean
  readonly 有对象: boolean
  readonly hasReview: boolean
}

const 未接入 = "解析状态还没接上"
const 无对象 = "右键一个文件或文件夹再用"
const 只针对文件 = "这一项只针对单个文件"
const 产物 = "产物只登记不解析"
const 后续计划 = "该类型的解析在后续计划"
const 在跑 = "这份文件已经在排队或解析中"

export function 入队不可用原因(b: 亮灯依据): string | undefined {
  if (!b.接入) return 未接入
  if (!b.有对象) return 无对象
  // 目录一律放行到确认弹窗：候选为 0 时由弹窗正文解释、确认键置灰。
  // 不在菜单项上直接灰掉——灰项的说明用户看不到，看起来就像「菜单坏了」。
  if (!b.isFile) return undefined
  if (b.row?.kind === "产物") return 产物
  if (!可解析路径(b.path, b.extensions)) return 后续计划
  if (运行中(b.row?.status)) return 在跑
  if (b.row?.status === "已解析") return "已经解析过了，要重来请用「重新解析」"
  return undefined
}

export function 重新解析不可用原因(b: 亮灯依据): string | undefined {
  if (!b.接入) return 未接入
  if (!b.有对象) return 无对象
  if (!b.isFile) return 只针对文件
  if (b.row?.kind === "产物") return 产物
  if (!可解析路径(b.path, b.extensions)) return 后续计划
  if (运行中(b.row?.status)) return 在跑
  if (b.row === undefined) return "这份文件还没有解析记录"
  if (b.row.status !== "已解析" && b.row.status !== "有问题") return "还没有解析过"
  return undefined
}

export function 取消不可用原因(b: 亮灯依据): string | undefined {
  if (!b.接入) return 未接入
  if (!b.有对象) return 无对象
  if (!b.isFile) return 只针对文件
  if (!运行中(b.row?.status)) return "这份文件现在没有在排队或解析"
  return undefined
}

export function 跳过不可用原因(b: 亮灯依据): string | undefined {
  if (!b.接入) return 未接入
  if (!b.有对象) return 无对象
  if (!b.isFile) return 只针对文件
  if (b.row?.kind === "产物") return 产物
  if (运行中(b.row?.status)) return "正在排队或解析中，先取消再跳过"
  if (b.row?.status === "已解析") return "已经解析过了，不能跳过"
  return undefined
}

export function 查看不可用原因(b: 亮灯依据): string | undefined {
  if (!b.接入) return 未接入
  if (!b.有对象) return 无对象
  if (!b.isFile) return 只针对文件
  if (!b.hasReview) return "抽取结果面板在后续计划"
  if (b.row === undefined || (b.row.status !== "已解析" && b.row.status !== "有问题"))
    return "这份文件还没有抽取结果"
  return undefined
}
```

```tsx
import { useDialog } from "@opencode-ai/ui/context/dialog"
import { ButtonV2 } from "@opencode-ai/ui/v2/button-v2"
import { DialogV2, DialogBody, DialogFooter, DialogHeader, DialogTitle } from "@opencode-ai/ui/v2/dialog-v2"
import { createSignal, Show, type JSX } from "solid-js"
import { FileOpError } from "./file-op-error"

/**
 * 解析动作的二次确认（计划 3 · 设计 §8.1）。
 *
 * 两条链共用：文件夹「将解析这个文件夹下的 N 个文件」与单文件「重新解析会重建全部事实」。
 * 壳与 `FileDeleteDialog` 同一套（`useDialog` ＋ `DialogV2`），焦点默认落在「取消」上
 * ——这两个动作都会覆盖已有结果（文件夹会把候选逐个入队；重新解析会删旧事实）。
 *
 * 回话约定同删除弹窗：**回一句字符串 = 没办成**，那句话就地显示、弹窗不关；`undefined` = 收工。
 */
export interface ParseConfirmDialogProps {
  标题: string
  正文: string
  确认文案: string
  /**
   * 确认按钮置灰（文件夹候选为 0 时）。灰着也**必须**把原因写进 `正文`——
   * 只灰不说，用户会以为界面卡了。
   */
  禁用?: boolean
  onConfirm: () => string | undefined | Promise<string | undefined | void>
}

export function ParseConfirmDialog(props: ParseConfirmDialogProps): JSX.Element {
  const dialog = useDialog()
  const [失败话, set失败话] = createSignal<string | undefined>()
  const [忙, set忙] = createSignal(false)

  async function 确定() {
    if (忙()) return
    set忙(true)
    let 回话: string | undefined | void
    try {
      回话 = await props.onConfirm()
    } catch {
      // 调用方正常情况下不会抛（两个出口都把失败收成字符串或 toast），这里只兜底：
      // **不**把异常抛回事件系统（那会变成一条无人接的 rejection、弹窗还开着）。
      回话 = "操作没办成，请重试"
    } finally {
      set忙(false)
    }
    if (typeof 回话 !== "string") {
      dialog.close()
      return
    }
    set失败话(回话)
  }

  return (
    <DialogV2 class="w-[min(26rem,calc(100vw-3rem))]">
      <div data-slot="parse-confirm-dialog" class="contents">
        <DialogHeader>
          <DialogTitle>{props.标题}</DialogTitle>
        </DialogHeader>
        <DialogBody class="flex w-full flex-col gap-2 px-4 pt-4 pb-2">
          <p data-slot="parse-confirm-body" class="min-w-0 text-[13px] text-v2-text-text-base">
            {props.正文}
          </p>
          <Show when={失败话()}>{(话) => <FileOpError 话={话()} />}</Show>
        </DialogBody>
        <DialogFooter>
          <ButtonV2 autofocus data-slot="parse-confirm-cancel" variant="neutral" onClick={() => dialog.close()}>
            取消
          </ButtonV2>
          <ButtonV2
            data-slot="parse-confirm-ok"
            variant="contrast"
            disabled={忙() || props.禁用 === true}
            onClick={() => void 确定()}
          >
            {props.确认文案}
          </ButtonV2>
        </DialogFooter>
      </div>
    </DialogV2>
  )
}
```

```ts
   * 文件夹解析：先确认，再**逐个**发入队。
   *
   * ## 为什么没有批量接口
   *
   * 逐个而不是批量是**有意的**：服务端一次收一个文件（与上传同一条约定），按文件分开的
   * 成败在界面上好交代。**不要**为了省几个请求在服务端加批量出口——一旦有了批量接口，
   * 它迟早会被写成「按状态全集扫」，把「已跳过」也一起翻回来（候选口径在
   * `目录下待入队` 里，见那里的注释）。批量只活在前端这一层。
   *
   * 失败即中断：后面的文件不再发，已发出的不回滚（入队幂等），收尾统一 `reload()`，
   * 界面按服务端的真实状态刷新，弹窗关闭、toast 说清。
   *
   * ## 候选为 0
   *
   * 仍然弹窗，但确认键置灰、正文说清为什么——直接 `return` 会让用户以为右键菜单没反应。
   */

    if (状态 === undefined) return
    const 候选 = 目录下待入队(目录, 全部(), 状态.rows(), 扩展名())
    if (候选.length === 0) {
      void dialog.show(() => (
        <ParseConfirmDialog
          标题="解析这个文件夹"
          正文="这个文件夹下没有需要入队的表格（已跳过的文件请用它的单文件右键菜单恢复）"
          确认文案="解析"
          禁用
          onConfirm={() => undefined}
        />
      ))
      return
    }
    void dialog.show(() => (
      <ParseConfirmDialog
        标题="解析这个文件夹"
        正文={`将解析这个文件夹下的 ${候选.length} 个文件`}
        确认文案="解析"
        onConfirm={async () => {
          let 成 = 0
          for (const path of 候选) {
            const 结果 = await 状态.parse(path, "入队")
            if (结果.kind === "error") {
              showToast({
                variant: "error",
                title: "文件夹解析中断",
                description: `第 ${成 + 1} 个文件没能入队：${结果.message}`,
              })
              break
            }
            成 += 1
          }
          // 不管成与败都按服务端真实状态重拉：已发出的入队已经生效，界面不能停在旧快照上。
          状态.reload()
          if (成 > 0) showToast({ variant: "success", title: `已加入解析队列（${成} 个文件）` })
          // 永远回 undefined：失败已经用 toast 说清，弹窗不该停在「再点一次会把已入队的重发」的状态
          return undefined
        }}
      />
    ))
  }

  function 成功文案(action: 人工解析动作) {
    switch (action) {
      case "入队":
      case "重新解析":
        return "已加入解析队列"
      case "取消":
        return "已取消解析"
      case "跳过":
        return "已跳过这份文件"
    }
  }
```

- `CaseMaterials.parse(path, action)` 返回 `解析结果`；Task 7 的 `执行解析` 只读 `kind` / `message`。
- `标记形状` 返回 `"half" | "check" | "alert" | undefined`；`CaseStatusBadge` 的 `data-shape` 用同一组值。
- `目录汇总` 的键 `已解析/总数/有问题` 在 Task 6 的测试与 Task 7 的渲染里逐字一致。
- `ContextMenu.Sub/SubTrigger/SubContent` 是 `packages/ui/src/components/context-menu.tsx` 已导出的原语（第 289-308 行），不是新造的。

### 4. 已知缺口（计划内不修，交付时随报告一起说）

1. **产物识别不在本计划**：新生成的表格类产物仍会被上传路径自动入队；计划 4/5 才补「生成物 = 产物」的判定。目前靠 `kind=产物` 的既有行拦，生成那一刻拦不住。
2. **「N 人」等实体计数**：悬停文案只报「事实数 / 号码数」；实体去重计数要等计划 6。
3. **「有 N 段未通过校验」的 N 目前没有生产者**：`parse_detail.slices` 的迁移注释约定了形状，但计划 2 的 `runJob` 只写 `{reason}`。前端按「reason → slices → 通用句」三支实现，第三支今天只会走到通用句。
4. **真栈走查未做**：本计划只到组件 / 真应用测试；3 秒轮询、真实 worker 的 2 秒节拍、Kobalte 子菜单在真浏览器的位置，都要在真栈验收时另跑（`#006-31`：组件绿 ≠ 真栈绿）。
5. **同一路径可能有多条材料行**（内容变了会另建）：视图取最新一行，旧行的历史事实不计入统计，也不在界面上展示。
6. **内容相同的两个文件会合并成一条材料**（幂等键是 `(project_id, fingerprint)`）：这是计划 2 的既定行为，本计划不区分「同一份内容的两条路径」。
7. **文件夹批量不覆盖「已跳过」**：候选口径是「未入队 / 有问题 / 无行」，已跳过被有意排除（跳过是人的意志，设计 §5.2）。想恢复某份被跳过的文件，用它的**单文件右键菜单**点「解析入库」；将来若需要「全部恢复」，另开入口，不要把它塞回文件夹批量。服务端**不提供批量出口**也是有意为之：批量只在前端逐个发，避免以后有人加批量接口时按状态全集扫、把这个排除规则丢掉。
8. **「查看解析结果」在计划 3 恒灰**：`onReviewParse` 的接缝有单测，但生产没有中栏接收方。菜单项由 Kobalte `disabled` 渲染出 `aria-disabled="true"`（测试已断言），并在**项内**写一行看得见的理由「抽取结果面板在后续计划」——不用原生 `title`，禁用项带 `pointer-events: none`，气泡永远不弹。Kobalte 的 `disabled` 同时把它从菜单的键盘焦点序列里跳过，所以 Tab / 方向键不会停在一个点不动的项上；真浏览器的键盘走查仍归真栈验收（见缺口 4）。计划 7 接上接收方之后自动亮。
9. **解析中取消时 worker 可能仍跑完**：`取消排队作业` 只撤 `排队中`；运行中的作业由 `runJob` 自己收尾（它可能写「完成」或「失败」）。材料落「有问题」＋「用户取消」是设计要的，但事实层可能包含取消之后才落的一小段。
10. **手动入队没有文件大小闸**：上传路径有大小限制，右键解析直接读盘并算 sha256；超大文件会占内存。计划 2 的既有缺口，本计划不新增闸。
11. **`queued_by` 的语义**：`applyParseAction` 在「入队」或「跳过」时把材料的 `queued_by` 更新为操作人；「重新解析」只把操作人写在**作业行**上（材料行保持上一次的人）；取消 / 完成 / 出问题都**不清空**它。理由：设计 §8.1 要求每次人工解析动作都能回溯到人，而「跳过」不建作业行，材料行是唯一落点。
12. **文件夹批量不可中途取消**：确认之后逐个发请求，用户关不掉进行中的循环；失败即中断，**已发出的不回滚**（入队幂等，重发同一条不会重复排队），结束统一 `reload()`，界面按服务端的真实状态刷新——不做本地乐观回滚，免得界面和服务端各说一套。

#### 计划执行期新发现的缺口（收尾裁定，不修）

13. **`queueAhead` 只数「排队中」的作业**：它是「我前面还有几份在排队」，不是含当前作业在内的剩余时长；前端文案据此只说「前面还有 N 个」，不换算分钟。
14. **`材料视图()` 的 `numbers` 全项目扫描、`latest` 缺索引**：材料数百条时存在已知慢查询风险；真栈实测后再决定是否单开一条迁移，不凭推测加索引。
15. **`case-parse.ts` handler 自身的 401 分支无测试**：实际的门是全局身份中间件，handler 里这一支属纵深防御，单独构造它要把中间件绕开，收益不抵成本。
16. **前端轮询遇一次失败即停**：不无限重试（避免把后端打崩），用户需做一次操作触发 `reload()` 才能恢复轮询。
17. **首屏到第一次回包之间五盏灯全灰**：此时 `loaded()` 还是 `false`，不可用原因一律是「解析状态还在读取，请稍候」——不下推演、不猜状态。
18. **目录汇总 `N/M` 的分母含「已跳过」**：分母是「会被解析的表格总数」（排除不可解析与产物），已跳过的表格仍在分母里；由行上的「已跳过」文案解释，不在数字里再拆一层。
19. **单文件直发无重入保护**：选中菜单项即关菜单，慢网连点的风险低，故不另建进行中闸。
