**Goal:** 让所有「涉及人」的查询结果诚实落在**已核实 / 户名匹配 / 无匹配**三档之一（设计 §3.8.4，A11），并让「问一个只有户名的名字」能解析到账户、答出「户名为 X 的账户（未核实身份）」；「0 笔」四分类（§3.8.5，A12）已在 P1 落地，本期只做回归门禁，不重写。

**关键裁定（执行时照此，不再来回讨论）：**

1. **三档描述「身份核实程度」，不是只给账户打标。**
   - `已核实` = 有至少一条**未排除**的 `实名登记` 边，且边的一端是 `type='人'`、另一端不是人（M3 焊死）。查询实体自己是「人」且有这样的边也算已核实。
   - `户名匹配` = 没有实名登记证据，但有名字：账户有未撤销的 `kind='户名'` 别名；或查询实体本身就是「人」（姓名即唯一身份线索，笔录抽出的「人」实体就是这种）。
   - `无匹配` = 连名字证据都没有（账户无户名、号码无实名登记）。文案明确「查不到归属」，不给近似值。
2. **`解析实体` 的解析顺序不变**：id → 规范值 → 户名别名；别名**精确等值**（不 trim、不 ilike、不做相似）。
3. **户名对应多个账户 ⇒ fail-closed**：抛 `工具错误("bad_input")`，消息列出候选账号并让调用方改用账号查询。**不挑一个**（M4 的唯一性候选要人点一次，本期不做）。
4. **`解析账户` 在账户语境下优先按户名找账户**：先走 `解析实体`；命中的不是账户（例如同名「人」实体）时，再用户名别名找账户，找到就用账户。理由：§3.8.1「查询按账户组织」，否则问「张三的流水」会在人实体上算 0 笔，错得像个正确答案。
5. **`query_relations` / `query_events` 未给查询实体时不逐端标注**（结果是边的列表，没有查询主体）；只给「查询主体」标。此扩展登记为缺口。

```ts
export * as OpenhiveCaseIdentity from "./case-identity"

/**
 * 身份三档（设计 §3.8.4）：任何涉及「人」的查询结果必须落在
 * 已核实 / 户名匹配 / 无匹配 之一。
 *
 * 判据是**证据**，不是名字像不像：
 * - 已核实   = 有一条未排除的 `实名登记` 边把实体焊到人上（M3）；
 * - 户名匹配 = 没有实名登记边，只有名字（账户上未撤销的 `kind='户名'` 别名；
 *              或「人」实体本身——笔录抽出的「人」实体就是一个名字）；
 * - 无匹配   = 连名字证据都没有，只能明说「查不到归属」。
 *
 * 不做姓名相似匹配（§3.8.3）：同名多账户由解析层 fail-closed，不在这里挑一个。
 */
export const 身份档们 = ["已核实", "户名匹配", "无匹配"] as const
export type 身份档 = (typeof 身份档们)[number]

export interface 身份判读 {
  readonly 档: 身份档
  /** 人话，含判据与查到了什么；户名匹配档必须含「未核实身份」字样。 */
  readonly 说明: string
}

export interface 身份标注 extends 身份判读 {
  /** 被标注实体的规范值（展示行）。 */
  readonly 实体: string
}

export interface 身份证据 {
  readonly 类型: string
  readonly 值: string
  /** 该实体上未撤销的 `kind='户名'` 别名值（账户才有）。 */
  readonly 户名们: readonly string[]
  /**
   * 经未排除的 `实名登记` 边连到的「人」的规范值。
   * 实体自己是「人」且有边时，人证就是它自己（说明里不重复点名）。
   */
  readonly 人证们: readonly string[]
}

/** 三档的读侧口径，五个工具共用一份（`#002-06`：同一前提不两处各写）。 */
export const 身份口径 =
  "涉及人的结果按身份三档标注（已核实 / 户名匹配 / 无匹配）：已核实=有未排除的实名登记证据；" +
  "户名匹配=只有名字、未核实身份；无匹配=查不到归属。户名匹配与无匹配不得当作本人。"

const 最多列人 = 3

function 列人证(人证们: readonly string[]): string {
  const 前 = 人证们.slice(0, 最多列人)
  return 人证们.length > 最多列人 ? `${前.join("、")} 等 ${人证们.length} 人` : 前.join("、")
}

export function 判定身份(证据: 身份证据): 身份判读 {
  if (证据.人证们.length > 0) {
    if (证据.类型 === "人")
      return { 档: "已核实", 说明: `已核实：「${证据.值}」已有实名登记账户证据，身份链完整` }
    return {
      档: "已核实",
      说明: `已核实：该${证据.类型}经「实名登记」证据关联到人「${列人证(证据.人证们)}」`,
    }
  }
  if (证据.类型 === "人")
    return {
      档: "户名匹配",
      说明: `只知道姓名「${证据.值}」，没有身份证号或实名登记证据，未核实身份`,
    }
  if (证据.类型 === "账户" && 证据.户名们.length > 0)
    return {
      档: "户名匹配",
      说明:
        `户名匹配，未核实身份：该账户登记在「${证据.户名们.join("、")}」名下，` +
        "但没有身份证号等实名登记证据，不能当作本人",
    }
  return {
    档: "无匹配",
    说明:
      证据.类型 === "账户"
        ? "查不到归属：该账户没有任何户名或实名登记证据，不能断定是谁的"
        : `查不到归属：该${证据.类型}没有任何户名或实名登记证据`,
  }
}
```

export interface 实体解析 {
  readonly id: string
  readonly value: string
  readonly type: string
  readonly ids: string[]
  /** 解析到的途径：id / 规范值 / 户名（A11 的「户名为 X 的账户」据此措辞）。 */
  readonly 命中: "id" | "规范值" | "户名"
}

/**
 * 按户名找账户（M2）：**精确等值**、不做相似匹配（§3.8.3）。
 *
 * 同一户名对应多个账户 ⇒ `bad_input` 列出候选。M4 的「唯一性候选」要人点一次采纳，
 * 本期不做；在此之前不许挑一个冒充答案（§3.8.4「无匹配不给近似值」）。
 *
 * 别名行按 (project_id, kind, value) 有索引（0039）；账户被「已排除」时不参与。
 */
export async function 解析户名(
  ctx: 工具上下文,
  值: string,
): Promise<{ id: string; value: string; type: string; ids: string[]; 命中: "户名" } | undefined> {
  const 行们 = rowsOf(
    await ctx.db.execute(sql`
      select e.id, e.type, e.canonical_value
        from auth.case_entity e
        join auth.case_entity_alias a
          on a.project_id = e.project_id and a.entity_id = e.id
       where e.project_id = ${ctx.身份.projectId}
         and a.kind = '户名' and a.value = ${值} and a.revoked_at is null
         and e.trust_state <> '已排除'
       order by e.created_at desc, e.type asc, e.id asc
    `),
  )
  const 按id = new Map<string, Record<string, unknown>>()
  for (const 行 of 行们) {
    const id = String(行.id)
    if (!按id.has(id)) 按id.set(id, 行)
  }
  const 候选 = [...按id.values()]
  if (候选.length === 0) return undefined
  if (候选.length > 1) {
    const 前 = 候选.slice(0, 5).map((行) => String(行.canonical_value))
    const 尾巴 = 候选.length > 5 ? ` 等 ${候选.length} 个` : ""
    throw new 工具错误(
      "bad_input",
      `户名「${值}」在本项目对应 ${候选.length} 个账户（${前.join("、")}${尾巴}），` +
        "无法确定是哪一个；请改用账号查询",
    )
  }
  const 唯一 = 候选[0]!
  return {
    id: String(唯一.id),
    value: String(唯一.canonical_value),
    type: String(唯一.type),
    ids: [String(唯一.id)],
    命中: "户名",
  }
}

export async function 解析实体(
  ctx: 工具上下文,
  值: string,
  称呼: string,
): Promise<实体解析> {
  const rows = rowsOf(
    await ctx.db.execute(sql`
      select id, type, canonical_value from auth.case_entity
       where project_id = ${ctx.身份.projectId} and (id = ${值} or canonical_value = ${值})
       order by (id = ${值}) desc, created_at desc, (type = '人') asc, type asc, id asc
    `),
  )
  const 行 = rows[0]
  if (行 !== undefined) {
    const id = String(行.id)
    const ids =
      id === 值
        ? [id]
        : rows.filter((行) => String(行.canonical_value) === 值).map((行) => String(行.id))
    return { id, value: String(行.canonical_value), type: String(行.type), ids, 命中: id === 值 ? "id" : "规范值" }
  }
  const 户名 = await 解析户名(ctx, 值)
  if (户名 !== undefined) return 户名
  throw new 工具错误("not_found", `本项目里找不到${称呼}：${值}`)
}

/** 查询主体的人话称呼：按户名解析到时写「户名为「X」的账户」（A11）。 */
export function 实体称呼(解析: { readonly 命中: "id" | "规范值" | "户名" }, 输入: string): string {
  return 解析.命中 === "户名" ? `户名为「${输入}」的账户` : `「${输入}」`
}

/**
 * 摘要末尾的身份后缀：已核实不打扰；另两档必须显著（§3.8.4）。
 * 多实体时带实体名，避免「甲是哪一档、乙是哪一档」说不清。
 */
export function 身份后缀(标注s: readonly 身份标注[]): string {
  const 未核实 = 标注s.filter((a) => a.档 !== "已核实")
  if (未核实.length === 0) return ""
  const 逐 = 未核实.map((a) => {
    const 档词 = a.档 === "户名匹配" ? "户名匹配，未核实身份" : "查不到归属，未核实身份"
    return 标注s.length > 1 ? `${a.实体}：${档词}` : 档词
  })
  return `（${逐.join("；")}）`
}
