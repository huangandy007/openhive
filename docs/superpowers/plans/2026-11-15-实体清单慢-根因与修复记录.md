# 实体清单慢：根因与修复记录

> 日期：2026-11-15
> 触发：真栈左栏实体面板读不出来（客户端 10s 超时）
> 性质：加固/修 bug（工作区 CLAUDE.md 六步轨道）
> 教训：`LEARNINGS #013-11`

## 1. 现象（用户可见）

真栈（kernel 4711 / front 3010 / 远端 PG `openhive_dev`）里 `GET /openhive/case/entities`
墙钟 **14.6–56s**；前端 `packages/app/src/project/entity-api.ts` 的 `TIMEOUT_MS = 10_000`
到点 abort，左栏实体 tab 一直是空面板（只看到「读取超时（10 秒），请稍后重试」）。

## 2. 取证（第 ① 步：用证据定根因）

### 2.1 表规模与单条延迟（排除「数据量」）

| 项 | 行数 | 单条 `count(*)` |
|---|---|---|
| `auth.case_entity` | 5,407 | 23–27ms（网络 RTT 主导） |
| `auth.case_relation` | 5,252 | 同上 |
| `auth.case_event` | 5,905 | 同上 |
| 本项目（`f77bb723-…`） | 14 / 8 / 8 | 同上 |

### 2.2 DAO 逐函数计时（远端真库）

| 函数 | 墙钟（`jit = on`，默认） | 墙钟（`jit = off`） |
|---|---|---|
| `分组计数` | **7,601ms** | **88ms** |
| `实体清单` | **14,318ms** | **109ms** |

结果一致：`{"核心":7,"提及":7}`、7 行。

### 2.3 `EXPLAIN (ANALYZE, BUFFERS)`（决定性证据）

| 语句 | 估计代价 | 计划节点数 | 全部节点 actual time 合计 | `JIT:` 行 | 墙钟 |
|---|---|---|---|---|---|
| `分组计数` | 25,510,361 | 198 | ~10ms | **7,146ms**（优化 4,137 + 发射 2,888） | 7,272ms |
| `实体清单` | 13,666,280 | 332 | ~198ms | **14,209ms**（优化 8,127 + 发射 5,912） | 14,318ms |

服务端确认：PG 16.3，`jit=on`、`jit_above_cost=100000`（均为 default），`openhive_dev` 非超管。

> 取证过程的一处未定项（如实记）：第一版 EXPLAIN 探针（drizzle `toQuery` 内联参数后用
> `db.execute(sql.raw(…))`）报 `permission denied for schema auth`（42501，position 7077），重跑仍复现；
> 改用同一个库句柄的 `db.$client.unsafe(<同一 SQL 文本>)` 即正常出计划。**该报错与 DAO 无关**
> （同一 DAO 在同一连接上跑得出正确结果），失败原因未进一步定位。

## 3. 根因

查询用了「按实体逐行相关子查询」的写法（`事件归属条件` 内联了多份
`auth.case_entity_alias ⋈ auth.case_entity` 户名对齐派生表），规划器把代价估到千万级，
越过 `jit_above_cost = 100000` ⇒ **每次请求都 JIT 编译一遍 198 / 332 节点的计划**；
结果集只有 7 行，编译成本完全无法摊销。真实执行只有 10–200ms。

结论：**不是 SQL 慢，是编译慢**。与 `#013-08/09/10` 同族但病根不同，那三条是 SQL/往返慢。

## 4. 修复（配置，不是代码）

```sql
ALTER ROLE openhive_dev SET jit = off
```

- 已在本机 dev 库落库（`pg_db_role_setting.setconfig = ["jit=off"]`）；
- 新会话实测 `current_setting('jit') = off`（`pg_settings.source = user`）；
- 回滚：`ALTER ROLE openhive_dev RESET jit`；
- **JIT 是会话级** ⇒ 角色级设定只影响新会话，旧连接池仍带 `jit=on`，**改完必须重启进程**；
- 代码侧改不了（Bun `connect()` 传不进会话参数，三条死路同 `statement_timeout`，见
  `packages/auth/src/db.ts` 注释），故落 `docs/workspace/deploy-todo.md` **D-17**。
