# 模型统一配置 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 后台任务（案件抽取、复制项目命名）改用配置文件中显式声明的 `task_model` 槽位，聊天保留现有兜底；失败（缺配置、模型不可用、0 段成功）显式可见。

**Architecture:** 在官方配置 schema 上「加」一个 `task_model` 字段（不动 `packages/core`），新增一个只读配置的解析器 `model-resolve.ts` 作为唯一入口；worker 启动期解析一次并缓存 `providerID/modelID`，作业执行期只做 `getModel` 校验；全部切片失败时作业落「失败」而不是「完成」；新增只读端点 `GET /openhive/config/models` 供设置页展示，端点只回模型名与来源，不回 apiKey / baseURL。

**Tech Stack:** Bun monorepo、Effect 4.0.0-beta.83（`Schema.TaggedErrorClass` / `Layer`）、SolidJS 1.9、Hono/Effect HTTP router、Drizzle + PostgreSQL（测试用 `startProductionDb` 夹具）。

**Spec:** `docs/superpowers/specs/2026-11-08-AI能力工程化/2026-11-08-模型统一配置-design.md`

## Global Constraints

- **最小化上游合并冲突是第一工程约束**：能新增文件就不改上游文件；必须改时只「加」不「改语义」；每处侵入按仓库惯例标 `【保留的定制 · 同步上游时不要丢】`。
- **不修改 `packages/core`**。`task_model` 的 schema 扩展只放在 `packages/opencode/src/config/config.ts`。
- 测试只在受影响 package 内跑（`packages/opencode`、`packages/app`）；**根目录 `bun test` 会 `exit 1`**。
- 面向用户的文案、错误信息、代码注释一律中文；标识符沿用仓库既有风格（英文公开 API ＋ 必要处中文内部名）。
- 不改会话里「用户显式选模型」的优先级；不批量改造现有 chat 调用点。
- 不谎称改了：报告只写实际跑过的命令与输出；跑不动的（真模型 / 真栈）如实进缺口表。


只想跑界面、不想配模型时，用 `OPENHIVE_CASE_INGEST_WORKER=0` 起栈（关掉后台消费 = 不做这项自检）。

## 与设计文档的实施期细化（先读这一节）

写计划时对着代码核出七处需要落定的细节。它们是实现口径，不改变设计意图：

1. **`resolveModel` 拆成「纯函数核心 ＋ Effect 包装」**。设计给的是一个 Effect 签名；但 `provider.defaultModel()` 与 `provider.getModel()` 都需要 `InstanceRef`，后台启动期没有实例上下文。因此：
   - `resolveModelFromConfig(config, purpose, explicit?)`：纯配置解析，`Effect<ResolvedModel, ModelUnavailable>`（无服务依赖），启动自检与单元测试都用它；
   - `resolveModel(purpose, explicit?)`：`Effect<ResolvedModel, ModelUnavailable, Config.Service | Provider.Service>`，chat 无显式模型时才委托 `defaultModel()`（保持现状）。

2. **启动自检只校验「配置文件能确定的事」**：字段存在、`provider/model` 格式、以及**当 `provider.<id>` 在配置文件里声明了 `models` 时**模型名必须在其中。provider 来自 `opencode auth login` 或 models.dev 时启动期无法离线校验（校验要 boot 实例、会往项目表写行），留到作业期由 `provider.getModel` 判定（错误名原文进 `parse_detail`；`unknown_provider` 保留在错误枚举里但当前无产生点）。这一条写进设计 §3.3 的修订。

3. **`GET /openhive/config/models` 是无实例上下文的全局口**，所以 `chat` 槽位只展示配置里的 `model`；运行时若兜底到「最近模型缓存」，设置页显示 `未设置`。不为了展示去 boot 实例。

4. **「全部切片失败 ⇒ 作业失败」是对既有有意设计的反转**。`case-ingest.ts:426-430` 原注释的理由是「同一件事说两遍」；设计 §5 与 00-总览 #4 已明确改成两处都说（作业状态是运行层聚合信号，全部失败通常是模型不可达这类系统性故障）。**实现时同步改掉那段注释**，不要留下自相矛盾的说明。

5. **设计 §5 第一行与 E4 的执行结果不同，但都成立**：E4 要求「配了 PG 必须配模型，否则拒绝启动」，所以「无 `task_model` 且无 `model`」在正常部署里的可见结果是**进程起不来**，不是「作业失败」。§5 那行描述的是 `runJob` 的兜底路径（例如配置在运行期被删掉、或 worker 在自检之外被独立调用）。两处都保留：启动期拦住是主路径，作业期显式失败是兜底。报告里不要把它写成「已按表格逐行验证」。

6. **`task_model` 只认全局配置**。worker 是挂在 `app` 层上的**全局单例**（`server.ts:536`），没有实例上下文，因此它读 `Config.getGlobal()`；只读端点同理。项目级 `opencode.jsonc` 里写 `task_model` 对后台任务不生效，设置页也不会显示它。这是「只认配置文件」在单 worker 架构下的自然结果，不是遗漏——写进设计 §3.3 的修订（Task 8），免得运维以为可以按项目配。

7. **测试进程默认关掉消费循环**（Task 3 Step 3）。启动自检一旦「配了 PG 就必须有模型」，凡是调用 `startProductionDb`（它会写 `PG_*`）又不需要抽取的用例都会在**层构造期**死掉——实测这类文件有几十个。它们原本就靠 worker 报错后自愈，没有任何一条依赖消费真的跑起来。所以默认值挪到 `test/preload.ts` 一处（与 I7 同一条理由），而不是去改几十个文件。真栈（`bun run`，不加载 preload）不受影响。

```ts
import { describe, expect, test } from "bun:test"
import { ProviderV2 } from "@opencode-ai/core/provider"
import { ModelV2 } from "@opencode-ai/core/model"
import { Effect } from "effect"
import {
  resolveModelFromConfig,
  resolveModelWith,
  解析启动模型,
  type ModelUnavailable,
  type Purpose,
} from "../../src/server/openhive/model-resolve"

type 配置 = Parameters<typeof resolveModelFromConfig>[0]

const 跑 = (config: 配置, purpose: Purpose, explicit?: { providerID: string; modelID: string }) =>
  Effect.runSync(Effect.either(resolveModelFromConfig(config, purpose, explicit)))

const 取错 = (结果: ReturnType<typeof 跑>): ModelUnavailable => {
  if (结果._tag === "Right") throw new Error("期望失败，实际成功")
  return 结果.left
}

describe("task 槽位", () => {
  test("有 task_model ⇒ 用它，source=task_model", () => {
    const 结果 = 跑({ model: "gw/chat", task_model: "gw/task" }, "task")
    if (结果._tag === "Left") throw new Error("不该失败")
    expect(结果.right).toMatchObject({ providerID: "gw", modelID: "task", source: "task_model" })
  })

  test("只有 model ⇒ 回落，source=model", () => {
    const 结果 = 跑({ model: "gw/chat" }, "task")
    if (结果._tag === "Left") throw new Error("不该失败")
    expect(结果.right).toMatchObject({ providerID: "gw", modelID: "chat", source: "model" })
  })

  test("两者都没有 ⇒ no_config，文案点名 task_model", () => {
    const 错误 = 取错(跑({}, "task"))
    expect(错误.reason).toBe("no_config")
    expect(错误.detail).toContain("task_model")
  })

  test("没有斜杠 / 空段 ⇒ bad_format", () => {
    expect(取错(跑({ task_model: "abc" }, "task")).reason).toBe("bad_format")
    expect(取错(跑({ task_model: "gw/" }, "task")).reason).toBe("bad_format")
    expect(取错(跑({ task_model: "/task" }, "task")).reason).toBe("bad_format")
  })

  test("provider 在配置里声明了 models、但模型名不在其中 ⇒ unknown_model", () => {
    const 错误 = 取错(
      跑({ task_model: "gw/nope", provider: { gw: { models: { chat: { name: "Chat" } } } } }, "task"),
    )
    expect(错误.reason).toBe("unknown_model")
    expect(错误.detail).toContain("gw/nope")
  })

  test("provider 声明了且模型名在 ⇒ 通过", () => {
    const 结果 = 跑(
      { task_model: "gw/task", provider: { gw: { models: { task: { name: "Task" } } } } },
      "task",
    )
    if (结果._tag === "Left") throw new Error("不该失败")
    expect(结果.right).toMatchObject({ providerID: "gw", modelID: "task" })
  })

  test("provider 不在配置文件里（来自授权/模型目录）⇒ 启动期放行，留给作业期 getModel 判定", () => {
    const 结果 = 跑({ task_model: "deepseek/deepseek-v4-pro" }, "task")
    if (结果._tag === "Left") throw new Error("不该失败")
    expect(结果.right).toMatchObject({ providerID: "deepseek", modelID: "deepseek-v4-pro" })
  })

  test("task 从不兜底到「第一个可用 provider」：没有任何配置就是 no_config", () => {
    const 错误 = 取错(跑({ provider: { a: { models: { m: { name: "M" } } } } }, "task"))
    expect(错误.reason).toBe("no_config")
  })

  test("task 绝不调用兜底：注入一个「一调用就炸」的 fallback，结果仍是 no_config", () => {
    const 结果 = Effect.runSync(
      Effect.either(resolveModelWith({}, "task", undefined, Effect.die(new Error("兜底被调用")))),
    )
    if (结果._tag === "Right") throw new Error("期望失败，实际成功")
    expect(结果.left.reason).toBe("no_config")
  })
})

describe("chat 槽位", () => {
  test("显式传入 ⇒ source=session，配置里的 model 不参与", () => {
    const 结果 = 跑({ model: "gw/chat" }, "chat", { providerID: "other", modelID: "x" })
    if (结果._tag === "Left") throw new Error("不该失败")
    expect(结果.right).toMatchObject({ providerID: "other", modelID: "x", source: "session" })
  })

  test("没有显式、配置有 model ⇒ source=model", () => {
    const 结果 = 跑({ model: "gw/chat" }, "chat")
    if (结果._tag === "Left") throw new Error("不该失败")
    expect(结果.right).toMatchObject({ providerID: "gw", modelID: "chat", source: "model" })
  })

  test("没有显式、配置也没有 model ⇒ 才走 fallback，source=fallback", () => {
    const 结果 = Effect.runSync(
      Effect.either(
        resolveModelWith(
          {},
          "chat",
          undefined,
          Effect.succeed({ providerID: ProviderV2.ID.make("a"), modelID: ModelV2.ID.make("b") }),
        ),
      ),
    )
    if (结果._tag === "Left") throw new Error("不该失败")
    expect(结果.right).toMatchObject({ providerID: "a", modelID: "b", source: "fallback" })
  })
})

describe("启动期解析", () => {
  test("旧环境变量被忽略，只打 WARN，不影响解析结果", () => {
    const 结果 = Effect.runSync(
```

```ts
export * as ModelResolve from "./model-resolve"

import { ProviderV2 } from "@opencode-ai/core/provider"
import { ModelV2 } from "@opencode-ai/core/model"
import { Config } from "@/config/config"
import { Provider } from "@/provider/provider"
import { Effect, Schema } from "effect"

/**
 * openhive 模型解析的唯一入口（2026-11-08，模型统一配置设计 §3.1）。
 *
 * ## 为什么后台任务不调用 `provider.defaultModel()`
 *
 * 默认兜底会落到「最近用过的模型」或「排序后的第一个模型」，全程不校验可达性——
 * 真实事故就是兜底到 `openai/gpt-5.6-terra-pro`，4 个切片 × 3 次重试全部 ECONNREFUSED。
 * 后台任务要花钱、要可复现，所以 `task` 只认配置：`task_model` → `model`，都没有就是
 * `no_config`，绝不猜。
 *
 * ## 为什么不在这里探活
 *
 * 「解析得出」与「调得通」是两件事：探活会在启动期发网络请求（内网网关尚未就绪就起不来），
 * 且失败粒度是网络错误而不是配置错误。启动期只查配置完整性，可达性由作业期的 `getModel`
 * 与真正的模型调用暴露。
 */

export type Purpose = "chat" | "task"

export type ModelSource = "session" | "task_model" | "model" | "fallback"

export interface ResolvedModel {
  readonly providerID: ProviderV2.ID
  readonly modelID: ModelV2.ID
  readonly source: ModelSource
}

export class ModelUnavailable extends Schema.TaggedErrorClass<ModelUnavailable>()("ModelUnavailable", {
  // 这个 effect 版本里 `Schema.Literal` 只收一个值；多值用 `Schema.Literals([...])`
  // （`config.ts:63` 的单值先例 ＋ `Schema.d.ts:3431` 的多值签名）。
  purpose: Schema.Literals(["chat", "task"]),
  // ⚠️ `unknown_provider` 本模块**不产生**：启动期拿不到 auth / models.dev 的 provider 目录
  // （见「实施期细化」第 2 条），provider 是否存在由作业期 `provider.getModel` 判。枚举里留着它，
  // 是为了作业期把那个错误映射回同一个 reason 词表；不要在解析器里补一个假的来源判定。
  reason: Schema.Literals(["no_config", "bad_format", "unknown_provider", "unknown_model"]),
  detail: Schema.String,
}) {}

/** 旧环境变量：只用于「检测到就告警」，**不再读取**。 */
export const 旧抽取模型ENV = "OPENHIVE_CASE_EXTRACT_MODEL"

/**
 * 拆 `provider/model`。provider 取第一段，其余并回模型名（模型名本身可以含 `/`，
 * 与 `provider/parseModel` 同口径）。空段一律算格式错。
 */
export function 拆模型(值: string): { providerID: ProviderV2.ID; modelID: ModelV2.ID } | undefined {
  const [providerID, ...rest] = 值.split("/")
  const modelID = rest.join("/")
  if (providerID === "" || modelID === "") return undefined
  return { providerID: ProviderV2.ID.make(providerID), modelID: ModelV2.ID.make(modelID) }
}

/**
 * 只看配置的解析。无服务依赖，启动自检与单元测试直接用它。
 *
 * `explicit` 只对 `chat` 有意义（会话里用户选的模型永远最高优先级）。
 */
export const resolveModelFromConfig = (
  config: Config.Info,
  purpose: Purpose,
  explicit?: { readonly providerID: string; readonly modelID: string },
): Effect.Effect<ResolvedModel, ModelUnavailable> =>
  Effect.gen(function* () {
    if (purpose === "chat" && explicit) {
      return {
        providerID: ProviderV2.ID.make(explicit.providerID),
        modelID: ModelV2.ID.make(explicit.modelID),
        source: "session" as const,
      }
    }

    const 槽位 = purpose === "task" ? (config.task_model ?? config.model) : config.model
    if (槽位 === undefined || 槽位 === "") {
      return yield* new ModelUnavailable({
        purpose,
        reason: "no_config",
        detail:
          purpose === "task"
            ? "未配置后台任务模型：请在 opencode.jsonc 设置 task_model 或 model（形如 provider/model）"
            : "未配置聊天模型：请在 opencode.jsonc 设置 model（形如 provider/model）",
      })
    }

    const 解析 = 拆模型(槽位)
    if (解析 === undefined) {
      return yield* new ModelUnavailable({
        purpose,
        reason: "bad_format",
        detail: `${purpose === "task" ? "task_model" : "model"}="${槽位}" 不是 provider/model 形式`,
      })
    }

    // 只在「配置文件自己声明了这个 provider 且声明了 models」时校验模型名。
    // provider 来自 auth / models.dev 时，这里离线看不到它的模型目录；放行，
    // 由作业期的 `provider.getModel` 报错，错误名原文进作业错误文案。
    const 声明 = config.provider?.[解析.providerID]
    const 模型表 = 声明?.models
    if (模型表 !== undefined && Object.keys(模型表).length > 0 && 模型表[解析.modelID] === undefined) {
      return yield* new ModelUnavailable({
        purpose,
        reason: "unknown_model",
        detail: `模型 ${解析.providerID}/${解析.modelID} 不在配置的 provider.${解析.providerID}.models 里`,
      })
    }

    return {
      ...解析,
      source: purpose === "task" ? (config.task_model ? "task_model" : "model") : "model",
    }
  })

/**
 * 把兜底作为 Effect 注入，而不是在函数体里直接 `yield*` 某个服务。
 *
 * 这样「task 绝不调兜底」可以由单测钉住：注入一个一调用就 die 的 fallback，
 * task 路径必须连碰都不碰它。否则这条约束只能靠读代码保证——
 * 而它正是这次事故的根因（隐式兜底），必须有一条会红的用例守着。
 */
export const resolveModelWith = (
  config: Config.Info,
  purpose: Purpose,
  explicit: { readonly providerID: string; readonly modelID: string } | undefined,
  fallback: Effect.Effect<{ readonly providerID: ProviderV2.ID; readonly modelID: ModelV2.ID }, unknown>,
): Effect.Effect<ResolvedModel, ModelUnavailable> =>
  Effect.gen(function* () {
    if (purpose === "task" || explicit !== undefined || (config.model !== undefined && config.model !== "")) {
      return yield* resolveModelFromConfig(config, purpose, explicit)
    }
    const 兜底 = yield* fallback.pipe(
      Effect.mapError(
        (error) =>
          new ModelUnavailable({ purpose, reason: "no_config", detail: `没有可用的聊天模型：${String(error)}` }),
      ),
    )
    return { providerID: 兜底.providerID, modelID: 兜底.modelID, source: "fallback" as const }
  })

/**
 * 统一入口。`chat` 且没有显式模型、配置也没有 `model` 时，保持现状走 `defaultModel()`。
 */
export const resolveModel = (
  purpose: Purpose,
  explicit?: { readonly providerID: string; readonly modelID: string },
): Effect.Effect<ResolvedModel, ModelUnavailable, Config.Service | Provider.Service> =>
  Effect.gen(function* () {
    const config = yield* (yield* Config.Service).get()
    return yield* resolveModelWith(config, purpose, explicit, (yield* Provider.Service).defaultModel())
  })

/**
 * 启动期解析：把旧环境变量的存在变成一条 WARN，然后把实际生效的模型记进 INFO。
 * 返回的 `ResolvedModel` 在 worker 的层作用域里缓存，作业执行期复用（不再重读配置）。
 */
export const 解析启动模型 = (
  config: Config.Info,
  env: Readonly<Record<string, string | undefined>>,
): Effect.Effect<ResolvedModel, ModelUnavailable> =>
  Effect.gen(function* () {
    if (env[旧抽取模型ENV] !== undefined && env[旧抽取模型ENV] !== "") {
      yield* Effect.logWarning(`${旧抽取模型ENV} 已废弃且被忽略：请改用 opencode.jsonc 的 task_model`)
    }
    const 模型 = yield* resolveModelFromConfig(config, "task")
    yield* Effect.logInfo("案件抽取模型已解析", {
      model: `${模型.providerID}/${模型.modelID}`,
      source: 模型.source,
    })
    return 模型
  })
```

> `Config` 必须是**值导入**（`import { Config }`）——`Config.Info` 是类型，`Config.Service`
> 是运行时服务，同一个名字两用。

```ts
/**
 * 设置页的模型槽位只读出口（2026-11-08，模型统一配置设计 §3.4）。
 *
 * ## 为什么不复用 `GET /config`
 *
 * 1. 它的 success schema 是上游 `ConfigV1.Info`（`groups/config.ts`），没有 `task_model`；
 * 2. 它返回整份配置，含 `provider.options.apiKey` / `baseURL`——不应送到浏览器。
 *
 * 这里只回模型名与来源。没有实例上下文（全局口），所以：
 * - 读 `Config.getGlobal()`，不读 `Config.get()`——后者走 `InstanceState`，而这个口没有
 *   `InstanceRef`（它是端点级中间件才注入的，见 `middleware/instance-context.ts:31`）；
 * - `chat` 只展示配置里的 `model`；运行时若兜底到「最近模型缓存」，设置页显示「未设置」。
 *   为展示去 boot 一个实例等于往项目表写行，不值得。
 */

export const PREFIX = "/openhive/config"

export const PATH = {
  models: `${PREFIX}/models`,
} as const

export type 槽位来源 = "task_model" | "model" | null

export interface 槽位视图值 {
  readonly model: string | null
  readonly source: 槽位来源
}

export interface 模型槽位视图 {
  readonly chat: 槽位视图值
  readonly task: 槽位视图值
}

/** 纯函数：输入配置，输出设置页要的三个事实（聊天用什么、后台用什么、后台是不是显式配的）。 */
export function 槽位视图(config: { readonly model?: string; readonly task_model?: string }): 模型槽位视图 {
  const 聊天 = config.model === undefined || config.model === "" ? null : config.model
  const 后台显式 = config.task_model === undefined || config.task_model === "" ? null : config.task_model
  return {
    chat: { model: 聊天, source: 聊天 === null ? null : "model" },
    task: 后台显式 !== null
      ? { model: 后台显式, source: "task_model" }
      : { model: 聊天, source: 聊天 === null ? null : "model" },
  }
}

export const routes = HttpRouter.use((router) =>
  Effect.gen(function* () {
    const config = yield* Config.Service
    yield* router.add("GET", PATH.models, () =>
      Effect.gen(function* () {
        return HttpServerResponse.jsonUnsafe(槽位视图(yield* config.getGlobal()))
      }),
    )
  }),
)
```

```ts
/**
 * 设置页「当前生效模型」的客户端（2026-11-08，模型统一配置设计 §3.4）。
 *
 * 与 `case-materials-api.ts` 同一套范式：同源相对路径、可注入的 `send`、
 * 失败不抛（收成 `{ kind: "error" }`）。
 *
 * ## 形状是闭集，不认识就整份判错
 *
 * `source` 只认 `task_model` / `model` / `null`。服务端将来多一种来源时，最坏行为是
 * 「这一块不显示」——好过把未知来源画成「显式配置」（`#002-02`：不知道 ≠ 空）。
 */
import { defaultSend, readJson, trySend, type ForkFetch } from "./openhive-fetch"

export const PATH = {
  models: "/openhive/config/models",
} as const

export type 槽位来源 = "task_model" | "model" | null

export interface 模型槽位 {
  readonly model: string | null
  readonly source: 槽位来源
}

export interface 生效模型 {
  readonly chat: 模型槽位
  readonly task: 模型槽位
}

export type 模型槽位结果 =
  | { readonly kind: "ok"; readonly value: 生效模型 }
  | { readonly kind: "error"; readonly message: string }

const 是来源 = (值: unknown): 值 is 槽位来源 =>
  值 === null || 值 === "task_model" || 值 === "model"

function 是记录(值: unknown): 值 is Record<string, unknown> {
  return typeof 值 === "object" && 值 !== null && !Array.isArray(值)
}

function 解析槽位(值: unknown): 模型槽位 | undefined {
  if (!是记录(值)) return undefined
  const model = 值["model"]
  if (model !== null && typeof model !== "string") return undefined
  if (!是来源(值["source"])) return undefined
  return { model, source: 值["source"] }
}

export function 解析生效模型(体: unknown): 生效模型 | undefined {
  if (!是记录(体)) return undefined
  const chat = 解析槽位(体["chat"])
  const task = 解析槽位(体["task"])
  if (chat === undefined || task === undefined) return undefined
  return { chat, task }
}

export async function 读生效模型(send: ForkFetch = defaultSend): Promise<模型槽位结果> {
  const response = await trySend(send, PATH.models)
  if (response === undefined) return { kind: "error", message: "服务端没有响应" }
  if (!response.ok) return { kind: "error", message: `服务端回了 ${response.status}` }
  const 值 = 解析生效模型(await readJson(response))
  if (值 === undefined) return { kind: "error", message: "服务端回包形状不对" }
  return { kind: "ok", value: 值 }
}
```
