## Global Constraints

1. **期望按规格写，不按现状写**。规格说「能力未就绪」就写「能力未就绪」。照现状写等于把红灯洗绿——这是本计划唯一的成功判据。
2. **seed 只走生产出口**：`enqueueMaterial` / `claimNextJob` / `runJob`（`case-ingest.ts:118/175/329`）。**禁止**裸 SQL 种 `case_entity` / `case_relation` / `case_event` / `case_fact_row`（`#006-28`：形状与校验都跟着生产走；`#006-35`：走生产出口）。

4. **明文，不脱敏**：账号、户名、金额一律原样（账号 `6222021234567890123` 这类）。
5. **上游零改动**：本计划只动 `packages/opencode/src/server/openhive/` 与我们自己的测试/夹具。不碰 `packages/opencode/src/session/`、`packages/opencode/src/mcp/`（那是官方文件）。
6. 每条命令带 `timeout 300`；退出码 124 = BLOCKED，不自动重跑。禁止 `bun install` / `bun run dev` / `bun --watch`；仓库根 `bun test` 被脚本强制 `exit 1`，只在 package 内跑具名文件。
7. 六步轨道（①证据定根因 ②先写会红的用例 ③改到绿 ④变异验证 ⑤门禁 ⑥grep 全部同类落点）与三条红线（不谎称改了 / 不做表面修改 / 不把测不了的写成已覆盖）。

## 设计裁定（实现期一律照此，不再逐条讨论）

- **D1 数据集位置**：`packages/opencode/test/fixtures/explore/dataset.ts`（数据集构造器 + `造工作簿`）+ `cases.ts`（期望表）。数据集是**代码**不是二进制：xlsx 用 `XLSX.utils` 现造（仓内既有惯例，无二进制夹具先例），git 版本化。
- **D2 资金故事在笔录里，明细行故事在 xlsx 里**：`aggregate_money` / `query_relations` 的钱来自笔录经假抽取器产出的 `转账` 关系；`query_rows` / 备注 / 外币 / 行级出处来自 xlsx。两者用**同一批账号与户名**对齐，二十题里的数字才互相印证。
- **D3 人↔账户的归属关系类型约定为 `"持有"`**：`query_relations{实体: 张三}` 能列出 `张三 -持有-> <账号>`；这是「人有多少账户」的唯一判据，也是 `实体没有关联账户` 的证据来源。约定写进 `09` §3.5 回写。
- **D4 空原因四拆是「证据驱动」的，不是无条件替换**：只有判得出证据才给四拆值，判不出仍给 `无匹配行`（不猜）。四个值的判定顺序与证据见 Task 3 的判定表。
- **D5 地点拒答 = 新增可选参数而不是改报错**：`query_events` 新增 `地点?: string`；非空时返回 `空原因: "能力未就绪"`、`缺口` 说明未支持、`下一步` 指向「按时间窗 + 参与实体查事件」。理由：`bad_input` 只告诉模型「参数不认识」，不告诉**为什么**；`09` §4.5 要求的是「能力未就绪」。这是「加」不是「改」。
- **D6 外币挂在明细行上**：`case_fact_row` 增 `currency`（默认 `CNY`），`币种` 列进标准字段；`query_rows` 合计与回显只计 CNY，非 CNY 行数写 `缺口`，全是外币时 `空原因 = "外币行全部未计入"`。**汇总侧（`aggregate_money`）不动**——关系没有币种，也不该凭 `金额原文` 猜。
- **D7 「出处能翻到原文」分两级兑现**：文本事实 ⇒ `get_citation` 非行分支补 `原文切片`（按 `locator` 从 `text_content` 切出原句）；明细行 ⇒ 行分支补 `材料定位`（`path` / `fileName` / `sheet` / `rowNo`）+ `extras` 原值，**不伪造原文正文**（xlsx 行没存原行文本，造假就是编数据）。这一分级写进 `09` §13.1。
- **D8 回放不断「自然语言答案」**：没有模型，只断 `工具结果` 的七字段与调用数。`09` §13.3 的「平均调用数 ≤ 8」落成**逐题上限**（期望表里的 `最大调用数`），全局平均留在 §13.5 缺口。
