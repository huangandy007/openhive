# P3 第一期：跨来源去重 + 卡片读端 · 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让同一笔转账在汇总里只计一次、人与账户在分组层面对齐成同一方，并交付工具层的 `query_timeline`。

**Architecture:** 写端在 `重建关系` 里先把 human 关系端点按「未撤销户名」对齐成账户代表，再按「对 + 币种 + 金额 + UTC+8 日历日」与 `资金交易` 事件一一匹配，只排除被覆盖的事件；新增 `case_relation.times_cny` 承载人民币笔数。读端 `aggregate_money` 按 `coalesce(times_cny, times, 1)` 计笔数、按对齐代表分组建对手方；`query_events` / `find_crossings` / 新增的 `query_timeline` 共用同一个「事件参与者条件」。

**Tech Stack:** Bun 1.4.3 + TypeScript 5.8.2 + Hono + Drizzle `sql` 模板 + PGlite（测试）+ oxlint。

**Spec:** `docs/superpowers/specs/2026-11-09-事实卡片抽象/10-P3-去重与卡片读端-设计.md`（下称「10」）；`09-AI探索与MCP工具-设计.md` §4.3（`query_timeline` 契约）、§4.5（外币口径）。

## Global Constraints

- **最小化与官方合并冲突**：只新增文件或在既有文件内做最小改动；不重构无关代码。
- **品牌/业务语义不进上游核心**：本期改动全部限制在 `packages/opencode/src/server/openhive/`、`packages/auth/src/migrations/` 与测试内。迁移只新增文件，不改既有迁移。
- **金额口径 Q16**：`times` = 全币种笔数；`amount` 只累加 `currency='CNY'`；`times_cny` = 该对 CNY 事件数。
- **笔数读侧回退**：`coalesce(times_cny, times, 1)`。**不能**写成 `coalesce(times_cny, times)`——human 行的 `times` 是 NULL，会整行消失。

## 与设计的偏差 / 实施裁定

执行前必须知道，下列每条都是实测把设计改掉的地方：

| # | 设计的写法 | 实际裁定 | 依据 |
|---|---|---|---|
| D-1 | §5 只在 `重建关系` 里去重 | **增加文本路径触发**：`跑文本` 在写完备注事实后，按「本材料贡献的 human 转账对（对齐后）」调 `重建关系` | 数据集先灌流水后灌笔录；不触发则机器行在 human 出现后永不重算，6 条红不会变绿（设计 §5 漏了这条写入顺序） |
| D-2 | §4 笔数 = `coalesce(times_cny, times)` | 改为 `coalesce(times_cny, times, 1)` | human 行 `insertRelation` 不写 `times`（NULL），少了 `1` 会把全部人工关系从汇总里删掉 |
| D-3 | §3.2「匹配计数进缺口」 | **本期不做**：计数无落点，读侧重算要再加查询 | 缺口本期只交「对齐歧义」与「纯外币」两条；匹配计数登记到第二期 |
| D-4 | §3.2 一律按金额匹配 | `已确认` / `已修正` 的 human 关系**忽略金额**，只按「对 + 日」一一匹配 | 人工改过金额的关系与原始事件金额不同，按金额匹配会让事件重新计入 ⇒ 双算 |
| D-5 | §1.3「表格卡片对按实体查隐形」 | 前提不成立：`写入翻译结果` 已把 `participants` 写进 `case_event.participants text[]`。§6.2 的条件因此**加对齐**（人→唯一户名账户），否则「按人查事件」仍查不到流水事件 | `case-translate-store.ts:173` + `case-event-store` 的 `事件列` 含 `participants`；只有「按人查」才真的漏 |
| D-6 | §6.3「查询次数上限 5」 | 改为 **≤7**：解析实体 1 + 事件 1 + 统计 1 + 参与者 1 + 出处 1 + `读身份标注` 2 | `读身份标注` 是两条 SQL（人证 + 户名），设计把它算成了 1 |
| D-7 | §7 mcp-server 用例只改工具数 | 同时改标题文字里的「8 个」 | 标题也是断言口径（`#006-29`） |

```ts
function 造工作簿(行们: (string | number)[][], 表名: string): Uint8Array {
  const wb = XLSX.utils.book_new()
  XLSX.utils.book_append_sheet(wb, XLSX.utils.aoa_to_sheet(行们), 表名)
  return new Uint8Array(XLSX.write(wb, { type: "array", bookType: "xlsx" }) as ArrayBuffer)

export async function 种P3数据集(
  db: Queryable,
  文件: Map<string, Uint8Array>,
): Promise<P3数据集> {
  const projectId = "p-p3"
  const 对齐项目 = "p-party"

  const 入队 = async (项目: string, 文件名: string, 字节: Uint8Array) => {
    文件.set(`${项目}/${文件名}`, 字节)
    const r = await enqueueMaterial(db, {
      projectId: 项目,
      path: 文件名,
      sourcePath: `${项目}/${文件名}`,
      fileName: 文件名,
      fingerprint: `fp-${项目}-${文件名}`,
    })
    if (!r.enqueued) throw new Error(`材料没有入队：${文件名}`)
    return r.materialId
  }

  const 跑 = async (materialId: string, 建抽取器?: () => Promise<抽取器>) => {
    const job = await claimNextJob(db)
    if (!job) throw new Error("队列是空的")
    if (job.materialId !== materialId) throw new Error(`认领到别人的作业：期望 ${materialId}，实得 ${job.materialId}`)
    const 结果 = await runJob(db, { readFile: async (p) => 文件.get(p)!, ...(建抽取器 === undefined ? {} : { 建抽取器 }) }, job)
    if (结果 !== "完成") throw new Error(`作业没有跑完：${结果}（材料 ${materialId}）`)
  }

  // R-J：队列是全局 FIFO 且 queued_at 只有秒精度 ⇒ 必须入队一份、跑完、再入队下一份。
  const 流水 = await 入队(projectId, "P3流水.xlsx", 造工作簿(流水行们, "流水"))
  await 跑(流水)
  const 笔录 = await 入队(projectId, "P3笔录.txt", new TextEncoder().encode(笔录正文))
  await 跑(笔录, async () => 建假抽取器(() => 假抽取器回答))

  const 对齐流水 = await 入队(对齐项目, "P3对齐.xlsx", 造工作簿(对齐行们, "流水"))
  await 跑(对齐流水)

  return {
    projectId,
    材料: { 流水, 笔录 },
    账号,
    对齐项目,
    对齐账号,
  }
}
```

```ts
export * as OpenhiveCaseParty from "./case-party"

import { sql, type SQL } from "drizzle-orm"

/**
 * 「同一方代表」（10 §3.1）。
 *
 * 人 ↔ 账户在库里是两行实体；笔录写人、流水写账户。对齐证据只有一条：账户上未撤销的
 * `kind='户名'` 别名，且别名值 = 人的规范值。**唯一**候选才对齐；0 个或 ≥2 个一律
 * 不对齐（fail-closed，宁可分开也不错误合并；候选数由读端写进缺口）。
 *
 * `户名来源` 是「未撤销户名 + 未排除实体」这条前提的**唯一出处**（`#002-06`）：
 * `case-identity.ts` 的 `读身份标注` 与这里的 `户名对齐` 都从它出发，谁都不许再抄一份
 * `a.kind='户名' and a.revoked_at is null ...`。
 *
 * ⚠️ 调用约定：`户名来源` 已经以 `where` 结尾，追加条件只能写 `and ...`；别名固定为
 * `a`（别名表）与 `ae`（别名所属实体），不要在调用点再声明同名表。
 */
export function 户名来源(projectId: string): SQL {
  return sql`auth.case_entity_alias a
    join auth.case_entity ae on ae.project_id = a.project_id and ae.id = a.entity_id
   where a.project_id = ${projectId} and a.kind = '户名' and a.revoked_at is null
     and ae.trust_state <> '已排除'`
}

/**
 * 对齐子查询（派生表）：`代表` = 唯一候选账户 id 或 null，`候选数` = 候选账户数。
 *
 * 只有「人」/「组织」才可能对齐；其他类型 `in ('人','组织')` 恒假 ⇒ 代表 null、
 * 候选 0，外层 `coalesce(代表, id)` 自然退回自己。
 *
 * 聚合在零行上仍返回一行（count=0、代表 null），所以可以安全地当 lateral 表或标量子查询。
 */
export function 户名对齐(projectId: string, id: SQL, 类型: SQL, 值: SQL): SQL {
  return sql`(select case when count(distinct a.entity_id) = 1 then min(a.entity_id) end as 代表,
                     count(distinct a.entity_id)::int as 候选数
                from ${户名来源(projectId)}
                 and ${类型} in ('人', '组织')
                 and a.value = ${值})`
}

/** 代表表达式：唯一候选账户，否则自己。 */
export function 对齐代表(projectId: string, id: SQL, 类型: SQL, 值: SQL): SQL {
  return sql`coalesce((select 代表 from ${户名对齐(projectId, id, 类型, 值)} 对齐), ${id})`
}
```

```ts
export * as OpenhiveCaseMatch from "./case-match"

import { 金额分 } from "./case-row-query"

/**
 * 同一笔转账的判定（10 §3.2）。
 *
 * 匹配键 = 对齐后的（付款方, 收款方）+ 币种 CNY + 金额 + **UTC+8 日历日**。
 * human 关系只有日期精度（笔录「2026年2月10日」），事件到秒；所以按日历日分桶，
 * 不按绝对时间相等。
 *
 * 一一匹配：同桶内关系与事件各按 (时间, id) 排序，只排除「前 N 个」事件（N = 关系数）。
 * 多出来的事件正常进机器聚合；多出来的关系不覆盖任何事件——宁可多算也不吞（fail-closed）。
 *
 * 两遍：
 * 1. `自动抽取` / `存疑`：桶键含金额（精确匹配）。
 * 2. `已确认` / `已修正`：桶键只含「对 + 日」，**忽略金额**。人工改过金额的关系若还按金额
 *    匹配，原事件会重新计入 —— 那是双算（D-4）。
 *
 * 时区固定 UTC+8（与 `case-time.ts` 同款约定），不随进程时区漂。
 */
const 时区偏移秒 = 8 * 3600
const 一天秒 = 86400

function 日历日(秒: number): number {
  return Math.floor((秒 + 时区偏移秒) / 一天秒)
}

export interface 关系候选 {
  readonly id: string
  readonly from代表: string
  readonly to代表: string
  readonly amount: string | null
  readonly firstAt: number | null
  readonly trustState: string
}

export interface 事件候选 {
  readonly id: string
  readonly from代表: string
  readonly to代表: string
  readonly amount: string
  readonly occurredAt: number | null
  readonly currency: string
}

function 先后(甲: { id: string }, 乙: { id: string }): number {
  return 甲.id < 乙.id ? -1 : 甲.id > 乙.id ? 1 : 0
}

function 分桶<项>(项们: readonly 项[], 键函数: (项: 项) => string): Map<string, 项[]> {
  const 桶 = new Map<string, 项[]>()
  for (const 项 of 项们) {
    const k = 键函数(项)
    const 列 = 桶.get(k)
    if (列 === undefined) 桶.set(k, [项])
    else 列.push(项)
  }
  return 桶
}

export function 匹配覆盖事件(
  关系们: readonly 关系候选[],
  事件们: readonly 事件候选[],
): Set<string> {
  const 可用 = 事件们
    .filter((e) => e.currency === "CNY" && e.occurredAt !== null)
    .sort((甲, 乙) => (甲.occurredAt! - 乙.occurredAt!) || 先后(甲, 乙))
  const 已用 = new Set<string>()
  const 覆盖 = new Set<string>()

  /** 从桶里取第一个未用事件；退化成线性扫描，桶内条数就是同日同额笔数，量很小。 */
  const 取 = (列: readonly 事件候选[] | undefined): 事件候选 | undefined => {
    if (列 === undefined) return undefined
    for (const e of 列) if (!已用.has(e.id)) return e
    return undefined
  }
  const 用 = (e: 事件候选): void => {
    已用.add(e.id)
    覆盖.add(e.id)
  }

  const 对日 = (f: string, t: string, 秒: number) => `${f}\u0000${t}\u0000${日历日(秒)}`
  // 日期与金额之间必须有分隔符：少了它，`10000`+`1` 与 `1000`+`01` 会撞键。
  const 精确桶 = 分桶(可用, (e) => `${对日(e.from代表, e.to代表, e.occurredAt!)}|${金额分(e.amount)}`)
  const 宽松桶 = 分桶(可用, (e) => 对日(e.from代表, e.to代表, e.occurredAt!))

  const 有效 = 关系们.filter((r) => r.trustState !== "已排除" && r.firstAt !== null)
  const 时间序 = (甲: 关系候选, 乙: 关系候选) => (甲.firstAt! - 乙.firstAt!) || 先后(甲, 乙)
  const 精确 = 有效
    .filter((r) => r.trustState !== "已确认" && r.trustState !== "已修正" && r.amount !== null)
    .sort(时间序)
  const 宽松 = 有效.filter((r) => r.trustState === "已确认" || r.trustState === "已修正").sort(时间序)

  for (const r of 精确) {
    const k = `${对日(r.from代表, r.to代表, r.firstAt!)}|${金额分(r.amount!)}`
    const 命中 = 取(精确桶.get(k))
    if (命中 !== undefined) 用(命中)
  }
  for (const r of 宽松) {
    const 命中 = 取(宽松桶.get(对日(r.from代表, r.to代表, r.firstAt!)))
    if (命中 !== undefined) 用(命中)
  }
  return 覆盖
}
```

> 注意：`日期` 与 `金额` 之间用 `|` 分隔。少了分隔符，`10000` + `1` 与 `1000` + `01` 会撞键。

```ts
/**
 * 「事件有一个付款方和一个收款方」的取数基（`#002-06`）：角色前提只写这一处。
 *
 * 三个调用点共用：`清本材料翻译` 取旧对、`重建关系` 取匹配候选、`重建关系` 聚合。
 * 基里**只放**三处都成立的前提（项目、两个角色、两端非空）；`type` / `trust_state` /
 * 对过滤由各调用点自己追加——把它们塞进基里，「旧对」就查不到非转账事件，
 * 重放换对手时会静默留下一笔聚合了已删事件的转账（`#013-02`）。
 */
function 资金参与者基(projectId: string): SQL {
  return sql`from auth.case_event e
    join auth.case_event_participant 付
      on 付.project_id = e.project_id and 付.event_id = e.id and 付.role = '付款方'
    join auth.case_event_participant 收
      on 收.project_id = e.project_id and 收.event_id = e.id and 收.role = '收款方'
   where e.project_id = ${projectId}
     and 付.entity_id is not null and 收.entity_id is not null`
}

export async function 重建关系(tx: Queryable, projectId: string, 对们: readonly 关系对[]): Promise<number> {
  if (对们.length === 0) return 0
  let written = 0
  for (let i = 0; i < 对们.length; i += INSERT_CHUNK_PAIRS) {
    const chunk = 对们.slice(i, i + INSERT_CHUNK_PAIRS)
    const 值 = sql.join(
      chunk.map((p) => sql`(${p.fromId}, ${p.toId})`),
      sql`, `,
    )

    // ① 该 chunk 的 human 转账关系（端点先对齐；对齐后落在本 chunk 的才算）。
    //    `#002-06`：别名前提只在 case-party.ts 定义；这里只负责 join 与行值过滤。
    const 关系行 = rowsOf(
      await tx.execute(sql`
        select r.id, r.amount::text as amount, r.first_at, r.trust_state,
               coalesce(起对齐.代表, r.from_id) as from_代表,
               coalesce(终对齐.代表, r.to_id) as to_代表
          from auth.case_relation r
          join auth.case_entity 起 on 起.project_id = r.project_id and 起.id = r.from_id
          join auth.case_entity 终 on 终.project_id = r.project_id and 终.id = r.to_id
          left join lateral ${户名对齐(projectId, sql`起.id`, sql`起.type`, sql`起.canonical_value`)} 起对齐 on true
          left join lateral ${户名对齐(projectId, sql`终.id`, sql`终.type`, sql`终.canonical_value`)} 终对齐 on true
         where r.project_id = ${projectId} and r.type = '转账' and r.source_kind = 'human'
           and r.trust_state <> '已排除'
           and (coalesce(起对齐.代表, r.from_id), coalesce(终对齐.代表, r.to_id)) in (values ${值})
      `),
    )
    const 关系们: 关系候选[] = 关系行.map((行) => ({
      id: String(行.id),
      from代表: String(行.from_代表),
      to代表: String(行.to_代表),
      amount: 行.amount === null ? null : String(行.amount),
      firstAt: 行.first_at === null ? null : Number(行.first_at),
      trustState: String(行.trust_state),
    }))

    // ② 该 chunk 的 CNY 资金事件（币种不是条件：匹配器自己按 CNY 过滤；这里全取是为了
    //    「全外币对」也有事件可数，只是匹配不上）。
    const 事件行 = rowsOf(
      await tx.execute(sql`
        select e.id, e.amount::text as amount, e.occurred_at, e.currency,
               付.entity_id as from_id, 收.entity_id as to_id
        ${资金参与者基(projectId)}
           and e.type = ${资金交易}
           and e.trust_state <> '已排除'
           and (付.entity_id, 收.entity_id) in (values ${值})
      `),
    )
    const 事件们: 事件候选[] = 事件行.map((行) => ({
      id: String(行.id),
      from代表: String(行.from_id),
      to代表: String(行.to_id),
      amount: String(行.amount),
      occurredAt: 行.occurred_at === null ? null : Number(行.occurred_at),
      currency: String(行.currency),
    }))
    const 覆盖 = [...匹配覆盖事件(关系们, 事件们)]

    // ③ 只删本函数自己那条确定性 id（见原注释）；已确认/已修正的机器行绝不覆盖。
    const 机器id们 = chunk.map((p) => 事实id(projectId, "转账", p.fromId, p.toId))
    await tx.execute(sql`
      delete from auth.case_relation
       where project_id = ${projectId}
         and id = any(${文本数组(机器id们)})
         and trust_state in ('自动抽取', '存疑')
    `)

    // ④ 聚合：排除被 human 覆盖的事件；times_cny 只数 CNY。
    const 聚合 = rowsOf(
      await tx.execute(sql`
        select 付.entity_id as from_id, 收.entity_id as to_id,
               count(*)::int as times,
               count(*) filter (where e.currency = 'CNY')::int as times_cny,
               coalesce(sum(e.amount) filter (where e.currency = 'CNY'), 0)::numeric(18,2)::text as amount,
               min(e.occurred_at) as first_at, max(e.occurred_at) as last_at,
               -- 精度取最粗；全为 NULL 时输出 NULL（M5：不升级为最细）。
               case when bool_or(e.precision = '到日') then '到日'
                    when bool_or(e.precision = '到分') then '到分'
                    when bool_or(e.precision = '到秒') then '到秒'
                    else null end as precision
        ${资金参与者基(projectId)}
           and e.type = ${资金交易}
           and e.trust_state <> '已排除'
           and (付.entity_id, 收.entity_id) in (values ${值})
           and e.id <> all(${文本数组(覆盖)})
         group by 1, 2
      `),
    )

    for (const 行 of 聚合) {
      const fromId = String(行.from_id)
      const toId = String(行.to_id)
      if (typeof 行.amount !== "string")
        throw new Error(`关系聚合的金额不是字符串（${fromId} → ${toId}）：${JSON.stringify(行.amount)}`)
      const 写入 = rowsOf(
        await tx.execute(sql`
          insert into auth.case_relation
            (id, project_id, from_id, to_id, type, first_at, last_at, precision, times, times_cny, amount,
             basis, source_kind, trust_state, created_at)
          values (${事实id(projectId, "转账", fromId, toId)}, ${projectId}, ${fromId}, ${toId}, '转账',
                  ${行.first_at ?? null}, ${行.last_at ?? null}, ${行.precision ?? null},
                  ${Number(行.times ?? 0)}, ${Number(行.times_cny ?? 0)}, ${行.amount}, null, 'data', '自动抽取',
                  ${nowSeconds()})
          on conflict (project_id, id) do nothing
          returning id
        `),
      )
      written += 写入.length
    }
  }
  return written
}
```

```ts
/**
 * 本材料贡献的 human 转账对，**按对齐后的账户对**返回。
 *
 * 为什么必须对齐：机器行 id 与聚合分组用的是账户对（A, B）；笔录写的可能是
 * （A, 人「李四」）。拿原始对去调 `重建关系`，删不到、也算不到真正受影响的机器行。
 */
export async function 本材料转账对(
  tx: Queryable,
  projectId: string,
  materialId: string,
): Promise<关系对[]> {
  return rowsOf(
    await tx.execute(sql`
      select distinct
             coalesce(起对齐.代表, r.from_id) as from_id,
             coalesce(终对齐.代表, r.to_id) as to_id
        from auth.case_relation r
        join auth.case_entity 起 on 起.project_id = r.project_id and 起.id = r.from_id
        join auth.case_entity 终 on 终.project_id = r.project_id and 终.id = r.to_id
        left join lateral ${户名对齐(projectId, sql`起.id`, sql`起.type`, sql`起.canonical_value`)} 起对齐 on true
        left join lateral ${户名对齐(projectId, sql`终.id`, sql`终.type`, sql`终.canonical_value`)} 终对齐 on true
       where r.project_id = ${projectId} and r.type = '转账' and r.source_kind = 'human'
         and r.id in (select fact_id from auth.case_citation
                       where project_id = ${projectId} and material_id = ${materialId}
                         and fact_type = 'relation')
    `),
  ).map((r) => ({ fromId: String(r.from_id), toId: String(r.to_id) }))
}
```

```ts
async function 查引用(
  db: Queryable,
  projectId: string,
  factType: 留痕类型,
  范围: SQL,
  上限?: number,
): Promise<{ 行们: (引用视图 & { factId: string })[]; 总数: number }> {
  const 行们 = rowsOf(
    await db.execute(sql`
      select c.id, c.fact_id, c.material_id, c.locator, c.extract_method, c.confidence,
             m.file_name, m.path, count(*) over() as 总数
        from auth.case_citation c
        left join auth.case_material m on m.project_id = c.project_id and m.id = c.material_id
       where c.project_id = ${projectId} and c.fact_type = ${factType} and ${范围}
       order by c.created_at asc, c.id asc
       ${上限 === undefined ? sql`` : sql`limit ${上限}`}
    `),
  )
  const 总数 = Number(行们[0]?.总数 ?? 0)
  return {
    总数,
    行们: 行们.map((行) => ({
      factId: String(行.fact_id),
      id: String(行.id),
      materialId: String(行.material_id),
      fileName: 文本(行.file_name),
      path: 文本(行.path),
      locator: 读杰森(行.locator),
      extractMethod: String(行.extract_method) as "机器" | "人工",
      confidence: 数字(行.confidence),
    })),
  }
}

export async function 引用们(
  db: Queryable,
  projectId: string,
  factType: 留痕类型,
  factId: string,
  上限?: number,
): Promise<{ 行们: 引用视图[]; 总数: number }> {
  const { 行们, 总数 } = await 查引用(db, projectId, factType, sql`c.fact_id = ${factId}`, 上限)
  return { 总数, 行们: 行们.map(({ factId: _factId, ...行 }) => 行) }
}

/** 一批事实的引用（时间线一页一次拿全，按 `created_at, id` 正序）。 */
export async function 批量引用(
  db: Queryable,
  projectId: string,
  factType: 留痕类型,
  factIds: readonly string[],
): Promise<Map<string, 引用视图[]>> {
  if (factIds.length === 0) return new Map()
  const { 行们 } = await 查引用(db, projectId, factType, sql`c.fact_id = any(${文本数组([...factIds])})`)
  const 按事实 = new Map<string, 引用视图[]>()
  for (const { factId, ...行 } of 行们) {
    const 列 = 按事实.get(factId)
    if (列 === undefined) 按事实.set(factId, [行])
    else 列.push(行)
  }
  return 按事实
}
```

- [ ] **Step 5: 实现 `query_timeline`**

在 `case-mcp-tools.ts` 的 `query_events` 之后加：

```ts
/**
 * 时间线（09 §4.3 / 10 §6.3）：某实体或某地点的事件，按 `(occurred_at, id)` **升序**游标翻页。
 *
 * 空原因四拆（顺序即优先级）：
 * 1. `地点` 分支 ⇒ `能力未就绪`（事件表没有地点维度，先拒答）；
 * 2. 该实体全期 0 个事件 ⇒ `对象未登记`（不是「没有事件」——对象根本不在事件里）；
 * 3. 有事件但全部缺时间 ⇒ `时间全部缺失`；
 * 4. 其余（有时间事件但窗口内 0 条）⇒ `无事件`。
 *
 * 查询预算 ≤7：解析 1 + 事件 1 + 统计 1 + 参与者 1 + 出处 1 + 读身份标注 2（10 偏差 D-6）。
 * 参与者也走 `事件参与者条件`（含对齐），所以按人能看到其唯一户名账户的流水事件。
 */
export async function query_timeline(
  ctx: 工具上下文,
  args: {
    实体?: string
    地点?: string
    起?: number
    止?: number
    类型?: string
    游标?: string
    限制?: number
  },
): Promise<工具结果> {
  校验时间窗(args)
  if (args.实体 !== undefined && args.地点 !== undefined)
    throw new 工具错误("bad_input", "实体与地点只能给一个")
  if (args.地点 !== undefined && args.地点 !== "") {
    const 参数: Record<string, unknown> = {}
    if (args.起 !== undefined) 参数.起 = args.起
    if (args.止 !== undefined) 参数.止 = args.止
    return {
      摘要: `按地点查时间线尚未支持：事件表没有地点维度，无法按「${args.地点}」过滤`,
      数据: null,
      口径: "时间线只按实体、类型与时间过滤；材料里没有地点字段，`地点` 参数不参与取数",
      缺口: ["事件表没有地点维度：地点只可能出现在事件摘要文本里，不能当作过滤条件"],
      空原因: "能力未就绪",
      出处: [],
      下一步: [{ 工具: "query_events", 参数, 为什么: "先按时间窗取事件，再在摘要里人工看地点" }],
    }
  }
  if (args.实体 === undefined || args.实体 === "")
    throw new 工具错误("bad_input", "实体与地点必须给一个（本期地点只返回「能力未就绪」）")

  const 实体 = await 解析实体(ctx, args.实体, "实体")
  const 限制 = 归一化限制(args.限制)
  const 参与 = 事件参与者条件(ctx, 实体)
  const 类型条件 = args.类型 === undefined ? sql`` : sql`and type = ${args.类型}`

  let 游标: { t: number; id: string } | undefined
  if (args.游标 !== undefined) {
    let 解: Record<string, unknown>
    try {
      解 = 解码游标对象(args.游标)
    } catch {
      throw new 工具错误("bad_input", "游标不是本函数签发的形状（应原样回传上一页给出的续页游标）")
    }
    const { t, id } = 解
    if (typeof t !== "number" || !是int32(t) || typeof id !== "string" || id === "" || id.includes("\u0000"))
      throw new 工具错误("bad_input", "游标字段不全、类型不对或数值超出 integer 范围")
    游标 = { t, id }
  }

  const 窗: SQL[] = [sql`occurred_at is not null`]
  if (args.起 !== undefined) 窗.push(sql`occurred_at >= ${args.起}`)
  if (args.止 !== undefined) 窗.push(sql`occurred_at <= ${args.止}`)
  // 游标条件与排序一致：(occurred_at, id) 严格大于上一页最后一行。
  if (游标 !== undefined)
    窗.push(sql`(occurred_at > ${游标.t} or (occurred_at = ${游标.t} and id > ${游标.id}))`)

  const 行们 = rowsOf(
    await ctx.db.execute(sql`
      select id, type, occurred_at, occurred_raw, precision,
             array_to_json(participants)::text as participants, summary, trust_state
        from auth.case_event
       where project_id = ${ctx.身份.projectId} and trust_state <> '已排除'
         and ${参与} ${类型条件}
         and ${sql.join(窗, sql` and `)}
       order by occurred_at asc, id asc
       limit ${限制 + 1}
    `),
  )
  const 本页 = 行们.slice(0, 限制)
  const 下一页游标 =
    行们.length > 限制 && 本页.length > 0
      ? 编码游标对象({ t: Number(本页[本页.length - 1]!.occurred_at), id: String(本页[本页.length - 1]!.id) })
      : null

  // 统计：全期事件数与「有时间」的事件数。窗口、游标、**类型**都不进——
  // 空原因是对象的属性（`09` §3.5：「对象未登记」= 实体不在事件参与者集合里）；
  // 若让 `类型` 参与，一个只有话单事件的实体查「转账」时间线会被误报成「对象未登记」。
  const 统计 = rowsOf(
    await ctx.db.execute(sql`
      select count(*)::int as 总数,
             count(*) filter (where occurred_at is not null)::int as 有时数
        from auth.case_event
       where project_id = ${ctx.身份.projectId} and trust_state <> '已排除'
         and ${参与}
    `),
  )[0]
  const 总数 = Number(统计?.总数 ?? 0)
  const 有时数 = Number(统计?.有时数 ?? 0)
  const 缺时间条数 = 总数 - 有时数

  const 空 = 本页.length === 0
  const 空原因: 空原因值 | null = 空
    ? 总数 === 0
      ? "对象未登记"
      : 有时数 === 0
        ? "时间全部缺失"
        : "无事件"
    : null

  const ids = 本页.map((行) => String(行.id))
  const 参与者按事件 = new Map<string, string[]>()
  if (!空) {
    const 参与者行 = rowsOf(
      await ctx.db.execute(sql`
        select p.event_id, p.role, e.canonical_value as value
          from auth.case_event_participant p
          join auth.case_entity e on e.project_id = p.project_id and e.id = p.entity_id
         where p.project_id = ${ctx.身份.projectId} and p.event_id = any(${文本数组(ids)})
         order by p.event_id asc, p.ordinal asc
      `),
    )
    for (const 行 of 参与者行) {
      const id = String(行.event_id)
      const 列 = 参与者按事件.get(id)
      const 项 = `${String(行.role)}：${String(行.value)}`
      if (列 === undefined) 参与者按事件.set(id, [项])
      else 列.push(项)
    }
  }
  const 引用按事件 = 空 ? new Map<string, 引用视图[]>() : await 批量引用(ctx.db, ctx.身份.projectId, "event", ids)

  const 事件们 = 本页.map((行) => {
    const id = String(行.id)
    const 参与者 =
      参与者按事件.get(id) ?? 解JSON<string[]>(String(行.participants ?? "[]"), []).map((值) => `参与者：${值}`)
    const 引用 = 引用按事件.get(id)?.[0]
    return {
      id,
      类型: String(行.type),
      时间: Number(行.occurred_at),
      时间精度: 行.precision === null ? null : String(行.precision),
      时间原文: 行.occurred_raw === null ? null : String(行.occurred_raw),
      参与者,
      事件摘要: 行.summary === null ? null : String(行.summary),
      信任态: String(行.trust_state),
      代表出处:
        引用 === undefined
          ? null
          : { 材料: 引用.fileName, 定位: 引用.locator },
    }
  })

  const 身份们 = [
    ...(
      await 读身份标注(ctx.db, ctx.身份.projectId, [
        { id: 实体.id, 类型: 实体.type, 值: 实体.value },
      ])
    ).values(),
  ]
  const 后缀 = 身份后缀(身份们)
  const 称呼 = 实体称呼(实体, args.实体)
  const 缺口 = [
    ...截断缺口(args.限制, 限制, 本页.length),
    `${限制} 条/页（时间升序）；游标只经本工具返回，不要自己造`,
  ]
  if (缺时间条数 > 0) 缺口.push(`${缺时间条数} 个事件没有时间，未进入时间线`)
  if (下一页游标 !== null) 缺口.push("还有下一页：把本页 `下一页游标` 原样传回 `游标`")

  return {
    摘要: 空
      ? 空原因 === "对象未登记"
        ? `${称呼}在事件里没有出现（对象存在但没有任何事件）${后缀}`
        : 空原因 === "时间全部缺失"
          ? `${称呼}有 ${总数} 个事件，但全都没有时间，排不出时间线${后缀}`
          : `${称呼}在给定时间窗内没有事件${后缀}`
      : `${称呼}的 ${事件们.length} 个事件（时间升序）${事件们[0]!.时间原文 ?? 事件们[0]!.类型} 起${后缀}`,
    数据: 空 ? null : { 事件们, 缺时间条数, 下一页游标 },
    口径:
      "事件按实体（先按 id、再按规范值解析；参与实体走 text[] 规范值 ∪ 参与者表的对齐代表）过滤；" +
      "时间按 occurred_at 闭区间、升序排列；游标是 (occurred_at, id)；默认不含「已排除」事件；" +
      "时间为 UTC+8 规范值，精度按各自标注。" + 身份口径,
    缺口,
    空原因,
    出处: 空
      ? []
      : 事件们.slice(0, 3).map((行) => ({
          事实: `事件「${行.类型}」@${行.时间原文 ?? String(行.时间)}`,
          代表: 行.id,
          可下钻: "get_citation",
        })),
    下一步: 空
      ? []
      : [
          ...(下一页游标 === null
            ? []
            : [
                {
                  工具: "query_timeline",
                  参数: {
                    实体: args.实体,
                    ...(args.起 === undefined ? {} : { 起: args.起 }),
                    ...(args.止 === undefined ? {} : { 止: args.止 }),
                    ...(args.类型 === undefined ? {} : { 类型: args.类型 }),
                    游标: 下一页游标,
                  },
                  为什么: "继续看下一页（时间升序）",
                },
              ]),
          {
            工具: "get_citation",
            参数: { 事实类型: "event", 事实id: 事件们[0]!.id },
            为什么: "抽验时间线第一条事件的原文与出处",
          },
        ],
    ...(身份们.length === 0 ? {} : { 身份: 身份们 }),
  }
}
```
