# 项目技能提交审核 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让作者在项目「能力」面板里看见每条技能处在哪一步，并用一个按钮把它入库并提交审核，不需要知道资产编号或目录。

**Architecture:** 三处改动，全部落在既有单点上：① 服务端按 assetId 查库，给内核清单补权威的 `assetStatus`（不再让前端用 `enabled` 猜来源）；② 提交审核的内容来源统一为 `/draft/<assetId>`，MCP 与 HTTP 共用同一条存储意图；③ 新增两个 HTTP 端点（入库、提交），授权与目录边界复用现有实现。

**Tech Stack:** Bun 1.4 / TypeScript / Effect 4.0-beta / SolidJS / Drizzle ORM / oxlint / bun:test。

**Spec:** `docs/superpowers/specs/2026-11-01-项目技能提交审核-design.md`

在 `映射内核清单` 之后新增：

```ts
/**
 * 给内核清单补「它在不在库里」的权威信号（2026-11-01，设计 §4.1）。
 *
 * 一次批量查：内核看得见的技能可能几十条，逐条查会变成 N 次往返。
 * **不回落、不猜测**：查不到就是查不到，前端据此显示「未入库」。
 */
export async function 补资产状态(
  db: { execute(query: ReturnType<typeof sql>): PromiseLike<unknown> },
  列表: readonly 内核技能[],
  读者: string,
): Promise<内核技能[]> {
  const ids = [...new Set(列表.flatMap((条) => (条.assetId === undefined ? [] : [条.assetId])))]
  if (ids.length === 0) return [...列表]
  const 占位 = sql.join(ids.map((id) => sql`${id}`), sql`, `)

  const rows = rowsOf(await db.execute(sql`
    select id, status, owner_id from auth.asset where id in (${占位})
  `))
  const 表 = new Map(
    rows.map((row) => [
      String(row["id"]),
      { status: String(row["status"]) as AssetStatus, ownerId: String(row["owner_id"]) },
    ]),
  )

  // 驳回理由（设计 §4.7）：同一个批量里再查一次通知表。按 created_at 倒序，
  // JS 里取每个 asset 的第一条——不用 PG 的 `distinct on`，PGlite 上也一样跑。
  const 通知行 = rowsOf(await db.execute(sql`
    select asset_id, body from auth.asset_notification
    where action = 'reject_business' and recipient_id = ${读者} and asset_id in (${占位})
    order by created_at desc
  `))
  const 最近驳回 = new Map<string, string>()
  for (const row of 通知行) {
    const id = String(row["asset_id"])
    if (!最近驳回.has(id)) 最近驳回.set(id, String(row["body"]))
  }

  return 列表.map((条) => {
    const 行 = 条.assetId === undefined ? undefined : 表.get(条.assetId)
    if (行 === undefined) return 条
    const 理由 = 最近驳回.get(条.assetId!)
    return {
      ...条,
      assetStatus: 行.status,
      assetOwnerId: 行.ownerId,
      ...(理由 === undefined ? {} : { assetRejectReason: 理由 }),
    }
  })
}
```

  test("只改指向旧目标的链接；指向别处的、手写的真目录都不动", async () => {
    const 根 = await 临时目录()

    if (typeof 描述 !== "string") return fail(BAD_REQUEST, "description 必须是字符串")

/**
 * 能力面板的两个写动作（2026-11-01，设计 §4.4）。
 *
 * 与页面其它调用一致：同源 cookie、JSON、失败抛出可读消息（由面板显示，不吞）。
 */
export interface 动作结果 { readonly ok: true } | { readonly ok: false; readonly message: string }

async function 发(url: string, body: unknown): Promise<动作结果> {
  const res = await fetch(url, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(body),
  })
  if (res.ok) return { ok: true }
  const 解析 = await res.json().catch(() => undefined)
  const message =
    typeof 解析 === "object" && 解析 !== null && typeof Reflect.get(解析, "error") === "string"
      ? String(Reflect.get(解析, "error"))
      : `请求失败（${res.status}）`
  return { ok: false, message }
}

/** 未入库 → 入库 → 提交。两段串行：入库成功、提交失败是**可恢复**的中间态（设计 §4.3）。 */
export async function 入库并提交(input: {
  readonly projectId: string
  readonly skillPath: string
  readonly name: string
  readonly description: string
  readonly category: string
  readonly visibility: string
  readonly department?: string
}): Promise<{ readonly assetId: string } | { readonly error: string }> {
  const 建 = await fetch("/openhive/assets/draft", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(input),
  })
  const 体 = await 建.json().catch(() => undefined)
  if (!建.ok) {
    const 消息 = typeof 体 === "object" && 体 !== null && typeof Reflect.get(体, "error") === "string" ? String(Reflect.get(体, "error")) : `入库失败（${建.status}）`
    return { error: 消息 }
  }
  const assetId = String(Reflect.get(体 as object, "assetId"))
  const 交 = await 发(`/openhive/assets/${assetId}/submit`, {})
  return 交.ok ? { assetId } : { error: `已入库，但提交失败：${交.message}。请再点一次「提交审核」。` }
}

/** 已入库的草稿 → 提交审核。 */
export async function 提交审核(assetId: string): Promise<动作结果> {
  return 发(`/openhive/assets/${assetId}/submit`, {})
}

## 真栈验收（作者本人操作，脚本代替不了）

1. 在一个项目里让 AI 生成一个 skill（或把文件夹拷进项目目录）→ 左栏「能力」出现它，标「未入库」。
2. 点「提交审核」→ 选分类与可见范围 → 成功；行变成「草稿」。
3. 再点「提交审核」→ 行变「审核中」，「等业务审核」。
4. 用管理员账号在治理台驳回 → 作者刷新后看到理由。
5. 再提交 → 通过 → 发布 → 项目里那条链接指向线上那份，草稿副本消失。

## 缺口（本机验不了 / 需实测确认）

- 从外部拷入的 skill 目录，内核**多久**能扫到（决定面板要不要「刷新能力」）。
- 前端从 `location` 反推 `skillPath` 时，项目目录的大小写 / 8.3 短名形状（`#006-23`）。
- 驳回理由读取依赖 `auth.asset_notification` 有那一行；通知失败不重试，缺行时显示「尚未提交过」。
