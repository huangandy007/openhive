# 项目能力面板 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在项目左栏加第三个 tab「能力 N」，回答民警一个问题：**「我在这个项目里现在能用什么？」** 面板按 技能 / 知识库 / MCP 三组纵向排列，收起的组压成横条贴底，点哪条哪条上移展开。

**Architecture:** 后端在既有的 `GET /openhive/project/assets` 里，跑完对账后顺带在同一个项目目录上读内核 `Skill.Service.available()`，把清单并进同一个回包（`skills` 字段）。前端拿这一份数据做三态合并（正常 / 没生效 / 本项目自带），渲染成三档手风琴。前端不碰沙箱路径，也不发第二个请求。

**Tech Stack:** Bun · TypeScript · Effect（后端路由 + `InstanceStore`）· SolidJS + happy-dom（前端组件）· Tailwind v4（样式类）

**Spec:** `docs/superpowers/specs/2026-10-27-项目能力面板-design.md`

## Global Constraints

- **不动上游文件**：本次改到的全部是 openhive 自建文件（`packages/opencode/src/server/openhive/`、`packages/app/src/{project,ai-assets,workspace}/`）。上游文件一个字不改。
- **不新增依赖**。
- **`bun test` 必须带 `timeout 300`**；退出码 124 不自动重跑。根目录禁止 `bun test`（其 script 直接 `exit 1`），一律在受影响 package 内跑。
- **不得 `git add -A` / `git add .`**，每次只 add 本任务列出的文件。
- **`undefined`（不知道）≠ 空数组 / `0`（明确没有）**：任何「读不到」都不得渲染成「没有」（`#002-02`）。
- **测试断言不比较节点**：被 Solid 渲染过的节点会让 bun 的实得值打印器挂死/OOM（`#009-01` / `#005-01`）。断布尔、断字符串、断数字。
- **后端集成测试的客户端契约写字面量，不 import 生产常量**（该测试文件头部已明文规定，`#003-05`）。这条只管 URL / 路径字面量；纯函数单测 import 被测函数是正常的。
- 提交信息末尾标注命中的 LEARNINGS 条目号。

```ts
/**
 * 内核视角的一条技能。
 *
 * **不含 `content`**：`Skill.Info.content` 是 SKILL.md 全文，进 HTTP 回包既浪费又是泄露面。
 * `assetId` / `assetName` 只在它确实是库里的一份资产时才有——「本项目自带」的那条两者皆无，
 * 前端据此分第三态（不能给它画「停用」）。
 */
export interface 内核技能 {
  readonly name: string
  readonly description?: string
  readonly location: string
  readonly assetId?: string
  readonly assetName?: string
}

interface 状态基 {
  readonly enabled: readonly string[]
  readonly enabledCount: number
  readonly limit: number
}

/**
 * 把内核清单并进返回体。
 *
 * `内核 === undefined` ⇒ **整个 `skills` 键缺席**，不是空数组。空数组会被前端读成
 * 「内核一条都没看见」⇒ 把每条技能都标成「没生效」，而事实只是「这次没读到」（`#002-02`）。
 */
export function 带内核清单<T extends 状态基>(
  base: T,
  内核: readonly 内核技能[] | undefined,
): T & { skills?: readonly 内核技能[] } {
  if (内核 === undefined) return base
  return { ...base, skills: 内核 }
}
```

```ts
/** 从内核技能的 location 里取最后一级目录名（= assetId，或用户自己的目录名）。 */
function 目录名(location: string): string | undefined {
  const 段 = location.split(/[\\/]/).filter((s) => s.length > 0)
  // 期望形态：<沙箱>/.opencode/(skill|skills)/<名>/SKILL.md —— 取倒数第二段。
  if (段.length < 2) return undefined
  return 段[段.length - 2]
}

/**
 * 在算好的项目目录上读内核技能清单（`Skill.Service.available()`）。
 *
 * `store` 缺席（只挂路由子集的测试）⇒ 返回 `undefined`：**不知道**，不谎报为空。
 * 读失败同理——告警并返回 `undefined`，让前端说「暂时读不到」，而不是把每条技能标成没生效。
 *
 * ⚠️ 必须在对账**之后**调（见 `对账并读` 末尾）。反过来的话，新成员第一次进项目时
 * 沙箱里还没有链接，全部技能都会被误报成「没生效」。
 */
function 读内核清单(deps: Deps, directory: string, 标题: ReadonlyMap<string, string>) {
  const store = deps.store
  if (Option.isNone(store)) return Effect.succeed<readonly 内核技能[] | undefined>(undefined)
  return store.value
    .provide(
      { directory },
      Effect.gen(function* () {
        const skill = yield* Skill.Service
        return yield* skill.available()
      }),
    )
    .pipe(
      Effect.map((list) =>
        list.map((info): 内核技能 => {
          const id = 目录名(info.location)
          const 名 = id === undefined ? undefined : 标题.get(id)
          return {
            name: info.name,
            ...(info.description === undefined ? {} : { description: info.description }),
            location: info.location,
            ...(id === undefined ? {} : { assetId: id }),
            ...(名 === undefined ? {} : { assetName: 名 }),
          }
        }),
      ),
      Effect.catchCause((cause) =>
        Effect.logWarning("读内核技能清单失败，本次不回报（不谎报为空）", { directory, cause }).pipe(
          Effect.as<readonly 内核技能[] | undefined>(undefined),
        ),
      ),
    )
}
```

```ts
import type { 内核技能 } from "@/ai-assets/enable-api"

/**
 * 「这个项目现在能用什么」的三态合并（`2026-10-27-项目能力面板-design.md` §4）。
 *
 * ## 三态
 *
 * - `library` ＋ `loaded: true` —— 库里有记录、内核也加载到了（正常）
 * - `library` ＋ `loaded: false` —— 库里有、内核没看见（**服务端已先对过账**，所以这是真问题）
 * - `local` —— 内核看得见、库里没有（用户自己在项目文件夹里写的）
 *
 * ## 为什么没有内核数据就返回 `undefined`
 *
 * 只有库侧数据时，无法区分「没生效」与「只是没读到」。返回空数组会把这些技能全画成
 * 「一条都没装」，那是假话（`#002-02`）。
 *
 * ## 顺序
 *
 * 库内条目按 `enabled` 的迭代顺序（服务端给什么就什么顺序），自带条目按内核返回顺序排在后面。
 * 两个来源各自有序，合并时**不重排**——重排等于替用户决定「哪个更重要」。
 */
export interface 库内条目 {
  readonly kind: "library"
  readonly assetId: string
  readonly name: string
  readonly description?: string
  readonly loaded: boolean
}

export interface 自带条目 {
  readonly kind: "local"
  readonly name: string
  readonly description?: string
}

export type 能力条目 = 库内条目 | 自带条目

export interface 合并输入 {
  readonly enabled: ReadonlySet<string>
  readonly skills: readonly 内核技能[] | undefined
}

export function 合并能力(输入: 合并输入): 能力条目[] | undefined {
  const 清单 = 输入.skills
  if (清单 === undefined) return undefined

  const 内核在某资产 = new Map<string, 内核技能>()
  const 自带: 自带条目[] = []
  for (const 条 of 清单) {
    if (条.assetId !== undefined && 输入.enabled.has(条.assetId)) {
      内核在某资产.set(条.assetId, 条)
      continue
    }
    自带.push({
      kind: "local",
      name: 条.name,
      ...(条.description === undefined ? {} : { description: 条.description }),
    })
  }

  const 库内: 库内条目[] = []
  for (const assetId of 输入.enabled) {
    const 命中 = 内核在某资产.get(assetId)
    库内.push({
      kind: "library",
      assetId,
      // 中文名优先取库里标题；内核没加载到它时只有 assetId 可用（不编一个名字出来）。
      name: 命中?.assetName ?? 命中?.name ?? assetId,
      ...(命中?.description === undefined ? {} : { description: 命中.description }),
      loaded: 命中 !== undefined,
    })
  }

  return [...库内, ...自带]
}

/**
 * 数「我能用的」= 库内条目数（含没生效的 ②）。
 *
 * 自带的 ③ 不数：它不在配额账上，算进去会出现「3/20」却只能再装 18 个（设计 §6）。
 */
export function 计数(条目: readonly 能力条目[]): number {
  return 条目.filter((条) => 条.kind === "library").length
}
```

```tsx
                  项目共启用 {props.enabledCount()} 个，其中 {数不到()} 个不在你的授权范围。

            </p>
          </Show>
        </div>

        <For each={后面()}>{(组) => 组头(组, true)}</For>

}
```
