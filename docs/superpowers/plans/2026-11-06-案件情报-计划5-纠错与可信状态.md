# 计划 5：纠错与可信状态（事实层的「人改机器」闭环）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让民警能给机器抽出来的每一条事实打 ✓ / ✗ / ？、改正错值、合并重复实体，并且每一次改都留下「改前、改后、谁、何时、为什么」——重放不冲掉人的判断，AI 只能提议不能改数。

**Architecture:** 一条新的写链路「读当前值 → 校验 → 同事务改值 ＋ 写留痕」，一个只读出口给出单条事实的完整画像（事实 ＋ 引用 ＋ 变更历史 ＋ 依赖标记）。留痕单独一张 `case_fact_change`（不是 `audit_event`：它必须与事实改动同事务、且要能按事实查）。合并＝别名并集 ＋ 关系改指 ＋ 自环标已排除 ＋ 删被并入行，拆分凭留痕里的全量快照原样恢复。传播＝实体被改后，指向它的关系与参与它的事件打 `basis_changed_at`。

**Tech Stack:** Bun 1.4.3 · TypeScript 5.8.2 · Effect 4.0.0-beta.83 · Hono 4.10.7 · Drizzle ORM 1.0.0-rc.2 · PGlite（测试用生产驱动夹具） · oxlint 1.60.0

**Spec:** `docs/superpowers/specs/2026-11-05-案件知识与情报体系/design.md` §5.3 / §9.1 / §9.2 / §9.3 / §9.4 / §9.5 / §9.6，判据 A11 / A18

## 预先裁定（实施期按此执行，不再回头讨论）

> 每条都写「为什么」与「错了的代价」。执行者若发现事实与此不符，按 ledger 规则上报，不要私自改口径。

**R1 · 本计划只做后端，前端一行不改。** 详情页底部三个按钮（§9.2）在计划 7。
- 为什么：计划 3/4 已经把「中栏」整体划给计划 7；现在顺手做一半界面，会让计划 7 拿到两份半成品。
- 代价：本计划交付后，功能只能靠测试与 curl 验；真栈可见的入口要等到计划 7（缺口表）。

**R2 · 留痕用新表 `case_fact_change`，不写 `audit_event`。**
- 为什么：① §9.6 要求改前值/改后值/人/时间/原因**全部留存**，它必须与事实改动**同事务**——`audit_event` 的既有口径是「尽力记、失败不拖垮业务」（`audit.ts` 文件头），事务里只能事后补记；② 「这条事实改过几次」要按 `(project_id, fact_type, fact_id)` 查，`audit_event` 没有这个索引。
- 代价：同一次纠错不会出现在治理审计看板里；若以后法制口径要求「进审计流水」，再在留痕写入处加一次 `尽力记`（不反向依赖）。

**R3 · 「修正」不改事实表结构，值直接写回当前列，原值只存在留痕里。**
- 为什么：§9.1「已修正：改过值，保留原值」——「保留」的回答是「查得到」，不是「再加一列」。加 `原值列` 会让每个读路径都要判断「读哪一列」，而撤销已经能凭留痕恢复。
- 代价：不看留痕的人在库里只看到新值；详情接口会把 `changes` 一并返回，界面必须能看见「改过」。

**R4 · 修正只认白名单字段，认不出的键一律 `409 bad_changes`。**
（2026-11-06 Task 3/4 统一：`400` 只给「结构不对/枚举不认识」（如 `action` 不在五种里、`reasonKind` 不认识），业务规则类拒绝一律 `409` ＋ `code`。原文写 400，与实现和测试不一致，按实现订正。）
- 白名单：实体 `canonicalValue` / `entityType`；关系 `amount` / `basis` / `relationType`；事件 `summary` / `occurredAt` / `precision`。
- 为什么：fail-closed。静默忽略一个拼错的键，用户会以为改成了；而失败时用户能看到「这个字段不支持修正」。
- 代价：改不了 `firstAt/lastAt/times`（聚合值，应由重放重算），缺口表记录。

**R5 · 改名/改类型撞上已存在的实体 ⇒ 409 `merge_required`，不自动合并。**
- 为什么：合并是不可逆性更高、要留「依据」的动作（§9.3）；把「改个名」偷偷做成合并，等于替用户做了判断。
- 代价：用户要两步（先看到提示，再走合并）；提示文案必须说清「已经有一个实体叫 X，请用合并」。

**R6 · 合并只允许同类型实体。**
- 为什么：六类要素的计数、图标、排序都按 `type` 走；跨类合并会让「这个实体到底算什么」失去答案。P19（同一账号被标成 `账户`/`号码`）的正确解是**先修正类型、再合并**。
- 代价：跨类合并要两步；错误更早暴露。

**R7 · 合并 = 别名并集 ＋ 关系改指 ＋ 自环标「已排除」 ＋ 删被并入行。**
- 为什么：§9.3「被并入者成为别名，关系一并转移」。自环（合并后 `from_id = to_id`）不是数据错误，是「同一个人给自己转账」这种事实已不成立，按 §9「不删除，只打状态」标 `已排除`。
- 代价：自环关系要写进合并留痕的 `after.自环`（**不**单独写 `排除` 留痕——库约束要求 `排除` 带「识别错/抽取错/材料本身有问题」三选一，而自环不是这三种原因）。

**R8 · 采纳 AI 提议只改提议状态，不自动执行合并。**
- 为什么：合并要留「依据什么」（§9.3），而 AI 给的理由**不等于**人的依据；一步到位会让留痕里的依据变成模型写的字。
- 代价：采纳之后用户还要点一次合并（两步）；提议与合并的关联靠 `payload` 里的 `survivorId`/`mergedId` 由界面带过去。

**R9 · 传播只做「实体被修正/排除 ⇒ 指向它的关系与参与它的事件打 `basis_changed_at`」。**
- 为什么：这两种依赖关系今天真实存在（`from_id/to_id`、`participants`）；「产物引用事实 ⇒ 报告请复核」的那一半**今天没有生产者**（产物的 `citation` 要等计划 7 保存产物时才写），现在建列就是空转。
- 代价：报告复核标记挂账；对某条依赖事实做任何人工动作时清除它的标记（`basis_changed_at = null`）。

**R10 · 「已排除」默认不进读路径。**
- 为什么：§9.1「已排除的数据不删，只是不进统计、不进 AI 回答，可切换查看」。默认藏、显式带 `includeExcluded=true` 才给。
- 代价：默认视图里被排除的事实「消失」——所以详情接口在 `includeExcluded=true` 时必须仍能取到它，界面要有「显示已排除」的开关（计划 7）。

**R11 · 权限 = 项目成员，不做「只有属主能改」。**
- 为什么：§3「协作边界由项目本身承担」；文件操作、解析动作今天都是「成员即可」。纠错若单独收紧，会让共享项目里只有属主能纠错——那不是设计要求。
- 代价：任何成员都能改；留痕记人，事后可查（§9.6 的用途正在这里）。

**R12 · 操作人姓名写时快照，与 `0015_audit_event` ② 同口径。**
- 为什么：账号被清理后留痕仍要能回答「谁」；join 出来的人名会静默变成空白。
- 代价：改名后旧留痕仍是旧名——这是对的行为（记的是当时那个人）。

```ts
export * as OpenhiveCaseFactChange from "./case-fact-change"

import { sql } from "drizzle-orm"
import { rowsOf } from "@opencode-ai/auth/migrate"
import { nowSeconds } from "@opencode-ai/auth/time"
import type { Queryable } from "./case-store"

/**
 * 事实留痕（设计 §9.6）：谁、何时、改前、改后、为什么。
 *
 * ## 为什么不是 `audit_event`
 *
 * 见 `0033_case_fact_trust.sql` 文件头：留痕必须与事实改动**同事务**，而 `audit_event`
 * 的口径是「尽力记、失败不拖垮业务」；按事实查「改过几次」也要用到本表自己的索引。
 *
 * ## 只增不改
 *
 * 本文件**没有** update / delete 函数，也不打算有——留痕可以被改 = 留痕不存在
 * （与 `@opencode-ai/auth/audit` 同一条纪律）。
 *
 * ## `before` / `after` 存的是「恢复得回去」的快照
 *
 * 撤销恢复的是 `before`；拆分恢复的是合并那行的 `before`。所以写进来的必须是**全量**，
 * 不是「只变了哪几个字段」——少一个字段，撤销就会把那个字段留在半改状态。
 */

export const 留痕类型们 = ["entity", "relation", "event"] as const
export type 留痕类型 = (typeof 留痕类型们)[number]

export const 留痕动作们 = ["确认", "排除", "存疑", "修正", "撤销", "合并", "拆分", "采纳", "否决"] as const
export type 留痕动作 = (typeof 留痕动作们)[number]

export const 纠正原因们 = ["识别错", "抽取错", "材料本身有问题"] as const
export type 纠正原因 = (typeof 纠正原因们)[number]

/** 可以「撤销」的动作全集：合并的撤销是拆分，提议的撤销不在本计划。 */
export const 可撤销动作们: readonly 留痕动作[] = ["确认", "排除", "存疑", "修正"]

export interface 操作人 {
  readonly id: string
  readonly name: string
  readonly policeNo: string
}

export interface 留痕写入 {
  readonly projectId: string
  readonly factType: 留痕类型
  readonly factId: string
  readonly action: 留痕动作
  readonly before?: unknown
  readonly after?: unknown
  readonly reasonKind?: 纠正原因 | null
  readonly reasonText?: string | null
  readonly actor: 操作人
}

/**
 * JSON 参数：`::text::jsonb` 这一层**不是装饰**（2026-11-06 本机实测，bun 1.4.3）。
 *
 * PG 由 `::jsonb` 把参数推成 jsonb 后，驱动会对「声明为 jsonb 的字符串参数」再
 * `JSON.stringify` 一次 ⇒ `{"a":1}` 落成 JSON **字符串标量**（`jsonb_typeof` = `string`）。
 * 先转 `text` 让参数按 text 原样送达，再由 PG 解析，才真的得到对象。
 * 与 `case-fact-store.ts` 的 `文本数组` 是同一条实测结论。
 */
const 杰森 = (值: unknown) =>
  值 === undefined || 值 === null ? sql`null` : sql`${JSON.stringify(值)}::text::jsonb`

/**
 * ## 读 `before` / `after` 不做二次解析
 *
 * 写入走 `::text::jsonb`（`杰森`），对象到手就是对象；驱动对 jsonb **字符串标量**
 * （`"abc"` / `"123"` / `"null"`）到手也已经是 JS 字符串。再 `JSON.parse` 一次会把
 * `"123"` 变成数字、`"null"` 变成 null——证据按原样恢复的契约就破了。本表由 0033 新建、
 * 没有二次编码的旧行，故不存在要兼容的历史；形状异常由测试里的裸 SQL 断言守，不靠 DAO 猜。
 */

/**
 * 操作人快照：姓名与警号**写时取**，之后不再 join（同 `0015_audit_event` ②）。
 *
 * 账号查不到（理论不可达）时用「已注销用户（前 8 位）」占位：`slice(0, 8)` 的宽度与
 * `audit.ts:71` 同；区别是这边连空串姓名也回落（那边不会）。不隐藏、也不写空串。
 */
export async function 操作人快照(db: Queryable, userId: string): Promise<操作人> {
  if (userId === "") throw new Error("留痕缺少操作人")
  const 行 = rowsOf(await db.execute(sql`select name, police_no from auth.user where id = ${userId}`))
  const 人 = 行[0]
  const 名 = 人?.name
  return {
    id: userId,
    name: typeof 名 === "string" && 名 !== "" ? 名 : `已注销用户（${userId.slice(0, 8)}）`,
    policeNo: typeof 人?.police_no === "string" ? 人.police_no : "",
  }
}

/** 记一条留痕，返回它的 id。**必须与事实改动在同一个事务里**（调用方负责）。 */
export async function 记变更(db: Queryable, input: 留痕写入): Promise<string> {
  const id = crypto.randomUUID()
  await db.execute(sql`
    insert into auth.case_fact_change
      (id, project_id, fact_type, fact_id, action, before, after, reason_kind, reason_text,
       actor_id, actor_name, actor_police_no, created_at)
    values (${id}, ${input.projectId}, ${input.factType}, ${input.factId}, ${input.action},
            ${杰森(input.before)}, ${杰森(input.after)},
            ${input.reasonKind ?? null}, ${input.reasonText ?? null},
            ${input.actor.id}, ${input.actor.name}, ${input.actor.policeNo}, ${nowSeconds()})
  `)
  return id
}

export interface 变更视图 {
  readonly id: string
  readonly action: 留痕动作
  readonly before: unknown
  readonly after: unknown
  readonly reasonKind: 纠正原因 | null
  readonly reasonText: string | null
  readonly actorId: string
  readonly actorName: string
  readonly createdAt: number
}

/** 按事实读全部留痕，写入正序（读出来就是一条时间线）。 */
export async function 变更历史(
  db: Queryable,
  projectId: string,
  factType: 留痕类型,
  factId: string,
): Promise<变更视图[]> {
  const 行们 = rowsOf(
    await db.execute(sql`
      select id, action, before, after, reason_kind, reason_text, actor_id, actor_name, created_at
        from auth.case_fact_change
       where project_id = ${projectId} and fact_type = ${factType} and fact_id = ${factId}
       order by seq asc
    `),
  )
  return 行们.map((行) => ({
    id: String(行.id),
    action: String(行.action) as 留痕动作,
    before: 行.before ?? null,
    after: 行.after ?? null,
    reasonKind: 纠正原因或空(行.reason_kind),
    reasonText: 文本或空(行.reason_text),
    actorId: String(行.actor_id),
    actorName: String(行.actor_name),
    createdAt: Number(行.created_at),
  }))
}

/** `unknown` → 原因枚举或 null：驱动读 `text` 列只会给字符串或 null，其它形状按没有处理。 */
function 纠正原因或空(值: unknown): 纠正原因 | null {
  return typeof 值 === "string" && (纠正原因们 as readonly string[]).includes(值) ? (值 as 纠正原因) : null
}

/** 同上，非字符串一律按 null——`String(unknown)` 会触发 no-base-to-string。 */
function 文本或空(值: unknown): string | null {
  if (值 === null || 值 === undefined) return null
  return typeof 值 === "string" ? 值 : null
}

/**
 * 从一条「撤销」留痕里读出它撤销了哪一条。
 *
 * 用途：同一条动作不能被反复撤销（否则「撤销」变成永动机，留痕里堆一串一样的行）。
 */
export function 被撤销的留痕(after: unknown): string | undefined {
  if (typeof after !== "object" || after === null) return undefined
  const 值 = (after as Record<string, unknown>)["被撤销的留痕"]
  return typeof 值 === "string" ? 值 : undefined
}

/**
 * 最近一次**还没被撤销过**的可撤销动作。没有 ⇒ `undefined`（调用点据此回 `nothing_to_undo`）。
 *
 * 写入序读、反向找：先跳过所有 `撤销` 行（它们不是被撤销的对象），再跳过已经被某条
 * `撤销` 点名过的那几条。
 *
 * 「写入序」= `seq`（0034 的 identity 列），**不是** `created_at`：后者只有秒级、同秒内
 * 与 `id`（随机 UUID）一起排是随机序，反向找会拿到较早那条，撤销就把后来的改动丢了。
 */
export async function 最近一次可撤销(
  db: Queryable,
  projectId: string,
  factType: 留痕类型,
  factId: string,
): Promise<变更视图 | undefined> {
  const 全部 = await 变更历史(db, projectId, factType, factId)
  const 已撤销 = new Set(
    全部
      .filter((条) => 条.action === "撤销")
      .map((条) => 被撤销的留痕(条.after))
      .filter((id): id is string => id !== undefined),
  )
  return [...全部]
    .reverse()
    .find((条) => 可撤销动作们.includes(条.action) && !已撤销.has(条.id))
}
```

```ts
function 文本(值: unknown): string | null {
  return 值 === null || 值 === undefined ? null : String(值)
}

function 数字(值: unknown): number | null {
  if (值 === null || 值 === undefined) return null
  const n = Number(值)
  if (!Number.isFinite(n)) throw new Error(`数值列读回的不是数字：${String(值)}`)
  return n
}

function 整数(值: unknown): number | null {
  const n = 数字(值)
  if (n === null) return null
  if (!Number.isInteger(n)) throw new Error(`整数列读回的不是整数：${String(值)}`)
  return n
}

/** `array_to_json(...)::text` 读回来一定是 JSON 文本；解不开就是空数组（不猜）。 */
function 文本组(值: unknown): string[] {
  if (typeof 值 !== "string" || 值 === "") return []
  try {
    const 解: unknown = JSON.parse(值)
    return Array.isArray(解) ? 解.map((x) => String(x)) : []
  } catch {
    return []
  }
}

/**
 * jsonb 读回：只解「二次编码的旧对象/数组」（字符串以 `{` / `[` 开头），其余原样返回。
 * 不做无条件的 `JSON.parse`——那会把真标量 `"123"` 变成数字、`"null"` 变成 null（Task 1 R4）。
 */
function 读杰森(值: unknown): unknown {
  if (typeof 值 !== "string" || !(值.startsWith("{") || 值.startsWith("["))) return 值 ?? null
  try {
    return JSON.parse(值)
  } catch {
    return 值
  }
}

  projectId: string,

  readonly type: 留痕类型

  readonly includeExcluded?: boolean

/**
 * 一条事实的完整画像。找不到（或已排除且没要求包含）⇒ `undefined`。
 *
 * 三个读必须是**同一个库句柄**：调用方给事务就给事务，给连接就给连接。
 */
export async function 事实详情(db: Queryable, input: 事实详情入参): Promise<事实详情 | undefined> {
  const 包含已排除 = input.includeExcluded === true
  const 事实 =
    input.type === "entity"
      ? await 读实体(db, input.projectId, input.id, 包含已排除)
      : input.type === "relation"
        ? await 读关系(db, input.projectId, input.id, 包含已排除)
        : await 读事件(db, input.projectId, input.id, 包含已排除)
  if (事实 === undefined) return undefined
  const [citations, changes] = await Promise.all([
    引用们(db, input.projectId, input.type, input.id),
    变更历史(db, input.projectId, input.type, input.id),
  ])
  return { ...事实, citations, changes }
}
```

```ts
interface Deps {

  /** 「这项目是我的吗」有一道来源在每用户库（老项目属主），见 `project-actor.ts`。 */

function ok(value: unknown) {
  return HttpServerResponse.jsonUnsafe(value, { status: 200 })
}

function fail(status: number, error: string, code?: string) {
  return HttpServerResponse.jsonUnsafe(code === undefined ? { error } : { error, code }, { status })
}

const 身份 = Effect.serviceOption(User.Service)

const 成员角色 = (deps: Deps, userId: string, projectId: string) =>
  成员角色共享({ pg: deps.pg(), database: deps.database }, userId, projectId)

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null && !Array.isArray(value)
}

/** 体不是 JSON 对象 ⇒ `undefined`（同 `project-assets.ts` / `case-parse.ts` 的 `读体`）。 */
function 读体(request: HttpServerRequest.HttpServerRequest) {
  return request.json.pipe(
    Effect.match({ onFailure: () => undefined, onSuccess: (value: unknown) => (isRecord(value) ? value : undefined) }),
  )
}

function 是合法段(value: unknown): value is string {
  return typeof value === "string" && value !== "" && User.isSafePathSegment(value)
}

const 是事实类型 = (value: unknown): value is 留痕类型 =>
  typeof value === "string" && (留痕类型们 as readonly string[]).includes(value)

function handleFacts(request: HttpServerRequest.HttpServerRequest, deps: Deps) {
  return Effect.gen(function* () {
    const user = yield* 身份
    if (Option.isNone(user)) return HttpServerResponse.empty({ status: 401 })

    const 参数 = new URL(request.url, "http://localhost").searchParams
    const projectId = 参数.get("projectId")
    const type = 参数.get("type")
    const id = 参数.get("id")
    if (!是合法段(projectId)) return fail(400, "projectId 非法", "bad_request")
    if (!是事实类型(type)) return fail(400, "type 只能是 entity / relation / event", "bad_request")
    if (typeof id !== "string" || id === "") return fail(400, "id 不能为空", "bad_request")

    if ((yield* 成员角色(deps, user.value.id, projectId)) === undefined)
      return fail(403, "不是该项目成员", "forbidden")

    const 详情 = yield* Effect.promise(() =>
      事实详情(deps.pg(), {
        projectId,
        type,
        id,
        includeExcluded: 参数.get("includeExcluded") === "true",
      }),
    )
    if (详情 === undefined) return fail(404, "找不到这条事实", "fact_not_found")
    return ok(详情)
  })
}
```

```ts
export * as OpenhiveCaseTrust from "./case-trust"

import { sql } from "drizzle-orm"
import { rowsOf } from "@opencode-ai/auth/migrate"
import {
  type 纠正原因,
  type 留痕类型,
  记变更,
  最近一次可撤销,
  操作人快照,
} from "./case-fact-change"
import type { 事实信任态 } from "./case-fact-store"
import { inTransaction, type Queryable } from "./case-store"

/**
 * 裁决：人给事实打 ✓ / ✗ / ？、改正错值、撤销上一次人工动作（设计 §9.1 / §9.2 / §9.6）。
 *
 * ## 一个事务里做三件事
 *
 * 读当前值（`for update`）→ 改 → 写留痕。**留痕必须与事实改动同事务**：分开写的话，
 * 进程在中间挂掉就留下「改了但没有痕迹」，而 §9.6 的整个用途就是「事后说得清」。
 *
 * ## 为什么读当前值要 `for update`
 *
 * 两个人同时改同一条事实时，后写的那次若基于读到的旧值算 `before`，留痕里的「改前」
 * 就是假的。锁住这一行，后到的事务会等，然后再读到的就是新值。
 *
 * ## 动作而不是目标状态
 *
 * 与 `case-parse.ts` 的 `POST /parse` 同一条口径：界面发「确认 / 排除」，落点由这里算。
 */

export const 裁决动作们 = ["确认", "排除", "存疑", "修正", "撤销"] as const
export type 裁决动作 = (typeof 裁决动作们)[number]

export const 裁决错误码们 = [
  "fact_not_found",
  "bad_changes",
  "merge_required",
  "basis_required",
  "nothing_to_undo",
] as const
export type 裁决错误码 = (typeof 裁决错误码们)[number]

export class 裁决冲突 extends Error {
  constructor(
    message: string,
    readonly code: 裁决错误码,
  ) {
    super(message)
    this.name = "裁决冲突"
  }
}

/** 一条事实「人改得动」的那几个值。`trustState` 单独放，它不属于「值」。 */
export interface 当前事实 {
  readonly trustState: 事实信任态
  readonly 值: Record<string, unknown>
}

const 信任态们 = ["自动抽取", "已确认", "已修正", "已排除", "存疑"] as const

function 是信任态(值: unknown): 值 is 事实信任态 {
  return typeof 值 === "string" && (信任态们 as readonly string[]).includes(值)
}

function 文本(值: unknown): string | null {
  return 值 === null || 值 === undefined ? null : String(值)
}

function 数字(值: unknown): number | null {
  if (值 === null || 值 === undefined) return null
  const n = Number(值)
  if (!Number.isFinite(n)) throw new Error(`数值列读回的不是数字：${String(值)}`)
  return n
}

/**
 * 读一条事实当前的状态与可改值。**`for update` 必须在事务里**（不在事务里调用会立刻生效，
 * 调用方自己保证传进来的是 `tx`）。
 *
 * 三种事实的「值」形状就是 `case-fact-change.ts` 留痕里 `before` / `after` 的形状——
 * 撤销靠它恢复，所以两边**必须是同一份**：改这里就要改撤销。
 */
export async function 读当前事实(
  db: Queryable,
  projectId: string,
  type: 留痕类型,
  id: string,
): Promise<当前事实 | undefined> {
  if (type === "entity") {
    const 行 = rowsOf(
      await db.execute(sql`
        select trust_state, canonical_value, type from auth.case_entity
         where project_id = ${projectId} and id = ${id}
         for update
      `),
    )[0]
    if (行 === undefined) return undefined
    return {
      trustState: String(行.trust_state) as 事实信任态,
      值: { canonicalValue: String(行.canonical_value), entityType: String(行.type) },
    }
  }
  if (type === "relation") {
    const 行 = rowsOf(
      await db.execute(sql`
        select trust_state, amount, basis, type from auth.case_relation
         where project_id = ${projectId} and id = ${id}
         for update
      `),
    )[0]
    if (行 === undefined) return undefined
    return {
      trustState: String(行.trust_state) as 事实信任态,
      值: {
        amount: 数字(行.amount),
        basis: 文本(行.basis),
        relationType: String(行.type),
      },
    }
  }
  const 行 = rowsOf(
    await db.execute(sql`
      select trust_state, summary, occurred_at, precision from auth.case_event
       where project_id = ${projectId} and id = ${id}
       for update
    `),
  )[0]
  if (行 === undefined) return undefined
  return {
    trustState: String(行.trust_state) as 事实信任态,
    值: {
      summary: 文本(行.summary),
      occurredAt: 数字(行.occurred_at),
      precision: 文本(行.precision),
    },
  }
}

export interface 裁决输入 {
  readonly projectId: string
  readonly factType: 留痕类型
  readonly factId: string
  readonly action: 裁决动作
  readonly reasonKind?: 纠正原因 | null
  readonly reasonText?: string | null
  /** 只有 `修正` 用：白名单字段 → 新值。 */
  readonly changes?: Record<string, unknown>
  readonly by: string
}

export interface 裁决结果 {
  readonly trustState: 事实信任态
  readonly 值: Record<string, unknown>
  readonly 留痕: string
}

async function 只改状态(
  tx: Queryable,
  input: 裁决输入,
  当前: 当前事实,
  目标: 事实信任态,
): Promise<裁决结果> {
  const 表 =
    input.factType === "entity"
      ? sql`auth.case_entity`
      : input.factType === "relation"
        ? sql`auth.case_relation`
        : sql`auth.case_event`
  await tx.execute(sql`
    update ${表} set trust_state = ${目标}
     where project_id = ${input.projectId} and id = ${input.factId}
  `)
  const 留痕 = await 记变更(tx, {
    projectId: input.projectId,
    factType: input.factType,
    factId: input.factId,
    action: input.action as "确认" | "排除" | "存疑",
    before: { trustState: 当前.trustState },
    after: { trustState: 目标 },
    reasonKind: input.reasonKind ?? null,
    reasonText: input.reasonText ?? null,
    actor: await 操作人快照(tx, input.by),
  })
  return { trustState: 目标, 值: 当前.值, 留痕 }
}

async function 撤销(
  tx: Queryable,
  input: 裁决输入,
  当前: 当前事实,
): Promise<裁决结果> {
  const 目标 = await 最近一次可撤销(tx, input.projectId, input.factType, input.factId)
  if (目标 === undefined) throw new 裁决冲突("这条事实没有可以撤销的人工动作", "nothing_to_undo")

  const 前 = 目标.before
  if (typeof 前 !== "object" || 前 === null) throw new 裁决冲突("留痕里没有可恢复的前值", "nothing_to_undo")
  const 快照 = 前 as Record<string, unknown>
  const 前状态 = 快照["trustState"]
  if (!是信任态(前状态)) throw new 裁决冲突("留痕里的前状态不合法", "nothing_to_undo")

  const 值: Record<string, unknown> = { ...当前.值 }
  for (const 键 of Object.keys(当前.值)) {
    if (键 in 快照) 值[键] = 快照[键]
  }

  await 写回(tx, input.projectId, input.factType, input.factId, 前状态, 值)
  const 留痕 = await 记变更(tx, {
    projectId: input.projectId,
    factType: input.factType,
    factId: input.factId,
    action: "撤销",
    before: { trustState: 当前.trustState, ...当前.值 },
    after: { trustState: 前状态, ...值, 被撤销的留痕: 目标.id },
    actor: await 操作人快照(tx, input.by),
  })
  return { trustState: 前状态, 值, 留痕 }
}

/**
 * 把「状态 ＋ 值」写回事实表。**Task 4 的修正与撤销共用这一处**——写回只有一份，
 * 三种表的列名映射也只有一份。
 */
export async function 写回(
  tx: Queryable,
  projectId: string,
  type: 留痕类型,
  id: string,
  trustState: 事实信任态,
  值: Record<string, unknown>,
): Promise<void> {
  if (type === "entity") {
    await tx.execute(sql`
      update auth.case_entity
         set trust_state = ${trustState}, canonical_value = ${String(值["canonicalValue"])},
             type = ${String(值["entityType"])}
       where project_id = ${projectId} and id = ${id}
    `)
    return
  }
  if (type === "relation") {
    const 金额 = 值["amount"]
    await tx.execute(sql`
      update auth.case_relation
         set trust_state = ${trustState}, amount = ${金额 === null || 金额 === undefined ? null : Number(金额).toFixed(2)},
             basis = ${值["basis"] === null || 值["basis"] === undefined ? null : String(值["basis"])},
             type = ${String(值["relationType"])}
       where project_id = ${projectId} and id = ${id}
    `)
    return
  }
  await tx.execute(sql`
    update auth.case_event
       set trust_state = ${trustState},
           summary = ${值["summary"] === null || 值["summary"] === undefined ? null : String(值["summary"])},
           occurred_at = ${值["occurredAt"] === null || 值["occurredAt"] === undefined ? null : Number(值["occurredAt"])},
           precision = ${值["precision"] === null || 值["precision"] === undefined ? null : String(值["precision"])}
     where project_id = ${projectId} and id = ${id}
  `)
}

/**
 * 裁决入口。`修正` 与 `撤销` 在 Task 4 接上；本任务只认 确认 / 排除 / 存疑。
 */
export async function 裁决(db: Queryable, input: 裁决输入): Promise<裁决结果> {
  return inTransaction(db, async (tx) => {
    const 当前 = await 读当前事实(tx, input.projectId, input.factType, input.factId)
    if (当前 === undefined) throw new 裁决冲突("找不到这条事实", "fact_not_found")

    if (input.action === "确认" || input.action === "排除" || input.action === "存疑") {
      const 目标: 事实信任态 =
        input.action === "确认" ? "已确认" : input.action === "排除" ? "已排除" : "存疑"
      // §9.2：选「错」要写一句话并选原因。库约束也会挡，但在这里先回一句人话。
      if (input.action === "排除" && (input.reasonKind === null || input.reasonKind === undefined || !input.reasonText?.trim()))
        throw new 裁决冲突("判定为错时必须选原因并写一句话", "bad_changes")
      if (input.action !== "排除" && input.reasonKind != null)
        throw new 裁决冲突("只有「排除 / 修正」需要原因", "bad_changes")
      return 只改状态(tx, input, 当前, 目标)
    }

    if (input.action === "撤销") return 撤销(tx, input, 当前)

    // Task 4 接上「修正」；在那之前这是一句明确的「还没做」，不是静默。
    throw new 裁决冲突("「修正」在 Task 4 接上", "bad_changes")
  })
}
```

```ts
  typeof value === "string" && (裁决动作们 as readonly string[]).includes(value)

function handleTrust(request: HttpServerRequest.HttpServerRequest, deps: Deps) {
  return Effect.gen(function* () {
    const user = yield* 身份
    if (Option.isNone(user)) return HttpServerResponse.empty({ status: 401 })

    const body = yield* 读体(request)
    if (body === undefined) return fail(400, "请求体不是 JSON 对象", "bad_request")

    const projectId = body["projectId"]
    const factType = body["factType"]
    const factId = body["factId"]
    const action = body["action"]
    if (!是合法段(projectId)) return fail(400, "projectId 非法", "bad_request")
    if (!是事实类型(factType)) return fail(400, "factType 只能是 entity / relation / event", "bad_request")
    if (typeof factId !== "string" || factId === "") return fail(400, "factId 不能为空", "bad_request")
    if (!是裁决动作(action)) return fail(400, "action 只能是 确认 / 排除 / 存疑 / 修正 / 撤销", "bad_request")

    if ((yield* 成员角色(deps, user.value.id, projectId)) === undefined)
      return fail(403, "不是该项目成员", "forbidden")

    const 结果 = yield* Effect.promise(() =>
      裁决(deps.pg(), {
        projectId,
        factType,
        factId,
        action,
        reasonKind: typeof body["reasonKind"] === "string" ? (body["reasonKind"] as 纠正原因) : null,
        reasonText: typeof body["reasonText"] === "string" ? body["reasonText"] : null,
        changes: isRecord(body["changes"]) ? body["changes"] : undefined,
        by: user.value.id,
      }).catch((error: unknown) => {
        if (error instanceof 裁决冲突) return error
        throw error
      }),
    )
    if (结果 instanceof 裁决冲突) return fail(409, 结果.message, 结果.code)
    return ok({ ok: true, trustState: 结果.trustState })
  })
}
```

```ts
  relation: ["amount", "basis", "relationType"],

const 关系类型们 = ["通话", "转账", "实名登记", "实际使用", "同案", "持有", "同行"] as const
const 数据直记关系 = ["通话", "转账", "实名登记"] as const
const 精度们 = ["到日", "到分", "到秒"] as const
```

2. 把 `裁决` 里那句「Task 4 接上」换成 `return 修正(tx, input, 当前)`，并新增：

```ts
/**
 * 修正：白名单字段写回 + 已修正。原值只进留痕（R3）——`before` 是全量快照，
 * 撤销与「改过什么」都靠它。
 *
 * 校验顺序是刻意的：**先校验全部字段，再写**。写到一半才发现第三个字段不合法，
 * 事务虽然会回滚，但错误信息会指向一个已经通过校验的字段，调试时会被带偏。
 */
async function 修正(tx: Queryable, input: 裁决输入, 当前: 当前事实): Promise<裁决结果> {
  const 改动 = input.changes
  if (改动 === undefined || Object.keys(改动).length === 0)
    throw new 裁决冲突("修正必须给出要改的字段", "bad_changes")
  if (input.reasonKind === null || input.reasonKind === undefined || !input.reasonText?.trim())
    throw new 裁决冲突("修正必须选原因并写一句话", "bad_changes")

  const 允许 = 修正白名单[input.factType]
  for (const 键 of Object.keys(改动)) {
    if (!允许.includes(键))
      throw new 裁决冲突(`「${input.factType}」不能改「${键}」，可改：${允许.join(" / ")}`, "bad_changes")
  }

  const 新值: Record<string, unknown> = { ...当前.值, ...改动 }

  if (input.factType === "entity") {
    const 名称 = 新值["canonicalValue"]
    if (typeof 名称 !== "string" || 名称.trim() === "")
      throw new 裁决冲突("实体规范值不能为空", "bad_changes")
    新值["canonicalValue"] = 名称.trim()
    if (!在(新值["entityType"], 实体类型们)) throw new 裁决冲突("实体类型不合法", "bad_changes")

    const 撞 = rowsOf(
      await tx.execute(sql`
        select id from auth.case_entity
         where project_id = ${input.projectId} and type = ${String(新值["entityType"])}
           and canonical_value = ${String(新值["canonicalValue"])} and id <> ${input.factId}
      `),
    )[0]
    if (撞 !== undefined)
      throw new 裁决冲突(
        `已经有一个实体叫「${String(新值["canonicalValue"])}」，请用合并而不是改名`,
        "merge_required",
      )
  }

  if (input.factType === "relation") {
    if (!在(新值["relationType"], 关系类型们)) throw new 裁决冲突("关系类型不合法", "bad_changes")
    const 金额 = 新值["amount"]
    if (金额 !== null && 金额 !== undefined) {
      if (typeof 金额 !== "number" || !Number.isFinite(金额) || 金额 < 0)
        throw new 裁决冲突("金额必须是不小于 0 的有限数", "bad_changes")
    }
    const 依据 = 新值["basis"]
    if (依据 !== null && 依据 !== undefined && typeof 依据 !== "string")
      throw new 裁决冲突("认定依据必须是文本或空", "bad_changes")
    const 需依据 = !(数据直记关系 as readonly string[]).includes(String(新值["relationType"]))
    if (需依据 && (依据 === null || 依据 === undefined || String(依据).trim() === ""))
      throw new 裁决冲突(`「${String(新值["relationType"])}」必须带认定依据`, "basis_required")
  }

  if (input.factType === "event") {
    const 摘要 = 新值["summary"]
    if (摘要 !== null && 摘要 !== undefined && typeof 摘要 !== "string")
      throw new 裁决冲突("事件摘要必须是文本或空", "bad_changes")
    const 时间 = 新值["occurredAt"]
    if (时间 !== null && 时间 !== undefined && (!Number.isInteger(时间) || (时间 as number) < 0))
      throw new 裁决冲突("发生时间必须是 Unix 秒整数或空", "bad_changes")
    const 精度 = 新值["precision"]
    if (精度 !== null && 精度 !== undefined && !在(精度, 精度们))
      throw new 裁决冲突("精度只能是 到日 / 到分 / 到秒", "bad_changes")

  const 留痕 = await 记变更(tx, {
    projectId: input.projectId,
    factType: input.factType,
    factId: input.factId,
    action: "修正",
    before: { trustState: 当前.trustState, ...当前.值 },
    after: { trustState: "已修正", ...新值 },
    reasonKind: input.reasonKind,
    reasonText: input.reasonText,
    actor: await 操作人快照(tx, input.by),
  })
  return { trustState: "已修正", 值: 新值, 留痕 }
}
```

```ts
export * as OpenhiveCasePropagation from "./case-propagation"

import { sql } from "drizzle-orm"
import { rowsOf } from "@opencode-ai/auth/migrate"
import { nowSeconds } from "@opencode-ai/auth/time"
import type { Queryable } from "./case-store"

/**
 * §9.4 传播：改了事实之后，**依赖它的事实**标「依据已变更」。
 *
 * ## 今天只有一种依赖是真的
 *
 * - 关系 → 两端实体（`from_id` / `to_id`）
 * - 事件 → 参与实体（`participants`）
 * - 产物 → 引用的事实：**没有生产者**（产物的 `citation` 要等计划 7 保存产物时才写），
 *   所以「报告请复核」那一半挂账（R9），不在这里建一张空转的列。
 *
 * ## 为什么是时间戳
 *
 * 界面要说「什么时候变的」，而不只是「变了」；清空它 = 人已经复核过这条依赖事实。
 */

/**
 * 标：指向这个实体的关系、参与这个实体的事件，全部置为「刚刚变过」。
 *
 * `unnest(participants)` 而不是 `participants @> array[$1]`：后者在不同驱动上对参数类型的
 * 推断不一致（`could not determine polymorphic type`），展开写法与驱动无关。
 */
export async function 标依赖已变更(
  db: Queryable,
  projectId: string,
  entityId: string,
): Promise<{ relations: number; events: number }> {
  const 时间 = nowSeconds()
  const 关系 = rowsOf(
    await db.execute(sql`
      update auth.case_relation
         set basis_changed_at = ${时间}
       where project_id = ${projectId} and (from_id = ${entityId} or to_id = ${entityId})
      returning id
    `),
  )
  const 事件 = rowsOf(
    await db.execute(sql`
      update auth.case_event
         set basis_changed_at = ${时间}
       where project_id = ${projectId}
         and exists (select 1 from unnest(participants) as 参与者 where 参与者 = ${entityId})
      returning id
    `),
  )
  return { relations: 关系.length, events: 事件.length }
}

/** 清：对某条依赖事实做了任何人工动作 ⇒ 它已经被人看过了。 */
export async function 清依赖标记(
  db: Queryable,
  projectId: string,
  factType: "relation" | "event",
  factId: string,
): Promise<void> {
  const 表 = factType === "relation" ? sql`auth.case_relation` : sql`auth.case_event`
  await db.execute(sql`
    update ${表} set basis_changed_at = null
     where project_id = ${projectId} and id = ${factId}
  `)
}
```

```ts
export async function 裁决(db: Queryable, input: 裁决输入): Promise<裁决结果> {
  return inTransaction(db, async (tx) => {
    const 当前 = await 读当前事实(tx, input.projectId, input.factType, input.factId)
    if (当前 === undefined) throw new 裁决冲突("找不到这条事实", "fact_not_found")

    const 结果 =
      input.action === "确认" || input.action === "排除" || input.action === "存疑"
        ? await 只改状态(tx, input, 当前, 目标态(input.action))
        : input.action === "撤销"
          ? await 撤销(tx, input, 当前)
          : await 修正(tx, input, 当前)

    // §9.4：值真的变了才传播（确认 / 存疑只是「看过了」）。
    if (input.factType === "entity" && (input.action === "修正" || input.action === "排除"))
      await 标依赖已变更(tx, input.projectId, input.factId)
    // 依赖事实被人工动过 ⇒ 它已经被人复核，标记清掉。
    if (input.factType === "relation" || input.factType === "event")
      await 清依赖标记(tx, input.projectId, input.factType, input.factId)

    return 结果
  })
}

function 目标态(action: 裁决动作): 事实信任态 {
  if (action === "确认") return "已确认"
  if (action === "排除") return "已排除"
  return "存疑"
}
```

```ts
export * as OpenhiveCaseMerge from "./case-merge"

import { sql } from "drizzle-orm"
import { rowsOf } from "@opencode-ai/auth/migrate"
import { 记变更, 操作人快照 } from "./case-fact-change"
import { inTransaction, type Queryable } from "./case-store"

/**
 * 合并与拆分（设计 §9.3）。
 *
 * ## 合并做了什么
 *
 * 别名并集（被并入者的 `canonical_value` 也变成别名）→ 关系两端改指主体 →
 * 合并后成为自环的关系标 `已排除`（自环不是数据错误，是「自己给自己转账」这种事实
 * 已经不成立；按 §9「不删除，只打状态」）→ 删掉被并入那一行。
 *
 * ## 为什么允许删
 *
 * §9.3 原话是「被并入者**成为别名**」——它不再是独立实体，留一行「已合并」的空壳会让
 * 每个读路径都要多判一次。代价是：删之前必须把**全量快照**写进留痕，拆分靠它原样恢复。
 *
 * ## 只允许同类型（R6）
 *
 * 六类要素的计数、图标、排序全按 `type` 走；跨类合并会让「这个实体算什么」失去答案。
 * P19（同一账号被标成账户 / 号码）的正确解是**先修正类型、再合并**。
 */

export const 合并错误码们 = [
  "fact_not_found",
  "type_mismatch",
  "bad_input",
  "not_a_merge",
  "already_split",
  "restore_conflict",
] as const
export type 合并错误码 = (typeof 合并错误码们)[number]

export class 合并冲突 extends Error {
  constructor(
    message: string,
    readonly code: 合并错误码,
  ) {
    super(message)
    this.name = "合并冲突"
  }
}

interface 实体快照 {
  readonly id: string
  readonly type: string
  readonly canonicalValue: string
  readonly aliases: string[]
  readonly attrs: unknown
  readonly trustState: string
  readonly createdAt: number
}

interface 关系快照 {
  readonly id: string
  readonly fromId: string
  readonly toId: string
  readonly trustState: string
}

export interface 合并输入 {
  readonly projectId: string
  readonly survivorId: string
  readonly mergedId: string
  readonly reasonText: string
  readonly by: string
}

export interface 合并结果 {
  readonly changeId: string
  readonly survivorId: string
  readonly aliases: string[]
  readonly movedRelations: number
  readonly selfLoops: readonly string[]
}

/**
 * jsonb 读回：只解「二次编码的旧对象/数组」（字符串以 `{` / `[` 开头），其余原样返回。
 * 不做无条件的 `JSON.parse`——那会把真标量 `"123"` 变成数字、`"null"` 变成 null（Task 1 R4）。
 */
function 读杰森(值: unknown): unknown {
  if (typeof 值 !== "string" || !(值.startsWith("{") || 值.startsWith("["))) return 值 ?? null
  try {
    return JSON.parse(值)
  } catch {
    return 值
  }
}

function 文本组(值: unknown): string[] {
  if (typeof 值 !== "string" || 值 === "") return []
  try {
    const 解: unknown = JSON.parse(值)
    return Array.isArray(解) ? 解.map((x) => String(x)) : []
  } catch {
    return []
  }
}

async function 读实体快照(tx: Queryable, projectId: string, id: string): Promise<实体快照 | undefined> {
  const 行 = rowsOf(
    await tx.execute(sql`
      select id, type, canonical_value, array_to_json(aliases)::text as aliases, attrs,
             trust_state, created_at
        from auth.case_entity
       where project_id = ${projectId} and id = ${id}
       for update
    `),
  )[0]
  if (行 === undefined) return undefined
  return {
    id: String(行.id),
    type: String(行.type),
    canonicalValue: String(行.canonical_value),
    aliases: 文本组(行.aliases),
    attrs: 读杰森(行.attrs),
    trustState: String(行.trust_state),
    createdAt: Number(行.created_at),
  }
}

async function 有牵连的关系(tx: Queryable, projectId: string, entityId: string): Promise<关系快照[]> {
  const 行们 = rowsOf(
    await tx.execute(sql`
      select id, from_id, to_id, trust_state
        from auth.case_relation
       where project_id = ${projectId} and (from_id = ${entityId} or to_id = ${entityId})
       order by id
    `),
  )
  return 行们.map((行) => ({
    id: String(行.id),
    fromId: String(行.from_id),
    toId: String(行.to_id),
    trustState: String(行.trust_state),
  }))
}

/**
 * 合并两个同类型实体。`survivorId` 留下，`mergedId` 成为它的别名。
 *
 * 事务内顺序是承重的：**先读全量快照 → 再改 → 再删 → 最后写留痕**。
 * 留痕里的 `before` 少一样东西，拆分就恢复不回来。
 */
export async function 合并实体(db: Queryable, input: 合并输入): Promise<合并结果> {
  if (input.survivorId === input.mergedId) throw new 合并冲突("不能把自己并进自己", "bad_input")
  if (input.reasonText.trim() === "") throw new 合并冲突("合并必须写下依据", "bad_input")

  return inTransaction(db, async (tx) => {
    const 主体 = await 读实体快照(tx, input.projectId, input.survivorId)
    if (主体 === undefined) throw new 合并冲突("找不到留下的那个实体", "fact_not_found")
    const 并入 = await 读实体快照(tx, input.projectId, input.mergedId)
    if (并入 === undefined) throw new 合并冲突("找不到被并入的实体", "fact_not_found")
    if (主体.type !== 并入.type)
      throw new 合并冲突(
        `只能合并同类型实体（${主体.type} ≠ ${并入.type}）——先把类型改对`,
        "type_mismatch",
      )

    const 关系们 = await 有牵连的关系(tx, input.projectId, 并入.id)

    const 自环 = 关系们
      .filter(
        (条) =>
          (条.fromId === 并入.id && 条.toId === 主体.id) ||
          (条.toId === 并入.id && 条.fromId === 主体.id) ||
          (条.fromId === 并入.id && 条.toId === 并入.id),
      )
      .map((条) => 条.id)

    // 关系改指：两端都改，两次 update 各自只动一侧。
    await tx.execute(sql`
      update auth.case_relation set from_id = ${主体.id}
       where project_id = ${input.projectId} and from_id = ${并入.id}
    `)
    await tx.execute(sql`
      update auth.case_relation set to_id = ${主体.id}
       where project_id = ${input.projectId} and to_id = ${并入.id}
    `)

    // 自环最多几条，逐条写比拼 `in (...)` 更稳：不依赖 `sql.join` 的写法（本仓没有先例）。
    for (const id of 自环) {
      await tx.execute(sql`
        update auth.case_relation set trust_state = '已排除'
         where project_id = ${input.projectId} and id = ${id}
      `)
    }

    // 别名并集：主体的旧别名 ＋ 被并入者的别名 ＋ 被并入者的规范值；去重、去掉主体自己的规范值。
    const 别名集 = new Set<string>([...主体.aliases, ...并入.aliases, 并入.canonicalValue])
    别名集.delete(主体.canonicalValue)
    const 别名 = [...别名集].sort()

    await tx.execute(sql`
      update auth.case_entity set aliases = ${别名}
       where project_id = ${input.projectId} and id = ${主体.id}
    `)
    await tx.execute(sql`
      delete from auth.case_entity where project_id = ${input.projectId} and id = ${并入.id}
    `)

    const 留痕 = await 记变更(tx, {
      projectId: input.projectId,
      factType: "entity",
      factId: 主体.id,
      action: "合并",
      before: {
        survivorAliases: 主体.aliases,
        被并入: 并入,
        关系们,
      },
      after: {
        aliases: 别名,
        自环,
      },
      reasonText: input.reasonText,
      actor: await 操作人快照(tx, input.by),
    })

    return {
      changeId: 留痕,
      survivorId: 主体.id,
      aliases: 别名,
      movedRelations: 关系们.length,
      selfLoops: 自环,
    }
  })
}

export interface 拆分输入 {
  readonly projectId: string
  readonly changeId: string
  readonly by: string
}

export interface 拆分结果 {
  readonly changeId: string
  readonly restoredEntityId: string
  readonly restoredRelations: readonly string[]
  /** 合并之后被人动过、或已经不存在的关系：**不覆盖**，列出来让人知道。 */
  readonly 未恢复: readonly string[]
}

/**
 * 拆分 = 撤销某一次合并（§9.3「并错了 → 拆分，原样恢复」）。
 *
 * 恢复的边界：只回滚**合并这一步**。合并之后人又动过的关系（状态变了 / 被删了），
 * 拆分不去覆盖它——那会把人后来的判断抹掉。这些关系进 `未恢复` 清单。
 */
export async function 拆分合并(db: Queryable, input: 拆分输入): Promise<拆分结果> {
  return inTransaction(db, async (tx) => {
    const 行 = rowsOf(
      await tx.execute(sql`
        select id, project_id, fact_id, action, before, after
          from auth.case_fact_change
         where project_id = ${input.projectId} and id = ${input.changeId}
      `),
    )[0]
    if (行 === undefined) throw new 合并冲突("找不到这条留痕", "fact_not_found")
    if (String(行.action) !== "合并") throw new 合并冲突("这条留痕不是一次合并", "not_a_merge")

    const 已拆 = rowsOf(
      await tx.execute(sql`
        select id from auth.case_fact_change
         where project_id = ${input.projectId} and fact_type = 'entity' and action = '拆分'
           and after ->> '合并留痕' = ${input.changeId}
      `),
    )
    if (已拆.length > 0) throw new 合并冲突("这次合并已经拆过了", "already_split")

    const 前 = 读杰森(行.before) as
      | { survivorAliases: string[]; 被并入: 实体快照; 关系们: 关系快照[] }
      | null
    if (前 === null || typeof 前 !== "object" || 前.被并入 === undefined)
      throw new 合并冲突("留痕里没有可恢复的快照", "restore_conflict")

    const 主体Id = String(行.fact_id)
    const 被并入 = 前.被并入

    const 撞 = rowsOf(
      await tx.execute(sql`
        select id from auth.case_entity
         where project_id = ${input.projectId} and type = ${被并入.type}
           and canonical_value = ${被并入.canonicalValue}
      `),
    )[0]
    if (撞 !== undefined)
      throw new 合并冲突(
        `已经又有一个实体叫「${被并入.canonicalValue}」了，先把那个处理掉再拆`,
        "restore_conflict",
      )

    await tx.execute(sql`
      insert into auth.case_entity (id, project_id, type, canonical_value, aliases, attrs, trust_state, created_at)
      values (${被并入.id}, ${input.projectId}, ${被并入.type}, ${被并入.canonicalValue},
              ${文本数组(被并入.aliases)},
              ${被并入.attrs === null || 被并入.attrs === undefined ? sql`'{}'::jsonb` : sql`${JSON.stringify(被并入.attrs)}::text::jsonb`},
              ${被并入.trustState}, ${被并入.createdAt})
    `)

    await tx.execute(sql`
      update auth.case_entity set aliases = ${文本数组(前.survivorAliases)}
       where project_id = ${input.projectId} and id = ${主体Id}
    `)

    const 恢复: string[] = []
    const 未恢复: string[] = []
    for (const 关系 of 前.关系们) {
      const 当前 = rowsOf(
        await tx.execute(sql`
          select from_id, to_id, trust_state from auth.case_relation
           where project_id = ${input.projectId} and id = ${关系.id}
        `),
      )[0]
      if (当前 === undefined) {
        未恢复.push(关系.id)
        continue
      }
      // 只恢复「还停在合并当时留下的样子」的关系；被人动过的不覆盖。
      const 没被动过 = String(当前.trust_state) === 关系.trust_state
      if (!没被动过) {
        未恢复.push(关系.id)
        continue
      }
      await tx.execute(sql`
        update auth.case_relation set from_id = ${关系.fromId}, to_id = ${关系.toId}
         where project_id = ${input.projectId} and id = ${关系.id}
      `)
      恢复.push(关系.id)
    }

    const 留痕Id = await 记变更(tx, {
      projectId: input.projectId,
      factType: "entity",
      factId: 主体Id,
      action: "拆分",
      before: null,
      after: { 合并留痕: input.changeId, 未恢复 },
      actor: await 操作人快照(tx, input.by),
    })

    return { changeId: 留痕Id, restoredEntityId: 被并入.id, restoredRelations: 恢复, 未恢复 }
  })
}
```

```ts
function handleMerge(request: HttpServerRequest.HttpServerRequest, deps: Deps) {
  return Effect.gen(function* () {
    const user = yield* 身份
    if (Option.isNone(user)) return HttpServerResponse.empty({ status: 401 })
    const body = yield* 读体(request)
    if (body === undefined) return fail(400, "请求体不是 JSON 对象", "bad_request")

    const projectId = body["projectId"]
    const survivorId = body["survivorId"]
    const mergedId = body["mergedId"]
    const reasonText = body["reasonText"]
    if (!是合法段(projectId)) return fail(400, "projectId 非法", "bad_request")
    if (typeof survivorId !== "string" || survivorId === "") return fail(400, "survivorId 不能为空", "bad_request")
    if (typeof mergedId !== "string" || mergedId === "") return fail(400, "mergedId 不能为空", "bad_request")
    if (typeof reasonText !== "string") return fail(400, "reasonText 必须是文本", "bad_request")

    if ((yield* 成员角色(deps, user.value.id, projectId)) === undefined)
      return fail(403, "不是该项目成员", "forbidden")

    const 结果 = yield* Effect.promise(() =>
      合并实体(deps.pg(), { projectId, survivorId, mergedId, reasonText, by: user.value.id }).catch(
        (error: unknown) => {
          if (error instanceof 合并冲突) return error
          throw error
        },
      ),
    )
    if (结果 instanceof 合并冲突) return fail(409, 结果.message, 结果.code)
    return ok({ ok: true, ...结果 })
  })
}
```

```ts
export * as OpenhiveCaseProposals from "./case-proposals"

import { sql } from "drizzle-orm"
import { rowsOf } from "@opencode-ai/auth/migrate"
import { nowSeconds } from "@opencode-ai/auth/time"
import { 记变更, 操作人快照 } from "./case-fact-change"
import { inTransaction, type Queryable } from "./case-store"

/**
 * AI 提议（设计 §9.5）：AI 只提议、不改数。
 *
 * ## 采纳不等于执行
 *
 * 采纳只把状态改成「已采纳」并留痕；**执行合并仍要走 `合并实体`**，而且要人再写一次
 * 「依据什么」（R8）。让「采纳」一步把数据也改了，留痕里的依据就变成模型写的字了。
 *
 * ## 提议本身也落一条留痕
 *
 * 判据 A18 要求「否决必须带理由与人、时间」。库里 `case_ai_proposal` 已经有这三列，
 * 这里再记一条 `case_fact_change`（fact_id = 提议 id）是为了让「这条提议被谁在什么时候
 * 处置过」与事实的留痕在同一个地方可查——复盘时只查一张表。
 */

export const 提议状态们 = ["待处理", "已采纳", "已否决"] as const
export type 提议状态 = (typeof 提议状态们)[number]

export const 提议错误码们 = ["proposal_not_found", "already_decided", "reason_required", "bad_input"] as const
export type 提议错误码 = (typeof 提议错误码们)[number]

export class 提议冲突 extends Error {
  constructor(
    message: string,
    readonly code: 提议错误码,
  ) {
    super(message)
    this.name = "提议冲突"
  }
}

export interface 提议视图 {
  readonly id: string
  readonly kind: string
  readonly payload: unknown
  readonly rationale: string | null
  readonly status: 提议状态
  readonly decidedBy: string | null
  readonly decidedAt: number | null
  readonly rejectReason: string | null
  readonly createdAt: number
}

/**
 * jsonb 读回：只解「二次编码的旧对象/数组」（字符串以 `{` / `[` 开头），其余原样返回。
 * 不做无条件的 `JSON.parse`——那会把真标量 `"123"` 变成数字、`"null"` 变成 null（Task 1 R4）。
 */
function 读杰森(值: unknown): unknown {
  if (typeof 值 !== "string" || !(值.startsWith("{") || 值.startsWith("["))) return 值 ?? null
  try {
    return JSON.parse(值)
  } catch {
    return 值
  }
}

function 映射(行: Record<string, unknown>): 提议视图 {
  return {
    id: String(行.id),
    kind: String(行.kind),
    payload: 读杰森(行.payload),
    rationale: 行.rationale === null || 行.rationale === undefined ? null : String(行.rationale),
    status: String(行.status) as 提议状态,
    decidedBy: 行.decided_by === null || 行.decided_by === undefined ? null : String(行.decided_by),
    decidedAt: 行.decided_at === null || 行.decided_at === undefined ? null : Number(行.decided_at),
    rejectReason: 行.reject_reason === null || 行.reject_reason === undefined ? null : String(行.reject_reason),
    createdAt: Number(行.created_at),
  }
}

export interface 建提议输入 {
  readonly projectId: string
  readonly id?: string
  readonly kind: string
  readonly payload: unknown
  readonly rationale?: string | null
}

/** 建一条提议（计划 6 的 AI 工具会调它；本计划的用例也调它）。 */
export async function 建提议(db: Queryable, input: 建提议输入): Promise<string> {
  if (input.kind.trim() === "") throw new 提议冲突("提议必须说明是哪一类", "bad_input")
  const id = input.id ?? crypto.randomUUID()
  await db.execute(sql`
    insert into auth.case_ai_proposal (id, project_id, kind, payload, rationale, status, created_at)
    values (${id}, ${input.projectId}, ${input.kind},
            ${JSON.stringify(input.payload)}::text::jsonb,
            ${input.rationale ?? null}, '待处理', ${nowSeconds()})
  `)
  return id
}

/** 列表，时间正序；`状态` 不给 = 全部。 */
export async function 提议列表(db: Queryable, projectId: string, 状态?: 提议状态): Promise<提议视图[]> {
  const 行们 = rowsOf(
    await db.execute(sql`
      select id, kind, payload, rationale, status, decided_by, decided_at, reject_reason, created_at
        from auth.case_ai_proposal
       where project_id = ${projectId}
         and (${状态 ?? null}::text is null or status = ${状态 ?? null})
       order by created_at asc, id asc
    `),
  )
  return 行们.map(映射)
}

export interface 处置输入 {
  readonly projectId: string
  readonly id: string
  readonly action: "采纳" | "否决"
  readonly reasonText?: string | null
  readonly by: string
}

/**
 * 处置一条提议。只有「待处理」能处置；重复处置回 409（不覆盖第一次的判断）。
 * 否决必须带理由——库约束 `case_ai_proposal_reject` 也会挡，这里先回一句人话。
 */
export async function 处置提议(db: Queryable, input: 处置输入): Promise<提议视图> {
  if (input.action === "否决" && (input.reasonText === null || input.reasonText === undefined || input.reasonText.trim() === ""))
    throw new 提议冲突("否决必须写一句理由", "reason_required")

  return inTransaction(db, async (tx) => {
    const 人 = await 操作人快照(tx, input.by)
    const 当前 = rowsOf(
      await tx.execute(sql`
        select status from auth.case_ai_proposal
         where project_id = ${input.projectId} and id = ${input.id}
         for update
      `),
    )[0]
    if (当前 === undefined) throw new 提议冲突("找不到这条提议", "proposal_not_found")
    if (String(当前.status) !== "待处理") throw new 提议冲突("这条提议已经处置过了", "already_decided")

    const 状态 = input.action === "采纳" ? "已采纳" : "已否决"
    const 理由 = input.action === "否决" ? (input.reasonText ?? null) : null
    await tx.execute(sql`
      update auth.case_ai_proposal
         set status = ${状态}, decided_by = ${input.by}, decided_at = ${nowSeconds()},
             reject_reason = ${理由}
       where project_id = ${input.projectId} and id = ${input.id}
    `)
    await 记变更(tx, {
      projectId: input.projectId,
      factType: "entity",
      factId: input.id,
      action: 状态 === "已采纳" ? "采纳" : "否决",
      before: { status: "待处理" },
      after: { status: 状态 },
      reasonKind: null,
      reasonText: 理由,
      actor: 人,
    })

    const 行 = rowsOf(
      await tx.execute(sql`
        select id, kind, payload, rationale, status, decided_by, decided_at, reject_reason, created_at
          from auth.case_ai_proposal
         where project_id = ${input.projectId} and id = ${input.id}
      `),
    )[0]
    if (行 === undefined) throw new 提议冲突("找不到这条提议", "proposal_not_found")
    return 映射(行)
  })
}
```

```ts
const 是提议状态 = (value: unknown): value is 提议状态 =>
  typeof value === "string" && (提议状态们 as readonly string[]).includes(value)

function handleProposals(request: HttpServerRequest.HttpServerRequest, deps: Deps) {
  return Effect.gen(function* () {
    const user = yield* 身份
    if (Option.isNone(user)) return HttpServerResponse.empty({ status: 401 })

    const 参数 = new URL(request.url, "http://localhost").searchParams
    const projectId = 参数.get("projectId")
    const 状态 = 参数.get("status")
    if (!是合法段(projectId)) return fail(400, "projectId 非法", "bad_request")
    if (状态 !== null && !是提议状态(状态)) return fail(400, "status 只能是三种之一", "bad_request")

    if ((yield* 成员角色(deps, user.value.id, projectId)) === undefined)
      return fail(403, "不是该项目成员", "forbidden")

    const 提议们 = yield* Effect.promise(() => 提议列表(deps.pg(), projectId, 状态 ?? undefined))
    return ok({ proposals: 提议们 })
  })
}

function handleProposalDecide(request: HttpServerRequest.HttpServerRequest, deps: Deps) {
  return Effect.gen(function* () {
    const user = yield* 身份
    if (Option.isNone(user)) return HttpServerResponse.empty({ status: 401 })
    const body = yield* 读体(request)
    if (body === undefined) return fail(400, "请求体不是 JSON 对象", "bad_request")

    const projectId = body["projectId"]
    const id = body["id"]
    const action = body["action"]
    if (!是合法段(projectId)) return fail(400, "projectId 非法", "bad_request")
    if (typeof id !== "string" || id === "") return fail(400, "id 不能为空", "bad_request")
    if (action !== "采纳" && action !== "否决") return fail(400, "action 只能是 采纳 / 否决", "bad_request")

    if ((yield* 成员角色(deps, user.value.id, projectId)) === undefined)
      return fail(403, "不是该项目成员", "forbidden")

    const 结果 = yield* Effect.promise(() =>
      处置提议(deps.pg(), {
        projectId,
        id,
        action,
        reasonText: typeof body["reasonText"] === "string" ? body["reasonText"] : null,
        by: user.value.id,
      }).catch((error: unknown) => {
        if (error instanceof 提议冲突) return error
        throw error
      }),
    )
    if (结果 instanceof 提议冲突) return fail(409, 结果.message, 结果.code)
    return ok({ ok: true, proposal: 结果 })
  })
}
```
