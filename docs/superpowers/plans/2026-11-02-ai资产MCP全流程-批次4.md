# AI 资产 MCP 全流程 · 批次 4（下发与观测）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让「已发布的 MCP 资产」自动变成内核全局配置里的 `mcp` 段（下线即消失），并让使用记录能分清「这是 skill 调用还是 MCP 调用」。

**Architecture:** `Config.replaceGlobalMcp()` 负责**整体替换** `mcp` 段（受保护键原样保留、先校验后写盘）；同步器 `mcp-config-sync.ts` 只读 `published_config` 快照并投影成配置；三个触发点（启动、生命周期出口、60 秒兜底）与治理监督器共用 `mcp-config-writer.ts` 里的**进程内串行写者**；使用记录加 `kind` / `tool_name` 两列，抽取器按「配置键前缀」归因 MCP 工具；`downlink.ts` 的判据从「显式 read 授权」退役为「读者可读」。

**Tech Stack:** Bun 1.4.2、TypeScript 5.8、Effect 4 beta、Drizzle 原始 SQL、jsonc-parser、PGlite 测试夹具。

**Spec:** `docs/superpowers/specs/2026-11-02-ai资产MCP全流程-design.md`（批次 4，§3.3 / §3.4 / §4 / §6 / §7 / §9）

```ts
    /**
     * 【保留的定制 · 同步上游时不要丢】把全局配置的 `mcp` 段**整体替换**（设计 §3.3.4）。
     *
     * ## 为什么必须整体替换
     *
     * 只做合并的话，资产下线 / 归档后旧连接（含凭据）会永远留在配置里。「配置 ≡ 已发布
     * 资产集合」要成为可断言的不变式（I1），删除就只能靠整段重写——`patchJsonc` 走的是
     * jsonc-parser 的「写值」路径，**删不掉键**。
     *
     * ## 受保护键
     *
     * `BUILTIN_MCP_SERVERS`（今天只有 `openhive-governance`）的值从现存配置**原样**保留：
     * 那条由治理监督器按实际端口写入，同步器既不知道端口、也无权改（上面 `readyHandler`）。
     *
     * ## 先校验后写盘
     *
     * 组装出的内容先按**将要写下去的字节**解析、再用与加载同一条 schema 解码，校验失败抛
     * defect、一个字节都不落盘（用户在 `写失败保留上一份` 上要的就是这个）。
     */
    const replaceGlobalMcp = Effect.fn("Config.replaceGlobalMcp")(function* (
      entries: Readonly<Record<string, ConfigMCPV1.Info>>,
    ) {
      const file = globalConfigFile()
      const before = (yield* readConfigFile(file)) ?? "{}"
      const 已解析 = ConfigParse.jsonc(before, file)
      const 现状 = isRecord(已解析) ? 已解析 : {}

      const 现存MCP = isRecord(现状["mcp"]) ? 现状["mcp"] : {}
      const 受保护: Record<string, unknown> = {}
      for (const name of BUILTIN_MCP_SERVERS) {
        if (name in 现存MCP) 受保护[name] = 现存MCP[name]
      }
      const nextMcp = { ...entries, ...受保护 }

      let updated: string
      if (!file.endsWith(".jsonc")) {
        updated = JSON.stringify({ ...现状, mcp: nextMcp }, null, 2)
      } else {
        const options = { formattingOptions: { insertSpaces: true, tabSize: 2 } }
        // 删除整段再插入：`modify(..., undefined)` 是 jsonc-parser 的「删除」语义。
        const cleared = applyEdits(before, modify(before, ["mcp"], undefined, options))
        updated = applyEdits(cleared, modify(cleared, ["mcp"], nextMcp, options))
      }

      // 校验失败抛 defect（`Effect.orDie`），错误类型保持 `never`：写入口只有「成功」与「没写」。
      yield* decodeConfig(ConfigParse.jsonc(updated, file), file).pipe(Effect.orDie)
      const changed = updated !== before
      if (changed) {
        yield* fs.writeFileString(file, updated).pipe(Effect.orDie)
        yield* invalidate()
      }
      return { changed }
    })
```

```ts
export * as OpenhiveMcpConfigWriter from "./mcp-config-writer"

import { Effect } from "effect"

/**
 * 【这是要保留的定制】openhive 模块：全局配置的**进程内串行写者**（设计 §3.3.4 触发点 4）。
 *
 * ## 为什么必须只有一个写者
 *
 * 两处会写同一份全局配置：治理监督器（就绪后写 `mcp.openhive-governance`）与 MCP 配置同步器
 * （整段替换 `mcp`）。两次「读 → 改 → 写」交错时，后写的那次会把前一次的键整段抹掉——
 * 表现是「治理工具偶发消失」「新发布的 server 偶发不见」，都不报错。
 *
 * 一个 Promise 尾巴就够：本进程是唯一写者（多实例部署时各写各的本地配置，互相不可见）。
 *
 * ## ⚠️ `Effect.runPromise` 会另起一根纤维
 *
 * 不继承请求上下文（`#010-07`）。两个调用点都不需要上下文：`Config` 在层构造时就锁住了
 * 文件系统服务，写配置也不看「当前请求是谁」。以后若有人想在这里读请求身份，先改成
 * `runPromiseWith` 传上下文，别指望它自己带过来。
 */

/** asset-service 包目录；**没设 = 不同步、治理子进程也不起**（dev / 单测默认无影响）。 */
export const ENTRY_DIR_ENV = "OPENHIVE_ASSET_SERVICE_DIR"

/** 同步器与治理监督器共用的开关：设了目录才算「这一份部署开了 MCP」。 */
export function 已启用(env: Record<string, string | undefined> = process.env): boolean {
  const dir = env[ENTRY_DIR_ENV]
  return dir !== undefined && dir.trim() !== ""
}

let 尾巴: Promise<unknown> = Promise.resolve()

/**
 * 把任务排进同一队列：前一个失败不挡住后一个（两个写者各自处理自己的失败）。
 *
 * ⚠️ 队列里的任务**不要再调 `串行写`**：它会排到自己后面，永远等不到（自锁）。
 * 需要「一个写者内部再写一次」时，直接在同一个任务里连写两次。
 */
export function 串行写<A>(任务: () => Promise<A>): Promise<A> {
  const 结果 = 尾巴.then(任务, 任务)
  尾巴 = 结果.then(
    () => undefined,
    () => undefined,
  )
  return 结果
}

/** Effect 侧入口：整段 Effect 进同一个队列。缺陷 / 失败都原样从 Promise 里抛给调用方的 `catchCause`。 */
export const 串行写Effect = <A>(effect: Effect.Effect<A>): Effect.Effect<A> =>
  Effect.suspend(() => Effect.promise(() => 串行写(() => Effect.runPromise(effect))))
```

```ts
 * 【这是要保留的定制】MCP 配置同步器（设计 §3.3.4）：库里的**发布快照** → 内核全局配置。
 *
 * ## 只读 `published_config`
 *
 * 草稿 / 迭代期改的是工作列，改动**不上线**（不变式 I7）；只有 `publish_iteration` 回写的
 * 快照才变。这一条让「迭代中改坏」不会波及线上（设计 §3.1.4）。
 *
 * ## 输出形状是 `ConfigMCPV1.Info`
 *
 * `transport` → `type`、`timeoutMs` → `timeout`，其余同名。投影**不查库第二次**：

/** 已发布 / 迭代中、且有发布快照的 MCP 连接（`::text` 的理由见 `mcp-connection.ts` 文件头）。 */
export async function 读取已发布连接(db: McpAvailabilityTarget): Promise<发布行[]> {
  const result = await db.execute(sql`
    select auth.asset.id as id,
           auth.asset_mcp_connection.published_config::text as published_config
      from auth.asset
      join auth.asset_mcp_connection on auth.asset_mcp_connection.asset_id = auth.asset.id
     where auth.asset.type = 'mcp'
       and auth.asset.status in ('published', 'iterating')
       and auth.asset_mcp_connection.published_config is not null
     order by auth.asset.id
  `)
  return rowsOf(result).map((row) => ({
    id: String(row["id"]),
    published_config: typeof row["published_config"] === "string" ? row["published_config"] : null,
  }))
}

function 错误文本(error: unknown): string {
  return error instanceof Error ? error.message : String(error)

/** 快照 → 配置条目。`undefined` = 形状过不了（缺 url / command），调用方跳过。 */
function 投影连接(连接: McpConnectionInput): ConfigMCPV1.Info | undefined {
  const 公共 = {
    ...(连接.enabled === undefined ? {} : { enabled: 连接.enabled }),
    ...(连接.timeoutMs === undefined ? {} : { timeout: 连接.timeoutMs }),
  }
  if (连接.transport === "remote") {
    if (连接.url === undefined) return undefined
    return {
      type: "remote",
      url: 连接.url,
      ...(连接.headers === undefined ? {} : { headers: { ...连接.headers } }),
      ...公共,
    }
  }
  if (连接.command === undefined) return undefined
  return {
    type: "local",
    command: [...连接.command],
    ...(连接.cwd === undefined ? {} : { cwd: 连接.cwd }),
    ...(连接.environment === undefined ? {} : { environment: { ...连接.environment } }),
    ...公共,
  }
}

function 组装配置(rows: readonly 发布行[]): {
  readonly entries: Record<string, ConfigMCPV1.Info>
  readonly 跳过: readonly 跳过[]
} {
  const entries: Record<string, ConfigMCPV1.Info> = {}
  const 跳过: 跳过[] = []

  for (const row of rows) {
    if (row.id === GOVERNANCE_MCP_SERVER) {
      跳过.push({ id: row.id, reason: "占用内建治理 server 的配置键" })
      continue
    }
    if (row.published_config === null) {
      跳过.push({ id: row.id, reason: "没有发布快照" })
      continue
    }

    let 输入: McpConnectionInput
    try {
      输入 = 规范化连接(JSON.parse(row.published_config))
    } catch (error) {
      跳过.push({ id: row.id, reason: 错误文本(error) })
      continue
    }
    const 配置 = 投影连接(输入)
    if (配置 === undefined) {
      跳过.push({ id: row.id, reason: "发布快照缺 url / command" })
      continue
    }
    entries[row.id] = 配置
  }

  return { entries, 跳过 }
}

/** 同步一次。抛错交给调用方（`尝试同步` / 触发封装）收。 */
export async function 同步MCP配置(deps: 同步依赖): Promise<同步结果> {
  const rows = await 读取已发布连接(deps.db)
  const { entries, 跳过 } = 组装配置(rows)
  const { changed } = await 串行写(() => Effect.runPromise(deps.config.replaceGlobalMcp(entries)))
  return { 键: Object.keys(entries).toSorted(), 跳过, changed }
}

/** 生命周期出口用：一次同步失败只记日志，不让「发布成功」变成 500（状态已经变了）。 */
export async function 尝试同步(deps: 同步依赖): Promise<同步结果 | undefined> {
  try {
    return await 同步MCP配置(deps)
  } catch (error) {
    console.error("[openhive-mcp-config-sync] 同步失败，保留上一份配置", error)
    return undefined
  }
}

/**
 * 触发封装：**先判门、再碰库**。
 *
 * - 非 MCP 资产 ⇒ 无操作（skill / 知识库不产 MCP 配置）；
 * - `OPENHIVE_ASSET_SERVICE_DIR` 未设 ⇒ 无操作：单测 / 本地 dev 不会去写开发机的全局配置；
 * - 没有 `Config` 服务（某些测试装配）⇒ 无操作，不炸。
 */
export const 触发同步 = (input: {
  readonly type: string
  readonly db: McpAvailabilityTarget
  readonly config: Pick<Config.Interface, "replaceGlobalMcp"> | undefined
  readonly env?: Record<string, string | undefined>
}): Effect.Effect<void> =>
  Effect.gen(function* () {
    if (input.type !== "mcp") return
    if (!已启用(input.env ?? process.env)) return
    const config = input.config
    if (config === undefined) return
    const 结果 = yield* Effect.promise(() => 尝试同步({ db: input.db, config }))
    yield* Effect.logInfo("MCP 配置同步", {
      键: 结果?.键.length ?? 0,
      跳过: 结果?.跳过.length ?? 0,
      changed: 结果?.changed ?? false,
    })
  })

/**
 * 兜底层：启动同步一次（第一个实例建立之前），之后每 60 秒一次。
 *
 * 启动那次**等完**：`MCP.state` 在首个请求建实例时就把配置读走、此后按目录缓存，晚写等于
 * 该实例永久缺新 server（与治理监督器同一条理由）。代价是启动会等这一次同步：库连不上最多
 * 耗到 `connect` 的超时后记 WARN 放行，**慢几秒但不会起不来**；盘只读由 `尝试同步` 吞掉、
 * 保留上一份配置。
 *
 * 不设进程级「已挂载」标记：两处 routes 图同时存在时多一个 60 秒循环而已，写者是串行的、
 * 整段替换是幂等的；不像治理子进程那样会多起一个进程。
 */
export const layer = Layer.effectDiscard(
  Effect.gen(function* () {
    if (!已启用(process.env)) return
    const config = yield* Config.Service
    const pgService = yield* OpenhivePg.Service

    // `pg()` 取库可能当场抛（这一份部署没配 PG）——包进 Effect 再拦，起不来只记一条 WARN，
    // 不能把「配置同步不可用」升级成「内核起不来」。同理盘只读也在 `尝试同步` 里吞掉。
    const 同步一次 = Effect.suspend(() =>
      触发同步({ type: "mcp", db: pgService.pg(), config, env: process.env }),
    ).pipe(
      Effect.catchCause((cause) => Effect.logWarning("MCP 配置同步跳过", { error: Cause.pretty(cause) })),
    )

    yield* 同步一次
    yield* Effect.forkScoped(Effect.forever(Effect.sleep(兜底间隔ms).pipe(Effect.andThen(同步一次))))
  }),
)
```
