# 计划 4：AI 抽取 harness（非结构化材料 → 事实层）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让笔录这类没有列的材料也能进事实层：文本抽取 → 切片 → 逐片调模型（结构约束 ＋ 回读校验 ＋ 重试）→ 实体 / 关系 / 事件 / 引用落库；部分成功照常入库，失败的片标出来让民警看得见。

**Architecture:** 在计划 2 的导入管线里按文件类型分流：表格走原链路（一行不动），文本走新 harness。harness 自上而下五层：任务壳（复用 `case_ingest_job` 与 `runJob`）、上下文装配（按行切片 ＋ 版本化口径 prompt）、结构约束（Effect Schema，`generateObject` 强制对象）、校验与重试（形状 → 回读原文 → 最多 3 次）、留痕（`parse_detail` 记模型名 / prompt 版本 / 每片问题）。模型调用用**依赖注入**：`runJob` 只认 `deps.建抽取器`，测试用假调用器，生产在 worker 层用 `InstanceStore.provide` 起项目实例后取 `Provider` 的默认模型。

**Tech Stack:** Bun 1.4.3 · TypeScript 5.8.2 · Effect 4.0.0-beta.83（Schema） · Vercel AI SDK 6.0.168（`generateObject`） · Drizzle 1.0.0-rc.2 · node:zlib · PGlite（测试用生产驱动夹具）

**Spec:** `docs/superpowers/specs/2026-11-05-案件知识与情报体系/design.md` §5.2 / §5.3 / §5.5 / §7.4 / §9.1

## 预先裁定（实施期按此执行，不再回头讨论）

> 每条都写「为什么」与「错了的代价」。执行者若发现事实与此不符，按 ledger 规则上报，不要私自改口径。

**R1 · 文本格式先支持 `.txt` / `.md` / `.log` / `.docx`。** PDF、图片、音视频**不登记、不解析**（保持今天的行为：上传只落盘不建档，右键回 `not_parseable`）。
- 为什么：PDF/OCR/ASR 是三个独立工程（字体编码、版面、语音模型），塞进本计划会让 harness 本身测不完。设计 §5.5 也把音视频定为「先登记，后台转写后再补」。
- 代价：真栈上 PDF 笔录仍不可解析；缺口表如实写。

**R2 · 模型调用用 `generateObject` ＋ Effect Schema，不走 task 子会话 / 会话存档。**
- 为什么：设计 §7.4 想要「会话存档自动留痕」，但 `SessionPrompt` 依赖请求级实例上下文与 session 表；后台 worker 没有请求。`agent.ts:368-435` 已证明「`Provider.getModel/getLanguage` ＋ `generateObject`」是仓库里唯一不建 session 的结构化调用形态。留痕改由 `parse_detail`（模型名 / prompt 版本 / 每片尝试次数）承担。
- 代价：没有逐次调用的会话记录；换模型重跑比对（设计 §7.4 留痕层后半）留到计划 5/7。

**R3 · 抽取口径是**版本化常量 prompt**（`PROMPT版本 = "2026-11-06.1"`），项目级 SKILL.md 覆盖留到后续。**
- 为什么：本项目 skill 解析依赖实例上下文，而 harness 的 prompt 必须能被单测钉住；先让口径可版本化、可回读，再谈覆盖。
- 代价：改口径要发版；项目级差异化暂不支持（缺口表）。

**R4 · 模型只吐原文，规范值本地算。** 实体给 `取值`（原文），关系给 `原文`（整句出处）＋ `金额原文`，事件给 `时间原文` ＋ `原文`；号码 / 金额 / 时间 / 实体规范值由 `case-value.ts` / `case-time.ts` 解析。
- 为什么：设计 §7.4「回读」要的是「抽出的原子值能在原文里定位到」。让模型吐规范值等于让它猜（`28万` → 它可能写 `280000` 也可能写 `28`），回读就失去意义。
- 代价：本地解析器认不出的金额/时间写 null ＋ `存疑`，比模型硬猜更诚实。

**R5 · 重放＝同事务「按本材料删引用 → 删本材料引用过的机器事实 → 重新插入」。** 实体**只 upsert 不删**，人工确认过的关系/事件（`已确认/已修正/已排除`）不删。
- 为什么：设计 §5.3「重放不丢人工结论」。0031 无外键，删材料不级联，必须显式清理。`on conflict do nothing` 只是导入幂等，不是重放（探查结论）。
- 代价：重跑后可能留下无引用实体（孤儿），缺口表记录；实体回收留给计划 5。

**R6 · 取消：片间检查材料状态；已不是「解析中」⇒ 停止后续片、提交已完成片、作业记「完成」、**不动材料状态**（它已被用户改成「有问题」）。**
- 为什么：`cas-parse` 的「解析中取消」把材料推到「有问题」；此时再 `完成` 是非法转移，会把整个事务回滚掉，连带已完成的事实。设计要求「取消保留切片」。
- 代价：取消后作业显示「完成」，与材料的「有问题」并存——这正是两件事（作业跑完 ≠ 材料无问题）。

**R7 · id 确定性哈希。** 实体 `sha256(projectId|type|canonicalValue)`、关系/事件/引用都按内容算前 32 位。
- 为什么：同一片重跑得到同一 id，后续「换模型重跑比对」才有稳定主键；随机 UUID 会让每次重跑都像「全新事实」。
- 代价：同一片里两条完全相同的转账会合成一条（`case_relation.times` 聚合字段就是为此留的）。

**R8 · 面积闸：单份文本 ≤ 2,000,000 字、≤ 400 片、每片 1500 字，超限抛可操作错误。**
- 为什么：`#011-03` 的教训——扫描成本＝列宽 × 行数，闸要按真实成本算；对 AI 是 token 成本与小时级等待。超限要用户拆文件，不能静默截断。
- 代价：超长卷宗要人工拆分（缺口表）。

**R9 · 文本材料的 `kind` 猜测：文件名含「笔录 / 询问 / 讯问 / 陈述」→ `笔录`，否则 `其他`。** 不做内容识别。
- 为什么：设计 §5.2 的「识别」一步对非表格没有确定性判据；先给一个可解释的启发式，比一律「其他」好。
- 代价：猜错只在类型上，不影响抽取（缺口表）。

**R10 · 材料视图的 `factCount/numberCount` 对文本材料取「引用去重计数」。** 表格口径不变（明细行）。
- 为什么：文本材料没有 `case_fact_row`；不改视图的话，「已解析 · 0 条事实」是在骗人。
- 代价：一个实体被 3 片引用只计 1 条（`count(distinct fact_type || ':' || fact_id)`），这是我们要的口径；与表格口径不同源，视图注释要写明。

```ts
export * as OpenhiveCaseParseable from "./case-parseable"

/**
 * 可解析材料的扩展名白名单——**全仓唯一一份**。
 *
 * 计划 2 只有表格；计划 4 增加文本类（AI 抽取 harness）。上传自动入队（`file.ts`）、
 * 右键入队（`case-parse.ts`）、材料视图的 `parseable`（`case-materials.ts`）三处问的是
 * 同一个问题，三处各写一份 `.endsWith` 就是 `LEARNINGS #002-06` 那种「同一前提两处各判，
 * 然后只改一处」的老账。
 *
 * ⚠️ 只比**小写后缀**，不猜内容：`.xlsm` / `.docx.bak` / 尾随空格都不认。
 */
export const 表格扩展名 = [".xlsx", ".xls", ".csv"] as const
export const 文本扩展名 = [".txt", ".md", ".log", ".docx"] as const
export const 可解析扩展名 = [...表格扩展名, ...文本扩展名] as const

export type 解析方式 = "表格" | "文本"

export function 解析方式(path: string): 解析方式 | undefined {
  const 低 = path.toLowerCase()
  if (表格扩展名.some((扩展名) => 低.endsWith(扩展名))) return "表格"
  if (文本扩展名.some((扩展名) => 低.endsWith(扩展名))) return "文本"
  return undefined
}

export function 可解析表格(path: string): boolean {
  return 解析方式(path) === "表格"
}

export function 可解析材料(path: string): boolean {
  return 解析方式(path) !== undefined
}
```

```ts
function 造zip(条目: Record<string, string>, 压缩: boolean): Uint8Array {
  const 编码 = new TextEncoder()
  const 本地: Uint8Array[] = []
  const 目录: Uint8Array[] = []
  let 偏移 = 0
  for (const [名, 内容] of Object.entries(条目)) {
    const 名节 = 编码.encode(名)
    const 原 = 编码.encode(内容)
    const 数据 = 压缩 ? new Uint8Array(deflateRawSync(原)) : 原
    const 头 = new DataView(new ArrayBuffer(30))
    头.setUint32(0, 0x04034b50, true)
    头.setUint16(8, 压缩 ? 8 : 0, true)
    头.setUint32(14, 0, true) // crc 不校验
    头.setUint32(18, 数据.length, true)
    头.setUint32(22, 原.length, true)
    头.setUint16(26, 名节.length, true)
    本地.push(new Uint8Array(头.buffer), 名节, 数据)

    const 中 = new DataView(new ArrayBuffer(46))
    中.setUint32(0, 0x02014b50, true)
    中.setUint16(10, 压缩 ? 8 : 0, true)
    中.setUint32(20, 数据.length, true)
    中.setUint32(24, 原.length, true)
    中.setUint16(28, 名节.length, true)
    中.setUint32(42, 偏移, true)
    目录.push(new Uint8Array(中.buffer), 名节)

    偏移 += 30 + 名节.length + 数据.length
  }
  const 目录起 = 偏移
  const 目录长 = 目录.reduce((n, 片) => n + 片.length, 0)
  const 尾 = new DataView(new ArrayBuffer(22))
  尾.setUint32(0, 0x06054b50, true)
  尾.setUint16(8, Object.keys(条目).length, true)
  尾.setUint16(10, Object.keys(条目).length, true)
  尾.setUint32(12, 目录长, true)
  尾.setUint32(16, 目录起, true)
  const 全 = [...本地, ...目录, new Uint8Array(尾.buffer)]
  const 总长 = 全.reduce((n, 片) => n + 片.length, 0)
  const out = new Uint8Array(总长)
  let at = 0
  for (const 片 of 全) {
    out.set(片, at)
    at += 片.length
  }
  return out
}
```

```ts
export * as OpenhiveCaseText from "./case-text"

import { inflateRawSync } from "node:zlib"

/**
 * 非表格材料的「文本层」。
 *
 * ## 只做两种
 *
 * `.txt/.md/.log` 按 UTF-8 严格解码，失败退 GBK（公安系统导出的文本大量是 GBK）。
 * UTF-8 用 `fatal` 而不是替换字符：替换字符会把「这是二进制文件」静默变成一段乱码文本，
 * 后面再喂给模型，等于把钱花在垃圾上。docx 用 zip 中央目录 ＋ `node:zlib`，不引第三方库
 * （R1 / Global Constraints）。
 *
 * ## 上限
 *
 * 字数上限是**扫描成本**的闸（`LEARNINGS #011-03`）：AI 抽取按片计费、按小时计等待，
 * 超限必须让用户拆文件，不能静默截断——截断后抽出来的「结论」看起来是完整的。
 */
export const 文本字数上限 = 2_000_000

/** docx 单个部件解压后的上限：防 zip 炸弹。 */
const 解压上限 = 50 * 1024 * 1024

export interface 文本结果 {
  readonly text: string
}

export function 抽取文本(bytes: Uint8Array, path: string): 文本结果 {
  const 低 = path.toLowerCase()
  const 原文 = 低.endsWith(".docx") ? 读docx(bytes) : 解码文本(bytes)
  const 文本 = 原文.replace(/^\uFEFF/, "").replace(/\r\n?/g, "\n")
  if (文本.trim() === "") throw new Error("文件里没有可读的文字")
  if (文本.length > 文本字数上限)
    throw new Error(`文本共 ${文本.length} 字，超过单份材料上限（${文本字数上限} 字）；请拆分后再导入`)
  return { text: 文本 }
}

function 解码文本(bytes: Uint8Array): string {
  for (const 编码 of ["utf-8", "gbk"]) {
    try {
      return new TextDecoder(编码, { fatal: true }).decode(bytes)
    } catch {
      // 换下一种；两种都不行时在循环外面报错，不能在这里吞掉。
    }
  }
  throw new Error("无法识别文件编码（既不是 UTF-8 也不是 GBK）")
}

function 读docx(bytes: Uint8Array): string {
  const 正文 = 读zip(bytes).get("word/document.xml")
  if (正文 === undefined)
    throw new Error("这个 .docx 里没有正文（word/document.xml）；如果是旧版 .doc 改了后缀，请用 Word 另存为 .docx")
  return 去掉xml标签(new TextDecoder("utf-8").decode(正文))
}

/** Word 的段落/换行/制表符先变成我们认的分隔符，再剥标签。 */
function 去掉xml标签(xml: string): string {
  return xml
    .replace(/<w:tab[^>]*\/>/g, "\t")
    .replace(/<w:br[^>]*\/>/g, "\n")
    .replace(/<\/w:p>/g, "\n")
    .replace(/<[^>]+>/g, "")
    .replace(/&lt;/g, "<")
    .replace(/&gt;/g, ">")
    .replace(/&quot;/g, '"')
    .replace(/&apos;/g, "'")
    .replace(/&#(\d+);/g, (_, n: string) => String.fromCodePoint(Number(n)))
    .replace(/&#x([0-9a-fA-F]+);/g, (_, n: string) => String.fromCodePoint(Number.parseInt(n, 16)))
    .replace(/&amp;/g, "&")
}

const 中央目录签名 = 0x02014b50
const 本地头签名 = 0x04034b50

function 读zip(bytes: Uint8Array): Map<string, Uint8Array> {
  const 视 = new DataView(bytes.buffer, bytes.byteOffset, bytes.byteLength)
  let 尾 = -1
  const 最早 = Math.max(0, bytes.length - 22 - 0xffff)
  for (let i = bytes.length - 22; i >= 最早; i--) {
    if (视.getUint32(i, true) === 0x06054b50) {
      尾 = i
      break
    }
  }
  if (尾 < 0) throw new Error("这不是一个有效的 .docx（找不到 zip 目录）")

  const 条目数 = 视.getUint16(尾 + 10, true)
  let 偏移 = 视.getUint32(尾 + 16, true)
  const 结果 = new Map<string, Uint8Array>()
  for (let n = 0; n < 条目数; n++) {
    if (偏移 + 46 > bytes.length || 视.getUint32(偏移, true) !== 中央目录签名)
      throw new Error("这个 .docx 的 zip 目录损坏了")
    const 方法 = 视.getUint16(偏移 + 10, true)
    const 压缩长 = 视.getUint32(偏移 + 20, true)
    const 原始长 = 视.getUint32(偏移 + 24, true)
    const 名长 = 视.getUint16(偏移 + 28, true)
    const 附长 = 视.getUint16(偏移 + 30, true)
    const 注长 = 视.getUint16(偏移 + 32, true)
    const 本地偏移 = 视.getUint32(偏移 + 42, true)
    if (压缩长 === 0xffffffff || 原始长 === 0xffffffff || 本地偏移 === 0xffffffff)
      throw new Error("暂不支持 zip64 的 .docx")
    if (偏移 + 46 + 名长 > bytes.length) throw new Error("这个 .docx 的 zip 目录损坏了")

    const 名 = new TextDecoder("utf-8").decode(bytes.subarray(偏移 + 46, 偏移 + 46 + 名长))
    if (本地偏移 + 30 > bytes.length || 视.getUint32(本地偏移, true) !== 本地头签名)
      throw new Error("这个 .docx 的 zip 条目损坏了")
    const 本地名长 = 视.getUint16(本地偏移 + 26, true)
    const 本地附长 = 视.getUint16(本地偏移 + 28, true)
    const 数据起 = 本地偏移 + 30 + 本地名长 + 本地附长
    if (数据起 + 压缩长 > bytes.length) throw new Error("这个 .docx 的 zip 条目越界了")
    if (原始长 > 解压上限) throw new Error("这个 .docx 里的单个部件太大，已拒绝解压")

    const 数据 = bytes.subarray(数据起, 数据起 + 压缩长)
    if (方法 === 0) 结果.set(名, 数据)
    else if (方法 === 8) {
      const 解 = new Uint8Array(inflateRawSync(数据))
      if (解.length !== 原始长) throw new Error("这个 .docx 的压缩数据长度对不上")
      结果.set(名, 解)
    } else throw new Error(`这个 .docx 用了不支持的压缩方式（${方法}）`)

    偏移 += 46 + 名长 + 附长 + 注长
  }
  return 结果
}
```

```ts
export * as OpenhiveCaseSlice from "./case-slice"

/**
 * 把一份长文本切成「适合一次模型调用」的片。
 *
 * ## 三条口径
 *
 * 1. **不重叠**：重叠会让同一段事实被抽两遍，实体去重能兜住、关系会重复（R7 的确定性 id
 *    也兜不住「同一段区间出现两次不同数字」）。宁可边界处的半句话交给下一片。
 * 2. **按行边界切**：笔录的语义单位是段；按字数硬切会把一句话劈开，模型的回读定位会跟着错。
 *    只有单行本身就超限时才硬切。
 * 3. **偏移是原文坐标**：`起/止` 直接进 `case_citation.locator`（0031 注释里的
 *    `{"start":0,"end":1200}`），面板要按它回跳原文。
 *
 * 上限（R8）按**扫描成本**算，不按「看起来大不大」：超过就报错让用户拆文件，
 * 静默截断会让抽出来的结论看起来是完整的（`LEARNINGS #011-03` 同族）。
 */
export interface 文本片 {
  readonly 起: number
  readonly 止: number
  readonly 文本: string
}

export const 每片字数 = 1500
export const 最多片数 = 400

export function 切片(
  text: string,
  opts: { 每片字数?: number; 最多片数?: number } = {},
): 文本片[] {
  const 上限 = opts.每片字数 ?? 每片字数
  const 片数上限 = opts.最多片数 ?? 最多片数
  if (上限 <= 0) throw new Error("每片字数必须是正数")
  if (text.length > 上限 * 片数上限)
    throw new Error(
      `文本共 ${text.length} 字，超过单份材料上限（${片数上限} 片 × ${上限} 字）；请拆分后再导入`,
    )

  const 片: 文本片[] = []
  let 起 = 0
  let 长 = 0
  let 行首 = 0

  const 冲刷 = () => {
    if (长 === 0) return
    const 文本 = text.slice(起, 起 + 长)
    if (文本.trim() !== "") 片.push({ 起, 止: 起 + 长, 文本 })
    长 = 0
  }

  for (const 行 of text.split(/(?<=\n)/)) {
    if (行.length > 上限) {
      冲刷()
      for (let i = 0; i < 行.length; ) {
        let j = Math.min(i + 上限, 行.length)
        // 别把代理对劈成两半：末尾是高代理时退一格。
        // `j - 1 > i` 这条不能省：上限为 1 且首字符是高代理时，退了就回到 `i`，死循环。
        const 末 = 行.charCodeAt(j - 1)
        if (j < 行.length && j - 1 > i && 末 >= 0xd800 && 末 <= 0xdbff) j -= 1
        片.push({ 起: 行首 + i, 止: 行首 + j, 文本: 行.slice(i, j) })
        i = j
      }
      行首 += 行.length
      continue
    }
    if (长 > 0 && 长 + 行.length > 上限) 冲刷()
    if (长 === 0) 起 = 行首
    长 += 行.length
    行首 += 行.length
  }
  冲刷()

  if (片.length > 片数上限) throw new Error(`文本超过 ${片数上限} 片；请拆分后再导入`)
  return 片
}
```

```ts
export * as OpenhiveCaseValue from "./case-value"

/**
 * 值归一与回读原语。
 *
 * ## 为什么这些不交给模型
 *
 * 设计 §7.4 边界 2：归一化是确定性工作。模型吐 `28万`，我们算 280000；它要是直接吐
 * `280000`，我们反而没法知道这是从原文哪一句来的。所以**只接受原文**，规范值全在这里算。
 *
 * ## 认不出就 undefined
 *
 * 金额/号码解析不出时返回 `undefined`，调用方写 null ＋ 标记存疑——错数字比没数字害人
 * （设计 §7.4 末段）。
 */
export function 号码归一(raw: string): string | undefined {
  const 数字 = raw.replace(/\D/g, "")
  return 数字 === "" ? undefined : 数字
}

const 中文数字: Record<string, number> = {
  零: 0, 〇: 0, 一: 1, 壹: 1, 二: 2, 贰: 2, 两: 2, 三: 3, 叁: 3,
  四: 4, 肆: 4, 五: 5, 伍: 5, 六: 6, 陆: 6, 七: 7, 柒: 7, 八: 8, 捌: 8, 九: 9, 玖: 9,
}
const 中文单位: Record<string, number> = { 十: 10, 拾: 10, 百: 100, 佰: 100, 千: 1000, 仟: 1000 }

function 中文整数(s: string): number | undefined {
  let 总 = 0
  let 段 = 0
  let 数 = 0
  for (const ch of s) {
    if (中文数字[ch] !== undefined) {
      数 = 中文数字[ch]!
      continue
    }
    if (中文单位[ch] !== undefined) {
      if (数 === 0) 数 = 1
      段 += 数 * 中文单位[ch]!
      数 = 0
      continue
    }
    if (ch === "万") {
      段 += 数
      总 += (段 === 0 ? 1 : 段) * 10_000
      段 = 0
      数 = 0
      continue
    }
    if (ch === "亿") {
      段 += 数
      总 = (总 + 段) * 100_000_000
      段 = 0
      数 = 0
      continue
    }
    return undefined
  }
  return 总 + 段 + 数
}

export function 金额元(raw: string): number | undefined {
  let s = raw.trim().replace(/[,，\s]/g, "")
  if (s === "") return undefined
  // 币种符号与单位要**先剥**再判括号：`（三千）元` 的结尾是「元」，
  // 先判括号会整个失配，负数就静默变成 undefined。
  s = s.replace(/^[¥￥]/, "").replace(/(元|圆|人民币|RMB|CNY)$/i, "")
  if (s === "") return undefined
  let 负 = false
  const 括号 = /^[（(](.+)[)）]$/.exec(s)
  if (括号) {
    负 = true
    s = 括号[1]!
  }
  if (s.startsWith("-")) {
    负 = !负
    s = s.slice(1)
  }

  let 值: number | undefined
  const 数字 = /^(\d+(?:\.\d+)?)(万|亿)?$/.exec(s)
  if (数字) {
    const n = Number(数字[1])
    if (!Number.isFinite(n)) return undefined
    值 = n * (数字[2] === "万" ? 10_000 : 数字[2] === "亿" ? 100_000_000 : 1)
  } else {
    const 中文 = /^([零〇一二两三四五六七八九十百千万亿壹贰叁肆伍陆柒捌玖拾佰仟]+)(万|亿)?$/.exec(s)
    if (!中文) return undefined
    const n = 中文整数(中文[1]!)
    if (n === undefined) return undefined
    值 = n * (中文[2] === "万" ? 10_000 : 中文[2] === "亿" ? 100_000_000 : 1)
  }
  const 结果 = Math.round(值 * 100) / 100
  return 负 ? -结果 : 结果
}

/** 忽略空白与换行差异的包含判断：模型抄原文时经常把换行抄成空格。 */
export function 文本包含(haystack: string, needle: string): boolean {
  const 针 = needle.replace(/\s+/g, "")
  if (针 === "") return false
  return haystack.replace(/\s+/g, "").includes(针)
}

/**
 * 人名形近命中（设计 §7.4「允许张叁 / 张三」）。
 *
 * 只允许**等长、差一个字**，且那个变体必须真的出现在原文里；长度 1 不做形近——
 * 「张」和「李」差一个字，形近规则会把所有单字名认成同一个。
 */
export function 形近命中(haystack: string, name: string): boolean {
  if (name.length < 2) return false
  for (let i = 0; i + name.length <= haystack.length; i++) {
    let 差 = 0
    for (let j = 0; j < name.length; j++) {
      if (haystack[i + j] !== name[j]) 差 += 1
      if (差 > 1) break
    }
    if (差 <= 1) return true
  }
  return false
}

/**
 * `type` 收 `string` 而不是 `实体类型`：类型枚举的源头在 `case-extract.ts`（它建 Schema），
 * 这里再 import 回去就成环了。归一规则只关心「是不是号码」，字符串比较足够。
 */
export function 实体规范值(type: string, value: string): string | undefined {
  if (type === "号码") return 号码归一(value)
  const 规范 = value.normalize("NFKC").trim().replace(/\s+/g, " ")
  return 规范 === "" ? undefined : 规范
}
```

```ts
export * as OpenhiveCaseFactStore from "./case-fact-store"

import { sql } from "drizzle-orm"
import { rowsOf } from "@opencode-ai/auth/migrate"
import { nowSeconds } from "@opencode-ai/auth/time"
import type { Queryable } from "./case-store"

/**
 * 五张事实表里「AI 抽取会写」的那几笔。
 *
 * ## 为什么单独一个文件
 *
 * `case-store.ts` 已经承担材料/状态/明细行三件事；把实体、关系、事件、引用的写入再塞进去，
 * 会变成又一个「什么都往里放」的文件。这里只放写路径，而且只放本计划用得到的那一半——
 * 读路径（实体清单、关系图）等计划 5/7 用到了再开。
 *
 * ## 无外键 ⇒ 清理必须显式带 project_id
 *
 * 0031 明确不设外键（事实层要能整片重建）。删材料不会级联，所以每条清理都写
 * `project_id = ? and ...`，漏一侧就会跨项目误删（`LEARNINGS` 多租户老账）。
 */

export interface 实体写入 {
  projectId: string
  id: string
  type: string
  canonicalValue: string
  aliases: string[]
}

/**
 * JS 字符串数组 → PG `text[]`。
 *
 * 本仓此前没有写过任何 `text[]` 列（0031 的 `aliases` / `participants` 是第一处），
 * 驱动的数组绑定行为没有先例可依：直接绑 JS 数组，不同驱动可能落成 JSON、也可能报错。
 * 走 JSON 再展开是显式的，与驱动无关，也不会因为升级驱动而悄悄变形状。
 */
function 文本数组(值: readonly string[]) {
  return sql`array(select jsonb_array_elements_text(${JSON.stringify(值)}::jsonb))`
}

/**
 * 按 `(project_id, type, canonical_value)` upsert，返回**库里那一行**的 id。
 *
 * 用 `do update` 而不是 `do nothing`：`do nothing` 不返回行，调用方拿不到既有 id，
 * 关系就会挂到一个不存在的实体上。别名取并集并去重。
 */
export async function upsertEntity(db: Queryable, input: 实体写入): Promise<string> {
  const 行 = rowsOf(
    await db.execute(sql`
      insert into auth.case_entity (id, project_id, type, canonical_value, aliases, created_at)
      values (${input.id}, ${input.projectId}, ${input.type}, ${input.canonicalValue},
              ${文本数组(input.aliases)}, ${nowSeconds()})
      on conflict (project_id, type, canonical_value) do update
         set aliases = (
           select coalesce(array_agg(distinct x), '{}'::text[])
             from unnest(auth.case_entity.aliases || excluded.aliases) as x
         )
      returning id
    `),
  )
  // `rowsOf` 返回 `Record<string, unknown>[]`；`!` 在这里是多余断言（本包没开
  // `noUncheckedIndexedAccess`），写成显式判空既过 lint 又能报出「没返回行」这种真异常。
  const id = 行[0]?.id
  if (id === undefined) throw new Error(`实体写入没有返回 id：${input.canonicalValue}`)
  return String(id)
}

export interface 关系写入 {
  projectId: string
  id: string
  fromId: string
  toId: string
  type: string
  amount?: number | null
  basis?: string | null
  sourceKind: "data" | "human"
  trustState: "自动抽取" | "存疑"
  firstAt?: number | null
  lastAt?: number | null
  precision?: string | null
  times?: number | null
}

/**
 * `numeric(18,2)` 列一律用**字符串**绑（`#002-01`、`case-store.ts` 里 `FactRowInput.amount`
 * 的注释同款理由：number 绑定出来的形状随驱动而变，还可能带浮点尾差）。调用方给 number，
 * 这里统一补两位小数。
 */
function 金额参数(值: number | null | undefined): string | null {
  return 值 === null || 值 === undefined ? null : 值.toFixed(2)
}

export async function insertRelation(db: Queryable, input: 关系写入): Promise<void> {
  await db.execute(sql`
    insert into auth.case_relation
      (id, project_id, from_id, to_id, type, first_at, last_at, precision, times, amount,
       basis, source_kind, trust_state, created_at)
    values (${input.id}, ${input.projectId}, ${input.fromId}, ${input.toId}, ${input.type},
            ${input.firstAt ?? null}, ${input.lastAt ?? null}, ${input.precision ?? null},
            ${input.times ?? null}, ${金额参数(input.amount)}, ${input.basis ?? null},
            ${input.sourceKind}, ${input.trustState}, ${nowSeconds()})
    on conflict (project_id, id) do nothing
  `)
}

export interface 事件写入 {
  projectId: string
  id: string
  type: string
  occurredAt: number | null
  occurredRaw: string | null
  precision: string | null
  participants: string[]
  summary: string | null
  trustState: "自动抽取" | "存疑"
}

export async function insertEvent(db: Queryable, input: 事件写入): Promise<void> {
  await db.execute(sql`
    insert into auth.case_event
      (id, project_id, type, occurred_at, occurred_raw, precision, participants, summary,
       trust_state, created_at)
    values (${input.id}, ${input.projectId}, ${input.type}, ${input.occurredAt},
            ${input.occurredRaw}, ${input.precision}, ${文本数组(input.participants)},
            ${input.summary}, ${input.trustState}, ${nowSeconds()})
    on conflict (project_id, id) do nothing
  `)
}

/**
 * 删除「被本材料引用、且是机器抽出来」的关系与事件。
 *
 * ⚠️ 必须先于 `deleteCitationsOfMaterial`：删完引用就找不到该删哪些事实了。
 * 人工确认/修正/排除过的一律不删（设计 §5.3「重放不丢人工结论」）。
 */
export async function 删除本材料的事实(db: Queryable, projectId: string, materialId: string): Promise<void> {
  await db.execute(sql`
    delete from auth.case_relation r
     using auth.case_citation c
     where c.project_id = ${projectId} and c.material_id = ${materialId}
       and c.fact_type = 'relation'
       and r.project_id = c.project_id and r.id = c.fact_id
       and r.trust_state in ('自动抽取', '存疑')
  `)
  await db.execute(sql`
    delete from auth.case_event e
     using auth.case_citation c
     where c.project_id = ${projectId} and c.material_id = ${materialId}
       and c.fact_type = 'event'
       and e.project_id = c.project_id and e.id = c.fact_id
       and e.trust_state in ('自动抽取', '存疑')
  `)
}

export async function deleteCitationsOfMaterial(
  db: Queryable,
  projectId: string,
  materialId: string,
): Promise<void> {
  await db.execute(sql`
    delete from auth.case_citation
     where project_id = ${projectId} and material_id = ${materialId}
  `)
}

export async function setMaterialText(
  db: Queryable,
  projectId: string,
  materialId: string,
  text: string,
): Promise<void> {
  const 行 = rowsOf(
    await db.execute(sql`
      update auth.case_material set text_content = ${text}
       where project_id = ${projectId} and id = ${materialId}
      returning id
    `),
  )
  if (行.length === 0) throw new Error(`材料不存在：${projectId}/${materialId}`)
}
```

```ts
export * as OpenhiveCaseExtract from "./case-extract"

import { Schema } from "effect"
import { parseTime, type Precision } from "./case-time"
import { 号码归一, 实体规范值, 形近命中, 文本包含, 金额元 } from "./case-value"

/**
 * 非结构化材料的抽取契约。
 *
 * ## 只收原文（R4）
 *
 * 模型输出里的 `取值` / `金额原文` / `时间原文` 都是**原文照抄**；规范值（号码、金额、时间、
 * 实体规范值）由这里算。模型一旦被允许「顺手归一」，回读就退化成「模型自己跟自己一致」，
 * 设计 §7.4 那句「28 万可能是编的」就挡不住了。
 *
 * ## 回读的顺序
 *
 * 出处整句 → 这一片原文（**整条事实的生死**）；原子值 → 出处整句（**该值的生死**）。
 * 出处都对不上，说明这条事实根本不是从这段文本里来的，直接丢；原子值对不上，按设计
 * 「置空 ＋ 存疑」，事实本身留下。
 *
 * ## 金额只有一条通路（别和表格那条混用）
 *
 * AI 抽取的金额**只经 `金额元`**（认万/亿/中文/会计写法，畸形一律 undefined）；
 * 表格那一路是 `case-rows.ts` 的 `parseAmount`（严格数字串，单位由列名单位闸整列拒收）。
 * 两者**不许交叉复用**：`parseAmount` 的输出是 `numeric` 字符串、认不出就拒整行，
 * 而这里要的是「认不出就置空 ＋ 存疑」。落库统一由 `case-fact-store.ts` 的金额参数
 * 转成两位小数字符串（`#002-01`）。
 */
export const 实体类型们 = ["人", "号码", "账户", "虚拟身份", "车辆", "物品", "地点", "组织"] as const
export type 实体类型 = (typeof 实体类型们)[number]

export const 关系类型们 = ["通话", "转账", "实名登记", "实际使用", "同案", "持有", "同行"] as const
export type 关系类型 = (typeof 关系类型们)[number]

/** 这几种关系是数据直接记录的，库里不要求 `basis`；其余必须给认定依据（0031 的 CHECK）。 */
const 数据直记 = new Set<关系类型>(["通话", "转账", "实名登记"])

export const 抽取结构 = Schema.Struct({
  实体: Schema.Array(
    Schema.Struct({
      类型: Schema.Literals(实体类型们),
      取值: Schema.String,
      别名: Schema.optional(Schema.Array(Schema.String)),
    }),
  ),
  关系: Schema.Array(
    Schema.Struct({
      类型: Schema.Literals(关系类型们),
      从: Schema.String,
      到: Schema.String,
      金额原文: Schema.optional(Schema.String),
      依据: Schema.optional(Schema.String),
      原文: Schema.String,
    }),
  ),
  事件: Schema.Array(
    Schema.Struct({
      类型: Schema.String,
      时间原文: Schema.optional(Schema.String),
      参与人: Schema.Array(Schema.String),
      简述: Schema.optional(Schema.String),
      原文: Schema.String,
    }),
  ),
})
export type 抽取结果 = Schema.Schema.Type<typeof 抽取结构>

export const PROMPT版本 = "2026-11-06.1"

/**
 * 抽取口径。**版本号进 parse_detail**，改口径必须同时改版本号——否则「同一份材料两次
 * 结果不一样」会说不清是哪一环变的（设计 §7.4 留痕层）。
 */
export function 系统提示(): string {
  return `你是公安案件材料的抽取器（口径版本 ${PROMPT版本}）。

只做一件事：从给定的一段材料原文里，抽出**明确写出来的**人、号码、账户、车辆、物品、地点、组织，以及它们之间的关系和发生的事。

规则（逐条遵守）：
1. 只抽这一段原文里写到的内容。没写的、要靠推理补的、别的段落里的，一律不抽。
2. 所有取值照抄原文：人名写原文里的人名，号码写原文里的号码，金额写原文里的金额（例如「28万」「1,234.50元」），时间写原文里的时间（例如「2026年3月5日下午」）。
   **不要换算**：不要自己把「28万」算成 280000，不要自己把「下午3点」算成 15:00，不要补年份。
3. 每一条关系、每一个事件都必须给「原文」：从这一段里**逐字复制**的、能说明这条事实的完整句子或分句。出处不能改写、不能拼接、不能省略。
4. 抽取不出人名、号码、金额、时间时，**不知道就留空**（省略该字段或给空字符串），绝不猜、绝不编。
5. 关系类型只能是：通话、转账、实名登记、实际使用、同案、持有、同行。除通话、转账、实名登记外，必须在「依据」里写认定依据（供述指认 / 扣押实物 / 技侦 / 登录或使用日志 / 资金闭环 / 推断），否则不要输出这条关系。
6. 事件类型写一句短语（例如「见面」「转账」「通话」「抓获」），不要写成长句。
7. 这一段里没有可抽的事实，就返回空的三个数组。`
}

export function 用户提示(input: {
  fileName: string
  片序号: number
  片数: number
  起: number
  止: number
  文本: string
}): string {
  return `材料：${input.fileName}
片段：第 ${input.片序号}/${input.片数} 片（全文第 ${input.起}–${input.止} 字）

${input.文本}
</原文>`
}

/** 数字串按号码判，其余按人判——只用于「关系/事件里出现、但实体清单没列」的角色。 */
function 推断实体类型(value: string): 实体类型 {
  return /^[\d\s\-()+]+$/.test(value) && 号码归一(value) !== undefined ? "号码" : "人"
}

/**
 * 「这段文字里有没有这串数字」——**只做包含判断，不产出规范值**。
 *
 * 别拿 `号码归一(出处)` 来比：`号码归一` 只对标识符成立（见 `case-value.ts` 的注释），
 * 喂整段原文会得到一串把日期、金额、号码拼在一起的数字，跨边界的幻觉值也能命中（`#011-01` 同族）。
 */
function 数字串(s: string): string {
  return s.replace(/\D/g, "")
}

function 命中(出处: string, 值: string): boolean {
  if (文本包含(出处, 值)) return true
  const 值号码 = 号码归一(值)
  if (值号码 !== undefined && 值号码.length >= 5) {
    if (数字串(出处).includes(数字串(值号码))) return true
  }
  return 形近命中(出处, 值)
}

export function 回读(结果: 抽取结果, 片文本: string): 回读输出 {
  const 问题: string[] = []
  const 实体 = new Map<string, 实体输入>()

  // `别名` 收 `readonly string[]`：schema 解出来的 `项.别名` 是只读数组，写成 `string[]`
  // 会让 `项.别名 ?? []` 在 typecheck 处报 TS4104（实现时实测）。
  const 加实体 = (类型: 实体类型, 原文值: string, 别名: readonly string[]): 实体输入 | undefined => {
    const 规范 = 实体规范值(类型, 原文值)
    if (规范 === undefined) {
      问题.push(`「${原文值}」不是一个可用的${类型}`)
      return undefined
    }
    const 键 = `${类型}\u0000${规范}`
    const 既有 = 实体.get(键)
    if (既有) {
      for (const 名 of 别名) if (名 !== 规范 && !既有.aliases.includes(名)) 既有.aliases.push(名)
      return 既有
    }
    const 项: 实体输入 = { type: 类型, canonicalValue: 规范, aliases: 别名.filter((名) => 名 !== 规范) }
    实体.set(键, 项)
    return 项
  }

  for (const 项 of 结果.实体) {
    if (!命中(片文本, 项.取值)) {
      问题.push(`实体「${项.取值}」在这段原文里找不到`)
      continue
    }
    加实体(项.类型, 项.取值, 项.别名 ?? [])
  }

  const 关系: 关系输入[] = []
  for (const 项 of 结果.关系) {
    if (!文本包含(片文本, 项.原文)) {
      问题.push(`关系「${项.从} → ${项.到}」的出处在这段原文里找不到`)
      continue
    }
    if (!数据直记.has(项.类型) && (项.依据 === undefined || 项.依据.trim() === "")) {
      问题.push(`关系「${项.从} → ${项.到}」是「${项.类型}」，但没有给认定依据`)
      continue
    }
    const 缺角色 = [项.从, 项.到].filter((值) => !命中(项.原文, 值))
    if (缺角色.length > 0) {
      问题.push(`关系「${项.从} → ${项.到}」的${缺角色.join("、")}在出处里找不到`)
      continue
    }
    加实体(推断实体类型(项.从), 项.从, [])
    加实体(推断实体类型(项.到), 项.到, [])

    let amount: number | null = null
    let 存疑 = false
    if (项.金额原文 !== undefined && 项.金额原文.trim() !== "") {
      if (!文本包含(项.原文, 项.金额原文)) {
        问题.push(`关系「${项.从} → ${项.到}」的金额「${项.金额原文}」在出处里找不到，已置空`)
        存疑 = true
      } else {
        const 值 = 金额元(项.金额原文)
        if (值 === undefined) {
          问题.push(`关系「${项.从} → ${项.到}」的金额「${项.金额原文}」认不出，已置空`)
          存疑 = true
        } else amount = 值
      }
    }

    关系.push({
      type: 项.类型,
      from: 实体规范值(推断实体类型(项.从), 项.从)!,
      to: 实体规范值(推断实体类型(项.到), 项.到)!,
      amount,
      basis: 项.依据 ?? null,
      原文: 项.原文,
      存疑,
    })
  }

  const 事件: 事件输入[] = []
  for (const 项 of 结果.事件) {
    if (!文本包含(片文本, 项.原文)) {
      问题.push(`事件「${项.类型}」的出处在这段原文里找不到`)
      continue
    }
    let 存疑 = false
    let occurredRaw: string | null = null
    let occurredAt: number | null = null
    let precision: Precision | null = null
    if (项.时间原文 !== undefined && 项.时间原文.trim() !== "") {
      occurredRaw = 项.时间原文
      if (!文本包含(项.原文, 项.时间原文)) {
        问题.push(`事件「${项.类型}」的时间「${项.时间原文}」在出处里找不到，已置空`)
        存疑 = true
      } else {
        const 时间 = parseTime(项.时间原文)
        if (时间 === undefined) {
          问题.push(`事件「${项.类型}」的时间「${项.时间原文}」认不出，已置空`)
          存疑 = true
        } else {
          occurredAt = 时间.seconds
          precision = 时间.precision
        }
      }
    }

    const 参与人: string[] = []
    for (const 人 of 项.参与人) {
      if (!命中(项.原文, 人)) {
        问题.push(`事件「${项.类型}」的参与人「${人}」在出处里找不到，已移除`)
        存疑 = true
        continue
      }
      const 规范 = 实体规范值(推断实体类型(人), 人)
      if (规范 === undefined) continue
      加实体(推断实体类型(人), 人, [])
      参与人.push(规范)
    }

    事件.push({
      type: 项.类型.slice(0, 40),
      occurredRaw,
      occurredAt,
      precision,
      participants: 参与人,
      summary: 项.简述 ?? null,
      存疑,
    })
  }

  return { 实体: [...实体.values()], 关系, 事件, 问题 }
}
```

> 时间的处理口径：`occurredRaw` **一律保留原文**（设计 §4.2「原始值永不改写」）；
> `occurredAt` 只在解析成功时非空。参与人少一个只置 `存疑`，**不回头清掉已经解析出来的时间**
> ——过度归零会让本来可用的时间也丢掉。

```ts
export * as OpenhiveCaseExtractRun from "./case-extract-run"

import { Schema } from "effect"
import { PROMPT版本, 抽取结构, 回读, 用户提示, 系统提示, type 实体输入, type 事件输入, type 关系输入 } from "./case-extract"
import { 切片, type 文本片 } from "./case-slice"

/**
 * 五层 harness 的执行层：片 → 调模型 → 校验 → 重试 → 汇总。
 *
 * ## 一片失败不牵连别的片
 *
 * 设计 §7.4「部分成功照常入库，不整份回滚」：这里从不抛错（除了切片本身的面积闸），
 * 每片自己带 `问题`。调用方按 `问题` 决定材料标不标「有问题」。
 *
 * ## 重试只重试这一片
 *
 * 失败的反馈（哪几个原子值回读不过）拼进下一次的用户提示——模型需要知道错在哪，
 * 只重启一次同样的 prompt 通常还会错在同一个地方。
 */
export interface 模型调用 {
  (输入: { 系统: string; 用户: string }): Promise<unknown>
}

export interface 抽取器 {
  readonly 模型标识: string
  readonly 调用: 模型调用
}

export interface 片结果 {
  readonly 片: 文本片
  readonly 实体: 实体输入[]
  readonly 关系: 关系输入[]
  readonly 事件: 事件输入[]
  readonly 问题: string[]
  readonly 尝试: number
}

export interface 抽取输出 {
  readonly 片们: 片结果[]
  readonly 模型标识: string
  readonly prompt版本: string
}

export interface 抽取选项 {
  /** 每片最多几次。默认 3（设计「上限 N 次」，N=3 是成本与成功率的折中）。 */
  最多尝试?: number
  /** 每片开始前问一次；返回 false 就不再跑后续片（取消，R6）。 */
  仍应继续?: () => Promise<boolean>
}

const 默认最多尝试 = 3

export async function 抽取材料(
  input: { 文本: string; fileName: string; 抽取器: 抽取器 },
  opts: 抽取选项 = {},
): Promise<抽取输出> {
  const 全部 = 切片(input.文本)
  const 最多 = Math.max(1, opts.最多尝试 ?? 默认最多尝试)
  const 片们: 片结果[] = []

  for (const [下标, 片] of 全部.entries()) {
    if (opts.仍应继续 && !(await opts.仍应继续())) break
    片们.push(
      await 抽一片({
        fileName: input.fileName,
        片序号: 下标 + 1,
        片数: 全部.length,
        片,
        调用: input.抽取器.调用,
        最多,
      }),
    )
  }

  return { 片们, 模型标识: input.抽取器.模型标识, prompt版本: PROMPT版本 }
}

async function 抽一片(input: {
  fileName: string
  片序号: number
  片数: number
  片: 文本片
  调用: 模型调用
  最多: number
}): Promise<片结果> {
  let 问题: string[] = []

  for (let 尝试 = 1; 尝试 <= input.最多; 尝试++) {
    const 用户 =
      用户提示({
        fileName: input.fileName,
        片序号: input.片序号,
        片数: input.片数,
        起: input.片.起,
        止: input.片.止,
        文本: input.片.文本,
      }) +
      (问题.length === 0
        ? ""
        : `\n\n上一次的输出有这些问题，请改正后重新输出（仍然只抽这一段原文里写到的）：\n- ${问题.join("\n- ")}`)

    let 原: unknown
    try {
      原 = await input.调用({ 系统: 系统提示(), 用户 })
    } catch (error) {
      const 说明 = error instanceof Error ? error.message : String(error)
      问题 = [`模型调用失败：${说明.slice(0, 200)}`]
      if (尝试 === input.最多) return { 片: input.片, 实体: [], 关系: [], 事件: [], 问题, 尝试 }
      continue
    }

    try {
      const 解析 = Schema.decodeUnknownSync(抽取结构)(原)
      const 回 = 回读(解析, input.片.文本)
      if (回.问题.length === 0)
        return { 片: input.片, 实体: 回.实体, 关系: 回.关系, 事件: 回.事件, 问题: [], 尝试 }

  return { 片: input.片, 实体: [], 关系: [], 事件: [], 问题, 尝试: input.最多 }
```

```ts
  try {
    const material = await getMaterial(db, job.projectId, job.materialId)
    if (!material) throw new Error(`作业指向的材料不存在：${job.materialId}`)
```

```ts
/**
 * 文本材料的 AI 抽取（设计 §7.4）。
 *
 * ## 顺序
 *
 * 读盘 → 文本层 → 切片 → 逐片抽取（会重试、会部分成功）→ **一个事务**里
 * 「删本材料旧引用 → 删旧机器事实 → 写新事实/引用 → 写 text_content → 改状态/收尾」。
 *
 * ## 取消（R6）
 *
 * 片间检查材料状态；不是「解析中」就停。事务里**不再推进材料状态**——用户已经把它改成
 * 「有问题」了，再写「完成」是非法转移，会把整批已完成的事实回滚掉。
 *
 * ## 作业与材料是两件事
 *
 * 部分片失败 ⇒ 材料「有问题」，作业仍「完成」（它确实跑完了）。全部片都干净却一条事实都没抽到
 * ⇒ 作业「失败」（这通常意味着模型没按规定输出）；全部片都失败 ⇒ 材料「有问题」带切片明细、
 * 作业仍「完成」——失败的原因已经在材料上了，再让作业「失败」等于同一件事说两遍。
 */
async function 跑文本(
  db: Queryable,
  deps: RunDeps,
  job: ClaimedJob,
  material: MaterialRow,
): Promise<"完成" | "失败"> {
  if (!deps.建抽取器) throw new Error("这份部署没有配置抽取模型（缺少抽取器）")

  const bytes = await deps.readFile(job.sourcePath)
  const { text } = 抽取文本(bytes, material.path)
  const 抽取器 = await deps.建抽取器(job)

  const 输出 = await 抽取材料(
    { 文本: text, fileName: material.fileName, 抽取器 },
    {
      仍应继续: async () => (await getMaterial(db, job.projectId, job.materialId))?.parseStatus === "解析中",
    },
  )

  const 已取消 =
    (await getMaterial(db, job.projectId, job.materialId))?.parseStatus !== "解析中"

  const 问题片 = 输出.片们.filter((片) => 片.问题.length > 0)
  // 抽取条数按片累加、未去重——它只进 `parse_detail` 给人看；视图里的计数另算（R10）。
  const 抽取条数 = 输出.片们.reduce((n, 片) => n + 片.实体.length + 片.关系.length + 片.事件.length, 0)

  // 两种「零结果」要分开说，且都必须在事务**之前**抛（事务一提交，抛错只会让材料落「有问题」
  // 却留下一批已入库的旧事实）。
  // ① 切片为空：文件读成了空；② 全部片都干净却零条事实：模型说了「什么都没有」。
  // 「全部片都失败」不在这里抛——它有 `问题片`，走下面的「有问题 ＋ 切片明细」。
  if (!已取消 && 输出.片们.length === 0) throw new Error("文本切片为空")
  if (!已取消 && 抽取条数 === 0 && 问题片.length === 0)
    throw new Error("这段文本里一条事实都没抽出来（可能不是案情材料，或模型没有按规定输出）")

  await inTransaction(db, async (tx) => {
    await 删除本材料的事实(tx, job.projectId, job.materialId)
    await deleteCitationsOfMaterial(tx, job.projectId, job.materialId)

    for (const 片 of 输出.片们) {
      const 实体id = new Map<string, string>()
      for (const 实体 of 片.实体) {
        const id = 事实id(job.projectId, 实体.type, 实体.canonicalValue)
        const 实际 = await upsertEntity(tx, {
          projectId: job.projectId,
          id,
          type: 实体.type,
          canonicalValue: 实体.canonicalValue,
          aliases: 实体.aliases,
        })
        实体id.set(`${实体.type}\u0000${实体.canonicalValue}`, 实际)
        await addCitation(tx, {
          id: 引用id(job.projectId, "entity", 实际, job.materialId, 片.片.起),
          projectId: job.projectId,
          factType: "entity",
          factId: 实际,
          materialId: job.materialId,
          locator: { start: 片.片.起, end: 片.片.止 },
          extractMethod: "机器",
        })
      }

      for (const 关系 of 片.关系) {
        const from = 实体id.get(`人\u0000${关系.from}`) ?? 实体id.get(`号码\u0000${关系.from}`)
        const to = 实体id.get(`人\u0000${关系.to}`) ?? 实体id.get(`号码\u0000${关系.to}`)
        // 回读阶段保证两端都在实体表里；这里拿不到 id 说明推断类型与规范值对不上，跳过。
        if (from === undefined || to === undefined) continue
        const id = 事实id(
          job.projectId, "relation", job.materialId, 片.片.起, 关系.type, from, to,
          String(关系.amount ?? ""), 关系.原文,
        )
        await insertRelation(tx, {
          projectId: job.projectId,
          id,
          fromId: from,
          toId: to,
          type: 关系.type,
          amount: 关系.amount,
          basis: 关系.basis,
          // 笔录是人说的（`case_relation.source_kind` 的语义：data＝数据直接记录，human＝人认定）。
          // 即便关系类型是「转账」，它是**人在笔录里说的转账**，不是流水数据 ⇒ human。
          sourceKind: "human",
          trustState: 关系.存疑 ? "存疑" : "自动抽取",
        })
        await addCitation(tx, {
          id: 引用id(job.projectId, "relation", id, job.materialId, 片.片.起),
          projectId: job.projectId,
          factType: "relation",
          factId: id,
          materialId: job.materialId,
          locator: { start: 片.片.起, end: 片.片.止 },
          extractMethod: "机器",
        })
      }

      for (const 事件 of 片.事件) {
        const id = 事实id(
          job.projectId, "event", job.materialId, 片.片.起, 事件.type,
          事件.occurredRaw ?? "", 事件.participants.join("|"), 事件.summary ?? "",
        )
        await insertEvent(tx, {
          projectId: job.projectId,
          id,
          type: 事件.type,
          occurredAt: 事件.occurredAt,
          occurredRaw: 事件.occurredRaw,
          precision: 事件.precision,
          participants: 事件.participants,
          summary: 事件.summary,
          trustState: 事件.存疑 ? "存疑" : "自动抽取",
        })
        await addCitation(tx, {
          id: 引用id(job.projectId, "event", id, job.materialId, 片.片.起),
          projectId: job.projectId,
          factType: "event",
          factId: id,
          materialId: job.materialId,
          locator: { start: 片.片.起, end: 片.片.止 },
          extractMethod: "机器",
        })
      }
    }

    await setMaterialText(tx, job.projectId, job.materialId, text)

    if (!已取消) {
      if (问题片.length > 0) {
        await applyParseAction(tx, {
          projectId: job.projectId,
          materialId: job.materialId,
          action: "出问题",
          detail: {
            reason: `有 ${问题片.length} 段没抽干净：${问题片[0]!.问题[0] ?? ""}`,
            slices: 问题片.map((片) => ({
              range: `${片.片.起}-${片.片.止}`,
              reason: 片.问题.join("；").slice(0, 200),
              count: 片.问题.length,
            })),
            model: 输出.模型标识,
            promptVersion: 输出.prompt版本,
            attempts: Math.max(...问题片.map((片) => 片.尝试)),
            factCount: 抽取条数,
          },
        })
      } else {
        await applyParseAction(tx, {
          projectId: job.projectId,
          materialId: job.materialId,
          action: "完成",
          detail: {
            model: 输出.模型标识,
            promptVersion: 输出.prompt版本,
            factCount: 抽取条数,
          },
        })
      }
    }

    await 收尾(tx, job, "完成", null)
  })

  return "完成"
}

function 事实id(...parts: (string | number)[]): string {
  return Hash.sha256(parts.join("\u0000")).slice(0, 32)
}

function 引用id(projectId: string, factType: string, factId: string, materialId: string, 起: number): string {
  return Hash.sha256([projectId, factType, factId, materialId, 起].join("\u0000")).slice(0, 32)
}
```

```ts
export * as OpenhiveCaseExtractAi from "./case-extract-ai"

import { generateObject, type LanguageModel } from "ai"
import { Schema } from "effect"
import { 抽取结构 } from "./case-extract"
import type { 模型调用 } from "./case-extract-run"

/**
 * AI SDK 的结构化调用适配器。
 *
 * ## 为什么是 `generateObject` 而不是 task 子会话（R2）
 *
 * 后台 worker 没有请求级实例上下文；`SessionPrompt` 的会话存档虽好，但它要求 session 与
 * `InstanceRef`。设计 §7.4 想要「会话存档自动留痕」，本计划用 `parse_detail` 记模型名 /
 * prompt 版本 / 每片尝试次数替代；逐次调用流水留给后续计划补。
 *
 * ## 超时
 *
 * 单片一次调用 120 秒上限：模型侧卡死时不能让单 worker 永远停在这一片（设计 §6.5 单 worker
 * 的已知代价，缺口表记录）。超时抛错，执行器按一次失败重试。
 */
const 单片超时ms = 120_000

export function 建调用模型(模型: LanguageModel): 模型调用 {
  // 两个适配器都是**就地**把 `~standard` 挂到 schema 上、返回同一个对象（effect beta.83 的
  // `dist/Schema.js:463` 与 `:517`）。分两步写是为了让顺序（先 validate、再补 jsonSchema）显式可见：
  // 写成 `Object.assign(toStandardSchemaV1(x), toStandardJSONSchemaV1(x))` 会让人以为是两个对象，
  // 万一将来实现改成返回副本，`~standard` 就会被只有 jsonSchema 的那份覆盖，校验直接失效。
  const schema = Schema.toStandardJSONSchemaV1(Schema.toStandardSchemaV1(抽取结构))
  return async (输入) => {
    const 结果 = await generateObject({
      model: 模型,
      schema,
      system: 输入.系统,
      prompt: 输入.用户,
      temperature: 0.1,
      abortSignal: AbortSignal.timeout(单片超时ms),
    })
    return 结果.object
  }
}
```

### 3. 类型一致性

- `解析方式` 在后端 `case-parseable.ts` 与三个调用点（`file.ts` / `case-parse.ts` / `case-materials.ts`）同名同形状。
- `抽取器` / `模型调用` 在 Task 7 定义，Task 8 的 `RunDeps.建抽取器`、Task 9 的 `建调用模型` 与夹具全部用它。
- `实体输入` / `关系输入` / `事件输入` 在 Task 6 定义，Task 7 原样返回，Task 8 只读字段名（`type` / `canonicalValue` / `from` / `to` / `amount` / `basis` / `occurredRaw` / `participants` / `存疑`）。
- `文本片.起/止` 在 Task 3、Task 7、Task 8 的 `locator` 三处同名。
- `实体规范值(type: string, value)` 收 `string`：类型枚举的唯一定义在 Task 6 的 `case-extract.ts`，
  Task 4 若 import 回去会成环（`case-extract` → `case-value` → `case-extract`）。
- `parse_detail.slices` 的键（`range` / `reason` / `count`）与前端 `case-materials-api.ts:27-36` 逐字一致。
- `删除本材料的事实` / `deleteCitationsOfMaterial` / `setMaterialText` 在 Task 5 定义、Task 8 调用，名字逐字使用。

### 4. 已知缺口（计划内不修，交付时随报告一起说）

1. **PDF / 图片 / 音视频不解析**（R1）：上传只落盘，右键回 `not_parseable`。OCR / ASR / PDF 文本层是后续独立计划。
2. **项目级抽取口径不可覆盖**（R3）：prompt 是版本化常量；项目级 SKILL.md 覆盖未接。
3. **没有逐次调用的会话存档**（R2）：审计只能看 `parse_detail`（模型名 / prompt 版本 / 每片尝试次数），看不到每次请求与响应原文。
4. **few-shot 样例是固定文本**：没有「从本项目已确认事实里取几条」；跨项目口径差异要靠后续 prompt 覆盖。
5. **换模型重跑比对 / 人工抽检未做**（设计 §7.4 留痕层后半）：差异清单与抽检入口留给计划 5/7。
6. **单 worker 会被 AI 作业阻塞**：一次 AI 作业最长可达数百片 × 120 秒；同一队列里的表格作业要等它跑完。并发与卡死回收（`运行中` 超时）不在本计划。
7. **实体不回收**：重放只删被本材料引用的关系/事件，实体只 upsert；改过的抽取值会留下无引用实体（孤儿），实体合并/回收留给计划 5。
8. **`text_content` 只写不读**：全文检索与「查看解析结果」的原文回跳留给计划 7。
9. **零事实 ≠ 一定有问题**：一份纯叙述材料也可能一条事实都抽不出，本计划一律标「有问题」让用户看见；这是「不许说谎成已解析」的代价。
10. **真栈未验**：本计划只到单测与真应用测试；真实模型调用、真实笔录（docx）抽样、单 worker 阻塞时长都要在真栈验收时另跑（`#006-31`：组件绿 ≠ 真栈绿）。
11. **`parse_detail.attempts` 取问题片的最大尝试次数**，不是每片明细；每片的问题在 `slices` 里。
12. **文件名类型猜测会错**（R9）：`讯问笔录(2).docx` 能猜对，`张三材料.docx` 会落「其他」；类型只影响标签，不影响抽取。
13. **`case_event.time_type` 不填**：事件是「发生」还是「记录」，材料里没有可靠判据；先留 null，等有人工纠正入口再补（设计 §4.2 的四个字段里只缺这一个）。
14. **笔录抽出的关系一律 `source_kind = 'human'`**：哪怕是「转账」，它也是人在笔录里说的，不是流水数据。日后接入银行流水时那一路才是 `data`。
