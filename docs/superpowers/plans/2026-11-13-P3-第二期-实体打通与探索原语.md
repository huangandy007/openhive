# P3 第二期：实体打通与探索原语 · 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让「实体被合并 / 改名」后关系、事件、参与者、户名别名全部跟着走且可原样拆回；把账户归属收成一份共享读基（户名唯一对齐 ⇒ 该账户），让 `aggregate_money` / 实体档案 / 关系图三处口径一致；补上 `explore_entity` 与 `money_flow` 两个探索原语。

**Architecture:** 两个前提各收成唯一出处（`#002-06`），放在 `case-party.ts`：**基 1**（事件是否归属某实体：参与者表 ∪ 文本值回退，含正向/反向户名对齐）与**基 2**（关系是否归属某账户：恰好一端落在「账户 ∪ 唯一对齐到它的人/组织」集合里）。所有读者接同一份子查询，不许各自再抄条件。写端只改两处指向（合并、改名）并留快照，读端靠基 1 的文本回退接住旧值。

**Tech Stack:** Bun · TypeScript · Drizzle SQL 模板 · PostgreSQL（PGlite 测试）· `@modelcontextprotocol/sdk`。

**Spec:** `docs/superpowers/specs/2026-11-09-事实卡片抽象/11-P3-第二期-实体打通与探索原语-设计.md`

## 与设计的偏差 / 实施裁定

| # | 裁定 | 理由 |
|---|---|---|
| D-1 | 基 1 的文本回退值集 = 「实体自己 ∪ 正向代表（`对齐代表`） ∪ 反向对齐者（`对齐到账户`）」三者的规范值 ∪ 别名 | 设计 §3.1 只写「规范值与别名」。只取实体自己时，按账户查 `B` 看不到笔录事件「见面 [李四, 周八]」——它的参与者表没有行，只能靠文本命中「李四」。反向对齐者的值必须进值集，否则 §3.1 的反向对齐只对参与者表生效、对文本路径失效 |
| D-2 | 关系图的端点投影只在**中心是账户**时生效；节点的 `度数` 保持原始端点口径 | 设计只要求「端点落在集合里的边纳入图」。度数描述库里该实体自身的原始关系数，投影改变的是「画哪些边」，不是「库里有几条」 |
| D-3 | `explore_entity` 的 `关系圈` 恒为 1 跳、按 `coalesce(户名对齐代表, 对方.id)` 分组、上限 10；`跳数=2` 时另出 `数据.邻域`（直接复用 `关系图()`） | 设计 §5 只列了 `关系圈` 与「2 跳沿用关系图」，没说 2 跳结果放哪。复用 `关系图()` 保证截断口径一致（含它自己的缺口） |
| D-4 | `money_flow` 的 `首末` 由 `aggregate_money` 的 `数据.首末` 提供（同一条汇总 SQL 里用窗口聚合 `min(min(...)) over ()`），不另写一遍关系条件 | 另写一条 `min/max` 会把「类型 / 归属 / 人民币笔数」三条前提抄第二份（`#002-06`），迟早漂 |
| D-5 | `money_flow` 的 `方向` / `对手` 同时作用于汇总、对手排行、集中度与单笔最大；单笔最大按事件参与者角色判收/付 | 设计 §6 把两者列为过滤参数。事件参与者表已有 `付款方 / 收款方` 角色（`case-translate.ts:220-221`），不需要另造判据 |
| D-6 | 合并留痕新增字段名 `参与者们`（`[{eventId, ordinal}]`）与 `别名们`（`[id]`）；拆分 `未恢复` 文案 `参与者:<eventId>#<ordinal>` / `别名:<id>` | 留痕是 JSON，无 schema 变更；文案要能和人对话 |
| D-7 | 合并只改 `case_event_participant.entity_id`，`mention_text` 原样保留 | `mention_text` 是原文提及（设计 `01:800`），改了就不是原文了 |
| D-8 | `裁决` 对 entity 类事实**不**触发资金重算（设计 §7.2 的裁定） | 实测 `重建关系` 只读事件与人工关系，entity 裁决不改这两类输入 ⇒ 无可观测行为，红不了就不动代码 |
| D-9 | `关系圈` 的「对方」展示跟随分组键：代表存在时显示代表的值 / 类型 / 属性；并只收 `coalesce(times_cny, times, 1) > 0` 的关系 | 分组键是代表而展示是端点，会出现「张三 3 笔」但对方列写着账号的错位（10 §3.1 的显示口径是唯一出处）；纯外币关系按 `aggregate_money` 同口径不进（金额是 0.00 的行会让圈里出现空组） |

```ts
import { rowsOf } from "@opencode-ai/auth/migrate"
import type { Queryable } from "./case-store"

/** `id in (...)` 片段：调用点把要匹配的列交进来，集合由本文件构造。 */
function id集合(ids: readonly string[]): SQL {
  return sql`(${sql.join(
    ids.map((id) => sql`${id}`),
    sql`, `,
  )})`
}

/**
 * 反向对齐集（11 §3.1）：**唯一**户名对齐到这批账户的 人 / 组织 id。
 *
 * 与 `户名对齐` 对称、同样 fail-closed：人的规范值恰好只对应一个账户（别名候选数 = 1），
 * 且那个账户就在 `账户ids` 里，才算对齐。别名对应 0 个或多个账户一律不算。
 * 已排除的人不算——那是人的判断，读端不许把它拉回来。
 */
export function 对齐到账户(projectId: string, 账户ids: readonly string[]): SQL {
  return sql`(select pe.id
     from auth.case_entity pe
    where pe.project_id = ${projectId}
      and pe.type in ('人', '组织')
      and pe.trust_state <> '已排除'
      and (select count(distinct a.entity_id)
             from ${户名来源(projectId)}
              and ae.type = '账户'
              and a.value = pe.canonical_value) = 1
      and exists (select 1 from ${户名来源(projectId)}
                   and a.entity_id in ${id集合(账户ids)}
                   and a.value = pe.canonical_value))`
}

/**
 * 归属实体集：实体自己 ∪ 正向代表（人 → 唯一户名账户）∪ 反向对齐者（账户 → 唯一户名的
 * 人/组织）。**事件与值都从这一个集合出发**（`#002-06`）。
 */
export function 归属实体集(projectId: string, 实体id: string): SQL {
  const id = sql`${实体id}`
  const 类型 = sql`(select type from auth.case_entity where project_id = ${projectId} and id = ${id})`
  const 值 = sql`(select canonical_value from auth.case_entity where project_id = ${projectId} and id = ${id})`
  return sql`(select ${id}::text as id
              union
              select (${对齐代表(projectId, id, 类型, 值)}) as id
              union
              select id from ${对齐到账户(projectId, [实体id])} 反向)`
}

/**
 * 归属值集：归属实体集里每个实体的规范值 ∪ 别名（`case_entity.aliases`）。
 * `participants text[]` 存的是规范值（`01` §3.3）；合并 / 改名只把旧值并进别名、不改 text[]，
 * 所以旧事件靠这一路仍然命中。
 */
export function 归属值集(projectId: string, 实体id: string): SQL {
  return sql`(select x.canonical_value as 值
                from auth.case_entity x
               where x.project_id = ${projectId} and x.id in ${归属实体集(projectId, 实体id)}
              union
              select 别名
                from auth.case_entity x, unnest(x.aliases) as 别名
               where x.project_id = ${projectId} and x.id in ${归属实体集(projectId, 实体id)})`
}

/** `归属值集` 的 JS 版：给需要按值过滤（对手、方向）的读端用。 */
export async function 读归属值(db: Queryable, projectId: string, 实体id: string): Promise<string[]> {
  const 行们 = rowsOf(await db.execute(sql`select 值 from ${归属值集(projectId, 实体id)} 值们`))
  return 行们.map((行) => String(行.值))
}

/**
 * 基 2（11 §3.2）：账户归属集 = 账户自己的 ids ∪ 唯一户名对齐到它的人/组织。
 * 只由账户构造：人 / 组织查关系时仍用「端点等于自己」的原口径。
 */
export function 账户归属集(projectId: string, 账户ids: readonly string[]): SQL {
  return sql`(select id from auth.case_entity
               where project_id = ${projectId} and id in ${id集合(账户ids)}
              union
              select id from ${对齐到账户(projectId, 账户ids)} 反向)`
}

/**
 * 关系归属某账户 ⇔ **恰好一端**落在归属集里（XOR，不是 `OR`）。
 *
 * 两端都落在集合里 = 账户内部往来（如「李四 → B」）：它在账户视角下会变成一个自环，
 * 既不产生对手方也不产生方向 ⇒ 不归属、不画、不计数，条数进缺口。
 */
export function 关系归属条件(
  projectId: string,
  账户ids: readonly string[],
  从: SQL,
  到: SQL,
): SQL {
  const 集 = 账户归属集(projectId, 账户ids)
  return sql`((${从} in ${集}) <> (${到} in ${集}))`
}

/**
 * 基 1（11 §3.1）：事件是否归属该实体。
 *
 * - 参与者表：`p.entity_id` ∈ 归属实体集（本人 / 正向代表 / 反向对齐者）；
 * - 文本回退：`participants` 的规范值 ∈ 归属值集（旧数据、对不上档案的参与者走这一路）。
 *

}
```

```ts
/**
 * 参与者摘要的唯一出处（11 §7.1）。
 *
 * - `值`：`participants text[]` 里的规范值，剔除「已排除」实体的规范值（`query_events` 用）；
 * - `摘要`：参与者表的 `角色：规范值`，剔除已排除实体；参与者表没有行时回退文本值（`query_timeline` 用）。
 *
 * 两个读口各写一遍迟早漂（`#002-06`）：此前 `query_events` 剔排除、`query_timeline` 不剔。
 */
async function 参与者视图(
  ctx: 工具上下文,
  行们: readonly { readonly id: string; readonly participants: readonly string[] }[],
  含已排除: boolean,
): Promise<Map<string, { 值: string[]; 摘要: string[] }>> {
  const 结果 = new Map<string, { 值: string[]; 摘要: string[] }>()
  if (行们.length === 0) return 结果
  const ids = 行们.map((行) => 行.id)
  const 已排除值 = new Set<string>()
  if (!含已排除) {
    const 排除行 = rowsOf(
      await ctx.db.execute(sql`
        select distinct canonical_value from auth.case_entity
         where project_id = ${ctx.身份.projectId} and trust_state = '已排除'
      `),
    )
    for (const 行 of 排除行) 已排除值.add(String(行.canonical_value))
  }
  const 摘要表 = new Map<string, string[]>()
  const 表行们 = rowsOf(
    await ctx.db.execute(sql`
      select p.event_id, p.role, e.canonical_value as value
        from auth.case_event_participant p
        join auth.case_entity e on e.project_id = p.project_id and e.id = p.entity_id
       where p.project_id = ${ctx.身份.projectId} and p.event_id = any(${文本数组(ids)})
         ${含已排除 ? sql`` : sql`and e.trust_state <> '已排除'`}
       order by p.event_id asc, p.ordinal asc
    `),
  )
  for (const 行 of 表行们) {
    const id = String(行.event_id)
    const 项 = `${String(行.role)}：${String(行.value)}`
    const 列 = 摘要表.get(id)
    if (列 === undefined) 摘要表.set(id, [项])
    else 列.push(项)
  }
  for (const 行 of 行们) {
    const 值 = 行.participants.filter((项) => !已排除值.has(项))
    const 摘要 = 摘要表.get(行.id) ?? 值.map((项) => `参与者：${项}`)
    结果.set(行.id, { 值: [...值], 摘要 })
  }
  return 结果
}
```

```ts
export interface 关系圈项 {
  readonly 对方: string
  readonly 对方类型: string
  /** 与 `档案关系.对方细类` 同型（`细类()` 返回 `string | undefined`，判不出给 `null`）。 */
  readonly 对方细类: string | null
  readonly 方向: "出" | "入"
  readonly 类型: string
  readonly 次数: number
  readonly 金额: string | null
  readonly 首: number | null
  readonly 末: number | null
}

/**
 * 一圈关系按「对方代表」聚合（`explore_entity` 用）：原始关系是每对多行，直接列出去不是
 * 一个圈。分组键与 `aggregate_money` 的对手方一致（`coalesce(户名对齐代表, 对方.id)`），
 * **展示也跟着走**（10 §3.1「显示优先用户名」）：代表存在时展示代表的值 / 类型 / 属性，
 * 否则展示端点本身。不改写端点、不合并实体（关系事实仍按原样）。
 */
export async function 关系圈(
  db: Queryable,
  input: {
    readonly projectId: string
    readonly id: string
    readonly type: string
    readonly 起?: number
    readonly 止?: number
  },
): Promise<关系圈项[]> {
  const 是账户 = input.type === "账户"
  const 归属集 = 是账户 ? 账户归属集(input.projectId, [input.id]) : undefined
  const from属于 = 归属集 === undefined ? sql`r.from_id = ${input.id}` : sql`r.from_id in ${归属集}`
  const 触达 = 归属集 === undefined
    ? sql`(r.from_id = ${input.id} or r.to_id = ${input.id})`
    : 关系归属条件(input.projectId, [input.id], sql`r.from_id`, sql`r.to_id`)
  const 窗: SQL[] = []
  if (input.起 !== undefined) 窗.push(sql`coalesce(r.last_at, r.first_at, 0) >= ${input.起}`)
  if (input.止 !== undefined) 窗.push(sql`coalesce(r.first_at, r.last_at, 0) <= ${input.止}`)
  const 行们 = rowsOf(
    await db.execute(sql`
      select min(coalesce(展示.canonical_value, 对方.canonical_value)) as 对方值,
             min(coalesce(展示.type, 对方.type)) as 对方类型,
             min(coalesce(展示.attrs::text, 对方.attrs::text)) as 对方attrs,
             case when ${from属于} then '出' else '入' end as 方向,
             r.type as 关系类型,
             sum(coalesce(r.times, 1))::int as 次数,
             sum(r.amount)::text as 金额,
             min(coalesce(r.first_at, r.last_at)) as 首,
             max(coalesce(r.last_at, r.first_at)) as 末
        from auth.case_relation r
        join auth.case_entity 对方
          on 对方.project_id = r.project_id
         and 对方.id = case when ${from属于} then r.to_id else r.from_id end
         and 对方.trust_state <> '已排除'
        left join lateral ${户名对齐(input.projectId, sql`对方.id`, sql`对方.type`, sql`对方.canonical_value`)} 对齐 on true
        left join lateral (
          select canonical_value, type, attrs
            from auth.case_entity
           where project_id = ${input.projectId} and trust_state <> '已排除' and id = 对齐.代表
        ) 展示 on true
       where r.project_id = ${input.projectId}
         and r.trust_state <> '已排除'
         and ${触达}
         and coalesce(r.times_cny, r.times, 1) > 0
         ${窗.length === 0 ? sql`` : sql`and ${sql.join(窗, sql` and `)}`}
       group by 方向, r.type, coalesce(对齐.代表, 对方.id)
       order by sum(r.amount) desc nulls last, 对方值 asc
       limit ${关系圈上限}
    `),
  )
  return 行们.map((行) => ({
    对方: String(行.对方值),
    对方类型: String(行.对方类型),
    对方细类: 细类(String(行.对方类型), String(行.对方值), 解JSON<Record<string, unknown>>(行.对方attrs, {})) ?? null,
    方向: String(行.方向) === "出" ? "出" : "入",
    类型: String(行.关系类型),
    次数: Number(行.次数),
    金额: (行.金额 as string | null) ?? null,
    首: 行.首 === null || 行.首 === undefined ? null : Number(行.首),
    末: 行.末 === null || 行.末 === undefined ? null : Number(行.末),
  }))
}
```

```ts
/**
 * 某账户的资金流（09 §4.2）：汇总 / 收支分列 / 首末 / 对手排行 / 单笔最大 / 集中度。
 *
 * 汇总、对手方、外币行数、空原因四拆、时间窗校验、账户解析**全部复用 `aggregate_money`**

 * 基 2 的归属修复随之自动生效。
 */
export async function money_flow(
  ctx: 工具上下文,
  args: { 账户: string; 起?: number; 止?: number; 方向?: string; 对手?: string },
): Promise<工具结果> {
  校验时间窗(args)
  const 方向 = args.方向 ?? "全部"
  if (方向 !== "收" && 方向 !== "付" && 方向 !== "全部")
    throw new 工具错误("bad_input", `方向只能是 收 / 付 / 全部，收到 ${String(args.方向)}`)
  const 目标方向 = 方向 === "收" ? "入" : 方向 === "付" ? "出" : undefined
  const 汇总结果 = await aggregate_money(
    ctx,
    {
      账户: args.账户,
      ...(args.起 === undefined ? {} : { 起: args.起 }),
      ...(args.止 === undefined ? {} : { 止: args.止 }),
    },
    { 对手方上限: 资金流对手上限 },
  )
  const 单笔口径 =
    "单笔最大取资金交易事件（CNY、未排除、经基 1 涉及本账户）；只有笔录人工关系、没有对应流水事件的笔不在榜上"
  // 空 / 材料未翻译：直接沿用 aggregate_money 的空原因与引导（同一判据，不另判一次）。
  if (汇总结果.空原因 !== null)
    return { ...汇总结果, 缺口: [...汇总结果.缺口, 单笔口径] }

  const 数据 = 汇总结果.数据 as {
    汇总: { 方向: string; 笔数: number; 合计: string }[]
    首末: { 首: number | null; 末: number | null } | null
    对手方: { 对手方: string; 方向: string; 笔数: number; 合计: string }[]
    外币行数: number
  }
  // 对手解析在过滤之前：解析不到是连 `bad_input` / `not_found` 都该原样抛出的入参问题。
  const 对手值们 = args.对手 === undefined ? undefined : await 读归属值(ctx.db, ctx.身份.projectId, (await 解析实体(ctx, args.对手, "对手")).id)
  const 汇总 = 目标方向 === undefined ? 数据.汇总 : 数据.汇总.filter((行) => 行.方向 === 目标方向)
  const 对手排行 =
    (目标方向 === undefined ? 数据.对手方 : 数据.对手方.filter((行) => 行.方向 === 目标方向)).filter(
      (行) => 对手值们 === undefined || 对手值们.includes(行.对手方),
    )
  const 笔数 = 汇总.reduce((和, 行) => 和 + 行.笔数, 0)
  const 合计 = (方向名: "入" | "出") => 汇总.find((行) => 行.方向 === 方向名)?.合计 ?? "0.00"
  // 集中度：前 3 对手金额 ÷ 同方向合计。金额是 numeric 字符串，这里只为百分比转一次浮点
  // （口径里写明是近似值；合计本身仍以字符串交给模型）。
  const 集中度: Record<string, string> = {}
  for (const 方向名 of ["出", "入"] as const) {
    const 行们 = 对手排行.filter((行) => 行.方向 === 方向名)
    if (行们.length === 0) continue
    const 总量 = 行们.reduce((和, 行) => 和 + Number(行.合计), 0)
    if (总量 === 0) continue
    const 前三 = [...行们].sort((甲, 乙) => Number(乙.合计) - Number(甲.合计)).slice(0, 3)
    const 占 = (前三.reduce((和, 行) => 和 + Number(行.合计), 0) / 总量) * 100
    集中度[方向名] = `${占.toFixed(1)}%`
  }

  // 账户实体再解析一次：`aggregate_money` 内部解析过但不外露实体（改它的返回形状会波及
  // 四个工具的信封契约）。代价是 2～3 次查询，已算进查询预算（D-4 的同一笔账）。
  const 解析 = await 解析账户(ctx, args.账户)

  const 单笔最大 = rowsOf(
    await ctx.db.execute(sql`
      select id, occurred_at, amount::text as amount, summary
        from auth.case_event
       where project_id = ${ctx.身份.projectId}
         and type = ${资金交易}
         and currency = 'CNY'
         and trust_state <> '已排除'
         and amount is not null
         and ${事件归属条件(ctx.身份.projectId, 账户.id)}
         ${目标方向 === undefined ? sql`` : sql`and exists (
             select 1 from auth.case_event_participant p
              where p.project_id = ${ctx.身份.projectId} and p.event_id = case_event.id
                and p.entity_id = ${账户.id} and p.role = ${目标方向 === "入" ? "收款方" : "付款方"})`}
         ${对手值们 === undefined ? sql`` : sql`and exists (
             select 1 from unnest(participants) as 参与者 where 参与者 = any(${文本数组(对手值们)}))`}
       order by amount desc, occurred_at asc nulls last, id asc
       limit ${单笔最大上限}
    `),
  ).map((行) => ({
    id: String(行.id),
    金额: String(行.amount),
    时间: 行.occurred_at === null || 行.occurred_at === undefined ? null : Number(行.occurred_at),
    摘要: (行.summary as string | null) ?? null,
  }))

  const 缺口 = [...汇总结果.缺口, 单笔口径]
  if (汇总.length === 0) 缺口.push(`所选方向（${方向}）在本时间窗内没有人民币转账关系`)
  if (对手值们 !== undefined && 对手排行.length === 0) 缺口.push("与所选对手没有符合条件的往来")
  const 件数 = (方向名: "入" | "出") => 汇总.find((行) => 行.方向 === 方向名)?.笔数 ?? 0
  return {
    摘要:
      `「${args.账户}」资金流：入 ${件数("入")} 笔 / ${合计("入")}，出 ${件数("出")} 笔 / ${合计("出")}；` +
      `前 ${对手排行.length} 个对手、单笔最大 ${单笔最大.length} 条` + (方向 === "全部" ? "" : `（已按「${方向}」过滤）`),
    数据: {
      笔数,
      收入合计: 合计("入"),
      支出合计: 合计("出"),
      首末: 数据.首末,
      汇总,
      对手排行,
      单笔最大,
      集中度,
      外币行数: 数据.外币行数,
    },
    口径:
      "汇总、对手方、外币行数、空原因与 aggregate_money 完全一致（账户归属按基 2：恰好一端落在本账户 ∪ 唯一户名对齐者）；" +
      "收支分列不相抵；首末为口径内最早 first_at 与最晚 last_at（不受方向影响）；" +
      "集中度 = 同方向前 3 对手金额 ÷ 该方向合计，百分比保留一位小数（近似值，合计仍以 numeric 字符串为准）；" +
      单笔口径 + "。",
    缺口,
    空原因: null,
    出处: 单笔最大.slice(0, 3).map((条) => ({
      事实: `单笔 ${条.金额} 元（${条.摘要 ?? "无摘要"}）`,
      代表: 条.id,
```
