# skill 版本迭代（P1）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让作者能把一份已发布的 skill 复制到自己项目里改，改完提交，管理员只走技术关就发新版本；不改就放弃，版本号回退。

**Architecture:** 状态机加两个动作（`submit_iteration` / `abort_iteration`）、两个存储意图（`copy_publish_to_workspace` / `discard_pending`）；`asset` 表加两列（变更说明、工作副本相对路径），三层同步（迁移 / drizzle 模型 / `AssetMetadata`）；使用面路由器加三个端点，授权在读请求体之前；前端详情页「版本」Tab 分三态，发起成功后经**既有的**跨栏传送带把工作副本路径塞进右栏。

**Tech Stack:** Bun 1.4.2 monorepo · Effect 4.0.0-beta（`Effect.gen` / `Result`）· drizzle-orm 原始 SQL · PostgreSQL（PGlite 测试夹具 `startProductionDb`）· SolidJS 1.9 · Kobalte Dialog · Tailwind v4 · oxlint 1.60。

**Spec:** `docs/superpowers/specs/2026-11-01-skill版本迭代-design.md`

**Interfaces:**
- Consumes: 无（本计划第一个 Task）。
- Produces:
  - `AssetMetadata.iterationNote: string`（非空，默认 `""`）
  - `AssetMetadata.iterationWorkspace: string | null`（相对**用户沙箱根**，如 `u1/p1/.openhive/iterations/asset_1`）
  - `AssetLifecycleUpdate.iterationNote?: string` / `iterationWorkspace?: string | null`
  - `updateAssetLifecycle` 的 `set` 用 `coalesce(占位符, 列)` 写这两列——`undefined` 传 `null` 即保留原值（与既有 `visibility` 同一手法）。

#### 为什么这两列要这样落

- `iteration_note` 存「最近一次发起」的意图，发布后**保留**当本版说明，下次发起时覆盖；放弃迭代清空（设计 §3）。
- `iteration_workspace` 存**相对沙箱根**的路径而不是绝对路径：换落盘根时不用搬库（`LEARNINGS #010-04`：路径进了库就得连库一起搬）。
- `iteration_workspace` 可空、`iteration_note` 非空默认 `''`：与 0026 的 `summary` / `precautions` 同一口径——空串与「没填」语义相同，多一种 null 态只让前端多一个分支。

3g. `AssetLifecycleUpdate` 接口加三个字段：

```ts
export interface AssetLifecycleUpdate {
  readonly expectedStatus: AssetStatus
  readonly status: AssetStatus
  readonly version: number
  readonly updatedAt: number
  readonly publishedAt: number | null
  readonly archivedAt: number | null
  readonly visibility?: AssetVisibility
  // 【保留的定制 · 同步上游时不要丢】版本迭代（2026-11-01）。
  //
  // `iterationNote` / `iterationWorkspace` 省略 = **不改**这两列（`coalesce(null, 列)`），
  // 与上面 `visibility` 同一手法：一次写入只管它负责的列，两条写入路径互不覆盖。
  //
  // `iterationWorkspace` 刻意**不带 `| null`**：在这个接口里 `null` 与 `undefined` 必须同义
  // （都表示「不改」），否则「传 null 是想清空还是想不改」就靠猜。
  // 清空单独给一个显式开关：
  readonly iterationNote?: string
  readonly iterationWorkspace?: string
  /**
   * 把 `iteration_workspace` 置 `null`（`abort_iteration` 用）。
   *
   * 为什么不复用 `iterationWorkspace: null`：`coalesce` 里 `null` 的含义是「保留原值」，
   * 同一个值兼表两件事，读代码的人分不出来，写代码的人迟早写反。
   */
  readonly clearIteration?: boolean
}
```

```ts
/**
 * 迭代工作副本在用户沙箱里的落点（2026-11-01 设计 §5）。
 *
 * ⚠️ `.openhive/` **不是** `.opencode/`，也不在 `.claude/skills`、`.agents/skills` 里：
 * 内核的 skill 扫描只看那四个目录（`skill/index.ts:23-25`）。工作副本一旦落进扫描范围，
 * 就会和项目里指向共享资产的那条链接**同名打架**——后到覆盖，谁赢取决于到达顺序
 * （`LEARNINGS #010-05`）。所以这一层目录名刻意与它们都不重名。
 */
export const ITERATION_ROOT_SEGMENT = ".openhive"

/** 上一级目录名。单独命名是为了让测试与文档引用同一个字面量。 */
export const ITERATION_DIRECTORY_NAME = "iterations"

/**
 * 工作副本的路径段：`<userId> <projectId> .openhive iterations <assetId>`。
 *
 * 逐段校验（不是拼完再校验）：`assertSafeSegment` 挡 `..`、分隔符、Windows 保留名，
 * 与资产根那一侧同一条口径。
 */
export function iterationWorkspaceSegments(
  userId: string,
  projectId: string,
  assetId: string,
): readonly string[] {
  return [
    assertSafeSegment(userId, "userId"),
    assertSafeSegment(projectId, "projectId"),
    ITERATION_ROOT_SEGMENT,
    ITERATION_DIRECTORY_NAME,
    assertSafeSegment(assetId, "assetId"),
  ]
}

/** 相对**用户沙箱根**的片段（落库用这个，`#010-04`：换根不用搬库）。 */
export function iterationWorkspaceRelative(userId: string, projectId: string, assetId: string): string {
  return iterationWorkspaceSegments(userId, projectId, assetId).join("/")
}

/**
 * 从库里那一段还原绝对路径，并校验仍在沙箱根**内部**。
 *
 * 两个防线缺一不可：写入时逐段校验挡的是「本次请求带进来的坏值」，这里挡的是
 * 「库里已经存着的坏值」（历史数据 / 手工改库）。库里被改坏时不能把文件写到根外面去。
 */
export function iterationWorkspaceDirectory(root: string, relative: string): string {
  const 段 = relative.split("/")
  for (const 一段 of 段) assertSafeSegment(一段, "工作副本目录")
  return assertWithinRoot(root, join(root, ...段), "工作副本目录")
}

/** 目录存在吗。不存在是正常态（第一次发起迭代），不抛错。 */
export async function directoryExists(directory: string): Promise<boolean> {
  const info = await statOrNull(directory)
  return info?.isDirectory() === true
}

/**
 * 目录里有「实质内容」吗：至少有一个非空子目录、或一个文件。
 *
 * 为什么不用 `readdir().length > 0`：`copyDirectory` 会连空子目录一起搬，一个只剩
 * `references/`（空）的 pending 目录读起来「有东西」，发布出来却是个空壳 skill。
 * 递归判到第一个文件为止——skill 目录都很小，不做缓存。
 */
export async function hasPendingContent(directory: string): Promise<boolean> {
  const info = await statOrNull(directory)
  if (info?.isDirectory() !== true) return false

  for (const 条目 of await readdir(directory, { withFileTypes: true })) {
    if (条目.isFile()) return true
    if (条目.isDirectory() && (await hasPendingContent(join(directory, 条目.name)))) return true
  }
  return false
}
```

```ts
/**
 * 本次流转要碰的工作副本。`undefined` = 这一条动作不碰工作副本。
 *
 * 三条迭代动作各有各的落点来源：
 * - `start_iteration`：**现在算**（用户 + 项目 + 资产），并落库；
 * - `submit_iteration` / `abort_iteration`：**读库里那一段**。库是唯一真相，
 *   再由出口传一份就是两份口径（`#002-06` / `#010-04`）。
 */
interface IterationTarget {
  /** 沙箱根（绝对）。 */
  readonly root: string
  /** 相对沙箱根的片段；`null` = 库里没有记录。 */
  readonly relative: string | null
  /** 绝对路径；`relative` 为 `null` 时也是 `null`。 */
  readonly directory: string | null
}

function 迭代目标(input: TransitionAssetInput, asset: AssetMetadata): IterationTarget {
  const 根 = input.workspaceRoot
  if (根 === undefined) {
    // 调用方漏传是**编码错误**，不是状态错误：不翻成用户可读的错误码，
    // 直接炸出来（出口永远会传，漏传说明接线断了）。
    throw new Error(`${input.action} 需要 workspaceRoot`)
  }

  if (input.action === "start_iteration") {
    const 项目 = input.projectId
    if (项目 === undefined) throw new Error("start_iteration 需要 projectId")
    // 用 `viewer.userId` 而不是 `asset.ownerId`：工作副本落在**发起人**的沙箱里，
    // 出口已校验 projectId 属于该发起人。ownerId 与 viewer 在作者动作上恒等，
    // 但写成 viewer 才是「谁发起、落在谁的沙箱」这条事实。
    const 相对 = iterationWorkspaceRelative(input.viewer.userId, 项目, asset.id)
    return { root: 根, relative: 相对, directory: iterationWorkspaceDirectory(根, 相对) }
  }

  const 相对 = asset.iterationWorkspace
  return {
    root: 根,
    relative: 相对,
    directory: 相对 === null ? null : iterationWorkspaceDirectory(根, 相对),
  }
}

/**
 * 本次流转要写进 `iteration_note` / `iteration_workspace` 的值。`undefined` = 不动这两列。
 *
 * - `start_iteration`：记说明、记工作副本；发起那一刻上一版的说明就被覆盖（设计 §3）；
 * - `submit_iteration`：两个都不动（说明仍是本次迭代的，路径仍指向作者手里那份）；
 * - `abort_iteration`：说明清空、路径清空——留着一条被放弃的说明，已发布资产会显示
 *   错误的注解（设计 §3 原话）。
 */
function iterationColumnsOf(
  action: SkillAction,
  reason: string | undefined,
  target: IterationTarget | undefined,
): { iterationNote: string; iterationWorkspace: string } | { clearIteration: true } | undefined {
  if (action === "start_iteration") {
    return { iterationNote: (reason ?? "").trim(), iterationWorkspace: target?.relative ?? "" }
  }
  if (action === "abort_iteration") return { clearIteration: true }
  return undefined
}
```

```ts
const CONFLICT = 409

/**
 * 迭代三个端点共用一个处理函数（`#002-06`：同一件事只该有一条实现）。
 *
 * **顺序是有判据的**（`LEARNINGS #004-09`）：身份 → 资产存在 → **授权** → 读请求体 → 校验
 * projectId → 流转。授权排在读体之前：非作者递畸形 JSON 拿 403 而不是 400——错误码本身
 * 不能变成「你有没有这个权限」的探针。
 */
function handleIteration(
  request: HttpServerRequest.HttpServerRequest,
  deps: Deps,
  action: SkillAction,
) {
  return Effect.gen(function* () {
    const user = yield* Effect.serviceOption(User.Service)
    if (Option.isNone(user)) return unauthorized()
    const userId = user.value.id

    const 参数 = yield* HttpRouter.params
    const assetId = 参数["id"] ?? ""
    const asset = yield* Effect.promise(() => assetById(deps.pg(), assetId))
    if (asset === undefined) return fail(NOT_FOUND, "资产不存在")

    const department = yield* 取部门(deps, userId)
    const grants = yield* Effect.promise(() => grantsFor(deps.pg(), userId))
    const viewer = { userId, department }

    const 预检 = yield* Effect.result(
      Effect.try({
        try: () => authorizeTransition(viewer, asset, grants, action),
        catch: (error) => error,
      }),
    )
    if (Result.isFailure(预检)) return 失败(预检.failure)

    let note: string | undefined
    let projectId: string | undefined
    if (action === "start_iteration") {
      const body = yield* 读取体(request)
      if (!isRecord(body)) return fail(BAD_REQUEST, "请求体不是 JSON 对象")

      const 说明 = body["note"]
      if (typeof 说明 !== "string") return fail(BAD_REQUEST, "note 必须是字符串")
      note = 说明

      const 项目 = body["projectId"]
      if (typeof 项目 !== "string" || !User.isSafePathSegment(项目)) {
        return fail(BAD_REQUEST, "projectId 不合法")
      }
      // 不是成员 ⇒ 400 而不是 404：404 会变成「这个项目 id 存在吗」的探针。
      const 是成员 = yield* Effect.promise(async () => {
        const rows = rowsOf(
          await deps.pg().execute(
            sql`select 1 as ok from auth.project_member where project_id = ${项目} and user_id = ${userId}`,
          ),
        )
        return rows.length > 0
      })
      if (!是成员) return fail(BAD_REQUEST, "目标项目不属于你")
      projectId = 项目
    }

    const 沙箱根 = workspaceRoot(process.env)
    const 结果 = yield* Effect.result(
      Effect.tryPromise({
        try: () =>
          transitionAsset({
            db: deps.pg(),
            root: assetsRoot(process.env),
            assetId,
            action,
            viewer,
            grants,
            workspaceRoot: 沙箱根,
            ...(note === undefined ? {} : { reason: note }),
            ...(projectId === undefined ? {} : { projectId }),
          }),
        catch: (error) => error,
      }),
    )
    if (Result.isFailure(结果)) return 失败(结果.failure)

    const updated = 结果.success
    // 只给作者回工作副本的**绝对路径**（前端要把它写进给 AI 的指令里）。
    const 工作副本 =
      updated.iterationWorkspace === null
        ? undefined
        : iterationWorkspaceDirectory(沙箱根, updated.iterationWorkspace)

    return ok({
      assetId: updated.id,
      status: updated.status,
      version: updated.version,
      ...(工作副本 === undefined ? {} : { workspace: 工作副本 }),
    })
  })
}

/**
 * 迭代出口的错误翻译。
 *
 * 与治理台那份**分开写**是有意的：本仓每个出口模块各有一份 `映射错误()`，见
 * `governance-assets.ts` 的同名函数——出口的失败面各不相同，抽成一份公共映射会让
 * 「这个出口会回哪些码」变成要跳文件才能读出来的事。
 *
 * 文案差异也是真的：`reason_required` 在这里是**变更说明**，不是治理台那句「理由」。
 */
function 失败(error: unknown) {
  if (error instanceof AssetTransitionError) {
    switch (error.code) {
      case "asset_not_found":
        return fail(NOT_FOUND, error.message)
      case "actor_not_allowed":
        return fail(FORBIDDEN, error.message)
      case "reason_required":
        return fail(BAD_REQUEST, "请填写变更说明")
      case "unknown_action":
      case "unsupported_asset_type":
        return fail(BAD_REQUEST, error.message)
      case "invalid_source":
      case "concurrent_transition":
      case "source_directory_required":
      case "personal_asset_not_shared":
      case "department_missing":
      case "visibility_not_applicable":
      case "iteration_not_submitted":
        return fail(CONFLICT, error.message)
    }
  }
  if (error instanceof MissingSourceDirectoryError) return fail(CONFLICT, error.message)
  throw error
}
```

接口与结果类型：

```ts
/** 迭代三次调用的回包：成功时可能带 `workspace`（发起才有）。 */
export type 迭代结果 =
  | { readonly kind: "ok"; readonly value: { readonly workspace?: string } }
  | { readonly kind: "rejected"; readonly message: string }
  | { readonly kind: "failed"; readonly message: string }

export interface ContentApi {
  save(assetId: string, patch: 内容补丁): Promise<ContentOutcome>
  /** 发起迭代：`note` 是变更说明（服务端必填），`projectId` 是工作副本落在哪个项目。 */
  iteration(assetId: string, note: string, projectId: string): Promise<迭代结果>
  submitIteration(assetId: string): Promise<迭代结果>
  abortIteration(assetId: string): Promise<迭代结果>
}
```

实现（`createContentApi` 内，`save` 之后加一个共用函数与三个方法）：

```ts
  /**
   * 一次 POST 的三态翻译。`save` 用的是 PATCH 且回包是整行，形状不同，所以只共用
   * 「怎么把 HTTP 结果读成 ok / rejected / failed」这一小段，不强行合并。
   */
  const 发送 = async (
    url: string,
    body: Record<string, unknown> | undefined,
    失败提示: string,
  ): Promise<迭代结果> => {
    let response: Response
    try {
      response = await send(url, {
        method: "POST",
        // 不带体时不发 Content-Type：空体配 application/json 有些中间层会拒。
        ...(body === undefined
          ? {}
          : { headers: { "Content-Type": "application/json" }, body: JSON.stringify(body) }),
      })
    } catch {
      return { kind: "failed", message: 失败提示 }
    }

    let 回包: unknown
    try {
      回包 = await response.json()
    } catch {
      回包 = undefined
    }

    if (response.status === 401) return { kind: "rejected", message: "登录状态已失效，请重新登录" }
    if (response.status >= 500) return { kind: "failed", message: 消息(回包, response) }
    if (!response.ok) return { kind: "rejected", message: 消息(回包, response) }
    if (!isRecord(回包)) return { kind: "failed", message: "服务返回的数据格式不对" }
    // `workspace` 只对发起迭代有意义；不是字符串就当作没给（前端退回「没有路径」的提示），
    // 不因此把一次**已经成功**的流转报成失败。
    const 路径 = 回包["workspace"]
    return { kind: "ok", value: typeof 路径 === "string" && 路径.length > 0 ? { workspace: 路径 } : {} }
  }

  return {
    save: ...,
    iteration: (assetId, note, projectId) =>
      发送(PATH.iteration(assetId), { note, projectId }, "操作失败，请检查网络后重试"),
    submitIteration: (assetId) => 发送(PATH.iterationSubmit(assetId), undefined, "提交失败，请检查网络后重试"),
    abortIteration: (assetId) => 发送(PATH.iterationAbort(assetId), undefined, "操作失败，请检查网络后重试"),
  }
```

> `消息(body, response)` 现在写的兜底是 `保存失败（HTTP n）`。改成带动作的说法：给它加第二个可选参数 `动作 = "保存"`，三个迭代调用分别传 `"操作"` / `"提交"`。**但 `save` 的既有断言不能再动**——默认值保持 `"保存"`，既有调用点一个字不改。

```ts
  const [迭代中, set迭代中] = createSignal<string | undefined>()

  /**
   * 三条迭代调用共用一把「一次一条」的锁（与保存 / 收藏同一纪律，`#010-05`）：
   * 后发的先到会把界面翻回去。
   *
   * 失败都写 `error`（详情自己有 `role="alert"` 读它），成功后清掉——不清的话
   * 上一次的 409 会一直挂在详情顶上。
   *
   * 这三条都**不**改本地行：版本号 / 状态以服务端为准，前端下一次 `load` 或
   * `applyAsset` 才更新。猜一个 `version + 1` 上去，失败时就得多写一次回滚。
   */
  const 迭代调用 = async <T>(
    assetId: string,
    跑: () => Promise<迭代结果>,
    成功: (结果: Extract<迭代结果, { kind: "ok" }>) => T,
  ): Promise<{ readonly ok: true; readonly value: T } | { readonly ok: false; readonly message: string }> => {
    // 已有在飞的不排队：用户点一次就够了，排队反而会在他改了主意之后偷偷执行。
    // ⚠️ 失败**不能**用 `string` 与成功值共用一个返回口——`startIteration` 的成功值本身就是
    // 字符串（工作副本路径），`typeof 结果 === "string"` 会把成功当失败。
    if (迭代中() !== undefined) return { ok: false, message: "上一条操作还没完成，请稍等" }
    set迭代中(assetId)
    try {
      const 结果 = await 跑()
      if (结果.kind !== "ok") {
        set错误(结果.message)
        return { ok: false, message: 结果.message }
      }
      set错误(undefined)
      return { ok: true, value: 成功(结果) }
    } catch {
      set错误("操作失败，请检查网络后重试")
      return { ok: false, message: "操作失败，请检查网络后重试" }
    } finally {
      set迭代中(undefined)
    }
  }

  const startIteration: AssetCatalog["startIteration"] = async (assetId, note, projectId) => {
    const 结果 = await 迭代调用(
      assetId,
      () => 内容Api.iteration(assetId, note, projectId),
      (值) => 值.value.workspace,
    )
    if (!结果.ok) return 结果
    return 结果.value === undefined ? { ok: true } : { ok: true, workspace: 结果.value }
  }

  const submitIteration: AssetCatalog["submitIteration"] = async (assetId) => {
    const 结果 = await 迭代调用(assetId, () => 内容Api.submitIteration(assetId), () => true)
    return 结果.ok ? true : 结果.message
  }

  const abortIteration: AssetCatalog["abortIteration"] = async (assetId) => {
    const 结果 = await 迭代调用(assetId, () => 内容Api.abortIteration(assetId), () => true)
    return 结果.ok ? true : 结果.message
  }
```

```tsx
 *
 * 弹窗放在这个组件内：它只属于这一处，提到外层只会让 `AssetDetail` 多三个状态。

function 版本面板(props: {
  readonly asset: AssetMetadata
  readonly 可写: boolean
  readonly onStart?: (note: string, projectId: string) => Promise<发起迭代结果>
  readonly onSubmit?: () => Promise<true | string>
  readonly onAbort?: () => Promise<true | string>
  readonly projects?: readonly { readonly id: string; readonly name: string }[]
  readonly currentProjectId?: string

  const [开弹窗, set开弹窗] = createSignal(false)
  const [说明, set说明] = createSignal("")
  const [项目, set项目] = createSignal<string | undefined>()
  /** 弹窗里的错误（发起失败）。关弹窗时清空。 */
  const [错误, set错误] = createSignal<string | undefined>()
  /**
   * 页面上（版本 Tab 里）的错误：提交 / 放弃失败、以及「发起成功但右栏没开会话」。
   *
   * 为什么不与 `错误` 共用一个信号：生命周期不同——关弹窗会把 `错误` 清掉，
   * 而「发起了但指令送不出去」这句话必须在弹窗关掉之后还留在页面上，
   * 否则用户以为一切正常，右栏其实一个字都没收到。
   */
  const [操作错误, set操作错误] = createSignal<string | undefined>()
  const [忙, set忙] = createSignal(false)

  const 上一次 = () => Math.max(1, props.asset.version - 1)
  const 迭代中 = () => props.asset.status === "iterating"

    set说明("")
    set错误(undefined)
    set项目(props.currentProjectId)
    set开弹窗(true)
  }

    if (忙()) return
    set开弹窗(false)
    set错误(undefined)

    const 发起 = props.onStart
    const 目标项目 = 项目()
    if (发起 === undefined || 目标项目 === undefined) return

    set错误(undefined)
```

#### 未提交怎么判

设计 §7 只说「治理台显示 `iteration_note`、未提交时禁用」。代码里治理台的列表是**直出 `listAssets()` 的行**（`governance-assets.ts` 的 `handleList` 把它们原样放进 `ok({assets})`），没有逐行加工的层。**按代码走**：在 `handleList` 里对 `iterating` 的行补 `iterationSubmitted`（一个 `Promise.all` 的文件判据），其余行补 `false`；`iterationNote` / `iterationWorkspace` 自动随 `AssetMetadata` 一起过去，不需要额外映射。
