## Clarifications

### Session 2026-11-17

- Q: 本次 014 的 MVP 交付边界切在哪一批？ → A: C —— 「批 1–6 + I3 最小骨架 + F5 数值收口」为 MVP；批 7 其余（面板密度精修、行尾回滚）、批 8（图例移出画布、圆角显式化、空态与演示提示）、批 9（HUD、字号、余项）为后续批次；规格不删除任何条目。
- Q: 若「从库加入事件」和「事件→事件」边所需的取数出口核查后并不具备，MVP 该怎么裁？ → A: 手写优先降级 —— MVP 交付事件格式、事件卡、两态面板、工具栏/右键两入口、「事件→参与方」角色边；第三页签「从库加入事件」与「事件→事件」边在取数出口核实后再做，不阻塞 MVP。
- Q: 深色主题下的品牌金这一项，本轮做还是不做？ → A: 只保证浅色 —— 修好「品牌金类无样式、选中态退回文字色」的浅色问题；深色 token 不动，记为缺口，待启用暗色模式时统一处理（宪法规定不启用暗色）。
- Q: MVP 算「完成」时，除了自动化用例和门禁，要不要把一条真栈手工主流程也算进去？ → A: 算 —— 完成判据 = 自动化用例变绿 + 三项门禁 + 一条真栈主流程（加手写事件→连参与方→存盘→重开→一次撤销）；跑不通不得宣称 MVP 完成。
- Q: 事件卡上的两行文字，具体各写什么？ → A: 第一行 `类型首字 · 金额`（无金额只显示类型首字），第二行按时间精度渲染的时间（日→`MM-DD`；时→`MM-DD HH时`；分/未标→`MM-DD HH:mm`），逐字可断言。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 画一张图，存得住、不丢、不重（Priority: P1）

民警在关系图里手动加节点、连线、删除、重试保存。现在的行为是：连点三次「加节点」界面上出现 7 个、盘上只有 4 个，拖一个其余一起塌到同一坐标；保存超时后重试，被提示「这份图在你打开之后被改过」；点过工具栏按钮后按 Delete 键没反应。本故事要求这些「以为发生了、其实没发生」的写入全部要么真的发生，要么当场说明为什么没发生。

**Why this priority**: 写路径是其余一切的前提。写不对的时候，任何后续验收（布局、事件、视觉）都测不出真实结果；数据被静默吞掉是民警无法察觉的取证级损失。

**Independent Test**: 在空白图上连续执行「加同名节点 ×2 → 连线 → 删除 → 模拟保存超时后重试」，逐条核对盘上文件内容与界面计数一致、撤销次数与动作次数一致、提示与实际结果一致。

**Acceptance Scenarios**:

1. **Given** 一张已有 4 个节点的图，**When** 同一批操作里加入两个同名同类型的手动节点，**Then** 返回的新增计数为 `2`，两个节点 id 互不相同，盘上节点数 = 6。
2. **Given** 手动新增节点，**When** 查看默认名称，**Then** 名称为递增的「新节点 1」「新节点 2」（不是三次都是「新节点」）。
3. **Given** 客户端与盘上版本不一致导致本地临时 id 被映射到同一个真实 id，**When** 写入返回映射，**Then** 立即重新载入整图并提示「图和你本地不一致，请重新载入」，不产生重复 id。
4. **Given** 一次写入已经被服务端落盘但客户端超时，**When** 用完全相同的载荷重试，**Then** 复用同一幂等键、静默采纳版本，界面不出现「被改过」；**When** 载荷变化后重试，**Then** 换用新幂等键，新改动不被旧结果覆盖。
5. **Given** 一个节点，**When** 连续粘贴两次，**Then** 得到两个 id 不同的节点。
6. **Given** 画布已选中一个节点、焦点在工具栏按钮上，**When** 按 Delete，**Then** 节点被删除，且本次删除只产生 1 个写入批次。
7. **Given** 焦点在检查器输入框，**When** 按 Delete，**Then** 只删除文字，不删除对象。
8. **Given** 演示模式，**When** 按 Delete，**Then** 仍然静默无副作用。

### User Story 2 - 画图的手感（Priority: P1）

民警用滚轮缩放、用空格或「手」拖动画布、从一个节点拖到另一个节点建立连线。现在纵向滚轮在精密触控板上不缩放；从圆心拖到目标的名字上松手什么都不发生、也没有任何提示；平移能力没有任何可发现的入口。

**Why this priority**: 这是「能不能画」的问题，与写路径并列在最前。手感坏掉时，民警不会认为「我不会用」，只会认为「这软件坏的」。

**Independent Test**: 逐个输入设备信号与拖拽路径触发，核对缩放比例、光标形态、连线是否建立与提示文案。

**Acceptance Scenarios**:

1. **Given** 画布打开，**When** 滚轮事件为 `deltaY: 3.75`（无横向分量），**Then** 缩放比例改变；**When** 事件为 `deltaX: 120, deltaY: 0`，**Then** 只平移、比例不变。
2. **Given** 按住空格，**When** 未拖动，**Then** 画布光标为 `grab`；**When** 拖动中，**Then** 为 `grabbing`；**When** 空白处悬停（未按空格、未选「手」），**Then** 保持默认光标。
3. **Given** 工具栏「选择」组选中「手」，**When** 用左键拖动画布，**Then** 画布平移且光标为 `grab`/`grabbing`。
4. **Given** 从某个节点的圆心开始拖动连线，**When** 在另一个节点的**名字标签**上松手，**Then** 连线建立（与在圆心松手等效）。
5. **Given** 拖动连线，**When** 在空白处松手，**Then** 不建立边，并显示「松手不在节点上，未建立连线」。
6. **Given** 已选中一个对象且它被检查器面板遮住，**When** 选中发生，**Then** 画布平移一次使该对象居中于未被面板覆盖的区域；之后拖动不会持续跟随。

### User Story 3 - 在图上表达「事件」（Priority: P2）

民警要把库里的资金/话单事件卡片搬上关系图，画成「谁 —(付款方)—▶ 转账 1.2 万 —(收款方)—▶ 谁」，也能手写图上没有来源的事件。现在图里只有实体、关系和文字三类对象，事件没有画布表达。

**Why this priority**: 事件是研判的主体（`01` 事实卡片），没有它就画不出「钱怎么走、谁在场」。但它依赖写路径与手感先稳定。

**Independent Test**: 分别通过「工具栏加事件」「画布右键加事件」「从库加入事件页签」三条入口建立事件，核对节点形状、九格字段落点、绑定/手写两态、参与方节点与角色边、一次撤销撤掉整批。

**Acceptance Scenarios**:

1. **Given** 库中存在一条带出处的事件（含付款方、收款方参与方），**When** 经「从库加入 → 事件」加入它，**Then** 图上出现 1 个事件节点（形状为事件卡）、已对上档案的参与方各 1 个节点（图上已有则复用）、每个参与方 1 条角色边（标签为角色名、性质为推断、依据为固定话术），**一次撤销**全部撤掉。
2. **Given** 该事件的某个参与方只有原文（未对上档案），**When** 加入事件，**Then** 不为它建节点，其原文写入保留属性「参与方·<角色>」，面板该行显示灰字「未对上档案」。
3. **Given** 一条没有出处的事件，**When** 尝试加入图上，**Then** 被拒绝并提示「这条事件没有出处，不能上图」。
4. **Given** 拖动建立一条「性质=推断」的边，**When** 未填依据或可信度，**Then** 无法提交；**When** 未填出处或证据就改成「事实」，**Then** 无法提交，且系统不代为填写依据。
5. **Given** 工具栏「加事件」，**When** 点击，**Then** 在视口中心落一个手写事件节点；**Given** 画布空白处右键，**Then** 菜单中出现「加事件」并在右键点落节点。
6. **Given** 选中一个手写事件，**When** 查看面板，**Then** 九格（干什么/何时/谁/和谁/何地/多少钱/其他/出处/可信度）可编辑，且没有可信态控件、徽标只能是「手写」。
7. **Given** 选中一个绑定事件，**When** 查看面板，**Then** 九格全部只读、只有备注与外环可改，且不提供「解绑」。
8. **Given** 事件节点的时间为空，**When** 尝试落盘，**Then** 拒绝保存；**Given** 名称为空但有类型、金额与时间，**Then** 名称兜底为「类型 · 金额|时长 · 时间」。

### User Story 4 - 让界面像产品，而不是开发者工具（Priority: P2）

民警打开关系图，希望一屏之内能同时看到画布、工具栏与筛选，图例不压在图上，检查器贴边且读得清，节点不是灰斑，选中态是品牌金。

**Why this priority**: 视觉与布局决定「愿不愿意用」，但不改变数据正确性，故排在功能之后。

**Independent Test**: 在固定窗口尺寸下量取工具栏、画布条、画布、检查器、图例的矩形与色值，并逐条与判据比对。

**Acceptance Scenarios**:

1. **Given** 编辑器打开，**When** 读取各控件矩形，**Then** 顶栏只含撤销/重做/已保存，工具栏为单行，搜索、筛选、计数与图例落在工具栏底边与画布顶边之间的画布条内；画布可见高度不低于同窗口改动前的实测值。
2. **Given** 画布，**When** 查找图例，**Then** 画布内部不存在图例；图例在画布条右端横排；画布条宽 <900 时折叠为「图例」按钮，点开为浮层。
3. **Given** 画布，**When** 点击画布左上角原「模式条」区域下方的节点中心，**Then** 该节点被选中，模式不变、文字数量不变。
4. **Given** 选中一个节点，**When** 读取其填充与描边，**Then** 填充为浅金 `#FEF3C7`、描边为 `#B45309` 2px，且仍能识别其类型色。
5. **Given** 打开检查器，**When** 读取其位置与尺寸，**Then** 宽 320px、右缘与上缘 0、高 100%；收起时只剩 40px 竖条，未选中时不渲染；按 `I` 展开、按 `Esc` 先取消选中再收起。
6. **Given** 工具栏，**When** 逐组查看，**Then** 四组图标单行放下（不出现横向滚动），模式按钮有按下态、动作按钮无，删除按钮为危险色，悬停 300ms 出现带快捷键的说明。
7. **Given** 开发态，**When** 未带 `?hud=1` 打开，**Then** 不渲染 HUD。

### User Story 5 - 排布、筛选、数值与首用引导（Priority: P3）

民警要把图排成环形/力导向/分层/网格，要按强度过滤弱关系，要能设外环档不越界，第一次打开空图要知道从哪开始。

**Why this priority**: 使用深度的提升项，依赖前面所有基础设施。

**Independent Test**: 逐个点击排列模式核对落点；设强度阈值核对隐藏与恢复；填越界档位核对提示与不落盘；空图与演示态核对引导文案。

**Acceptance Scenarios**:

1. **Given** 一张图，**When** 依次选择环形/力导向/分层/网格并确认自动布局，**Then** 每次落点与「按该模式计算出的目标位置」完全一致，且每次弹确认条、锁定节点不动。
2. **Given** 强度过滤设为「只看 ≥ 3 档」，**When** 图上存在 1–2 档的边，**Then** 这些边不渲染，角落提示「已隐藏 N 条较弱关系」，一键可恢复。
3. **Given** 选中节点，**When** 外环档填入 `12`，**Then** 就地提示「要填 0–4 的整数」且不写入文件；线宽档使用同一套校验与提示。
4. **Given** 选中节点，**When** 打开外环颜色，**Then** 只能从 7 个预设色 + 「自动」中选择；「自动」按节点类型上色。
5. **Given** 空图，**When** 打开，**Then** 正中提供「从库加入」「让 AI 起一张」两个入口与一行「数据都在你自己的项目文件里」。
6. **Given** 演示模式下所有节点出现序均为 0/未写，**When** 进入演示，**Then** 先提示「先在检查器里填出现序，演示才有步骤」。
7. **Given** 任意浮层（从库加入/筛选/新建事件），**When** 按 `Esc` 或点外部，**Then** 关闭；浮层层级高于画布右键菜单；筛选面板覆盖画布而不顶起画布。

### Edge Cases

- 同名节点在**同一批**与**不同批**分别加入时，前者必须全部保留（重名是允许的，去重只按 id）。
- 幂等重试时载荷「部分相同、部分不同」：按「逐字相同」判定，不同即换新键。
- 超时后盘上内容既非「已存 + 本批」也非旧版本：不静默采纳，按冲突提示。
- 连线终点落在节点外环、名字标签、边标签上：只有命中「带节点标识的元素」才算落点；预览连线本身不得成为命中目标。
- 删除键在 `input` / `textarea` / 可编辑区域、演示模式、多选状态下的行为各自固定，不得互相串味。
- 事件参与方在图上已存在但为不同对象（同名不同 id）：按库 id 复用，不做名字匹配。
- 绑定事件无出处、参与方未对上档案、事件时间为空：三种「不完整」各自 fail-closed，且提示可区分。
- 事件与事件之间的「先/同时/同一事件」关系：若取数出口不提供，则只能由用户手写，系统不臆造。
- 画布条窄于 900 时图例折叠；此时导出产物仍必须含图例。
- 浅色下品牌金不得退回文字色（类必须真的有样式）；深色主题不在本轮验收范围（宪法不启用暗色模式），但必须在缺口表登记。
- 圆角基值缺失导致的「圆角=0」不得靠补基值掩盖，必须显式声明。

## Requirements *(mandatory)*

### Functional Requirements

**写路径可靠性**

- **FR-001**: 手动新增节点 MUST NOT 被「同名复用」合并；同一批内两个同名同类型节点 MUST 全部新增，返回计数为 2 且 id 不同。
- **FR-002**: 「同名复用」MUST 是一个显式开关，默认关闭；只有 AI 生成式加节点这一条路径可以开启。
- **FR-003**: 手动新增节点的默认名称 MUST 递增（新节点 1、新节点 2…），不得固定为同一个名字。
- **FR-004**: 客户端换 id 后 MUST 按 id 去重；发现两个临时对象映射到同一 id 时 MUST 立即重载整图并提示「图和你本地不一致，请重新载入」，MUST NOT 产生重复 id。
- **FR-005**: AI 路径复用了图上已有节点时 MUST 给出一行可见提示。
- **FR-006**: 每次写入 MUST 携带幂等键；幂等键 MUST 由「图标识 + 递增序号」稳定生成；仅当重试载荷与上次失败载荷逐字相同才复用同键，载荷变化 MUST 换新键。
- **FR-007**: 收到超时或版本冲突时 MUST 先读一次盘；若盘上内容等于「已存文档 + 本批操作」，MUST 静默采纳版本且不报「被改过」。
- **FR-008**: 写入成功后 MUST 断言 id 唯一；不唯一即立即请求重载（幻影重复态自愈）。
- **FR-009**: 复制/粘贴、Alt+拖 MUST 与手动新增走同一判据；同一节点粘贴两次 MUST 得到 2 个不同 id。

**视图交互**

- **FR-010**: 纵向滚轮 MUST 一律缩放，包括小数 `deltaY`；仅当 `ctrlKey` 非真且横向位移绝对值大于纵向时才平移。
- **FR-011**: 按住空格时画布光标 MUST 为 `grab`，拖动中为 `grabbing`；空白悬停 MUST 保持默认光标。
- **FR-012**: 「选择」组 MUST 提供 指针 / 手 / 连线 三种模式；「手」模式下左键拖动即平移，光标为 `grab`/`grabbing`。
- **FR-013**: 连线按下与松手 MUST 使用同一套命中判据（含名字标签）；预览连线 MUST NOT 参与命中；落空 MUST 提示「松手不在节点上，未建立连线」。
- **FR-014**: Delete / F2 的键盘监听 MUST 挂在编辑器根容器并由其独家接管；画布内不得再单独监听同一按键；输入框/可编辑区域守卫 MUST 保留；一次按键 MUST 只产生一次写入。
- **FR-015**: 选中对象与检查器矩形相交时，画布 MUST 平移一次使其居中于剩余可视区，且 MUST NOT 持续跟随后续拖动。

**布局**

- **FR-016**: 「排列」MUST 提供环形 / 力导向 / 分层 / 网格四种模式（默认环形）并配一个自动布局按钮；结果 MUST 等于按所选模式计算的目标位置（不得另写一套算法）；每次 MUST 弹确认条；锁定节点 MUST 不动。

**事件对象**

- **FR-017**: 图的来源类别 MUST 新增「事件」一个取值；MUST NOT 为此新增其他键；事件节点 MUST 绑定库事件标识，缺该标识 MUST 判为结构不合法并拒绝写入。
- **FR-018**: 「事件」类来源 MUST NOT 冒用「实体」类来源；「已在图上」判定 MUST 继续只认「实体」类来源。
- **FR-019**: 事件节点 MUST 保留三个属性键：`金额`（数字+单位连写，单位必填）、`时间精度`（日/时/分）、`参与方·<角色>`（未对上档案的参与方原文）；其余属性一律归入「其他」。
- **FR-020**: 事件的九格 MUST 按固定落点映射：干什么→名称与类型；何时→首末时间与时间精度；谁/和谁/何地→参与方同表按角色区分并生成角色边；多少钱→金额；其他→其他属性；出处→出处列表；可信度→来源可信度与徽标；事件间关系→「先/同时/同一事件」边。
- **FR-021**: 手写事件（来源为手写）MUST 允许编辑九格；MUST NOT 提供可信态控件，徽标只能是「手写」。
- **FR-022**: 绑定事件（来源为事件）MUST 将其九格锁定为只读，只允许改备注与外环；MUST NOT 提供解绑入口。
- **FR-023**: 绑定事件上图时 `出处` MUST 非空；为空 MUST 拒绝并提示「这条事件没有出处，不能上图」。
- **FR-024**: 参与方未对上档案时 MUST NOT 建节点、MUST NOT 按姓名模糊匹配，其原文 MUST 落入保留属性键，面板 MUST 标注「未对上档案」。
- **FR-025**: 事件 MUST 有三个入口：工具栏「加事件」（落视口中心）、画布空白右键「加事件」（落右键点）、从库加入面板的「事件」页签；前两者 MUST 是同一个动作。
- **FR-026**: 从库加入事件 MUST 生成 1 个事件节点 + 每个已对上档案的参与方节点（图上已有则复用）+ 每个参与方 1 条角色边；整批 MUST 合成一个批次、一次可撤销。
- **FR-027**: 事件相关边 MUST 符合语义：事件→参与方为实线 1px + 箭头 + 角色标签；事件→事件为点线 + 箭头 + 「先/同时/同一事件」；实体→实体不变。推断边 MUST 具备非空依据与可信度；事实边 MUST 具备非空出处或证据；依据文案 MUST 使用固定话术（手写：`手写事件「<摘要>」的<角色>`；库：`库事件 <event_id> 的<角色>`）。

**筛选与强度**

- **FR-028**: 工具栏 MUST 提供「只看 ≥ N 档」的强度过滤；隐藏弱边时画布角落 MUST 明示「已隐藏 N 条较弱关系」并支持一键恢复。
- **FR-029**: 图例 MUST 保持纯说明，MUST NOT 变成筛选控件。
- **FR-030**: 不提供阈值的编辑界面；阈值只能通过文件修改（本版明确不做）。

**数值口径**

- **FR-031**: 线宽档与外环档 MUST 统一为「自动 / 0–4」；越界输入 MUST 就地提示「要填 0–4 的整数」且不写入文件；两处 MUST 使用同一实现点。
- **FR-032**: 外环颜色 MUST 改为预设下拉：7 个预设色 + 「自动」，MUST NOT 接受自由文本。
- **FR-033**: 外环「自动」MUST 按节点类型上色；连接多的节点 MUST 同时用粗环与角标数字（连接数）双通道表达。

**检查器内容**

- **FR-034**: 检查器 MUST 为四段结构：头段（形状色块 + 名称 + 类型·细类 + 来源徽标 + 可信态徽标 + 收起）、可改区、只读区（灰底 + 🔒 + 出处 chip，悬停说明「来自库快照，请在库中修改」）、操作脚（左主操作、右删除）。
- **FR-035**: 未绑库字段 MUST 为输入框并失焦即存（一条改动=一条撤销）；已绑库字段 MUST 为灰行 + 出处 chip；态 MUST 只在绑定/加入动作里切换，MUST NOT 在输入过程中自动切换。
- **FR-036**: 四类对象的可改字段、只读字段与操作脚 MUST 符合固定表：实体（改名称/类型/细类/外环档色/备注；只读来源/属性/出处/首末时间；操作 打开档案/只看邻居/删除）；事件·手写（改名称/类型/时间/参与方/金额/其他/备注/外环；出处空并明示；操作 看参与方/删除）；事件·绑定（只改备注/外环；其余只读；操作 看参与方/删除）；连接（改标签/性质/方向/线宽档/备注；只读依据/可信度/次数/金额/证据/出处；操作 跳到两端/删除）；文字（改内容/字号/加粗/颜色/对齐/宽度/出现序；操作 删除）。
- **FR-037**: 事件节点必填字段 MUST 保持：id/名称/类型/来源/x/y/时间；名称空时 MUST 兜底为「类型 · 金额|时长 · 时间」；时间未填 MUST 拒绝落盘。
- **FR-038**: 修改边「性质」时 MUST 走闸：改「推断」须就地填依据 + 可信度；改「事实」须出处或证据非空；系统 MUST NOT 代填依据。
- **FR-039**: 刚改过的字段 MUST 在行尾提供 `↩ 撤销此字段`（仅当它仍是本会话最近一次写入）；该入口 MUST 复用全局撤销栈（Ctrl+Z 同一条），MUST NOT 另造历史；一次撤销 MUST 等于一次写盘。

**首用与浮层**

- **FR-040**: 空图 MUST 在正中提供「从库加入」「让 AI 起一张」两个入口与一行「数据都在你自己的项目文件里」。
- **FR-041**: 演示模式下若全部节点出现序为 0/未写，MUST 先提示「先在检查器里填出现序，演示才有步骤」。
- **FR-042**: 所有浮层（从库加入/筛选/新建事件）MUST 支持 `Esc` 关闭与点外部关闭；层级 MUST 高于画布右键菜单；筛选面板 MUST 覆盖画布而非顶起画布。

**界面**

- **FR-043**: 编辑器 MUST 为三行结构：顶栏只留撤销/重做/已保存（34px）；工具栏单行（约 32px）；新增画布条（约 30px）承载搜索 + 筛选（放大镜图标）+ 节点·边·文字计数 + 图例；标题行 MUST 删除。
- **FR-044**: 搜索/筛选/计数 MUST 落在工具栏底边与画布顶边之间；画布可见高度 MUST 不低于同窗口改动前的实测值（不写死两处冲突读数中的任何一个）。
- **FR-045**: 工具栏 MUST 为四组图标（选择：指针/手/连线；画：加节点/加事件/加文字/从库加入/删除/锁定；排：对齐/等距/排列下拉+自动布局；找：隔离/查找路径/强度过滤；整：合并/导出/演示/适配全部/路径标注），复刻既有图标、单行不折行；模式按钮 MUST 有按下态（品牌金边框 + 浅金底），动作按钮 MUST 无按下态；删除 MUST 用危险色；悬停 300ms MUST 出带快捷键的说明。
- **FR-046**: 「加事件」按钮 MUST 紧接「从库加入」之后，同属「画」组。
- **FR-047**: 画布内 153×26 透明模式条 MUST 删除；其下方节点的中心点击 MUST 命中该节点（模式不变、文字数不变）。
- **FR-048**: 检查器 MUST 为 320px 宽、右缘与上缘 0、高 100%；尺寸常量 MUST 与邻域图共用同一定义，不得复制第二份。
- **FR-049**: 检查器形态 MUST 为白卡（层 2 底色）+ 圆角 12 + 柔和阴影 + 1px 描边；每行 MUST 有标签；输入框高 ≥28、行距 ≥6；只读区 MUST 与可改区形状不同；内容溢出时面板内滚动，头段与操作脚固定。
- **FR-050**: 检查器收起态 MUST 为 40px 竖条「详情」+ 类型色点；点窄条或按 `I` 展开；未选中 MUST 不渲染；`Esc` MUST 先取消选中再收起。
- **FR-051**: 画布 MUST 有 1px 描边 + 圆角 8 + 与外围不同的底色阶。
- **FR-052**: 未选中节点 MUST 为类型色浅底 + 类型色 1.5px 描边，与画布底色可辨（不得呈灰斑）。
- **FR-053**: 选中节点 MUST 为浅金底 `#FEF3C7` + `#B45309` 2px 描边，并保留类型色可识别。
- **FR-054**: 边标签 MUST 为 12px + 2px 同底 halo。
- **FR-055**: 圆内 MUST 保持类型首字，MUST NOT 加类型图标；细类 MUST 只在面板出现。
- **FR-056**: 事件 MUST 渲染为圆角小卡 96×34、rx=6、两行内容，并使用独立的事件形状标识；MUST 忽略节点的样式形状设置。两行内容固定为：**第一行 `类型首字 · 金额`**（金额取保留属性「金额」，缺失时只显示类型首字）；**第二行 `时间`**，按时间精度渲染——精度「日」显示 `MM-DD`，精度「时」显示 `MM-DD HH时`，精度「分」或未标注显示 `MM-DD HH:mm`（如 `转 · 12,000` / `03-04 14:22`）。
- **FR-057**: 编辑态图例 MUST 移出画布，位于画布条右端横排（12px、间距 12）；画布条宽 <900 MUST 折叠为「图例」按钮，点开为浮层；画布内 MUST NOT 渲染任何图例；导出 MUST 仍含图例；折叠按钮热区 ≥32×24（触控环境 44×44）。
- **FR-058**: 开发态 HUD MUST 默认不渲染，仅 `?hud=1` 时显示，且与「已保存」分行。
- **FR-059**: 品牌金 MUST 在**浅色**主题下可用（不得出现类无样式、选中态退回文字色）；圆角 MUST 显式声明（不得依赖未生成的基值）；MUST NOT 手改自动生成的色表。**深色主题不在本轮范围**：深色下的品牌金（及其变蓝的强调色/描边）记为缺口，待启用暗色模式时统一处理（宪法规定不启用暗色模式）。
- **FR-060**: 画布标签字号 MUST 为 12px；面板与工具栏 MUST 保持 12–13px（不追 14px 正文口径）。

### 测试先行纪律（TDD，强制）

> 用户要求「spec 的生成，要严格遵循 TDD 规范」；以下条款与功能需求同等效力，任务分解与实施必须按其执行。

- **TR-001**: 每一条 FR MUST 先有一条**会红的**自动化用例钉住它；交红时必须给出该用例的**实得值**（实际计数、实际 id、实际光标、实际矩形），禁止只写「失败」。
- **TR-002**: 每条 FR 完成后 MUST 做**变异验证**：把修复对应的一处拆掉，该用例 MUST 变红；必须记录「拆哪一处 → 红哪几条」。
- **TR-003**: 用例 MUST 断言可观测值，禁止断言实现细节；禁止以「默认值恰好满足」「子串匹配」「哑断言」方式制造假绿；DOM 存不存在一律用布尔比较。
- **TR-004**: 任务 MUST 按可独立验收的最小切片拆分；一个切片 MUST 单独提交，提交信息 MUST 写明本切片覆盖的条目号。
- **TR-005**: 每个切片收尾 MUST 跑受影响模块的类型检查、单元测试与静态检查（在仓库根执行），三者全部通过才算完成。**MVP 收尾另加一条真栈主流程**：「加手写事件 → 连参与方 → 存盘 → 重开 → 一次撤销」MUST 跑通并记录实际结果；跑不通 MUST NOT 宣称 MVP 完成。
- **TR-006**: 测不了的（真设备滚轮信号、真实触控板、真 PG、真模型、窄屏实测）MUST 如实写进缺口表；MUST NOT 写成「已覆盖」。

### Key Entities

- **关系图文档**：一份 `.hgraph` 文件，含标题、时间戳、设置、节点、边、文字三类对象集合；本规格只新增「来源类别 = 事件」这一个取值，其余结构不变。
- **对象**：节点（实体 / 事件）、边（连接）、文字。形状由对象类别决定：圆=实体、圆角小卡=事件、线=连接、方框=文字。
- **事件节点**：绑定库事件或手写产生；携带九格信息、参与方（含角色与是否对上档案）、金额、时间精度、出处、可信度。
- **参与方**：事件与实体/人名之间的关系承载者；一条参与方对应图上一条带角色标签的推断边；未对上档案时不产生对象。
- **检查器**：对象属性的唯一编辑面板，按「未绑库/已绑库」两态呈现同一槽位。
- **幂等键**：一次写入的唯一标识，用于超时重试时避免「被改过」误报。
- **布局模式**：环形 / 力导向 / 分层 / 网格，作为自动布局的输入。
- **强度阈值与外环阈值**：决定线宽档与外环档的换算口径，仅由文件配置，不在界面提供编辑。

## Success Criteria *(mandatory)*

- **SC-008**: 事件节点缺时间、绑定事件缺出处、参与方未对上档案三种情况，拒绝/降级行为 3/3 符合预期且提示可区分。

- **SC-012**: 画布条四项（搜索/筛选/计数/图例）矩形全部落在工具栏底边与画布顶边之间；画布可见高度不低于改动前同窗口实测值；图例在画布内的节点数为 0。

- **SC-017**: 所有无法在本机验证的项在缺口表中有明确记录（条数 = 实际未验项数），交付说明中「已覆盖」项与用例一一对应。
- **SC-018**: MVP 完成时，真栈主流程「加手写事件 → 连参与方 → 存盘 → 重开 → 一次撤销」5 步全部通过（5/5），且每步的实际结果被记录；任一步失败即 MVP 未完成。

- **格式兼容**：新增「事件」来源类别后，旧图文件（不含事件）MUST 继续可读；不要求旧版本客户端能读新文件。
- **单用户桌面浏览器**：目标环境为公安内网桌面浏览器、中文界面；不涉及移动端、不涉及多人实时协同。
- **视觉值来源**：颜色/圆角/字号以项目既有设计系统为唯一来源，规格中的具体数值取自设计文档，实施时不得自创。
- **画布高度基线**：设计文档中两处读数冲突，以「同窗口改动前的实测值」为准，不在规格中写死。
- **面板共享**：检查器尺寸常量与邻域图共用，修改会同时影响邻域图；本规格接受该连带影响，不额外修改邻域图行为。
- **测不了的东西**：真实触控板信号、真机 `deltaY`、200% 缩放 LOD、A3 300DPI 出图、窄屏 1280/1440 观感等，按缺口表处理，不作为本规格的完成前提。
