# Research：复用裁定与备选（Phase 0）

> 用户指令：**优先复用源码已有能力；已支持的功能只做适配，不新建。**
> 每条 = 决策 / 理由 / 被否的备选。行号来自实测或设计文档 `11`（该文档的证据章节逐条附 `file:line`）。

## R1 同名复用开关

- **决策**：`应用操作(文档, 操作)` 增可选入参 `同名复用?: boolean`，缺省 `false`；仅 AI 工具 `graph_add` 传 `true`。
- **理由**：复用判据本体已实现（`hgraph-edit.ts:409-419`「R7 署名复用」），错的只是「谁都能触发」。
- **备选**：客户端预检重名（同一前提两处判，`#002-06`）；另建手动加节点函数（重复实现坐标/属性语义）。

## R2 幂等键

- **决策**：客户端生成 `web:<路径>:<实例段>:<序号>`（实例段 = 时间戳36进制-实例计数-随机8位，每编辑器实例一次），同载荷同键、异载荷换键；服务端零改动。**实现期修正**：只要序号、不要实例段时，刷新后新实例会用同一个 `…:1` 命中旧键——服务端只按键查表不校验载荷（`hgraph-ops.ts`），于是不同载荷被重放（US1 评审 C1）。
- **理由**：客户端 API 已留参数位（`project/hgraph-api.ts:106` 声明、`:159` 透传，但 `hgraph/*` 里**现在一次都没传**），服务端幂等索引排在 CAS 之前（`hgraph-ops.ts:513-519`），窗口为进程内 10 分钟、按「人＋项目＋归一路径＋键」隔离（`:347-371`），重放能力已有用例（`test/server/case-hgraph-ops.test.ts:424`）。`写结果.重放` 已回，客户端尚未消费（`hgraph-api.ts:85-88`）。
- **`批次` 不能当幂等键**：`批次 = 批-${++批次序号}` 每次 `发送` 自增（`editor.tsx:854`），而重试就是新的一次 `发送` ⇒ 键必变，重放永不命中。
- **备选**：服务端按操作指纹去重（改契约、与 AI 工具语义冲突）；时间戳作键（重试不复用）。

## R3 幻影重复态

- **决策**：写入成功分支断言 id 唯一，不唯一即请求重载。
- **理由**：重复来自一次 200 成功应答，轮询按版本比较永远察觉不到（`editor.tsx:1077`）。
- **备选**：轮询改为内容全量比较（代价高）。

## R4 滚轮与平移

- **决策**：`是双指平移 = ctrlKey !== true && |deltaX| > |deltaY|`；空格加 `grab` 光标；模式组加「手」。
- **理由**：现有判据 `deltaY % 1 !== 0` 把精密触控板当双指（`canvas.tsx:83`）；空格状态已存在（`:349`）。
- **备选**：加「滚轮行为」设置（YAGNI）；重写指针状态机（现有链路已覆盖拖动/框选）。

## R5 连线命中

- **决策**：松手用与按下同一套 DOM 命中（`elementFromPoint` + `closest("[data-node-id]")`），数学判据降为兜底；预览线 `pointer-events:none`；落空提示。
- **理由**：按下认标签、松手只认圆心 15px（`canvas.tsx:577` vs `geometry.ts:104-117`），不对称造成「拖到名字上松手没反应」。
- **备选**：把数学半径放大到覆盖标签（标签位置随布局变，仍会漏）。

## R6 删除键作用域

- **决策**：监听上移到编辑器根容器、独家接管；画布内删掉同一监听；输入守卫与演示静默原样搬。
- **理由**：三个删除入口已收敛到同一翻译点（`editor.tsx:1602-1615`），差的只是焦点（点在工具栏后按键到不了画布）。
- **备选**：按钮 `preventDefault`（治标）；全局热键（违反基线 §11-12）。

## R7 布局入口

- **决策**：「排列」下拉 + 自动布局，复用 `排列模式` / `布局目标`；确认条与锁定不变。
- **理由**：四种算法都在（`graph-layout.ts:81/83`、`:211-219`），邻域图已有四个按钮（`graph.tsx:891-909`）；**hgraph 侧模式参数已全通**——`自动布局: (模式) => {set布局模式(模式); set待确认布局(true)}`（`editor.tsx:1631-1634`）→ `布局目标(文档(), 布局模式())`（`:1376`），只差工具栏没往下传（`toolbar.tsx:153`）。
- **备选**：四个独立按钮（宽不够）；右键菜单（不可发现）。

## R8 事件来源类别

- **决策**：`来源.kind` 加 `"事件"`，复用 `来源.实体` 槽位存事件 id。
- **理由**：格式面最小（spec 全局原则「最小契约面」）；面板两态与「已在图上」判定都按 `kind` 分。
- **备选**：新增对象集合（格式面翻倍）；冒用 `实体`（id 语义冲突）。

## R9 参与方与角色

- **决策**：读既有 `case_event_participant`（`role` 已是落点），角色词表复用 `case-card-template.ts:34`；事件详情只回名字数组，就在**同一读出口**补结构化 `role`（加法），展示口径沿用既有的 `role：value` 拼法。
- **理由**：`case-fact-read.ts:73-88` 已有事件详情、`:220-239` 已含排除规则；`case-mcp-tools.ts:960-995` 已把 `role` 从 `case_event_participant` 读出来并按 `ordinal` 排序 ⇒ 数据与排序语义都有现成出处；新建出口要重写权限与排除。
- **备选**：前端按名字匹配（`01` §3.8.3 明确不做）；新 endpoint（权限/排除重写）。

## R10 事件间关系

- **决策**：只手写「先/同时/同一事件」，不从库取。
- **理由**：仓库中无事件关系表/读取代码（grep 仅命中无关文本）；spec MVP-2 已裁定降级。
- **备选**：新建关系表（超范围）。

## R11 强度过滤

- **决策**：复用既有线宽档表与「可见集合」过滤入口（演示态已有同型），加 N 阈值与角落提示；图例保持纯说明。

## R12 数值收口

- **决策**：外环档复用线宽档的校验与提示模板；外环颜色改下拉，选项复用画布的 7 色表。
- **理由**：线宽档样板正确且完整——清空删键、非有限 / 非整数 / 越界都就地提示「要填 0–4 的整数」（`inspector.tsx:340-357`）；外环缺同一道闸，只判 `Number.isFinite`（`inspector.tsx:214-221`），颜色还是自由文本（`:224-228`）；色名 → 槽位映射在 `canvas.tsx:523-531`，档位纯函数与上限 4 在 `geometry.ts:505-517`。
- **备选**：另建色表（`#002-06`）；自由文本兜底（静默失效）。

## R13 检查器常量与骨架

- **决策**：`面板宽/面板边距` 由 `graph.tsx:26-27` 升级为 320/0，hgraph 继续 import；四段骨架在既有容器内重排。

- **连带（实测）**：`graph.tsx:1326`、`:1411` 面板 class `w-[280px]`；`inspector.tsx:451` class 里的 `w-[280px]`（已被 `style` 覆盖，仍是死值）；`graph.tsx:1302` 缩放条 `right: "292px"`；三条既有用例的 304 / `w-[280px]` / 292 口径。

## R14 视觉 token

- **决策**：只修一处无样式的品牌金类（`canvas.tsx:1011` → `border-v2-border-border-focus`）；裸 `rounded` 实测 15 处改显式（实施前再 grep 一次）；**不动** `packages/ui` 的 `colors.txt`/`tailwind.ts`/`theme.css`。

## R15 类型色

- **决策**：复用邻域图的类型→色映射（`形状` `:46` 已导出；`填充` `:53`、`描边` `:65`、`描边色` `:76`、`边颜色` `:81` 需加 `export`），按类型字符串调用；入参收窄成结构型 `{type; subtype?}` 让两边节点都能传。

## R16 工具栏与图标

- **决策**：复用既有 v2 图标组件 `@opencode-ai/ui/v2/icon`；缺的图形**追加键**到同一张 `icons` 表，注释写「openhive 定制 · 【同步上游时保留】」。
- **理由**：① 同一页已有先例——`case-views/card-template-editor.tsx:5` 就用 `@opencode-ai/ui/v2/icon`（`xmark-small`）；② `name` 类型是 `keyof typeof icons | (string & {})`（`icon.tsx:194`），追加键不必改类型；③ 现成图形覆盖住大半（`plus`/`folder-add-left`/`chevron-down`/`grid-plus`/`reset`/`outline-sliders`/`magnifying-glass`/`expand`/`outline-share`）；④ 2026-10-29 提交 `e5b4745882` 已按同样方式加过 `star`/`star-filled`，并写明保留约定。
- **缺的图形**：指针、手、连线、加文字、删除、锁定、对齐、等距、隔离、查找路径、合并、演示、路径标注（约 13 个）。
- **`graph-icons.tsx` 不能当工具栏图标源**：全文件只有 12 个**节点类型**图标（人/手机/证件/卡/账户…），文件头写明「不进 `packages/ui/src/components/icon.tsx`」，用途是画在节点圆心。
- **备选**：旧版 `@opencode-ai/ui/icon`（97 个图形，`selector`/`link`/`trash`/`eye`/`dot-grid` 齐全）→ 同页两套图标系统、视口与笔画不一致；`hgraph/toolbar-icons.tsx` 内联 SVG → 第二套系统；第三方图标库 → 新依赖 + 视觉不一致。

- **决策**：前端统一用 `test:components` 那套参数跑（`--conditions=browser --preload ./happydom.ts --preload ./solid-jsx.ts`）；后端沿用 `test/server/case-hgraph-*` 夹具；每个 FR 先红后绿 + 变异验证。

## 两个工程事实（已核实 2026-11-17，不再是待办）

1. **事件详情不带角色**：`case-fact-read.ts:81` 的 `事件详情.participants: readonly string[]` 只有名字，`:220/:239` 也只做排除过滤。**但角色数据在库里**：`case_event_participant.role` 已被 `case-mcp-tools.ts:974` 读出，并拼成 `role：value` 的展示串（`:984`）；写入端在 `case-fact-store.ts:392`，词表在 `case-card-template.ts:34`。⇒ R8 的「同一读出口补结构化 `role`」可行且是加法；面板里「角色 + 名字」的展示口径可直接沿用 `role：value` 的既有约定。
2. **事件取数出口「不具备」要更精确地说**：仓库**已有** `query_events`（`case-mcp-tools.ts:1011`）与它的界面出口 `/openhive/timeline`（`case-ui-routes.ts:334-360`，按参与实体 + 时间窗，`含未验证: true`）。缺的只有两件：① 时间线路由**强制要求实体 id**（`id 不能为空` + `取规范值` 404），没有**项目级**事件列表；② 前端没有对应的客户端 API。⇒ spec 澄清 2 的「手写优先降级」结论不变（MVP 不做第三页签），但**后续批次不需要新建取数层**：给 `query_events` 加一条可选参数的 HTTP 路由即可，不复制 SQL、不重写权限与排除规则。

> 两项的缺口都写进 spec 的缺口表（TR-006），不伪装成已覆盖。
