## User Scenarios & Testing

### User Story 1 - 资产浏览（左栏导航 + 中栏搜索/卡片/详情）（Priority: P1）

「AI 资产」工作区复用三栏：左栏纯导航（空间筛选 + Skill/MCP/知识库三 Tab + 业务分类折叠，分类节点不列资产）；中栏浏览（全局搜索框 + 卡片网格 + 详情 tab：介绍/注意事项/评价/版本）。左栏永不产生长滚动条。

**Why this priority**: 资产浏览是民警「用」资产的入口，左栏纯导航 + 中栏浏览避免海量资产塞进窄左栏。

**Independent Test**: 进入 AI 资产工作区，按分类浏览、全局搜索、点卡片看详情，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 民警点图标栏「AI 资产」，**When** 进入，**Then** 左栏显示空间筛选 + 三 Tab + 业务分类折叠（分类名 + 数量角标，节点下不列资产）
2. **Given** 民警在中栏全局搜索框输入关键词，**When** 搜索，**Then** 跨分类/跨类型列出命中项（带业务分类标签 + 类型标签）
3. **Given** 民警点某资产卡片，**When** 进入详情，**Then** 头部固定（名称 + 收藏 + 评分 + 作者 + 「▶ 执行此 skill」）+ tab 栏（介绍/注意事项/评价/版本）

---

### User Story 2 - 资产生命周期（7 状态机 + 审核两道关）（Priority: P1）

Skill 走完整 7 状态机（草稿 → 审核中 → 已发布 → 迭代中 → 已下线 → 已归档）；审核两道关分离——业务专家审「内容正确 + 可泛化性」、IT 审「技术合规」。MCP / 知识库生命周期简化。

**Why this priority**: 生命周期是「个人提效 → 组织增智」的治理核心——只有经过「可泛化性」审核的 skill 才谈得上全单位复用。

**Independent Test**: 一个 skill 从草稿提交审核 → 业务通过 → 技术发布 → 上线，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 作者提交 skill 审核，**When** 提交，**Then** 进入「审核中」，站内信通知业务管理员
2. **Given** 业务管理员审核，**When** 通过（审正确性 + 可泛化性），**Then** 进入待技术发布，通知作者 + 系统管理员
3. **Given** 审核被驳回，**When** 驳回，**Then** 退回草稿，作者收到驳回理由
4. **Given** 已发布 skill 发起迭代，**When** 迭代，**Then** 旧版继续可用 + 新版本在途（版本号 +1），新版本发布后替换旧版

---

### User Story 3 - 权限管理（三级空间 + 授权组 + 四类权限）（Priority: P1）

四类权限（读/写/审/管）、三级空间（全局/部门/个人）、授权组（跨部门定向授权，RBAC 自定义 role）。授权（RBAC 读权限）与收藏（个人偏好）彻底分离，弃用「启用」。

**Why this priority**: 资产权限是「谁能看/用什么资产」的安全边界，授权与收藏分离避免「启用」的语义混淆。

**Independent Test**: 授权某资产给部门/授权组、收藏某资产，两者独立生效，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 管理员把资产授权给某部门，**When** 授权，**Then** 该部门用户可读/用，其他部门不可见
2. **Given** 某资产授权给跨部门「授权组」，**When** 组内用户访问，**Then** 可见/可用（三级空间 ∪ 授权组）
3. **Given** 民警收藏某资产，**When** 收藏，**Then** 收藏只影响右栏抽屉排序，不改变授权（无权资产仍不可见）

---

### User Story 4 - Skill 制作（自然语言主路径）（Priority: P1）

Skill 制作主路径 = 自然语言编写 + 测试迭代：人形成思路 → 大白话输送给 AI「请帮我生成一个 skill」→ 测试迭代 → 提交审核。入口 = 与右栏 AI 对话，无需专门入口。

**Why this priority**: 领域专家不会编程，制作门槛低是「领域经验沉淀为 skill」的前提，是组织增智的关键动作。

**Independent Test**: 作者在右栏对话「帮我生成一个 skill」→ 产物落沙箱 → 测试，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 作者在右栏 AI 对话，**When** 说「请帮我生成一个 skill」，**Then** AI 生成 skill 落盘到作者沙箱，无需专门入口
2. **Given** 作者测试生成的 skill，**When** 发现问题，**Then** 修正迭代（草稿在沙箱正常试用，无特殊 UI）

---

### User Story 5 - MCP 授权差异 + 数据隔离四环（Priority: P2）

MCP 是「连接」，授权比 skill 多两层：下发（连到哪、怎么连）、身份（以谁的身份连 + 服务端 RLS）。数据隔离四环：授权 → 下发 → 连接带身份 → 服务端 RLS 过滤。

**Why this priority**: MCP 真连数据库取数据，连接身份是数据隔离的最后一环（F4 capability 第三层「MCP 账号兜底」的落点），但相对 skill 治理非首屏必需。

**Independent Test**: 用户查某 MCP，带身份连接 + 服务端 RLS 过滤，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户有权用某 MCP，**When** 连接，**Then** 按用户拼好连接配置（下发）+ 带用户身份连接
2. **Given** 用户查询，**When** 服务端收到带身份请求，**Then** RLS 过滤，只返回有权数据

---

### User Story 6 - 收藏 + 下指令给 AI（Priority: P2）

收藏作为右栏「更多 skill 抽屉」的排序加权（高频在前、收藏低频排后）；详情页「▶ 让 AI 助手执行此 skill」把一句指令填入右栏输入框。

**Why this priority**: 收藏加权与下指令把资产「发现 → 使用」链路打通，但非上线阻断项。

**Independent Test**: 收藏资产后抽屉排序变化、点「▶」填入指令，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 民警收藏某 skill，**When** 打开右栏「更多 skill」抽屉，**Then** 收藏的 skill 排序加权（低频排后）
2. **Given** 民警在详情页点「▶ 让 AI 助手执行此 skill」，**When** 点击，**Then** 一句指令填入右栏输入框（skill 名 + 当前上下文），可编辑发送

---

### Edge Cases

- AI 资产工作区的右栏不做指令卡投影切换（AI 资产本身不是业务分析模块）。
- 发布不广播给全体（新 skill 让民警在资产工作区主动发现）。
- 资产「权威性」是挣来的——发布后发现误导要能快速下线、标记、迭代。
- 个人资产升级为全局/部门资产时，不动作者沙箱原始文件（发布是复制）。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 将 Skill / MCP / 知识库统一抽象为「资产」，用一套元数据（名称/ID/类型/描述/图标/标签/所有者/部门/可见范围/版本/状态/收藏数/使用次数/评分/反馈）、一套权限、一套生命周期治理。
- **FR-002**: 左栏 MUST 纯导航——空间筛选 + 三 Tab（Skill/MCP/知识库）+ 业务分类折叠，分类节点不列资产、永不产生长滚动条。
- **FR-003**: 中栏 MUST 提供全局搜索框 + 卡片网格 + 详情 tab（介绍/注意事项/评价/版本），「注意事项」必须是显式的不确定性标注。
- **FR-004**: Skill MUST 走完整 7 状态机（草稿 → 审核中 → 已发布 → 迭代中 → 已下线 → 已归档）；MCP / 知识库生命周期简化（仅技术审核/授权）。
- **FR-005**: 审核 MUST 两道关分离——业务管理员审「内容正确 + 可泛化性」，系统管理员审「技术合规」。
- **FR-006**: 权限 MUST 分四类动作（读/写/审/管）+ 三级空间（全局/部门/个人）+ 授权组（跨部门定向授权，复用 RBAC）。
- **FR-007**: 授权（RBAC 读权限）与收藏（个人偏好）MUST 分离，弃用「启用」；收藏只影响右栏抽屉排序。
- **FR-008**: Skill 制作 MUST 以自然语言编写 + 测试迭代为主路径，入口 = 右栏 AI 对话，无需专门入口。
- **FR-009**: MCP 授权 MUST 走三层（授权 / 下发 / 身份）+ 数据隔离四环（授权 → 下发 → 连接带身份 → 服务端 RLS）。
- **FR-010**: 详情页 MUST 提供「▶ 让 AI 助手执行此 skill」，把一句指令填入右栏输入框。

### Key Entities

- **资产（Skill / MCP / 知识库）**：统一元数据 + 状态 + 可见范围 + 收藏数/使用次数/评分。
- **资产状态机**：草稿 / 审核中 / 已发布 / 迭代中 / 已下线 / 已归档。
- **授权组**：RBAC 自定义 role（role_type='group'），跨部门定向授权。

---

## Success Criteria

### Measurable Outcomes

- **SC-001**: 民警能浏览 / 搜索 / 收藏 / 调用资产，左栏永不产生长滚动条。
- **SC-002**: 资产生命周期状态流转正确，审核两道关（业务 / 技术）分离。
- **SC-003**: 授权与收藏分离，无权资产不可见 / 不可用。
- **SC-004**: Skill 制作门槛低——领域专家用自然语言即可生成 skill。

---

## Assumptions

- 资产物理存放约定（`/assets/pending` / `global` / `dept` / `archive` + 作者沙箱）由资产服务维护，提交审核/发布用资产治理 MCP 工具驱动（技术选型留 plan）。
- 复用 F4 的 RBAC 三张表（role / user_role / role_resource），授权组不新造权限体系。
- 复用 F8 的指令卡机制——收藏加权影响「更多 skill」抽屉排序。
- 知识库建库粒度已确定为「按主题一个库」（法条库 / 办案规范库 / 历史案例库等），本 feature 引用此决策，知识库管理在 F10 治理后台。
- 具体技术（RAGFlow、资产服务、进程内缓存等）留 plan。
