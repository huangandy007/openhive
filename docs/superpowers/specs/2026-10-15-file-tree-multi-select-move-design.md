# 左栏文件树「多选 → 拖拽批量移动」设计

- **日期**：2026-10-15
- **分支**：`multi-tenant`
- **性质**：本仓定制（openhive），提交信息须标注「这是要保留的定制」
- **上游约束**：改动落在 fork 自己的文件里（`packages/app/src/project/**`、`packages/app/src/workspace/**`），**不碰** `packages/ui` 与 `packages/session-ui` 的上游源码

---

## 1. 背景与目标

民警在左栏「文件」Tab 里整理项目文件。今天移一个文件要三步：**右键 → 点「移动」→ 在目标选择器里点目标文件夹**。用户原话：「要移动的文件多时体验感就急剧下降」。选十个文件就是三十步。

一句话目标：**在文件树里选中一批条目，拖到目标文件夹上松手，即把它们都移过去；有没移成的，用弹窗说清哪个没成、为什么。**

## 2. 范围

### v1 做

- **选中集**：单击（单选，今日行为不变）／`Ctrl`（⌘）加选与取消／`Shift` 从锚点连选（范围＝**当前可见行**）／点空白清空
- **拖**：从已选中的行起拖 ⇒ 整批；从未选中的行起拖 ⇒ 只那一行（并当场把它变成唯一选中）
- **落点**：文件夹行 ⇒ 它自己；文件行 ⇒ 它的父目录；行之间的空白 ⇒ 项目根（复用今日右键与拖入共用的那个 `落点()`）
- **非法落点不接管**：源自己 / 源的子孙 / 源现在就在的那个目录 ⇒ 不 `preventDefault`（浏览器给禁止光标）、**一个请求都不发**
- **批量执行**：逐个发（服务端一次只收一个），各自记账
- **全部成功** ⇒ 静默 ＋ 重取清单
- **有任何失败** ⇒ **报告弹窗**：列出没成的（路径 ＋ 原因）与成了的（路径），已成功的不回滚
- **右键「移动」/「复制」的失败也收进同一个弹窗**（用户 2026-10-15 裁定）
- 拖拽悬停时高亮当前落点

### v1 不做

- 撤销 / 跨项目移动 / 键盘多选（`Ctrl+Space`、`Shift+↑↓`）/ `Esc` 清空选中集 / 拖到树外 / MinIO 那棵下树
- **工具栏按选中集批量操作**：工具栏的改名 / 删除仍只作用**焦点行**（今日语义，不放大）
- **新建 / 重命名 / 删除 / 上传 / 下载 五条的失败报告口**：**新建 / 重命名 / 删除**三条已由 2026-10-16 那轮结清（见 `2026-10-16-file-op-failure-in-place-design.md`）；**上传 / 下载**两条仍在射程外（仍走内联 `file-op-message`）
- 触摸设备（平板没有拖拽手势）——民警用桌面浏览器
- 拖拽中的进度反馈（行上转圈之类）

## 3. 总架构

四层，都落在 fork 自己的文件里：

1. **选中集**（`file-tree.tsx` 内）—— 与既有的 `selected` / `expanded` 同级的三只组件内信号：`选中集: ReadonlySet<string>`、`锚点: string | undefined`。**不引入 Provider、不加任何挂载前提**（`LEARNINGS #005-27`）。
2. **落点判据**（`file-tree-model.ts` 纯函数）—— `能落到(源们, 目标目录): boolean`。可单测，不进组件。
3. **一条出口 prop**（`FileTreeProps` 新增 `onMoveTo?(路径们, 目录)`）—— 树只知道「有一批东西要落到某目录」，不知道请求怎么发、结果怎么报。
4. **接线层的一批一次**（`workspace-entry.tsx`）—— `搬一批(dir, 路径们, mode)`：**右键那条老路与拖拽那条新路共用这一份实现**；结果由**报告弹窗**（新文件 `file-move-report-dialog.tsx`）回报。

### 3.1 为什么落在 `FileTree`、不落在 `DualFileTree`

- 移动是「**一棵树搬自己的行**」；`落点()`（`file-tree.tsx:387`）与 `指针行()`（`:933`）都在树里，拖拽起点的判断（这一行在不在选中集里）也只有树知道。
- `dual-file-tree.tsx:209` 的 `可放()` 注释**明写**「同树内不算……那条路与本组件无关，别在这里把它吃掉」——**同树拖拽正是它让出来的那条空档**。本次不碰 `dual-file-tree.tsx` 任何一行（`onMoveTo` 会随 `{...rest}` 自动透传给上树，见 `dual-file-tree.tsx:86` 的 `splitProps`）。
- 跨树拖（备份 / 拉回）因此**天然不受影响**：它由 `DualFileTree` 根委托接管，我们只在 `FileTree` 的 region 上加了同树分支。

### 3.2 为什么报告弹窗由**接线层**开（与删除确认「树自己开」相反）

删除确认的**对象在树里**（哪一行、什么名字），树自己开最省事。本次这份是**远端结果的报告**：「几个成了、几个没成、各是什么原因」**只有发请求那一层知道**。树要开它就得把结果反向传回来——多一条会漂的通道。

接线层今天**没有** `useDialog()`（`workspace-entry.tsx:107` 只在注释里提到 `useSettingsDialog` 内部用它），本次新增。**已验证不产生新挂载前提**：`workspace-entry.test.tsx:64` 的挂具**已经**包了 `DialogProvider`（因为树里的 `useDialog()` 早就在用），生产侧由 `app.tsx` 的 provider 覆盖。

## 5. 数据流

### 5.1 选中集怎么变

两只新信号与既有的焦点行**各自独立**，只在三个手势上按下面这张表联动：

| 手势 | 焦点行 `selected()` | 选中集 `选中集()` | 锚点 |
|---|---|---|---|
| 单击一行 | 它 | `{它}` | 它 |
| `Ctrl`/`⌘` 点一行 | 它 | 切换它的成员资格 | **不动** |
| `Shift` 点一行 | 它 | 锚点到它之间**当前可见的行**（含两端） | **不动** |
| 点行之间空白 | **不动** | `{}` | 清掉 |

- **焦点行语义逐字不变**——它今天有 7 个消费者（`file-tree.tsx:482` / `:486` 新建的 parent、`:544` / `:559` 渲染、`:752-753` 工具栏禁用、`:767` 工具栏取 path、`:970` Enter/空格），本次**一条都不改**。
- **`data-selected` 与 `ROW_SELECTED` 类的判据从 `selected() === path` 改成 `选中集().has(path)`**。单击路径下 `选中集 === {它}` ⇒ **表现与今日逐字相同**（既有断言应当全绿）；多选时自动就有多行高亮，不必新造第二个类。
  - ⚠️ **属性值域一个字都不改**（2026-10-15 按 `file-tree.tsx:544` 原文勘误）：今天写的是 `data-selected={选中 ? "true" : undefined}`——**未选中的行根本没有这个属性**，不是 `"false"`。判据一律断「带不带 `data-selected="true"`」，**不要断 `="false"`**（那会断在一个从不存在的值上）。
- 单击是**最高频**的路径（不按修饰键），改判据后它一行都不差；这是选这条改法而不是「再养一个高亮类」的理由。
- ⚠️ 代价（据实记）：`Ctrl` 取消选中一行之后，它仍是焦点行却**没有高亮**。v1 接受（焦点行剩下的可见作用只有键盘 `tabindex`）。
- 推论（点空白**不清焦点行**）：点过空白之后锚点已清、焦点行仍在，此后再 `Shift` 点会从**上一个焦点行**连到它，而不是只选该行——这是本表「点行之间空白」行与下面无锚点兜底的应有推论，原文没写透。
- `Shift` 点而**还没有锚点**（刚刷新、或从没单击过）⇒ 锚点当**焦点行**——「焦点行」指**这次手势之前**的那一行（`Ctrl` 先点过 A 时，A 就是它）；连焦点行也没有 ⇒ 就是它自己（退化成单击）。
- **无全选**：不提供 `Ctrl+A`（v1 不做）。
- `Shift` 的范围按**当前可见行序**（`行序` 数组）取闭区间：折叠着的子孙不在里面，正是用户眼睛看到的那一段。

### 5.2 拖

**起拖**（region 委托，`onDragStart`）：

```
指针行(event) → 路径
选中集().has(路径) ? 按可见行序排好的整批 : [路径]（并把选中集设成 {路径}）
拖源 = 这批
```

- 同树拖拽的判据是**组件自己的 `拖源` 信号**，**不读 `dataTransfer` 的 payload**——这是 `dual-file-tree.tsx:91-95` 已经写下的理由（happy-dom 里没有 `DragEvent`，读 payload 会多一处立不住的依赖）。本次沿用：**不写 payload、不设 `effectAllowed`**。
  - 与双树那层不打架：双树根委托的 `onDragStart` 同样会跑（后跑、后写），跨树那一放的语义仍是它自己的 `copy`。
- 路径们按**当前可见行序**（自上而下）给出：让判据能写死，也让「谁先发」有确定答案。

**悬停**（`拖过`，改动后）：

```
从桌面(event)            → preventDefault（老路：上传，一字不改）
否则 能落到(拖源, 落点(指针行(event)))
  真  → preventDefault ＋ 记落点高亮
  假  → 什么都不做（浏览器给禁止光标）
```

⚠️ **桌面那一支必须判在最前面**——它的判据是 `dataTransfer.types` 含 `"Files"`，与我们的分支互斥，但顺序写反会让「从桌面拖文件进来」被同树分支吞掉。

**松手**（`放开`，改动后）：

```
从桌面(event) → 老路一字不改
否则 preventDefault；dir = 落点(指针行(event))
     能落到(拖源, dir) 假 → 直接 return（零请求）
     真 → onMoveTo?.(拖源, dir)
```

**非法落点三条**（纯判据 `能落到`，任一源不合法即整体不接管）：

1. 目标就是某个源自己（拖到自己身上）
2. 目标以「某个源 ＋ `/`」开头（拖进自己的子孙）
3. `落点(源) === 目标`（它现在就在那儿）

第 1 条同时覆盖了「一选中就 Ctrl 点三个文件夹、然后拖到其中一个上」这个最容易发生的场景。
**多个源里有一个不合法 ⇒ 整个手势不接管**，不做「能搬的搬了、不能搬的留下」——一次手势在磁盘上只该发生一件事（见 §9 取舍 5）。

⚠️ 三条的**次序**：第 1、2 条（自己 / 子孙）先判，第 3 条（原地）后判。顶层文件的目标是 `""`（项目根），若先把「根 ⇒ 合法」放行就会漏掉「它现在就在根里」——`落点(源) === ""` 的那一份同样要拦。

**拖拽目标态高亮**：悬停合法落点时，给**当前落点那一行**加 `data-drop-target="true"`；落点是项目根（没有行代表它）时给 region 加。离开 / 松手 / `dragend` 清掉上一处。

### 5.3 接线层：一批一次、一个报告口

```ts
type 搬报告 = {
  标题: "移动" | "复制"
  成了: string[]
  没成: { 路径: string; 原因: string }[]
}

function 搬一批(dir: string, 路径们: readonly string[], mode: "copy" | "move")
```

- `搬(dir)`（右键那条老路）⇒ `搬一批(dir, [目标.path], 目标.mode)`
- `onMoveTo`（拖拽那条新路）⇒ `搬一批(dir, 路径们, "move")`
- **两条入口共用一份实现**：同一个动作的两条入口不许各写一套（`LEARNINGS #002-06`）。
- `搬忙()` 为真 ⇒ 直接 return（防重入，与既有 `搬忙` 一致，一行）。
- 逐个 `await`，分开记账（不并发：一次手势的请求数可控，且与既有的 `传()` 同一形状）。
- 收尾三种：

```
全成        → 收下({ kind: "done", path: dir })              // 清话 ＋ 重取清单（复用既有成功支）
部分成      → set文件话(undefined)；拨清单重取()；报结果(值)
全都没成    → 报结果(值)                                      // 不重取：磁盘一点没变，重取是空跑
```

—— `报结果(值)` ＝ `void dialog.show(() => <FileMoveReportDialog 报告={值} />)`（`show()` 的范式同 `file-tree.tsx:786`）。不养 `报告` 信号：弹窗是**只读的一次性快照**，值关进闭包、没有必要落在信号上，少一只没人读的状态。`报告` 是 `FileMoveReportDialog` 的 **prop 名**，不是信号，读代码时别把它当信号找。

**`收下()` 已改（2026-10-16）**：它仍是**五个动作**（新建 / 重命名 / 删除 / 移动 / 复制）共用的结论口，但从「自己写 `文件话` 信号」改成**只回一句话**（`undefined` = 办成），报在哪由各调用方决定——`建条` / `改名条` / `删条` 三路把回话原样交回发起它的那个面（见 `2026-10-16-file-op-failure-in-place-design.md`）。当初移动 / 复制从它分出来（自己写全两个分支），是因为把弹窗塞进它会**连带改掉另外三个动作的报告方式**，超出那次所指。⚠️ 那份「成功支两行」的重复**当时是有意的**，要在代码注释里写明理由——但现在 `收下` 已回话化、不再自己画任何东西，那份「别顺手合并」警戒的前提没了；合并时要保住「回话交回各发起面」这条。

**移动之后清空选中集**：那些路径在移动后纷纷失效。不清的话，第二次拖拽会拿一批已经不在原处的路径去发请求。清空是唯一可预测的收场（见 §9 取舍 6）。

## 6. 边界与错误处理

| 情形 | 行为 |
|---|---|
| 拖到非法落点（自己 / 子孙 / 原地） | 不接管：不 `preventDefault`、**0 个请求**、无任何提示（光标已是禁止态） |
| 桌面拖文件进来 | **照旧上传**（`onDropFiles`），同树分支不吃它 |
| 跨树拖（沙箱 ↔ MinIO） | **照旧**（`DualFileTree` 根委托接管，本组件不参与） |
| 目标已有同名文件 | 后端 400 ⇒ 记进「没成」，原因就是服务端那句原话 |
| 拖进自己的子孙 | 前端已挡；后端另有 `INTO_ITSELF` ⇒ 若前端判断有漏，仍落到「没成」而不是静默 |
| 批里有的成一个没成 | **不回滚**；弹窗同时列出两边；已成的照旧重取清单 |
| 全都没成 | 弹窗出现；**不重取**清单（磁盘一点没变） |
| 全部成功 | **不弹窗**，静默 ＋ 重取（这是最常走的那条，不该每次都拦一下） |
| 移动进行中再发起一次 | `搬忙()` 为真 ⇒ 第二次一个请求都不发 |
| 拖拽期间树被重取 / 折叠 | 落点按**松手那一刻**重算（`指针行(event)` 现算），不看悬停时记下的东西 |
| 项目根 | 落点 `""` ＝ 项目根 —— 与今日拖入上传的落点语言同一套 |
| 空选中集 | 拖拽必然起自某一行 ⇒ 不可能为空（起拖时已把该行设为整批） |
| `dataTransfer` 可能不存在 | 产品码对 `dataTransfer` **一律可选链**（happy-dom 没有 `DragEvent`，既有前提，见 `file-tree.tsx:949`） |

## 8. 缺口表（本机验不了 / 本轮不做，如实记）

- **原生拖拽在真浏览器的完整链条**：**真栈已覆盖（Task 7，`file-tree-multi-move-real.spec.ts` 主 spec 2 passed）**。判据 30 实测磁盘真搬（`档案/ = ["乙.csv","甲.csv"]`、`资料/` 空、旧位置 `existsSync === false`）；判据 31 实测非法落点磁盘不动。组件层（裸 `Event`）只证明「handler 收到事件时做对了事」，真栈（裸指针 `page.mouse`）才证明「浏览器真的会触发 `dragstart → dragover → drop`」——两者**分工**，证明力分层见下一条。
- **判据 31 的证明力分两层：磁盘断言守后端、`drop === 0` 观测守客户端守卫**（变异实测，2026-10-16）：把 `file-tree.tsx` 里 `拖过`/`放开` 两处 `能落到` 守卫拆成 `if (false)` 后，drag 计数由正常 `drop: 0` 变成 `drop: 1`（守卫没了 ⇒ `dragover` 不再拦 ⇒ `drop` 真的触发了、`onMoveTo` 真的发出去），磁盘**仍不动**——后端 `packages/opencode/src/server/openhive/file.ts` 的 `INTO_ITSELF`（`:315` 定义、`:563` 拦截）拒「目录拖进自己」。⇒ ① 判据 31 的两句**磁盘断言**（「非法落点不该动磁盘」「文件必须还在原处」）守的是**后端那层**；② 本轮加的一条 **`expect(计数.drop).toBe(0)`**（「非法落点不该收到 drop——守卫没接管」）守的是**客户端守卫**——变异下它**恰红 1 条**（`Expected: 0 / Received: 1`，红在该句，`#004-14` 安全属性排前面），证明「非法落点 ⇒ 我们不接管 ⇒ 浏览器不触发 drop」这条在真栈有牙了。它与**组件层** `file-tree.test.tsx`（「拖到源自己身上 ⇒ `onMoveTo` 一次没被调，且 dragover 没被 preventDefault」）、**单测** `file-tree-dnd.test.ts`（「拖到自己身上 ⇒ 不行（目录）」）是**同一条判定在三层上的镜像**（真栈 `drop===0` ↔ 组件层 `defaultPrevented===false` ↔ 单测 `能落到` 判据）。
- **触摸设备上没有任何入口**：平板 / 触屏笔记本上「多选 + 拖拽」今天走不通，也没有替代路径（右键菜单那条一次只移一个）。v1 接受——民警用桌面浏览器。
- **dark 主题下选中态对比度**：既有已知缺陷（品牌浅金在 dark 无覆盖 ⇒ 1.99:1，已登记，落点 2→3）。多选会**放大**它（多行同时是浅金底）。本轮**不修**——要修得动 v2 token 的 dark 覆盖，是另一件事；本 spec 只把它记成「被放大的既有项」。
- **大批量的耗时与中途打断**：逐个 `await`，没有取消按钮。今天 `传()` 就是同一形状，本轮不为它发明新机制。
- **一次拖几千行**：不测（树本身要先能铺出几千行）。
- **非沙箱那棵下树（MinIO）不参与**：它的拖拽仍只有「跨树备份 / 拉回」两条语义。
- **键盘多选**：不做 ⇒ 只用键盘的人今天仍只有单选（登记为下一步，与工具栏批量同一批）。
- **一批里同时含某个目录与它的子孙**：`Shift` 连选可以把 `资料` 与 `资料/a.txt` 一起选中（父在可见行序里靠前）。`搬一批` 先搬 `资料`（`a.txt` 随之进了 `档案/资料/`），轮到 `资料/a.txt` 时源已不在原处 ⇒ 报告里出现一条「没成」。**无数据丢失**（那一条确实没被单独搬走），但会给不懂技术的用户一条看不懂的失败行。本轮**不修**——正确的修法是「起拖时剔掉『源是另一个源的子孙』的项」，那是**新加一条批组装规则 ＋ 它自己的 RED／变异周期**，不是补一处漏写的分支（与 F4 性质不同）。登记为下一步。同时记明：三套测试的落点已覆盖「部分成／全败／全成」，**没有**覆盖这个形状。

## 9. 关键取舍记录

1. **多选用系统式 `Ctrl`/`Shift`，不用复选框**（用户 2026-10-15 裁定）：与民警用惯的资源管理器一致；复选框会改行高、且与「这一行可拖」的信号互相干扰。
2. **失败走弹窗、不回滚**（用户两次裁定）：批量失败是一组消息（哪几个、各为什么），内联一句话承载不了；已成功的部分不回滚——回滚本身也会失败，还会把「成了的」再搬一次。
3. **右键「移动」/「复制」的失败也收进同一个弹窗**（用户 2026-10-15 裁定）：
   - 同一个动作（移动）的**两条入口**（右键 / 拖拽）必须用同一种方式报告，否则同一个动作看用户怎么点而有两种回话。
   - 实现上落在 **`搬()` 与 `搬一批()` 共用一份**，`收下()` 从写 `文件话` 改成**回一句话**（2026-10-16）；移动 / 复制仍走各自那份。
   - **反方向的边界与理由**（据实记，2026-10-15 当时的考虑）：按「由弹窗发起的动作、失败回弹窗」这条原则，**新建 / 重命名 / 删除**也够格——它们的发起处同样是弹窗（`file-create-dialog` / `file-delete-dialog`），失败却飘在工具栏下方那一句里。当时**没动它们**：用户点名的是移动，而改它们要把 `收下` 一起翻掉（连带 `:2479` 与新建 / 重命名两条既有断言）。**这条已由 2026-10-16 那轮结清**（见 `2026-10-16-file-op-failure-in-place-design.md`）。
   - **上传 / 下载**同理留在内联（上传由桌面拖拽发起、下载由右键菜单发起，都不经过弹窗）。
4. **落点在 `FileTree`、报告弹窗在接线层**：见 §3.1 / §3.2。
5. **部分源不合法 ⇒ 整个手势不接管**，不做「能搬的先搬」：一次手势在磁盘上只该发生一件事；「三个文件夹里有两个搬进了第三个」几乎不是任何人的本意。
6. **移动之后清空选中集**：移动后那些路径纷纷失效；要「只留没成的选中」就得把结果反传回树，多一条会漂的通道。清空是唯一可预测的收场。**据实重申代价**：清空发生在合法落点松手那一刻（`放开` 里 `set选中集` 排在 `onMoveTo` **之前**）——所以**后端**再拒绝（目标已有同名 ⇒ 400 进弹窗）时，选中集**已经没了**，想重试的用户得重选（弹窗刚告诉了他哪几个没成）；而前端非法落点（`能落到` 判 false）在清空之前就 `return`，**不**清选中集（那是「不接管」，一次手势什么都没发生）。
7. **`selected()` 语义不变，`data-selected` 改判选中集**：单击是最高频路径，改判据后它逐字不变（`选中集 === {它}`）；多选高亮随之免费得到，不必养第二个类。**属性值域也不改**（`"true"` / 无属性，见 §5.1 的勘误）。代价见 §5.1。
8. **不写 `dataTransfer` payload、不设 `effectAllowed`**：沿用 `dual-file-tree.tsx:91-95` 已写下的理由——同页面内拖拽的判据是组件自己的信号，payload 只会在 happy-dom 里多一处立不住的依赖。
9. **逐个 `await`、不并发**：与既有 `传()` 同一形状；一次手势的请求数可控，且「几个成了」这句话在这一层说得清。
10. **判据里「不接管」必须同时钉「没发请求」与「没 `preventDefault`」**：只钉前者分不开两条实现（`#005-19`）。
