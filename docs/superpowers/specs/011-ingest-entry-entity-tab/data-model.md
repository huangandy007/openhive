# Phase 1 Data Model：解析入库入口收敛与实体页签下架

**Date**: 2026-11-15 | **Spec**: [spec.md](./spec.md)

## 结论先行

**本 feature 无数据库变更**：零迁移、零表结构改动、零新接口（FR-012 / SC-005）。
下面的「实体」全部是**视图层概念**——由既有接口返回的数据与前端内存状态组合而成，用来把 FR 中的名词（K / N / M、候选集、选中集）钉成可实现、可断言的对象。

## E1 盘上文件（`path`）

| 字段 | 来源 | 说明 |
|---|---|---|
| `path` | 文件树目录列表 | 项目沙箱内相对路径，`/` 分隔 |
| `可解析` | `可解析路径(path, parseableExtensions)`（`case-materials-view.ts:29`） | 扩展名在服务端给的白名单内 |

**状态派生**：盘上文件自身没有状态字段；它的「入队状态」由**是否有对应材料行**决定——没有材料行即「未入队」（`未入队` 不是盘上属性，是 `材料视图` 缺省的显示结论）。

**校验规则**：
- 目录（以 `/` 结尾）不是文件，不进候选。
- 路径必须位于被展开的目录下（`目录下待入队` 的前缀判定，`case-materials-view.ts:168-175`）。

## E2 材料（`材料视图`，`case-materials-api.ts:38-48`）

| 字段 | 类型 | 与本次相关 |
|---|---|---|
| `path` | string | 与盘上文件一一对应（唯一键） |
| `kind` | string | `"产物"` 时不可入队（只登记不解析） |
| `status` | `未入队 \| 排队中 \| 解析中 \| 已解析 \| 有问题 \| 已跳过` | 候选判据的核心输入 |
| `parseable` | boolean | 服务端口径的可解析标记 |

**状态迁移（由本次入口产生）**：

```text
（无材料行）
  └─ 右键「解析入库」 → 新建材料：未入队 → 排队中 → 解析中 → 已解析 | 有问题
已跳过 ─（单项右键「解析入库」恢复）→ 排队中
已解析 ─（「重新解析」，本 feature 不改行为）→ 排队中
```

**规则**：
- 上传**不再**产生材料（FR-001）；材料只由「解析入库」或「重新解析」产生。
- `入队` 幂等：对 `已解析 / 排队中 / 解析中` 的路径调用，服务端返回不入队（`enqueued: false`），不产生重复材料（Assumptions）。

## E3 解析作业（服务端队列项，不新增字段）

每份**新入队**的材料对应一条排队记录，由既有队列按既有置顶算法执行。
本 feature **不改**队列、不改置顶（FR-015）；前端只在收尾 `reload()` 后从 `status/queueAhead` 读回真实状态。

## E4 选中集（`选中集()`，`file-tree.tsx:445`）

| 项 | 说明 |
|---|---|
| 元素 | 文件路径与目录路径的集合（Ctrl / Shift 选中） |
| 大小 | **K** —— 显示在「解析入库」触发项右侧（FR-010） |
| 与右键行的关系 | 右键行 ∈ 选中集 ⇒ 作用域 = 整个选中集；右键行 ∉ 选中集 ⇒ 作用域 = 右键行自身（不管选中集多大，US2 AC8） |

**规则**：只有 `选中集().size > 1` 时才算「多选状态」（`是选中集`，`file-tree.tsx:708-712`）。

## E5 候选集（入队的作用对象）

```text
选中项 ──┬─ 文件：文件待入队(path, row, extensions)    ── 通过 ⇒ 加入候选
         └─ 目录：目录下待入队(目录, 文件们, 行们, ext) ── 全部加入候选
         去重（见过集合）⇒ 候选集
```

| 量 | 含义 | 展示位置 |
|---|---|---|
| **N** | 候选集大小（去重后的文件数） | 确认框正文 |
| **M** | 被排除的**选中项**数（一份文件 / 一个展开后 0 候选的目录各算一项） | 确认框正文 |

**文件级判据（`文件待入队`，从 `目录下待入队:178-182` 抽出，行为不变）**：

| 情形 | 结果 | 依据 |
|---|---|---|
| 非文件（`/` 结尾） | 排除 | `目录下待入队:174` |
| 扩展名不在白名单 | 排除 | `可解析路径` |
| `kind === "产物"` | 排除 | 产物只登记不解析 |
| `status ∈ {排队中, 解析中}` | 排除 | 运行中不重复排 |
| `status === "已解析"` | 排除 | 已有结果，重来用「重新解析」 |
| `status === "已跳过"` | **批量排除**（单项右键仍放行） | 2026-11-06 裁定，`case-materials-view.ts:150-157` |
| 无材料行 / `status === "未入队"` / `status === "有问题"` | **通过** | 未入队或需重来 |

**口径约束（FR-005 / FR-006）**：
- 批量（目录 / 选中集）与单项右键的差异**只允许存在一处**：批量用 `文件待入队`（排除「已跳过」），单项用 `入队不可用原因`（放行「已跳过」）。两条规则都已有注释固定，本 feature 不新增第三种待遇。
- 读不到状态（`!rowsLoaded`）时**不猜**：`解析入库` 的可用性回「还在读 / 读取失败」原话（`入队不可用原因:219`），不做候选计算。

## E6 批量执行记录（收尾报告，纯前端瞬时对象）

| 字段 | 类型 | 说明 |
|---|---|---|
| `成功 S` | number | `状态.parse(path, "入队")` 返回 `kind === "ok"` 的份数 |
| `失败 F` | `{ path, message }[]` | 返回 `kind === "error"` 的项，**保留顺序**，报告前 3 条 |
| 不变式 | `S + F = N` | 恒成立（每份候选恰好落入一个桶） |

**收尾动作**：`状态.reload()` **一次**；toast 同时报 S、F、"重试只补没成功的、不会重复"。
