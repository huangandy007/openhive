# Phase 1 Contracts：解析入库入口收敛与实体页签下架

**Date**: 2026-11-15 | **Spec**: [spec.md](../spec.md) | **Data Model**: [data-model.md](../data-model.md)

本 feature **没有对外 HTTP / SDK 契约变更**（FR-012：零新接口、零迁移）。可观察的行为契约全在 UI 与既有接口的**副作用**上，因此这里写的是界面契约；实现时以此为准，测试按此断言。

---

## C1 上传（既有 `POST /openhive/case/files/upload`）

| 项 | 契约 |
|---|---|
| 请求 / 响应形状 | **不变**（文件名、路径、判重、幂等、内容指纹语义全部照旧） |
| 副作用 | 只写盘。**不**建材料行、**不**排作业（FR-001） |
| 同名文件 | 仍按既有规则拒绝（Edge Case） |
| 返回后 | 文件树刷新可见该文件；其材料状态为「未入队」 |

**测试契约**：上传一份真 `.xlsx` ⇒ `case_material` 0 行、`case_ingest_job` 0 条（TR-002，先红）。

## C2 上传完成弹窗（`file-transfer-dialog.tsx` `完成态`）

| 条件 | 契约 |
|---|---|
| `state.action === "上传"` 且 `kind === "done"` | 摘要行之下**多一行弱化提示**，指引右键「解析入库」（FR-002） |
| `state.action === "下载"` | **没有**该提示 |
| 其他（运行中 / 错误） | 不变 |

提示文案只此一处定义（放在 `完成态` 内），不得由调用方传入。

## C3 右键菜单 · 解析子菜单（五个既有项）

菜单项与现文案不变：`解析入库 / 重新解析 / 取消解析 / 跳过解析 / 查看解析结果`。
作用域判定统一走 `判菜单目标(path)`（由 `判下载目标` 改名），返回 `file | folder | selection`。

| 作用域 | `解析入库` | 其余四项 | 右侧说明 |
|---|---|---|---|
| `file`（右键行不在选中集 / 未多选） | 按 `入队不可用原因` 亮灰（现状不变，含「已跳过」放行） | 现状不变 | 无 |
| `folder` | 照现状放行到确认框（候选 0 由弹窗解释） | 现状不变 | 无 |
| `selection`（右键行 ∈ 选中集且 `size > 1`） | **状态已读到即保持可点**（2026-11-15 终审 D2 对齐裁定）：`rowsLoaded` 且已接入时 `解析入库` 保持可点，0 候选仍弹确认框、确认键禁用并由正文解释；未读到 / 读取失败 / 未接入时置灰并回原话（FR-009）。N/M 由 `选中集入队范围(...)` 算（`选中集待入队(...)` 仅测试兼容用） | **全部置灰**，统一原因（FR-008） | `解析入库` 右侧显示「已选 K 项」（FR-010） |

**统一原因**：多选下四项不可用，文案固定为「多选时只支持解析入库」这一类**单一来源**常量（同一字符串给四个原因函数用，不许各写一句）。

## C4 确认弹窗（复用 `ParseConfirmDialog`）

| 字段 | `folder` 作用域（现状，`file-tree.tsx:642-685`） | `selection` 作用域 |
|---|---|---|
| 标题 | 「解析这个文件夹」 | 「解析选中的文件」 |
| 正文 | 「将解析这个文件夹下的 N 个文件」 | 「将解析选中的 N 个文件」；N > 0 且 M > 0 时追加「另有 M 个选中项不在本次范围」；N = 0 时正文概括说明没有一个可入队，并至少点名已解析 / 已跳过（其余原因按同一句概括） |
| 确认键 | 正常 | N = 0 ⇒ **置灰**；弹窗仍弹出（FR-009） |
| 取消键 | 始终可用 | 始终可用 |

**数字契约**：**正文**里的 N = 候选集大小；正文里的 M = 被排除的选中项数；二者单位不同（文件 vs 选中项），不得互换或合并（FR-007 / FR-010）。确认框**标题**固定为动作名（文件夹「解析这个文件夹」/ 多选「解析选中的文件」），不放数字——避免标题过长（2026-11-15 终审 D1 对齐裁定）。

## C5 批量执行（`执行批量入队`，文件夹与多选共用）

```text
for 每份候选（保持候选顺序）:
  结果 = await 状态.parse(path, "入队")
  结果.ok  ⇒ S += 1
  结果.err ⇒ F.push({ path, message })   // 继续，不 break
状态.reload()        // 恰好一次
toast:
  F = 0 ⇒ 「已加入解析队列（S 个文件）」
  F > 0 ⇒ 「成功 S 份；F 份未能入队」+ 前 3 条原因 + 「重试只补没成功的、不会重复」
```

**不变式**：`S + F = N`；即使中途用户离开页面，已发出的请求不回滚（Edge Case）。

## C7 既有接口（不变，列出以便断言）

| 接口 | 用途 | 本次变化 |
|---|---|---|
| `POST /openhive/case/parse`（`{path, action}`） | 逐份入队 / 重新解析 / 取消 / 跳过 | **无**（批量复用，`action=入队`） |
| `GET /openhive/case/materials` | 材料清单 + 可解析扩展名 | **无** |
| `POST /openhive/case/files/upload` | 上传写盘 | 仅副作用：不再入队 |

**唯一入口契约**（FR-003）：材料行只能由 `case/parse` 新建（`入队` 或 `跳过`）；**作业**只由 `入队` 新建；为此新增一条路由级用例钉住它（TR-003）。
