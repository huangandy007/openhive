# Phase 0 Research：解析入库入口收敛与实体页签下架

**Date**: 2026-11-15 | **Spec**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md)

本 feature 的**产品裁定已在 `07` 落地**（§3–§5 + §6 边界 + §9 实现前修订），这里不再重开产品讨论，只登记「怎么做」的工程决策：选了什么、为什么、否了哪些替代方案。

---

## D1 上传不再入队：删掉，而不是削弱

**Decision**：删除 `handleUpload` 落盘后的入队段（`file.ts:855-873`），上传只写盘。

**Rationale**：
- `07` §3.1 的流程是「原件先落盘 → 预处理 skill 出标准副本 → 副本入库」。上传顺手入队会让原件直接进解析链路，预处理永远被绕过。
- 唯一入口（FR-003）是「上传时询问」「独立按钮」「拖拽即入队」都不做的理由；留着一段入队代码就等于留第二个入口。
- 删除后 `handleUpload` 不再需要 `pg`（`file.ts:406` 的注册同步收口），也顺手消掉一条「上传路径依赖 PG 可用」的隐式耦合。

**Alternatives considered**：
- *保留但加开关*：留下两条代码路径与一个配置项，超出「只做要求的事」，且开关必然有人打开。
- *保留但改成「只登记材料、不排作业」*：材料行的语义是「一次解析的去重单位」，没有解析就没有材料——造半行数据是新的不一致来源。

---

## D2 批量只在前端逐份发，不做服务端批量接口

**Decision**：批量 = 前端按候选集逐份调既有 `POST /openhive/case/parse`（`action=入队`）。

**Rationale**：
- `目录下待入队`（`case-materials-view.ts:162-185`）的注释已定案：**「已跳过」不进批量候选**，因为跳过是人的意志；而服务端「该走哪个动作」见到「已跳过」返回「入队」。若服务端提供「按一批路径批量入队」，它会按状态全集扫，把用户逐份跳过的文件悄悄翻回来。
- 逐份也天然满足「失败不中断」：每份独立请求，第 2 份失败不影响第 3 份。
- 零新接口、零迁移（FR-012），符合最小改动与上游同步约束。

**Alternatives considered**：
- *新增批量接口*：翻回「已跳过」的风险 + 新接口 + 新鉴权面，被否（`07` §5.6）。
- *前端 `Promise.all` 并发*：失败归因变模糊（哪一份对应哪个错误要靠下标对齐），且并发上限、服务端排队竞争都成新问题。串行沿用现有文件夹批量的行为，最省。

---

## D3 候选判据只抽一次：`文件待入队`

**Decision**：从 `目录下待入队` 抽出文件级判据 `文件待入队(path, row, extensions)`；`目录下待入队` 改为「目录内文件逐个调它」；新增 `选中集待入队(选中项, 文件们, 行们, extensions)` 也调它。

**Rationale**：
- 07 §5.5 要求「候选判据只有一份口径」；今天的判据散落在 `目录下待入队` 的循环体里（`:178-182`），选中集若照抄就是第二份（`#002-06`）。
- 抽出后 `目录下待入队` 的行为必须原样不变——这是 TR-005 的硬要求（既有用例不改断言、全绿）。

**Alternatives considered**：
- *在 `file-tree.tsx` 里另写一份三元判断*：两份同一前提，必漂。
- *把判据写进 `入队不可用原因` 并让两者共用*：两者语义**故意不同**（单份放行「已跳过」、批量排除），合并会把 `07` 的区分抹平；保持两个函数、明确注释，比硬合更安全。

## D4 多选的作用域判据：复用「右键行在不在选中集」

**Decision**：把 `判下载目标`（`file-tree.tsx:723-735`）改名为 `判菜单目标`，解析子菜单与下载共用同一份 `{kind: "file" | "folder" | "selection"}` 判定。

**Rationale**：
- 现成实现已经回答了「右键落在 file / folder / selection」三态，且下载已按它工作；解析需要同一个三态（spec US2 AC8：判据是「右键行在不在选中集」，不是选中集大小）。
- 改名而非复制，避免两处各判一次（`#010-06`）。下载的两处调用（`:1452`、`:1670` 附近）语义不变。

**Alternatives considered**：
- *解析路径单独判 `是选中集(path) && 批.size > 1`*：与下载判据重复，且容易漏掉「右键行不在选中集」的分支。

---

## D5 「已跳过」的两种待遇：沿用既有分工，不新建分歧

**Decision**：单项右键放行「已跳过」（`入队不可用原因` 现状即如此，`:215-228` 只挡「已解析 / 运行中 / 产物 / 不可解析」）；批量排除（`目录下待入队:181` 已排除 `已跳过`）。新增的 `选中集待入队` 走批量语义 ⇒ 也排除。

**Rationale**：
- 这不是本次新增的分歧，而是 2026-11-06 已裁定、且在 `case-materials-view.ts:150-157` 写明的一对（单份是明确动作，批量不该替人翻回）。本 feature 只保证：新路径**不引入第三种待遇**。
- 与之配套的 UI 交代：确认框正文必须说明「另有 M 个选中项不在本次范围」（FR-007），因为被排除的可能是用户以为会入队的「已跳过」。

**Alternatives considered**：
- *统一成放行*：批量会把用户跳过的东西全拉回来，直接违背裁定。
- *统一成排除*：单份右键会对「已跳过」灰掉，「恢复这一份」失去入口。

---

## D6 三个数字：K / N / M 各有唯一来源

**Decision**：
- **K** = 选中集大小（`选中集().size`），显示在「解析入库」触发项右侧；
- **N** = 候选文件数（`选中集待入队(...).length`），显示在确认框正文；
- **M** = 被排除的选中项数（选中项数 − 有贡献的选中项数，文件夹按「展开后有候选」计），显示在确认框正文。

**Rationale**：07 §5.4 明确三者语义不同、不许混用；`07` 的实现前修订把命名定死，本方案照抄命名，避免实现期再起别名。

**Alternatives considered**：
- *只在确认框里给一个总数*：用户无法解释「我选了 3 个，怎么只入队 2 个」。

---

## D7 批量失败：继续 + 收尾一次交代

**Decision**：把 `确认解析文件夹`（`file-tree.tsx:642-690`）的执行体抽成 `执行批量入队(候选)`：逐份 `状态.parse(path, "入队")`，失败**继续**并收集 `{path, message}`；跑完 `状态.reload()` 一次；toast 报 `成功 S 份` 与 `F 份未能入队`（前 3 条原因）+「重试只补没成功的、不会重复」。

**Rationale**：
- 现有实现遇错 `break`（`:665-675` 附近）——批量场景下这会吞掉后续所有文件，且用户只知道「有一个失败」。
- `入队` 是幂等逐份动作（服务端 `enqueueMaterial` 对已解析/排队中返回 `enqueued: false`），重试只补未成功的，不会重复——这句话可以如实写给用户。

**Alternatives considered**：
- *首个失败即中止（现状）*：与 SC-003「其余文件全部被提交」直接冲突。
- *失败静默、只报成功数*：不满足 FR-011。

---

## D8 实体页签：删 pane 与接线，不删能力

**Decision**：从 `sidebar-tabs.tsx` 删 `"entity"` 键、文案、顺序项与 pane；从 `workspace-entry.tsx` 删 `EntityPanel`/`实体路径` import、`entityApi` prop 与注入；从 `layout-new.tsx` 删 `createEntityApi`/`ENTITY_API`；删除 `entity-panel.tsx` 与其测试。**`entity-api.ts` 与实体详情页、伪路径不动。**

**Rationale**：FR-013 要求「清理干净」，FR-014 要求「下架界面不等于下架能力」；`07` §3.2 给了保留清单。`entity-api.ts` 还被实体详情页用，删它等于把详情页一起下架。

**Alternatives considered**：
- *仅从 `TAB_ORDER` 移除、保留 pane*：留下不可达代码与测试，grep 收尾会残留，且 stories 还会渲染它。

## D9 上传完成提示放在弹窗自身

**Decision**：在 `完成态`（`file-transfer-dialog.tsx:144-160`）内按 `props.state.action === "上传"` 渲染一行弱化提示。

**Rationale**：`FileTransferState` 已带 `action` 字段（`:30`/`:38`），不需要新 prop、不需要调用方传文案；提示与「完成摘要」同源同处，不会分叉。

**Alternatives considered**：
- *由 `workspace-entry` 传一条 `提示` prop*：文案两个来源，下载路径还得记得传 `undefined`。

---

## D10 测试策略

**Decision**：
- 运行时时序：UI 组件测试一律 `--conditions=browser` + `happydom.ts` + `solid-jsx.ts`（`packages/app` 的 `test:components` 脚本即此口径，`#009-02`）。
- 批量失败/顺序断言用现成假状态 `假材料状态({ parse })`（`case-materials.test-support.ts`）：`parse` 回调可按路径返回 `{kind: "error", message}`，`记.解析` 记录调用顺序，`记.重拉` 记录 `reload` 次数——足以钉住「失败后继续」与「收尾只 reload 一次」。
- 服务端用例：上传断言反转（TR-002）+ 唯一入口路由级用例（TR-003）。

**Rationale**：不新增测试基建，直接复用 `#009-02` 的跑法与既有假实现；`入队` 的幂等语义由服务端用例守，前端只守「发了几次、顺序如何」。

**Alternatives considered**：
- *起真栈跑 e2e 断批量*：慢且脆；真栈只做手工验收（quickstart 的手工节），测不了的写缺口表（TR-007）。
