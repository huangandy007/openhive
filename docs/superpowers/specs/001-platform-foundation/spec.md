## User Scenarios & Testing

### User Story 1 - 三栏工作台框架（Priority: P1）

民警登录后进入统一的三栏工作台，一眼看清「我在哪、在干什么」。左栏导航、中栏浏览、右栏 AI 会话，配合图标栏五入口与顶栏，构成所有业务模块的统一承载框架。

**Why this priority**: 三栏是全部功能模块（项目管理 / 资金 / 话单 / AI 资产）的统一壳，缺了它任何模块都无法挂载，是平台的物理骨架。

**Independent Test**: 登录后看到左/中/右三栏 + 图标栏五入口 + 顶栏，点任一入口左栏切换为该模块导航、中栏切换为对应内容，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 民警已登录，**When** 进入主界面，**Then** 看到左/中/右三栏布局 + 图标栏五入口 + 顶栏
2. **Given** 民警在三栏工作台，**When** 点图标栏任一入口，**Then** 左栏切换为该模块导航、中栏切换为对应内容
3. **Given** 民警在中栏浏览分析结果，**When** 需要让 AI 干活，**Then** 在右栏发起，不面对代码编辑器

---

### User Story 2 - 共享中栏跨模块累积（Priority: P1）

中栏是跨模块共享的 tab 容器。各模块（项目管理 / 话单分析 / 资金分析）通过动作打开的新 tab（明细 / 关系图 / 文档 / 图谱等）**跨模块累积保留**；切换模块不清空、不打扰中栏已有 tab；tab 按模块着色标识来源。

**Why this priority**: 共享中栏是「专注工作单元、不串案」的关键体验，避免切换模块时丢失正在看的内容，是民警「看得清、不打断」的底座。

**Independent Test**: 在资金分析打开一个明细 tab，切到项目管理再切回资金分析，tab 仍在且选中状态与内容保留，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户在资金分析打开了明细 tab，**When** 切换到项目管理，**Then** 中栏已有 tab 不清空、不打扰
2. **Given** 中栏有多个来自不同模块的 tab，**When** 观察 tab 栏，**Then** 每个 tab 按来源模块着色区分，点哪个激活哪个
3. **Given** 用户切回资金分析模块，**When** 查看中栏，**Then** 之前打开的明细 tab 仍在且内容保留
4. **Given** 中栏同时打开大量 tab 导致空间不足，**When** 观察 tab 栏，**Then** 溢出的 tab 收进行末「⋯」，不用横向滚动条

---

### User Story 3 - 中栏多形态内容区（Priority: P1）

中栏按内容类型自动切换视图。Word / Excel / PPT / PDF / 思维导图 / 图文混排 / 图片 / 数据明细 / 可视化图表 / 分析记录都是中栏一等公民；代码编辑器降级为少数技术用户的可选工作区。

**Why this priority**: 民警高频面对文档 / 表格 / 图表，中栏必须摆脱「代码编辑器」的程序员心智，按内容类型呈现，否则「用不起来」的根因无法消除。

**Independent Test**: 点文件树某 `.docx` 中栏渲染文档预览视图，点 `.xlsx` 渲染表格视图，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 文件树有 `.docx` 文件，**When** 点该文件，**Then** 中栏渲染文档预览视图
2. **Given** 文件树有 `.xlsx` 文件，**When** 点该文件，**Then** 中栏渲染表格预览视图
3. **Given** 文件树有未知扩展名文件，**When** 点该文件，**Then** 中栏给出可理解的降级呈现（不白屏、可提示）

---

### User Story 4 - 三栏职责分离（Priority: P2）

左栏 = 导航（去哪个项目、看哪个文件）；中栏 = 看改（看结果 + 改结果 + 交互）；右栏 = AI 会话（让 AI 干活）。用户不写代码，也不面对代码。

**Why this priority**: 三栏职责清晰是「民警用起来」的前提，但属框架体验的进一步收敛，非功能阻断项，故列 P2。

**Independent Test**: 观察三栏职责分工——定位数据走左栏、看结果走中栏、让 AI 干活走右栏，互不越界。

**Acceptance Scenarios**:

1. **Given** 民警需要定位数据对象，**When** 用左栏导航，**Then** 定位到项目 / 文件 / 数据对象
2. **Given** 民警在中栏查看结果，**When** 需要修改结果，**Then** 在中栏内完成交互（拖拽编辑等），不切到代码编辑器

---

### Edge Cases

- 中栏同时打开大量 tab 时，tab 栏如何承载（溢出收进「⋯」，不用横向滚动条）。
- 中栏遇到无对应视图的内容类型时，降级呈现（不白屏、可提示）。
- 左栏切换模块时，只切换「当前工作上下文」（决定能打开什么新 tab），不动中栏已有 tab。
- 中栏为空（尚无任何 tab 打开）时，显示模块默认内容或空态，而非空白。

---

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 提供统一三栏布局：左栏导航 / 中栏浏览 / 右栏 AI 会话。*（承载物：**新建**三栏骨架 `workspace/three-pane.tsx`，挂载于 new 布局 `layout-new.tsx:41` 的 `<main>`）*
- **FR-002**: 图标栏 MUST 提供五个入口（项目管理 / AI 资产 / AI 会话 / 话单分析 / 资金分析）+ 底部「系统设置」。*（承载物：**新建**——new 布局无图标栏）*
- **FR-003**: 顶栏 MUST 含品牌 Logo、站内信（未读红点）、全屏、用户下拉（个人信息 / 修改密码 / 用户管理 / 退出登录）。*（承载物：品牌部分**换皮** opencode `titlebar.tsx`（v2 分支已有 `#opencode-titlebar-right` 注入点）；站内信为**新增**）*
- **FR-004**: 中栏 MUST 作为跨模块共享的 tab 容器，各模块打开的 tab 跨模块累积保留。*（承载物：**新建**——opencode 现存两条 tab 系统均不满足本条：`context/tabs.tsx` 键为 session/draft，`context/layout-tabs.ts` 是 per-session、切 session 即丢）*
- **FR-005**: 中栏 tab MUST 按来源模块着色标识，点哪个激活哪个。*（承载物：**新建** `center/tab-bar.tsx`）*
- **FR-006**: 左栏切换模块 MUST 只切换当前工作上下文，不清空、不打扰中栏已有 tab。*（承载物：**新建**独立 `center/tab-store.ts`，不侵入 opencode session 状态管理）*
- **FR-007**: 中栏 MUST 按内容类型（扩展名）路由到对应视图（文档 / 表格 / 演示 / PDF / 思维导图 / 图文混排 / 图片 / 数据明细 / 可视化图表 / 分析记录）。*（承载物：**新建** `center/view-registry.ts` + `center/views/*`）*
- **FR-008**: 中栏视图 MUST 支持注册式扩展——新增格式只需注册新视图，框架零改动。*（承载物：**新建** `center/view-registry.ts` 的注册接口）*
- **FR-009**: 代码编辑器 MUST 降级为「少数技术用户的可选工作区」，不是默认视图、不是主角。*（承载物：调整 new 布局下代码编辑器的默认可见性，非重写编辑器本体）*
- **FR-010**: 中栏「特有 tab」MUST 由各模块通过动作打开产生（非预置常驻）。*（承载物：**新建** tab-store 的「动作开 tab」API）*

### Key Entities

- **中栏 tab**：模块来源、着色标识、激活状态、绑定的内容视图。
- **内容视图注册表**：内容类型（扩展名）→ 视图组件 的映射，承载注册式扩展。
- **三栏工作台**：图标栏 + 顶栏 + 左栏（导航）+ 中栏（浏览）+ 右栏（AI 会话）。

---

## Success Criteria

### Measurable Outcomes

- **SC-001**: 民警登录后 3 秒内看到完整三栏工作台（首屏加载）。
- **SC-002**: 切换模块后，中栏已有 tab 100% 保留、选中状态与内容不丢失。
- **SC-003**: 新增一种文件格式的中栏视图支持，框架零改动（只注册新视图）。
- **SC-004**: 民警无需代码知识即可定位「我在哪个项目、正在看什么」。

---

## Assumptions

- 前端复用现有 opencode 原生界面框架（**当前生效的 new 布局 / v2**，见 `refactor-targets.md` §1），以「换皮 + 新增组件」方式改造（既定战略决策，见 design-v2 §8.1），不走 React 自研。
- 运行环境：公安内网、桌面 PC、中文、约 1600 用户（并发活跃约 320~480）。
- 右栏 AI 会话的「指令卡机制」细节在 F8（AI 会话）feature 展开，本 feature 只定义右栏骨架与位置。
- 各模块的「特有 tab」（明细 / 关系图 / 文档 / 图谱）由各模块通过动作打开，非本 feature 预置常驻。
- 中栏「AI 资产」模块例外——它的中栏是「资产浏览器」而非「产物浏览器」，本 feature 只提供框架，资产浏览逻辑在 F9 展开。
