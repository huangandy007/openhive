# 中栏内容「发到会话」设计

- **日期**：2026-10-14
- **分支**：`multi-tenant`
- **性质**：本仓定制（openhive），提交信息须标注「这是要保留的定制」
- **上游约束**：改动落在 fork 自己的文件里，不碰 `session-ui` 的上游源码（只调用它已有的口）

---

## 1. 背景与目标

民警在中栏看文件（表格 / 文档 / 代码），经常需要把**看到的一段内容**拿去问 AI。现在只能手工复制、再切到右栏粘贴。

本设计给出两条更短的入口：

- **拖**：在中栏选中 → 拖进右栏输入框 → 松手
- **右键**：在中栏选中 → 右键 → 点「发送到会话」

一句话目标：**把中栏选中的内容，插进右栏会话输入框的光标处。**

## 2. 范围

### v1 做

- 两条入口（拖 / 右键），最后落进**同一个插入动作**（只写一份，不各写一套）
- 「选中内容」= 浏览器**原生选区**，不自建行选择模型
- 行数上限 **50 行**，超了不发送并提示
- 右键菜单含 **「复制」**（补回被接管的浏览器原生能力）与 **「发送到会话」**
- 右栏没开会话时**明确提示**，不静默丢弃

### v1 不做

- 不连续选择（要第 2/7/8 行就分几次发，每次插在光标处，自然累加）
- 不把内容发成 `@文件` 引用（发的是**正文**）
- 不区分「发给哪一栏会话」（右栏只有一个会话槽）
- 只按**行数**设上限，不按字数

## 3. 总架构

三层：

1. **一个共享插入动作** —— 右栏的 `草稿操作.addText(文本)`（上游 store 已有）＋ 把焦点交还输入框（`controller.restoreFocus()`，原生件「历史回退之后把焦点还回去」用的那一套公开口）。两条路都只调这一个动作。
   - ⚠️ **2026-10-14 勘误**（Task 3 实施时实测，原文写错）：原文写 `controller.dispatch({ type: "focus.editor" })`，并称它是「原生件自己在 `onFocus` 里用的那一支」。**实测不成立**：`focus.editor` 在原生件里是**同名两物**——**事件**（`machine.ts:31`）在 `machine.ts:77` 只把 `state.focus` 记成 `"editor"`、**不推任何 command**；真聚焦的是**命令**那条（`machine.ts:40` → `interaction.ts:159` 的 `editor?.focus()`）。`dispatch` 发的是事件 ⇒ **一行什么都不做的调用**（读起来像在聚焦）。改调 `restoreFocus()`。
2. **一个跨栏接线盒**（新文件 `ai-session/send-to-session.ts`）—— 中栏与右栏是两个互不相识的组件，中栏喊一嗓子右栏听不见。接线盒让右栏挂上时**登记一个收件口**，中栏发送时取来代写。
3. **两条载体** —— 拖（改右栏已有的 drop 处理）、右键（中栏容器上的菜单），都调接线盒里**同一个** `发送到会话`。

**为什么用接线盒、不引入 Provider**：加 Provider 会给一串既有测试加挂载前提（`LEARNINGS #005-27`：给组件加 `useXxx()` 前提会让「只是借这个前提」的用例集体改）。接线盒是仓里的老写法——`center/views/reading-size.ts`、`project/current-project.ts` 都是模块级的一小块共享状态；这里只是把「共享一个值」换成「共享一个动作」。

**依赖方向**：接线盒放 `ai-session/`，中栏 import 它（`center → ai-session`）。这不是新方向——`center/session-edits-wiring.ts:2` 已经在做同一件事（中栏接线进 `@/ai-session/session-actions`）。反方向（`ai-session → center`）也有先例（`ai-session-slot.tsx:3` 用 `@/center/tab-context`）。

## 5. 数据流

### 5.1 拖（A1）

中栏拖选表格 → 浏览器原生拖拽 → 载荷 `text/plain` 是制表符分隔文本（探针实测：`"张三\t1200\t46296\r\n…"`）→ 落进右栏输入框 → `onDrop`：

```
路径 = 拖入路径(载荷)
路径 有值  → 老路：@文件 引用（一字不动）
否则有内容 → 发送到会话(载荷)
```

### 5.2 右键（A2）

中栏容器 `onContextMenu` → **选区非空才接管**（`preventDefault` ＋ 记坐标开菜单）→ 点「发送到会话」→ `发送到会话(选区文本)`。

### 5.3 接线盒

```ts
type 发送结果 = { ok: true } | { ok: false; 原因: "没有会话" | "行数超限" }

/** 右栏输入框挂上时传一个收件口，卸载时传 undefined 收回。 */
export function 订阅会话输入(收: ((文本: string) => void) | undefined): void

/** 把文本发进会话输入框。返回结果供调用方决定要不要提示。 */
export function 发送到会话(文本: string): 发送结果
```

顺序：**先查收件口 → 再查行数 → 最后才调收件口**。无收件口时**不**做行数检查（右栏都没开，说什么行数）。

## 6. 边界与错误处理

| 情形 | 行为 |
|---|---|
| 右栏没开会话（无收件口） | 不插入；提示「先开一个会话」 |
| 拖拽落点不在输入框 | 不触发（drop 只挂在输入框的 `<form>` 上） |
| 没选中 / 选中全是空白 | 右键**不接管**，放行浏览器原生菜单 |
| 选区 > 50 行 | 不发送；提示「一次最多发 50 行，请少选点」 |
| 拖拽载荷带 `text/html` | **只读 `text/plain`**，`text/html` 一概不看 |
| 正文里含 `@` | 纯文本插入，**不**触发 mention（`addText` 不认 `@`；只有 `addMention` 才产引用） |
| 选区是**全局**的（`window.getSelection()`），不绑定发起右键的那一栏 | 在左栏选中的文本、去中栏空白处右键，发的仍是那段。v1 **接受**：要绑栏就得自建选择模型，与 §9.1 同一条取舍 |
| 两条路的空白处理不一致 | 右键那条 `.trim()` 之后为空 ⇒ 不接管（`content-menu.tsx:68`）；拖拽那条**原样**送。v1 **接受**（拖拽载荷来自浏览器，不会被空白噪声触发） |
| 任何带 `text/plain` 的拖拽都会插正文 | 不只中栏：从其它应用拖一段纯文本进输入框，也走正文分支。v1 **接受**——这正是「拖文本进输入框」的正常期望；老路 `@文件` 只由**路径形状**认领 |

**行数数法**：按 `\r\n|\r|\n` 拆，**末尾那个换行不算一行**——否则正好选 50 行会被算成 51、白拒。

⚠️ **正文路不要补 `@` 锚点**。文件引用那条路上有个「第二次拖失效」的老坑（`addMention` 用 `lastIndexOf("@")` 反推范围，须先补 `@`）。正文走 `addText`，**没有那套反推**，照抄只会平白插入一个 `@`。这点要写进代码注释，免得后来人照抄。

**插入后焦点**：调 `controller.restoreFocus()` 把焦点交还输入框，用户可直接接着打字。
（⚠️ 2026-10-15 勘误：本节原写 `controller.dispatch({ type: "focus.editor" })` —— **那是一行什么都不做的调用**，
理由与实测见 §3 的「2026-10-14 勘误」；实现里用的是 `restoreFocus()`，见 `session-panel.tsx:585`。）

## 8. 缺口表（本机验不了 / 本轮不做，如实记）

- **AI 收到这段文本后怎么用**：不在本轮（这是「送进去」的功能，不是「AI 理解」）。
- **插入后焦点是否**真的**回到输入框并能直接打字**：组件层钉「`document.activeElement` 落在编辑器上」（2026-10-14 实测 happy-dom 的 `activeElement` 可用，故这里**有**自动化断言）；**真人指针下能不能接着打字**仍要真栈确认一次（判据：点完发送后**不先点输入框**、用裸键盘直接打字）。
- **超大表的整份解析**：不在本轮（表格视图本身只铺前 1000 行 × 64 列）。
- **生产 build 下「拖/右键 ⇒ 文本进输入框」这条链真跑通**（2026-10-14 真栈实测新增缺口）：本机唯一的真栈挂具（`packages/app/e2e/real-stack/stack.ts`）起的是 Vite **dev server**，`vite-plugin-solid` 在 serve 模式把 `solid-js` 解析到 `dist/dev.js`（`devComponent` ＋ `@solid-refresh`），而 `ready()` 在数据落定那一刻**同目录重算**一次 ⇒ `SessionPanel` **挂载两次**（探针实测 `面板挂载 序=1 → 序=2`），第二次的 `订阅会话输入` 把模块级收件口盖成**孤儿 store** ⇒ 两条插入判据在挂具下**恒红**（实测输入框文本 `""`）。生产 `solid.js` **无此包装**（源码读实）⇒ 预期单次挂载、这条链通；**但未真跑过生产 build 的 e2e** ⇒ 此开口**未闭合**，不写成已覆盖。`send-to-session-real.spec.ts` 把这两条标 `test.fixme()` 并在文件头注明根因，右键/对照/几何那几条照跑照绿。
  > **闭合条件**：出现一条能在生产 `solid.js`（非 `dev.js`）下跑 e2e 的挂具（例如 `vite build` ＋ `vite preview`，或把挂具的 `resolve.conditions` 钉成生产那份）⇒ 摘掉 `test.fixme`、那两条必须转绿。在那之前，§7 判据 1 / 4 / 6 的**真栈那一栏记为未覆盖**；判据 6 / 9 的**组件层端到端已于 2026-10-15 闭合**（见 `session-panel.test.tsx` 那条「中栏右键 ⇒ 右栏输入框」用例），真栈只剩「原生拖拽 / 原生选区 / 裸键盘」三样非接缝的东西。
- **收件口指向孤儿时界面静默无出口**（`LEARNINGS #005-41` 第二问 / `#006-27` 形状）：若真出现「面板被挂两次」，`发送到会话` 仍返回 `{ok:true}`（收件口在、只是写进孤儿 store）⇒ **界面什么都不发生、无提示、无出口**。本条是伪影暴露出的**真实产品行为**，**登记为独立排期项，不在本轮修**。
  > **闭合条件（2026-10-15 最终评审复核后升级为排期项）**：满足其一即闭合 —— ① 生产侧出现**第二处**挂我们
  > `SessionPanel` 的地方时**同批**做（评审已核实当前唯一：`packages/app/src/ai-session/ai-session-slot.tsx:24`；
  > `packages/app/src/pages/session.tsx:2275` 挂的是**上游**会话页、不是我们的）；② 或把收件口改成**回布尔**
  > （写不进去回 `false`），`发送到会话` 据此回 `{ok:false, 原因:"没有会话"}` ⇒ 民警看到「先在右栏开一个会话」
  > 而不是静默（这条与登记先后顺序无关，是稳的那一半）；③ 或先实测双挂载下**谁先登记**，再加「收回时判身份 /

## 9. 关键取舍记录

1. **不建行选择模型，用原生选区**：探针实测原生拖选已经把正确的 TSV 交出来了；自建模型要么与浏览器行为不一致，要么得重写一遍选择逻辑（`LEARNINGS #005-20`：认上游已有的记号，别发明第二种）。
2. **右键只在有选区时接管**：一旦接管就顶掉了浏览器原生菜单（复制 / 全选 / 打印）。只在有内容要发时才接管，是**把丢失限制在最小的窗口**；菜单里补上「复制」是底线（`LEARNINGS #006-32`：降级实现不能变成「功能更少的控件」）。
3. **超限「拒发并说清」而不是静默截断**：截断就得再发明一条「截多少、怎么告诉用户」的规则，多半猜不准；而静默截断正是 `sheet-view` 文件头点名要避免的「静默少给」。
4. **接线盒而非 Provider**：见 §3。
