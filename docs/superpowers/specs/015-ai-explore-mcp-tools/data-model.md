# Data Model: AI 探索与 MCP 工具

**Feature**: `015-ai-explore-mcp-tools` · **Date**: 2026-11-17

本 feature **不新增数据库表、不新增列、不新增迁移**。它定义的是**工具返回契约**与**前端派生数据**两类模型；持久化仍然只读既有案件表。

---

## 1. 七字段信封（工具返回，服务端硬校验）

**来源**：`09` §3.2–§3.4；实现 `packages/opencode/src/server/openhive/case-mcp-server.ts:735`（`校验信封`）。

| 字段 | 类型 | 约束（`校验信封` 实际执行） |
|---|---|---|
| `摘要` | `string` | 存在且**非空**；只给结论 + 片段，不给全文 |
| `数据` | `unknown` | 必须存在（`undefined` 视为缺字段）；「空」只认 `null` 或长度 0 的数组（`case-envelope.ts:81`） |
| `口径` | `string` | 存在且**非空** |
| `缺口` | `string[]` | 必须是数组；截断/近似/未覆盖项追加在此 |
| `空原因` | `空原因值 \| null` | 必须**恰好**与 `数据` 的空性相反：数据空 ⇒ 非 null；数据非空 ⇒ null |
| `出处` | `出处项[]` | 必须是数组；每项 `{事实, 代表, 可下钻}`（`case-envelope.ts:59-65`） |
| `下一步` | `下一步项[]` | 必须是数组；每项 `{工具, 参数, 为什么}`，**不自动执行**（`case-envelope.ts:67-72`） |
| `身份` | 可选第 8 字段 | 图工具等需要标明「以谁的身份执行」时携带；不在 `校验信封` 的必需键里 |

**违约处理**：`信封违约`（`case-mcp-server.ts:724`）→ 折成 `tool_failed`，回给模型的只有固定文案「工具执行失败，已记入服务端日志」，原文只进留痕。**不是** `bad_input`——这是实现错误，模型无法自纠。

**截断**（`case-mcp-server.ts:762`，`截断数据`）：
- 预算 `数据预算字节 = 30 * 1024`（`case-envelope.ts:28`），测量口径 `序列化字节 = Buffer.byteLength(JSON.stringify(值))`。
- 数组：从尾部按条截，直到 ≤ 预算；截掉多少写进 `缺口`，并注明「摘要 / 出处按截断前数据计算」。
- 非数组（如 `find_crossings` 的对象）：不截；超限时**必须**写缺口（fail-closed，不许静默放行）。
- 首条即超限：原样返回 + 缺口写明「无法按条截断」。

## 2. 空原因枚举（16 值，顺序即优先级）

**来源**：`case-envelope.ts:37-54`（唯一出处）。规则：**一个返回只报一个**；多个同时成立按表序取第一个；其余进 `缺口`。

| # | 值 | 语义 |
|---|---|---|
| 1 | `无此实体` | 查无此实体 |
| 2 | `实体存在但无任何事实` | 实体在，但没有任何事实行 |
| 3 | `材料未解析` | 相关材料还没走解析 |
| 4 | `确实没有交易` | 数据完整，确无交易 |
| 5 | `实体没有关联账户` | 实体本身没有账户 |
| 6 | `账户未在材料中出现` | 账户不在已入库材料里 |
| 7 | `项目内资金材料未翻译` | 有材料但未翻译成事实 |
| 8 | `外币行全部未计入` | 全部被单位闸排除 |
| 9 | `无事件` | 无符合条件的事件 |
| 10 | `对象未登记` | 对象未登记到参与表（**仅 `query_timeline` 拥有**） |
| 11 | `时间全部缺失` | 有行但时间不可用 |
| 12 | `能力未就绪` | 工具明确不支持该查询（如按地点取事件） |
| 13 | `材料未入库` | 材料尚未入库 |
| 14 | `该材料未解析` | 指定的那**一份**材料未解析 |
| 15 | `无匹配行` | 通用兜底 |
| 16 | `用途未结构化` | 用途字段未结构化 |

**归属纪律**：每个工具只报自己拥有的值；不拥有的情形用 `无匹配行` 兜底；`对象未登记` 不许其他工具借用（写进 `contracts/mcp-envelope-contract.md` 的逐工具表）。

## 3. 预算模型（每次调用）

**实现**：`新预算计数`（`case-mcp-server.ts:149`），默认实例 `默认预算`（:168）；计次键 `${userId}\u0000${projectId}`（:154）。

| 属性 | 值 |
|---|---|
| 上限 | 12 次 / 窗口 |
| 窗口 | 10 分钟空闲滑窗（窗内无新调用即重置） |
| 计数时机 | **分发之前**计次（成功、失败都算） |
| 第 12 次起 | `计次` 返回 `>= 12` ⇒ 正常执行，但 `缺口` 末尾追加固定文案 `预算上限缺口`：「近 10 分钟内查询已达 12 次，必须收尾并列出未覆盖项」（:142，判断在 :882） |
| 第 13 次及以后 | 每次仍注入同一条缺口，**不拦截**（防止半途断掉） |
| 未知工具名 | **不计数**（③ 名字门在 :859 提前 return，计次在 :866） |
| 必填参数缺失 | **不计数**（`校验必填` 在 :864，先于计次） |
| 工具失败 | 不注入缺口（失败结果先回错误码让模型纠正；注入只在成功分支 :882） |
| 图工具 | 计入预算；因无 `缺口` 字段，上限提示挂成**显式字段** `预算上限缺口`（:872） |

## 4. 错误码（9 个）

**形状**：`{ error: <码>, message: <中文说明> }`，作为 `isError: true` 的工具结果返回（`失败结果`，`case-mcp-server.ts:790`）。

| 码 | 触发面 |
|---|---|
| `bad_input` | 参数名不认识、类型不对、值越界（`收参数`，:650） |
| `not_found` | 实体/文件/档案不存在 |
| `not_a_member` | 非项目成员 |
| `forbidden` | 写工具非属主 |
| `too_many` | 结果超上限且不可截断语义下要求收窄 |
| `ambiguous_path` | 路径匹配多份材料 |
| `write_failed` | 写图/档案失败 |
| `tool_failed` | 工具内部错误 / 信封违约 |
| `unknown_tool` | 工具名不在分发范围 |

**前端新增**：每个码一句「人话引导」（D3 表），未知码不伪造引导。

## 5. 收尾行派生数据（前端，不入库）

**来源**：本 feature 新增纯函数 `closing-stats.ts`；输入是**本轮全部 assistant 消息的 parts**（`AssistantParts` 的 `props.messages` 经 `收尾部件(消息们, 取部件)` 合并）。tool part 挂在当步消息上、最终回答是另一条无 tool 的消息，只吃单条消息会恒为 0（2026-11-17 终审 F1）。

| 字段 | 类型 | 计算 |
|---|---|---|
| `查询次数` | `number` | `是信封工具键(part.tool)` 为真的 tool part 数（**不含**图工具；工具错误调用也计入） |
| `覆盖材料数` | `number` | 各次 `出处[].代表` 中**含 `#`** 的那些、`#` 之前文本的去重集合大小（实体 id / 账户号不是材料） |
| `缺口总项` | `number` | 各次 `缺口` 数组长度之和，**排除**以服务端上限文案开头的条目 |
| `首条缺口` | `string \| null` | 按调用顺序第一条非空缺口，同样排除服务端上限条目 |
| `已达上限` | `boolean` | 任一信封 `缺口` 条目以服务端 `预算上限缺口` 文案开头 |

**渲染规则**：
- `查询次数 === 0` ⇒ 整行不渲染（普通闲聊不出现统计）。
- `缺口总项 === 0` ⇒ 不显示缺口段。
- `已达上限 === true` ⇒ 附「已达 12 次上限，以下未覆盖项见工具卡缺口」。前端**不**自己数 12：服务端按 `(userId, projectId)` + 10 分钟窗口计数，前端按轮次计数必然对不上（2026-11-17 终审 F3）。
- 解析失败的工具输出跳过，不计入材料/缺口（`查询次数` 仍按工具键计入）。

**不变量**：该函数不 `JSON.parse` 原始文本，只用 `解析工具输出`（`envelope-parse.ts:90`）——解析口径全仓唯一（`#002-06`）。
