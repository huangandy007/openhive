# Contract · 前端工具卡 / 收尾行 / 入口

**Feature**: `015-ai-explore-mcp-tools` · **Version**: 1（2026-11-17）

实现出处：`packages/session-ui/src/components/envelope-tool.tsx`（工具卡）、`message-part.tsx`（消息尾部）、`packages/app/src/center/case-views/entity-profile.tsx`（入口）。

## 1. 工具卡（已落地，本期只验收）

| 块 | 内容 | 可见条件 |
|---|---|---|
| 标题 | `摘要` 原文 | 恒显示 |
| 副标题 | 人话工具名（`ui.envelopeTool.tool.<name>`） | 恒显示 |
| 入参 | `入参摘要(props.input)` | 有入参时 |
| 摘要 | `摘要` | 恒显示 |
| 口径 | `口径：<文本>` | `口径` 非空 |
| 空原因 | `为什么没有：<值>` + 第一条 `下一步.为什么` | `空原因` 非 null |
| 缺口 | `缺口` 列表（每条） | `缺口.length > 0` |
| 数据量 | `共 N 行 · X B` 或 `对象数据 · X B` | 恒显示 |
| 出处 | `事实 + 代表` 列表 | `出处.length > 0` |
| 下一步 | `工具名 + 为什么`，**不可点击** | `下一步.length > 0` |
| 原始 JSON | 原生 `<details>`，默认折叠 | 恒存在 |

**不得**：隐藏 `空原因` / `缺口`；把实体 id 当标题；把 `下一步` 做成按钮（一期）。

## 2. 错误卡（本期加一句引导）

现状（`envelope-tool.tsx:193-232`）：能解析成 `{error, message}` ⇒ 显示「错误码：<码>」+ 消息；解析不了 ⇒ 原样显示文本。

本期新增：在消息下加一行**人话引导**。

- 映射函数：`错误码引导键(码: string): string | undefined`（`envelope-parse.ts`）。
- i18n 键：`ui.envelopeTool.errorHint.<码>`，zh / en 各 9 条。
- 未知码 ⇒ `undefined` ⇒ **不渲染引导行**（只留原码与原文）。

## 3. 收尾行（本期新增）

**位置**：助手消息的最后一个 text part 之后，紧邻既有 `meta` 行（`message-part.tsx` `Show when={meta()}` 块内/后），复用同一行排版（`text-12-regular text-text-weak`）。

**输入**：当前消息的 parts（`data.store.part?.[message.id]`），不传全量会话。

**渲染**：

| 条件 | 输出 |
|---|---|
| `查询次数 === 0` | **不渲染** |
| `查询次数 > 0` | `本轮回答查询 {{count}} 次 · 覆盖材料 {{materials}} 份` |
| `缺口总项 > 0` | 追加 ` · 缺口 {{gaps}} 项`，并把 `首条缺口` 以 `title` 或紧随小字展示（只一条） |
| `查询次数 >= 12` | 追加 ` · 已达 12 次上限，未覆盖项见工具卡缺口`（对齐 `09` §8.2 的「已达 12 次上限，XX 未覆盖」） |

**i18n 键**：`ui.closingLine.summary` / `.gaps` / `.budget`。

**措辞纪律（FR-033）**：该行数字是**本条回答**的 parts 统计，不是服务端 10 分钟窗口计数，故写「本轮回答」；**禁止**写「本次探索」或暗示它等于预算窗口。10 分钟窗口口径只以工具卡 `缺口` 里的固定文案为准。

**口径（与预算的已知差异）**：`查询次数` 只数**信封工具**；图工具（`graph_*`）计入服务端预算但不计入此行。此差异必须在用例与报告里可见，不得改口径去「对齐」。

**不变量**：
- 只调 `closing-stats.ts` 一个纯函数，不在组件里重复过滤/解析（`#002-06`）。
- 纯函数与组件**不得同名**（`.ts` / `.tsx` 解析分歧风险）。
- 非信封工具 part、解析失败的 part 一律跳过。

## 4. 入口起手（本期新增两枚）

**位置**：`entity-profile.tsx` 头部操作区（与既有「发到会话」按钮同区）。

| 按钮 | 显示条件 | 点击行为 |
|---|---|---|
| 查个人 | `档().type === "人"` | `发到会话(「查一下『<规范值>』名下有哪些账户、与谁有资金往来，按时间窗给出结论和出处。」)` |
| 查个账户 | `档().type === "账户"` | `发到会话(「查一下账户『<规范值>』的资金往来：笔数、合计、对手排行与大额明细，并给出出处。」)` |

> 上表两句子是**本计划拟定的产品文案**（`09` §7.1 只规定「当前选中实体 + 时间窗」与落点，未给字面句），需评审后定稿；定稿前不得在别处复制第二份。

**行为契约**：
- 只**预填**输入框（`发送到会话` 的「替换」路径），**不自动发送**。
- 不新增路由跳转、不新增全局状态。
- 点击成功无 toast；失败沿用 `发送失败提示`（「没有会话」/「行数超限」）。
- 预填句逐字固定，用例断言整句（含实体名）。

**不显示**：类型为地点 / 号码 / 公司 / 其他时，两枚按钮都不出现。

## 5. i18n 命名空间

| 前缀 | 用途 |
|---|---|
| `ui.envelopeTool.*` | 既有工具卡文案（本期只加 `errorHint.*`） |
| `ui.closingLine.*` | 收尾行文案（新） |

**预填句不走 i18n**：沿用既有 `发到会话` 调用风格，中文句子内联在 `entity-profile.tsx`（与 :620 同款）；按钮名如需多语再走 i18n。

en 为从属：zh 缺键视为缺陷；en 缺键回退 zh（若现有 i18n 不回退，则用例必须覆盖 en 键存在）。
