# OpenHive 竞品差距分析与补齐建议

- **日期**：2026-09-05
- **状态**：待审阅
- **对标产品**：WorkBuddy（腾讯云企业版）、千问办公（阿里 QwenWork）
- **关联文档**：`2026-08-17-多用户多租户改造-design.md`、`2026-08-30-前端落地策略-opencode换皮-design.md`

## 1. 结论摘要

openhive 在**多租户架构层**（认证、隔离、RBAC、沙箱）设计扎实，达到企业级水平；但在**产品层**存在一个根本性的范式错位——它仍停留在「AI 编程工具」的形态，而目标场景（公安内网数据分析）需要的是一个「AI 研判平台」。

对标两个头部 AI 办公产品，openhive 缺失的关键能力按优先级：

| 优先级 | 缺失能力 | 一句话 |
|---|---|---|
| P0 | 范式纠偏 | 中栏从「代码编辑器」翻转为「数据 + 可视化」为主 |
| P0 | 交付层 | AI 一键生成研判报告 / 关系图谱 / 资金流向图 / 报表 |
| P1 | 业务技能资产化 | 沉淀可复用的「公安研判技能包」 |
| P1 | 可视化分析 | 关系图谱、资金链路图、时序图 |
| P2 | 治理后台 | 用量 / 成本 / 审计 / 组织架构 |
| P2 | 数据接入框架 | 运营商 / 银行 / OSINT 数据源管理 |

## 2. 竞品研究摘要

### 2.1 WorkBuddy（腾讯云）

定位「AI 原生桌面智能体工作台」，企业版三大能力：

1. **数字员工**：云端 7×24 运行，连接企业知识库 / 业务系统 / 连接器，内置 Skill，可创建、发布、复用、分发——把碎片知识沉淀为可管理的 AI 资产。
2. **「项目」人机协同**：人和 Agent 在同一项目共享上下文 / Skills / MCP，从「一个人带 AI」升级为「一群人和一群 Agent 共事」。
3. **企业管理后台**：组织架构、成员授权、统一审计、用量统计、成本优化。

交付三模式：SaaS / VPC 专享 / 私有化。定价 198 元/月/用户（SaaS）、316 元/月/用户（专有云）。

### 2.2 千问办公（阿里 QwenWork）

定位「**交付型 AI**——不止对话，更能交付」，基于 Qwen3.8。六大能力：

1. 钉钉深度打通（25 项企业协作能力）
2. Office 产物生成（Word/PPT/Excel/PDF，带公式、带母版）
3. 多模态理解与生成
4. **全栈免部署网页交付**（数据看板、H5、带数据库的小业务系统）
5. 专业数据源接入（1688、小红书等）
6. 技能与专家套件市场（研发/法务/财务/人事/电商预制技能）

### 2.3 两者共通的「下一代范式」

两个巨头殊途同归，都跨过了「AI 对话工具」这条线：

- **价值出口变了**：从「陪你聊天」变成「交付成品」（报告 / 表格 / 看板 / 系统）。
- **用户变了**：从「程序员」变成「业务人员」（写文档的、审合同的、做人事的）。
- **能力在资产化**：把经验 / 知识封装成可复用、可分发、可管理的「技能 / 数字员工」。

这三条是衡量 openhive 差距的标尺。

## 3. openhive 现状定位

从两份 specs 提炼：

- **技术底座**：opencode fork，SolidJS 原生前端换皮，多租户改造（每用户沙箱 + 每用户 SQLite + RBAC/RLS）。
- **目标场景**：公安内网，100+ 用户，话单分析、资金分析。
- **产品形态**：三栏（资源管理器 20% / 代码编辑器 50% / AI 会话 30%），话单/资金是「复用三栏框架的工作区」。
- **AI 能力**：复用 opencode 原生会话（对话 + 改文件），资源面板有 Skills/MCP/知识库。

**一句话定位**：openhive 目前是「给民警用的 AI 编程工具 + 多租户」，而不是「给民警用的 AI 研判平台」。

---

## 4. 核心诊断：范式错位

这是所有差距的根。具体表现为三处：

1. **中栏是代码编辑器（占 50% 主战场）**——但民警不写代码，opencode 的 IDE 基因没洗掉。
2. **AI 的产出停在「对话」**——分析完还得民警手动整理成报告，产品没有「交付物」概念。
3. **Skills 是技术型 skill**——没有「公安业务技能」，而业务技能才是垂直产品的护城河。

---

## 5. 完整差距清单（7 条）

每条按「竞品做法 → openhive 现状 → 差距 → 建议」展开。

### 差距 1｜范式错位：中栏从「代码编辑器」翻转为「数据 + 可视化」⭐️ 最根本

- **竞品做法**：WorkBuddy / 千问都面向非程序员业务人员，界面以「业务数据 / 交付物」为核心，而非代码。
- **现状**：三栏中栏 50% 给代码编辑器，话单/资金只是「复用三栏框架的额外工作区」（§8.2「中栏为主战场」、§9.1）。
- **差距**：产品的默认形态是「IDE」，而核心用户不需要 IDE。代码编辑器对民警几乎无用，却占据了最核心的屏幕空间和心智定位。
- **建议**：把产品心智从「IDE」翻转成「分析工作台」。中栏从单一的「代码编辑器」改为**多形态内容区**——民警最高频的 Word / Excel / PPT / 思维导图 / 图文混排文档、数据明细、可视化图表都是中栏的一等公民，按内容类型自动切换合适视图；代码编辑器降级为「少数技术用户的可选工作区」。specs §9 的「工作区抽象」方向是对的，但权重分配反了——话单 / 资金 / 文档应是主角，代码应是配角。

### 差距 2｜没有「交付层」：AI 只能聊，不能出成品 ⭐️ 最致命

- **竞品做法**：千问的灵魂是「交付型 AI」——直接产出 Word/PPT/Excel/看板/带数据库的小系统；WorkBuddy 的「数字员工」也以交付业务结果为目标。
- **现状**：§9.3 的 AI 联动只到「选中数据 → AI 在会话里回复」就停，没有任何「产物生成」层。
- **差距**：AI 分析完，民警还得**手动把结论整理成报告**。产品价值链上最该补的一环缺失——而这恰恰是民警「为什么用你的产品」的理由。
- **建议**：补「交付层」，让 AI 一键产出研判所需的**交付物**：
  - 📄 研判报告（Word/PDF，自动套用模板、结构化结论）
  - 🕸️ 话单关系图谱（谁和谁通话、频率、聚类、核心人员）
  - 💰 资金流向图（来源 → 中转 → 去向、分层转移）
  - 📊 统计报表（汇总指标、趋势图）

  这些产物生成后直接在中栏（多形态内容区）打开查看 / 编辑——「AI 生成 → 中栏交付 → 存回案件」形成闭环，民警全程无需离开平台、无需手工整理格式。

### 差距 3｜缺「业务技能资产化」：Skills 停在技术层，没有「公安业务技能包」

- **竞品做法**：WorkBuddy 的「数字员工」= 把企业碎片知识封装成可复用、可分发、可管理的 AI 资产；千问有「专家套件市场」（法务/财务/人事/研发预制技能，开箱即用）。
- **现状**：资源面板（§8.7）的 Skills 是 opencode 原生技术型 skill（格式化、计算、图表），没有业务技能概念。
- **差距**：缺「业务级技能包」——「话单关系分析」「资金链路追踪」「涉案人员画像」「同案串并」等。这些是民警「一键复用老民警经验」的东西，也是产品**最深的护城河**（竞品有通用技能，但没有公安业务技能）。
- **建议**：在资源面板之上，抽象一层「业务技能」：可创建、可命名、可复用、可团队共享、可版本化，运行时把业务技能翻译成「提示词 + 工具调用 + 数据访问」的组合。

### 差距 4｜缺可视化分析：话单/资金只有「表格」，没有「图谱」

- **竞品做法**：千问的「看板 / 图表」是核心能力之一。
- **现状**：§8.14 话单/资金中栏形态是「数据明细表 + 筛选导出」，specs 里完全没有关系图谱、资金链路图、时序图。
- **差距**：对公安研判，「一张通话关系网络图」比一万行表格更能让民警一眼看出「谁是核心、谁在串联」；「资金流向桑基图」是资金分析标配。可视化缺失直接决定产品专业度。
- **建议**：话单/资金工作区补「图谱视图」（关系图、桑基图、时序图、热力图），与「明细表」双视图切换。

### 差距 5｜管理后台单薄：只有「账号 CRUD」，没有「治理」

- **竞品做法**：WorkBuddy 的企业后台是打企业市场的王牌——组织架构、成员授权、统一审计、用量统计、成本优化。
- **现状**：管理员后台（§4.2）只做了录入/重置/停用/脱敏开关。
- **差距**：缺运营治理维度：
  - **用量/成本看板**：谁调了多少次模型、花了多少 token、各单位成本分摊（§5.4 有分析库，但没落到「管理员用量看板」）。
  - **审计看板**：§12.1 埋了审计日志，但没设计「管理员怎么查看」的界面。
  - **组织架构树**：用户表有 org/dept/section 字段，后台却是平铺列表。
- **建议**：管理员后台从「账号管理」扩成「账号 + 组织 + 用量 + 审计」四块；组织树、用量统计、审计检索是内网合规的刚需。

### 差距 6｜数据接入能力未展开：缺「数据源管理框架」

- **竞品做法**：千问能接入 1688、小红书等外部数据源，自动抓取竞品/评论/诊断数据。
- **现状**：§9.5 说数据来自旧系统（蜂巢/小蜜蜂），「数据接入是主要工程量」，但设想只到「迁移/对接旧系统 + 查询 API」。
- **差距**：公安研判的数据来源远不止旧系统——运营商话单、银行流水、社保、轨迹、OSINT 开源情报。缺一个「数据源接入层」的框架设计。
- **建议**：抽象「数据源接入层」：数据源注册、连接器（connector）、抽取/清洗、脱敏、血缘追踪。话单/资金模块的数据层都基于这一层。

### 差距 7｜协作偏浅：共享项目只共享「文件」，缺「协同研判」

- **竞品做法**：WorkBuddy 的「人机协同项目」、千问的钉钉打通。
- **现状**：§11 共享项目只共享「文件」（git 仓库），会话彻底私有（「共享结果不共享过程」）。
- **差距**：协作只有「文件共享」，缺「协同研判」——多民警合办案件时，需要共享的是「分析结论 / 证据链 / 研判进展」，而不只是文件。
- **建议（有边界地增强）**：公安办案强调保密与留痕，不宜照搬 WorkBuddy 的开放协同。可在共享项目内增加「共享结论 / 标注 / 研判时间线」，但仍保持：会话私有、全程审计留痕、权限最小化。

## 6. P0 重点设计建议（展开）

### 6.1 范式纠偏：从 IDE 到研判工作台

**目标**：让民警打开 openhive，第一眼看到的是「案件 / 数据 / 分析」，不是「代码编辑器」。

- **默认工作区反转**：登录后默认进入「研判工作台」（案件列表 / 数据面板），而非空代码项目。代码工作区退为「高级用户」入口。
- **三栏重定义**：左栏 = 案件 / 数据导航；中栏 = **多形态内容区**（不再默认代码编辑器）；右栏 = AI 会话。
- **中栏多形态内容区**：民警最高频处理的 Word / Excel / PPT / 思维导图 / 图文混排文件，中栏须提供「在线查看 + 实时编辑」（对标千问的 Office 在线编辑能力）；数据明细与可视化图谱（关系图 / 桑基 / 时序）与文档并存，按内容类型切换视图。
- **「案件」作为一级对象**：把 specs 里的「项目」抽象对齐到公安语境——「项目 = 案件」，案件聚合话单 / 资金 / 证据 / 研判过程。这比「git 仓库」更贴合用户心智。

### 6.2 交付层：研判产物生成

**目标**：让「生成研判报告 / 图谱 / 报表」成为一等公民功能，而非事后手动整理。

- **产物类型**：研判报告（Word/PDF）、关系图谱、资金流向图、统计报表，全部可由 AI 从「选中数据 + 会话上下文」一键生成。
- **报告生成链路**：勾选数据 / 结束一段分析 → 点「生成报告」→ AI 套用**报告模板**（标题 / 案情摘要 / 分析过程 / 结论 / 附件图谱）→ 产出可编辑 Word/PDF → 存回案件空间。
- **模板体系**：管理员可配置「报告模板」和「图谱样式」，保证全单位输出格式统一（对标千问的「PPT 保留母版」）。
- **产物落库**：交付物作为案件资产存回沙箱 / 对象存储，可回溯、可导出、可归档。

## 7. 补齐优先级与路线图

| 阶段 | 事项 | 依赖 | 说明 |
|---|---|---|---|
| **P0** | 范式纠偏（默认工作区反转 + 三栏重定义） | 现有 specs §8/§9 | 决定产品是谁的，立项级 |
| **P0** | 交付层（研判报告 / 图谱 / 报表生成） | 依赖可视化基础 | 产品的价值出口 |
| **P1** | 可视化分析（关系图谱 / 资金链路 / 时序） | 数据接入 | 研判专业度 |
| **P1** | 业务技能资产化（公安研判技能包） | 资源面板 §8.7 | 护城河 |
| **P2** | 治理后台（用量/成本/审计/组织树） | 分析库 §5.4 | 内网合规，可晚做但要留接口 |
| **P2** | 数据接入框架 / 协同研判增强 | 旧系统改造节奏 | 依赖外部，别过早 |

**关键原则**：P0 的两项（范式纠偏 + 交付层）是「产品成立与否」的问题，应先于一切工程细节确定；P1 是「产品好不好」的问题；P2 是「产品能不能规模化、能不能合规」的问题。

## 9. 待决策点

1. **真实用户与核心场景确认**：核心用户是否确为民警？话单/资金分析是否为最高频场景？「代码编辑」是否基本无用（决定范式纠偏是否成立）？
2. **「案件」作为一级对象**：是否要把「项目」重命名为「案件」，并聚合话单/资金/证据？这是范式纠偏的落点，需产品侧拍板。
3. **交付层优先级 vs 工期**：P0 的「交付层」工程量不小，是否接受「先做报告生成，图谱/报表次之」的分期？
4. **业务技能的范围**：第一批「公安研判技能包」具体包含哪几个（话单关系分析、资金链路追踪、涉案画像……），需业务专家（老民警）输入。
