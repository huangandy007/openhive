---

## 0. 一句话

把中栏表格从「一坨挤在一起的裸表格」改造成**只读、Excel 式、可筛选可调宽可隐藏列**的表格阅读器；不做编辑与统计（交给右栏 AI），并把打开/浏览速度做成硬指标。

---

## 1. 背景：用户原话与诉求映射

2026-10-18 用户反馈（逐条保留原意）：

1. 希望像 Excel 一样浏览；目前中栏数据打开**挤在一起**；
2. 行高自动不一致，**姓名被垂直排列**；时间显示不是 `yyyy-mm-dd hh:mm:ss`；
3. 不能**隐藏/显示列**，不能跟随业务分析的心理需求；
4. 不能**调宽/缩小列宽**；
5. 不能**筛需要的行**；
6. 用户**不会**在中栏编辑数据或做统计，这些交给右栏 AI；
7. 希望打开/浏览**速度快**。

映射到本期能力：

| 诉求 | 能力 |
|---|---|
| 1 | Excel 式阅读骨架：冻结表头、行号列标、网格线、固定行高、单元格内边距 |
| 2 | 单行不折行 + 省略号；日期时间统一格式 |
| 3 | 列显示/隐藏（全部列复选清单） |
| 4 | 列宽拖拽 + 双击自适应 + 初始宽度估算 |
| 5 | 按列筛选（多列 AND） |
| 6 | **只读**，不做编辑/公式/统计 |
| 7 | Worker 解析、首屏分阶段、虚拟滚动、缓存 |

补充确认纳入：**点表头排序**、**Ctrl+F 查找**。多工作表切换**不纳入**，但必须明确告知。

## 2. 事实核查（现状与根因）

### 2.1 当前渲染路径

`packages/app/src/center/views/sheet-view.tsx`：

1. `XLSX.read(bytes, { type: "array", codepage: 65001 })` **在主线程整份解析**；
2. `sheet_to_json` 裁到 `1000 行 × 64 列`；
3. 逐格创建 `<td>`，塞进一个**没有样式、没有列宽模型、没有表头**的裸 `<table>`。

### 2.2 缺陷根因（与用户症状一一对应）

| 症状 | 根因 |
|---|---|
| 挤在一起 | 无列宽模型、无单元格内边距、`table` 无边界样式 |
| 行高不一致、姓名竖排 | 未设 `table-layout: fixed` 与 `white-space: nowrap`，CJK 逐字折行 |
| 时间格式不对 | 直接使用 SheetJS 的显示文本 `w`（随文件格式而变），未做列级规范化 |
| 不能调宽/隐藏列/筛选 | 渲染是一次性 `textContent` 写入，没有列模型与交互状态 |
| 大表卡顿 | 解析在主线程；DOM 行数随表增长 |

### 2.3 已有基础件

- `@tanstack/solid-virtual` **已是仓库既有依赖**（上游文件树/时间线在用），虚拟滚动不新增包；
- Kobalte 的菜单/弹层/输入组件现成；
- `BinaryView` 的 `BytesRenderer` 契约已支持「异步渲染 + 返回 cleanup」，错误分档（`encrypted` / `error` / `empty`）现成；
- `/file/content` 只支持整文件读取（无 `offset/limit`）——本期不做服务端分页。

### 2.4 中栏架构约束

`center-content.tsx` **只渲染当前激活 Tab**，切 Tab 会卸载视图。因此：

- 列宽、筛选等 UI 状态必须存在视图之外，否则切回即丢；
- 数据缓存是可选加速项（见 §8.2）。

## 3. 目标与非目标

### 3.1 目标

1. Excel 式阅读骨架 + 列宽 + 隐藏列 + 筛选 + 排序 + 查找；
2. 打开/浏览速度达到 §11 的硬指标；
3. 现有「加密 / 损坏 / UTF-8 CSV / HTML 当文本 / 截断必须明说」等不变量一条不少；
4. 与上游合并面为零：不新增依赖、不改后端、不碰 `BinaryView` / `center-content` / `view-registry`。

### 3.2 非目标

- 编辑、公式、统计、图表、条件格式；
- 多工作表切换（只显示第一张，但必须告知）；
- 单元格样式还原（颜色/字体/边框）、合并单元格渲染、公式栏；
- 多级排序；
- 服务端分页 / 流式取数 / Range 直读；
- 跨会话持久化；
- 视图内下载按钮（预览档提示用户从文件树下载）。

## 4. 规模分层

### 4.1 阈值（可调常量，单一来源）

```ts
export const 规模 = {
  首屏行数: 200,
  预览行数: 1000,
  预览列数: 64,
  全量行上限: 100_000,      // 数据行，不含表头
  全量格上限: 4_000_000,    // 行 × 列的保护上限（防极宽表）
  全量列上限: 256,
  分块行数: 5000,
  缓存格上限: 200_000,
  缓存份数: 3,
  UI状态缓存份数: 20,
} as const
```

### 4.2 分档行为

| 档 | 判据 | 行为 |
|---|---|---|
| **全量档** | 数据行 ≤ 10 万 **且** 总格数 ≤ 400 万 | 全量解析；排序/筛选/查找作用于全部数据 |
| **预览档** | 数据行 > 10 万 **或** 总格数 > 400 万 | 只物化前 1000 行 × 64 列；横幅明确告知；**不提供「加载全部」**；排序/筛选/查找只作用于预览数据；提示用户从文件树下载后用 Excel/WPS 查看 |

补充规则：

- 预览档横幅文案必须写出**原表总行数/总列数**与**当前显示的截断范围**，不允许静默少给；
- 400 万格保护上限即使行数未超也生效（例如 200 列 × 9 万行）；
- 全量档列数超过 256 时，只显示前 256 列并在横幅说明截断（与预览档同一套“明说”规则）；
- 多工作表：只显示第一张，横幅写「工作簿共 N 张表，当前仅显示：表名」；
- 表格扩展名集合继续复用 `center/views/index.ts` 的 `表格扩展名` 常量，不另写一份。

## 5. 架构

### 5.1 数据流

```
点击文件
  └─ 现有打开闸门（表格 5MB，不变）
      └─ BinaryView 取字节、解 base64
          └─ renderSheet(bytes, container)
              ├─ 命中数据缓存（§8.2）→ 直接挂载网格
              └─ 否则启动解析客户端
                  ├─ Worker（首选）／主线程分块（降级）
                  ├─ 首屏：表名、总行/总列、首行表头、前 200 行、列类型采样
                  │    → 立刻挂载网格并渲染表头与前 200 行
                  ├─ 判定档位
                  │    ├─ 全量档 → 每 5000 行一块回传
                  │    └─ 预览档 → 只回前 1000 行 × 64 列 + 总数，done(mode:"preview")
                  └─ done / error
                      → 排序、筛选、查找在已加载数据上生效
```

**关键**：首屏不等全量；解析期间界面可滚动、可切 Tab、可操作右栏。

### 5.2 解析协议

```ts
type 请求 = {
  id: number
  bytes: ArrayBuffer          // transfer，零拷贝
  limits: typeof 规模
}

type 回包 =
  | { type: "meta"; id: number; sheetNames: string[]; sheetName: string;
      totalRows: number; totalCols: number; header: string[];
      preview: Cell[][]; columnTypes: ColumnType[] }
  | { type: "chunk"; id: number; start: number; rows: Cell[][] }
  | { type: "done"; id: number; mode: "full" | "preview";
      truncatedRows?: number; truncatedCols?: number }
  | { type: "error"; id: number; kind: "password" | "parse"; message: string }
```

- `Cell = string | null`；
- 日期在解析端就转成 `yyyy-MM-dd HH:mm:ss` 规范串；零填充规范串按字典序即时间序；
- 列类型 `ColumnType = "text" | "number" | "date" | "datetime"`，由首屏采样推断；
- 陈旧 `id` 的回包一律丢弃；关闭 Tab / 换文件时 `cancel()` 并 `terminate()`。

### 5.3 解析策略

1. **首屏解析**：`XLSX.read(bytes, { sheetRows: 1001, cellNF: true, codepage: 65001 })`（**不要 `cellDates: true`**，理由见 §6.5 的探针记录）；
   - 用 `!fullref`（若存在）读原表真实范围；同时用 `!ref` 取首屏范围；
   - 首屏已经拿全（总行 ≤ 1001）时，不再二次解析；
   - 小表一次解析完成，避免无谓开销。
2. **全量解析**：仅当首屏未拿全且落在全量档时，再做一次不带 `sheetRows` 的解析，分块回传；
3. **预览档**：只保留首屏解析结果（裁到 1000 行 × 64 列），不回传全量；
4. `sheetRows` / `!fullref` 在 CSV 与老 `.xls` 上的可靠性**实现时先用夹具探针确认**；若不可靠，退回「解析后计总行」并如实登记（见 §14）。

### 5.4 渲染结构

- 用 `div[role="grid"]`，不用 `<table>`：
  - 每行 `display: grid` + 固定 `grid-template-columns`；
  - 表头 `position: sticky; top: 0`；
  - 行号列 `position: sticky; left: 0`；
  - 垂直用 `@tanstack/solid-virtual`，只渲染视口 + overscan（8 行）；
  - 水平原生滚动；行高固定 28px，因此无需测量行高；
  - ARIA：`aria-rowcount` / `aria-colcount` / `role="row"` / `role="gridcell"`。
- 文字选择继续走浏览器原生选区（`select-text` 已由 `BinaryView` 容器提供），`send-to-session` 无需改动。

### 5.5 接线与文件落点

| 文件 | 动作 |
|---|---|
| `packages/app/src/center/views/sheet-view.tsx` | **保留**导出 `SheetView` / `renderSheet`，并从 `sheet-model` re-export `行上界` / `列上界` / `是加密工作簿`（既有测试与调用点不因搬家失效）；渲染实现改为「**先 await 首屏解析**（加密/损坏在此抛给壳）→ 挂载网格 → 返回 cleanup」；不再直接引 `XLSX` |
| `packages/app/src/center/views/sheet/sheet-model.ts` **（新）** | 纯逻辑：类型、日期规范化、列类型推断、列宽估算、排序/筛选/查找、规模常量、`是加密工作簿`（从 `sheet-view.tsx` 移入并 re-export） |
| `packages/app/src/center/views/sheet/sheet-parse.ts` **（新）** | 解析客户端：Worker 优先、主线程分块降级、协议编解码、`cancel` |
| `packages/app/src/center/views/sheet/sheet-parse-worker.ts` **（新）** | Worker 入口；`new Worker(new URL(...), { type: "module" })` |
| `packages/app/src/center/views/sheet/sheet-grid.tsx` **（新）** | 网格：虚拟滚动、粘性表头/行号、列宽拖拽、单元格渲染 |
| `packages/app/src/center/views/sheet/sheet-controls.tsx` **（新）** | 工具栏、列清单浮层、筛选浮层、查找条、横幅/筛选条 |
| `packages/app/src/center/views/sheet/sheet-state-cache.ts` **（新）** | UI 状态 LRU + 解析数据 LRU |
| `packages/app/src/index.css` | 仅新增 `[data-component="sheet-view"]` 作用域样式（`flex:1; min-height:0; padding:0; overflow:hidden`）与网格样式；不改全局 `table` 规则 |

约束：

- 不改 `BinaryView` / `center-content.tsx` / `view-registry.ts` / 后端；
- `sheet-parse.ts` 的主线程降级路径 **动态 import `xlsx`**，避免把解析库提前拉进首屏 chunk；
- `index.test.tsx` 有一条「视图必须动态 import」的源码守卫，改完须重跑。

## 6. 阅读骨架

### 6.1 行与单元格

- 固定行高 **28px**；单元格 `padding: 0 8px`；垂直居中；
- `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`；
- 悬停显示完整内容：v1 用原生 `title` 属性（零新组件、零浮层开销）；
- 对齐照 Excel：数字、日期右对齐；文本左对齐；空值为空白；
- 网格线：单元格右边/下边 1px 浅色线，表头底边加深；悬停整行浅高亮；不做斑马纹。

### 6.2 列宽

- `table-layout: fixed` 的等价物：固定 `grid-template-columns` 像素宽度；
- 初始列宽：采样前 200 行 + 表头；全角字符按 13px、半角按 7px 估算，加 16px 内边距，钳制 `[64px, 320px]`；
- 拖拽：列边界 5px 热区，最小 48px、最大 800px；
- 双击边界：按内容自适应；扫描上限 1000 行，避免大表卡顿；
- 列宽存 UI 状态缓存（§8.1）。

### 6.3 冻结与定位

- 表头行冻结；横向滚动时列名始终可见；
- 行号列冻结在左侧，宽度 56px；
- 表头单元格内用淡色小字显示列标 `A/B/C`（不单独占一行）；
- 行号显示**原始 Excel 行号**；首行作为表头时数据行从 `2` 开始；
- 排序/筛选后行号**不变**（仍指向原表行号）。

### 6.4 首行与表头

- 默认**首行作为表头**：加粗、浅底色、冻结；
- 列显示/隐藏、筛选、排序的列名取首行文字；空表头回退列标；
- 重复表头名允许存在，内部以列序号为键；列清单用 `A/B/C` 区分；
- 工具栏提供「首行是表头」开关，关闭后首行还原为普通数据行。

### 6.5 日期时间

- 列级类型推断：某列 ≥80% 的非空采样单元格可识别为日期/时间 ⇒ 该列按日期处理；
- 格式：有时间分量 → `yyyy-MM-dd HH:mm:ss`；纯日期 → `yyyy-MM-dd`；
- 转换路径（**不做时区平移**）：
  - **主路径：Excel 序列号** → `XLSX.SSF.parse_date_code(serial)` 直接得到 `{y,m,d,H,M,S}` 墙上时间分量；读取参数保持默认 `cellDates: false`，避免 JS `Date` 的时区语义；
  - JS `Date`（防御性分支，正常情况下不会出现）→ 用 UTC getter 取分量（与 SheetJS 的存储口径一致）；
  - 文本（SheetJS 未识别成日期时）→ 正则拆分年月日时分秒，**禁止** `new Date("YYYY-MM-DD")`（会按 UTC 解释）；
- 无法识别为日期的文本原样显示，不猜；
- 日期列右对齐。

> **探针实测（2026-10-18，本机 bun + xlsx）**：
> - `sheetRows: 1001` 在 `.xlsx` 与 `.xls`（biff8）上都保留 `!fullref`：`!ref=A1:B1001`、`!fullref=A1:B1500`；CSV 无 `!fullref`（但 CSV 解析便宜，可全量读后计数）。
> - `cellDates: true` 时，xlsx 日期格读回 `t:"d"`、`v` 的 UTC 时刻等于墙上时间（时区语义含糊）；改为默认 `cellDates: false` 后，日期格是 `t:"n"`、`v:46296.354166…`，`XLSX.SSF.parse_date_code` 交回 `{y:2026,m:10,d:1,H:8,M:30,S:0}`——正是墙上时间。
> - CSV 的 `2026-10-01 08:30:00` 同样落成序列号，且 `w` 保留原文；因此主路径对 CSV / xlsx 统一。

## 7. 阅读控制

### 7.1 列显示 / 隐藏

- 单列入口：列头 `⋯` 菜单 →「隐藏此列」；
- 全局入口：工具栏「列」→ 全部列复选清单（可搜索），含「全部显示」「重置」；
- 隐藏列不渲染（跳过列模板与单元格），提升性能；
- 工具栏显示「显示 12 / 40 列」；
- 被隐藏列上的筛选**保留并标注“该列已隐藏”**；
- 所有列被隐藏时显示空态 +「全部显示」。

### 7.2 筛选

- 列头漏斗 → 浮层：值清单（计数、复选、搜索）、文本条件（包含/等于/为空）、清除本列；
- 多列筛选 **AND**；
- 筛选条：每条条件可单独删除；「清除全部」；
- 行数摘要：「筛选后 1,234 行 / 共 56,789 行」；
- 结果为空时显示空态 +「清除筛选」；
- 值清单最多先列 1000 个不同值，其余通过搜索收窄；
- 只作用于已加载数据；预览档横幅已说明。

### 7.3 排序

- 点列头循环：升序 → 降序 → 取消；列头显示 ▲/▼；
- **单列排序**（多级排序不做）；
- 规则：数字按数值、日期按规范串字典序、文本按 `Intl.Collator("zh")`、空值无论升降序都排最后；
- 排序稳定；
- 行号仍显示原始 Excel 行号。

### 7.4 查找

- `Ctrl+F` / `Cmd+F` 打开查找条；`Esc` 关闭；
- 输入框、上一处/下一处、`第 n / 共 m 个`；
- 范围：已加载的**全部行 × 可见列**（隐藏列不搜）；
- 命中项：当前项滚动到视口并高亮，其余命中淡高亮；
- 查找与筛选独立：筛选只影响显示，查找仍搜全部已加载数据；
- 无命中显示「0 个」；
- 输入去抖 150ms。

## 8. 状态、缓存与生命周期

### 8.1 UI 状态缓存

- 内容：列宽、隐藏列、筛选、排序、首行开关、滚动位置（纵向/横向）；
- 键：`path + "\n" + 当前重载代(path)`；LRU 最多 **20** 份；
- 切 Tab 再回来原样恢复；关 Tab 后保留，LRU 淘汰；
- 同一文件在左右两栏各开一份时**共享同一份缓存条目**：后挂载的一栏读到当时的列宽等状态；一栏改动**不会实时推送**到另一栏（2026-10-18 真栈实测：左栏 64 → 184px，右栏保持 64px，见 §14.1）；
- `当前重载代` 通过 `untrack` 读取，避免把缓存读取挂进无关的响应式依赖。

### 8.2 解析数据缓存

- 仅缓存 **≤20 万格**的解析结果，LRU 最多 **3** 份；
- 键同 §8.1（含重载代），重载后旧缓存自动失配；
- 命中时跳过解析，但仍会经过 `BinaryView` 的取字节（下载）流程——**缓存省的是解析，不是取数**；
- 更大的表不缓存，切回时重新解析并显示进度；
- 理由：常见台账/名单切换近瞬时；多张大表同时缓存会吃光内存。

### 8.3 生命周期

- 每个网格实例一个解析客户端；卸载/换文件时 `cancel()` + `terminate()`；
- 后台解析不残留；
- 数据缓存与 UI 缓存均为模块级，不随组件卸载丢失。

## 9. 错误与降级

| 情形 | 行为 |
|---|---|
| 工作簿加密 | 解析端回 `kind:"password"` → 抛 `需要密码(...)` → 壳落 `encrypted`；**不说“损坏”** |
| 解析失败（首屏未出） | 抛给 `BinaryView` → 壳落 `error` |
| 解析失败（首屏已出） | 保留已加载行；横幅「解析中断，当前仅显示前 N 行」；**不把残缺当完整** |
| Worker 不可用 / 创建失败 | 自动降级主线程分块解析，功能一致 |
| Worker 崩溃 | 同「首屏已出后失败」；终止 Worker |
| 空表 / 零数据行 | 显示「这张表没有数据」 |
| 所有列隐藏 | 空态 +「全部显示」 |
| 筛选无结果 | 空态 +「清除筛选」 |
| 用户关闭 Tab | cleanup 卸载网格并终止解析 |

## 10. 边界清单

- 残缺行按最宽行补 `null`，列不错位（现有不变量保留）；
- 合并单元格只显示左上角值，不画合并；
- 公式显示缓存值，不显示公式；
- 空表头格回退列标；
- 筛选落在隐藏列上：条件保留并标注；
- 空值排序恒排最后；
- 预览档的排序/筛选/查找只作用于预览行，横幅写明；
- 多工作表只显示第一张，横幅写明总表数；
- 超长表头/单元格：省略号 + 悬停全文；
- CSV 中文编码：继续使用 `codepage: 65001`；
- 单元格 HTML 一律按文本渲染（安全不变量）；
- 数字长 ID：沿用 Excel 的显示语义（科学计数法等），本期不改。

## 11. 性能目标（真机校准项）

基准：**5 MB / 约 5 万行 × 40 列**的表格。

1. 点击打开后 **≤1 秒**出现表头与前 200 行（不白屏）；
2. 解析期间界面不冻结：可滚动、可切 Tab、可操作右栏；
3. 全量就绪后，排序/筛选/查找 **≤200ms** 响应；
4. 关闭 Tab 后 Worker 终止、内存回落（浏览器任务管理器实测）；
5. 10 万行表的解析耗时与峰值内存**必须实测并记录**，未达标则回退阈值或调优。

数字未校准前不写成“已达标”；真机结果写入缺口表。
