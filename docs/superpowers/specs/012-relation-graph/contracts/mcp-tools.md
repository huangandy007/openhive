# 契约 · AI 改图的 5 个工具

**文件**：`packages/opencode/src/server/openhive/case-hgraph-tools.ts`（新）
**注册**：`case-mcp-server.ts` 的 `TOOLS` + `工具名` 联合 + `分发表`；`graph_add / graph_update / graph_remove` 同时加进 `写工具名`（属主门）。
**实现**：全部转调 `hgraph-ops.ts` 的 `应用并写回(...)`。**工具层不写任何写盘逻辑**（唯一写入者）。

**共 5 个**（`08` §6.2 定死，不多不少）。返回**不套**查库工具的七字段信封（`case-mcp-server.ts` 的信封校验对 `图工具名` 集合跳过）。

## 0. 三道门（沿用，不新写）

| 门 | 位置 | 行为 |
|---|---|---|
| 身份 | `case-mcp-server.ts:670` | `_meta` 目录必须恰为 `<workspaceRoot>/<userId>/<projectId>`，否则 `identity_required` |

## 1. `graph_list`

**入参**：无

**返回**：
```jsonc
{ "图": [ { "路径": "分析/张三资金流向.hgraph", "标题": "张三资金流向", "节点数": 42, "更新时间": "2026-11-15T10:03:00+08:00" } ] }
```

- 扫描项目目录下的 `.hgraph`（跳过 `.git`、跳过超深目录的隐藏目录由既有遍历规则决定；实现复用目录遍历，不新写）。
- 解析失败的文件**照列**，`节点数: null`，另加 `"打不开": true`——不因为一份坏文件让整个列表失败。

---

## 2. `graph_read`

**入参**：`{ "路径"?: string }`

**返回**：
```jsonc
{ "路径": "...", "版本": "...", "节点": [ … ], "边": [ … ], "文字": [ … ] }
```

- 节点/边对象**原样**（含 `出处` / `证据` / `时间` / `来源`），不裁剪、不改名——模型改前先看的就是这份。
- 超过 50 个节点时**不截断**（读是产物本身，本就在几百 KB 内）；文件 > 2 MB 时返回 `bad_input`：「这份图太大，请先在界面里拆分」。

**路径省略规则**（5 个工具共用，`08` §6.6）：

| 项目里的图数量 | 不带 `路径` |
|---|---|
| 恰好 1 张 | 用它，并在返回里明说 `"路径": "…"`（不让模型猜） |
| 0 张 | `not_found`：「这个项目里还没有关系图」 |
| ≥ 2 张 | `ambiguous_path`：「项目里有 N 张图，请先调 graph_list 并点名要改哪一张」——**不猜** |

## 3. `graph_add`

**入参**：
```jsonc
{
  "路径": "分析/张三资金流向.hgraph",
  "节点": [ { "临时id": "tmp1", "名称": "张三", "类型": "人员",
             "来源": { "kind": "实体", "实体": "ent_x", "值": "张三", "库类型": "人", "可信": "已确认" },
             "出处": ["mat_x#Sheet1#12"], "时间": { "首": "2026-01-03", "末": "2026-05-11" },
             "属性": [] } ],
  "边":   [ { "临时id": "tmpE1", "从": "tmp1", "到": "n3", "标签": "转账", "性质": "事实",
             "方向": "有向", "证据": [{ "关系": "rel_1", "出处": "mat_x#Sheet1#12" }],
             "出处": ["mat_x#Sheet1#12"], "时间": { "首": "", "末": "" } } ],
  "批次": "ai-1", "幂等键": "…"
}
```

**返回**：
```jsonc
{ "路径": "...", "版本": "...", "映射": { "tmp1": "n7" }, "复用": ["张三"],
  "新增": { "节点": 1, "边": 1 }, "放置": [{ "临时id": "tmp1", "x": 412, "y": 268 }] }
```

**规则**：

| 规则 | 说明 |
|---|---|
| 单次 ≤ 50 | 节点 + 边合计 > 50 ⇒ `too_many`：「一次最多 50 条，请分批」 |
| 整批原子 | 任一条不合格 ⇒ 一条都不写（不是前 29 条留下） |
| 署名复用 | 图上已有**同名且同类型**的节点 ⇒ 复用它、不新建，返回 `复用` 里点名「复用了已有节点 张三」；同名不同类型照常新建 |
| 放置 | 没给 `x/y` ⇒ 服务端放置（邻居外圈 → 既有节点质心 → 画布中心；不叠、不随机） |
| 硬闸 | 事实缺出处 / 推断缺依据或可信度 ⇒ 整批拒绝，原话见 `hgraph-format.md` §2 |
| 幂等 | 同 `幂等键` 重试 ⇒ 返回上次结果，不重复写 |

## 4. `graph_update`

**入参**：
```jsonc
{
  "路径": "...",
  "目标": [
    { "类别": "节点", "id": "n3", "字段": { "名称": "张三丰", "备注": "…" } },
    { "类别": "边",   "id": "e1", "字段": { "标签": "大额转账", "性质": "推断" } }
  ],
  "批次": "ai-1"
}
```

- 可改字段白名单：节点 `名称/类型/细类/外环/备注/出现序/锁定/样式`；边 `标签/性质/方向/备注/线宽档/出现序`；文字 `内容/字号/加粗/颜色/对齐/宽度/出现序`。
- **改 `性质` 为「推断」同样过硬闸**（必须有 `依据` + `可信度`）——否则模型能从这条绕过去（08 §6.3 的教训）。
- `id` 不存在 ⇒ `not_found`：「图上没有 n9」；**不**顺手新建。
- 返回：`{ 路径, 版本, 更新: 2 }`。

---

## 5. `graph_remove`

**入参**：`{ "路径": "...", "目标": [{ "类别": "节点", "id": "n7" }, { "类别": "边", "id": "e2" }], "批次": "ai-1" }`

**返回**：
```jsonc
{ "路径": "...", "版本": "...", "删除": { "节点": 3, "边": 4 },
  "说明": "删了 3 个节点（张三、李四、王五）和 4 条边" }
```

- 删节点**连带删边**，算同一步，不再单独计数（`删除.边` 含连带）。
- 前端按 `批次` 把整批算**一步撤销**（`Ctrl+Z` 一次全还原，FR-037）。
- `id` 不存在 ⇒ `not_found`（不静默成功——「删了个不存在的东西却说删了」是最坏的谎）。

## 6. 失败与话术

| code | 原话（回给模型，不折成兜底） |
|---|---|
| `identity_required` | （既有门的话术，不重复） |
| `forbidden` | 「只有项目属主能改关系图」 |
| `bad_input` | 具体缺什么：`「节点 tmp2 标了推断但没写依据」` |
| `too_many` | 「一次最多 50 条，请分批」 |
| `ambiguous_path` | 「项目里有 3 张图，请先 graph_list 再点名」 |
| `not_found` | 「图上没有 n9」/「项目里没有这张图」/「这个项目里还没有关系图」 |
| `write_failed` | 「没存上：<原因>」——**绝不说成功** |

**留痕**：沿用 `case-mcp-server.ts` 的调用留痕（工具名、耗时、ok、错误码、原始异常只进 stderr）。

## 7. 与既有工具的关系

- 图工具**不做查库**：不加 `query_*` 之类的调用，不改 `09` 的七字段信封。
- 「一圈关系搬进图」由模型自己 `query_relations` + `graph_add` 组合完成，**不提供**「整圈搬进来」按钮/工具（08 §10 写死不做）。
- 预算：沿用同一 `(userId, projectId)` 12 次窗口（不改预算代码）。风险与接受理由见 `research.md` R14。
