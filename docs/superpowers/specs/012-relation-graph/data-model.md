# Phase 1 · 数据模型（`.hgraph`）

**唯一真相**：项目目录里的 `.hgraph` 文件。本文件定义它的**磁盘形状**、**校验规则**、**派生口径**与**写入操作的代数**；不定义数据库表（本 feature 不新增表、不改表结构）。

**来源**：`08` §4.1 骨架 + §4.2 九条规则 + §4.3 开放词表 + §4.4 版本；`spec.md` FR-001~FR-034。

---

## 1. 顶层对象 `图文件`

| 键 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `格式` | `1` | ✅ | 只认 `1`；读到 `> 1` ⇒ **只读打开**并提示升级（FR-010） |
| `标题` | `string` | ✅ | 新建时取文件名（去后缀）；可空串 |
| `创建于` | `string`（ISO 8601 带时区） | ✅ | 新建时写一次，之后不变 |
| `更新于` | `string`（ISO 8601 带时区） | ✅ | 每次成功写入由服务端刷新 |
| `设置` | `设置` | ✅ | 见 §2 |
| `节点` | `节点[]` | ✅（可空数组） | id 文件内唯一 |
| `边` | `边[]` | ✅（可空数组） | 两端必须指向存在的节点 id |
| `文字` | `文字[]` | ✅（可空数组） | id 文件内唯一（与节点/边共用命名空间规则） |

**未知字段**：**保留原始 JSON 树**——解析时只读已知键，序列化时把未知键原样贴回（含嵌套对象里的未知键）。禁止「解析成类型化对象再整体序列化」（必丢字段，`08` §4.4）。

**key 语言**：一律中文；新增键照此惯例，不混 `source` / `type` 这类英文 key。

## 2. `设置`

| 键 | 类型 | 默认 | 用途 |
|---|---|---|---|
| `线宽度量` | `"按类型默认" \| "按金额" \| "按次数"`（首版只实现默认） | `"按类型默认"` | 自动线宽的量纲 |
| `次数阈值` | `number[]`，升序 | `[1, 2, 5, 10, 50]` | 次数 → 线宽档 |
| `金额阈值` | `number[]`，升序 | `[10000, 50000, 200000, 1000000]` | 金额 → 线宽档 |
| `外环阈值` | `number[]`，升序 | `[1, 2, 4, 8]` | 连接数 → 外环档 |

阈值只影响**渲染档位**，不影响任何写入判定。

## 3. `节点`

| 键 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `id` | `string` | ✅ | `n<k>`；文件内唯一、永不变；**服务端分配**（FR-014） |
| `名称` | `string` | ✅ | 可空串；检查器可改（失焦即存） |
| `类型` | `string` | ✅ | **开放词表**：字面字符串，读取时不校验白名单（FR-009）；未知类型用默认形状照显 |
| `细类` | `string` | ❌ | 空则不写 |
| `来源` | `来源` | ✅ | 见 §5；`kind ∈ 实体/关系/推断/手写` |
| `可信度` | `"高" \| "中" \| "低"` | 条件必填 | `来源.kind = "推断"` 时必填（FR-006） |
| `属性` | `属性[]` | ❌ | 绑库快照；只读（检查器无输入框） |
| `出处` | `string[]` | 条件必填 | `出处` 为行级定位；`性质=事实` 的**边**必须有；节点的 `来源.kind=实体/关系` 时尽量有，取不到写空数组并在界面标「未取到出处」 |
| `时间` | `{ 首: string, 末: string }` | ✅（可空串） | 打包进文件，不做时序界面（FR-007） |
| `备注` | `string` | ❌ | 可改 |
| `x` / `y` | `number` | ✅ | 画布坐标（整数像素）；**只在 `dragend` 落盘** |
| `外环` | `{ 档?: 0..4, 颜色?: string }` | ❌ | 手动设过档位/颜色后不再随连接数自动变；「恢复自动」= 删该键 |
| `出现序` | `number` | ❌ | 演示步进；可空；**只由人工或 AI 显式携带**，不自动生成（FR-008） |
| `链接` | `string` | ❌ | 预留图间跳转；只存不跳（FR-008） |
| `锁定` | `true` | ❌ | **格式补充**，见 §9.1；缺省即未锁定（不写 `false`） |
| `样式` | `{ 颜色?: string, 形状?: string }` | ❌ | 节点级显式覆盖；不是老图观感稳定的依据（FR-009） |

## 5. 子形状

### 5.1 `来源`

```jsonc
{ "kind": "实体", "实体": "ent_xxx", "值": "张三", "库类型": "人", "可信": "已确认" }
{ "kind": "关系", "关系们": ["rel_123", "rel_124"] }
{ "kind": "推断", "依据": "两人同日同酒店入住" }
{ "kind": "手写" }
```

- `kind = 实体` ⇒ 绑库节点；`实体` 是库 id（不是图上 id），可缺（实体被合并/删除时跳转失效）。
- `kind = 推断` ⇒ **必须**有 `依据`（非空），且节点/边必须有 `可信度`。
- `kind = 关系` ⇒ 用于「从库关系页加边」的边来源，`关系们` 是库关系 id 列表。
- `kind = 手写` ⇒ 人工新建。
- 可选 `并入: string[]`：合并节点时记录被并入的库实体 id（**不新增第 5 种 kind**，见 §9.2）。

### 5.2 `属性`

```jsonc
{ "键": "开户行", "值": "招商银行", "出处": ["mat_x#Sheet1#12"] }
```

绑库快照；只读；`值` 为字符串。

### 5.3 `证据`

```jsonc
{ "关系": "rel_123", "出处": "mat_x#Sheet1#12" }
```

一条证据 = 一条库关系 + 它的行级出处。`出处` 单串（不做区间），因为关系是逐条的。

### 5.4 `时间`

```jsonc
{ "首": "2026-01-03", "末": "2026-05-11" }
```

日期粒度由来源决定（库里可能是秒级）；写入时统一成 `YYYY-MM-DD` 或空串。**不做时区换算**（抄库里的展示值）。

### 5.5 `金额`

```jsonc
{ "值": "12000", "单位": "元" }
```

### 5.6 行级出处（`出处` 数组的元素）

`材料#工作表#行号`：首 `#` 结束材料 id（材料 id 不含 `#`），末 `#` 开始行号，中间整段是工作表名（**可含 `#`**）。可压缩为 `材料#表#起-末`。同一材料的区间超过 50 行 ⇒ 只存首末区间。解析规则**只有一处实现**（`解析出处`，见 research R7）。

## 6. 校验规则（每条对应 spec 的 FR，必须有用例）

| 编号 | 规则 | 触发点 | FR |
|---|---|---|---|
| V-01 | `格式` 不是 `1` ⇒ 只读；`> 1` 提示升级 | 读 | FR-010 |
| V-02 | 节点/边/文字 id 文件内唯一；`从`/`到` 必须指向存在的节点 | 读 + 写 | FR-014 |
| V-03 | `来源.kind` 必须是四值之一；`性质` 必须是两值之一；`方向` 必须是两值之一 | 读 + 写 | FR-002/005 |
| V-04 | `性质 = 事实` 的边 且 `出处` 为空且 `证据` 为空 ⇒ **拒绝写入** | 写（所有入口） | FR-017 |
| V-05 | `来源.kind = 推断` 且 `依据` 为空 ⇒ 拒绝写入 | 写（所有入口） | FR-006 |
| V-06 | 推断 且缺 `可信度` ⇒ 拒绝写入 | 写（所有入口） | FR-006 |
| V-07 | `类型` 不做白名单校验 | 读 + 写 | FR-009 |
| V-08 | 未知键原样保留（含嵌套） | 读→写往返 | FR-010 |
| V-09 | 出处语法：三段非空、行号整数、区间两端为整数且起 ≤ 末 | 写 | FR-003 |
| V-10 | 批量 ≤50（AI 工具）；超限拒绝并建议分批 | 写（工具入口） | FR-035 |
| V-11 | 路径：真实路径在项目内、后缀小写归一为 `.hgraph` | 写 | FR-016 |
| V-12 | 文件非空且当前版本 ≠ 客户端版本 ⇒ 409，不写 | 写 | FR-012 |
| V-13 | 同一批次内任一对象不合格 ⇒ **整批不写** | 写 | FR-013 |

> V-04/05/06 的判据是**一个函数**（`校验来源`），在「应用并写回」里对每个待写对象调用——所以 HTTP 手工、AI 工具、检查器改性质三条入口自动一致（FR-017）：入口不必各写一份。

## 7. 写入操作（`操作`）的代数

所有写入都是「读最新文件 → 应用这一小批操作 → 校验 → 原子写回」。操作是**数据**，不是代码：

| 操作 | 入参 | 说明 |
|---|---|---|
| `加节点` | `节点[]`（临时 id 可缺省） | 缺省 id 时服务端分配；缺省坐标时**服务端放置**（§7.1） |
| `加边` | `边[]`（临时 id 可缺省） | 两端可用临时 id，服务端按映射替换 |
| `加文字` | `文字[]` | 同上 |
| `改字段` | `{ 类别: "节点"\|"边"\|"文字", id, 补丁: Record<string, unknown> }[]` | 只允许改白名单字段（名称/类型/细类/外环/备注/标签/性质/出现序/锁定/线宽档/样式）；`补丁[键] = null` 表示删该键 |
| `删对象` | `{ 类别, id }[]` | 删节点 ⇒ 连带删两端边，算同一步 |
| `移动` | `{ 类别: "节点"\|"文字", id, x, y }[]` | 坐标由前端算（对齐/自动布局都翻译成 `移动`） |
| `合并节点` | `{ 保留: id, 并入: id[] }` | 端点重指、出处/证据/备注并集、属性以保留者为准、`来源.并入` 追加；与已有边重复则保留两条并偏移（不自动去重） |

**服务端不做几何**：对齐、等距、自动布局、粘贴偏移全部由前端用 `graph-layout.ts` 算好，作为 `移动` / `加节点` 的坐标发出。这样服务端不复制一份布局算法（R8）。

### 7.1 服务端放置（仅当调用方没给坐标）

1. 若新节点要连到已有节点：在该邻居的外圈上找一个**与既有节点不重叠**的位置（按 `节点半径` 的留白）；
2. 无邻居：放在**既有节点的质心**（空图则画布中心）附近的空位；
3. 永不放在 `(0,0)`，永不随机。

> 与 `08` 的差异（如实记录）：`08` 写「无邻居则放当前视口中心」，但 AI 工具没有视口。改用「既有节点质心」，等价意图（看得见、不叠一坨）；人工双击加节点时由前端给点击坐标，不走放置。

## 8. 状态与生命周期

### 8.1 保存状态（前端）

```text
干净 ──本地改动──> 待发 ──发出──> 在途 ──200──> 干净（版本=新版本）
  ↑                 │              └──409──> 冲突：询问「重新载入？」
  └──重载（清栈）────┴──失败(<5xx/网络)──> 待发（改动保留，可重试）
```

- 「待发」有 500ms 防抖；**拖动例外：只在 `dragend` 进入待发**（FR / 08 §6.1）。
- 失败**绝不**假装成功：状态停在「待发」并提示「没存上」，检查器字段回滚到改前。

### 8.2 撤销栈（前端）

- 每步 `{ 逆操作: 操作[], 副本?: 对象[], 批次?: string }`；20 步上限。
- 同一 `批次` 的多步合并为一步；`Ctrl+Z` / `Ctrl+Shift+Z`。
- 外部重载（409 重载 / 轮询静默重载 / 手动「重新载入」）⇒ 清栈 + 提示「图已重新载入，撤销记录已清空」。

### 8.3 文件生命周期

| 事件 | 行为 |
|---|---|
| 新建 | create 空文件 → `POST /openhive/hgraph/init` 写骨架（非空不覆盖，幂等） |
| 打开 | `hgraph/read`；0 字节 ⇒ 先 `init` 再读；解析失败 ⇒ 只读报错 + 「以文本方式打开」 |
| 删除（外部） | 标签页提示「文件已不存在」，**禁止保存** |
| AI 改动 | 轮询发现版本变化 → 无待发 ⇒ 静默重载；有 ⇒ 询问 |

## 9. 格式补充与取舍（实现期必须照此，不得再自创）

### 9.1 `锁定` 键（格式补充）

`08` §5.13 / FR-022 要求「节点可锁定」，但 §4.1 骨架没列键。定义：节点可选 `"锁定": true`；缺省即未锁定（**不写 `false`**，文件保持干净）。语义：自动布局与框选拖动不动它；对齐/等距等显式命令仍生效。

理由：不锁会丢「用户精心摆好的骨架」；而把这个状态放到别处（浏览器存储）会让同一份文件在不同机器上行为不同——违反「文件是唯一真相」。

### 9.2 合并的标记（消解 `08` 的措辞歧义）

`08` §4.2 规则 2 定 `来源.kind` 只有四值，§5.12 又说「`来源` 标 `合并`」。**不新增第 5 种 kind**：保留者的 `来源.kind` 保持原值，合并事实记为 `来源.并入: string[]`（被并入的库实体 id）；界面在 `并入` 非空时显示「已合并」徽标（派生，不落盘）。

理由：kind 是「凭什么在图上」的四分类，掺进一个「怎么来的」会污染判定；且 `08` 明确 `并入` 字段用于追溯。

### 9.3 版本与未知字段

- 版本不进文件（是服务端算的内容哈希）；文件里只有 `格式`。
- `更新于` 由服务端写；客户端给的 `更新于` 一律忽略。
- 未知键保留（V-08）；`格式 > 1` 只读。

## 10. 导出记录（不落文件、不落库）

一次导出在**内核日志**写一行：

```jsonc
{ "事件": "hgraph导出", "userId": "...", "projectId": "...", "路径": "分析/张三资金流向.hgraph",
  "时间": "2026-11-15T10:03:00+08:00", "文件名": "专案A-张三资金流向-20261115-1003.png" }
```

定位是**可追溯**，不是控制（不承诺禁止截图、不承诺永久可查）。**不新增审计表**（`08` §8.1）。

## 11. 派生数据（只在界面算，不落盘）

| 派生 | 口径 |
|---|---|
| 节点外环档（自动） | 连接数 ≥ `外环阈值` 的档位；手动设过则用 `外环` |
| 边线宽档（自动） | 按 `设置.次数阈值` / `金额阈值`；手动 `线宽档` 覆盖 |
| 双向边偏移 | 同一对节点的第 k 条（k 从 0 起）垂直偏移 `k × 8px` |
| 隐藏计数 | 隔离与筛选共用一个计数：`隐藏 = 总数 - 可见数`，界面写「已隐藏 N 个节点」 |
| 库角标 | 快照值/类型/可信态 ≠ 当前库 ⇒ 「已变更」；实体不存在/已排除 ⇒ 「库中已无」；只改界面，不改文件 |
| 证据附录排序 | 节点表与边表按 `出现序` 升序（空值排最后），同序按 `id` |
| 导出文件名 | `<项目名>-<图名>-<YYYYMMDD-HHmm>.png`（同名 `.md` 为附录） |
