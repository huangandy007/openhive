# Phase 0 · 研究（012 关系图产物）

**目的**：把 plan 里所有「怎么做」的未知项定下来，并把每个决定与**现成实现**对齐——优先复用，复用不了才新增。

**结论先行**：本 feature 没有真正的技术未知（格式、协议、交互都已在 `08` 定稿）；下面 17 条是**落地决定**，每条都写「决定 / 理由 / 备选为何不行」，实现期不再重新讨论。

## R1 · 写入通道：新建 `hgraph-ops`，并让通用写口拒绝 `.hgraph`

**决定**：`.hgraph` 的唯一写入者是 `packages/opencode/src/server/openhive/hgraph-ops.ts`；`file.ts` 的 `handleWrite`（`POST /openhive/file/write`）在路径闸之后加一道判据：后缀小写归一为 `.hgraph` ⇒ 拒绝（`400`，`code: "HGRAPH_READONLY"`，文案「关系图请在关系图视图里改」）。

**理由**：通用写口（`file.ts:1254-1330` 实读）与本 feature 的语义有四处硬冲突——① `content.trim()` + BOM/CRLF「信封」还原会改 JSON 的形状；② 读→比→写之间有间隙且**无 per-path 串行锁**（文件头自己登记了这个缺口）；③ 写是非原子的单个 `writeFile`，没有 temp+rename，也没有 win32 占用重试；④ 版本口径是「trim 后文本」，不是内容哈希（同毫秒同大小互换会漏判）。把它改成兼顾 `.hgraph` = 为一个功能动共享写口，两种语义互相污染。

**备选**：① 扩展通用写口支持模式参数——否决，改共享出口且调用方都得判模式；② 前端直接写 `POST /openhive/file/write`——否决，违反 FR-011 且上面四条全踩；③ 只靠 AI 走 ops、人工走通用写口——否决，正是 `#007-02` 的「两条路两个读者」。

**负向断言**（TR-008）：写一条用例证明通用写口对 `.hgraph` 返回拒绝码；再 grep 一遍全仓 `.hgraph` 写入调用点，确认只有 `hgraph-ops`。

## R2 · 版本 = 文件内容哈希（原始字节），10 秒轮询只 stat

**决定**：
- 版本 = `sha256(原始字节)` 前 16 字节（hex，32 字符），在 `hgraph-lock.ts` 内算一次，读口与写口共用。
- 每次写成功返回新版本；客户端存为 `版本`。
- 前端每 10 秒 `GET /openhive/file/stat`（**复用** `file.ts` 的 stat 口）比对 `mtime/size`；变了才 `GET /openhive/hgraph/read` 算哈希；哈希与本地 `版本` 不同且本地**无未发出改动** ⇒ 静默重载（并清撤销栈）；有未发出改动 ⇒ 询问「重新载入？」。

**理由**：`mtime:size` 不是版本（08 §6.1 实测过同毫秒同大小互换）；`trim` 后文本也不是（通用写口的教训）。stat 轮询几乎零成本，避免每 10 秒读整份文件。

**备选**：① `Bun.hash`（64 位非加密）——更快，但测试里要断言具体值、且跨实现无标准；选 SHA-256，成本可忽略（几百 KB）。② 轮询直接读内容——否决，300 节点图每 10 秒读一次纯浪费。

## R3 · 串行锁：进程内 per-path promise 链，不用文件锁

**决定**：`hgraph-lock.ts` 维护 `Map<绝对路径, Promise<void>>`，每次「读-改-写」以链式串行执行；写结束（成功或失败）从链上退出。

**理由**：08 §6.1 明确「服务端按路径串行化（进程内一把锁）」。本产品是**单进程内核 + 内网私有部署**（宪法 §一），进程内锁足够；跨进程/多设备协同明确不在范围（08 §13 第 7 条）。

**备选**：① 文件锁（`proper-lockfile`）——引入依赖、win32 语义复杂，且多设备同时开同一图本就不支持；② SQLite 事务锁——图不在库里，凭空建一张表违反「不新增表」。

**测试**：并发两条写同一路径，断言第二条看到第一条的新版本（顺序确定、无丢失）；两条写**不同**路径可并行（不互相阻塞）。

## R4 · 原子写：临时文件 + rename，win32 占用 3 次重试

**决定**：写临时文件 `<目标>.tmp-<随机>`（同目录，保证同卷）→ `rename` 覆盖目标；`EPERM`/`EBUSY` 重试 3 次（50 / 150 / 450ms）；仍失败 ⇒ `500` 并回「文件被其他程序占用，没存上」。任何一步失败都删临时文件。

**理由**：08 §9 已定；同目录临时文件是 POSIX/win32 都能原子 rename 的唯一简单做法。

**备选**：① 直接覆盖写——中断留半截 JSON，正是要避免的；② 写备份后覆盖——两次写、两个失败面。

**测试**：临时目录里写成功后断言无残留 `.tmp-*`；模拟 rename 失败（注入）断言原文件字节不变。

## R5 · id 分配：文件内最大序号 + 前缀

**决定**：节点 `n<k>`、边 `e<k>`、文字 `t<k>`；`k` = 现有同类 id 中前缀数字的最大值 + 1（不是行数，删除后不复用）。调用方只给临时 id（`tmp1` 等），写入时服务端换正式 id，返回 `{ 临时id: 正式id }` 映射。

**理由**：08 §4.2 规则 1；文件是唯一真相，id 只需文件内唯一，不需要全局序列（序列要存储，凭空建表）。

**备选**：① 全局自增序列（DB）——多一个存储、多一次 IO；② 随机 id——可读性差、人工看文件时难对照。

## R6 · 幂等键：进程内 Map + 10 分钟窗口 + 上限

**决定**：`hgraph-ops` 内维护 `Map<幂等键, { 结果, 时间 }>`，窗口 10 分钟（与 MCP 预算窗口同值），超过 1000 项时清理过期项。命中即返回上次结果（含同一批次号与 id 映射）。

**理由**：幂等的唯一真实场景是「AI 工具超时重试」（秒级），进程重启丢键可接受；落库要新增表（违反不新增表）。窗口取值与 `case-mcp-server.ts` 的预算窗口一致，避免第二套时间常量。

**备选**：① 落库——新增表 + 迁移；② 内容哈希去重——「同名同类型复用」已经挡了重复节点，但挡不住不同名/推断节点/边，且内容哈希会把「两次有意加同一批」误判为重试。

**测试**：同键两次调用，第二次返回同一结果且文件字节不变；不同键相同内容写两次，得到两份对象（有意为之）。

## R9 · 读取：新增 `GET /openhive/hgraph/read` 返回 `{ 内容, 版本 }`

**决定**：不直接用 `LoadFileContent`（它不返回版本），改为 `hgraph/read`。响应 `{ 内容: string, 版本: string }`；0 字节文件先走 `POST /openhive/hgraph/init` 再读。

**理由**：版本只能由服务端算（原始字节哈希）；`load` 的 trim 语义也不适合 JSON。**读文件本身复用** `file-content.ts` 的类型与 `readProjectFile` 的取数链，只多一个版本字段。

**备选**：前端自己哈希 `load` 的返回——trim 后文本 ≠ 原始字节，服务端算的是原始字节，两边永远对不上（正是通用写口那条假冲突的同型问题）。

## R10 · 导出：SVG → Image → canvas → PNG；A3 300 DPI 按长边 4961px

**决定**：
- 画面：克隆当前画布 `<svg>` → 去掉交互态（选中描边、悬停、演示层）→ `XMLSerializer` → `data:`/Blob URL → `Image` → 画到 canvas。
- 两档：`屏幕（2 倍像素）` = 画布 CSS 尺寸 × 2；`A3 打印（300 DPI）` = 按 300 DPI 的 A3 纸（3508×4961 px）等比放入，白底。
- 标题块：可选的 `<g>` 在导出时临时追加（项目名/图名/导出时间/导出人），屏幕档默认不加。
- 附录：与 PNG 同一次下载的两个文件（浏览器允许连续两次下载），同名 `.md`；不写回项目目录。
- 字体：先用当前字体栈导出，**真栈截图比对中文**（节点名/金额/图例）；掉字则把字体 base64 内联进 SVG（08 §13 第 5 条），实测结果写进实现报告。
- 授权：**先** `POST /openhive/hgraph/export`（成员 + 路径闸 + 留痕）拿到许可，**再**渲染下载。

**理由**：08 §8 已定；不引入导出库。

**备选**：① `foreignObject`——跨浏览器与 canvas 兼容性差（08 已否）；② 服务端渲染——无 headless 浏览器依赖，凭空加一个重依赖。

**测试**：纯函数测文件名 `项目名-图名-YYYYMMDD-HHmm.png`、A3 尺寸换算、附录表格排序；渲染与字体属真栈验收，进缺口表。

**决定**：
- 搜索/列表：`EntityApi.list`（`GET /openhive/case/entities`，`q` 只匹名称与别名）；类型是**结果列 + 前端筛选**。
- 快照：`GET /openhive/case/entity?id=`（`实体档案`：`canonical_value / type / subtype / attrs / trust_state / 引用[]`）。
- **首末时间**：`实体档案` 没有实体级首末字段（实读 `case-fact-read.ts:39-49`、`case-detail-api.ts:52-90`）。改为**前端从档案里既有的数据聚合**：`min(关系[].首, 事件[].occurred_at)` 与 `max(关系[].末, 事件[].occurred_at)`；都没有 ⇒ 空 `{首:"", 末:""}`。同一份档案被上限截断（`缺口` 非空）时聚合值是**下界**，在检查器「库里现在」段如实标注「档案有截断，时间为已知范围」。
- 出处：把 `引用[]` 拼成 `材料#工作表#行号`（`materialId` + `locator.sheet` + `locator.row`），交给同一个 `压缩出处`。
- 关系页：`GET /openhive/case/graph?id=<实体>&跳数=1` 取 `边`；勾选后用 `GET /openhive/case/facts?type=relation&id=` 取该关系的 `citations`（证据与出处成对）、`firstAt/lastAt`、`amount`、`times`。
- 角标：打开图后对**绑库节点**逐个 `GET /case/entity`，**并发上限 6**，进度可见；超过 200 个绑库节点时顶部提示「库中变化仍在比对」，不静默当成「无变化」。

**理由**：FR-031 禁止新增后端检索接口；`entity-api.ts` 是 `07` §2.2 定下「不删、不改契约」的模块。前端聚合避免动 `case-entity-list.ts`（高频、且改它就是给上游冲突加面）。

**备选**：① 给实体档案加 `首/末` 字段——动高频文件、改共享契约；② 新增批量子接口——越界；③ 不写时间——违反 FR-007/FR-032。

**缺口（如实登记）**：300+ 节点图的角标比对是 N 次请求，本机只验到并发池与进度，未在 1000 节点真栈上量过总耗时。

## R12 · 演示态与快捷键：挂在画布容器，不注册全局热键

**决定**：演示态是一个**本地信号**（`演示中`）；进入时给画布容器加 `data-presenting` 并 `requestFullscreen()`（失败则退回全屏遮罩，不报错）；快捷键一律挂在容器的 `keydown`（`tabindex="0"` + 焦点管理），**不 `window.addEventListener`**。

**理由**：FR-040 明写「MUST NOT 注册全局热键」；`LEARNINGS #006-37` / `#005-30` 的浮层与焦点教训。全屏 API 在测试环境没有，组件测试只断言 `data-presenting` 与步进，真栈验画面。

**备选**：全局热键——与编辑器/会话面板的快捷键互抢。

## R13 · 撤销栈：逆操作 + 被删对象副本；AI 批次按批次号合并

**决定**：
- 一步 = `{ 逆操作: 操作[], 副本?: 被删对象[], 批次?: string }`。
- 人工操作：前端在发请求**前**构造逆操作（移动记原坐标、改字段记旧值、删除记被删对象完整副本、合并记被并入者与重指前的边）。
- 服务端返回 `批次`（AI 工具调用时带入，前端写入时也带批次号——前端一步一批）。
- 前端把同一批次的逆操作合并为一步；20 步上限，超出丢最旧；外部重载（409/轮询/手动）清栈并提示。
- 移动只在 `dragend` 记一步（拖动期间的坐标在本地信号里）。

**理由**：FR-029 明写「MUST NOT 用整图快照」；副本比快照省内存且能精确还原 id。

**备选**：整图快照——20 步 × 几百 KB 直接就撑爆内存，且还原会改掉别的并发写入。

**测试**：撤销后剩余对象计数、端点指向、字段旧值；AI 3 次调用同批次 ⇒ 1 次撤销全还原。

## R14 · MCP：5 个工具只加实现；信封校验按工具名分流；预算照旧计数

**决定**：
- 5 个工具加进 `TOOLS`、`工具名` 联合、`分发表`；`graph_add/update/remove` 加进 `写工具名`（属主门）。
- 图工具的返回**不套**七字段信封：`case-mcp-server.ts` 里 `校验信封(结果)` 改为「图工具跳过」。实现方式是在 `case-hgraph-tools.ts` 导出一个 `图工具名` 集合，server 判断后跳过（一处判据）。
