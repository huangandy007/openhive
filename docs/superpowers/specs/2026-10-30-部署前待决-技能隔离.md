# 部署前必须回答：技能文件对模型可见，怎么隔离？

> **状态：挂账，未开发。** 记录于 2026-10-30，用户裁定「部署时再讨论」。
> 触发时机：**内网部署开工前**，由本文件逐条过一遍。

## 1. 问题是什么

现在的权限卡在「技能名字」上：

- `skill` 工具：`Permission.evaluate` 判决（`tool/skill.ts` 的 `ctx.ask`）
- 斜杠命令：`SessionPrompt.command` 里补了一次同样的判决（004 · R1）

但模型要干活，走的是 `bash` 和 `read`——那一层**只问「能不能跑命令 / 读文件」，不认识技能**。
所以五条调用路径里，只有前两条受管控：

| 路径 | 受权限管控 | 计入使用记录（2026-10-30 口径） |
|---|---|---|
| `skill` 工具 | ✅ | ✅ |
| 斜杠命令 `/技能名` | ✅（004 R1） | ✅ |
| `read` 读 SKILL.md | ❌ | ✅ |
| `bash` 跑技能脚本 | ❌ | ✅ |
| 内建技能 | ❌ | ❌（无资产身份） |

**实测证据（真栈 2026-10-30）**：模型在会话里直接
`bash python ".opencode/skill/<assetId>/scripts/md_to_word.py"`，产出了真实 Word 文档。
它既没经过 `skill` 工具，也没经过任何技能级授权判断。

## 2. 为什么现在不做

1. **属于部署期问题**：本机是单用户开发环境，没有多租户隔离需求。
2. **依赖内网环境验证**：方案 B 需要在目标机器的 Docker 里实测 `bwrap` 能不能跑。
3. **不影响当前开发**：记录、授权、界面等功能可以继续推进。

## 3. 两个候选方案

### 方案 A：部门级容器隔离（低复杂度）

- 一个部门一个 Docker 容器，只挂本部门的项目目录与资产
- 容器数 = 部门数（十几个），与项目数无关
- **Docker 原生能力，不需要额外权限**
- 前提：隔离边界是「部门之间」，同部门同事可互看

### 方案 B：进程级沙箱（高复杂度）

- 每次工具调用建一个临时 Linux 命名空间（`bwrap`），视图 = 项目目录 + 本项目已启用资产
- 容器数不变（几个），沙箱随命令创建销毁
- 需要改 `tool/shell.ts`（上游）与 `tool/read.ts`（上游）——**碰上游文件，按定制三原则单独提交**
- 需要容器放开权限：`seccomp=unconfined` 或 `--cap-add SYS_ADMIN`

## 4. 部署前必须先回答的两个问题

### 问题一：隔离边界是什么？

- **部门之间要隔离**，同部门同事可互看 → 走方案 A，Docker 原生就够
- **每个人之间都要隔离**，同事也互相看不到 → 必须走方案 B

> 公安内网大概率是前者。这一句定了，方案差很多。

### 问题二（仅方案 B）：内网 Docker 能跑 bwrap 吗？

```bash
docker run --rm --security-opt seccomp=unconfined alpine sh -c \
  "apk add -q bubblewrap && bwrap --unshare-all --ro-bind / / -- /bin/echo 沙箱可运行"
```

- 输出「沙箱可运行」⇒ 方案 B 成立
- 报权限错误 ⇒ 换 seccomp 配置或改走方案 A

## 5. 无论选哪个方案都成立的一条

**资产目录必须只读挂载**（`/assets:ro`）：模型可以跑脚本，但不能改技能本身。
