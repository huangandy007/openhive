# 关系图聚焦与压缩设计

> 日期：2026-11-08　状态：待用户审阅
> 前置：`docs/superpowers/specs/2026-11-05-案件知识与情报体系/design.md` §8.3（图只画选中实体 1～2 跳、节点上限约 50）
> 教训：`#002-01`（`numeric` 的聚合结果按字符串回传，不转浮点）、`#002-06`（同一个前提要在所有落点逐一检查）

## 0. 用户已拍板的四条（2026-11-08 讨论）

1. 办案有两个阶段：**先铺开看结构，再顺线深挖** ⇒ 需要「全貌 / 聚焦」两档模式，而不是一张永远长大的图。
2. 「全貌」铺开范围仍是**当前对象 1～2 跳**，不推翻 §8.3 的「不是全项目拓扑」。
3. 压缩手段取三样：**按关系强度切片、枢纽点单独标出、二跳按父节点分簇**；**不做**按实体类型折叠。
4. 下钻「以此为中心」**换一张干净的图**（反转 2026-11-07「下钻保留旧点」那条要求）。

## 1. 问题

一张图节点一多，注意力被稀释；点「以此为中心」后又展开一圈，越钻越多，最终无法查看。若中心节点挂着大量资金 / 话单信息，会一次带出成片的关系与节点。

## 2. 现状（全部有出处）

| 事实 | 出处 |

| 节点上限 50，前端传更大也封顶 | `case-graph.ts:73`、`:174` |

| 下钻 = 原地换中心 **＋ 并图**，旧节点一条不删 | `graph.tsx:364`（`并图`）、`:403`（`本次并入`）、`:540`（`换中心到`） |
| 返回按来路栈重新取上一个中心 | `graph.tsx:552` |

### 2.1 三个实测结论（比表格更重要）

1. **强度排序实际失效。** `times` / `first_at` / `last_at` 三列只由 `insertRelation`（`case-fact-store.ts:122`）写入；它唯一的调用点 `case-ingest.ts:544` 只传了 `type` / `amount` / `basis`，没传这三列。于是 `order by coalesce(times,0) desc, coalesce(last_at,first_at,0) desc, id`（`case-graph.ts:141`）退化成**按 `id` 字典序**：候选超过 49 条时，画哪 49 条基本是任意的；`amount` 有值但排序没用它。
2. **`关联数` 不能用来判枢纽。** 它按「图上画出来的边」计（`case-graph.ts:292`），最多 49。与 300 人有往来的账户在图上可能只显示「关联 5 条」。
3. **话单/流水明细目前不进图。** 明细行落 `case_fact_row`，关系图只画 AI 抽取出的 `case_relation`。以后把明细接进图，聚合必须做在入库那一步——这是本设计的前置前提，不在本期范围。

## 3. 根因

| # | 根因 | 后果 |
|---|---|---|
| a | 上限按「每一圈」算，**累计无上限** | 下钻三次即可到 150+ 节点 |
| b | 强度数据缺失、排序退化 | 名额给谁由 `id` 决定 |
| c | **没有边聚合**：同一对端点的多条记录各占一个名额 | 几百条流水只带出 1 个新节点，别的关系全被挤掉 |
| d | 缺「枢纽」与「二跳归属」两种结构信息 | 真正的通道看不出来，二跳点散成一圈 |
| e | 布局没为大 N 设计：环形等角均分、力导向 O(n²×200) | 标签重叠、视觉成毛线球 |

## 4. 设计

### 4.1 后端口径（`case-graph.ts`）

#### 4.1.1 入参

```ts
关系图入参 {
  projectId, id, 跳数?: 1 | 2, 类型?: readonly string[], 上限?: number,
  强度?: "全部" | "重点" | "强"   // 新增；省略 = "全部"
}
```

路由 `handleGraph`（`case-ui-routes.ts:233`）校验：`强度` 只认这三个值，其余 `400`；省略按 `全部`。

#### 4.1.2 边先聚合，再进名额

按 `(from_id, to_id, type)` 合成一条：

```ts
图边 {
  id: string            // 合成 id：`rel|${from}|${to}|${type}`；只作图上标识与选中键
  from, to, type: string
  times: number         // sum(coalesce(times, 1))：合并了几条关系记录 / 几次
  amount: string | null // 转账合计（numeric 字符串，不转浮点）
  trust_state: string   // 全同取原值；混合取 "混合"
  明细数: number        // 合并了多少条原始关系（≥1）
}
```

- 金额按 `sum(r.amount)::text` 取回，全程字符串；比较阈值时才在 SQL 里用 `numeric`（`#002-01`）。
- 自环（`from = to`）仍是一条边；度数只给该节点加 1（沿用现有 `new Set` 写法，`case-graph.ts:295`）。

**为什么必须先聚合**：一条流水 / 一条笔录关系就是一行，几百行同一对端点会占满边名额，却只带出 1 个新节点。

#### 4.1.3 强度档

保留条件 = **次数达标 或 金额达标**（转账看金额，其余看次数）：

| 档 | 次数 | 转账金额合计 |
|---|---|---|
| 全部 | 不过滤 | 不过滤 |
| 重点 | ≥ 2 | ≥ 1,000 元 |
| 强 | ≥ 5 | ≥ 10,000 元 |

一笔 20,000 元的转账即使只发生 1 次，也算「强」——这是用户确认过的「或」口径。

#### 4.1.4 节点新增两个字段

```ts
图节点 {
  …,
  度数: number,     // 库里与该实体相关（未被排除）的关系总数——判枢纽用
  经由?: string     // 二跳节点是从哪个一跳节点过来的——分簇用
}
```

- `度数` 单独查一轮：只对图上节点（≤50），用 `(from_id, to_id)` 两侧的 `union all` 计数，仍排除已排除的关系与对端实体。**第二半要加 `r.from_id <> r.to_id`**：自环同一条关系会从两侧各产一行，不加就数成 2。`union all`（不是 `union`）是必须的——`union` 会把「同一对端点的多条关系」去重成 1 条，度数与图上条数就再也对不上。代价小，不能拿 `关联数` 顶替。度数**不接**类型/强度筛选：枢纽的判据是「这个实体在库里跟多少关系连着」，不该随当前视图口径漂移；也正因如此，界面上不能把它写成「全部」。
- `经由` 在 `收一圈` 加点时记录「当前在图的端点」为父；同一节点只记第一次到达的父。

#### 4.1.5 缺口分两种，另给一个结构化字段

`关系图结果` 新增：

```ts
关系图结果 {
  节点, 边,
  缺口: string[],
  强度缺口?: { 未显示: number; 总数: number }   // 新增
}
```

- 强度筛掉的不写进 `缺口` 文案，走 `强度缺口`（前端要用它渲染「放宽」按钮，不能解析中文）。
- `缺口` 继续只放**上限截断**：条数改为「聚合后的关系条数」。第 1 跳那句必须写明口径——`第 1 跳只画了前 X 个节点，该跳共 N 条符合当前强度的关联关系`。它和 `强度缺口` 并列渲染、分母不同（前者只数中心、只数达标；后者数中心＋已画一跳点、只数不达标），写成「共 N 条」会被读成总数，还可能和「较弱 N 条未显示」相加（终审 S3）。
- 两个计数在同一批聚合结果上取：先算出每条聚合边是否达标，再 `count(*) over ()` 与 `count(*) filter (where 达标) over ()`。
- **实现偏离（T1 裁定，勿当新缺陷）**：`强度缺口` 用**独立**聚合查询，scope 限定为「跳数 1 = 中心；跳数 2 = 中心＋**已画出的**一跳点」。原因：第 1 跳与第 2 跳各取一次 `count(*) over()`，中心↔一跳点那批组会在两轮各出现一次，相加会翻倍；而把两轮并成一条窗口 SQL 在「一条都不达标」时窗口值会随行被筛掉。§4.1.6 的窗口写法只用于**单圈**取候选。

#### 4.1.6 SQL 形状

三层，避免拿「聚合前的行数」冒充「聚合后的关系数」：

```sql
select * from (
  select g.*,
         count(*) over ()::int as 全部组数,
         count(*) filter (where g.达标) over ()::int as 达标组数
    from (
      select r.from_id, r.to_id, r.type,
             sum(coalesce(r.times, 1))::int as 次数,
             sum(r.amount)                  as 金额数,   -- 排序用 numeric，别拿文本比大小
             sum(r.amount)::text            as 金额合计,
             count(*)::int                  as 明细数,
             (sum(coalesce(r.times, 1)) >= :次数阈
              or sum(r.amount) >= :金额阈)   as 达标
        from auth.case_relation r
        join auth.case_entity 起 on 起.project_id = r.project_id and 起.id = r.from_id
        join auth.case_entity 终 on 终.project_id = r.project_id and 终.id = r.to_id
       where r.project_id = :项目
         and r.trust_state <> '已排除'
         and 起.trust_state <> '已排除' and 终.trust_state <> '已排除'
         and (r.from_id in (:前沿) or r.to_id in (:前沿))
         and (:类型为空 or r.type in (:类型))
       group by r.from_id, r.to_id, r.type
    ) g
) h
where h.达标
order by h.次数 desc, h.金额数 desc nulls last, h.明细数 desc, h.from_id, h.to_id, h.type
limit :剩余 + 1
```

- `全部组数` / `达标组数` 在**已分组**的结果上取，只用于判断**单圈**里有没有被强度筛掉；跨圈的 `强度缺口` 见 §4.1.5 的「实现偏离」——不能把两圈的窗口值相加（中心↔一跳点那批会翻倍）。
- 排序把金额放进来后，「画哪 49 条」才有意义。
- 结构性保证不变：每条聚合边最多带 1 个新节点 ⇒ 节点数不越过上限。

#### 4.1.7 上限

仍为 `默认节点上限 = 50`，仍 `Math.min` 封顶。两轮 BFS 的「剩余名额」按**聚合后的边**算。

### 4.2 前端（`graph.tsx`）

#### 4.2.1 两档模式是派生状态

不新增 `模式` 信号；高亮由现有三项算出：

```ts
全貌 = 跳数 === 2 && 强度 === "重点" && 分簇 === true
聚焦 = 跳数 === 1 && 强度 === "全部"
```

- `分簇` **不进 `聚焦` 判据**：它只在 2 跳有意义，控件也只在 2 跳渲染。若把它算进去，用户在 1 跳留下 `分簇 === true` 就会出现「两档都不亮、又没有可见控件可改」的死状态（终审 S1）。
- 点「全貌」⇒ 一次设三项；点「聚焦」⇒ 一次设三项（其中 `分簇 = false` 只是顺手归位，不参与判据）。用户随后改任一项，高亮自然消失，回到「自定义」。
- 新增一个 `分簇` 信号（boolean），只在 `跳数 === 2` 时显示控件、生效。
- 任何一项变化都沿用现有「换数据 = 替换」路径（`本次并入` 删除后，取数只有替换一种）。

#### 4.2.2 强度档

`全部 / 重点 / 强` 三颗按钮，样式与跳数按钮一致，位置在跳数右侧；带 `data-slot="graph-strength"`、`data-strength`。

#### 4.2.3 枢纽标记

- 判据：`度数 >= 10`（常量 `枢纽度数阈值 = 10`）。
- 视觉：在节点外画一圈细实线外环（`data-slot="graph-node-hub"`）；不新造颜色，用 `var(--v2-border-border-strong)`。
- 面板节点区两行：`图上 N 条`（现有 `关联数`：当前类型/强度筛选下画出来的**聚合边**数）与 `库内 M 条`（新 `度数`：该实体在库内的全部**原始关系**数，不受类型/强度筛选影响）；是枢纽时再加一行 `枢纽`。两把尺不同（聚合边 vs 原始关系），所以标签分开写「图上 / 库内」，不并成「全部」——那会被读成「图上应该有的总数」（终审 S2）。
- 悬停 `<title>` 带上 `（枢纽 · 库内 312 条）`，与视觉一致。

#### 4.2.4 二跳分簇

`分簇 && 跳数 === 2` 时：

- 外环排序键从 `type, id` 改为 `经由, type, id`，同父相邻、顺序确定。
- 每个 `经由` 组画一段外环弧（`data-slot="graph-cluster"`），旁边标「经由 张三（12）」。
- **只有「环形」排列把排序键改为 `经由, type, id` 并画弧与标签**：其它三种排列没有「外环」这个概念，不排序、不画弧（网格/分层仍按类型排，不为一档模式改它们的语义）。
- 弧锚在**自动布局**的外环上：手动拖过的节点会与自己的弧脱开。这是已知取舍（测试钉住「拖动不改弧」），不是缺陷。
- 标签最多画 **8 组**（按组内节点数降序取前 8），再多就会糊成一片；弧不受此限。
- `经由` 缺失、或父节点已被上限截掉 ⇒ 归入「其他」组。
- 组内节点数 ≤ 1 不画弧，避免视觉噪音。

#### 4.2.5 弱关系条

`强度缺口?.未显示 > 0` 时，在现有 `缺口` 上方渲染一颗按钮：

> `较弱关系 137 条未显示 · 放宽到「重点」`

点击把强度**放宽一档**（`强 → 重点 → 全部`）；已在「全部」时服务端不返回 `强度缺口`，按钮不渲染。`data-slot="graph-weak-chip"`。

#### 4.2.6 下钻换干净图

- 删除 `并图()`、`本次并入` 与它们的行为分支；取数只有「替换」。
- `以下钻` / `返回上一中心`：清空 `选中`、`多选`、`手动位置`；保留 `跳数`、`强度`、`类型`、`分簇`、`缩放`、`平移`、`来路`。
- `返回` 仍按来路栈重新取数，不需要缓存旧图。

#### 4.2.7 面板

- 边面板：`次数`（N 次 / 记录数）、`金额`（合计）、`可信`（可能是「混合」）、`明细数`（N 条原始关系）。
- 其余（以中心、打开档案、复制、发送到会话、右键菜单）不变。

### 4.3 边界与空态

| 情形 | 处理 |
|---|---|
| 强度筛完一条边都没有，但库里有 | `当前强度下没有关系（共 M 条较弱）` ＋ 放宽按钮；**不显示**「还没有关系」 |
| 库里真没有关系 | 现有的「还没有关系」 |
| `trust_state` 混合 | 边面板显示「混合」，不冒充某一状态 |
| 聚合后金额全为空 | `amount` 回 `null`，面板显示 `—` |
| 自环 | 一条边、度数只加 1 |
| 非法 `强度` | 路由 400（同 `跳数` 只认 1/2） |
| `跳数 = 1` | 分簇控件隐藏，`经由` 全为 `undefined` |
| 二跳父节点被截断 | 归入「其他」簇 |
| 下钻后旧节点重现 | 手动位置已清空，按自动布局重新摆 |

## 6. 测试

## 7. 验收判据（真栈）

1. 造一个「枢纽账户 + 120 个对手方」的项目（走生产出口造数）。
2. 打开关系图：全貌默认 `2 跳 / 重点 / 分簇`，图上节点 ≤ 50；枢纽账户带外环。
3. 「强」档后弱关系消失，底部出现「较弱关系 N 条未显示」；点「放宽」回来。
4. 二跳点按「经由」成弧成组，能看出「这批是从谁过来的」。
5. 点「以此为中心」：旧中心与旧邻居消失，只剩新中心这一圈；「← 返回」能回去。
6. 同一个项目在「聚焦」档下 1 跳、无分簇。
