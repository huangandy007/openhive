# 契约：状态与原因码

**来源**：需求文档 §6.4 / §14 第 3 条；spec FR-033 ~ FR-038。

## 状态（六态闭集，不变）

| 状态 | 含义 | 谁触发 |
|---|---|---|
| `未入队` | 文件在项目里，未排队 | 上传（开关关闭）/ 扫描前 |
| `排队中` | 已入队，等后台 | 自动 / 人工入队 |
| `解析中` | 正在跑 | worker |
| `已解析` | 成功入库 | worker |
| `有问题` | 失败或未识别 | worker |
| `已跳过` | 人工跳过 | 人工 |

**MUST NOT 新增第七态。** 探测结论（已识别 / 未识别）是 `probe` 列，不是状态；「未识别」最终仍落 `有问题` + 原因码。

## 原因码（六值，字面值即契约）

```text
未识别:无匹配适配器
未识别:缺必需列:<列名>
未识别:值闸不过:<检查项>
失败:读文件
失败:转换器异常
失败:入库异常
```

| 原因码 | 精确判据 | 触发层 |
|---|---|---|
| `未识别:无匹配适配器` | 适配器注册表零命中，且档案 / 四层识别也未得出结论 | 作业链（M2 前置分支） |
| `未识别:缺必需列:<列名>` | 适配器表头闸不过；`<列名>` = 第一个缺失的必需列（按 `requiredHeaders` 声明顺序） | 探测 / 作业链 |
| `未识别:值闸不过:<检查项>` | 样本行某检查项通过率低于阈值；`<检查项>` = `admission.checks` 中的名字 | 作业链 |
| `失败:读文件` | 读盘 / 读表抛错（含面积闸、编码、空文件） | 作业链 |
| `失败:转换器异常` | 子进程非零退出 / 超时 / 输出不合 `converter-output-contract.md` | 执行器包装层 |
| `失败:入库异常` | 事实行写入事务失败 | 写入层 |

## 写入规则

1. 结构化写入 `case_ingest_job.reason_code`；成功与失败两条路径都在同一处写（`case-ingest.ts:388-398` 的「各自兜底」形状不变）。
2. 自由文本 `parse_detail.reason` 与作业 `error` **保留**，供人阅读；原因码供筛选与统计。
3. 原因码**只覆盖入过队的材料**；`未入队` 材料不伪造原因码（由扫描覆盖，FR-037）。
4. 探测的「未识别」只写 `case_material.probe`，**不**写 `parse_status`；最终状态由作业写。
5. 材料列表的「未识别」筛选口径：最近一次作业 `reason_code LIKE '未识别:%'`；状态取值仍是闭集（FR-038）。

## 测试钉法（TR-003）

- 六种原因码逐值断言**字面值**，禁止只断言「非空」或 `toContain('未识别')`（`#005-47`）。
- 变异：删掉原因码写入 ⇒ 对应字面值断言必须红；把 `缺必需列` 改成 `无匹配适配器` ⇒ 必须红。
