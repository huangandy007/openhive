**设计来源**：本规格唯一依据是 `2026-11-18-数据格式自适应与自动入库-需求.md`（2026-11-19 复核后的版本，下称「需求文档」）。识别四层、数据源档案、属性列与六态状态机以 `2026-11-09-事实卡片抽象/01-事实卡片与数据翻译-设计.md`、`过程文档/05-实体属性标记与入库规范.md` 为准；本规格只写需求文档已写的内容，**未写的部分不新增**。

**现状（2026-11-19）**：上传只落盘、不建材料、不排作业；入库唯一入口是右键「解析入库」；后台单 worker 顺序消费；数据源档案按表头集合匹配（缺列即不命中）；属性列 `属性:<归属>:<键>` 与六态状态机**已落地**；适配器注册表、两道闸探测、转换器执行、富化层、结构化原因码、作业进度、启用后扫描与一键重跑均**未落地**。已落地不代表已验收——本规格的全部需求仍是验收口径，优先级只表示验收先后，**不表示可延后或可砍**。

## Clarifications

### Session 2026-11-19

- Q: 第一个对外版本包含哪些部分（MVP 构成）？ → A: **全量**——需求文档 §12.6 的第 1–4 组全部进第一个对外版本，不分批上线；AC-1 ~ AC-12 全部是发布门槛；P1/P2/P3 只表示验收先后，不表示可延后或可砍。
- Q: 自动入队交付时默认开还是默认关？ → A: **默认开**。准入闸 N8 MUST 先于「对外打开」就绪（同一版本内的编码顺序约束）；项目 MUST 保留关闭开关。
- Q: 微信 `...@wx.tenpay.com` 这类非数字账号能否建账户实体？ → A: **精准放宽**——只增加已知支付账号后缀 `@wx.tenpay.com`（不区分大小写），不做泛化邮箱、不做「含 `@` 即账户」；这些行上的属性与户名别名 MUST 能挂上（FR-030）。
- Q: 「1 秒内给出已识别/未识别」是否含排队？ → A: **不含**。探测 MUST 独立于主转换队列（可并发），单份落盘后 ≤1 秒可见第一版结论；批量以「已探测 k / N」单调增长呈现，不承诺每份 1 秒；**以作业结果为最终结论**（探测不得覆盖）。
- Q: 富化「参考类 / 身份类」怎么分、查不到怎么处置？ → A: **按键的语义分类**（受控表，与数据源无关）：参考类留空 + 告警；身份类进「待确认」；**案件库单列为「匹配」**，未命中记为「未匹配」，既不告警也不进待确认；**未登记的键一律按身份类处理**（fail-closed）。

- Q: 确定性转换是否收进内核、由内核调用适配器？ → A: **是**。这是需求文档 D2 的核心决策，整份交付都建立在此之上；`01` §2.1 / §2.4 的回写登记为后续文档动作，本次不改 `01`。
- Q: 自动入队的范围？ → A: **只限数据目录 / 专用拖入区**，二者共用同一条「落盘 → 建材料」路径，MUST NOT 另开第二套入口实现。
- Q: 是否提供「自动启用可信技能」开关？ → A: **提供，默认关闭**（US8）。
- Q: 作业进度存在哪？ → A: **新增独立的进度列**，不复用 `parse_detail`——后者是给人看的明细，进度是运行中状态，混在一处会让两者语义互相污染。
- Q: 档案是否本次补可选列 / 优先级 / 规则版本 / hints？ → A: **本次补齐四项**，否则多档案只能按命中次数定序，规则版本也进不了报告。
- Q: 可信技能白名单由谁维护？ → A: **单位管理员（平台级）**；项目内只决定「开关开不开」，不给项目属主增删白名单的权限。
- Q: 档案前端是否本次补？ → A: **补列表 / 建档 / 撤销**，否则 A 类「教一次」只能靠 AI 会话完成。
- Q: 重跑时人工改过的**属性值**是否保留（不只是事实行）？ → A: **保留**，与事实行同等待遇；机器重算 MUST NOT 覆盖人工确认过的属性。
- Q: A 类数据源档案是否也受「发布 / 启用校验」？ → A: **是**，至少校验字段映射与必需列，与转换器包同一道发布闸。
- Q: 坏行跳过率是否设阈值？ → A: **不设**；坏行全部计入报告的「跳过行数 + 告警」，只有整份不可用才按原因码判失败。
- Q: `SKILL.md` 的 description 规则怎么验？ → A: **发布评审项**，不要求自动校验；不因此新增 lint 或模型判定。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 拖入一个文件夹，剩下的交给系统 (Priority: P1)

民警把整个文件夹拖进数据目录，不需要挑 skill、不需要先跑预处理、不需要右键。材料列表里立刻出现每份文件，1 秒内每行标出「已识别 / 未识别」，之后系统在后台自己转换入库，用户可以走开再回来。

**Why this priority**: 这是需求文档五条痛点里的前三条（不知道该用哪个 skill、每份文件四步、一直在等）。没有这一步，后面所有能力都没有入口。

**Independent Test**: 经生产上传出口向数据目录拖入 3 份表格，直接查材料表与作业表：断言出现 3 条材料、3 条作业，状态从「排队中」自动推进而无需任何右键动作；同一文件再拖一次，断言材料条数不变、作业新增一次。再把同样的文件经普通上传入口传一次，断言只落盘、无材料行。

**Acceptance Scenarios**:

1. **Given** 数据目录、自动入队开关已打开，**When** 一次拖入 3 份可解析表格，**Then** 材料列表出现 3 条记录，状态自动推进，全程无需右键或 AI 会话。
2. **Given** 同一份文件（同内容指纹）已在项目里，**When** 再次拖入，**Then** 不新建第二条材料，只对已有材料重新入队一次。
3. **Given** 普通文件上传入口（非数据目录、非专用拖入区），**When** 上传任何文件，**Then** 行为与今天完全一致——只落盘，不建材料、不排队。
4. **Given** 一份不受支持的扩展名（PDF、图片、`.xlsm`、名字带尾随空格），**When** 拖入数据目录，**Then** 按现有白名单口径拒绝，白名单不扩大。
5. **Given** 单份文件已落盘，**When** 1 秒内完成表头探测，**Then** 该行显示「已识别」或「未识别」，且探测不排在转换队列之后。
6. **Given** 一次拖入 20 份，**When** 观察前 1 秒，**Then** 必须出现「已探测 k / N」且 k 单调增长；全量转换在后台，状态图标实时更新，「解析中」显示已处理行数 / 总行数或当前阶段。
7. **Given** 用户离开页面，**When** 稍后返回，**Then** 状态与进度不回退；批量时能看到转换队列位置（与探测进度分列）。
8. **Given** 探测已判「已识别」，**When** 后台全量执行失败，**Then** 最终状态为「有问题」+ 原因码，界面不得停留在「已识别」。
9. **Given** 项目把自动入队开关**关掉**，**When** 上传文件，**Then** 只落盘，材料停留在「未入队」；重新打开后，这些文件由启用后扫描纳入候选。

### User Story 2 - 系统自己认格式，用户不选 skill (Priority: P1)

同一份银行流水，上次要人先跑预处理、再右键入库；这次拖进来就自动认出它是哪种格式，按该项目已启用的适配器转换，直接出事实行。新格式由管理员「教一次」——发布一个转换器包或配一条数据源档案——之后本项目全员受益，用户侧再没有「选 skill」这个动作。

**Why this priority**: 「格式多，不知道该用哪个 skill」是第一条痛点，也是本 feature 与现状最大的差别。没有它，自动入队只会把文件更快地送进错误识别。

**Independent Test**: 准备三份同规模文件分别命中「已启用的 B 类转换器」「只有 A 类档案」「两者都没有」，逐份走入口，断言命中路径、报告中的适配器 id / 版本、以及无匹配时的「有问题 + `未识别:无匹配适配器`」。再造一次多适配器同时通过（含两个 `priority` 相同的），重复跑多次，断言每次结论一致。

**Acceptance Scenarios**:

1. **Given** 本项目已启用一个带识别卡的转换器，**When** 拖入与它 `requiredHeaders` 完全匹配的文件，**Then** 内核按适配器执行并读取其 JSON 结果，**跳过**四层识别与模型；报告写明适配器 id 与版本。
2. **Given** 同一份文件同时被适配器与数据源档案命中，**When** 执行，**Then** 以适配器为准，档案不做决策，但「档案也被命中」记进报告便于排查。
3. **Given** 两个适配器都通过两道闸，**When** 选一个执行，**Then** 按 `priority` 取最高；`priority` 相同按 `id` 字典序（不靠目录扫描顺序），重复跑结论一致；报告列出全部命中项。
4. **Given** 没有任何适配器通过，**When** 解析结束，**Then** 材料状态为「有问题」，原因码 `未识别:无匹配适配器`。
5. **Given** 转换器执行抛错或超时，**When** 落入结果，**Then** 状态「有问题」+ 原因码 `失败:转换器异常`，**不得**静默回退到四层识别或模型。
6. **Given** 一个 A 类格式，**When** 建好一条数据源档案后拖入第二份同格式文件，**Then** 零人工入库；若少一列，状态「有问题」+ `未识别:缺必需列:<列名>`；界面能列出现有档案、新建与撤销。
7. **Given** 一个转换器包缺四件套之一、识别卡过不了校验、`entry` 不存在、或 `attributeKeys` 有词表外的键，**When** 发布或启用，**Then** 被拒绝并列出具体缺项 / 越界键。
8. **Given** 转换器产出的结果，**When** 入库，**Then** 只认单文件（事实行与报告同文件）；全程不产生、也不读取 xlsx 副本。

### User Story 3 - 开户行、银行卡号问得到，还带出处 (Priority: P1)

民警问「这个对方账户的开户行是什么」「这个账户有哪几张卡」，AI 能答出值，并且每个值都能翻回 `材料#表#行`。两份材料给出不同开户行时，两条并存而不是互相覆盖；机器补的和人确认过的分得开。

**Why this priority**: 这是第五条痛点「实体属性问不到」。属性列没有按约定落进实体，AI 就只能答「查不到」。

**Independent Test**: 用一份含 `属性:对方:开户行` / `属性:对方:银行卡号` 的真实流水走完整链路，直接查实体属性与出处；再喂一份同一实体、不同开户行的材料，断言两条并存；再喂空值行、全角冒号列名、词表外键各一份，断言三种情形各有明确结论（不产观察 / 进「未认出」/ 照收并告警）。

**Acceptance Scenarios**:

1. **Given** 一份已解析材料带 `属性:对方:开户行`，**When** 查这个对方账户的属性，**Then** 值存在且带 `材料#表#行` 出处。
2. **Given** 两份材料对同一实体的同一属性给出不同值，**When** 查询，**Then** 两条都在（按值去重、保留首次出处，异源冲突不覆盖）。
3. **Given** 属性列在该行为空，**When** 入库，**Then** 不产生观察（不是空值观察）。
4. **Given** 同侧账号是 `...@wx.tenpay.com` 这类非数字账号，**When** 入库，**Then** 该行上的属性与户名别名必须能挂上（口径见 FR-030），**不得静默丢弃**。
5. **Given** 列名用全角冒号（`属性：对方：开户行`），**When** 解析，**Then** 进「未认出」，报告可见，**不得**静默当成合法属性列。
6. **Given** 转换器产出了受控词表之外的键，**When** 入库，**Then** 照收并登记，报告单列「词表外键」并告警——不改名、不丢弃、不静默。
7. **Given** 开户人（户名），**When** 入库，**Then** 走别名而不是属性。
8. **Given** 一个转换器仍输出裸列名 `对方银行卡号` / `本方银行卡号`，**When** 入库，**Then** 内核在疑似标准副本上告警或拒收，**不得**把它静默认成对方账号 / 本方账号。

### User Story 4 - 没解析成，也要说清为什么 (Priority: P1)

一份文件没被解析，材料列表上是一个明确的标记，点开或悬停能读到「为什么」：没有适配器、缺哪一列、哪个值闸没过、还是读文件失败。民警能按「未识别」把这类文件筛出来，也不会把「系统没认出」误当成「文件里没数据」。

**Why this priority**: 静默失败会直接误导研判。状态机不再扩态，但失败必须可判别、可筛选、可复核。

**Independent Test**: 对每种原因码各构造一份文件（无适配器 / 缺必需列 / 值闸不过 / 读文件失败 / 转换器异常 / 入库异常），逐条断言材料状态与原因码**字面值**；再构造一份历史遗留的「未入队」材料，断言它没有原因码、但能被启用后扫描找到。

**Acceptance Scenarios**:

1. **Given** 任意材料，**When** 查看状态，**Then** 取值恒在六态闭集内（未入队 / 排队中 / 解析中 / 已解析 / 有问题 / 已跳过），**不得**出现第七态。
2. **Given** 未识别的三种成因，**When** 写入结果，**Then** 原因码分别为 `未识别:无匹配适配器`、`未识别:缺必需列:<列名>`、`未识别:值闸不过:<检查项>`。
3. **Given** 三类失败，**When** 写入结果，**Then** 原因码分别为 `失败:读文件`、`失败:转换器异常`、`失败:入库异常`。
4. **Given** 材料列表，**When** 按「未识别」筛选，**Then** 只列出原因码前缀为 `未识别` 的材料。
5. **Given** 一份历史上传、从未排队的材料，**When** 查看，**Then** 状态「未入队」且**没有**原因码（不伪造）；它由启用后扫描覆盖。
6. **Given** 一份材料因缺列失败，**When** 查看原因，**Then** 原因码里带具体列名，人话说明同时保留。

### User Story 5 - 启用技能后，旧文件一键重跑 (Priority: P1)

管理员启用了新转换器后，系统主动告诉用户「发现 N 份文件可能适用，是否解析？」。确认后一键批量入队并给出汇总；已经解析过的文件不会被偷偷改写，需要时由人点「用新规则重新解析」，并事先告知「会更新机器结论，人工确认保留」。没权限的人看到的是置灰按钮和「需要项目属主启用」，而不是一句含糊的「请先启动技能」。

**Why this priority**: 没有它，用户得回到目录里一份份翻、一份份右键，自动入队的价值被抵消一半；而自动改写历史数据是不可接受的风险。

**Independent Test**: 先上传一份文件（此时无适配器）→ 断言「有问题 + `未识别:无匹配适配器`」；再启用适配器 → 断言出现含数量的提示；确认后断言一个服务端请求完成批量入队并返回汇总；对已解析材料断言不会被自动重跑；用成员身份与属主身份各走一次，断言按钮可见性与可点击性不同。

**Acceptance Scenarios**:

1. **Given** 文件在适配器启用前上传，**When** 查看状态，**Then** 「有问题」+ `未识别:无匹配适配器`。
2. **Given** 管理员启用适配器，**When** 回到材料页，**Then** 弹出「发现 N 份文件可能适用，是否解析？」，N 与实际候选数一致。
3. **Given** 用户确认，**When** 批量重跑，**Then** 由**一个**服务端请求完成批量入队并返回汇总；前端不循环发 N 次请求。
4. **Given** 已解析的材料，**When** 启用新规则，**Then** 不自动重跑；提供「用新规则重新解析」按钮，并提示「会更新机器结论，人工确认保留」。
5. **Given** 候选范围，**When** 扫描，**Then** 覆盖三类：目录里有但无材料记录的文件、状态「未入队」的材料、状态「有问题」且原因码前缀为 `未识别` 的材料。
6. **Given** 共享项目的成员（非属主），**When** 遇到需要启用的提示，**Then** 看到置灰按钮与「需要项目属主启用」；属主看到「启用并解析」并点一次即可生效。
7. **Given** 同一份文件，**When** 提醒过并被选择「稍后」，**Then** 不再重复弹提示，只在文件行留一个问号标记。
8. **Given** 系统没有对应格式的技能，**When** 用户拖入，**Then** 提示「暂无可用的解析技能」，并提供「提交格式需求」入口。

### User Story 6 - 缺的值批量补全，不逐行查库 (Priority: P2)

一份 5,000 行的流水里约 1,000 个去重后的号码需要补归属地、约 1,000 个账号需要回查案件库已有实体。系统先把键去重收齐，每类查一次，再统一回填——不是一行一行地问数据库。每个补上的值都带「依据 + 置信度 + 版本」；查不到的，参考类留空并告警，身份类进「待确认」而不是猜一个。

**Why this priority**: 没有统一富化阶段，清洗与补全就没有位置；逐行查库在批量导入下会把等待时间放大到不可用。它是 P2 而不是 P1，因为核心承诺（自动识别与入库）不依赖它先到位。

**Independent Test**: 造 5,000 行、约 1,000 个去重键的样本，真栈计时断言富化总开销 < 1 秒；同时用语句计数断言案件库只发出一条批量查询、全程无逐行查询；再构造必查不到的身份键，断言进「待确认」而不是给出猜测值。

**Acceptance Scenarios**:

1. **Given** 一次转换产生 5,000 行，**When** 富化执行，**Then** 先去重产键、每类一次批量查、Map 回填；实测总开销 < 1 秒。
2. **Given** 案件库查询，**When** 检查执行，**Then** 只有一条批量语句，且复用既有唯一索引；不存在按行的重复查询。
3. **Given** 静态参考库，**When** 富化，**Then** 整表载入内存、按版本刷新，而不是逐键查。
4. **Given** 外部服务，**When** 批量请求，**Then** 受并发上限、超时、缓存与负缓存约束。
5. **Given** 一个补全值，**When** 查看，**Then** 同时带 值 / 依据 / 置信度 / 版本。
6. **Given** 参考类键查不到，**Then** 留空并告警、不阻塞入库；**Given** 身份类键查不到，**Then** 进「待确认」，**不得**猜、**不得**写空值；**Given** 案件库匹配不到，**Then** 记为「未匹配」，**不得**告警、**不得**进待确认。
7. **Given** 富化执行位置，**Then** 由内核富化层执行，**不是**转换器的一部分，**不经过** MCP。
8. **Given** 一个未在受控表登记的富化键，**When** 查不到，**Then** 按身份类处理（进待确认），**不得**默认当参考类静默放过。

### User Story 7 - 每份材料的报告与版本可回滚 (Priority: P2)

任取一份已解析材料，都能看到它当时用的是哪个适配器、哪个版本、两道闸的逐项通过率、跳过了多少行、富化了多少、原件 SHA-256 是多少。停用一个适配器后，同格式的新文件不会偷偷用旧规则处理，而是回到「未识别」；历史报告仍保留当时的版本。

**Why this priority**: 没有报告，「为什么这份文件解析成这样」就无从复核；没有版本，「规则升级」与「历史结论被改写」就分不开。

**Independent Test**: 任取一份已解析材料，逐项核对报告五要素；停用适配器后拖入同格式新文件，断言「有问题 + `未识别:无匹配适配器`」且报告未被覆盖；再对历史材料断言报告里的版本号仍是旧版本。

**Acceptance Scenarios**:

1. **Given** 任一份已解析材料，**When** 打开报告，**Then** 五项齐全：适配器 id / 版本 / 规则版本；两道闸逐项（分母、命中、通过率、阈值）；转换行数 / 跳过行数 / 告警清单；富化统计（补全数、未补全数、参考库版本）；原件 SHA-256。
2. **Given** 报告内容，**When** 检查存储，**Then** 报告不进事实行表。
3. **Given** 适配器被停用，**When** 拖入同格式新文件，**Then** 状态「有问题」+ `未识别:无匹配适配器`，**不得**静默使用旧规则。
4. **Given** 停用后回看历史材料，**When** 打开报告，**Then** 仍保留它解析当时的适配器版本。
5. **Given** 规则升级，**When** 生效，**Then** 只提示重跑，**不**自动改写历史结论。

### User Story 8 - 可信技能免确认（可选开关）(Priority: P3)

项目可以打开一个默认关闭的开关：打开后，遇到单位审核过、在白名单内的技能，系统自动启用并解析，成员拖入即入库，无需任何确认。白名单之外的一律仍需提示——不允许任意技能自动执行代码。

**Why this priority**: 它把「首次新格式必须确认一次」的默认安全口径，在受控前提下放开。P3，因为它不是核心承诺，缺了只是多一次点击。

**Independent Test**: 开关关闭时拖入匹配文件，断言仍需提示；打开开关并让技能在白名单内，断言零确认直接解析；把技能移出白名单，断言恢复提示；改动开关后检查留痕记录。

**Acceptance Scenarios**:

1. **Given** 项目级开关，**Then** 默认关闭。
2. **Given** 开关打开且技能在白名单内、已发布，**When** 成员拖入匹配文件，**Then** 自动启用并解析，无需确认。
3. **Given** 开关打开但技能不在白名单，**When** 拖入，**Then** 仍需提示。
4. **Given** 开关被改动，**Then** 变更留痕（谁、何时、改成了什么）。

### Edge Cases

- **拖入文件夹里混有不可解析文件**（PDF、图片、`.xlsm`、尾随空格）：按现有白名单逐一拒绝，不因「同批有可解析文件」而放行，也不扩大白名单。
- **同名不同内容的两个文件**：视为两份不同材料（内容指纹不同）；**不同名同内容**：同一条材料，只重新入队。
- **转换器超时**：落「有问题」+ `失败:转换器异常`，不无限等待，不自动改走模型。
- **样本行通过、全量出现坏行**：坏行进报告「跳过行数 + 告警」，不因此把整份材料判失败；确有整份不可用的，按对应原因码落「有问题」。
- **属性列所在侧建不成实体**：当前会被静默丢弃——这是已知缺口（FR-030），必须有明确口径，验收不得写成「属性已全覆盖」。
- **探测结论与作业结论冲突**：以作业结果为最终结论；探测的「已识别」不得阻止状态回落到「有问题」，也不得让界面停在乐观结论上。
- **词表外键**：运行期照收 + 登记 + 报告单列 + 告警；发布期则直接拒绝（同一份键，两个时机两个动作）。
- **自动入队开关关闭期间落盘的文件**：状态「未入队」，无原因码，等扫描覆盖。
- **同一格式多份同时拖入**：单 worker 顺序消费，排队可见；本次不承诺并发。
- **100,000 行**：只要求有实测记录，不作为阻塞阈值。

## Requirements *(mandatory)*

### Functional Requirements

**入口与材料建立（需求 FR-01）**

- **FR-001**: 数据入口 MUST 在文件落盘成功后**立即**建材料并入队，MUST NOT 等待格式探测结果；探测结果只决定「已识别 / 有问题（未识别）」与原因码。
- **FR-002**: 入队失败 MUST NOT 回删已落盘文件。
- **FR-003**: 自动入队 MUST 只对数据目录 / 专用拖入区生效；二者是**同一入口的两处可见范围**，MUST 走同一条「落盘 → 建材料」路径，MUST NOT 各写一套实现。MUST 只接受现有可解析白名单（`.xlsx` / `.xls` / `.csv` / `.txt` / `.md` / `.log` / `.docx`）；普通文件上传 MUST 保持现状。
- **FR-004**: 一次拖入文件夹 MUST 逐个建材料、逐个排队；同内容指纹 MUST NOT 建第二条材料，重复拖入 MUST 视为对已有材料的重新入队。
- **FR-005**: 自动入队 MUST **交付即默认开启**；准入闸 MUST 先于「对外打开」就绪（编码顺序约束）；项目 MUST 保留关闭开关，关闭期间落盘的文件按「未入队」处理。开发期以开关关闭做内部验证。

**适配器探测（需求 FR-02）**

- **FR-006**: 探测顺序 MUST 为 适配器注册表 → 数据源档案 → 四层识别与模型兜底；适配器命中 MUST 跳过后续识别；档案命中与否 MUST 只记入报告、不参与决策。
- **FR-007**: 探测 MUST 两道闸且顺序固定：表头闸（只读表头）在前，值验证闸（样本行）在后。
- **FR-008**: 零命中 MUST 置「有问题」+ 原因码 `未识别:无匹配适配器`。
- **FR-009**: 多命中 MUST 按 `priority` 取最高；`priority` 相同 MUST 按 `id` 字典序决定，MUST NOT 依赖目录扫描顺序；报告 MUST 列出全部命中项。
- **FR-010**: 报告 MUST 记录实际采用者的适配器 id 与版本。

**转换执行（需求 FR-03）**

- **FR-011**: 规则型适配器 MUST 由内核直接按声明的行规则执行，MUST NOT 启子进程。
- **FR-012**: 转换器型适配器 MUST 由内核调用其入口并读取其 JSON 输出（事实行 + 报告），MUST NOT 读取 xlsx 副本。
- **FR-013**: 转换器 MUST NOT 写库、连库；xlsx 副本 MUST 降级为按需导出，MUST NOT 作为入库必经环节。
- **FR-014**: 转换器失败 MUST 落「有问题」+ 原因码，MUST NOT 静默回退到四层识别或模型。

**转换器包与识别卡（需求 FR-04、§6.1、§6.2）**

- **FR-015**: 一个 B 类格式的转换器包 MUST 为固定四件套：`SKILL.md`、`adapter.json`、`convert.*`、`test/`。
- **FR-016**: `SKILL.md` 的 `description` MUST 只写「什么时候用」，MUST NOT 摘要工作流。该规则为**发布评审项**，MUST NOT 要求系统自动校验文案内容。
- **FR-017**: `adapter.json` MUST 声明：`id`、`name`、`version`、`kind`、`materialType`、`attributeKeys`、`match.requiredHeaders`、`match.optionalHeaders`、`match.priority`、`admission`、`entry`、`output.file`。
- **FR-018**: `requiredHeaders` 缺任一列 MUST 不命中（fail-closed）。
- **FR-019**: `entry` MUST 声明输入与输出；`input` MUST 指原件；输出 MUST 是**一个** JSON 文件，事实行与报告同文件。
- **FR-020**: 转换器输出 MUST 含 `rows` 与 `report` 两段且互不混写；`rowNo` MUST 是源文件行号；金额 MUST 为正数、方向 MUST 只用 `收` / `付` 表达；属性列 MUST 只出现在 `extras`。
- **FR-021**: 报告 MUST NOT 写入事实行表。
- **FR-022**: 发布 / 启用 MUST 校验包：四件套缺件、识别卡 schema 不过、`entry` 不存在、`attributeKeys` 越界，任一成立 MUST 拒绝并列出缺项或越界键。**A 类数据源档案同样受发布 / 启用校验**：至少校验字段映射合法与必需列声明，任一不成立 MUST 拒绝并列出问题项。

**属性列（需求 FR-05、§6.3）**

- **FR-023**: 转换器 MUST 按 `属性:<归属>:<键>` 命名输出属性列；归属 MUST 仅 `对方` / `本方`。
- **FR-024**: 键 MUST 是受控词表的叶子词；转换器 MUST 在 `attributeKeys` 里声明全部会产出的键；没有属性列 MUST 声明空数组。
- **FR-025**: 属性键的口径 MUST 为双层：发布 / 启用期 fail-closed（`attributeKeys` 中任一键不在受控词表内 MUST 阻止发布，执行见 FR-022），运行期不丢原文（见 FR-026）。
- **FR-026**: 运行期遇到词表外的键 MUST 照收并登记，报告 MUST 单列「词表外键」并告警；MUST NOT 静默、改名或丢弃。
- **FR-027**: 属性列 MUST 只认半角冒号；全角 MUST 进「未认出」并可见。
- **FR-028**: 空值 MUST 不产生观察；同一键多值 MUST 并存，按值去重并保留首次出处。
- **FR-029**: 属性列 MUST NOT 参与表类型投票与字段召回。
- **FR-030**: 账户形状判定 MUST 在现有「剥空白与连字符后匹配 `^\d{6,32}$`」之外，**精确放宽**已知支付账号后缀：剥空白后以 `@wx.tenpay.com` 结尾（不区分大小写）同样算账户；MUST NOT 泛化到任意邮箱、MUST NOT 采用「含 `@` 即账户」的判定。属性 MUST 只在该侧能建实体的行上挂载；放宽后这些行上的属性与户名别名 MUST 能挂上，MUST NOT 静默丢弃。新增后缀 MUST 改同一处判定并补对应用例。
- **FR-031**: 户名 MUST 走 `kind='户名'` 的别名，MUST NOT 走属性。
- **FR-032**: 内核 MUST 在疑似标准副本上对裸属性列（`对方银行卡号` / `本方银行卡号`）告警或拒收，MUST NOT 让它静默变成对方账号 / 本方账号。

**状态与原因码（需求 FR-07、§6.4）**

- **FR-033**: 状态 MUST 沿用六态闭集（未入队 / 排队中 / 解析中 / 已解析 / 有问题 / 已跳过）；MUST NOT 新增第七态。
- **FR-034**: 「未识别」MUST 用原因码表达：`未识别:无匹配适配器`、`未识别:缺必需列:<列名>`、`未识别:值闸不过:<检查项>`。
- **FR-035**: 失败 MUST 用原因码表达：`失败:读文件`、`失败:转换器异常`、`失败:入库异常`。
- **FR-036**: 原因码 MUST 结构化写入作业结果；供人阅读的自由文本 MUST 保留。
- **FR-037**: 原因码 MUST 只覆盖入过队的材料；「未入队」材料 MUST NOT 伪造原因码，由扫描（FR-038）覆盖。
- **FR-038**: 材料列表 MUST 支持按「未识别」筛选；状态取值 MUST 仍为闭集。

**启用后扫描与批量重跑（需求 FR-08）**

- **FR-039**: 启用适配器后 MUST 扫描三类候选：目录里可解析但无材料记录的文件、状态「未入队」的材料、状态「有问题」且原因码前缀为 `未识别` 的材料。
- **FR-040**: 扫描结果 MUST 以「发现 N 份文件可能适用，是否解析？」呈现，N MUST 与实际候选数一致。
- **FR-041**: 用户确认后 MUST 由**一个**服务端请求完成批量入队并返回汇总；MUST NOT 由前端循环发出 N 次单文件请求。
- **FR-042**: 已解析材料 MUST NOT 自动重跑；重跑 MUST 由人显式触发，并 MUST 提示「会更新机器结论，人工确认保留」。人工确认 / 人工改过的**属性值**与事实行同等待遇，重跑 MUST 保留。

**技能提醒与权限（需求 FR-09、FR-10）**

- **FR-043**: 提醒 MUST 只在三个时刻出现：项目零数据技能（一次性提示）、上传后未识别（指出具体格式与技能）、启用后扫描（提示可重跑数量）。
- **FR-044**: 提醒 MUST 带按钮；同一份文件 MUST 只提醒一次；选择「稍后」后 MUST 只在文件行留标记。
- **FR-045**: 有权限者 MUST 看到「启用并解析」；无权限者 MUST 看到「需要项目属主启用」且按钮置灰；MUST NOT 用泛泛的「请先启动技能」代替。
- **FR-046**: 系统无对应技能时 MUST 提示「暂无可用的解析技能」并提供「提交格式需求」入口。
- **FR-047**: 「自动启用可信技能」MUST 为项目级开关、默认关闭；开启后 MUST 只对白名单内且已发布的技能自动启用；非白名单 MUST 仍需提示。**白名单由单位管理员在平台级维护**，MUST NOT 由项目属主自行添加。
- **FR-048**: 开关变更 MUST 留痕（谁、何时、改成了什么）。

**富化（需求 FR-06）**

- **FR-049**: 富化 MUST 拆为「产键 → 每类一次批量查 → Map 回填」；MUST NOT 逐行查库。
- **FR-050**: 静态参考库 MUST 整表载入内存并按版本刷新；案件库 MUST 用一条批量查询且复用既有唯一索引；外部服务 MUST 有并发上限、超时、缓存与负缓存。
- **FR-051**: 每个补全值 MUST 带「值 + 依据 + 置信度 + 版本」。
- **FR-052**: 富化键 MUST 按**键的语义**分三类，且类别来自受控表（与数据源无关）：**参考类**（开户行、卡种 / 卡行、号码归属地、行号）查不到 MUST 留空 + 告警且不阻塞入库；**身份类**（证件号、户名、实名核验结论）查不到 MUST 进「待确认」，MUST NOT 猜、MUST NOT 写空值；**匹配类**（案件库的账号 / 人名 / 组织名）未命中 MUST 记为「未匹配」，MUST NOT 告警、MUST NOT 进待确认。**未在受控表登记的键 MUST 按身份类处理**（fail-closed），MUST NOT 默认当参考类。
- **FR-053**: 富化 MUST 由内核富化层执行，MUST NOT 作为转换器的一部分，MUST NOT 经过 MCP。

**反馈与进度（需求 FR-11）**

- **FR-054**: 单份材料 MUST 在落盘后 **1 秒内**给出第一版结论（「已识别 / 未识别」）；探测 MUST 只读表头与样本行，MUST NOT 排在主转换队列之后（独立通道，允许并发）。批量拖入 MUST 显示「已探测 k / N」且 k 单调增长，MUST NOT 承诺每份都在 1 秒内出结论。
- **FR-055**: 全量转换 MUST 在后台执行，状态 MUST 实时更新；「解析中」MUST 显示已处理行数 / 总行数或当前阶段。**探测结论 MUST NOT 覆盖作业结论**：探测为「已识别」而后台全量失败时，最终状态 MUST 为「有问题」+ 对应原因码。
- **FR-056**: 批量作业 MUST 显示转换队列位置（与探测进度分别呈现）；离开页面再回来 MUST NOT 出现状态或进度回退；完成 MUST 可通知。

**报告与版本（需求 FR-12、FR-13）**

- **FR-057**: 每份材料的报告 MUST 含五项：适配器 id / 版本 / 规则版本；两道闸逐项（分母、命中、通过率、阈值）；转换行数 / 跳过行数 / 告警清单；富化统计（补全数、未补全数、参考库版本）；原件 SHA-256。
- **FR-058**: 适配器、数据源档案、参考库 MUST 有版本，且版本 MUST 写入对应材料的报告。
- **FR-059**: 适配器停用后 MUST 回到「有问题」+ `未识别:无匹配适配器`，MUST NOT 静默用旧规则处理。
- **FR-060**: 规则升级 MUST 走「提示 + 一键重跑」，MUST NOT 自动改写历史结论；历史报告 MUST 保留当时的版本。

**安全与治理（需求 §7.2、§7.3）**

- **FR-061**: 转换器 MUST NOT 接触数据库凭据；子进程 MUST NOT 直连数据库；执行 MUST 只读输入、只写临时输出目录，并 MUST 有超时。
- **FR-062**: 启用 / 停用 MUST 按现有项目权限判定（成员与属主差异可见），MUST NOT 仅靠前端隐藏。
- **FR-063**: 转换器执行（哪个版本、哪些文件）MUST 可审计。
- **FR-064**: 适配器、数据源档案、参考库 MUST 走既有资产发布 / 停用流程；版本变更 MUST 通过 `test/` 与金标准回归集。
- **FR-065**: 本次交付 MUST NOT 改变普通文件上传行为、MUST NOT 改变现有解析状态机、MUST NOT 改变数据源档案的表头集合匹配规则。

### Key Entities

- **材料（case_material）**：项目里的一行文件记录；状态取自六态闭集；承载原因码、进度与报告；是「拖入即建、一条记录贯穿全程」的主体。
- **解析作业（case_ingest_job）**：一次执行；记录排队 / 开始 / 结束时间、尝试次数、发起人、结果与原因码。
- **适配器包**：一个格式的处理单元，固定四件套（说明、识别卡、转换实现、测试）；可发布、可停用、带版本。
- **识别卡（adapter.json）**：给内核读的结构化声明；含必需 / 可选表头、优先级、闸门阈值、入口与输出、会产出的属性键。
- **数据源档案（A 类）**：表头集合 → 字段的映射；表头集合匹配、列序无关、缺列不命中；项目级。
- **原因码**：记录「为什么没解析成」的结构化标记；前缀区分未识别与失败。
- **转换报告**：一次解析的可复核凭据；不进事实行表。
- **富化结果**：一个补全值及其依据、置信度与版本。
- **富化键分类表**：受控的「键 → 参考类 / 身份类 / 匹配类」映射；决定查不到时的处置，未登记键按身份类兜底。
- **可信技能白名单**：允许自动启用并执行的技能集合；决定「免确认」的边界。

## TDD Requirements *(mandatory)*

本 feature 严格按 TDD 实现：**先写会红的用例 → 写最小实现到绿 → 重构**。没有先观测到红的行为，不算实现完成（宪法「九、Implementation Discipline」）。

- **TR-001**: 每一条 FR 在写实现前 MUST 先有至少一条会红的自动化用例；红的原因 MUST 是「缺该行为」，不是拼写或环境错误；红时实得值 MUST 记录在实现报告里（`#003-03`、`#005-49`）。
- **TR-002**: 材料与作业 MUST 经生产出口建立（真实上传 / 真实入队），MUST NOT 在用例里裸种 SQL（`#006-28`、`#006-35`）；夹具与产物 MUST NOT 抢占固定目录（`#006-09`）。
- **TR-003**: 六态闭集 MUST 有用例钉住「非法转移被拒」；六种原因码 MUST 逐值断言**字面值**，MUST NOT 只断言「非空」（`#005-47`）。
- **TR-004**: 适配器探测 MUST 覆盖三态（零命中 / 唯一命中 / 多命中），且多命中 MUST 用两个 `priority` 相同的适配器重复跑多次，断言结论恒为同一 `id`；MUST NOT 用一次性运行冒充确定性。
- **TR-005**: 属性列 MUST 用真实行原文的用例（`#013-07`），并逐项覆盖：空值不产观察、全角冒号进「未认出」、同键多值并存、词表外键照收并告警、裸列名告警或拒收、非数字账号不静默丢弃。`@wx.tenpay.com` 行 MUST 有一组用例同时钉住「属性挂上」与「户名别名挂上」，且该用例 MUST 先于首个转换器入库（C7 先于 C2）。
- **TR-006**: 重跑 MUST 有「不叠加」用例：同一材料连续重跑两次，派生数据（属性、别名、富化缓存、参与者）行数 MUST 不增长；新增派生存储 MUST 各自有清理用例。
- **TR-007**: 「无逐行查询」MUST 用语句数 / 调用次数断言，MUST NOT 只看最终结果对不对（`#004-01`：按底层调用点数够）；5,000 行 < 1 秒 MUST 在真栈实测，MUST NOT 用 PGlite 推断。
- **TR-008**: 变异验证 MUST 成对拆（`#005-37`）：拆表头闸、拆原因码写入、拆按材料清理出口、拆 `priority` 决胜，各自 MUST 让对应用例变红，红成什么样按 `#003-03` 三类据实记。
- **TR-009**: 门禁 MUST 在仓库根跑受影响包的 typecheck + 测试 + oxlint（`#004-10`）；根目录 `bun test` 被脚本禁止，MUST NOT 从根跑；单条用例 MUST 带 `timeout` 运行；跑不动的门禁 MUST 明说没跑。
- **TR-010**: 前端断言「元素不存在」MUST 用布尔比较，MUST NOT 用 `toBeNull()`（`#013-12`）；置灰按钮 MUST 同时断言「不可点击」与「原因可见」。
- **TR-011**: 验不了的项（真实模型 A1/A2、100,000 行性能、20 份并发观感）MUST 写进缺口表，MUST NOT 写成已覆盖（`#004-03`）。
- **TR-012**: 探测通道 MUST 有三组用例：单份落盘后 ≤1 秒出结论、批量「已探测 k / N」在 1 秒内出现且单调增长、探测「已识别」但全量失败时最终状态为「有问题」+ 原因码（变异：把探测结论直接当最终状态，最后一条必须变红）。
- **TR-013**: 富化三类处置 MUST 各有用例（参考类留空告警 / 身份类进待确认 / 匹配类记未匹配），并单列「未登记键默认进待确认」（变异：把默认值改成参考类，该用例必须变红——`#005-47`）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 单份可解析表格落盘后 **1 秒内**显示「已识别 / 未识别」；一次拖入 20 份时 **1 秒内**出现「已探测 k / N」并单调增长；全程**零次**右键「解析入库」动作。
- **SC-002**: 已识别格式 5,000 行端到端 **≤ 10 秒**（阻塞项）；100,000 行只要求留下实测记录，不设阻塞阈值。
- **SC-003**: 5,000 行、约 1,000 个去重键的富化开销 **< 1 秒**，且逐行查询语句数 **为 0**。
- **SC-004**: 未识别与失败的样本 **100%** 落到六种原因码之一，且能在材料列表按「未识别」筛出；「未识别」被说成「系统故障」的次数为 0。
- **SC-005**: 进入结论的每一个属性值 **100%** 带 `材料#表#行` 出处；两份材料冲突时 **100%** 两条并存。
- **SC-006**: 同内容指纹重复拖入 **100%** 不新建第二条材料。
- **SC-007**: 同一材料连续重跑 N 次，派生数据行数 **恒定不增长**。
- **SC-008**: 需求文档 §8 的 **AC-1 ~ AC-12 全部通过**；其中 AC-8 的 100,000 行只要求实测记录。
- **SC-009**: 所有新增或反转的用例在实现前均观测到红（记录实得），实现后全绿；变异验证逐条留痕；缺口项如实列出。

## Scope Boundaries

- **由相邻能力负责**：识别四层内部（别名、词典、形状、模型兜底）与翻译内核、六状态状态机、`case_event` / `case_entity` / `case_citation` 结构、既有 MCP 工具契约——本次**只在其前加探测或在旁加出口，不改判据**。
- **本期不做**：跨项目共享数据源档案（项目级为止）；首次新格式全自动（除可信技能白名单外必须确认一次）；模型直接写库、转换器直连数据库；重写现有解析状态机；百万行入库性能（只记录，不承诺）；批量并发消费（本次仍单 worker，顺序消费）。
- **已知缺口（验收不得写成已覆盖）**：
  - **其它支付账号形状**（支付宝邮箱等，微信 `@wx.tenpay.com` 已按 FR-030 放宽）：仍不满足账户形状，其行上的属性与户名别名会被丢弃；验收**不得**宣称属性列已覆盖所有支付账号。
  - **真实模型识别（A1 / A2）**：本机不可验，只登记不关闭；本次代码交付完成后，对应验收单位仍可能停在「待验收」。
  - **100,000 行性能**：只有实测记录，无阻塞阈值。
  - **20 份并发的观感**：单 worker 顺序消费，本次只承诺「队列位置可见」，不承诺并发提速。
- **交付边界**：一次性交付指**对外只发一个版本**，不指所有改动同时动手；编码顺序与硬依赖由 plan 阶段按需求文档 §12.6 展开（含「清理出口先于批量重跑」「发布校验先于注册表加载」「非数字账号口径先于首个转换器入库」「准入闸先于自动入队对外打开」）。第一个对外版本**即全量**：第 1–4 组全部能力、AC-1 ~ AC-12 全部为门槛；**不存在可对外发布的「部分 MVP」**（见 Clarifications）。
