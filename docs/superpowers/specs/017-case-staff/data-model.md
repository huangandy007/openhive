- 编号与文件名、索引行三者一致（校验器检查）；
- `P`/`O` 只给需要跨文档引用的对象编号；证人、被害人、民警写姓名。

## 3. 台账表结构

### 3.1 材料登记表（8 列，设计 §6.3 定）

```markdown
| M编号 | 原文件名 | 当前路径 | 材料类型 | 上传时间 | 关联E | 状态 | 备注 |
```

- 状态：`待归档` / `已归档` / `待归类`（FR-032：**不设**解析状态，异常写备注）。
- 当前路径：项目相对路径，必须与盘上一致（FR-025）；移动后由 AI 经 `move_material` 后更新。
- 关联E：多值用 `、` 分隔。
- 备注：同批写 `同批：YYYY-MM-DD-来源`；解析异常写 `解析异常`；待归类写原因。

### 3.2 证据索引（18 列，附录 B 定）

```markdown
| E编号 | 法定种类 | 证据名称 | 来源M | 提取人 | 提取时间 | 提取地点 | 保管链 | 证明内容 | 待证事实 | 证明力/局限 | 印证证据 | 原件/介质存放地 | 哈希/校验 | 风险标记 | 状态 | 确认人 | 确认时间 |
```

- 法定种类：八类之一或 `待定`；`待定` 必须在风险标记写 `种类待定：<原因>；补正期限 YYYY-MM-DD`（FR-046）。
- 待证事实受控类别：`主体身份` / `主观明知` / `客观行为` / `犯罪数额` / `危害后果` /
  `共同犯罪地位` / `量刑情节` / `程序事实`（每行至少一个；F 启用后须覆盖到 F）。
- 状态：`草稿` / `已确认` / `已排除`。

### 3.3 研判索引（11 列，附录 C 定）

```markdown
| A编号 | 日期 | 主题/问题 | 输入E/F/A | 推理摘要 | 结论（事实说明什么） | 新线索L | 置信度 | 状态 | 产出/下一步 | 复核人 |
```

- 状态五档：`新发现` / `分析中` / `已证实` / `已排除` / `待补证`；`已证实` 必填复核人（FR-047）。
- 置信度：`高` / `中` / `低`。
- 结论列**禁止罪名认定表述**（校验器按词表拦「构成…罪」「涉嫌…罪」——词表在
  `scripts/lib/`，不写具体罪名）。

### 3.4 待证事实清单（F，plan 定，默认关闭）

写在 `案件信息.md` 的受管小节内，列：

```markdown
| F编号 | 待证事实 | 对应构成要件/情节 | 覆盖E | 状态 | 备注 |
```

状态：`未覆盖` / `部分覆盖` / `已覆盖`。启用后校验 E↔F 双向覆盖（FR-050）。

### 3.5 任务台账（plan 定）

```markdown
| T编号 | 任务 | 责任人 | 期限 | 状态 | 来源 | 反馈 | 备注 |
```

- 状态：`待办` / `进行中` / `已完成` / `已取消`；`逾期` 是**派生**（期限 < 今日且未完成），不写入。
- 期限：`YYYY-MM-DD` 或 `当日` / `持续`（后者不参与逾期判定）。

### 3.6 线索台账（plan 定）

```markdown
| L编号 | 发现日期 | 线索内容 | 来源 | 状态 | 下一步 | 转研判A | 备注 |
```

- 状态：`待核查` / `核查中` / `已证实` / `已排除` / `转研判`。
- 来源：`A` / `E` / `日报` / `会议` / `现场` / `技术` + 编号；转研判后回填 A 编号。

### 3.7 印证台账（plan 定）

## 5. 托管块与源版本指纹

### 5.1 托管块语法（FR-071，设计 §12.4）

```markdown
<!-- AUTO:BEGIN 抓捕对象 -->
…由台账生成的表格…
<!-- AUTO:END 抓捕对象 -->
```

- 名称：`[^\s]+`，同一文件内唯一，**不许嵌套**；
- `BEGIN`/`END` 必须成对、顺序正确；不配对 = 校验错误；
- 同步只替换块内内容；块外一字不动；
- 发放版（`*-发放版.md`）与已签发/已发放文书**没有**托管块语义：任何情况下不改。

### 5.2 源版本（指纹）

D 表「源版本（指纹）」= `sha256(规范化后的源台账内容)`，规范化规则：

1. 取该文档声明的源（如 `P001`、`E`、`A`）；
2. 只取源台账的**数据行**（跳过表头、分隔行、`<!-- AUTO:* -->` 与空行）；
3. 每行去首尾空白、单元格内连续空白压成一个空格、行尾去 `|` 外的空白；
4. 按源顺序拼接，行间 `\n`，末尾不加换行；
5. `sha256` 的 16 位小写十六进制前缀写入 D 表。

`sync_docs.py --dry-run` 比对「当前指纹」与 D 表记录：不同即列入影响清单，并输出逐项 diff。


## 7. 校验不变量（`validate_case.py` 的检查清单）

| 组 | 不变量 | 级别 |
|---|---|---|
| 引用 | 文本中的 `E\d{3}` / `A\d{3}` / `L\d{3}` / `T\d{3}` 均存在于对应台账 | 错误 |
| 编号 | 同前缀无重复；文件名编号与索引行编号一致 | 错误 |
| E | 法定种类合法或待定+补正；来源 M 存在；证明内容 / 待证事实非空且非法律结论；印证 E 存在 | 错误 |
| A | 状态合法；`已证实` 有复核人；输入 A 无环；结论无罪名认定 | 错误 |
| L/V/T | 来源/对应编号存在；转研判回填 A；V 结果合法 | 错误 |
| D | 来源记录存在；法律文书在拘留/报捕/起诉节点有复核人+复核时间 | 错误 |
| M | 登记表路径在盘上存在；`材料/` 下每份文件（除登记表自身与 `.gitkeep`）有 M 行 | 错误 |
| 积压 | `00-待归档/` 有文件；状态 `待归类` 的行；原始记录缺「已整理」 | 警告 |
| 命名 | §4.1 正则、禁用词、目录白名单（外部来件豁免） | 错误 |
| 规模 | 单目录 > 200 文件 | 警告 |
| 阶段 | 状态属于五态；阶段行齐全 | 错误 |
| 逾期 | T 行 `未完成`/`进行中` 且期限早于当天 ⇒ `T_OVERDUE` | 警告 |
| 跨文档 | 同一编号在两处定义冲突（P 姓名/角色：人员台账↔抓捕对象清单；阶段看板↔阶段行）⇒ `X_CONFLICT`；汇总数字差异（人数/金额）⇒ `X_CONFLICT` | 错误 / 警告（身份字段冲突为错误，汇总数字为警告） |

`--strict`：警告计为失败（退出码 1）；有错误 → 退出码 2；全干净 → 0。

## 8. 与平台数据的对应关系

| 技能侧 | 平台侧 | 对应方式 |
|---|---|---|
| M 编号 | `auth.case_material.id` | **不直接对应**；以「原文件名 + 当前路径」对应 |
| 同一份文件识别 | `case_material.fingerprint`（内容指纹，唯一，移动不变） | 技能不存指纹，只在需要判重时提示去平台查 |
| 解析状态 | `case_material.parse_status` 六态 | 只读；异常写备注「解析异常」 |
| 材料移动 | `POST /openhive/file/move` / MCP `move_material` | 移动后 `case_material.path` 由 `迁移材料路径` 同步 |
| 产物文件 | `case_material`（`kind='产物'`，`parse_status='未入队'`） | 技能不主动登记产物；由平台产物保存链路处理 |
| 事实引用 | `[[fact:<类型>:<id>]]`（类型限 entity / relation / event） | 技能**不使用**（M/E 不在允许类型内，见 research D12） |
| 视图 | `case://<projectId>/<view>/<arg>` | 研判的时间线/关系图/资金图按需引用，不复制数据 |
