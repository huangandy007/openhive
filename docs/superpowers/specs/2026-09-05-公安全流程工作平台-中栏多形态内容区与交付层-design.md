- **日期**：2026-09-05

## 1. 背景与目标

### 1.1 产品初衷：个人提效、组织增智

本产品的初衷是**个人提效、组织增智**。公安工作应在**各个环节**都能利用 AI 提高效率——只提升某一个环节的效率，无法让整个组织的效率整体提升。

因此 openhive 必须**放眼公安工作的全流程**，而非仅仅停留在情报研判（话单 / 资金分析）。全流程至少包括：

| 环节 | 典型工作 | AI 能交付什么 |
|---|---|---|
| 情报研判 | 话单分析、资金分析 | 研判报告、关系图谱、资金流向图、统计报表、**分析思路/结论** |
| 内勤文字 | 通知、总结、汇报、简报、会议纪要 | 各类公文（docx） |
| 方案制作 | 行动方案、工作方案、安保方案 | 方案文档（docx / pptx） |
| 考核督导 | 考核方案、督导报告、评分 | 考核报告（docx / xlsx） |
| 专项行动 | 行动方案、战果统计、专报 | 方案、战果报表、专报 |
| 案件办理 | 卷宗整理、侦查材料、文书 | 案件文书、材料清单 |
| 审讯取证 | 讯问提纲、笔录、取证清单 | 讯问提纲、笔录整理 |
| 报捕起诉 | 提请批捕、起诉意见、案卷 | 提请批准逮捕书、起诉意见书 |

**共性**：所有环节的产出，形态都收敛到「文档（docx）+ 表格（xlsx）+ 演示（pptx）+ 图（图谱/图表）」四类，以及「结构化分析结论」。这正是「中栏多形态内容区 + 交付层」能横向覆盖全流程的根本原因。

### 1.2 两个关键纠正

相对此前「研判工作台」定位，本设计做两点纠正：

1. **去掉脱敏**：前期话单 / 资金分析设计了「敏感字段脱敏」功能。用户明确不需要——**这些数据本来就是拿来分析的，屏蔽了怎么分析**。故本设计移除脱敏开关与列级脱敏，分析对象始终明文可见（合规边界由 RBAC 权限控制，而非对数据本身做脱敏）。
2. **分析思路 / 分析结论是一等公民**：研判不只是「看图出报告」，**分析思路（我为什么这么分析）和分析结论（我得出什么判断）本身就要能编辑、存档、对照**——这是「组织增智」的关键落点，老民警的思路能沉淀下来供新人对照学习，也是串并案的依据。

## 2. 已确认的设计决策

| 决策项 | 结论 |
|---|---|
| 产品定位 | **公安工作全流程 AI 工作平台**（情报研判只是其中一个环节） |
| Office 文档（Word/Excel/PPT）编辑方式 | **AI 生成 + 在线预览 + 拖拽到本地编辑 + 拖拽回**（不部署 OnlyOffice，不自研重编辑器） |
| 思维导图 / 图文混排（轻格式） | 中栏**在线编辑**（轻量编辑器） |
| 文档定位 | **文件树的一等公民**，不是独立「工作区」 |
| 交付物范围 | **一次性做完**：研判报告 + 关系图谱 + 资金流向图 + 统计报表；其余环节复用同一交付引擎 |
| 「项目」→「案件」 | 一级对象对齐到公安语境（案件聚合话单/资金/证据/产物） |
| 分析思路 / 分析结论 | **可编辑、可存档、可对照**，作为案件资产沉淀 |
| 业务技能包 | 「怎么分析」的方法资产（护城河），与交付层（「产出什么成品」）是同一链路的两段，见 §6 |
| 数据脱敏 | **移除**（分析数据始终明文，合规靠 RBAC 而非脱敏） |

## 3. 全流程环节地图

产品不再以「工作区类型（代码/话单/资金）」为一级心智，而以**「案件」为轴，环节为线**：

```
                     ┌─────────────────────────────────────────┐
                     │           案件（一级对象）              │
                     └─────────────────────────────────────────┘
        ┌────────────┬────────────┬────────────┬────────────┬───────…
     情报研判      内勤文字      方案制作      考核督导      专项行动   …
        │            │            │            │            │
   话单/资金      通知/总结    行动/安保     考核/督导     方案/战果
        │            │            │            │            │
   研判报告       公文docx      方案docx     考核docx      战果xlsx
   关系图谱         /pptx         /pptx        /xlsx        专报docx
   资金流向图
   统计报表
   分析思路/结论
        └────────────┴────────────┴────────────┴────────────┴───────…
                              ↓ 统一落到
                    中栏多形态内容区（预览/编辑）
                              +
                    交付层（模板化生成）
```

- **每个环节**接入「中栏多形态内容区」查看/编辑其产物，接入「交付层」AI 生成其产物。
- **交付引擎与模板体系是通用的**：情报研判出「研判报告」，考核督导出「考核报告」，报捕起诉出「起诉意见书」——区别只在**模板**与**数据来源**，生成链路完全一致。

## 4. 中栏多形态内容区

### 4.1 内容类型清单与视图路由

| 内容类型 | 格式 | 中栏视图 | 能力等级 |
|---|---|---|---|
| Word 文档 | `.docx` | 文档预览 | 在线预览 + 拖拽到本地编辑 |
| Excel 表格 | `.xlsx` | 表格预览 | 在线预览 + 拖拽到本地编辑 |
| PPT 演示 | `.pptx` | 幻灯片预览 | 在线预览 + 拖拽到本地编辑 |
| PDF | `.pdf` | 翻页预览 | 在线预览 |
| 思维导图 | `.xmind` / `.md` | 导图视图 | **在线编辑** |
| 图文混排 | `.md` / 富文本 | 富文本编辑器 | **在线编辑** |
| 图片 | `.png` / `.jpg` | 图片预览 | 在线预览 |
| 话单数据 | 数据表 | 明细表 + 关系图谱 | 查询 + 可视化 |
| 资金数据 | 数据表 | 明细表 + 桑基图 | 查询 + 可视化 |
| **分析记录** | 富文本 + 结构化 | 分析记录视图 | **在线编辑 + 对照** |
| 代码 | 源码 | 代码编辑器 | 保留（降级为可选） |

- **视图路由**：一个「内容视图注册表」`扩展名 → 视图组件`。文件树点文件 → 查注册表 → 中栏渲染对应视图。新增格式只需注册新视图，框架零改动（复用 specs §9.4「工作区注册」思路，下沉为「视图注册」）。
- **分析记录**是新增的一等公民内容类型，见 §5。

### 4.2 文档编辑方式：拖拽到本地 ↔ 拖拽回

这是本设计的核心交互，复用 specs §10.3 已有上传/下载能力，以「拖拽」形式呈现：

```
文件树里的 .docx/.xlsx/.pptx
   →（拖拽出浏览器到本地桌面/文件夹）= 下载到本地
   → 本地用 WPS/Office 编辑
   →（拖拽回资源管理区）= 上传
   → 覆盖原文件（项目是 git 仓库，自动 commit 留痕）
```

- **拖拽出**：浏览器 drag-out 能力，文件树条目可拖出到桌面，触发下载。
- **拖拽回**：drag-in 上传（specs §8.13 已有拖拽上传），拖回同名文件 = 覆盖 + git commit 留痕。
- **版本留痕**：不搞额外版本系统，靠 git 历史天然留痕（符合 CLAUDE.md「最小侵入 + 复用 opencode 原生能力」）。
- **AI 生成优先**：多数文书由 AI 生成，民警只需拖出去微调，再拖回来归档。

### 4.3 与「案件」工作区的衔接

- 文档是「文件树里的一等公民」，不是独立工作区。
- 「案件」作为一级对象，天然聚合：**话单数据 + 资金数据 + 证据文件（docx/pdf/图片）+ 全流程产物（报告/方案/文书/报表）+ 分析记录**，全部在中栏统一查看。
- specs §9 的「工作区抽象」保留，但**权重反转**：话单 / 资金 / 文档是主角，代码是配角；文档作为通用文件能力横跨所有环节。

## 5. 分析思路 / 分析结论：编辑 · 存档 · 对照

这是本设计新增的核心能力，直接服务「组织增智」初衷。

### 5.1 为什么需要

研判（话单/资金）时，民警的产出不只是「一张图、一份报告」，而是**一套分析思路和判断**：

- **分析思路**：先从通话频次入手锁定核心号码 → 再查资金流向 → 串联同伙 → 确定层级。
- **分析结论**：核心嫌疑人是 A，资金链是 A→B→C，A 通过 B 洗钱后转给 C。

这两样东西，如果只存在会话里、随会话翻篇，**经验就流失了**。把它们结构化、存档、可对照，才能让**个人经验沉淀为组织资产**。

### 5.2 能力设计（自动生成草稿 · 手动修订定稿）

原则：**编辑 = 自动生成草稿 + 手动修订；存档 = 自动存草稿 + 手动定稿**。既不把民警当打字员（全手动违背「个人提效」初衷），也不让 AI 结论未经审核就进正式资产（全自动违背「人在回路」）。

| 能力 | 自动（AI） | 手动（民警） |
|---|---|---|
| **编辑** | 分析过程中 AI 边分析边归纳「分析思路」「分析结论」为结构化草稿，民警无需从零写 | 民警修订、补充、纠正（AI 可能漏判误判，最终判断在民警）；结论可关联证据（勾选的数据行、图谱节点） |
| **存档** | 每个分析阶段自动存「草稿快照」到案件，经验不丢 | 民警确认后「定稿」，定稿才进入正式对照与串并案 |
| **对照** | 对定稿做辅助检索（相似案件 / 类案推荐） | 民警发起对照，见下 |

**对照的三种形态**：

- **纵向对照**：同一案件不同阶段（初判 → 深入研判 → 结案）的思路演进；
- **横向对照**：不同案件的分析思路/结论并排比对，支撑**串并案**与**类案参考**；
- **学习对照**：新人对照老民警沉淀的成熟分析范式。

### 5.3 数据形态

- 分析记录 = `结构化字段（案件、环节、时间、作者）+ 富文本正文（思路 + 结论）+ 关联引用（数据行 / 图谱节点 / 文件）`。
- 存储复用文件树（Markdown 或富文本），结构化字段用 frontmatter 标注，git 留痕。
- 对照视图：中栏可「并排打开」多份分析记录，或「筛选 + 列表」式浏览，做串并案参考。

## 6. 业务技能包与交付层：一条链路的两个阶段

两者不是并列的独立能力，而是**同一条研判链路的先后两段**：

```
业务技能包（怎么分析） → 结构化分析结论（中间产物） → 交付层（怎么产出成品）
      分析过程              分析结果                      成品输出
```

| | 公安业务技能包 | 交付层 |
|---|---|---|
| 本质 | 分析的过程 / 方法 | 分析的成品 / 输出 |
| 回答的问题 | 「拿到数据，怎么下手分析」 | 「分析完了，怎么变成能交的东西」 |
| 沉淀 | 老民警的分析套路（话单关系分析、资金链路追踪、涉案画像、同案串并…） | 全环节的格式模板（报告/图谱/报表/文书模板） |
| 对标竞品 | WorkBuddy「数字员工 / 技能市场」 | 千问「交付型 AI」 |

**衔接点 = 结构化分析结论**：

- 技能驱动 AI 一步步拆数据，产出「谁和谁通话、频率、核心人员、资金链 A→B→C」这样的**结构化结论**。
- 交付层把这个结论灌进不同模板，产出 docx / 图 / xlsx。

**一个技能 → 多个交付物**：同一个「话单关系分析」技能跑完，民警选「出报告」就出研判报告、选「出图」就出关系图谱、选「出表」就出统计报表——同一套结论，三个模板。

**为什么缺一不可**：

- 只有技能、没有交付层 → 分析到位但结论停在会话里，民警还得手动整理，价值链在成品处**断掉**。
- 只有交付层、没有技能 → 模板再漂亮，AI 不懂公安分析套路，出不来有价值结论，**空有格式没内涵**。

**一句话**：技能是「护城河」（沉淀公安业务经验，竞品没有），交付层是「价值出口」（让成品一键落地）。技能保证「分析有深度」，交付层保证「成果能交付」。

## 7. 交付层

### 7.1 交付物清单（一次性做完）

| 交付物 | 格式 | 说明 |
|---|---|---|
| 研判报告 | Word / PDF | 研判环节最高频交付物 |
| 话单关系图谱 | 交互图 / 图片 | 谁和谁通话、频率、聚类、核心人员 |
| 资金流向图 | 桑基图 / 图片 | 来源 → 中转 → 去向、分层转移 |
| 统计报表 | Excel | 汇总指标、趋势图 |
| 分析记录 | 富文本 / Markdown | 分析思路 + 分析结论（§5） |

> 其余环节（内勤 / 方案 / 考核 / 专项 / 案件 / 审讯 / 报捕起诉）复用**同一交付引擎**，通过配置不同**模板**产出对应文书。生成链路见 §7.2。

### 7.2 通用生成链路（全流程共用）

```
民警勾选数据 / 结束一段分析 / 指定一个环节
   → 点右栏「生成」
   → AI 汇总会话上下文 + 选中数据 → 产出结构化内容
        （按所选环节模板：案情摘要 / 数据来源 / 分析过程 / 结论与建议 …）
   → 套用「环节模板」（单位抬头、字体、段落、落款）
   → 生成 .docx（可另存 PDF）/ .xlsx / .pptx
   → 中栏自动打开预览
   → 一键存回案件空间（文件树可见，随案件归档）
```

- **模板体系**（管理员可配置）：每个环节一套模板——「研判报告模板」「考核报告模板」「起诉意见书模板」「专项行动方案模板」……AI 只填结构化字段，**不做自由排版**，保证全单位格式统一，对标千问「PPT 保留母版」。
- **生成方式**：模板 + 结构化字段填充（而非 AI 自由排版）。

### 7.3 关系图谱 / 资金流向图

- AI 从话单/资金数据**抽取实体关系**（人、号码、账户、交易往来），产出结构化关系数据。
- 中栏用图可视化库渲染**可交互图谱**（拖拽、缩放、筛选、钻取核心节点），可导出图片插入报告。

### 7.4 统计报表

- AI 从话单/资金数据汇总关键指标（总量、趋势、分布），产出结构化报表数据。
- 套用「报表模板」生成 `.xlsx`（带公式、带样式），中栏预览 + 拖拽到本地编辑。

### 7.5 模板体系

- 管理员后台配「报告模板」「图谱样式」「报表口径」及**全流程各环节文书模板**，全单位统一。
- 民警只需「勾选数据 + 选环节 + 一句话」，格式由模板兜底。

---

## 8. 闭环数据流

```
民警选环节/勾数据 → AI 出报告/方案/文书/图谱/报表 → 中栏预览 → 存回案件
                              ↑ 拖出本地微调 → 拖回归档 ↓
         分析过程：记录思路/结论 → 存档 → 对照（串并案/类案/学习）
```

民警全程不离开平台、不用管排版、不用手抄结论；分析经验不流失，沉淀为组织资产。

## 9. 技术选型（建议，实现时验证）

| 能力 | 建议方案 | 说明 |
|---|---|---|
| Word 预览 | docx-preview（纯前端） | 浏览器渲染 docx 为 HTML |
| Excel 预览 | SheetJS / LuckySheet | 前端渲染 xlsx |
| PPT 预览 | pptx → 图片/PDF（pdf.js） | 后端 LibreOffice headless 转换 |
| PDF 预览 | pdf.js | 前端翻页 |
| 思维导图 | markmap（Markdown → 导图） | 与图文混排 Markdown 统一 |
| 图文混排 / 分析记录 | TipTap（富文本） | 支持图片粘贴；分析记录用 TipTap + frontmatter |
| 关系图谱 | AntV G6 | 中文文档好、图布局成熟 |
| 桑基图/统计图 | ECharts | 桑基、时序、柱状、饼图 |
| 文书生成 | docx 模板 + docxtemplater 填充 | AI 产结构化 JSON → 填充模板 → 出 docx |
| PDF 导出 | LibreOffice headless | docx → pdf |

> 全部为内网可自建的开源方案，无外部 SaaS 依赖。

## 11. 分阶段实施

| 阶段 | 内容 | 说明 |
|---|---|---|
| 1 | 中栏多形态内容区 | 视图注册表 + 文档预览（docx/xlsx/pptx/pdf）+ 思维导图/富文本在线编辑 + 拖拽出/回 |
| 2 | 交付层 - 研判报告 + 分析记录 | 模板体系 + 报告生成 + 分析思路/结论编辑·存档·对照 + 中栏预览 + 存回案件 |
| 3 | 交付层 - 图谱/报表 | 关系图谱、资金流向图、统计报表 |

| 5 | 全流程文书模板 | 内勤/方案/考核/专项/案件/审讯/报捕起诉各环节模板 + 通用生成引擎接入 |

## 12. 待决策点（剩余）

1. **「案件」命名与结构**：是否正式把「项目」重命名为「案件」？案件字段（案件编号、性质、承办人）何时补齐？
