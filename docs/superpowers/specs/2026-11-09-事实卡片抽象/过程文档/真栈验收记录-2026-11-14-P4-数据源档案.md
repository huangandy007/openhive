## 5. 复跑方式（供获用户同意后执行）

> 起栈是长驻进程：用后台任务启动，**不套 `timeout 300`**（否则 5 分钟被杀）；其余命令逐条前缀 `timeout 300`。

1. **起栈**（先按记忆核对旧进程启动时间与命令行，确认端口无监听；**不要**直接杀陌生进程）：

   ```bash
   cd D:/project/study/openhive/openhive/packages/app && \
   REAL_STACK_STATE_DIR="D:/openhive-stack-state" OPENHIVE_ASSETS_ROOT="D:/assets" REAL_STACK_DB=remote \
   bun e2e/real-stack/stack.ts
   ```

   等 `STACK_READY`（含 `kernel` / `front` / `db` 三字段）后再继续。

2. **确认迁移**：远端库 `auth._migration` 应有 `0043`；`information_schema.columns` 应有 `auth.case_material.format_fingerprints`（`NOT NULL`、默认 `'[]'::jsonb`）与 `auth.case_source_profile` 表、`case_source_profile_active` 部分索引。

3. **重放 699 行真实材料**：带 `.stack.json` 的 cookie（`openhive_session`）调
   `POST /openhive/case/parse {"projectId":…,"path":…,"action":"重新解析"}`，轮询 `auth.case_material.parse_status` 到 `已解析`。

4. **建档**：`build_source_profile`（MCP）或 `POST /openhive/case/source-profile/build`（HTTP，需属主身份），参数为材料 id（可带 `工作表` / `名称` / `覆盖`）。
   注意实现层缺口：建档读 `case_table_format`；材料若**只被档案命中过**（从未普通识别），会得到 `no_usable_sheet`。首次验收请用**普通识别产生过缓存**的材料建档。

5. **再重放一次并核对**：`parse_detail.mapping.工作表.Sheet1.档案` 有值、`case_source_profile.hit_count` 增长、事件数与摘要指纹不变（指纹口径沿用 `md5(string_agg(id || '|' || coalesce(summary,'∅')) order by id)`）。

6. **列表 / 撤销**：`GET /openhive/case/source-profiles`、`list_source_profiles`（MCP）、`revoke_source_profile` / `POST /openhive/case/source-profile/revoke`；再撤同一 id 应为 404 / `not_found`。

7. **列顺序打乱**：只用**临时目录里的合成 XLS**（含真数据时同样不入 git），不改真文件。
