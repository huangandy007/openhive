# AI 接卡片层·第一刀：账户进出「人说的笔」明细（设计）

> 日期：2026-11-15
> 归属：P4「AI 接卡片层」第一刀（STATUS 候选 ① 的场景切片）
> 上游设计：`01-事实卡片与数据翻译-设计.md` §3.2（基 2 归属）/ §3.11（用途）；`11` §3.2（账户归属）/ §9.1（已排除）
> 性质：非 bug 类功能，先谈设计、定稿后才进 writing-plans（工作区 CLAUDE.md）

## 1. 为什么做这一刀

同一个案子里的事实有两条入库路：

| | 表格路（`case-translate-store.ts`） | AI 抽取路（`case-ingest.ts`） |
|---|---|---|
| 参与者 | 参与者表（角色 / 原文 / 逐角色出处） | 只有 `participants text[]` 文本 |
| 用途 | `purpose` / `purpose_l1` + 依据 | 空 |
| 金额 | `case_event.amount` | 事件无金额；只有关系行带金额 |
| 出处 | 行级（工作表 + 行号） | 字符区间 |

两条路的**钱**其实已经汇合：笔录独有的转账会重建成 human 关系（`case-ingest.ts:1009-1016`，D-1），而 `aggregate_money` 的汇总/对手方读 `case_relation type='转账'`、**不筛 `source_kind`**（`case-mcp-tools.ts:1746-1753`）。所以合计口径今天是对的。

缺的是**明细**：`money_flow` 的单笔榜只认机器事件（`case-mcp-tools.ts:2216-2251`），人说的笔只在一句口径里被提到「只有笔录人工关系、没有对应流水事件的笔不在榜上」（`case-mcp-tools.ts:2287-2302`）。民警查账户进出时，钱数对得上、明细看不到。

本刀只解决**一个真场景**：查账户进出时，笔录/人工的转账与流水笔同页可见，且不被误当成流水。**不做**通用语义对齐（用途、角色、跨路去重），那些留在后续刀。

## 2. 现状证据（读码核实，2026-11-15）

- 汇总条件不筛 `source_kind`：`case-mcp-tools.ts:1746-1753`；
- 单笔榜基础条件：机器事件 + `amount is not null` + 角色方向（`case-mcp-tools.ts:2216-2241`）；
- 现有口径与缺口原话：`case-mcp-tools.ts:2287-2302`；`query_relations` 的同类口径：`case-mcp-tools.ts:872-877`；
- 资金页只渲染汇总 / 对手方 / 余额，**没有明细**：`money.tsx:60-140`；页面的钱走 `/openhive/case/money` → `aggregate_money`（`case-ui-routes.ts:372`）；
- 实体档案已有「数据说的 / 人说的」两段词（按 `source_kind` 分）：`entity-profile.tsx:135`——本刀沿用，不新造第三套叫法。

## 3. 决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **不做跨路去重**：两栏各列一条；同一笔两处都有时会出现两次 | 模糊匹配（金额+时间窗+双方）会造出「猜出来的同一笔」，比重复更危险；`query_relations` 已是这个口径，沿用不新造 |
| D2 | 人说的笔 = **关系行**，一行一条（可能已聚合多次，带 `times`） | 笔录事件的金额只在关系行上；事件行没有 `amount`，拿不到金额 |
| D3 | 金额 / 时间 / 次数缺失**照实写**（`金额未记 / 时间未记`），不补 0 | `#002-02`：不知道 ≠ 某个具体值 |
| D4 | 人说的笔上限 **20** 条；命中上限才加截断缺口 | 与对手方上限同量级；复用 `截断缺口`（没满不报警） |
| D5 | 流水栏本轮就用现有 `单笔最大`（前 10），**不做全量流水明细** | YAGNI；全量明细需要新查询与新截断口径，登记为非目标 |
| D6 | 出口加在 `aggregate_money.数据`；`money_flow` 透传；加**内部选项** `方向`（不暴露给 MCP 入参） | 资金页与 AI 回答同源（`#002-06`）；方向过滤 + 截断要在 SQL 里，不能先在 JS 里截再筛 |
| D7 | 页面用「数据说的 / 人说的」词，标题写明「流水（单笔最大前 10）」 | 与实体档案一致；标题自带截断说明，不制造「完整明细」的错觉 |
| D8 | `人说的笔` 键缺席（老服务端）⇒ 页面显示「本次未返回」，不是「没有」 | `#002-02`；方向不可反：不知道 ≠ 空 |

## 4. 数据口径（唯一出处）

在 `aggregate_money` 内部、基于**同一份 `汇总条件`** 派生：

```
来源：case_relation
条件：type = '转账'
      and source_kind = 'human'
      and trust_state <> '已排除'
      and 关系归属条件(账户.ids)          // 基 2：恰好一端落在归属集
      and 对手端未排除（另一端口径与对手方相同）
      and 时间窗与汇总同口径（与窗口有交集）
      and coalesce(times_cny, times, 1) > 0
方向：case when from_id ∈ 归属集 then '出' else '入'
对手：人 / 组织取 canonical_value；账户取唯一户名对齐代表名，取不到用 canonical_value
      （与「对手方」的 coalesce 口径一致）
排序：coalesce(last_at, first_at) desc nulls last, id asc
上限：20
```

输出行（数字均为字符串 / Unix 秒，前端不转浮点）：

| 字段 | 类型 | 缺失时 |
|---|---|---|
| `id` | string | — |
| `方向` | `"出" \| "入"` | — |
| `对手` | string | — |
| `金额` | numeric 字符串 | `null`（关系没记金额） |
| `首` / `末` | number | `null`（未记） |
| `精度` | string | `null` |
| `次数` | number | `null`（没记过次数） |

口径句（追加到 `aggregate_money` 的 `口径`）：
1. 「人说的笔按**关系行**各列一条，一行可能已聚合多次（看 `次数`）；流水栏按**事件**各列一条」；
2. 「同一笔可能同时有流水事件与人工关系，两栏各列一条；**汇总与对手方已去重**」（沿用 `query_relations` 原话）。

缺口：`人说的笔.length === 20` 时追加「人说的笔已截到前 20 条，可能还有更多」。

## 5. 出口形状

### 5.1 `aggregate_money`（资金页路由直接读）

`数据` 增加：

```jsonc
{
  // …现有字段（汇总 / 对手方 / 首末 / 外币行数 / 余额走势 …）一字不动
  "人说的笔": [ /* 第 4 节的行 */ ]
}
```

- 内部选项加 `方向?: "入" | "出"`：只作用于「人说的笔」的 SQL 条件与截断；汇总/对手方不受影响；
- `空` 判据不变（只看汇总 / 对手方 / 余额走势）；只有人说的笔时汇总本就非空，`数据` 不会变成 `null`。

### 5.2 `money_flow`（AI 的「查账户进出」）

- `数据` 透传 `人说的笔`（并把 `目标方向` 传给 `aggregate_money` 的内部选项）；
- `摘要` 加半句：「…；人说的 N 笔」；
- `出处` **维持现状**（机器单笔前 3 条不动）：人说的笔的行里已带关系 `id`，`get_citation` 可下钻，不另占配额；
- `缺口`：透传截断句；`下一步` 不变。

## 6. 页面（`money.tsx`）

在「对手方」之后加 **明细** 区，两段：

```
明细
  流水（单笔最大前 10）        人说的（笔录 / 人工）
  ─────────────────────      ─────────────────────
  50000.00 · 2026-03-12 …    出 → 李四 · 50000.00 · 2026-03-12
  …                          …
  空态：没有流水笔             空态：没有人说的笔 / 本次未返回
```

- 行文本用于 `data-copy` 与双击发会话（沿用现有行交互，不加新交互）：
  - 流水行：`50000.00 · 2026-03-12 09:41:07 · <摘要或「无摘要」>`
  - 人说的行：`出 → 李四 · 50000.00 · 2026-03-12`（缺失段写「金额未记」「时间未记」）
- `解资金` 解析器：`人说的笔` 必须整份形状校验——对象数组；`id` / `对手` 为字符串；`方向` 只认 出/入；`金额` 为字符串或 null；`首` / `末` / `次数` 为 number 或 null。形状不对 ⇒ 整份判错、`人说的` 段显示「本次未返回」，**不静默降级成空数组**（`#002-02`）。

## 7. 非目标（登记，不实现）

- 全量流水明细 / 分页；
- 跨路去重（同一笔两处匹配）；
- AI 事件补角色、金额、模板号；
- 用途对齐（文本事件过用途规则表）与旧 43 条事件回填；
- 人说的笔的逐条「已确认 / 已排除」裁决入口（沿用实体档案）。

## 9. 真栈验收（合成材料，不碰真警数据）

1. 造一份合成笔录（「2026-03-12 我转了 50000 元给李四」），走生产解析入口；
2. 查张三账户：
   - 工具返回 `数据.人说的笔` 含该笔（方向=出、对手=李四、金额 50000.00），`数据.单笔最大` 不含；
   - 汇总/对手方数字与改造前同一份数据**逐字一致**；
3. 资金页两段各渲染一次，空态与「本次未返回」各看一次（可用一份没有人类关系的项目）。

## 10. 风险与缺口

- **重复展示**：同一笔可能两栏各出现一次。靠口径句与栏标题区分；若真栈反馈「看成两笔」，下一刀再做匹配（登记）。
- **人说的来源**：`source_kind='human'` 既可能是笔录抽取，也可能是人工裁决产生的关系。栏标题写「人说的（笔录 / 人工）」，不写成「笔录」。
- **关系行聚合**：多笔小额可能已聚合成一行（`times`），与流水栏的逐事件粒度不同；口径写明，不在本刀拆开。

## 11. 已知限制（2026-11-15）

- `单笔最大` 回包不含 `precision` ⇒ 流水行按 `YYYY-MM-DD HH:mm` 显示，可能对只到日的来源补出时分（人说的行已按精度处理；流水行待补字段后再修）。
- 人说行只展示 `首`；聚合多行（`次数 > 1`）时看不到 `末` 的区间。
