- 日期：2026-11-14
- 状态：待评审（brainstorming 产出，经用户逐节确认口径）
- 归属：P4 子项目 2「学习层 · 数据源档案」（`01` §12.1 P4；`01` §6.2）
- 上游：`01-事实卡片与数据翻译-设计.md` §6.2（四类记忆）§6.3（学习闭环）§6.4（冲突与失效）、Q21（记忆冲突优先级）

## 0. 一页结论

新增一张按项目隔离的表 `auth.case_source_profile`，把「一类来源 → 表头原文对应的列映射」记下来。下一次同一来源的表格**列顺序变了**（指纹不命中）时，按「表头集合」认出来并直接套映射，把 L0 全自动从「同一份格式」扩展到「同一类来源」。

本轮只做**内核 + 显式确认接口**：建档由人（或民警的 AI）对某份已成功解析的材料显式触发，不做前端、不做单位/方向/时间约定（hints）、不做卡片模板。

## 1. 背景与问题

现状（`01` §6.1）已有两类记忆：

| 记忆 | 表 | 键 |
|---|---|---|
| 表头别名 | `case_field_alias` | 表头原文 → 一个字段 |
| 表格格式 | `case_table_format` | 指纹（表头 + 每列数据特征的 sha256）→ 按**列下标**的映射 |

`case_table_format` 的问题是：同一家银行/运营商**不同月份列顺序变了**，指纹就变，四层识别全部重跑。`01` §6.2 的解法是数据源档案：粒度从「一份确切格式」升到「一类来源」，条件是「表头集合重合」而不是「指纹完全一致」。

上一刀（P4 用途二期）只确认了「表格 → 卡片」的翻译结果；本刀补的是**认表这一侧的记忆**，与翻译层无耦合。

## 2. 与 `01` §6.2 的偏差（登记）

| `01` §6.2 的写法 | 本轮实现 | 理由 |
|---|---|---|
| `fingerprint`（样例指纹）列 | **不建** | 本轮不承担 hints；样例指纹只用于建档案去重，用「type + header_set + mapping 相同」判定更直接 |
| `rule_version` 列 | **不建** | 字段目录变更靠**命中时逐字段校验**兜底（失效字段 ⇒ 不命中，回落普通识别） |
| `hints` 列（单位/时间格式/方向约定/文件名模式） | **不建**（设计 §7 登记为缺口） | hints 要改 `toFactRows` 与单位闸，风险与收益另算；本刀先解决「列顺序变了仍命中」 |
| `mapping` 按列下标 | **按表头原文** | 列顺序无关的前提就是映射不能绑下标 |
| 档案 `type` 与模板 `event_type` 对应 | 本轮只校验 `type`，模板另立 | 卡片模板不在本刀 |

`01` Q3 的「按项目隔离」照做；Q21 的「档案 > 格式缓存 > 别名 > 模型」照做；Q21 的「档案命中但单位/方向与本次数据不一致 ⇒ 不套用」本轮无 hints 可查，换成 §4 的列/类型校验。

## 3. 数据模型（迁移 `0043_case_source_profile`）

```sql
CREATE TABLE auth.case_source_profile (
  id          text    NOT NULL,
  project_id  text    NOT NULL,
  name        text    NOT NULL,          -- 默认「材料文件名 · 工作表名」，可后改（本刀无界面）
  type        text    NOT NULL,          -- 资金 / 话单 / 其他（建档拒绝「其他」）
  header_set  jsonb   NOT NULL,          -- 表头原文数组，顺序无关，不归一化（#011-01）
  mapping     jsonb   NOT NULL,          -- {表头原文: 字段}，不是列下标
  hit_count   integer NOT NULL DEFAULT 0,
  created_at  integer NOT NULL,
  updated_at  integer NOT NULL,
  revoked_at  integer,
  PRIMARY KEY (project_id, id),
  CONSTRAINT case_source_profile_type CHECK (type IN ('资金','话单','其他'))
);

CREATE INDEX case_source_profile_active
  ON auth.case_source_profile (project_id) WHERE revoked_at IS NULL;

ALTER TABLE auth.case_material
  ADD COLUMN format_fingerprints jsonb NOT NULL DEFAULT '[]'::jsonb;
```

`format_fingerprints` 形如 `[{"工作表":"sheet","指纹":"…"}]`，在解析成功时写入；建档接口据此从 `case_table_format` 读回 header 与 mapping，**不需要重读文件**。旧材料没有该列内容 ⇒ 建档返回 409，提示先重放。

## 4. 命中规则（纯函数）

新模块 `packages/opencode/src/server/openhive/case-source-profile.ts`，不碰库、不读时钟：

```ts
export interface 档案候选 {
  id: string
  name: string
  type: "资金" | "话单" | "其他"
  mapping: Record<string, string>   // 表头原文 → 字段
  hitCount: number
  updatedAt: number
}

export interface 档案命中 {
  id: string
  name: string
  columns: Record<number, 识别字段>  // 还原成当前列下标
}

export function 匹配数据源档案(input: {
  表头: (string | null)[]
  档案们: readonly 档案候选[]
}): 档案命中 | null
```

判定（按序，任一不过即跳过该档案）：

1. 档案 `mapping` 的**每个表头都必须在当前表头里**（精确字符串、trim 后相等；缺一列不套）；
2. 映射出的有效字段 ≥ 2，且每个字段都在当前字段目录内（脏字段/已删字段 ⇒ 跳过）；
3. 还原成列下标后 `classifyMaterialType(columns) === 档案.type`（防拿资金档案套话单）；
4. 多候选排序：映射列数多者优先 → `hit_count` 高者 → `updated_at` 新者；
5. 前两名「映射列数与 `hit_count` 都相同、但映射不同」⇒ **不命中**（fail-closed，不猜）。

> 「有效字段」= `是识别字段` 且该表头在档案里；不要求全是标准列（extras 字段也可入档，`classifyMaterialType` 只认标准列）。

未认出的新列照旧进 `extras`；命中只让 `hit_count + 1`，**不重写** `case_table_format`。

## 5. 接口

### 5.1 HTTP（`/openhive/case`，沿用 R51 次序：身份 → 项目门 → 参数校验 → DAO）

| 方法与路径 | 入参 | 行为 |
|---|---|---|
| `GET /source-profiles` | `projectId`、`含撤销?` | 列本项目档案（默认未撤销），返回 `id/name/type/header_set/hit_count/created_at/updated_at/revoked_at` |
| `POST /source-profile/build` | `{projectId, materialId, 工作表?, name?, 覆盖?}` | 读材料 `format_fingerprints` → `case_table_format` → 建/更新档案 |
| `POST /source-profile/revoke` | `{projectId, id}` | 写 `revoked_at`；已撤销再撤销返回 `false` |

**建档规则**：

- 材料 `format_fingerprints` 为空 ⇒ **409**「该材料还没有可用的解析指纹，请先重放」；
- 指定 `工作表` 不在指纹清单 ⇒ 400；未指定则取第一张「映射后有 ≥ 2 个有效字段且类型 ≠ 其他」的表，全都不满足 ⇒ 400；
- 类型为「其他」⇒ **400**（不把认不出列的格式固化成档案）；
- 同 `type` + 同 `header_set` + 同 `mapping` 的活跃档案已存在 ⇒ **幂等返回既有 id**；
- 同 `type` 且表头重合 ≥ 80% 但映射不同 ⇒ **409**，带 `覆盖=true` 才更新该档案（`mapping/header_set/updated_at`），不新增、不静默覆盖（§6.4 #1）；
- `name` 缺省为 `材料文件名 · 工作表名`；本刀不做改名。

### 5.2 MCP（`case-mcp-server`）

| 工具 | 作用 |
|---|---|
| `list_source_profiles` | 列本项目档案；参数 `含撤销?` |
| `build_source_profile` | `{材料, 工作表?, 名称?, 覆盖?}`；项目取自身份，**不让模型传 projectId** |
| `revoke_source_profile` | `{档案}` |

写操作与 HTTP 走同一个 DAO/服务函数（`#002-06`：同一前提单一出处）。

## 6. 接入（数据流）

```
跑表格（case-ingest）
  ├─ 读表头 → 匹配数据源档案（新，先于指纹缓存）
  │    命中 ⇒ columns 直接用；parse_detail 记 档案:{id,name}
  │    未中 ⇒ 现有顺序：指纹缓存 → 四层识别 → 模型兜底
  ├─ 零列闸 / 时间列守卫 / 待确认 照旧
  └─ 完成事务：写 format_fingerprints（新增）；档案命中时 hit_count+1
```

- `识别材料` 增加可选的「档案映射」入参：命中的表**不跑四层、不参与模型、不写格式缓存**（与格式缓存命中的语义一致）。
- `dryRun` 不读不写档案（离线基线不变）。
- 人工结论保护、重放幂等、事实写入全部不动。

## 7. 明确不做（缺口登记）

| 缺口 | 说明 |
|---|---|
| hints | 单位（元/万元/分）、时间格式、方向约定、文件名模式本轮不存不用 |
| 前端 | 无档案列表/编辑/撤销界面；只能走 HTTP 或 MCP |
| 跨项目共享 | 按项目隔离（Q3） |
| 卡片模板 | 本刀只做「认表」，不做「翻译」的记忆 |
| 表头改名 | 匹配按表头原文精确相等；来源改了表头写法就命中不了，需另建档案 |
| 档案淘汰 | 无 TTL/自动清理；`revoked_at` 只能手撤 |
| 多表材料 | 档案按工作表各建各的；不表达「一份文件多表一起套」 |
| 语义失效 | 只校验字段存在与类型；字段语义（如单位规则）变化无法察觉 |

## 8. 测试与验收判据

### 8.1 完成判据（开工前确认）

1. **匹配器单测**（合成数据）：列顺序打乱仍命中并还原正确下标；缺一列不命中；< 2 列不命中；类型不符不命中；未知字段不命中；撤销由调用方过滤后不命中；两档案打平且映射不同 ⇒ 不命中；多档案按覆盖列数/hit_count/updated_at 选。
2. **ingest 集成**：同一表头集合、列顺序打乱的材料走档案（`parse_detail.档案` 有值、识别方法不为模型）；缺一列回落普通识别；档案命中后 `hit_count + 1`；事件与未用档案时一致。
3. **建档**：幂等（同映射二次 build 返回同 id、不新增行）；冲突 409；`覆盖=true` 更新且 `updated_at` 变；类型「其他」拒绝；无指纹 409；`format_fingerprints` 在解析成功后被写入。
4. **撤销**：撤销后同一材料不再命中、列表默认可见性正确、重复撤销返回 `false`。
5. **迁移**：新表与 CHECK、部分索引存在；`case_material.format_fingerprints` 默认 `[]` 且有 NOT NULL。
6. **变异验证**（`#003-03`）：拆「缺列不套」→ 缺列用例红；拆类型校验 → 类型不符用例红；拆打平不命中 → 平手用例红；拆 ≥2 → 单列用例红。逐条记录拆哪行、红哪条。
7. **门禁**：`packages/opencode` 受影响测试 + typecheck + 根 oxlint（既有 1 error 非本刀）。
8. **grep 同类落点**：`Record<number, 识别字段>` 的读口、`识别材料` 的调用方、`读格式`/`写格式`、`parse_detail` 写入口、`case_material` 列清单、路由注册、MCP 工具注册与 schema。

### 8.2 真栈验收（需用户同意重启）

对 699 行真实材料：解析成功 → 建档案 → 再重放 → `parse_detail.档案` 命中、`hit_count` 增长、事件指纹不变；列表与撤销走 MCP/HTTP 各验一次。列顺序打乱用合成 XLS 在临时目录验证（真文件不改）。

### 8.3 明确不覆盖

- hints 生效、前端展示、跨项目共享、卡片模板、表头改名命中、档案自动淘汰——见 §7。
- 真栈列顺序打乱不拿真文件做（会改原件）；只用合成文件。
