## 1. 背景与问题

### 1.1 用户感受到的问题

1. **格式多，不知道该用哪个 skill。** 不同银行的 Excel 表头不同，按「一种格式一个 skill」的思路，用户被迫承担「选适配器」的职责。
2. **每份文件四步。** 预处理 → 复核副本 → 右键解析 → 入库，重复且耗时。
3. **一直在等。** 同步、逐文件、前台串行；批量上传时等待不可控。
4. **清洗与补全没有位置。** 有的列缺值，有的值需要查参考数据（如号码归属地）、查案件库已有实体，现有链路没有统一的富化阶段。
5. **实体属性问不到。** 对方账户的开户行、绑定银行卡号等信息，需要按 `属性:<归属>:<键>` 约定落进实体 `attrs`，AI 才查得到；现有转换器输出的是裸列名，不满足约定。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 |
|---|---|
| G1 | 用户只做「拖入」一个动作；系统自动探测格式、自动转换、自动入库 |
| G2 | 新格式「教一次」，之后本项目全员自动；配置/转换器可发布、可版本化、可回滚 |
| G3 | 转换由确定性代码驱动，模型只在「首次认列」时出现一次 |
| G4 | 富化（参考库/案件库/外部服务）批量执行，不逐行查库 |
| G5 | 状态可见、提醒具体：用户知道「现在到哪一步」「下一步该做什么」 |
| G6 | 每一条补全/转换结果都可回溯到出处，人工确认与机器结论分得开 |

### 2.2 非目标

- 不做跨项目自动共享（A 类档案目前是项目级，见 §10）。
- 不做「首次新格式全自动」：首次必须确认一次，除非项目开启「自动启用可信技能」且技能在白名单内。
- 不让模型直接写库；不让转换器直接连数据库。
- 不重写现有解析状态机（优先用「原因码」表达未识别，见 §6.4）。
- 不在本次交付实现百万行入库性能（只定目标与测量方法）。

## 3. 核心决策（讨论结论）

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | **用户不选 skill**；系统按「表头闸 + 值验证闸」自动探测 | 适配器不应暴露在用户决策面上 |
| D2 | **适配器是一等资产，由内核确定性调用**，不由模型调用 | 转换是确定性工作，模型调用只会增加延迟与不确定性 |
| D3 | **格式分两类**：A 类只配「表头集合 → 列映射」（数据源档案）；B 类写转换器（行级规则） | 能配置就不写代码；skill 只留给真正需要逐行判断的格式 |
| D4 | **转换器包固定四件套**：`SKILL.md` + `adapter.json` + `convert` + `test/` | 人/模型看说明，内核看识别卡，测试守回归 |
| D5 | **属性列由转换器产出、内核挂载**：`属性:<归属>:<键>` | 转换器知道「源文件哪列是对方开户行」；内核负责实体、合并、出处 |
| D6 | **富化拆成「产键 → 批量查 → 回填」**；内部直连，不走 MCP | 逐行查库是 O(N×RTT)；MCP 是给 AI 会话用的 |
| D7 | **状态用图标 + 悬停说明**；「未识别」优先用原因码，不新增状态 | 状态机改动大；原因码足够筛候选 |
| D8 | **启用后提示 + 一键重跑**（A 方案），不自动改写历史 | 自动重跑会静默改写已解析数据，成本不可控 |
| D9 | **技能提醒具体到「哪个技能 + 一键启用」**；无权限时提示联系项目属主 | 「记得启动技能」这类泛泛提醒无效 |
| D10 | **两段式反馈**：落盘后先读表头，1 秒内给「已识别/未识别」；全量在后台跑 | 用户不必盯着转圈猜 |
| D11 | **性能目标**：已识别格式 5,000 行 ≤ 10 秒；100,000 行 ≤ 2 分钟（待实测） | 等待是用户厌恶的主要来源 |

## 4. 用户流程

### 4.1 现状

```
上传 → 只落盘
     → 右键「解析入库」→ 排队 → 认列 → 写明细 → 翻译 → 卡片
     → （复杂格式）人工先跑 skill 产副本 → 再右键副本入库
```

### 4.2 目标

```
拖入文件夹
  → 落盘
  → 1 秒内：表头探测 → 已识别 / 未识别（带原因）
  → 已识别：自动建材料 + 排队
      ① 适配器探测（表头闸 → 值闸 → 唯一命中）
      ② 执行（规则型 或 转换器型）
      ③ 富化（批量产键 → 批量查 → 回填）
      ④ 写事实行 → 翻译 → 卡片
  → 结果：已解析 / 未识别（待确认） / 有问题（失败） / 已跳过
```

用户只做「拖入」；只有「未识别」和「失败」才需要人介入。

## 5. 功能需求

### FR-01 拖入自动入队

- 仅对 `case-parseable.ts` 白名单内的扩展名（`.xlsx/.xls/.csv/.txt/.md/.log/.docx`）生效；
- 仅对指定入口生效（数据目录 / 专用拖入区），普通文件上传行为不变；
- 支持一次拖入文件夹，逐个建材料、逐个排队；
- 同一文件（同内容指纹）不重复建材料；重复拖入视为「再试一次」。

**验收**：拖入 3 份表格，材料列表出现 3 条记录，状态从「排队中」自动推进，无需右键。

### FR-02 适配器探测

- 探测对象：本项目已启用、带 `adapter.json` 的转换器 + 数据源档案；
- 顺序：表头闸（读表头即可，便宜）→ 值验证闸（先用前 N 行样本，转换时全量）；
- 结果：
  - 唯一通过 ⇒ 采用；
  - 零个通过 ⇒ 材料标「未识别」，写原因；
  - 多个通过 ⇒ 按优先级选一个，报告里写明命中了哪几个。

**验收**：同一份文件只会被一个适配器处理；报告里有适配器 id 与版本。

### FR-03 转换执行

- **规则型**：内核按声明的行规则执行，不启子进程；
- **转换器型**：内核调用转换器入口，读取其 JSON 输出（事实行 + 报告），不读 xlsx 副本；
- 转换器不直接写库、不直接连库；
- 副本 xlsx 降级为「按需导出」，不作为入库必经环节。

**验收**：转换器执行后，事实行可直接进入翻译层；全程没有「先产副本再读副本」。

### FR-04 转换器包规范

每个 B 类格式固定四件套：

```
<格式名>/
  SKILL.md          # 给人/模型看：适用条件、两道闸、字段绑定、已知限制
  adapter.json      # 给内核看：识别卡（见 §6.1）
  convert.*         # 确定性转换实现
  test/             # 样本 + 变异样本 + 断言
```

`SKILL.md` 的 `description` 只写「什么时候用」，不摘要工作流（避免模型照描述跳过正文）。

### FR-05 属性列产出

- 转换器按 `属性:<归属>:<键>` 命名输出属性列；
- 归属仅 `对方` / `本方`；键在词表内（`开户行`、`银行卡号`、`证件号`），词表外照收但需登记；
- 空值不产观察；
- 原始列一个字不改、一列不删；
- 开户人（户名）不走属性，走 `case_entity_alias kind='户名'`。

**验收**：AI 问「这个对方账户的开户行」「这个账户有哪几张卡」能答出值，并带 `材料#表#行` 出处；两份材料冲突时两条都在。

### FR-06 富化层

- 分三类：静态参考库、案件库、外部服务；
- 统一流程：扫描/转换时收集去重键 → 每类一次批量查 → 建 Map → 回填；
- 静态参考库优先整表载入内存（进程级缓存，按版本刷新）；
- 案件库用一条 `unnest` 批量查询，复用唯一索引 `case_entity_canonical (project_id, type, canonical_value)`；
- 外部服务批量请求、并发上限、超时、缓存、负缓存；
- 每个补全值带「值 + 依据 + 置信度 + 版本」；
- 查不到：参考类留空 + 告警；身份类进「待确认」，不猜。

**验收**：5,000 行、去重后约 1,000 键，富化总开销 < 1 秒；无逐行查询语句。

### FR-07 状态与原因码

- 沿用现有状态：`未入队 / 排队中 / 解析中 / 已解析 / 有问题 / 已跳过`；
- 新增**原因码**（不改状态机）：
  - `未识别:无匹配适配器`
  - `未识别:缺必需列:<列名>`
  - `未识别:值闸不过:<检查项>`
  - `失败:读文件`
  - `失败:转换器异常`
  - `失败:入库异常`
- 原因码写入作业结果，材料列表可按「未识别」筛选。

**验收**：上传一份没有适配器的文件，状态为「有问题」或「未入队」+ 原因码 `未识别:无匹配适配器`，界面能筛出。

### FR-08 启用后扫描与一键重跑（A 方案）

- 启用转换器后，扫描本项目两类文件：
  1. 目录里可解析、但 `case_material` 没有记录的文件；
  2. 状态为「未入队 / 有问题」、且原因码为「未识别」的文件；
- 弹提示：「发现 N 份文件可能适用，是否解析？」；
- 用户确认后批量入队；
- **已解析的文件不自动重跑**，提供「用新规则重新解析」按钮，并提示「会更新机器结论，人工确认保留」。

**验收**：先上传未启用 → 未识别；启用后提示 N 份；一键重跑后变为已解析。

### FR-09 技能提醒与权限兜底

- 提醒只在三种时刻出现：
  1. 项目一个数据技能都没启用：一次性提示「解析数据需要先启用对应技能，系统会在遇到文件时告诉你是哪一个」；
  2. 上传后未识别：明确指出「检测到 N 份「XX」格式的文件，需要启用「XX 技能」」；
  3. 启用后扫描：提示可重跑的文件数。
- 提醒必须带按钮；同一份文件只提醒一次；「稍后」后只在文件行留黄色问号；
- 有权限的人看到「启用并解析」；无权限的人看到「需要项目属主启用」并置灰按钮；
- 系统没有对应技能时：「暂无可用的解析技能」，提供「提交格式需求」。

**验收**：成员在共享项目里看到禁用按钮与原因；属主点一次即可启用并解析。

### FR-10 可选：自动启用可信技能

- 项目级开关，默认关闭；
- 打开后，遇到匹配的已发布且在白名单内的技能，自动启用并解析；
- 只对单位审核过的「可信技能」生效，不允许任意技能自动执行代码。

**验收**：开关打开后，成员拖入匹配文件无需任何确认；非白名单技能仍需提示。

### FR-11 两段式反馈与进度

- 落盘后先只读表头，1 秒内给出「已识别 / 未识别」；
- 全量转换在后台执行，状态图标实时更新；
- 「解析中」显示进度（已处理行数 / 总行数或当前阶段）；
- 批量作业显示队列位置；可离开页面，完成后通知。

### FR-12 报告与审计

每份材料的报告包含：

- 命中的适配器 id / 版本 / 规则版本；
- 表头闸与值验证闸的逐项结果（分母、命中、通过率、阈值）；
- 转换行数、跳过行数、告警清单；
- 富化统计（补全数、未补全数、参考库版本）；
- 原件 SHA-256。

### FR-13 版本与回滚

- 适配器、档案、参考库都有版本；
- 版本写入每份材料的报告；
- 适配器可停用；停用后该格式回到「未识别」，不会静默用旧规则；
- 规则升级走「提示 + 一键重跑」，不自动改写历史。

## 6. 契约

### 6.1 识别卡 `adapter.json`

```json
{
  "id": "wechat-wallet-statement",
  "name": "微信账户流水预处理",
  "version": "1.0.0",
  "kind": "converter",
  "materialType": "资金",
  "match": {
    "requiredHeaders": ["查询账号", "付款方支付帐号", "收款方支付帐号", "借贷标志", "交易金额", "交易余额", "交易时间"],
    "optionalHeaders": ["收款方的商户号", "收款方的商户名称", "付款方银行卡号", "收款方银行卡号"],
    "priority": 100
  },
  "admission": {
    "checks": ["查询账号非空", "借贷标志合法", "金额可解析", "时间可解析", "方向与本方一致", "卡行成对", "开户人可分类"],
    "thresholds": {
      "时间可解析": 0.99,
      "方向与本方一致": 0.98,
      "其余": 1.0
    }
  },
  "rowRules": [
    "本方方 = 借贷=='借' ? 付款方 : 收款方",
    "对方方 = 借贷=='借' ? 收款方 : 付款方"
  ],
  "entry": {
    "command": "bun run convert.ts",
    "input": "xlsx",
    "output": "json"
  },
  "output": {
    "rows": "factRows.json",
    "report": "report.json"
  }
}
```

要求：

- `requiredHeaders` 缺一列即不命中；
- `admission.thresholds` 必须可执行、可复现；
- `entry` 必须声明输入与输出；输出为 JSON，不是 xlsx；
- `priority` 用于多命中时排序；
- `version` 变更必须重跑 `test/`。

### 6.2 转换器输出契约

```json
{
  "rows": [
    {
      "sheet": "Sheet1",
      "rowNo": 2,
      "startedAt": 1730000000,
      "amount": "1234.56",
      "direction": "收",
      "ownerAccount": "6222...",
      "counterparty": "6217...",
      "currency": "CNY",
      "extras": {
        "属性:对方:开户行": "招商银行",
        "属性:对方:银行卡号": "6214..."
      }
    }
  ],
  "report": {
    "adapterId": "wechat-wallet-statement",
    "adapterVersion": "1.0.0",
    "sourceSha256": "...",
    "gates": [],
    "warnings": [],
    "skippedRows": []
  }
}
```

约束：

- `rowNo` 必须是源文件 Excel 行号，用于出处 `材料#表#行`；
- 金额一律正数，方向只用 `收/付` 表达；
- 属性列只出现在 `extras`，不冒充标准字段；
- 报告与事实行分开，报告不进入 `case_fact_row`。

### 6.3 属性列契约

- 列名：`属性:<归属>:<键>`；
- 归属：`对方` | `本方`；
- 键：首批 `开户行`、`银行卡号`、`证件号`；词表外照收；
- 只认半角冒号；全角进「未认出」，不静默；
- 空值不产观察；
- 同一键多值并存，去重按值保留首次出处（`05` §5、`01` §14.1 Q14）；
- 属性列不参与表类型投票与字段召回；
- **挂载前提**：属性只在该侧规范值可建实体时挂载（`case-translate.ts:347-348`）。当前 `是账户形状` 只认 `^\d{6,32}$`（`case-field-registry.ts:48,56`），因此 `...@wx.tenpay.com` 这类非数字账号行上的 `属性:对方:开户行` 等会被静默丢弃，户名别名同理。该口径待 §14 第 10 条裁定；裁定前 C2 不得宣称属性列已覆盖微信账号行。

### 6.4 状态与原因码

| 状态 | 含义 | 谁触发 |
|---|---|---|
| 未入队 | 文件在项目里，未排队 | 上传 |
| 排队中 | 已入队，等后台 | 自动/人工 |
| 解析中 | 正在跑 | worker |
| 已解析 | 成功入库 | worker |
| 有问题 | 失败或未识别 | worker |
| 已跳过 | 人工跳过 | 人工 |

原因码（写入作业结果，不新增状态）：

```
未识别:无匹配适配器
未识别:缺必需列:<列名>
未识别:值闸不过:<检查项>
失败:读文件
失败:转换器异常
失败:入库异常
```

### 6.5 富化查询契约

输入：

```json
{
  "kind": "参考库|案件库|外部服务",
  "keys": ["13800000000", "622202..."],
  "projectId": "...",
  "version": "可选"
}
```

输出：

```json
{
  "命中": {
    "13800000000": { "值": "湖南长沙", "依据": "参考:号段库@2026-11", "置信度": 0.99 }
  },
  "未命中": ["622202..."],
  "版本": "号段库@2026-11"
}
```

约束：

- 先 `distinct` 键，再批量查；
- 案件库用一条 `unnest` 语句；
- 静态参考库整表载入内存；
- 不作为转换器的一部分；由内核富化层执行；
- 不经过 MCP。

## 9. 实施方式与交付范围（一次性）

本轮**不拆期、不分批上线**：§12 的 M1–M10、N1–N9、C1–C3、C5–C7 作为一个交付范围统一设计、统一验收（C4 是本机不可验的验收缺口，见第 8 条）。原因不是赶进度，而是这些能力互相咬合——只上自动入队而没有适配器探测，B 类格式仍会被四层识别猜错；只上转换器而没有重解析清理，重跑会叠加属性与别名；只上富化而没有准入闸，拒收文件仍会从原件直入。拆开上线，等于把「半条链路」暴露给用户更久。

交付完成时，以下必须**同时**成立：

1. 数据入口拖入 → 自动建材料 + 排队；仅数据目录、仅白名单扩展名。
2. 适配器注册表 + 两道闸探测 + 转换器执行；B 类格式不选 skill、不产副本、不调模型即可入库。
3. 属性列按 `属性:<归属>:<键>` 入库；AI 查询带 `材料#表#行` 出处。
4. 富化层（参考库/案件库/外部服务）批量补全；无逐行查询。
5. 启用后扫描 + 一键重跑；未识别/失败有原因码，界面可筛。
6. A 类档案可自助建档；技能提醒与权限兜底可用。
7. 报告含适配器 id/版本/规则版本、闸门逐项、SHA-256；版本与回滚可用。
8. AC-1 ~ AC-8 全部通过；C4（真实模型 A1/A2）作为本机不可验的验收缺口单独登记，不作为代码交付阻塞项。

> **两个前置**：① C7 按 §14 第 10 条裁定非数字账号（`...@wx.tenpay.com`）的实体口径，并先于 C2 落地，否则微信账号行上的属性/别名挂不上（§6.3）；② M6 必须同时收口「档案命中的材料也写 `format_fingerprints`」，否则只被档案命中的材料无法再建档（`STATUS.md` P4 真栈已复现）。
>
> **交付边界与存量缺口见 §15**。A1/A2 是 `01-P2` 的验收项，C4 只登记、不关闭；本次代码交付完成后，`01-P2` 仍可能停在「待验收」，不得写成「全绿」。

> 一次性交付指**对外只发一个版本**，不指所有改动同时动手。M/N/C 的编码先后与硬依赖见 §12.6；同一次交付内部可以按依赖顺序推进。

## 13. 术语

| 术语 | 含义 |
|---|---|
| 适配器 | 一种格式的处理单元，含识别卡、闸、转换逻辑或行规则 |
| 识别卡 | `adapter.json`：给内核读的结构化声明 |
| 转换器 | B 类适配器的确定性实现（如微信流水 `convert.ts`） |
| 数据源档案 | A 类格式的「表头集合 → 字段」映射 |
| 富化 | 用参考库/案件库/外部服务补全缺失值或补充属性 |
| 未识别 | 没有适配器命中，或闸不过；不是系统故障 |
| 原因码 | 记录「为什么没解析成」的结构化标记 |
| 可信技能 | 单位审核过、允许自动启用的技能 |
