## 0. 一页结论

1. **探索能力由四块组成，缺一块都"不会追"**：工具（一次给一圈）、纪律（怎么追、何时停）、skill（这类案子怎么查）、入口（民警怎么开口）。数据底座（01）决定上限。
2. **推进方式：单问内挖到底**。用户问一句，AI 在一次回答里自己决定查几轮，挖到能给出带出处的结论；挖不下去就明说缺什么。不跨问题自主发起。
3. **预算：≤ 12 次工具调用、≤ 30 秒**。**次数由服务端数**（复用 `调用留痕`，到限固定注入「收尾并写缺口」）；**30 秒 v1 不计时**（用户 2026-11-12 裁定，§5.4）。达上限必须收尾并写缺口，不许硬凑结论。
4. **新增 4 个探索原语**：`explore_entity` / `money_flow` / `query_timeline` / `query_rows`。**3 个只组合现有读函数**（01 §9 唯一取数层）；**`query_rows` 是唯一新增读函数**——只读 `case_fact_row`，契约归 01 §7.11，不是「再包一层」。
5. **所有查库工具返回同一个七字段信封**：`摘要 / 数据 / 口径 / 缺口 / 空原因 / 出处 / 下一步`（现有 7 个 + 新增 4 个）。缺字段服务端直接报错。图写入 5 个走「改文件」通道，**不套用**（`08` §6.2）。
6. **空结果由服务端分类，模型照抄**。四类资金空结果（确实没有 / 无关联账户 / 账户未出现 / 材料未翻译）从约定变成字段，加上各工具特有值，统一成一张枚举总表（§3.5，代码里是**一个**联合类型）；「答不出『没有』」有了代码保证。
7. **地点时间线先不做真的**：参与者只有 `text[]` 规范值、没有角色（`case-mcp-tools.ts:348-351`），到 01 P3 参与者表落地前，按地点查返回「能力未就绪」，**不返回空**。
8. **skill v1 只做一份：资金研判**。套路写进 skill 资产，不写进 SQL、不写进内核源码。
9. **不做编排器、不做主动探索、不做向量检索**。模型仍是决策者，工具只负责"一次多给一点"。
10. **验收**：固定 20 条问题集 + 工具层单测 + 真栈回放；指标是「结论带出处 100%」「未解析答成没有 = 0」。

## 1. 问题是什么

用户给的四条痛点，按优先级原样保留：

| # | 痛点 | 现在的表现 |
|---|---|---|
| 1 | **AI 不会往下追** | 问「张三和谁有资金往来」，它列完对手就停；不会查对手的账户、不会把通话和转账串起来、不回原始材料确认 |
| 2 | **查不到 / 查漏了也不知道** | 返回空就答「没有」；只查转账漏了现金与微信；材料没解析也照样答 0 笔 |
| 3 | **有结论但不可复核** | 出处、时间窗、口径没交代；民警想核对时翻不回原文 |
| 4 | **工具面不够用** | 缺按地点 / 时间线 / 明细行 / 批量查；一次只能查一个实体，拉一圈成本高 |

### 1.1 现状盘点（代码证据）

现有 7 个只读工具（`case-mcp-server.ts:48-56` 的 `工具名` 数组）：

| 工具 | 能力 | 缺口 |
|---|---|---|
| `search_materials` | 文件名 + 正文片段 | 不报解析状态汇总，不知道该材料能不能查 |
| `query_entities` | 类型 / 关键词 / 含已排除 | 不支持按属性查（`attrs` 无 GIN，01 §7.10）；不能按户名反查人 |
| `query_relations` | 按实体拉一圈（`case-mcp-tools.ts:273-306`） | 返回原始关系行，不聚合；量大时 token 失控 |
| `query_events` | 类型 / 参与实体 / 时间窗 | 参与者只有 `text[]` 规范值，无角色、无地点（`case-mcp-tools.ts:348-351`） |
| `get_citation` | entity / relation / event / row 四类 | `row` 分支**至今无生产写入者**（01 §2.2 ③：表早已支持，没人写） |
| `aggregate_money` | 按账户汇总 | 只查 `case_relation where type='转账'`；表格数据没翻译时返回 0 笔（01:488） |
| `find_crossings` | 甲乙交叉：共同关联 + 共同时空（`case-mcp-server.ts:171-174`） | 只回答两两交叉；两侧各 ≤500 条关系求交，覆盖不到进缺口；不产出"下一步" |

**共同的三个病**：

1. **描述只交代"查什么"**（`case-mcp-server.ts:93-175`），不交代"什么时候该用、什么时候别用、返回的字段怎么读"，模型只能靠猜。
2. **一次只给一条**，要凑齐"一圈"得连续调 5–10 次——30 秒预算在原子调用上就烧光了。
3. **返回体没有统一的"我看完了知道什么"**：口径、缺口、空结果语义各工具各说各的，模型只能自己组织语言，于是把"没查到"说成"没有"。

> 反证：写侧反而定得细——08 §6.2 给 5 个图工具逐项写了入参要点与拒绝规则（`08` §6.2），还专门解决"多张图时不许瞎猜"。查询侧没有同等强度的设计，这就是本文要补的。

### 1.2 四条痛点 → 设计落点

| 痛点 | 靠什么解决 | 在哪一节 |
|---|---|---|
| 不会往下追 | 原语一次给一圈 + 纪律逼下钻 + skill 给动作链 | §4、§5、§6 |
| 查不到/查漏 | `空原因` 字段 + `缺口` 必填 + 四类空结果 | §3、§5、§9 |
| 不可复核 | `出处` 进信封 + 关键数字抽验 + 过程可见 | §3、§8、§13 |
| 工具面不够 | 4 个原语（一圈 / 资金 / 时间线 / 明细） | §4 |

## 2. 总览：分层与职责

```
用户问题
   │
   ▼
入口层   三个起手（查人 / 查账户 / 查时间段）+ 页面带入上下文 + 按钮澄清
   │
   ▼
skill 层 资金研判（这类案子怎么查：顺序、判据、输出格式）
   │
   ▼
纪律层   怎么追、何时停、空结果怎么说（MCP instructions + 工具描述）
   │
   ▼
工具层   探索原语（一次给一圈） ＋ 原子工具（精确取一条 / 下钻到出处）
   │
   ▼
数据层   现有读函数（01 §9 唯一取数层；页面与 AI 共用）
   │
   ▼
信封     摘要 / 数据 / 口径 / 缺口 / 空原因 / 出处 / 下一步
```

**为什么不做编排器（一个 `investigate()` 全包）**：

- 它把"临场判断"写死成固定流程，遇到没预料到的问题就只能返回"查不了"；
- 一个工具干规划、执行、总结三件事，测试面巨大，出错时无法定位是规划错还是取数错；
- 与 agent 模型的分工冲突：模型本来就是决策者，我们只需要给它更好的手和更硬的底线；
- 01 已明确"不造新识别引擎"，同理不造新编排引擎。

**原语与原子工具的分工**：

- **原语**回答"给我一眼看全"——按主题聚合、带摘要、带下一步；
- **原子工具**回答"给我看这一条"——精确过滤、窄返回、用于下钻与抽验出处。

## 3. 统一返回信封

### 3.1 形状

所有**查库**工具（现有 7 个 + 新增 4 个）返回同一个外壳：

```json
{
  "摘要": "张三名下 2 个账户，近 30 天与 5 个对手有 37 笔往来、合计 82 万元；其中 3 个对手同时出现在话单里。",
  "数据": { "…该工具特有…": "…" },
  "口径": "项目=…；时间窗=2024-10-01~11-01；只含已解析材料；关系强度=全部",
  "缺口": ["2 份资金材料未解析：mat_a、mat_b", "事件按时间取前 200，另有 37 条未返回"],
  "空原因": null,
  "出处": [
    { "事实": "关系 账户→账户 37 笔", "代表": "mat_x#Sheet1#12", "可下钻": "get_citation" }
  ],
  "下一步": [
    { "工具": "query_timeline", "参数": { "实体": "ent_xxx" }, "为什么": "看这 5 个对手与张三的通话是否同期" }
  ]
}
```

### 3.2 七个字段各自的规矩

**谁写（2026-11-12 定）**：七个字段全部由**工具实现**产出（`case-mcp-tools.ts` 里每个工具的返回字面量），`case-mcp-server.ts` 只做校验与截断。**不设**「server 按工具名模板拼摘要」那一层——摘要要「7 个账户、合计 32 笔」这种数据知识，模板拼出来是字段复读，民警读不懂；而且它等于把每个工具的语义在 server 复制一份（同类落点问题，`LEARNINGS #002-06`）。

**类型怎么变**：`工具结果`（`case-mcp-tools.ts:22-27`）由 `{数据, 口径?, 缺口?}` 变七字段，`口径` / `缺口` 由可选改**必填**（`缺口` 可为空数组）。11 个工具（7 原子 + 4 原语）逐个补齐 `摘要 / 空原因 / 出处 / 下一步`。

| 字段 | 填写方 | 规则 |
|---|---|---|
| `摘要` | 工具 | **人话，不是数据复述**。它就是"过程可见"的那一行：民警在会话里看到的是它，不是 JSON |
| `口径` | 工具 | 必填，字符串。写清过滤条件与数据范围；**模型不许改写** |
| `缺口` | 工具 | 必填，数组（无缺口给空数组）。截断、未解析、未就绪、外币隔离，全在这里 |
| `空原因` | 工具 | 有数据时为 `null`；无数据时必须是 §3.5 总表的枚举值之一，模型照抄 |
| `出处` | 工具 | 只放**能支撑 `摘要` 里那些数字**的代表行；逐条细节走 `get_citation` |
| `下一步` | 工具 | 建议，不自动执行；每条给工具、参数、一句话理由 |
| `数据` | 工具 | 该工具特有的结构；条数与体积受 §3.4 约束 |

### 3.3 为什么空原因必须由服务端填

01 §3.8.5 已经给出四类空结果（`01:487-494`），但那是"文档约定"，模型可以忽略。变成字段之后：

- 模型要回答"没有"，只能转述 `空原因`，转述错了就与原文字面不符，人工复核一眼能抓；
- 服务端知道"材料解析状态""是否有外币行""参与者表是否就绪"这些模型看不到的事实，它填才准；
- 这是 `01 §0.0 推论 1`「工具层保证会取到」的落地：**描述管"什么时候用"，信封管"看完知道什么、还差什么"**。

### 3.4 服务端硬校验

| 校验 | 不通过时 |
|---|---|
| 七个字段必须齐全（`缺口` 可为空数组，`空原因` 可为 null） | `tool_failed`，回给模型一句固定中文 |
| `限制` 默认 50、上限 200，超出按 200 截断并写 `缺口` | 静默截断**禁止** |
| 单次返回序列化后 > 30 KB | `数据` 为数组时**从尾部**截到 ≤ 30 KB，且至少留 1 条；字节数按 `Buffer.byteLength(JSON.stringify(数据))` 算（换测量方式就会截出不同条数，真栈回放不可复现）；截掉多少写进 `缺口`。静默截断禁止。**补白（2026-11-12 实现期定）**：① 首条记录**自身**就超 30 KB 时无法按条截断——原样返回该条，并在 `缺口` 写「返回数据超过 30 KB，但首条记录自身即超限（N 字节），无法按条截断」，不许静默超限，也不许谎报「截掉 0 条」；**多行数组里首条自身超限**（`[huge, small]`）与单条数组同一条文案——退到 1 条仍装不下，就只能原样交付并承认超限（页里有几条都一样）；② **非数组 `数据`**（`find_crossings` 的 `{ 共同关联, 共同时空 }`）没有「条」可截：**不截数据**，但超过预算时**必须**在 `缺口` 写「数据非数组，无法按条截断（N 字节），已原样返回」——不许静默超限；③ `query_rows` **自己按同一字节预算取页**（`数据预算字节` 只定义在 `case-envelope.ts`，工具自限与服务端兜底共用这一个出处）：整页超 30 KB 时退让到装得下的前 k 行，再用 `限制: k` **重取同一页**，续页游标因此落在**真正交付的最后一行**，`摘要` / `出处` 也按交付行重算；服务端截断从此只作兜底。数组**真截断**那条缺口补一句「摘要 / 出处按截断前数据计算」（摘要由工具在截断之前写好，服务端不回头改） |
| `空原因` 非 null 时，`数据` 必须为空 | 违反视为实现错误，测试拦截 |
| **`数据` 为空时，`空原因` 必须非 null** | 反向镜像。没有这条，「空数据 + `空原因=null`」会被模型当成"确实没有"，§13.4 的变异也就无从拦截 |
| 参数名白名单 | 沿用现有 `收参数` 的 fail-closed：多写一个键直接 `bad_input`，不静默忽略（`case-mcp-server.ts:233`） |

### 3.5 空原因枚举总表

**代码里落成一个联合类型常量**（`空原因值`），§4 各节与 §9 只引用、不另立字面值；测试按它逐值覆盖，被默认值满足的断言不算覆盖（`LEARNINGS #005-47`）。

| 值 | 归属 | 触发条件 | 回答里必须出现的引导 |
|---|---|---|---|
| `无此实体` | 4 个原语共用（`解析实体` 抛 `not_found` 折成此值） | 项目内按全名 / id 精确查不到 | 换个说法，或按名称在实体档案里搜 |
| `实体存在但无任何事实` | `explore_entity` | 实体在，关系与事件都是 0 | 该实体可能只是被引用，建议顺着关联材料查 |
| `材料未解析` | `explore_entity` | 该实体只剩未解析材料覆盖 | 去右键「解析入库」 |
| `确实没有交易` | `money_flow` | **材料已翻译**、实体类型为「账户」、有存在证据（`持有` 关系或明细行）、时间窗内 0 笔**且窗口内无外币行**（外币行也算一笔，只有外币行时让位给 `外币行全部未计入`，§4.5 第 2 条） | 放宽时间窗 / 换账户 |
| `实体没有关联账户` | `money_flow` / `query_relations` | **材料已翻译**、实体类型为「人 / 组织」、没有任何 `持有` 关系（关系类另需「未按类型过滤」或「类型=`持有`」） | 先查账户，或核对户名 |
| `账户未在材料中出现` | `money_flow` | **材料已翻译**、实体类型为「账户」、`持有` / `转账` 关系与明细行都为 0 | 去核对材料是否缺 |
| `项目内资金材料未翻译` | `money_flow` | 项目内存在未解析材料（`未解析材料数 > 0`；同一 path 只认最新一行、`产物` 不计），且第 1–3 条都不成立 | 去解析 / 翻译，**不许答 0 笔** |
| `外币行全部未计入` | `money_flow` + `query_rows` | 两个工具判据不同：`money_flow`＝时间窗内只有外币行（人民币汇总 / 余额走势皆空）；`query_rows`＝本次结果全外币（无游标、无下一页时） | 写明外币行数，说明合计不含外币 |
| `无事件` | `query_timeline` | 时间窗内 0 事件 | 放宽时间窗 / 换类型 |
| `对象未登记` | `query_timeline` | 实体不在事件参与者集合里 | 说明事件侧尚未登记该对象 |
| `时间全部缺失` | `query_timeline` | 命中事件但 `occurred_at` 全空 | 提示只能按材料翻 |
| `能力未就绪` | `query_timeline`（地点分支） | `01` P3 参与者表未落 | 明说「按地点查暂不支持」+ 材料指引 |
| `材料未入库` | `query_rows` | 指定材料不在本项目 | 核对材料名 |
| `该材料未解析` | `query_rows` | 材料在、未解析 | 去右键「解析入库」 |
| `无匹配行` | **原子工具 + `query_rows`**（通用的「条件无命中」） | 条件无命中（兜底）；已解析但查不到任何行 / 任何记录时都可用它；`未解析材料数 > 0` 时摘要**不许**断言「没有任何」 | 放宽条件 / 换关键词或时间窗 |
| `用途未结构化` | 二期（`01` P4 的按用途 / 商户查） | 用途字段未落 | 只能按时间 / 账户 / 金额翻明细，备注原文随行回显 |

**三条规矩**：

1. 一个返回**只报一个** `空原因`；多个同时成立时按本表**从上到下**取第一个（表已按"越靠近数据缺失越靠前"排好），其余进 `缺口`，不丢。
2. 数据类空原因（`材料未解析` / `该材料未解析` / `材料未入库` / `项目内资金材料未翻译` / `能力未就绪` / `用途未结构化`）在回答里**必须**把「去解析 / 去检查材料」放最显眼处（§9 硬规则）。
3. 任何值都**不许**被改写成「没有 / 查不到」（§5.2 纪律 2）。

**实现口径（2026-11-12，判定表在 `case-mcp-tools.ts` 的 `判资金空原因` / `判关系空原因`）**：第 1–3 条都以「**材料已翻译**」为前提——还有未解析材料时不许对全案数据下否证。`确实没有交易` 只对「账户」生效；`账户未在材料中出现`（第 2 条）只对「账户」、`实体没有关联账户`（第 3 条）只对「人 / 组织」，两条**按实体类型互斥**——代码里第 3 条的字面次序排在第 2 条之后，与总表相反但**结果等价**，别照总表把第 3 条提到第 2 条前面（那只会改可读性，不改判据）。兜底的 `无匹配行` 在 `未解析材料数 > 0` 时，摘要**不许**出现「没有任何」这类否定句：资金类由第 4 条 `项目内资金材料未翻译` 接住；关系类没有第 4 条，摘要写「按现有已解析材料没有命中（还有 N 份材料尚未解析）」（`query_relations`，T7 裁定 R-AE）。

## 4. 四个探索原语

共同约定：项目由调用身份决定（工具不接受项目名，沿用 `01:1343`）；所有实体参数**先过 `解析实体`**（`case-mcp-tools.ts:207`）；默认 50 条、上限 200；返回体走 §3 信封。

### 4.1 `explore_entity`：一圈

| 项 | 内容 |
|---|---|
| 入参 | `实体`（名称或 id）、`起?`、`止?`、`跳数?`（1 或 2，默认 1）、`限制?` |
| `数据` | `档案`（类型 / 细类 / 规范值 / 别名 / 属性 / 信任态）；`关系圈`（按对方聚合，前 10：方向、类型、次数、金额、首末、对方细类）；`事件`（最近 10：时间、类型、参与者摘要、信任态）；`总数`（关系总数 / 对方数 / 事件总数） |
| `空原因` | `无此实体` / `实体存在但无任何事实` / `材料未解析`（总表见 §3.5） |
| `下一步` | 账户 → `money_flow`；有事件 → `query_timeline`；要找具体一条 → `get_citation` |
| 组合自 | `实体档案()`（`case-entity-list.ts:289`，已带 `关系总数` / `对方数` / `事件总数`）+ `关系图()`（`case-graph.ts:288`，已带 `缺口` 与 `强度缺口`） |

**查库路径不消歧（2026-11-12 定）**：`解析实体`（`case-mcp-tools.ts:207-227`）实测把同 `canonical_value` 的多行当**同一实体的多行**处理——展示取排序第一行，其余收进 `ids` 供关系过滤（`:203-205` 的注释写明「实体从不删除、重灌只删本材料的引用」）。所以查库路径**产不出「同名多实体」**：同值多行不是多个实体，而真正两个不同的人同叫张三（`canonical_value` 不同）会走 `not_found`。按名找人属于**入口层**——按名称在实体档案里搜（`case-entity-list.ts:143-150` 已支持名称 / 别名 `ilike`），由人在界面上选。查库路径另造一套候选枚举，就是给身份判据开第二个出处（`LEARNINGS #010-06`）。

`跳数=2` 沿用 `关系图()` 的两轮限行（`case-graph.ts:17`），被截掉的边进 `缺口`。

### 4.2 `money_flow`：资金

| 项 | 内容 |
|---|---|
| 入参 | `账户`、`起?`、`止?`、`方向?`（收 / 付 / 全部）、`对手?` |
| `数据` | 笔数；收入合计 / 支出合计（分列，**不相抵**）；首末；对手排行前 20（笔数、金额、首末）；单笔最大前 10（含出处代表）；集中度（前 3 对手占比）；`外币行数` |
| `空原因` | 沿用 01 §3.8.5 四拆：`确实没有交易` / `实体没有关联账户` / `账户未在材料中出现` / `项目内资金材料未翻译`；另有 `外币行全部未计入`（总表见 §3.5） |
| `下一步` | `explore_entity`（对手）/ `query_rows`（大额明细）/ `query_timeline`（同期通话） |

### 4.3 `query_timeline`：时间线

| 项 | 内容 |
|---|---|
| 入参 | `实体?` 或 `地点?`（二选一）、`起?`、`止?`、`类型?`、`游标?`、`限制?` |
| `数据` | 事件按 `(occurred_at, id)` 升序：时间与精度、类型、参与者摘要、信任态、代表出处；`缺时间条数` |
| `空原因` | `无事件` / `对象未登记` / `时间全部缺失` / `能力未就绪`（地点分支，见下；总表见 §3.5） |
| 分页 | 游标分页，不用 offset（`01 §7.5`） |
| 下一步 | `get_citation`（抽验）/ `query_rows`（该事件明细） |

**地点分支必须先拒答**：`case_event.participants` 只存规范值、没有角色（`case-mcp-tools.ts:348-351` 的注释已实证），"何地"要到 01 P3 参与者表落地才分得清。在那之前按地点查返回 `能力未就绪` + 材料指引，**不能返回空**。

### 4.4 `query_rows`：明细回溯

> **本节已随 `01` P1 定稿（2026-11-12）**：入参、数据、空原因、依赖以本表为唯一契约；交付边界（P1 只做内核读函数、MCP 注册归本文其余部分、行级出处不写 `case_citation`）见 `01` §7.11。本文全文已于同日修订定稿（见文首修订清单）。

| 项 | 内容 |
|---|---|
| 入参 | `材料?`、`账户?`、`方向?`、`金额起?`、`金额止?`、`时间起?`、`时间止?`、`游标?`、`限制?`——**没有备注关键词**（2026-11-12 修正，01 §3.11） |
| `数据` | 明细行：时间、金额、方向、对手账号 / 户名、本方账号、**备注原文（回显用，`extras` 里的值）**、行级定位（`材料#表#行`，即主键） |
| `空原因` | `材料未入库` / `该材料未解析` / `无匹配行`（总表见 §3.5） |
| 依赖 | `case_fact_row.extras`（已在，无需新增列）；「按用途/商户查」是二期 `case_event.purpose` + 参与者角色，不在本工具 |
| 补白（2026-11-12，随 `01` P1 实现定） | `账户` 命中**本方账号或对方账号之一**，入参先按 `ownerAccount` 归一化（去横线）；`游标` 由内核函数签发、调用方**只回传**（自造即 `bad_input`）；不指定 `材料` 且本项目零明细时 `空原因 = 无匹配行`，并**必须**在 `缺口` 写「项目内没有任何已入库明细」；`空原因` 为 null ⇔ `数据.行们` 非空（镜像校验）；区间一律闭区间，反向区间 `bad_input`；**单页按 30 KB 字节预算自限**（`数据预算字节`）——超预算时退让到前 k 行并重取同一页，`摘要` 里的行数与 `数据.length` 一致，续页游标落在真正交付的最后一行，服务端截断只是兜底 |

只读 `case_fact_row`，不新写 SQL 查询别的事实表。行级定位**直接由该表主键 `(material_id, sheet, row_no)` 组成**，不解析 `fact_id` 字符串——表名本身可能含 `#`（`01` Q20）。`case_citation` 的 `row` 分支今日无生产写入者（`case-mcp-tools.ts:440-442` 的注释已自认），**今后也不写**（`01` §7.11），所以行级定位**不依赖它**，只在它存在时附上。

### 4.5 三处硬限制（全部显式，不许静默）

1. **地点时间线未就绪**（§4.3）——`query_events` **接** `地点` 参数：先过时间窗校验（非整数 / 起大于止 ⇒ `bad_input`），再回 `能力未就绪` 七字段信封（`数据: null`、`出处: []`，`下一步` 带同一时间窗的 `query_events`；起止缺省时参数对象**不写空键**）。原设计预期「靠拒答」不成立——拒答由工具自己解释，不能指望模型。
2. **外币**（`01` §14 Q16 的现行口径，2026-11-12 实现）：`case_fact_row` 有 `currency` 列（迁移 `0038`，`text NOT NULL DEFAULT 'CNY'`），写入口 `解析币种` 归一化，行视图回显 `币种`。
   - **行侧（`query_rows`）**：混合币种返回全部行 + 缺口「**本页** N 行非人民币未计入」（只数本次交付行，不是全量）；**全外币** ⇒ `数据: []` + `空原因: 外币行全部未计入`（与「`数据` 为 null」的严格读法不同，七字段按「`空原因` 非空 ⇒ `数据` 为空」实现）；分页时（有游标 / 后续页存在）不给该空原因——本页恰好全外币不等于全部未计入。
   - **汇总侧（`aggregate_money`）**：`余额走势` 只取 `currency = 'CNY'` 的行（`行数`＝参与走势的人民币行数，受 `余额行上限` 200 截断；外币行单独由 `外币行数` 交代，**两者不可相加**）；非空结果里 `数据.外币行数` 恒给（可为 0，取同一时间窗、不受余额 200 行截断）；`外币行数 > 0` ⇒ 缺口「本窗口内 N 行非人民币未计入汇总与余额走势」。
   - **`解析币种` 是 fail-closed**：`CNY` / `RMB` / `人民币` / `元` / 空（含纯空白）⇒ `CNY`；其余**原样大写**（`美元` 仍是 `美元`，不归一化成 `USD`），认不出的**不当人民币**；小写形态（`usd`）在写入口已大写、`rmb` 已归一到 `CNY`，不会以原样进库。原文被改写时（`usd` ⇒ `USD`、`人民币` ⇒ `CNY`）按原表头留进 `extras`（A16）。
   - **`汇总` / `对手方` 天然不含 xlsx 流水**：关系只有笔录抽取一条写入路径（`case-ingest.ts:750`），明细行不生成关系。
3. **备注关键词检索未支持**（`01` §3.11 已撤销该入参）：`query_rows` 不接 `备注关键词`，多传即 `bad_input`；工具描述里写明「要按备注找，只能按账户 + 时间翻明细，备注随行回显」。回答里**不许**把「不支持按备注检索」说成「没有」。

另有一条通用规则：`空原因` 只能报**一个**。多个同时成立时，按 §3.5 总表从上到下的次序取第一个；其余原因进 `缺口`，不丢。

### 4.6 与原子工具的分工

| 场景 | 用哪个 |
|---|---|
| "这个人/账户整体什么情况" | `explore_entity` |
| "钱从哪来、到哪去、和谁最多" | `money_flow` |
| "某天发生了什么、先后顺序" | `query_timeline` |
| "这一笔的原文和备注" | `query_rows`（按材料+时间定位到行，备注随 `extras` 回显） |
| "这个数字的出处" | `get_citation` |
| "按名字模糊找实体" | `query_entities`（精确过滤，不做模糊匹配） |

## 5. 追查纪律

### 5.1 流程（写进提示词，不是代码编排）

```
解析实体 → 用原语拉一圈 → 按 缺口 / 下一步 下钻 → 关键数字 get_citation 抽验 → 作答
```

### 5.2 八条

| # | 纪律 | 谁能拦 |
|---|---|---|
| 1 | **先解析再查询**：拿名字直接当参数算调用错误 | 工具描述 + `解析实体` |
| 2 | **空结果照抄**：`空原因` 与对应引导动作原样转述，禁止改写成"没有/查不到" | 信封 + 提示词 |
| 3 | **数字只认本次返回**：结论里每个数必须来自本次调用；跨轮记忆凑数、改口径都算错 | 提示词 |
| 4 | **时间窗必须进结论**：说"近 30 天"就要写清实际起止；没给就写"全时段" | 提示词 |
| 5 | **四类限定显式标注**：户名匹配未核实 / 推断非事实 / 跨源未合并（候选）/ 材料未解析 | 提示词 + 验收 |
| 6 | **三种停**：目标达成 / 预算用尽（12 次由服务端数；30 秒只写纪律、不计时）/ 需人裁决（按名找到多人、合并候选、推断升事实）——每种都要停下来讲清楚 | 12 次：服务端计数；30 秒：仅提示词 |
| 7 | **同参不重调**：一次探索里相同工具 + 相同参数只调一次 | 提示词 |
| 8 | **不跨问题**：答完即停，`下一步` 是给人点的建议，不是自己接着查的理由 | 提示词 |

### 5.3 纪律放哪

- **正文**放 MCP server 的 `instructions`：opencode 客户端已读取并保存 `result.instructions`（`packages/opencode/src/mcp/index.ts:535`）。
- **摘要**放 4 个原语的 `description` 开头：一段固定话 + "什么时候用 / 什么时候别用 / 结果要照抄哪些字段"。
- ✅ **已实证（2026-11-12）**：`session/system.ts:142-158` 把 `mcp.instructions()` 拼成 `<mcp_instructions><server name=…>` 写进 system prompt，透传成立，不必再当风险挂。但**它按工具权限过滤**：`item.tools.length === 0 || Permission.disabled(item.tools, ruleset).size < item.tools.length`——该 agent 若一个 case 工具都没开，整份纪律也不会进上下文（工具不可用、纪律也缺席，是一致的，但要知道）。残余风险只剩「正文太长占 token」与「多 server 时的拼接顺序」，进 §13.5。

### 5.4 预算

- 单次回答 ≤ **12 次工具调用**、≤ **30 秒**；
- **次数由服务端数**：`case-mcp-server.ts:60-70` 的 `调用留痕` 每次调用已落一行（工具 / 耗时 / ok / 错误码），按 `(userId, projectId)` + 10 分钟空闲窗口累计（实现口径，见 §13.5）；第 12 次起在返回的 `缺口` 里固定注入「**近 10 分钟内查询已达 12 次**，必须收尾并列出未覆盖项」。这是提示词之外的硬约束，不靠模型自觉；
- **30 秒 v1 不计时、不上闸（2026-11-12 用户裁定）**：服务端既不知道"这一轮回答从什么时候开始"（它只看得到每次工具调用），也不强制中断；工具描述照旧写「尽量在一次回答里收尾」。这是**明知的缺口**，不假装已覆盖（§13.5）。等真栈回放拿到真实 p95 再决定要不要动会话层加计时；
- 原语单次 p95 目标 ≤ 2 秒（现有实测：明细 100 行 138 ms，`01 §7.1`）；
- 达上限时回答必须带一句"已达查询上限，以下未覆盖：…"，并列出缺口。

### 6.3 与工具、纪律的关系

- skill 走 01 §6.6 的**资产七态流水线**：版本、金标准问题、可下线；改 skill 不改内核源码。
- **落点（2026-11-12 修正）**：它是**产品资产**，**不进仓库 `.opencode/skills/`**——那里是开发 opencode 自身的技能（`effect` / `rtl-aware-development`），放进去既给所有开发 opencode 的人装上一个业务技能，真栈也不会加载。发布到全局资产档 `/assets/global/skills/资金研判/SKILL.md`：内核配置的 `skills.paths` 读的就是它（`project-assets.ts:42`）；项目档才会落在 `<沙箱>/.opencode/(skill|skills)/<名>/SKILL.md`（`project-assets.ts:367`）。

| 平均工具调用数 | ≤ 8 |
| 单次回答 p95 | ≤ 30 秒（**真栈回放时人工量，无硬闸**，§13.5） |
| 资金汇总与人工核算 | 完全一致 |

### 13.4 变异验证

按项目铁律**成对拆**（`LEARNINGS #005-37`）：

1. 把 `缺口` / `空原因` 的填装拆掉（改成 `null`）⇒ 四条空结果用例必须**全红**；
2. 只拆**镜像校验**（去掉「`数据` 为空 ⇒ `空原因` 非空」）⇒ 必须有一条用例红在「空数据却给 `空原因=null`」上。这次拆不出红，说明 §3.4 那条规则根本没落地。

红在哪一句、实得值多少，实现期按 `LEARNINGS #003-03` 据实记。

### 13.5 缺口表（本机不一定能验的）

| 项 | 为什么 |
|---|---|
| 真模型的探索行为稳定性 | 依赖具体模型与上下文，A/B 结果只对该模型成立 |
| `instructions` 正文的 token 占用与多 server 拼接顺序 | 透传本身**已实证**（`session/system.ts:142-158`），只剩这两项要实测 |
| 并发多个会话同时探索 | 需真栈并发压测，本机单栈只能定性看 |
| 30 秒**不做硬闸**（2026-11-12 用户裁定） | 只有「12 次」有代码数，「30 秒」v1 只靠提示词纪律 + 真栈回放时人工量 p95。补闸要动会话层（记录一轮的起点），且观察到的慢多半是模型思考而非工具取数，故本轮不做；拿到真实 p95 再定 |
| **12 次预算的两条近似**（实现后记） | HTTP 入口是**每请求**新建 MCP server（无状态，`case-mcp-http.ts`），`_meta` 里没有会话 id ⇒ 计数只能按 `(userId, projectId)` + **10 分钟空闲窗口**：① 同一用户同一项目**并发**两个会话共用一个计数；② 一次探索中**停顿超过 10 分钟**会重新计数。由此还有一条容易被误读的后果：**同一民警 10 分钟内连续追问不同问题也共用同一个计数**（窗口按最后一次调用滑动），所以模型可见的缺口文案写「**近 10 分钟内查询已达 12 次**，必须收尾并列出未覆盖项」，不写「本次探索」——那是计不出来的。要精确到「一轮回答」得让会话层参与（记录轮次起点），本轮不做 |
| **非数组 `数据` 没有结构截断**（实现后记） | `find_crossings` 的 `数据` 是 `{ 共同关联, 共同时空 }` 对象（两侧上限 500 / 50），服务端只能**写缺口告知**「数据非数组，无法按条截断（N 字节），已原样返回」，不裁数据；真实上限靠工具自身的条数上限（每侧 500、共同时空 50）。`aggregate_money` 的对象有界（汇总 ≤2 / 对手方 ≤10 / 走势单对象），不构成风险 |
| **真模型行为未验**（T7 记） | 回放是手工编码的调用序列，证明「数据集 + 工具返回 + 调用数」，**不证明模型会不会这么查**；§13.3 的「平均调用数 ≤ 8」「结论带出处 100%」同此。真栈 + 真模型回放要 provider 凭据，本机未做 |
| **前端工具卡的真栈视觉验收未做**（T7 记） | 现有真栈进程起于 2026-11-09，早于工具卡的全部提交；补做要从 HEAD 起一套栈 + 一次真模型轮次（需 provider 凭据） |
| **xlsx 明细行没有原文正文**（T7 记） | D7 只兑现到 `材料定位` + `extras` 原值；要返回行原文，得在 ingest 时把整行原值快照存下来（新列），本期不做 |
| **`case_citation.fact_type='row'` 仍无生产写入者**（T7 记） | 本计划不断行级引用，只断行定位可回查；`get_citation` 行分支查不到引用时如实写缺口 |
| **`解析币种` 不把 `美元` 归一化成 `USD`**（T7 记） | 库里同一币种至多并存 `美元` 与 `USD`（小写形态在写入口已大写、`rmb` 已归一到 `CNY`，不会以原样进库）；外币判定 `<> 'CNY'` 不受影响，回显与将来跨币种聚合会漂（`#011-02` 白名单的尾巴） |
