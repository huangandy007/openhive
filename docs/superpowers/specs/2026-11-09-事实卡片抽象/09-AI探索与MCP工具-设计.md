## 0. 一页结论

1. **探索能力由四块组成，缺一块都"不会追"**：工具（一次给一圈）、纪律（怎么追、何时停）、skill（这类案子怎么查）、入口（民警怎么开口）。数据底座（01）决定上限。
2. **推进方式：单问内挖到底**。用户问一句，AI 在一次回答里自己决定查几轮，挖到能给出带出处的结论；挖不下去就明说缺什么。不跨问题自主发起。
3. **预算：≤ 12 次工具调用、≤ 30 秒**。达上限必须收尾并写缺口，不许硬凑结论。
4. **新增 4 个探索原语**：`explore_entity` / `money_flow` / `query_timeline` / `query_rows`。它们**不新写 SQL**，只组合现有读函数（01 §9 唯一取数层）。
5. **所有工具返回同一个七字段信封**：`摘要 / 数据 / 口径 / 缺口 / 空原因 / 出处 / 下一步`。缺字段服务端直接报错。
6. **空结果由服务端分类，模型照抄**。四类空原因（确实没有 / 无关联账户 / 账户未出现 / 材料未翻译）从约定变成字段，「答不出『没有』」有了代码保证。
7. **地点时间线先不做真的**：参与者只有 `text[]` 规范值、没有角色（`case-mcp-tools.ts:348-351`），到 01 P3 参与者表落地前，按地点查返回「能力未就绪」，**不返回空**。
8. **skill v1 只做一份：资金研判**。套路写进 skill 资产，不写进 SQL、不写进内核源码。
9. **不做编排器、不做主动探索、不做向量检索**。模型仍是决策者，工具只负责"一次多给一点"。
10. **验收**：固定 20 条问题集 + 工具层单测 + 真栈回放；指标是「结论带出处 100%」「未解析答成没有 = 0」。

## 1. 问题是什么

用户给的四条痛点，按优先级原样保留：

| # | 痛点 | 现在的表现 |
|---|---|---|
| 1 | **AI 不会往下追** | 问「张三和谁有资金往来」，它列完对手就停；不会查对手的账户、不会把通话和转账串起来、不回原始材料确认 |
| 2 | **查不到 / 查漏了也不知道** | 返回空就答「没有」；只查转账漏了现金与微信；材料没解析也照样答 0 笔 |
| 3 | **有结论但不可复核** | 出处、时间窗、口径没交代；民警想核对时翻不回原文 |
| 4 | **工具面不够用** | 缺按地点 / 时间线 / 明细行 / 批量查；一次只能查一个实体，拉一圈成本高 |

### 1.1 现状盘点（代码证据）

现有 7 个只读工具（`case-mcp-server.ts:48-56` 的 `工具名` 数组）：

| 工具 | 能力 | 缺口 |
|---|---|---|
| `search_materials` | 文件名 + 正文片段 | 不报解析状态汇总，不知道该材料能不能查 |
| `query_entities` | 类型 / 关键词 / 含已排除 | 不支持按属性查（`attrs` 无 GIN，01 §7.10）；不能按户名反查人 |
| `query_relations` | 按实体拉一圈（`case-mcp-tools.ts:273-306`） | 返回原始关系行，不聚合；量大时 token 失控 |
| `query_events` | 类型 / 参与实体 / 时间窗 | 参与者只有 `text[]` 规范值，无角色、无地点（`case-mcp-tools.ts:348-351`） |
| `get_citation` | entity / relation / event / row 四类 | `row` 分支**至今无生产写入者**（01 §2.2 ③：表早已支持，没人写） |
| `aggregate_money` | 按账户汇总 | 只查 `case_relation where type='转账'`；表格数据没翻译时返回 0 笔（01:488） |
| `find_crossings` | 甲乙交叉：共同关联 + 共同时空（`case-mcp-server.ts:171-174`） | 只回答两两交叉；两侧各 ≤500 条关系求交，覆盖不到进缺口；不产出"下一步" |

**共同的三个病**：

1. **描述只交代"查什么"**（`case-mcp-server.ts:93-175`），不交代"什么时候该用、什么时候别用、返回的字段怎么读"，模型只能靠猜。
2. **一次只给一条**，要凑齐"一圈"得连续调 5–10 次——30 秒预算在原子调用上就烧光了。
3. **返回体没有统一的"我看完了知道什么"**：口径、缺口、空结果语义各工具各说各的，模型只能自己组织语言，于是把"没查到"说成"没有"。

> 反证：写侧反而定得细——08 §6.2 给 5 个图工具逐项写了入参要点与拒绝规则（`08:441-481`），还专门解决"多张图时不许瞎猜"。查询侧没有同等强度的设计，这就是本文要补的。

### 1.2 四条痛点 → 设计落点

| 痛点 | 靠什么解决 | 在哪一节 |
|---|---|---|
| 不会往下追 | 原语一次给一圈 + 纪律逼下钻 + skill 给动作链 | §4、§5、§6 |
| 查不到/查漏 | `空原因` 字段 + `缺口` 必填 + 四类空结果 | §3、§5、§9 |
| 不可复核 | `出处` 进信封 + 关键数字抽验 + 过程可见 | §3、§8、§13 |
| 工具面不够 | 4 个原语（一圈 / 资金 / 时间线 / 明细） | §4 |

## 2. 总览：分层与职责

```
用户问题
   │
   ▼
入口层   三个起手（查人 / 查账户 / 查时间段）+ 页面带入上下文 + 按钮澄清
   │
   ▼
skill 层 资金研判（这类案子怎么查：顺序、判据、输出格式）
   │
   ▼
纪律层   怎么追、何时停、空结果怎么说（MCP instructions + 工具描述）
   │
   ▼
工具层   探索原语（一次给一圈） ＋ 原子工具（精确取一条 / 下钻到出处）
   │
   ▼
数据层   现有读函数（01 §9 唯一取数层；页面与 AI 共用）
   │
   ▼
信封     摘要 / 数据 / 口径 / 缺口 / 空原因 / 出处 / 下一步
```

**为什么不做编排器（一个 `investigate()` 全包）**：

- 它把"临场判断"写死成固定流程，遇到没预料到的问题就只能返回"查不了"；
- 一个工具干规划、执行、总结三件事，测试面巨大，出错时无法定位是规划错还是取数错；
- 与 agent 模型的分工冲突：模型本来就是决策者，我们只需要给它更好的手和更硬的底线；
- 01 已明确"不造新识别引擎"，同理不造新编排引擎。

**原语与原子工具的分工**：

- **原语**回答"给我一眼看全"——按主题聚合、带摘要、带下一步；
- **原子工具**回答"给我看这一条"——精确过滤、窄返回、用于下钻与抽验出处。

## 3. 统一返回信封

### 3.1 形状

所有工具（含现有 7 个）返回同一个外壳：

```json
{
  "摘要": "张三名下 2 个账户，近 30 天与 5 个对手有 37 笔往来、合计 82 万元；其中 3 个对手同时出现在话单里。",
  "数据": { "…该工具特有…": "…" },
  "口径": "项目=…；时间窗=2024-10-01~11-01；只含已解析材料；关系强度=全部",
  "缺口": ["2 份资金材料未解析：mat_a、mat_b", "事件按时间取前 200，另有 37 条未返回"],
  "空原因": null,
  "出处": [
    { "事实": "关系 账户→账户 37 笔", "代表": "mat_x#Sheet1#12", "可下钻": "get_citation" }
  ],
  "下一步": [
    { "工具": "query_timeline", "参数": { "实体": "ent_xxx" }, "为什么": "看这 5 个对手与张三的通话是否同期" }
  ]
}
```

### 3.2 七个字段各自的规矩

| 字段 | 谁填 | 规则 |
|---|---|---|
| `摘要` | 服务端 | **人话，不是数据复述**。它就是"过程可见"的那一行：民警在会话里看到的是它，不是 JSON |
| `口径` | 服务端 | 必填，字符串。写清过滤条件与数据范围；**模型不许改写** |
| `缺口` | 服务端 | 必填，数组（无缺口给空数组）。截断、未解析、未就绪、外币隔离，全在这里 |
| `空原因` | 服务端 | 有数据时为 `null`；无数据时必须是 §4 的枚举值之一，模型照抄 |
| `出处` | 服务端 | 只放**能支撑 `摘要` 里那些数字**的代表行；逐条细节走 `get_citation` |
| `下一步` | 服务端 | 建议，不自动执行；每条给工具、参数、一句话理由 |
| `数据` | 服务端 | 该工具特有的结构；条数与体积受 §3.4 约束 |

### 3.3 为什么空原因必须由服务端填

01 §3.8.5 已经给出四类空结果（`01:487-494`），但那是"文档约定"，模型可以忽略。变成字段之后：

- 模型要回答"没有"，只能转述 `空原因`，转述错了就与原文字面不符，人工复核一眼能抓；
- 服务端知道"材料解析状态""是否有外币行""参与者表是否就绪"这些模型看不到的事实，它填才准；
- 这是 `01 §0.0 推论 1`「工具层保证会取到」的落地：**描述管"什么时候用"，信封管"看完知道什么、还差什么"**。

### 3.4 服务端硬校验

| 校验 | 不通过时 |
|---|---|
| 七个字段必须齐全（`缺口` 可为空数组，`空原因` 可为 null） | `tool_failed`，回给模型一句固定中文 |
| `限制` 默认 50、上限 200，超出按 200 截断并写 `缺口` | 静默截断**禁止** |
| 单次返回序列化后 > 30 KB | 先截条目再序列化，缺口里写明截掉多少 |
| `空原因` 非 null 时，`数据` 必须为空 | 违反视为实现错误，测试拦截 |
| 参数名白名单 | 沿用现有 `收参数` 的 fail-closed：多写一个键直接 `bad_input`，不静默忽略（`case-mcp-server.ts:233`） |

## 4. 四个探索原语

共同约定：项目由调用身份决定（工具不接受项目名，沿用 `01:1343`）；所有实体参数**先过 `解析实体`**（`case-mcp-tools.ts:207`）；默认 50 条、上限 200；返回体走 §3 信封。

### 4.1 `explore_entity`：一圈

| 项 | 内容 |
|---|---|
| 入参 | `实体`（名称或 id）、`起?`、`止?`、`跳数?`（1 或 2，默认 1）、`限制?` |
| `数据` | `档案`（类型 / 细类 / 规范值 / 别名 / 属性 / 信任态）；`关系圈`（按对方聚合，前 10：方向、类型、次数、金额、首末、对方细类）；`事件`（最近 10：时间、类型、参与者摘要、信任态）；`总数`（关系总数 / 对方数 / 事件总数） |
| `空原因` | `无此实体` / `同名多实体` / `实体存在但无任何事实` / `材料未解析` |
| `下一步` | 账户 → `money_flow`；有事件 → `query_timeline`；要找具体一条 → `get_citation` |
| 组合自 | `实体档案()`（`case-entity-list.ts:289`，已带 `关系总数` / `对方数` / `事件总数`）+ `关系图()`（`case-graph.ts:288`，已带 `缺口` 与 `强度缺口`） |

`同名多实体` 时 `数据` 给候选清单（id / 类型 / 规范值 / 信任态），**不替用户挑**——与 01 §3.8.3「不做姓名模糊匹配」同一口径。`跳数=2` 沿用 `关系图()` 的两轮限行（`case-graph.ts:17`），被截掉的边进 `缺口`。

### 4.2 `money_flow`：资金

| 项 | 内容 |
|---|---|
| 入参 | `账户`、`起?`、`止?`、`方向?`（收 / 付 / 全部）、`对手?` |
| `数据` | 笔数；收入合计 / 支出合计（分列，**不相抵**）；首末；对手排行前 20（笔数、金额、首末）；单笔最大前 10（含出处代表）；集中度（前 3 对手占比）；`外币行数` |
| `空原因` | 沿用 01 §3.8.5 四拆：`确实没有交易` / `实体没有关联账户` / `账户未在材料中出现` / `项目内资金材料未翻译`；另有 `外币行全部未计入` |
| `下一步` | `explore_entity`（对手）/ `query_rows`（大额明细）/ `query_timeline`（同期通话） |
| 依赖 | 01 P2 资金翻译。没翻译时**必须**返回 `项目内资金材料未翻译`，不许返回 0 笔 |

### 4.3 `query_timeline`：时间线

| 项 | 内容 |
|---|---|
| 入参 | `实体?` 或 `地点?`（二选一）、`起?`、`止?`、`类型?`、`游标?`、`限制?` |
| `数据` | 事件按 `(occurred_at, id)` 升序：时间与精度、类型、参与者摘要、信任态、代表出处；`缺时间条数` |
| `空原因` | `无事件` / `对象未登记` / `时间全部缺失` / `能力未就绪`（地点分支，见下） |
| 分页 | 游标分页，不用 offset（`01 §7.5`） |
| 下一步 | `get_citation`（抽验）/ `query_rows`（该事件明细） |

**地点分支必须先拒答**：`case_event.participants` 只存规范值、没有角色（`case-mcp-tools.ts:348-351` 的注释已实证），"何地"要到 01 P3 参与者表落地才分得清。在那之前按地点查返回 `能力未就绪` + 材料指引，**不能返回空**。

### 4.4 `query_rows`：明细回溯

| 项 | 内容 |
|---|---|
| 入参 | `材料?`、`账户?`、`方向?`、`金额起?`、`金额止?`、`时间起?`、`时间止?`、`游标?`、`限制?`——**没有备注关键词**（2026-11-12 修正，01 §3.11） |
| `数据` | 明细行：时间、金额、方向、对手账号 / 户名、本方账号、**备注原文（回显用，`extras` 里的值）**、行级出处（`材料#表#行`） |
| `空原因` | `材料未入库` / `该材料未解析` / `无匹配行` |
| 依赖 | `case_fact_row.extras`（已在，无需新增列）；「按用途/商户查」是二期 `case_event.purpose` + 参与者角色，不在本工具 |

只读 `case_fact_row`，不新写 SQL 查询别的事实表。行级出处**直接由该表主键 `(material_id, sheet, row_no)` 组成**，不解析 `fact_id` 字符串——表名本身可能含 `#`（`01` Q20）。`case_citation` 的 `row` 分支今日无生产写入者（`case-mcp-tools.ts:440-442` 的注释已自认），所以行级出处**不依赖它**，只在它存在时附上。

### 4.5 三处硬限制（全部进信封，不许静默）

1. **地点时间线未就绪**（§4.3）——返回 `能力未就绪`。
2. **外币**：01 §14 Q16 未定之前，`money_flow` 只汇总人民币；外币行**不进合计**，`缺口` 写"3 行非人民币未计入"。
3. **同名多实体**：列候选、进 `下一步`，由模型问用户（按钮见 §7）。

另有一条通用规则：`空原因` 只能报**一个**。多个同时成立时，按各节枚举的先后次序取第一个（枚举已按"越靠近数据缺失越靠前"排好）；其余原因进 `缺口`，不丢。

### 4.6 与原子工具的分工

| 场景 | 用哪个 |
|---|---|
| "这个人/账户整体什么情况" | `explore_entity` |
| "钱从哪来、到哪去、和谁最多" | `money_flow` |
| "某天发生了什么、先后顺序" | `query_timeline` |
| "这一笔的原文和备注" | `query_rows`（按材料+时间定位到行，备注随 `extras` 回显） |
| "这个数字的出处" | `get_citation` |
| "按名字模糊找实体" | `query_entities`（精确过滤，不做模糊匹配） |

## 5. 追查纪律

### 5.1 流程（写进提示词，不是代码编排）

```
解析实体 → 用原语拉一圈 → 按 缺口 / 下一步 下钻 → 关键数字 get_citation 抽验 → 作答
```

### 5.2 八条

| # | 纪律 | 谁能拦 |
|---|---|---|
| 1 | **先解析再查询**：拿名字直接当参数算调用错误 | 工具描述 + `解析实体` |
| 2 | **空结果照抄**：`空原因` 与对应引导动作原样转述，禁止改写成"没有/查不到" | 信封 + 提示词 |
| 3 | **数字只认本次返回**：结论里每个数必须来自本次调用；跨轮记忆凑数、改口径都算错 | 提示词 |
| 4 | **时间窗必须进结论**：说"近 30 天"就要写清实际起止；没给就写"全时段" | 提示词 |
| 5 | **四类限定显式标注**：户名匹配未核实 / 推断非事实 / 跨源未合并（候选）/ 材料未解析 | 提示词 + 验收 |
| 6 | **三种停**：目标达成 / 预算用尽（≤12 次、≤30 秒）/ 需人裁决（同名多实体、合并候选、推断升事实）——每种都要停下来讲清楚 | 客户端计时 + 提示词 |
| 7 | **同参不重调**：一次探索里相同工具 + 相同参数只调一次 | 提示词 |
| 8 | **不跨问题**：答完即停，`下一步` 是给人点的建议，不是自己接着查的理由 | 提示词 |

### 5.3 纪律放哪

- **正文**放 MCP server 的 `instructions`：opencode 客户端已读取并保存 `result.instructions`（`packages/opencode/src/mcp/index.ts:535`）。
- **摘要**放 4 个原语的 `description` 开头：一段固定话 + "什么时候用 / 什么时候别用 / 结果要照抄哪些字段"。
- ⚠️ 实现时必须验证 `instructions` 是否真的拼进模型上下文；**没透传就以工具描述为准**（两处同源，改一处）。这条写进实现计划的风险项，不假装已覆盖。

### 5.4 预算

- 单次回答 ≤ **12 次工具调用**、≤ **30 秒**（客户端计时，超时收尾）；
- 原语单次 p95 目标 ≤ 2 秒（现有实测：明细 100 行 138 ms，`01 §7.1`）；
- 达上限时回答必须带一句"已达查询上限，以下未覆盖：…"，并列出缺口。

## 6. skill 层：资金研判 v1

### 6.1 分工

| 层 | 管什么 | 形态 |
|---|---|---|
| 纪律 | 所有问题共有的底线（照抄空原因、带出处、何时停） | MCP instructions |
| **skill** | **某一类案子怎么查**（顺序、判据、输出格式） | `SKILL.md` 资产 |
| 工具 | 能查什么、返回什么形状 | MCP 工具 |

### 6.2 内容骨架

```markdown
# 资金研判

适用：账户 / 人 / 资金往来、大额、对手、时间段。

起手
1. 先解析实体：账户优先；问人时先查人，再顺着账户走
2. explore_entity 拉一圈
3. 按问题选：往来 → money_flow；先后 → query_timeline；某一笔 → query_rows
4. 每个进结论的数字，至少用 get_citation 抽验一条

判据
- 户名匹配 ≠ 本人（标「未核实身份」）
- 跨源重复不合并，只出候选（01 D2）
- 材料未翻译要明说，不答 0 笔
- 推断与事实分开，图与结论都标

输出
结论（含时间窗） / 证据链（材料#表#行） / 缺口 / 下一步

停
同名多实体、合并候选、推断要不要升为事实 —— 停下来问人
```

### 6.3 与工具、纪律的关系

- skill **只引用工具名**，不写 SQL、不复制返回结构；
- skill **不重复纪律**——纪律是全局的，skill 只补"资金类"的特有判据；
- skill 走 01 §6.6 的资产流水线：版本、金标准问题、可下线；改 skill 不改内核源码。

### 6.4 验收

固定问题集里的**资金 4 条**做 A/B：装 skill 与不装 skill 各跑一次真栈，看"是否下钻、是否带出处、空结果是否照抄"。这是真模型行为，结论写进 `§13.5 缺口表`，不吹成已覆盖。

## 7. 入口层：民警怎么开口

### 7.1 三个起手

| 起手 | 预填 | 落点 |
|---|---|---|
| 查个人 | 当前选中实体 + 时间窗 | 会话 |
| 查个账户 | 当前选中账户 | 会话 |
| 查一段时间 | 案件时间窗 | 会话 |

点下去不跳新页面，只是把问题预填成一句带上下文的话，走同一个会话与同一套工具。

### 7.2 从页面带入上下文

实体档案页、关系图里「问 AI」沿用 `ask-ai.ts`，带上当前实体 id / 图文件路径。这是最自然的入口：民警看到可疑账户，直接在页面上问。

### 7.3 澄清一律按钮

| 场景 | 按钮 |
|---|---|
| 同名多实体 | "是 A / 是 B / 都不是" |
| 是否合并两个实体 | "合并 / 不合并 / 再看看" |
| 推断要不要升成事实 | "升为事实（需补出处）/ 保持推断" |

与 01 §5.3「按钮优先」同一口径；不要求用户打字解释。

### 7.4 不做

- 推荐问题轮播、好奇心驱动的主动提醒；
- 新的独立 AI 页面（复用现有会话）。

## 8. 过程可见

### 8.1 探索卡

会话里每次工具调用渲染成一张卡，三行：

- **标题**：人话参数——"查 张三名下账户的资金往来，2024-09-01 ~ 10-11"，不显示 `entity_id`；
- **正文**：信封的 `摘要`，一字不改；
- **脚注**：`口径` 折叠；`缺口` 与 `空原因` 非空时**必显**，点开看详情。原始 JSON 默认折叠。

### 8.2 收尾行

回答末尾一行："本次探索 7 次查询、覆盖 12 份材料；缺口 2 项（1 份资金材料未解析）"。预算用尽时写在这里："已达 12 次上限，XX 未覆盖"。

### 8.3 错误映射

| 错误码 | 给人看的话 |
|---|---|
| `bad_input` | "参数不对，我再试一次"（模型自己改） |
| `not_found` | "没找到这个实体" |
| `not_a_member` | "无权访问该项目" |
| `tool_failed` | 保持现状那一句固定中文（不回显原文，`case-mcp-server.ts:265`） |

### 8.4 不做

- 不新增后台作业：30 秒内同步返回；
- 不做假进度条；
- 用户点停止即停（opencode 原生能力）。

## 9. 数据依赖：别把数据问题算成 AI 问题

| 能力 | 依赖 | 没到位时工具怎么答 |
|---|---|---|
| 按用途/商户查（「这笔钱干什么用」） | 二期 `case_event.purpose` + 参与者角色（01 P4） | `空原因="用途未结构化"`，并指引「当前只能按时间/账户/金额翻明细，备注原文可在明细行里看到」 |

| 按地点查时间线 | 01 P3 参与者表 | `空原因="能力未就绪"` |
| 未验证模板卡片过滤 | 01 §14 Q15 | 落库字段不存在时**没法过滤**，只能把「含未验证模板产出」写进 `缺口`（不假装已排除）；字段落地后默认排除，`含未验证` 才返回 |

**硬规则**：凡是数据类空原因，回答里必须把「去解析 / 去检查材料」放在最显眼处，过程卡上标一句"这是数据没到位，不是没有"。

## 13. 验收

### 13.1 固定问题集（20 条）

| 组 | 问题 | 必须出现的东西 |
|---|---|---|
| 人（4） | 张三名下有几个账户 / 张三和李四有没有联系 / 张三的手机号被别人用过吗 / 案件里叫张三的有几个 | 户名匹配要标「未核实身份」；多实体要列候选 |
| 账户（4） | 某账户给谁转了多少 / 最大一笔 / 交易最频繁的对手 / 近 30 天进账 | 笔数与合计；时间窗；对手排行 |
| 时间线（4） | 某人某日发生了什么 / 某地点某周发生了什么 / 某账户首末次交易 / 通话高峰是哪天 | 收付分列不相抵；地点题必须是「能力未就绪」 |
| 空结果（4） | 有账户无交易 / 人无实名账户 / 账户存在但未出现 / 项目资金材料未翻译 | `空原因` 逐字对应四类之一，且带引导动作 |
| 其余（4） | 同名多实体 / 未解析材料 / 外币行 / 某个数字的出处 | 不得出现「没有」；外币写缺口；出处能翻到原文 |

### 13.2 三层验证

1. **工具层单测**（in-memory MCP 握手）：信封七字段必填；四类空原因各一例；截断写缺口；上限强制；地点未就绪拒答；外币隔离；`空原因` 非空时 `数据` 必须为空。
2. **真栈回放**（真 PG + 真模型）：固定集中抽 10 条，人工看三件事——有没有往下追、空结果有没有照抄、数字有没有出处。
3. **数字一致性**：复用 01 的 A4，「某账户给谁转了多少」与人工核算完全一致。

### 13.3 指标

| 指标 | 目标 |
|---|---|
| 结论带出处的比例 | **100%** |
| 「未解析」被答成「没有」的次数 | **0** |
| 平均工具调用数 | ≤ 8 |
| 单次回答 p95 | ≤ 30 秒 |
| 资金汇总与人工核算 | 完全一致 |

### 13.4 变异验证

按项目铁律拆一次：把 `缺口` / `空原因` 的填装拆掉（改成 `null`），四条空结果用例必须**全红**。红在哪一句、实得值多少，实现期按 `LEARNINGS #003-03` 据实记。

### 13.5 缺口表（本机不一定能验的）

| 项 | 为什么 |
|---|---|
| 真模型的探索行为稳定性 | 依赖具体模型与上下文，A/B 结果只对该模型成立 |
| `instructions` 是否拼进上下文 | 客户端读取已确认（`mcp/index.ts:535`），拼装位置实现时实测 |
| 并发多个会话同时探索 | 需真栈并发压测，本机单栈只能定性看 |
| 30 秒预算是客户端要求 | 服务端不强制中断，只保证单次调用快 |
