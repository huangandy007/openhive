### 1.4 全局原则（所有条目共用）

1. **单一出处**（`#002-06`）：同一前提只在一处判——命中节点、删除选中、幂等键、来源类别、档位范围，都只留一个实现点。
2. **失败必提示**：任何「用户以为发生、实际没发生」的动作都要给可见反馈（连线失败、复用节点、写入失败、被隐藏的弱边）。
3. **不伪造证据**：依据/出处只写得出事实来源的话术，不编条款页码（沿用 `entity-picker.tsx:136`、§6.3 口径）。
4. **最小契约面**：格式只加 `来源.kind="事件"` 一个枚举值，不新增键（见 F3-1）。

## 2. 功能设计

### F0 写路径可靠性（最严重，先做）

#### F0-1 手动加节点不被「同名复用」吞掉 ✅

- **现象**（实测）：连点 3 次加节点，服务端回 `映射 {临时n1..n3 → n4}`、`新增 0`；UI 显示 7 个、盘上 4 个；拖一个「副本」时 4 个一起塌到同一坐标。
- **根因**：`hgraph-edit.ts:409` 的同名复用判据是「id 不匹配 `/^[net]\d+$/` 且名称+类型相同」——手动加节点的 `临时n1`（中文前缀）不匹配，于是**手动路径与 AI 路径同分支**；而设计 §6.4 只授权 **AI** 复用。另两处放大器：`editor.tsx:281-289` 的 `换id` 不查映射撞车；`editor.tsx:1574-1597` 默认名恒为「新节点」。
- **设计**：给 `应用操作`／`应用并写回` 加显式入参 `同名复用?: boolean`（缺省 `false`）；仅 `case-hgraph-tools.ts:348` 的 `graph_add` 传 `true`。客户端 `换id` 后按 id 去重，发现映射值撞车即弹「图和你本地不一致，请重新载入」。默认名改「新节点 N」（递增）。AI 路径的「复用了已有节点 X」要给一行提示。
- **判据**：① 手动路径同批两个同名节点 ⇒ `新增 2`、两个不同 id；② 映射撞车 ⇒ 不产生重复 id，且界面提示重载；③ 变异：拆掉开关那条用例必须红。

#### F0-2 幂等键：超时重试不得变成「别人改过」 ✅

- **现象**（实测）：`route.fetch()` 落盘后延迟 12.5s 回包（客户端 10s 超时）⇒ 状态栏「没存上」；点重试带旧版本 ⇒ 409 `VERSION_CONFLICT`「这份图在你打开之后被改过」。
- **根因**：客户端 `editor.tsx:864-870` 只传 `批次`（每次重算），**从不传 `幂等键`**；`hgraph-api.ts:159` 留了参数位、服务端 `幂等索引` 已就绪（`hgraph-ops.ts:503`：幂等判定排在 CAS 之前）。
- **设计**：客户端每次发送生成稳定键 `web:${图路径}:${序号}`；**仅当重试载荷与上次失败载荷逐字相同**（同版本、同操作）才复用同键，载荷变了换新键（否则服务端重放旧结果、新改动被静默丢掉）。兜底：收到超时/409 先读一次，若盘上内容 == 已存文档+本批，静默采纳版本、不弹「别人改过」。
- **判据**：同载荷重试复用键、异载荷换键；变异：去掉幂等键，超时用例必须红。

#### F0-3 幻影重复态自愈 ✅

- **现象**：`editor.tsx:1077` 轮询在 `新版本 === 版本()` 时直接 return；重复节点来自一次 200 成功应答，版本已推进 ⇒ 永远不重载。
- **设计**：`发送` 成功分支加断言——`换id` 后 id 不唯一 ⇒ 立即请求重载。F0-1 修好后源头消失，此条是兜底。

#### F0-4 同类落点 🔒 覆盖

复制/粘贴（`graphops.ts:57`「原名+副本」，临时 id 同样不匹配显式形状）与 Alt+拖走同一判据 ⇒ F0-1 的开关一并修复。**判据**：同一节点粘贴两次 ⇒ 2 个不同 id 的节点。合并撤销已用「先删保留者」规避，不动。

### F1 视图交互

#### F1-1 滚轮：纵向一律缩放，平移只认横向占优 ✅

- **根因**：`canvas.tsx:83` 用「`deltaY % 1 !== 0`」当触控板判据；Windows 精密触控板、平滑滚动、倾斜滚轮都送小数 `deltaY` ⇒ 被当成双指平移，只挪不缩。整数滚轮（我本机合成）反而正常——设备相关假绿。
- **设计**：`是双指平移 = 事件.ctrlKey !== true && Math.abs(事件.deltaX) > Math.abs(事件.deltaY)`。代价：触控板纵向双指变成缩放（可接受，缩放是滚轮普遍预期）；平移仍有空格+拖、中键拖、**手**模式（F1-2）。**不加「滚轮行为」设置**（YAGNI）。
- **判据**：`deltaY: 3.75` 必须改变 `scale`；`deltaX: 120, deltaY: 0` 只平移、不改 `scale`。

#### F1-2 平移可发现性 + 「手」模式 ✅

- **现状**（实测）：容器 `cursor: auto`，全画布无 `grab/grabbing`；空格+拖、中键拖可用（用户已自己发现空格）。
- **设计**：① 空格按下/抬起切容器 `cursor: grab`／拖动中 `grabbing`（`空格` 状态变量已存在，`canvas.tsx:349`）；② 空白悬停保持 `default`（左键拖是框选，别用 `grab` 自相矛盾）；③ 工具栏模式组扩成 **指针 / 手 / 连线**，选「手」时左键拖即平移 + `grab` 光标（不用记快捷键的唯一可发现入口）；④ 不做画布角落的快捷键提示（工具栏已有「手」）。

#### F1-3 连线命中：起点终点同一判据，失败必提示 ✅

- **现象**（实测）：从圆心拖到目标**名字标签**上松手 ⇒ 无浮层、无提示；起点认标签、终点不认——不对称。
- **根因**：按下用 DOM `closest("[data-node-id]")`（`canvas.tsx:577`，圆+名字都算）；松手用数学判据 `geometry.ts:104-117`（**圆心 15 内容像素**内），标签在圆下 20–23px ⇒ 不是落点。
- **设计**：松手复用按下同一套命中（`document.elementFromPoint` → `closest("[data-node-id]")`），数学判据只作兜底（半径放大到屏幕 ~24px + 吸附最近）。**预览线必须 `pointer-events: none`**，否则 `elementFromPoint` 命中的是线本身。落空时给一行提示「松手不在节点上，未建立连线」。
- **判据**：拖到标签上松手必须建边（或至少出浮层）；真空处松手不建边且有提示。

#### F1-4 删除键作用域：监听上移，画布不再独占 ✅

- **现状**（实测）：工具栏删除（`toolbar.tsx:82-92`）、检查器批量删除（`inspector.tsx:499-508`）、Delete 键（`canvas.tsx:895-901`）**已经是同一个动作**（`editor.tsx:1602-1615` 是唯一翻译点）；差的是 Delete 只在画布有焦点时生效——点筛选按钮后 `document.activeElement` 变成 `button[hgraph-filter-toggle]`，按键根本不到处理器。
- **设计**：keydown 监听上移到 **编辑器根容器**（`editor.tsx:1685-1696`，仍在 `hgraph/` 内，符合 §11-12「不注册全局热键」）。**根容器独家接管**，画布那段删掉（避免同一次按键两遍写入）；`input/textarea/[contenteditable]` 守卫原样搬过去（`canvas.tsx:855-862`，M1 实测过）。同批把 `F2`（重命名）一并上移。
- **判据**：点工具栏任意按钮 → 点画布选中节点 → Delete 能删且**写盘批次 = 1**；检查器输入框里 Delete 只删文字（`editor.test.tsx:1387` 绿）；演示态 Delete 仍静默（`present.test.tsx:940` 绿）。

#### F1-5 面板遮挡自动避让 ✅

选中后若对象屏幕矩形与面板（320px）相交 ⇒ 画布平移使对象居中于剩余可视区；**一次即止**，不持续跟随（避免拖动时画面乱跑）。

#### F3-3 手写 / 绑定两态 + 出处硬闸 ✅

- 手写（`kind="手写"`）：九格可编，**没有可信态控件**，徽标只能「手写」——不给它标「事实」的路径。
- 绑定（`kind="事件"`）：九格全只读，只留 备注 / 外环；**不提供解绑**（解绑＝有出处快照退化成无出处手写，撞硬闸；要手写就新建）。
- 绑定事件落节点时 `出处` 必须非空，空则拒绝加入并提示「这条事件没有出处，不能上图」（§6.3 fail-closed）。
