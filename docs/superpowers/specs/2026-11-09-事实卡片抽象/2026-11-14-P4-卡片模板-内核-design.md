# 卡片模板编辑器（第一刀：内核）设计

> 日期：2026-11-14
> 归属：P4 学习层 · 卡片模板（`01-事实卡片与数据翻译-设计.md` §4.7）
> 状态：设计已逐节确认，待写实现计划
> 范围：内核（数据模型、校验、通用翻译、预览、转正、AI 默认过滤、HTTP）。SolidJS 前端编辑器为第二刀。

---

## 1. 背景与目标

`01` §4.7 要求「把映射交给用户」：加一类普通数据（话单、订餐、乘车……）不写代码，用户配一张模板即可产卡。现状只有骨架：

- 迁移 `0039_case_translate_p2` 已建 `auth.case_card_template` 与 `case_event.template_id`；
- `case-card-template.ts` 已有内置 `内置:资金/v1`、九格槽位类型、Q18 槽位种类校验；
- `case-event-types.ts` 已有第四份词表（9 种事件类型）。

缺的是：用户模板 CRUD / 校验 / 版本、按槽位产卡的通用翻译、前 20 行预览、`verified_at` 转正、AI 默认过滤、HTTP 出口。

**本刀目标**：用户经 HTTP 配一张「通话」模板，按前 20 行预览确认后转正；之后解析同类文件自动套用产卡；未转正模板产出的卡片默认不进 AI 查询。

**成功判据**：

1. 用一份合成话单材料，经「建模板 → 预览 → 转正 → 重新解析」全链路在集成测试里产出通话卡；
2. 转正前 `query_events / query_timeline / find_crossings` 默认查不到这些卡，带 `含未验证: true` 能查到；转正后默认能查到；
3. 所有写口属主门、读口成员门；槽位/角色/实体类型越界在保存前被拒。

## 3. 已确认的决策

| # | 决策 | 结论 |
|---|---|---|
| D1 | 翻译广度 | 通用引擎 + 话单样板。任何非内置模板按槽位产卡；验收用「通话」。不做区间合并/行间计算。 |
| D2 | 同类型多模板 | 每（项目，事件类型）一张启用中的用户模板；用户模板覆盖内置；新建同类型须先停用旧模板。 |
| D3 | 转正时机 | 预览确认即转正：转正接口带已解析材料，服务端现场重跑前 20 行，至少 1 张卡才写 `verified_at`。 |
| D4 | 写权限 | 建 / 改 / 停用 / 转正 = 项目属主；列表 / 预览 = 项目成员。HTTP 与未来的 MCP 写口同一道门。 |
| D5 | 禁建类型 | 用户模板不能选 `资金交易`（方向算法定谁/和谁）与 `住宿`（区间合并）。 |
| D6 | 生命周期 | 软停用 + 编辑降级：不硬删；编辑映射 `version + 1` 且清 `verified_at`。 |
| D7 | 引擎位置 | 新建 `case-template-translate.ts` 并行；`case-translate.ts` 的资金逻辑不改。 |
| D8 | 套用入口 | 识别后按「required 全命中 + 槽位字段命中最多」自动建议并套用；解析请求可显式指定 `templateId`。 |
| D9 | 预览取数 | 只接受已解析材料，复用 `parse_detail` 的列映射；预览不写库、不调模型。 |
| D10 | 保存前预览闸 | 内核在**转正**时强制预览；「保存前必须预览」由第二刀前端落实。空项目也能先建未验证模板。 |

## 4. 与既有设计的偏差（必须留痕）

1. **`01` §4.7.6「保存前必须预览」**：本刀改为「转正时强制预览」。理由：内核先行的前提下，模板未转正时其卡片本就不进 AI；把服务端闸放在转正这一步，既守住安全边界，又不要求项目里先有一份已解析材料才能建模板。第二刀前端仍按原设计先预览再保存。
2. **`01` §4.7.2 的「其他」示例写作 `{ "时长": "durationSec" }`**：规范 JSON 仍用 `[{ 字段: "durationSec" }]` 数组（与已落地的 `模板槽位` 类型、Q18 校验一致）；`attrs` 的键取「字段显示名」（`通话时长`），不取手写标签，避免用户自造键。
3. **`01` §4.7.7「模板优先，规则兜底」**：本刀对**逐表分类为资金**的表不跑模板，只跑资金代码规则。原因：用户模板禁止 `资金交易` 类型，若让「消费」模板命中资金表，会与代码规则对同一行各产一张卡（卡片 id 槽位不同，无法幂等覆盖）。
4. **`01:861` 要求模板声明实体-实体边**：本刀模板还不带「边声明」字段，因此模板卡只写参与者、不建 `case_relation`；话单「主叫↔被叫」的边留到后续刀。
5. **模板卡用途**：统一 `未分类`（`判定用途` 兜底），不参与资金用途统计。理由：用途词表（§3.11）是资金语义，拿它判话单/乘车会制造假分类。

## 6. 词表与模板校验

### 6.1 三份词表（代码常量）

**角色词表**（新增，`case-card-template.ts` 导出）：

```ts
export const 角色们 = [
  "主体", "对方", "入住人", "同住人", "付款方", "收款方",
  "主叫", "被叫", "地点", "出发地", "到达地",
  "车辆", "物品", "班次", "经办人", "其他",
] as const
```

- `谁 / 和谁` 可用：角色们去掉 `地点 / 出发地 / 到达地`；
- `何地` 可用：`地点 / 出发地 / 到达地`；
- 省略角色时的默认值：`谁` → `主体`，`和谁` → `对方`，`何地` → `地点`。

**实体类型词表**：直接复用 `case-extract.ts` 的 `实体类型们`（人 / 号码 / 账户 / 虚拟身份 / 车辆 / 物品 / 地点 / 组织），不另抄一份（`#002-06`）。

**字段显示名**（新增，`case-field-registry.ts` 导出的同一份常量）：

| 字段 | 显示名 | 字段 | 显示名 |
|---|---|---|---|
| caller | 主叫号码 | callee | 被叫号码 |
| startedAt | 时间 | durationSec | 通话时长 |
| amount | 金额 | balance | 余额 |
| counterparty | 对方账号 | counterpartyName | 对方户名 |
| ownerAccount | 本方账号 | direction | 方向 |

### 6.2 槽位规范 JSON

```json
{
  "谁": { "字段": "caller", "角色": "主叫", "实体类型": "号码" },
  "和谁": [{ "字段": "callee", "角色": "被叫", "实体类型": "号码" }],
  "何时": { "字段": "startedAt" },
  "何时止": null,
  "何地": null,
  "多少钱": null,
  "其他": [{ "字段": "durationSec" }]
}
```

- 单值槽也可以写成数组（统一由 `拆填法` 处理）；`谁 / 何时 / 何时止 / 多少钱` 最多 1 条；
- `和谁 / 何地 / 其他` 可多条；
- `其他` 条目不允许带 `角色` / `实体类型`（带了就拒，不静默忽略）。

### 6.3 `校验模板定义`

新增函数（`case-card-template.ts`）：

```ts
export interface 模板定义 {
  name: string
  eventType: string
  slots: unknown
  required: unknown
}

export function 校验模板定义(定义: 模板定义): string[]
```

返回错误清单，空数组 = 通过。检查顺序与内容：

1. `name`：trim 后非空、≤ 200 字；
2. `eventType`：`是事件类型` 且不是 `资金交易` / `住宿`；否则错误串写明「资金交易由方向算法负责、住宿由区间合并负责，不能建用户模板」；
3. `slots`：先跑既有 `校验槽位种类`（Q18：字段词表 + 槽位种类 + 「其他」拒收金额/时间/方向）；
4. `slots` 形状：`九格们` 之外的键也拒（防止拼写错静默丢失）；
5. 重复字段：同一字段出现在两个槽（含「其他」）⇒ 错误；`何时` 与 `何时止` 同字段必然落在这里；
6. 槽位上限：`谁 / 何时 / 何时止 / 多少钱` 各 ≤ 1 条；全部条目合计 ≤ 100 条；
7. 角色：`谁 / 和谁` 的 `角色` 必须在「参与角色集」；`何地` 的 `角色` 必须在 `地点 / 出发地 / 到达地`；`其他` 不允许角色；
8. 实体类型：若给了 `实体类型`，必须在 `实体类型们`；`何地` 给了就必须是 `地点`；`其他` 不允许实体类型；
9. `required`：数组、元素是 `九格们` 成员、无重复、不含 `其他`；`谁` 自动视为必填（传不传都在）。**规范化**：校验通过后存库的 `required` 强制加入 `谁`（顺序按 `九格们`），DAO 只存规范化结果；
10. 必填槽必须已填：`required` 中每个槽在 `slots` 里至少一条填法。

**不校验的东西**（`01` §4.7.5）：单位换算、借贷方向、时间格式、金额形状。这些永远走代码。

## 7. 模板 DAO（`case-card-template-store.ts`）

### 7.1 错误类型

```ts
export type 模板错误码 =
  | "bad_request"     // 定义不合法（错误清单在 message 里）
  | "conflict"        // 同类型已有启用中的用户模板
  | "immutable"       // 试图修改/停用内置模板
  | "not_found"       // 模板不存在
  | "state_changed"   // 转正乐观锁失败（预览期间被改）

export class 模板错误 extends Error {
  readonly code: 模板错误码
}
```

### 7.2 接口

```ts
export interface 模板行 {
  id: string
  name: string
  event_type: 事件类型
  slots: 模板槽位
  required: string[]
  version: number
  verified_at: number | null
  hit_count: number
  disabled_at: number | null
  created_at: number
}

export async function 列出模板(
  db: Queryable,
  input: { projectId: string; 含停用?: boolean },
): Promise<模板行[]>

export async function 建模板(
  db: Queryable,
  input: { projectId: string; 定义: 模板定义 },
): Promise<{ id: string }>

export async function 改模板(
  db: Queryable,
  input: { projectId: string; id: string; 定义: 模板定义 },
): Promise<{ version: number; verified_at: number | null }>

export async function 停用模板(
  db: Queryable,
  input: { projectId: string; id: string },
): Promise<boolean>

export async function 转正模板(
  db: Queryable,
  input: { projectId: string; id: string; expectedVersion: number },
): Promise<{ verified_at: number; already: boolean }>

export async function 记模板命中(
  db: Queryable,
  projectId: string,
  ids: readonly string[],
): Promise<void>
```

入参 `slots` 落库用 `JSON.stringify(...)::text::jsonb`，`required` 落库用 `文本数组`（与 `确保内置模板` 同一写法）；读回 `slots` 用 `读jsonb`（`case-translate-store.ts` 的既有工具），不假设驱动返回形状。

### 7.3 语义

- **建**：先 `校验模板定义`；按 `九格们` 顺序算规范化必填（`谁` 恒在，其余取用户传的集合）；生成 `用户:<uuid>`；同类型已有启用中的用户模板 ⇒ `conflict`（唯一索引也兜底，23505 翻 `conflict`）。`version = 1`、`verified_at = NULL`、`hit_count = 0`。
- **改**：内置 ⇒ `immutable`；不存在 ⇒ `not_found`；`定义.eventType` 改到已有启用模板的类型 ⇒ `conflict`；`定义` 全量替换（`name / event_type / slots / 规范化 required`）。一条 UPDATE 同时算版本与验证位：

  ```sql
  version = version + case when slots is distinct from $slots
                              or required is distinct from $required
                              or event_type is distinct from $eventType
                           then 1 else 0 end,
  verified_at = case when slots is distinct from $slots
                       or required is distinct from $required
                       or event_type is distinct from $eventType
                    then null else verified_at end
  ```

  只改 `name` 不动版本与 `verified_at`。
- **停用**：内置 ⇒ `immutable`；已停用 ⇒ 返回 `false`（路由回 404，语义「没有可停用的」）；成功写 `disabled_at = nowSeconds()`。
- **转正**：内置 ⇒ `immutable`；已停用 ⇒ `conflict`；`verified_at` 非空 ⇒ 返回 `{ verified_at, already: true }`；否则 UPDATE 带 `and version = $expectedVersion and verified_at is null`，0 行 ⇒ `state_changed`。`expectedVersion` 由路由在跑预览前读取。
- **记命中**：一次材料翻译成功后，对**实际产出 ≥1 张卡片**的用户模板 id（去重）逐个 `hit_count + 1`，与卡片写入同一事务。套用了但全行被跳过的不记——命中数回答的是「这张模板真的产过卡」。
- **列表**：默认 `disabled_at is null`；`含停用=true` 全部。排序 `disabled_at nulls first, event_type asc, id asc`。内置行也返回。
- **读**：既有 `读模板` 增加 `disabled_at` 列。

### 7.4 自动建议（纯函数）

```ts
export interface 模板建议 {
  id: string
  name: string
  event_type: 事件类型
  分数: number
}

/** 命中唯一最高分且 ≥ 2 才返回；平局、不足、无合格模板返回 undefined。 */
export function 建议模板(
  模板们: readonly 模板行[],
  映射字段集: ReadonlySet<识别字段>,
): 模板建议 | undefined
```

- 只考虑 `disabled_at === null` 且 id 以 `用户:` 开头的模板；
- 合格 = `required` 每个槽至少一条填法，且该填法的字段 ∈ 映射字段集；
- 分数 = 所有槽位条目（数组展开）中字段 ∈ 映射字段集的数量；
- 唯一最高分且分数 ≥ 2 才胜出。

## 8. 通用翻译引擎（`case-template-translate.ts`）

```ts
export interface 翻译模板输入 {
  projectId: string
  materialId: string
  template: 模板行
  rows: readonly FactRowInput[]
}

export function 翻译模板(input: 翻译模板输入): 翻译结果
```

`翻译结果 / 卡片草稿 / 卡片参与者 / 跳过` 沿用 `case-translate.ts` 的类型。本刀对该文件只做**类型放宽、新跳过原因、判据导出**，资金逻辑的分支与判定结果一律不变：

- `卡片草稿.participants` 放宽为 `[卡片参与者, ...卡片参与者[]]`（允许单参与方事件；`ordinal = 0` 仍恒为主体）；
- `卡片参与者.角色` 放宽为角色词表类型（资金用的 5 个角色是其子集）；
- `卡片参与者.实体类型` 改为 `case-extract.ts` 的 `实体类型`（8 种；资金用的 4 种是其子集）；
- `卡片草稿.amount` 放宽为 `string | null`；
- `卡片草稿.occurredAt` 放宽为 `number | null`、`occurredRaw` 与 `precision` 放宽为可空（`何时` 不是强制必填槽）；
- 新增可选 `模板id?: string`、`occurredEnd?: number | null`；
- `跳过原因们` 追加 `"必填槽为空"`、`"时间区间倒置"`（资金路径不产这两个原因）；
- `case-translate.ts` 导出既有判据 `文本值`、`是空行`，并把现有第十八至二十五行的两条汇总行判定原样提成 `export function 汇总行原因(row): "小计行" | "合计行" | null`，资金循环改为调用它。提取前后同一输入返回同一结果，既有资金用例是这条等价性的守卫。模板引擎只调这三处，不复制正则（`#002-06`）。

### 8.1 逐行算法

对每一行：

1. **空行** → 跳过 `空行`；
2. **汇总行** → 复用 `汇总行原因(row)`：返回 `小计行` / `合计行` 就按该原因跳过；
3. 按槽取值；任一 `required` 槽没有任何非空原文或数值 → 跳过 `必填槽为空`；
4. `何时` 有原文但解析不出 → 跳过 `时间无法解析`；
5. `何时` 与 `何时止` 都有值且 `何时止 < 何时` → 跳过 `时间区间倒置`；
6. 产出一张 `卡片草稿`。

### 8.2 取值

字段取值分两类（`FactRowInput`）：

- 标准列：`caller / callee / startedAt / durationSec / amount / balance / counterparty / counterpartyName / ownerAccount / direction / currency`；
- `extras`：`address / merchant / contactPhone / personName / deliveredAt / ownerName`。

时间字段统一走一个取值函数 `取时间(row, 字段)`：

- `startedAt` → 值取 `row.startedAt`、原文取 `row.startedRaw`、精度取 `row.precision`；
- 其余时间字段（`deliveredAt`）→ 值取 `parseTime(extras[字段])`，原文取该 extras 值，精度取解析结果；解析不出时值为 `null`、原文保留。
- `何时` 与 `何时止` 共用它；`何时止` 的精度不进卡片类型（`卡片草稿` 只有 `precision` 一个字段，存 `何时` 的）。

规范化参与方值与实体判定：

- 规范值 = `归一化值(字段, 原值)`（与识别层同一份，`#002-06`）；
- 提及 = 原件写法：`ownerAccount / counterparty` 优先用 `ownerAccountRaw / counterpartyRaw`，其余字段用原值；
- 可建实体 = 字段形状闸通过：`字段目录[字段].形状` 存在则调它，不存在则「非空即通过」；掩码/位数不足只留 `mention_text`。

### 8.3 槽位落点

| 槽 | 落点 |
|---|---|
| 谁 | 参与者 `ordinal = 0`；角色默认 `主体`；实体类型 = 填法指定或按种类推导 |
| 和谁 | 参与者 `ordinal = 1..n`；角色默认 `对方` |
| 何地 | 参与者排在最后；角色默认 `地点`；实体类型恒 `地点` |
| 何时 | `occurredAt`；原文进 `occurredRaw`；`precision` 沿用行上的值 |
| 何时止 | `occurredEnd` |
| 多少钱 | `amount`，字符串恒正数（去负号）；无此槽或该行无值 ⇒ `null` |
| 其他 | `attrs[字段显示名] = 原值`（`durationSec` 存数字，其余存原文） |

实体类型推导（填法省略时）：`账号→账户`、`号码→号码`、`户名→人`、`文本→人`、`商户→组织`、`地点→地点`。

### 8.4 摘要与用途

- 摘要格式（拼接后超 200 字截断并加 `…`）：

  ```text
  <事件类型>：<谁>[ 与 <和谁们>][，<何时原文>][ 至 <何时止原文>][，<何地们>][，<金额> <币种>][，<其他键 值>]
  ```

  空槽连同它的前导分隔符一起省略；至少留下「事件类型：谁」。

  例：`通话：13800000001 与 13900000002，2026-11-14 10:00，通话时长 180`。
- 用途：`判定用途({ 备注: null, 交易类型: null, 方向: null })`，落到兜底 `未分类`；不拿资金备注规则判非资金事件。

### 8.5 关系边

模板卡**不建** `case_relation`。`写入翻译结果` 里既有的关系重建只处理 `卡片草稿.type === 资金交易` 的卡，模板卡天然跳过；本刀不改那段逻辑。

### 9.1 逐表收集

### 9.2 选择与翻译

1. 若作业带 `templateId`（人工指定）：校验（属于本项目、非内置、启用中、`event_type` 合法）后，套到**所有** `模板候选表`；跳过打分，`方式 = "指定"`。

## 11. AI 默认过滤

### 11.1 唯一判据

`case-card-template.ts` 导出：

```ts
/** 只允许在 `from auth.case_event`（未起别名）的查询里用：片段裸引 `case_event`。 */
export function 模板可见条件(含未验证: boolean | undefined): SQL | undefined {
  if (含未验证 === true) return undefined
  return sql`not exists (
    select 1 from auth.case_card_template t
     where t.project_id = case_event.project_id
       and t.id = case_event.template_id
       and t.verified_at is null)`
}
```

- `template_id is null`（AI 抽取等旧路径）不匹配子查询 ⇒ 可见；
- 已停用但已验证的模板卡仍可见（停用只挡新解析套用，不追溯已有结论）；
- 内置资金模板 `verified_at` 非空 ⇒ 资金卡不受影响；
- 编辑映射清 `verified_at` 后，该模板的**历史卡片立刻退出** AI 默认查询，重新转正后恢复——这是「编辑降级」的可见后果；
- 模板行永不硬删 ⇒ 不存在「卡片指向已消失模板」的路径；判据只回答 `verified_at is null`，不额外做存在性判断。

### 11.2 落点

| 位置 | 改动 |
|---|---|
| `query_events` | 主查询的 `条件` 加 `模板可见条件(args.含未验证)`；`用途` 命中 0 条时那条「未判 purpose 数」诊断 count 也加同一条件（否则诊断数会数进用户看不见的卡）；返回的 `口径` 串补一句「默认不含未验证模板产出的卡片」 |
| `query_timeline` | 列表条件与「总数 / 有时数」统计查询都加；否则空原因与列表打架 |
| `find_crossings` | `时空条件` 加 |
| `case-mcp-server.ts` | 三个工具 `inputSchema` 增加 `含未验证: boolean`，描述写明「默认不返回未验证模板产出的卡片」；`收参数` 白名单增加 `"含未验证"` |
| `handleTimeline`（HTTP） | 调 `query_events` 时显式传 `含未验证: true`（民警要能看到未验证卡片） |

调用点统一写 `const 可见 = 模板可见条件(args.含未验证); if (可见 !== undefined) 条件.push(可见)`；不要 push 空 SQL 片段——`sql.join(..., sql\` and \`)` 会拼出 `and and`。

## 15. 缺口与风险

| 缺口 / 风险 | 影响 | 处置 |
|---|---|---|
| 旧材料无 `parse_detail.mapping.工作表[sheet].列` | 预览/转正 409 | 明确提示先重新解析；不静默回退到格式缓存（档案命中的材料没有格式缓存） |
| 模板版本历史不回滚（Q22） | 改错只能再改回来 | 登记缺口；`version` 只用于乐观锁与审计 |
| 模板卡不建关系边 | 主叫↔被叫不出现在关系图 | 登记；等模板带端点声明再做 |
| 模板卡用途 `未分类` | 用途统计不含话单等 | 设计如此；用途二期只覆盖资金 |
| 「其他」属性键用显示名 | 同一字段只有一种键，不能自定义标签 | 不打字、不出错优先 |
| 户名字段默认实体类型 `人` | 可能把账户户名建成人名实体 | 模板可显式改实体类型；预览可见 |
| 真栈 A14 未跑 | 未在真栈验证 | 待用户同意重启后补 |
| 解析请求显式模板只对非资金表生效 | 全资金材料里显式模板不会套用 | 接口文档写明「资金表仍走代码规则」；`parse_detail` 的 `卡片模板` / `未翻译表` 如实标明每张表去向 |
