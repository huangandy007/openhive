## 0. 一页结论

1. **产物就是图本身**，不配讲稿。讲稿用户自己另记（2026-11-11 用户裁定）。
2. **文件是唯一真相**：一张图 = 一个 `.hgraph` 文件，库只供料，不建图表、不双写（`LEARNINGS #007-02`：一份数据两处存，两处一起写没有任何单项断言看得出来）。
3. **图必须自包含**：绑库节点把值、类型、可信态、属性、出处抄进文件；库里改了什么，图不变，只加角标提示。
4. **混合口径**：节点/边分「事实」与「推断」，事实必须带行级出处，推断必须写依据。AI 想标事实却没有出处，**工具直接拒绝**。
5. **AI 不整份重写文件**，只提交操作：读最新 → 应用 → 校验 → 原子写回。人拖坐标与 AI 加节点因此不相交。
6. **多张图并行**：每张图一个标签页，撤销栈各算各的，AI 工具必须点名路径。
7. **视觉用两个独立通道**：边粗 = 关系强弱（金额/次数），节点外环粗 = 该节点在图上的分量（连接数）；都可手动覆盖。
8. **图不写回库**，单向。这条写进"不做"，防止以后有人顺手做双向同步。

## 1. 问题是什么

用户的原话：

> 「日常工作中，用户是通过对信息的了解、梳理获取清晰的关系信息，理清思路。我们前期所做的是让 AI 能够查询……交互后要形成产物，这个产物的形态我希望是关系图。这个过程就是案件侦破推进的过程。最后通过关系图用户可以清晰地讲述他的思路。」

拆开是三层意思：

- **现在缺的不是查询**，查询已经有了（实体、关系、事件、明细行）；
- **缺的是"把查到的组织成自己的理解"**：AI 查完，结果散在对话里，用户脑子里的那张图没有落点；
- **产物要能讲**：图的形态本身就是汇报材料，别人看着图能听懂办案逻辑。

所以这不是"加一个可视化"，而是**给"查"接上一个"结论"**：查询是过程，图是产物。

## 2. 与现有能力的关系

### 2.1 现有的「关系图」是放大镜，不是产物

`packages/app/src/center/case-views/graph.tsx`（1773 行）与 `packages/opencode/src/server/openhive/case-graph.ts`（440 行）已经有一张图，但它是**只读的实体邻域视图**：

| | 现有邻域图 | 本文的关系图产物 |
|---|---|---|
| 数据来源 | 库里实时查出来的 1～2 跳 | 一份文件 |
| 谁决定画什么 | SQL（以某实体为中心，上限 50，`case-graph.ts:94`） | 人 + AI 主动挑选 |
| 能不能改 | 只读，换中心 = 换一张图 | 可增删改，位置留得住 |
| 是不是产物 | 不是，关了就没 | 是，落项目文件树，可备份、可导出 |
| 出处 | 天然有（就是库里那条边） | 要设计：哪些有出处、哪些是推断 |

**结论：两者并存，互不改动。** 邻域图继续做"看一圈"，新图做"讲一件事"。邻域图的四套布局算法（`自动位置`，`graph.tsx:219`）直接复用，不另写。

### 2.2 AI 手上已有什么

`case-mcp-server.ts` 已注册：`query_entities` / `query_relations` / `query_events` / `get_citation`。其中 `query_relations(实体=…)` 就是"拉一圈"（`case-mcp-tools.ts:273-306`），`get_citation` 支持 `entity` / `relation` / `event` / `row` 四类事实。

所以"把张三这一圈加到我的图里"不需要新按钮——AI 用现有查询拿到邻域，再用本文新增的 `graph_add` 一次画上去。

### 2.3 视图注册表只认最后一个点

`view-registry.ts:73-92` 的 `extensionOf` 语义对齐 `path.extname`：取 basename 最后一个点之后。故：

- `.graph.json` ⇒ 扩展名是 `.json`，会被 JSON 的视图（若有）抢走；
- 必须有自己的后缀 ⇒ **`.hgraph`**，内容是 JSON。

## 3. 决定一：文件是唯一真相

### 3.1 三个方案

| 方案 | 真相在哪 | 好处 | 为什么不选 |
|---|---|---|---|
| **文件为真相**（采纳） | `.hgraph` 文件 | 产物可直接交付、备份、归档；AI 与人共用一条写路径 | — |
| 库里建表，文件只是导出 | `case_graph` 表 | 可查询、可做权限 | 一份数据两处存，读者分流时没有任何单项断言看得出来（`#007-02`）；"AI 改库"与"人拖文件"必然打架 |
| 双写 | 两边 | 看似兼容 | 同上，且多一套同步逻辑要维护 |

### 3.2 自包含

绑库的节点/边，把**当时看到的**抄进文件：

- 节点：值、库类型、细类、可信态、属性（开户行/卡号/证件号…）、出处；
- 边：次数、金额、出处、关系 id 列表；
- 同时保留库 id，用于"跳回实体详情"。

理由：实体会被改名、被合并、被排除；**产物不能随库漂**。半年后打开这张图，它必须还是当时那张。

### 3.3 单向

库 → 图，只能单向。图上加的东西**不**变库里的实体或关系。想知道"这条线索为什么在图上"，答案在图文件自己的出处与依据里。

### 4.2 四条钉死的规则

1. **`id` 文件内唯一、永不变。** 节点的 `id` 是 `n1`，不是库 id；库 id 放在 `来源.实体`，可以没有。实体被合并/删除时图不崩，只是"跳转"失效并提示。
2. **每个节点/边必须能回答"凭什么在图上"。** `来源.kind` 四值：`实体` / `关系` / `推断` / `手写`。边的 `性质` 两值：`事实`（实线）/ `推断`（虚线）。
3. **出处是行级的**：`材料#工作表#行号`，与 `case_citation` 同形（`case-store.ts:423-432`：工作表名可含 `#`，按首末 `#` 解析）。
4. **坐标落盘**：`x` / `y` 是图的一部分，拖完即存。

### 4.3 类型是开放词表，不是枚举

初稿写死七类（人/账户/号码/公司/车辆/地址/其他），被用户当场否掉：i2 的常用类型有二十来类（车辆、电信、犯罪、活动、资金、军事、人员、商品、社交媒体、网络犯罪、位置、文档、武器、医疗、组织、其他…），实际办案远不止七个。

改定：

- `类型` 存**字面字符串**，读取时**不校验白名单**；
- 认识的类型给专属颜色/形状；不认识的用默认形状 + 名字照显示，**不报错、不丢节点**；
- 第一版内置一套基础类型；**类型导入后置**，但字段现在就留好：`类型` + 可选 `样式: { 颜色, 形状 }` 快照。类型表以后怎么变，老图的观感不跟着变；
- 库实体大类（人/账户/号码/公司）与图上类型（犯罪/电信/社交媒体）**不是一套**。绑库节点两个都存（`来源.库类型` + 外层 `类型`），加入时按映射表给初值，用户改了就按用户的。
- i2 的类型**名称**是通用词，可照用；**图标是商业资产**，不抄，用自有形状与颜色。

### 4.4 版本与兼容

- `格式: 1`。将来不兼容的改动加一，读到更高版本**只读打开**并提示"请升级"；
- 未知字段**保留原样写回**，不许静默丢弃（AI 或新版本写入的字段，旧版本不能吃掉）。

## 5. 决定三：图上的手动操作

判据：**民警用鼠标能不能把脑子里那张图完整画出来，并且画错能收回。**

### 5.1 工具栏与控制

- 全图标，悬停 300ms 出文字说明，说明里**带快捷键**（「删除（Delete）」「撤销（Ctrl+Z）」）；
- 图标复用 `graph-icons.tsx`，不新画一套；
- 分三组，分隔线隔开：**选择｜画**（指针、连线、加节点、文字）、**排**（对齐、等距、自动布局）、**整**（缩放适配、导出、撤销重做）。

### 5.2 连线是一个模式，不是一次拖拽

初稿把"拖到另一个节点上松手 = 连线"与"拖动摆位"放在同一次拖拽里，用户当场指出会打架。改定：

- 工具栏两个模式：**指针** / **连线**；
- 连线模式下，在节点上按下并拖动，有一根线跟随鼠标，落到另一个节点上松手即成边，落到空白处不成边；
- 指针模式下拖动只移动，永远不建边；
- 双击空白 = 新增节点（指针模式），与工具栏「加节点」等价。

### 5.3 选区与多选

- **Shift + 点击**：加入/移出选中；
- **框选**：指针模式在空白处拖出选框；按住 `Shift` 框选 = 追加，不按 = 替换；
- **高亮**：选中节点描边加粗 + 外圈光晕；选中边加粗提亮；检查器顶部显示「已选 N 个」；
- 点空白 / `Esc` 取消；
- 多选后可做：整体拖动、对齐、等距、删除。

### 5.4 对齐与等距

- 选中 ≥2 才亮：左 / 水平居中 / 右 / 顶 / 垂直居中 / 底；
- 以**选中范围的边界**为准（最外侧那个不动）；
- 选中 ≥3 才亮：水平等距 / 垂直等距，两端不动、中间均分；
- 每一步进撤销栈。

### 5.5 自由文字

用户要的不是节点标签，是**能在图上写话并排版**：

- 「文字」按钮 → 点画布落一个文本框，直接敲；
- 可排版：字号（小/中/大）、加粗、颜色（预设色）、对齐（左/中/右）、框宽可拖、自动换行；
- 可拖动、可删除、可撤销，导出 PNG 时一起导出；
- **不做**：斜体/下划线/字体族/旋转/从 Word 粘贴富文本。中文办案记录用不上，加了只会让人把图当文档写。

### 5.6 视觉的两个独立通道

| 通道 | 表达什么 | 默认怎么算 |
|---|---|---|
| **边的粗细** | 这一条关系有多强 | 按关系类型选度量：资金类按金额，通信类按次数，其他按次数 |
| **节点的外环粗细** | 这个节点在图上的分量 | 按它在图上的连接条数，4 档 |

**为什么强弱不能跨类型比**：转账比次数没意义（一笔 50 万 vs 五十笔 1 万），话单比金额更是胡说。所以度量按关系类型定。

**为什么用固定阈值而不是分位数**：分位数会让"每加一条边，全图粗细重排"，同一张图今天讲和明天讲不一样，汇报时会被问住。固定阈值写进 `设置`，改了就固定。

默认档位：

- 次数：1 / 2～4 / 5～9 / 10～49 / 50+
- 金额：1 万以下 / 1～5 万 / 5～20 万 / 20～100 万 / 100 万以上
- 外环：1 条 / 2～3 条 / 4～7 条 / 8 条以上

**手动覆盖**：选中边可设「自动 / 1～5 档」（5 档即加粗强调）；选中节点可设外环档位与颜色（预设色）。覆盖值写文件（`线宽档` / `外环`），没写就按规则自动算。外环颜色默认按类型，手动改色用于"红环 = 重点对象"这类标记。

**手动值冻结**（2026-11-11 用户裁定）：外环一旦被手动设过档位或颜色，就**不再随连接数自动变**。理由：手动动过就是一次"人工判断"，不能被算法悄悄改回去——连接数从 3 涨到 9，用户标的 3 档还得是 3 档。要恢复自动，在检查器里点「恢复自动」，删掉覆盖值。

**节点连线多时**（"毛线球"）三层叠加：

1. **弱线淡化**：1～2 档的边降低不透明度，强边自然跳出来；
2. **强度过滤**：工具栏档位滑块「只看 ≥3 档」，隐藏弱边，画布角落明说「已隐藏 12 条较弱关系」——**不能悄悄藏**；
3. **外环加粗**：一圈细边汇到一个粗环上，"这个人是核心"一眼看得出。

**不做边捆绑**（多条线拧成一股）：好看但难解释，民警讲图时说不清"这一股到底几条"。

**图例常驻**，两组刻度分开画：「线粗 = 关系强弱」「环粗 = 连接多少」，另标「实线 = 事实 / 虚线 = 推断」。

### 5.7 检查器：点节点后显示什么、显示在哪

#### 5.7.1 位置与形态

- **右侧浮动面板，宽 320px，不改变画布尺寸**。图的坐标是固定逻辑坐标（viewBox），画布宽度一变缩放比就变、所有节点会跳；浮层不碰画布，图形纹丝不动。
- 沿用邻域图的观感（`graph.tsx` 的 `面板宽 = 280`、`面板边距 = 24`），只是加宽到 320 放得下属性表。
- **不挡被选中的节点**：选中节点中心若落在面板覆盖区，画布自动向左平移一小段，保证"点了它就能看见它"。

#### 5.7.2 内容：三段竖排 + 底部一条

```
┌──────────────────────────────┐
│ ● 张三              [事实] × │   ← 类型色圆点 + 名称 + 状态徽标
│ 人 · 嫌疑人                   │
├──────────────────────────────┤
│ 图上记的                      │
│  开户行   招商银行  [材料3#1] │   ← 属性：键值 + 出处标签（可点）
│  银行卡号 6214…     [材料3#1] │
│  备注  ┌──────────────────┐  │   ← 可编辑，失焦即存，算一步撤销
│        │ 推测为司机        │  │
│        └──────────────────┘  │
├──────────────────────────────┤
│ 库里现在            [查看 ▾] │   ← 默认收起，点了才查
│  关联 12 · 金额合计 86 万      │

```

- **头段**：类型色圆点、名称、类型 · 细类、状态徽标（事实/推断/手写；绑库的再带库可信态）。
- **「图上记的」**（来自文件，稳定不变）：一律 `键 —— 值` 两列。属性每条后挂**出处小标签**，点它跳到材料那一行；库里没有属性时明写「库中无记录属性」，不空着让人猜。备注是可直接编辑的文本域，失焦即存，算一步撤销。
- **「库里现在」默认收起**：不点不查，避免每选一次节点就打一次库。展开后先给三个数字（关联数、金额合计、首末时间），再列最多 5 条关系（点一条高亮对应边），最后一句「库中还有 N 条关系未上图」——只报数量，要加请让 AI 加。
- **底部「打开档案」**：见 §5.7.4。

#### 5.7.2.1 哪些能改、哪些不能改

按**信息来源**划一刀，不能凭手感：

| 字段 | 能不能在面板改 | 口径 |
|---|---|---|
| 名称、类型、细类 | **能**，失焦即存 | 图上这张卡怎么叫、算哪类，画图人说了算 |
| 外环档位、外环颜色 | **能**，选完即生效 | "人工标记重点"的通道 |
| 备注 | **能**，失焦即存 | 用户自己的批注 |
| **属性**（开户行 / 卡号 / 证件号…） | **不能** | 它们是从库里抄来的快照。图上改了库里没改，就成了"文件说招商银行、库说建设银行"，还查不出谁先改的。要改去实体详情页改库，回来点「刷新此节点」 |
| 可信态、出处 | **不能** | 出处只能由"从库加入"或 AI 带出处产生；手工节点就是「手写 / 推断」，不出处 |

**类型框是"可输入的下拉"**：下拉列内置类型，但允许直接打字写新的——对应 §4.3 的开放词表，不会因为词表里没有就卡住人。

**没有「保存」按钮**：名称、备注失焦即存；类型、颜色、档位点选即存。存成功图上立刻重绘；存失败**把那个字段回滚到改前**并在面板里报「没存上」——界面不能显示一个其实没存进去的值。每一次改动都算一步撤销。

#### 5.7.3 收起与展开

- 收起不是消失，而是缩成右侧一条 **40px 窄条**，竖排「详情」二字 + 一个类型色圆点（表示当前选中是什么）。
- 展开方式两种：**点窄条** 或 **快捷键 `I`** 切换。
- **不做「再点节点就自动展开」**：有人习惯反复点各个节点，自动弹面板会让人反感（2026-11-11 用户裁定）。面板收起是上一刻的状态，不因下一次点击被强行推翻。
- `Esc` / 点空白 = **取消选中**并收起面板，不记为"用户把面板关了"。

#### 5.7.4 「打开档案」按钮

- 绑库节点：按钮可点，打开实体档案标签页（`case://<项目>/entity/<id>`，`entity-profile.tsx`）。
- 未绑库节点：**按钮灰显、不可激活**，旁边一行小字「这条不在库里」。
- 双击绑库节点等价于点这个按钮；双击未绑库节点无动作。
- 为什么不做成"点节点即开档案页"：看图时十次点击有八九次是"确认一下这是什么"，要的是瞬时、不离开图；每次点击都切走页面，讲图讲到一半就得来回切标签，听众的注意力会断。深挖才走档案页，浮层给"够看"的摘要。

#### 5.7.5 特殊情形

| 情形 | 面板怎么变 |
|---|---|
| **多选**（≥2） | 换成「已选 3 个」+ 对齐 / 等距 / 删除，不显示单个详情 |
| **选中边** | 同一个面板换成边的信息：标签、性质、次数、金额、两端节点、出处、**备注（可编辑）**；同样分「图上记的 / 库里现在」。可改：标签、性质、备注、线宽档；只读：次数、金额、出处。**没有出处的边不许改成「事实」**——与 AI 工具走同一条硬闸，提示"补出处，或保持推断" |
| **点空白 / `Esc`** | 取消选中，面板收起 |

明确不做：模态弹窗（挡住图，讲图时最忌讳）；并排挤开画布的双栏（坐标会跳）；把详情做成新标签页（看个节点就跳走，回不来）。

### 5.8 撤销

- `Ctrl+Z` 撤回最近 20 步，`Ctrl+Shift+Z` 重做；
- 新增、删除、连线、改字、移动、对齐、自动布局，各算一步；
- **AI 的一整批变更也算一步**（见 §6.5）；
- 撤销栈**按标签页独立**，切换标签页不串。

### 5.9 自动布局

- 力导向 / 环形 / 分层 / 网格，复用 `graph.tsx` 的 `自动位置`（`:219`）；
- 新图没有"中心/跳数"，映射成大图时按 BFS 分层、度数最高者为临时中心；
- 自动布局会覆盖手动摆位，**必须弹确认**，且这次操作可撤销。

### 5.10 规模

- 不设硬上限；
- >300 节点提示「这张图已经偏大，建议拆成多张」；
- >1000 节点只提示性能风险，**不拦、不截断**——截断一张图等于骗人。

### 5.11 新建文件与类型选择

现有弹窗只问名字（`file-create-dialog.tsx:110-137`）。改成「名称 + 类型」两段：名字框下面一行**类型胶囊**，默认选中 Markdown；底下仍是落点那行与取消/确定。

```
┌─────────────────────────────┐
│ 新建文件                 ×  │
│ 名称                        │
│ [张三资金流向            ]  │
│ 类型                        │
│ ┌────────┐┌──────────┐┌─────┐│
│ │◈ 关系图││≡ Markdown││▤ 表格││

│ └────────┘└──────────┘└─────┘│
│ 建在：项目根目录            │
│           [取消] [确定]     │
└─────────────────────────────┘
```

#### 5.11.1 只有「可新建」的类型才进列表

**能打开 ≠ 能新建。** 系统能打开 Word / Excel / PDF / 图片 / 思维导图，但**空文件打不开**——新建一个 0 字节的 `.docx`，双击得到的是"文件已损坏"。格式本身要求完整包结构，这不是实现偷懒。

第一版只列四类（2026-11-11 用户裁定）：

| 类型 | 后缀 | 初始内容 |
|---|---|---|
| 关系图 | `.hgraph` | 预置 §4.1 的空图骨架（`格式/标题/节点/边/文字`） |
| Markdown 文档 | `.md` | 空 |
| 文本文件 | `.txt` | 空 |
| 表格 | `.csv` | 空（首行留空，打开即空表） |

不列 Word / Excel / PDF / 图片 / 思维导图（空文件不合法），也不列代码类（民警不会在案卷里新建 `.ts`）。**后期要加再加**，列表做成数据驱动，加一项不改界面。

#### 5.11.2 名称与后缀

用户只写名字，后缀由类型决定，提交时自动补。三种输入都要顺畅：

| 用户输入 | 选择的类型 | 结果 |
|---|---|---|
| `张三资金流向` | 关系图 | `张三资金流向.hgraph` |
| `张三.hgraph` | 关系图 | `张三.hgraph`，**不重复加** |
| `张三.md` | 关系图 | 输入框里已知后缀自动把类型胶囊**切到 Markdown**，并提示「已按输入的后缀切换类型」——不报错 |

判后缀用 `path.extname` 语义（取最后一个点之后，`view-registry.ts:73-92` 同一份规则）；`3.5万流水` 这种名字点不在末尾且尾巴不是已知后缀，就当名字，不切。

#### 5.11.3 空骨架怎么落地（2026-11-12 定）

现有创建接口只会造**空文件**（`file.ts:1077`「造一个空文件或空目录」），不会预置内容。三条路里选第三条：

| 方案 | 问题 |
|---|---|
| 改通用 create 支持初始内容 | 动核心文件写接口，为一个小功能扩大改动面 |
| 前端 create 后直接写内容 | 多一条写路径，违反 §6.1 |
| **✅ create 后立即调 `POST hgraph/init`** | 由 `hgraph-ops` 写骨架（校验文件为空才写），写路径仍唯一 |

`hgraph/init` 的行为：文件存在且为 0 字节 ⇒ 写 §4.1 空骨架（`格式:1` + 标题取文件名 + 空 `节点/边/文字` + 默认 `设置`）；文件非空 ⇒ 不覆盖，直接返回现有内容（幂等，重复点"新建"不会清掉图）。

新建文件夹不弹类型选择，行为不变。

## 6. 决定四：AI 怎么改图

### 6.1 不整份重写

AI 若整份重写文件，用户正在拖的节点坐标会被覆盖，而且没人会发现坐标变了。所以**一切都走"操作"**：

```
读最新文件 → 应用这一小批操作 → 校验 → 原子写回（临时文件 + rename）
```

人拖坐标、AI 加节点，都是同一个入口，只是操作不同。两者不相交，因此不会互相覆盖。

**服务端按路径串行化**（进程内一把锁），同一张图不并发写。

**写路径唯一（2026-11-12 定）**：前端拖拽、改字段、AI 工具——**全部**调 `hgraph-ops` 的操作与保存接口，**前端不直接调通用文件写接口**。否则人一条路、AI 一条路，串行锁只锁住一半（`#007-02` 的形态）。前端 `hgraph/file.ts` 只承担**解析与 schema 校验**（读回、预览、测试用），它不是写入者。

**版本 CAS（防止互相覆盖）**：每次读返回 `版本`（服务端 `stat` 出来的 `<mtimeMs>:<size>`，10 秒轮询只 `stat`、不读内容）。保存时客户端带上「我基于哪个版本」；服务端发现当前版本已变 ⇒ **409 拒绝**，返回最新版本，由前端按 §6.7 问用户「重新载入？」——不替用户选、不静默合并。

### 6.2 五个工具

| 工具 | 入参要点 | 干什么 |
|---|---|---|
| `graph_list` | — | 列出本项目所有图：路径、标题、节点数、更新时间 |
| `graph_read` | 路径 | 读节点与边（含出处），改前先看 |
| `graph_add` | 路径 + 一批节点/边 | 批量新增（**单次 ≤50**，超出拒绝并建议分批） |
| `graph_update` | 路径 + 目标 id + 字段 | 改名称/类型/标签/备注/性质/位置 |
| `graph_remove` | 路径 + 目标 id | 删节点或边，返回连带删掉的条数 |

**共 5 个**（`09` §1.1 末尾的反证段也按 5 个计）。路径必须：落在项目目录内、后缀 `.hgraph`。校验复用现有路径闸（`file.ts` 的归属与穿越判定）。

**不套用 `09` 的七字段信封**：`09` 的信封只要求**查库**工具（§0 第 5 条、§3.1 明写「现有 7 + 新增 4」，图写入不在内），因为图写入属「改文件」通道（`09` §0 第 5 条、§11 已声明不并入查库）。这 5 个工具返回自己的结构（路径 / 复用说明 / 删除条数 / 错误话术）；失败一律 `isError`，不伪装成功。

### 6.3 出处是硬闸

`graph_add` 收到一条标「事实」的节点或边却没有 `出处`，**工具直接报错拒绝**，原文告诉 AI：

> 这条标了事实但没给出处：要么补出处，要么改成推断并写明依据。

这条不写在提示词里求模型自觉——**它必须是代码里的判据**，否则模型换个写法就绕过去了。

同理：`性质: "推断"` 必须同时有 `来源.依据`，空依据也拒绝。

### 6.4 同名复用

AI 加节点时，若图上已有**同名且同类型**的节点，复用它并连到它上面，返回里明说「复用了已有节点 张三」。否则图上会出现两个"张三"，用户还得自己合并。同名不同类型（人张三 / 账户张三）不算重复，新建。

### 6.5 AI 可以删，但可撤销

用户裁定：AI 可以删任何节点（不止自己加的）。

配套两条，不是限制是保护：

1. AI 每次删除**必须回话说明删了什么**（几个节点、哪几条边）；
2. 这一整批删除在前端**算一步可撤销的操作**——`Ctrl+Z` 能整批退回。模型一次删错，用户至少能完整还原。

### 6.6 多张图并行

- 每张 `.hgraph` 一个标签页，可同时开多张；
- AI 工具**必须点名路径**，不做"项目当前图"这种隐式状态（多张并行时它一定猜错）；
- 只有项目里**恰好一张**图时，路径可省略；
- 有多张而 AI 拿不准，调 `graph_list` 列出来问用户，**不许瞎猜往最近改的那张写**。

### 6.7 前端怎么看到 AI 的改动

- 每次操作即时发出（防抖 500ms），本地几乎没有"未保存"的东西；
- 页面每 10 秒对一次文件版本（服务端 `stat` 出的 `<mtimeMs>:<size>`，见 §6.1），发现变了且本地无未发出改动 → 静默重载；
- 本地刚拖完还没发出去、AI 恰好也改了 → 弹「图已被更新，重新载入？」，**不替用户选**；
- 只重载被改的那一张标签页（按路径匹配）。

## 7. 决定五：图与库的衔接

**从库里上图（2026-11-12 改：入口在图视图内）**

原设计写「实体详情页 / 实体面板右键 → 加入关系图」。`07` 已定稿**下架实体页签**、且明确「本轮不给详情页补入口」，面板与详情页都失去入口（`entity-panel.tsx` 的生产接线只有 `workspace-entry.tsx` 一处，页签摘掉即断）。故入口改由本视图自带：

- 图工具栏「**从库加入**」→ 弹出选择器：搜索框（**名称 / 别名**）+ 结果列表（名称、类型、细类、可信态、关联数）+ **多选** →「加入当前图」；
- **搜索口径照服务端能力走**：`GET /openhive/case/entities` 的 `q` 只匹 `canonical_value` 与 `aliases`（`case-entity-list.ts:143-150` 实读），**不匹类型**。故「按类型找」不做成搜索条件，而是把**类型当结果列表的一列 + 前端筛选**——零服务端改动（改那段 SQL 属高频文件，与「最小化上游冲突」相悖）；
- 选择器复用 `entity-api.ts` 的 `list`（字段刚好够这四列：`type` / `subtype` / `trust_state` / `关联数`），该模块 `07` §3.2 已定**不删、不改契约**，不新写后端接口；
- 加入瞬间拍快照：值、类型、细类、可信态、**出处**（`get_citation` 的 entity 分支，取不到就在节点上写明「未取到出处」，不假装有）；
- 关系同理：选择器可切「关系」页，勾选后加边，带 `关系们` 与出处；
- **「以此为中心展开一圈」仍不做按钮**（§2.2、§10）：一圈由 AI 用 `query_relations` + `graph_add` 代劳，人工只做「挑人/挑关系」。

**快照拿不到时（当前阶段的常态）**：表格来源今天不建实体，属性写入属 `01` P2（`01` §12.1）。所以本阶段能被选中的实体多半来自文本材料，`attrs` 与出处常为空——节点照建，写明「未取到出处」「库中无记录属性」，**不拦、不伪造**。

**从图上回库**

- 双击绑库节点 → 实体详情页（伪路径 `case://<项目>/entity/<id>`，页面仍在）。**这等于给详情页补了一个入口**，与 `07` 不冲突：`07` 只是不恢复"浏览清单"，而这里的入口始终有上下文（从图上某个具体节点进去）。
- 检查器里的出处可点 → 跳到材料那一行。

**库里变了，图不变**

- 打开图时拿节点快照与当前库对一遍：值被改、实体被合并、被排除，都在节点上加角标；
- 点角标能看见差异（「文件里记的是张三，库里现在叫张三丰」），但**文件内容一个字不改**；
- 用户可手动「刷新此节点」把快照更新到最新。

## 8. 决定六：导出图片

- 图文件右键或工具栏「导出 PNG」；
- 导出内容 = 当前画布所见（含图例、文字块、线的粗细与虚实），2 倍分辨率、白底；
- 不做 SVG 导出（第一版），不做 PDF；
- 导出的图**不带**交互态（选中高亮、悬停提示）。

### 8.1 授权与留痕（2026-11-12 定，收口 `01` §14.3 Q23）

图里全是明文（`01` §10.1），而导出的 PNG 落到项目目录**之外**，会脱离项目的归属边界。所以导出不是"点一下就下载"：

| 项 | 口径 |
|---|---|
| **谁能导** | 项目成员；路径必须落在本项目目录内、后缀 `.hgraph`（复用统一下载权限与路径闸） |
| **怎么导** | 前端先调 `POST /openhive/hgraph/export`（服务端校验归属 + 留痕 + 记账），返回许可后才渲染下载；**先授权、后出图**，不是先下载再补记 |
| **留痕** | 一条：人 + 项目 + 图路径 + 时间 + 文件名；写内核日志（目前无独立审计表，`01` §13 Q8 的"查询审计"落地时并入同一处） |
| **文件名** | `<项目名>-<图名>-<YYYYMMDD-HHmm>.png`，多张图多次导出不互相覆盖 |
| **界面提示** | 导出后一行「已记录本次导出」——不是解释给用户听，是让"被记录"这件事能被感知（明文前提下这条不能省） |

**不做的**：不加水印、不加掩码（用户拍板：本项目一律明文）；不做"禁止导出"开关（导出是汇报的刚需，闸口放在"可追溯"而不是"不准"）。

## 9. 出错的时候

| 情形 | 表现 |
|---|---|
| **JSON 解析失败** | 打开即报「这份图打不开，第几个节点缺了什么」，提供「以文本方式打开」；**禁止一切写回**，包括 AI 工具 |
| **保存失败** | 明确报「没存上」，改动留在页面可重试；**绝不假装成功** |
| **文件被外部删除** | 标签页提示「文件已不存在」，**禁止保存**（否则一存就"复活"成空图） |
| **同路径两个标签页** | 复用现有「同路径只开一个 tab」，从根上不产生两份编辑态 |
| **外部编辑器改了文件** | 保存时版本不一致 → 按 §6.7 处理 |
| **写入中断** | 临时文件 + `rename` 原子替换，不留半截文件 |

**手工验收**

1. 新建弹窗里选「关系图」→ 生成 `.hgraph` 空骨架，双击进图视图，空图能画；输入 `张三.md` 时类型自动切到 Markdown，不出现 `.md.md`；
2. 拖节点 → 关闭再开，位置一模一样；
3. 指针模式拖动只移动；连线模式 A 拖到 B 成边，拖到空白不成边；
4. `Ctrl+Z` 能撤 20 步，含 AI 的一整批删除；

7. 导出 PNG，画面与画布一致，含图例与文字块；文件名符合 §8.1（`<项目名>-<图名>-<YYYYMMDD-HHmm>.png`）；文件树右键与工具栏两个入口都走 `POST hgraph/export`，**内核日志留一条含人/项目/图路径/时间/文件名**的记录；非项目成员调用该接口被拒；
8. 库里把某实体排除后再开图：节点带角标，**文件字节不变**；
9. 手工把 JSON 改坏 → 打开报错、不覆盖、AI 工具也拒绝写；
10. 图文件随项目一起被备份/拉回；
11. 面板里改名称 / 类型 / 外环颜色 / 档位 → 失焦或点选即存，关闭重开仍在；模拟保存失败时**字段回滚并提示「没存上」**；属性与出处**没有输入框**，只有跳转；
12. **版本 CAS**：两个标签页开同一张图，A 加节点保存成功 → B 再保存被 409 拒绝并提示「图已被改动，已重新载入」，**B 的改动不落盘、A 的不被覆盖**。

## 13. 风险与实现期参数

> 设计层面**已无待拍板事项**（2026-11-11）。以下都是实现时定、或已知会长期存在的风险，不阻塞开工。
>
> **2026-11-12 补充**：实现前审计发现的六处空缺已全部定案，不再列为待拍板——① 人与库的接缝改为图视图内「从库加入」选择器（`07` 下架实体页签后原右键入口不可用，§7）；② 导出授权、留痕、文件名（§8.1）；③ 写路径唯一 + 版本 CAS（§6.1）；④ 空骨架怎么落地（§5.11.3）；⑤ 落点清单补齐真实路径与五处漏项（§11）；⑥ 验收降级与新增加两条（§12）。下面的条目仍是真风险。

1. **AI 批量上限 50** 是拍脑袋的第一版值，真实使用后再调。
2. **属性快照会过期**：库里补了开户行，图上还是旧的，只有角标与「刷新此节点」这条人工路径。是否要做"打开图时自动更新快照"——不做，理由同 §3.2（产物不能自己变）。
3. **图的体积**：几百节点 + 出处数组，文件可能到几百 KB；目前无压力，真要大了再考虑出处去重。
4. **撤销栈是内存态**：关闭标签页即丢；不做持久化撤销。
5. **导出 PNG 的中文字体**：SVG 转 canvas 时字体不回退会掉字。定下来的顺序：先按当前字体栈导出一次并用真栈截图比对（含中文节点名、金额、图例）；**只要有一个字掉就内联字体**（base64 `@font-face` 写进 SVG），不走 `foreignObject`（跨浏览器与 canvas 兼容性更差）。实测结果写进实现报告，不能只写「已处理」。
6. **类型映射表**（库大类 → 图类型）首版按一对一直译（人→人员、账户→账户、号码→电信、公司/组织→组织，其余落"其他"），真实使用后再调。
7. **多人/多设备**：图放在项目文件树里，天然跟备份走；但两人同时开同一张图不在本设计范围。
8. **自动布局在无中心图上的映射**（BFS 分层 + 度数最高者为临时中心）是实现细节，可能与旧图的观感不同，需实测。

## 附：讨论过程（一步一步）

1. **用户提出**：希望通过 AI 交互或手动在关系图中加节点/关系，图以文件落盘；产物形态就是关系图，用于讲清侦破思路。
2. **确认理解**：现有邻域图是"放大镜"，要的是"白板 + 卷宗"，两者并存。
3. **第一问**：节点允不允许"库里没有" → **混合**（绑库实体 + 自由线索，事实实线 / 推断虚线）。
4. **第二问**：文件形态。初稿提 `.md + 数据块` / 纯 JSON / 双文件，用户否掉整个方向：**产物就是图，不配讲稿**。改为单一图文件。
5. **第三问**：AI 直接画还是先建议 → **直接画**。
6. **类型词表**：初稿写死七类，用户拿 i2 截屏指出类型很多，改为**开放字符串 + 后置导入**。
7. **手动操作范围**：定下拖、加、连、改、删、框选、对齐、文字、撤销、自动布局；撤销用户明确要。
8. **连线方式**：初稿"拖到节点即连线"与移动抢同一次拖拽，用户指出会打架，改为**工具栏连线模式**。
9. **AI 删除权限**：我建议 AI 只能删自己加的，用户裁定 **AI 可以删**；配套"回话说明 + 整批可撤销"。
10. **多图并行**：用户要求按多张图设计 → 路径必填、标签页独立撤销栈、不做项目级"当前图"。
11. **线宽与强弱**：定下按类型选度量、固定阈值 5 档、弱线淡化、强度过滤、图例。
12. **节点外环**：用户拿 i2 截屏提出"圆周粗细代表节点"；定下外环 4 档、颜色默认按类型、可手动覆盖。
13. **导出与批量加入**：导出 PNG 要；邻域图批量加入不做界面，由 AI 代劳。
14. **检查器形态**：定下右侧 320px 浮动面板、三段结构、自动避让；收起为 40px 窄条，点窄条或 `I` 展开。初稿的「再点节点就自动展开」被否——有人习惯反复点节点，自动弹开会反感。底部「打开档案」按钮，未绑库节点灰显不可点。
15. **新建改成"名字 + 类型"**：用户要求把新建关系图收进现有新建弹窗，用类型胶囊选。定下只列**可新建**的四类（关系图 / Markdown / 文本 / CSV），Word / Excel / PDF 等空文件不合法的格式不进列表；输入已知后缀时自动切换类型，不重复加后缀。
16. **节点属性在面板里改**：可改名称 / 类型 / 细类 / 外环 / 备注，失焦或点选即存、失败回滚；库快照属性与出处只读，改要去实体详情页改库。
17. **收尾两条**（2026-11-11 用户裁定）：边加可选的 `备注` 字段；外环手动值**冻结**，不再随连接数自动变，要恢复自动需点「恢复自动」删掉覆盖值。设计到此冻结。
