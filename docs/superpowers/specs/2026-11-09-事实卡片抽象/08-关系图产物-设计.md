## 0. 一页结论

1. **产物就是图本身**，不配讲稿。讲稿用户自己另记（2026-11-11 用户裁定）。
2. **文件是唯一真相**：一张图 = 一个 `.hgraph` 文件，库只供料，不建图表、不双写（`LEARNINGS #007-02`：一份数据两处存，两处一起写没有任何单项断言看得出来）。
3. **图必须自包含**：绑库节点把值、类型、可信态、属性、首末时间、出处抄进文件；库里改了什么，图不变，只加角标提示。
4. **混合口径**：节点/边分「事实」与「推断」，事实必须带行级出处，推断必须写依据。AI 想标事实却没有出处，**工具直接拒绝**。
5. **AI 不整份重写文件**，只提交操作：读最新 → 应用 → 校验 → 原子写回。人拖坐标与 AI 加节点因此不相交。
6. **多张图并行**：每张图一个标签页，撤销栈各算各的，AI 工具必须点名路径。
7. **视觉用两个独立通道**：边粗 = 关系强弱（金额/次数），节点外环粗 = 该节点在图上的分量（连接数）；都可手动覆盖。
8. **图不写回库**，单向。这条写进"不做"，防止以后有人顺手做双向同步。
9. **格式先留六个字段**（`时间` / `方向` / `证据` / `可信度` / `出现序` / `链接`），第一版不建界面。它们不增加实现量，但决定这套格式半年后能长还是得重来（§4.2）。
10. **「事实」只表示"有行级出处"，不表示"内容为真"**。材料本身可能错，所以推断必须再带 `可信度`；看图的领导不该把实线读成铁证（§4.2 规则 6）。
11. **图和库之间还有一个方向**：手写/推断节点可「绑定到库实体」升级为事实，不是只出不进（§5.7.2.1）。

## 0.1 范围边界（先看这一节）

> **这一节是防过度设计的闸门。** 功能的默认答案是「不做」——要进第一版，必须回答"没有它，民警的哪一步做不下去"。
>
> **第一版只服务四句话**（超出即砍）：
> ① 民警能把脑子里的图**完整画出来**，画错能收回；
> ② AI 能把查到的**画上去**，且每条都说得清凭什么；
> ③ 图能**讲给人听**（不另配讲稿）；
> ④ 图能**落盘、备份、导出**成交付材料。
>
> 一个功能服务不了这四句中的任何一句 ⇒ 不进第一版。

### 0.1.5 砍功能的自检三问（新加任何能力都先过一遍）

1. **没有它，上面四句里的哪一句做不下去？** 答不出 ⇒ 砍。
2. **能不能用"已有能力 + 一句话提示"代替？** 能 ⇒ 不做界面。
3. **是不是"看起来很专业、但民警一个月用不到一次"？** 是 ⇒ 后置。

**过度设计的信号**（出现即停手复核）：

- 为一张图引入**第二种数据存储**（库表、缓存、索引文件）；
- 出现**第二条写路径**（前端直写、脚本直写、通用文件接口写 `.hgraph`）；
- 为渲染引入 **WebGL / 图数据库**，而 800 节点降级后仍可用；
- 为"以后可能要多个人"引入 CRDT / 协同框架；
- 为"可能会配置"加一堆开关（阈值、档位已是配置，别再加同类）；
- 为了让图"更好看"加动画、渐变、阴影、图标库。

## 1. 问题是什么

用户的原话：

> 「日常工作中，用户是通过对信息的了解、梳理获取清晰的关系信息，理清思路。我们前期所做的是让 AI 能够查询……交互后要形成产物，这个产物的形态我希望是关系图。这个过程就是案件侦破推进的过程。最后通过关系图用户可以清晰地讲述他的思路。」

拆开是三层意思：

- **现在缺的不是查询**，查询已经有了（实体、关系、事件、明细行）；
- **缺的是"把查到的组织成自己的理解"**：AI 查完，结果散在对话里，用户脑子里的那张图没有落点；
- **产物要能讲**：图的形态本身就是汇报材料，别人看着图能听懂办案逻辑。

所以这不是"加一个可视化"，而是**给"查"接上一个"结论"**：查询是过程，图是产物。

## 2. 与现有能力的关系

### 2.1 现有的「关系图」是放大镜，不是产物

`packages/app/src/center/case-views/graph.tsx`（1773 行）与 `packages/opencode/src/server/openhive/case-graph.ts`（440 行）已经有一张图，但它是**只读的实体邻域视图**：

| | 现有邻域图 | 本文的关系图产物 |
|---|---|---|
| 数据来源 | 库里实时查出来的 1～2 跳 | 一份文件 |
| 谁决定画什么 | SQL（以某实体为中心，上限 50，`case-graph.ts:94`） | 人 + AI 主动挑选 |
| 能不能改 | 只读，换中心 = 换一张图 | 可增删改，位置留得住 |
| 是不是产物 | 不是，关了就没 | 是，落项目文件树，可备份、可导出 |
| 出处 | 天然有（就是库里那条边） | 要设计：哪些有出处、哪些是推断 |

**结论：两者并存，互不改动。** 邻域图继续做"看一圈"，新图做"讲一件事"。邻域图的四套布局算法（`自动位置`，`graph.tsx:219`）直接复用，不另写。

### 2.2 AI 手上已有什么

`case-mcp-server.ts` 已注册：`query_entities` / `query_relations` / `query_events` / `get_citation`。其中 `query_relations(实体=…)` 就是"拉一圈"（`case-mcp-tools.ts:273-306`），`get_citation` 支持 `entity` / `relation` / `event` / `row` 四类事实。

所以"把张三这一圈加到我的图里"不需要新按钮——AI 用现有查询拿到邻域，再用本文新增的 `graph_add` 一次画上去。

### 2.3 视图注册表只认最后一个点

`view-registry.ts:73-92` 的 `extensionOf` 语义对齐 `path.extname`：取 basename 最后一个点之后。故：

- `.graph.json` ⇒ 扩展名是 `.json`，会被 JSON 的视图（若有）抢走；
- 必须有自己的后缀 ⇒ **`.hgraph`**，内容是 JSON。

## 3. 决定一：文件是唯一真相

### 3.1 三个方案

| 方案 | 真相在哪 | 好处 | 为什么不选 |
|---|---|---|---|
| **文件为真相**（采纳） | `.hgraph` 文件 | 产物可直接交付、备份、归档；AI 与人共用一条写路径 | — |
| 库里建表，文件只是导出 | `case_graph` 表 | 可查询、可做权限 | 一份数据两处存，读者分流时没有任何单项断言看得出来（`#007-02`）；"AI 改库"与"人拖文件"必然打架 |
| 双写 | 两边 | 看似兼容 | 同上，且多一套同步逻辑要维护 |

### 3.2 自包含

绑库的节点/边，把**当时看到的**抄进文件：

- 节点：值、库类型、细类、可信态、属性（开户行/卡号/证件号…）、**首末时间**、出处；
- 边：次数、金额、**方向**、**首末时间**、**证据**（每笔关系与它的出处成对，§4.2 规则 5）、关系 id 列表；
- 同时保留库 id，用于"跳回实体详情"。

理由：实体会被改名、被合并、被排除；**产物不能随库漂**。半年后打开这张图，它必须还是当时那张。

### 3.3 单向

库 → 图，只能单向。图上加的东西**不**变库里的实体或关系。想知道"这条线索为什么在图上"，答案在图文件自己的出处与依据里。

> **键名与取值词表**（2026-11-15）：key 一律中文（`格式/标题/节点/边/文字/来源/出处/证据/时间/方向/可信度/出现序/链接/设置`）；`来源.kind` 取值 `实体 / 关系 / 推断 / 手写`；`性质` 取值 `事实 / 推断`；`方向` 取值 `有向 / 无向`；`可信度` 取值 `高 / 中 / 低`；`金额` 为 `{ 值, 单位 }`，`值` 用字符串避免浮点，负数表示流出。新加字段照此惯例，不要混入 `source` / `type` 这类英文 key。

### 4.2 九条钉死的规则

1. **`id` 文件内唯一、永不变，由服务端分配。** 节点的 `id` 是 `n1`，不是库 id；库 id 放在 `来源.实体`，可以没有。实体被合并/删除时图不崩，只是"跳转"失效并提示。**AI 与前端只给临时 id**，写入时由服务端换成正式 id 并返回映射（§6.2）——自增 id 在多端/并发下必然撞。
2. **每个节点/边必须能回答"凭什么在图上"。** `来源.kind` 四值：`实体` / `关系` / `推断` / `手写`。边的 `性质` 两值：`事实`（实线）/ `推断`（虚线）。
   **语义边界**：「事实」= **有行级出处**，**不等于内容为真**——材料本身可能记错、可能是伪造的。所以实线只承诺"可追溯到某一行"，不承诺"这一行说的是真的"。
3. **出处是行级的**：`材料#工作表#行号`，与 `case_citation` 同形（`case-store.ts:423-432`：工作表名可含 `#`，按首末 `#` 解析）。**解析必须照抄现有实现，不在前端另写一份**（材料名同样可能含 `#`，两处各写一份必然分叉）。
   连续行合并写区间（`mat_x#Sheet1#12-13`）；超过 50 行时只存首末区间，明细回材料查——逐行存会一张话单把文件撑到 MB 级（§13.3）。
4. **坐标落盘**：`x` / `y` 是图的一部分，**`dragend` 才存**（§6.1），拖动过程中的中间坐标不落盘。
5. **证据与关系成对。** `证据: [{ 关系, 出处 }]`，沿用 `出处` 作汇总。禁止用两个平行数组（`关系们` 与 `出处` 各排各的）——那样"这 1.2 万是哪笔"就答不上来，而 §3.3 已定图不写回库，这里是**唯一能回答的地方**。
6. **`可信度` 是推断的必备项**：`高 / 中 / 低`。没有它，「事实/推断」二值会被读成"真/假"——事实只等于有出处（规则 2），推断的可靠程度必须单独说。来源可靠度评级（A1–F6 这类）后置，字段留在此处扩展。
7. **`方向` 必须显式**：`有向`（画箭头）/ `无向`（不画）。**A→B 与 B→A 是两个不同的有向边，永不合并**；同一对节点间的双向资金往来存两条边，画成带偏移的平行边、各自标金额。把 A→B 与 B→A 合成一条无向线，等于把资金流向判反。
8. **`时间` 抄进文件**：节点与边各记 `{ 首, 末 }`，来源是库里的首末时间（检查器已在显示，抄进来近乎零成本），手写节点可空。**这是产物自包含原则的直接后果**——§3.2 不许回库补数据，现在不抄，将来做时序分析就得推倒所有已有图。
9. **`出现序` 与 `链接` 先留字段**：`出现序` 给演示模式分步揭示用，可空；`链接` 指向另一张图的某个节点（总图 → 细节图），可空。第一版不建界面，只保证写入不被丢弃。

### 4.3 类型是开放词表，不是枚举

初稿写死七类（人/账户/号码/公司/车辆/地址/其他），被用户当场否掉：i2 的常用类型有二十来类（车辆、电信、犯罪、活动、资金、军事、人员、商品、社交媒体、网络犯罪、位置、文档、武器、医疗、组织、其他…），实际办案远不止七个。

改定：

- `类型` 存**字面字符串**，读取时**不校验白名单**；
- 认识的类型给专属颜色/形状；不认识的用默认形状 + 名字照显示，**不报错、不丢节点**；
- 第一版内置一套基础类型；**类型导入后置**，但字段现在就留好：`类型` + 可选 `样式: { 颜色, 形状 }`（节点级显式覆盖）。**老图观感不变靠下一条"类型表只增不改"保证，不靠这个可选快照**；
- 库实体大类（人/账户/号码/公司）与图上类型（犯罪/电信/社交媒体）**不是一套**。绑库节点两个都存（`来源.库类型` + 外层 `类型`），加入时按映射表给初值，用户改了就按用户的。
- i2 的类型**名称**是通用词，可照用；**图标是商业资产**，不抄，用自有形状与颜色。
- **类型表只增不改**（2026-11-15）：已发布类型的颜色与形状**永不修改**，新观感就新增一个类型。`样式` 只是节点级的显式覆盖，**不是稳定性的依赖**——只靠"可选快照"保证不了老图不变（没写 `样式` 的节点会跟着类型表走），靠"不改已发布类型"才保证得了。

### 4.4 版本与兼容

- `格式: 1`。将来不兼容的改动加一，读到更高版本**只读打开**并提示"请升级"；
- 未知字段**保留原样写回**，不许静默丢弃（AI 或新版本写入的字段，旧版本不能吃掉）。**实现要求**：解析保留**原始 JSON 树**，只在已知字段上读写，序列化时把未知字段原样贴回；**禁止**解析成类型化对象再整体序列化——那条路必然丢字段，而且不会报错（§11 第 3 条据此约束 `hgraph/file.ts`）。

## 5. 决定三：图上的手动操作

判据：**民警用鼠标能不能把脑子里那张图完整画出来，并且画错能收回。**

### 5.1 工具栏与控制

- 全图标，悬停 300ms 出文字说明，说明里**带快捷键**（「删除（Delete）」「撤销（Ctrl+Z）」）；
- 图标复用 `graph-icons.tsx`，不新画一套；
- 分四组，分隔线隔开：**选择｜画**（指针、连线、加节点、文字）、**排**（对齐、等距、自动布局）、**找**（搜索、隔离、查找路径、从库加入）、**整**（缩放适配、演示、导出、撤销重做）。

### 5.2 连线是一个模式，不是一次拖拽

初稿把"拖到另一个节点上松手 = 连线"与"拖动摆位"放在同一次拖拽里，用户当场指出会打架。改定：

- 工具栏两个模式：**指针** / **连线**；
- 连线模式下，在节点上按下并拖动，有一根线跟随鼠标，落到另一个节点上松手即成边，落到空白处不成边；
- 指针模式下拖动只移动，永远不建边；
- 双击空白 = 新增节点（指针模式），与工具栏「加节点」等价。

### 5.3 选区与多选

- **Shift + 点击**：加入/移出选中；
- **框选**：指针模式在空白处拖出选框；按住 `Shift` 框选 = 追加，不按 = 替换；
- **高亮**：选中节点描边加粗 + 外圈光晕；选中边加粗提亮；检查器顶部显示「已选 N 个」；
- 点空白 / `Esc` 取消；
- 多选后可做：整体拖动、对齐、等距、删除；选中 ≥2 个节点还可**合并为一个**（§5.12）。

### 5.4 对齐与等距

- 选中 ≥2 才亮：左 / 水平居中 / 右 / 顶 / 垂直居中 / 底；
- 以**选中范围的边界**为准（最外侧那个不动）；
- 选中 ≥3 才亮：水平等距 / 垂直等距，两端不动、中间均分；
- 每一步进撤销栈。

### 5.5 自由文字

用户要的不是节点标签，是**能在图上写话并排版**：

- 「文字」按钮 → 点画布落一个文本框，直接敲；
- 可排版：字号（小/中/大）、加粗、颜色（预设色）、对齐（左/中/右）、框宽可拖、自动换行；
- 可拖动、可删除、可撤销，导出 PNG 时一起导出；
- **不做**：斜体/下划线/字体族/旋转/从 Word 粘贴富文本。中文办案记录用不上，加了只会让人把图当文档写。

### 5.6 视觉的两个独立通道

| 通道 | 表达什么 | 默认怎么算 |
|---|---|---|
| **边的粗细** | 这一条关系有多强 | 按关系类型选度量：资金类按金额，通信类按次数，其他按次数 |
| **节点的外环粗细** | 这个节点在图上的分量 | 按它在图上的连接条数，4 档 |

**为什么强弱不能跨类型比**：转账比次数没意义（一笔 50 万 vs 五十笔 1 万），话单比金额更是胡说。所以度量按关系类型定。

**为什么用固定阈值而不是分位数**：分位数会让"每加一条边，全图粗细重排"，同一张图今天讲和明天讲不一样，汇报时会被问住。固定阈值写进 `设置`，改了就固定。

默认档位：

- 次数：1 / 2～4 / 5～9 / 10～49 / 50+
- 金额：1 万以下 / 1～5 万 / 5～20 万 / 20～100 万 / 100 万以上
- 外环：1 条 / 2～3 条 / 4～7 条 / 8 条以上

**手动覆盖**：选中边可设「自动 / 1～5 档」（5 档即加粗强调）；选中节点可设外环档位与颜色（预设色）。覆盖值写文件（`线宽档` / `外环`），没写就按规则自动算。外环颜色默认按类型，手动改色用于"红环 = 重点对象"这类标记。

**手动值冻结**（2026-11-11 用户裁定）：外环一旦被手动设过档位或颜色，就**不再随连接数自动变**。理由：手动动过就是一次"人工判断"，不能被算法悄悄改回去——连接数从 3 涨到 9，用户标的 3 档还得是 3 档。要恢复自动，在检查器里点「恢复自动」，删掉覆盖值。

**方向必须画出来**（2026-11-15）：`方向: 有向` 的边在箭头端画实心箭头，`无向` 不画。资金分析里"谁给谁钱"就是结论本身，一条没箭头的线等于把结论抹掉一半。双向资金往来是**两条有向边**（`§4.2` 规则 7），渲染成同一对节点间带偏移的平行边，各自标金额，标签错开；**禁止**把它们合成一条无向线。同一对节点间的关系种类超过一条（转账 + 通话）时，同一条边的渲染规则：第 k 条边横向偏移 k×8px。

**节点连线多时**（"毛线球"）三层叠加：

1. **弱线淡化**：1～2 档的边降低不透明度，强边自然跳出来；
2. **强度过滤**：工具栏档位滑块「只看 ≥3 档」，隐藏弱边，画布角落明说「已隐藏 12 条较弱关系」——**不能悄悄藏**；
3. **外环加粗**：一圈细边汇到一个粗环上，"这个人是核心"一眼看得出。

**不做边捆绑**（多条线拧成一股）：好看但难解释，民警讲图时说不清"这一股到底几条"。

**图例常驻（可折叠）**，两组刻度分开画：「线粗 = 关系强弱」「环粗 = 连接多少」，另标「实线 = 事实 / 虚线 = 推断」；右边再补一条「箭头 = 方向」。小画布上图例挡内容，折叠成一个小图标。

### 5.7 检查器：点节点后显示什么、显示在哪

#### 5.7.1 位置与形态

- **右侧浮动面板，宽 320px，不改变画布尺寸**。图的坐标是固定逻辑坐标（viewBox），画布宽度一变缩放比就变、所有节点会跳；浮层不碰画布，图形纹丝不动。
- 沿用邻域图的观感（`graph.tsx` 的 `面板宽 = 280`、`面板边距 = 24`），只是加宽到 320 放得下属性表。
- **不挡被选中的节点**：选中节点中心若落在面板覆盖区，画布自动向左平移一小段，保证"点了它就能看见它"。

#### 5.7.2 内容：三段竖排 + 底部一条

```
┌──────────────────────────────┐
│ ● 张三              [事实] × │   ← 类型色圆点 + 名称 + 状态徽标
│ 人 · 嫌疑人                   │
├──────────────────────────────┤
│ 图上记的                      │
│  开户行   招商银行  [材料3#1] │   ← 属性：键值 + 出处标签（可点）
│  银行卡号 6214…     [材料3#1] │
│  备注  ┌──────────────────┐  │   ← 可编辑，失焦即存，算一步撤销
│        │ 推测为司机        │  │
│        └──────────────────┘  │
├──────────────────────────────┤
│ 库里现在            [查看 ▾] │   ← 默认收起，点了才查
│  关联 12 · 金额合计 86 万      │
│  首次 2026-01-03 末次 2026-05-11│
│  · 转账 → 李四  3 次 / 1.2 万  │   ← 点一条，图上高亮对应边
│  · 通话 → 王五  18 次          │
│  库中还有 5 条关系未上图       │
├──────────────────────────────┤
│ [打开档案]                    │   ← 未绑库时灰显不可点
└──────────────────────────────┘
```

- **头段**：类型色圆点、名称、类型 · 细类、状态徽标（事实/推断/手写；绑库的再带库可信态）。
- **「图上记的」**（来自文件，稳定不变）：一律 `键 —— 值` 两列。属性每条后挂**出处小标签**，点它跳到材料那一行；库里没有属性时明写「库中无记录属性」，不空着让人猜。备注是可直接编辑的文本域，失焦即存，算一步撤销。
- **「库里现在」默认收起**：不点不查，避免每选一次节点就打一次库。展开后先给三个数字（关联数、金额合计、首末时间），再列最多 5 条关系（点一条高亮对应边），最后一句「库中还有 N 条关系未上图」——只报数量，要加请让 AI 加。
- **底部「打开档案」**：见 §5.7.4。

#### 5.7.2.1 哪些能改、哪些不能改

按**信息来源**划一刀，不能凭手感：

| 字段 | 能不能在面板改 | 口径 |
|---|---|---|
| 名称、类型、细类 | **能**，失焦即存 | 图上这张卡怎么叫、算哪类，画图人说了算 |
| 外环档位、外环颜色 | **能**，选完即生效 | "人工标记重点"的通道 |
| 备注 | **能**，失焦即存 | 用户自己的批注 |
| **属性**（开户行 / 卡号 / 证件号…） | **不能** | 它们是从库里抄来的快照。图上改了库里没改，就成了"文件说招商银行、库说建设银行"，还查不出谁先改的。要改去实体详情页改库，回来点「刷新此节点」 |
| 可信态、出处 | **不能** | 出处只能由"从库加入"或 AI 带出处产生；手工节点就是「手写 / 推断」，不出处 |

**手写/推断节点的出口（2026-11-15）**：上表把「属性」与「出处」锁成只读，但如果用户后来在档案里查到了证据，得有一条升级路——检查器新增「**绑定到库实体**」：打开 §7 的选择器选一个库实体，绑定后 `来源` 改为 `实体`、出处取 `get_citation`、属性转为只读快照、状态徽标从「手写/推断」变「事实」。不绑定则保持原状。没有这个入口，「事实」就是一道只能降不能升的单向门，面板上会留下一个用户点不进去的死角。

**类型框是"可输入的下拉"**：下拉列内置类型，但允许直接打字写新的——对应 §4.3 的开放词表，不会因为词表里没有就卡住人。

**没有「保存」按钮**：名称、备注失焦即存；类型、颜色、档位点选即存。存成功图上立刻重绘；存失败**把那个字段回滚到改前**并在面板里报「没存上」——界面不能显示一个其实没存进去的值。每一次改动都算一步撤销。

#### 5.7.3 收起与展开

- 收起不是消失，而是缩成右侧一条 **40px 窄条**，竖排「详情」二字 + 一个类型色圆点（表示当前选中是什么）。
- 展开方式两种：**点窄条** 或 **快捷键 `I`** 切换。
- **不做「再点节点就自动展开」**：有人习惯反复点各个节点，自动弹面板会让人反感（2026-11-11 用户裁定）。面板收起是上一刻的状态，不因下一次点击被强行推翻。
- `Esc` / 点空白 = **取消选中**并收起面板，不记为"用户把面板关了"。

#### 5.7.4 「打开档案」按钮

- 绑库节点：按钮可点，打开实体档案标签页（`case://<项目>/entity/<id>`，`entity-profile.tsx`）。
- 未绑库节点：**按钮灰显、不可激活**，旁边一行小字「这条不在库里」。
- **双击 = 重命名**（2026-11-15 改）：双击节点进入名称内联编辑，与检查器名称框走同一条路径。双击=重命名是画图与文件管理的通用肌肉记忆（Figma / Office / 文件树），双击却跳页会很恼人。打开档案 = 点「打开档案」按钮，或 `Alt + 双击`。
- 为什么不做成"点节点即开档案页"：看图时十次点击有八九次是"确认一下这是什么"，要的是瞬时、不离开图；每次点击都切走页面，讲图讲到一半就得来回切标签，听众的注意力会断。深挖才走档案页，浮层给"够看"的摘要。

#### 5.7.5 特殊情形

| 情形 | 面板怎么变 |
|---|---|
| **多选**（≥2） | 换成「已选 3 个」+ 对齐 / 等距 / 删除，不显示单个详情 |
| **选中边** | 同一个面板换成边的信息：标签、性质、方向、次数、金额、两端节点、证据与出处、**备注（可编辑）**；同样分「图上记的 / 库里现在」。可改：标签、性质、方向、备注、线宽档；只读：次数、金额、证据、出处。**没有出处的边不许改成「事实」**——与 AI 工具走同一条硬闸（§6.3），提示"补出处，或保持推断" |
| **点空白 / `Esc`** | 取消选中，面板收起 |

明确不做：模态弹窗（挡住图，讲图时最忌讳）；并排挤开画布的双栏（坐标会跳）；把详情做成新标签页（看个节点就跳走，回不来）。

### 5.8 撤销

- `Ctrl+Z` 撤回最近 20 步，`Ctrl+Shift+Z` 重做；
- 新增、删除、连线、改字、移动、对齐、自动布局、合并节点，各算一步；
- **AI 的一整批变更也算一步**（见 §6.5）。这里的「一批」按**批次号**算，不按工具调用次数算（§6.2）——一张 200 节点的图分 4 次调用写入，用户也只按一次 `Ctrl+Z`；
- **实现按逆操作 + 被删对象副本**，不按整图快照：1000 节点 × 20 步的整图快照，内存与序列化开销都不可接受；更糟的是"撤销"会退化成"整份覆盖"，绕过出处闸（§6.3）；
- **外部重载后撤销栈必须清空**（2026-11-15）：409 冲突重载、10 秒轮询静默重载、外部改动重载——任一种发生后，旧撤销栈里的逆操作都基于旧版本，按下去会把旧内容写回、覆盖掉刚拉进来的改动。清栈并在界面上说一句「图已重新载入，撤销记录已清空」；
- **移动只在 `dragend` 记一步**，拖动过程中的中间坐标既不进栈也不落盘（§6.1、§6.7）；
- 撤销栈**按标签页独立**，切换标签页不串。

### 5.9 自动布局

- 力导向 / 环形 / 分层 / 网格，复用 `graph.tsx` 的 `自动位置`（`:219`）；
- 新图没有"中心/跳数"，映射成大图时按 BFS 分层、度数最高者为临时中心；
- 自动布局会覆盖手动摆位，**必须弹确认**，且这次操作可撤销；**锁定的节点不动**（§5.13）。

### 5.10 规模

- 不设硬上限；
- >300 节点提示「这张图已经偏大，建议拆成多张」；
- >1000 节点只提示性能风险，**不拦、不截断**——截断一张图等于骗人。
- **"提示了但用不了"等于拦**（2026-11-15）：给渲染降级规则，而不是只给提示——
  - 拖动/缩放进行中：隐藏标签、边简化描边，松手 200ms 后恢复（静止帧必须完整）；
  - >800 节点：默认关闭标签，只显示选中与悬停邻居的标签，工具栏可强制打开；
  - 判据：1000 节点下拖动帧率 < 30fps，这一版视为未达标，实现报告里如实写，并记录"何时该换 canvas/WebGL"。第一版不做 WebGL，但**判据要留**，否则"只提示不拦"会变成事实上的不支持和无人负责。

#### 5.11.1 只有「可新建」的类型才进列表

**能打开 ≠ 能新建。** 系统能打开 Word / Excel / PDF / 图片 / 思维导图，但**空文件打不开**——新建一个 0 字节的 `.docx`，双击得到的是"文件已损坏"。格式本身要求完整包结构，这不是实现偷懒。

第一版只列四类（2026-11-11 用户裁定）：

| 类型 | 后缀 | 初始内容 |
|---|---|---|
| 关系图 | `.hgraph` | 预置 §4.1 的空图骨架（`格式/标题/节点/边/文字`） |
| Markdown 文档 | `.md` | 空 |
| 文本文件 | `.txt` | 空 |
| 表格 | `.csv` | 空（首行留空，打开即空表） |

不列 Word / Excel / PDF / 图片 / 思维导图（空文件不合法），也不列代码类（民警不会在案卷里新建 `.ts`）。**后期要加再加**，列表做成数据驱动，加一项不改界面。

#### 5.11.2 名称与后缀

用户只写名字，后缀由类型决定，提交时自动补。三种输入都要顺畅：

| 用户输入 | 选择的类型 | 结果 |
|---|---|---|
| `张三资金流向` | 关系图 | `张三资金流向.hgraph` |
| `张三.hgraph` | 关系图 | `张三.hgraph`，**不重复加** |
| `张三.md` | 关系图 | 输入框里已知后缀自动把类型胶囊**切到 Markdown**，并提示「已按输入的后缀切换类型」——不报错 |

判后缀用 `path.extname` 语义（取最后一个点之后，`view-registry.ts:73-92` 同一份规则）；`3.5万流水` 这种名字点不在末尾且尾巴不是已知后缀，就当名字，不切。

#### 5.11.3 空骨架怎么落地（2026-11-12 定）

现有创建接口只会造**空文件**（`file.ts:1077`「造一个空文件或空目录」），不会预置内容。三条路里选第三条：

| 方案 | 问题 |
|---|---|
| 改通用 create 支持初始内容 | 动核心文件写接口，为一个小功能扩大改动面 |
| 前端 create 后直接写内容 | 多一条写路径，违反 §6.1 |
| **✅ create 后立即调 `POST /openhive/hgraph/init`** | 由 `hgraph-ops` 写骨架（校验文件为空才写），写路径仍唯一 |

`/openhive/hgraph/init` 的行为：文件存在且为 0 字节 ⇒ 写 §4.1 空骨架（`格式:1` + 标题取文件名 + 空 `节点/边/文字` + 默认 `设置`）；文件非空 ⇒ 不覆盖，直接返回现有内容（幂等，重复点"新建"不会清掉图）。

新建文件夹不弹类型选择，行为不变。

### 5.12 合并节点【第一版】· 拆分【后置】

§5 开头的判据是「画错能收回」，而 §3.2 自己承认实体会被合并——图上同样会长出两个"张三"（一个从库加、一个手写，或者名字不同但其实是同一人）。没有合并，用户只能删一个重画，**边、备注、外环标记、出现序全丢**，这恰恰是收不回。

- **合并**：选中 ≥2 个节点 →「合并为一个」。指定保留哪个 `id`，其余节点的边端点重指向保留者；重指后若与已有边重复，**保留两条并偏移**，不自动去重（自动去重会把两笔钱悄悄加在一起）；`出处` / `证据` 取并集；`备注` 拼接并加分隔；`属性` 冲突以保留者为准、另一侧并入备注；`来源` 标 `合并`，被并入的实体 id 记进 `来源.并入` 供追溯；整次算一步撤销。
- **拆分【后置，第一版不做】**：触发条件见 §0.1.3（"合并错了 / 一个节点其实是两个人"出现 ≥3 次）。将来做也只做最小版——「把选中的边拆到新节点上」，属性拆分不做。
- 合并只改文件，**不改库**（§3.3）；绑定关系以保留者的 `来源.实体` 为准，不做双绑。

### 5.13 复制、粘贴与锁定【第一版】

- `Ctrl+C` / `Ctrl+V`：复制选中节点与**两端都在选区内的边**；粘贴偏移 24px、id 全部重新分配、名称追加「副本」后缀，整次可撤销。
- `Ctrl+D` 原地复制；`Alt + 拖` 拖出一份副本。
- **锁定位置**：节点可锁定。锁定的节点：自动布局不动它、框选拖动不动它；对齐/等距这类显式命令仍然生效；解锁恢复。理由：§5.9 只弹一次确认，挡不住"用户精心摆好的骨架被一次布局冲掉"。

### 5.14 右键菜单【第一版】

工具栏与检查器之外的高频入口，避免"先精确点中、再切面板"：

| 右键位置 | 菜单项 |
|---|---|
| 节点 | 重命名 · 打开档案（未绑库灰显）· 复制 · 锁定/解锁 · 只看邻居 · 合并所选 · 删除 |
| 边 | 改标签 · 改性质 · 删除 |
| 文字 | 编辑 · 复制 · 删除 |
| 空白 | 加节点 · 粘贴 · 自动布局 · 适配全部 · 查找路径 |

菜单项与工具栏/检查器调**同一个动作函数**，不各写一套——同一件事只有一个出口（§6.3 同族）。

### 5.15 视口、导航与查找路径【第一版】

- **缩放**：滚轮；**平移**：空格 + 拖 / 中键拖 / 双指；**适配**：工具栏「适配全部」「适配选中」，`Ctrl+0` 适配全部。
- **回退视角**：`Alt+←` 回上一个视角（讲图时点错地方能回来），最多 20 个。
- 双击空白**保持"加节点"**（§5.2 已定），不做"双击空白=适配"——两者冲突，以已定为准。
- **搜索定位**：画布左上搜索框，按名称匹配，`Enter` 居中选中，`↑/↓` 在结果间跳。
- **隔离**：选中节点 →「只看邻居」（1 跳，可再点扩展）；画布角落明说「已隐藏 N 个节点」并提供「退出隔离」——与 §5.6 的强度过滤同一口径，**不能悄悄藏**。
- **查找路径**：选两个节点 →「查找路径」，本地 BFS 求最短路径并高亮，面板列出跳数与途经节点。**这是本地图算法，不走 AI**：AI 侧没有路径工具，`graph_read` 返回全量图，大图塞不进上下文——图一大，"这两人怎么联系上的"AI 答不了、人工也没有工具，两条路会同时断。第一版必须有。（AI 侧路径工具列入 §0.1.3 后置，触发条件＝前端查找路径不够用。）
- **筛选**：按类型 / 性质（事实/推断）/ 度量（≥N 档）过滤，与隔离共用同一个"已隐藏 N 个"口径。

### 5.16 标签与可读性【第一版】

300 节点以上"用不了"的头号原因是标签互相遮挡，不是渲染慢。规则：

- **按缩放级别显隐（LOD）**：缩放 < 60% 只显示外环 3 档以上节点的标签；< 30% 全隐；选中与悬停永远显示。
- **重叠取舍**：按优先级保留——选中 > 悬停 > 外环档高 > 度数高；被压掉的不画。不做避让连线（大图上比遮挡更乱）。
- **截断**：超过 12 字符截断加省略号，悬停出全文；检查器里永远是全文。
- **边标签**：默认缩放 ≥ 80% 才显示；强度过滤开启时只显示未隐藏的。
- 运动帧与静止帧分开：拖动/缩放过程中按 §5.10 降级，松手恢复。

## 6. 决定四：AI 怎么改图

### 6.1 不整份重写

AI 若整份重写文件，用户正在拖的节点坐标会被覆盖，而且没人会发现坐标变了。所以**一切都走"操作"**：

```
读最新文件 → 应用这一小批操作 → 校验 → 原子写回（临时文件 + rename）
```

人拖坐标、AI 加节点，都是同一个入口，只是操作不同。两者不相交，因此不会互相覆盖。

**服务端按路径串行化**（进程内一把锁），同一张图不并发写。

**写路径唯一（2026-11-12 定）**：前端拖拽、改字段、AI 工具——**全部**调 `hgraph-ops` 的操作与保存接口，**前端不直接调通用文件写接口**。否则人一条路、AI 一条路，串行锁只锁住一半（`#007-02` 的形态）。前端 `hgraph/file.ts` 只承担**解析与 schema 校验**（读回、预览、测试用），它不是写入者。

**版本 CAS（防止互相覆盖）**：每次读返回 `版本`。**版本 = 文件内容哈希**（`Bun.hash` 或 SHA-256 取前 16 字节），**不是** `<mtimeMs>:<size>`——同毫秒内两次写入且大小不变（例如两个字段值互换）时 `mtime + size` 会给出同一个版本，覆盖就漏过去了（2026-11-15 改）。10 秒轮询仍然只 `stat`，`mtime/size` 变了才读内容算哈希。保存时客户端带上「我基于哪个版本」；服务端发现当前版本已变 ⇒ **409 拒绝**，返回最新版本，由前端按 §6.7 问用户「重新载入？」——不替用户选、不静默合并。

**拖动不逐帧落盘**（2026-11-15）：拖动期间只改本地坐标，**`dragend` 才发一次**保存。原「每次操作即时发出（防抖 500ms）」在拖拽下会产出几十次中间写入，放大版本 churn 与 409 概率，还把磁盘写入变成了动画的一部分。

### 6.2 五个工具

| 工具 | 入参要点 | 干什么 |
|---|---|---|
| `graph_list` | — | 列出本项目所有图：路径、标题、节点数、更新时间 |
| `graph_read` | 路径 | 读节点与边（含出处），改前先看 |
| `graph_add` | 路径 + 一批节点/边 | 批量新增（**单次 ≤50**，超出拒绝并建议分批） |
| `graph_update` | 路径 + 目标 id + 字段 | 改名称/类型/标签/备注/性质/位置 |
| `graph_remove` | 路径 + 目标 id | 删节点或边，返回连带删掉的条数 |

**共 5 个**（`09` §1.1 末尾的反证段也按 5 个计）。路径必须：落在项目目录内、后缀 `.hgraph`。校验复用现有路径闸（`file.ts` 的归属与穿越判定）。

**五条的协议细则（2026-11-15 补）**：

- **id 由服务端分配**：AI 只给临时 id（如 `"tmp1"`），服务端写入时换成正式 id，并在返回里给映射表；前端手工新建同理。自增 id 在多端/并发下必然撞。
- **批量原子**：`graph_add` 的一批**要么全写要么全不写**——先全量校验、再一次性写；第 30 条不合格时不许留下前 29 条。`graph_remove` 删节点时连带的边算**同一步**，不再单独计。
- **批次与幂等**：入参可带 `批次`（AI 同一任务填同一个值）与 `幂等键`。同批次的多批写入在前端**合并为一步撤销**（§5.8）；同幂等键重复调用返回上次结果、不重复写入（重试安全）——否则 AI 一次超时重试就会把节点加两遍，而「同名同类型复用」挡不住不同名、推断节点和边。
- **新节点摆放**：做**增量放置**——新节点放在其邻居外圈的空位上并避让已有节点；无邻居则放在当前视口中心附近的空位。禁止放在 `(0,0)` 或随机点：AI 加的节点叠成一坨，用户第一眼就不再信任这张图。
- **路径闸**：除"落在项目目录内 + `.hgraph`"外，还要求**先 `realpath` 再判归属**（junction/symlink 逃逸，`LEARNINGS #009-03`），后缀判定先小写归一（Windows 大小写不敏感）。

**不套用 `09` 的七字段信封**：`09` 的信封只要求**查库**工具（§0 第 5 条、§3.1 明写「现有 7 + 新增 4」，图写入不在内），因为图写入属「改文件」通道（`09` §0 第 5 条、§11 已声明不并入查库）。这 5 个工具返回自己的结构（路径 / 复用说明 / 删除条数 / 错误话术）；失败一律 `isError`，不伪装成功。

### 6.3 出处是硬闸

**任何写入路径**（`graph_add`、`graph_update`、人手工新建、检查器改性质）收到一条标「事实」的节点或边却没有 `出处`，一律拒绝——**共用同一个校验函数**，不是每个入口各写一遍（2026-11-15 补：原文只写 `graph_add`，模型换个工具就能把推断边改成「事实」，闸就绕过去了）。原文告诉 AI：

> 这条标了事实但没给出处：要么补出处，要么改成推断并写明依据。

这条不写在提示词里求模型自觉——**它必须是代码里的判据**，否则模型换个写法就绕过去了。

同理：`性质: "推断"` 必须同时有 `来源.依据`，空依据也拒绝。

### 6.4 同名复用

AI 加节点时，若图上已有**同名且同类型**的节点，复用它并连到它上面，返回里明说「复用了已有节点 张三」。否则图上会出现两个"张三"，用户还得自己合并。同名不同类型（人张三 / 账户张三）不算重复，新建。

### 6.5 AI 可以删，但可撤销

用户裁定：AI 可以删任何节点（不止自己加的）。

配套两条，不是限制是保护：

1. AI 每次删除**必须回话说明删了什么**（几个节点、哪几条边）；
2. 这一整批删除在前端**算一步可撤销的操作**——`Ctrl+Z` 能整批退回。模型一次删错，用户至少能完整还原。

### 6.6 多张图并行

- 每张 `.hgraph` 一个标签页，可同时开多张；
- AI 工具**必须点名路径**，不做"项目当前图"这种隐式状态（多张并行时它一定猜错）；
- 只有项目里**恰好一张**图时，路径可省略；
- 有多张而 AI 拿不准，调 `graph_list` 列出来问用户，**不许瞎猜往最近改的那张写**。

### 6.7 前端怎么看到 AI 的改动

- 改动即时发出（防抖 500ms），但**拖动只在 `dragend` 发一次**（§6.1）；本地几乎没有"未保存"的东西；
- 页面每 10 秒对一次文件版本（`stat` 出的 `mtime/size` 变了再算内容哈希，见 §6.1），发现变了且本地无未发出改动 → 静默重载；
- 本地刚改完还没发出去、AI 恰好也改了 → 弹「图已被更新，重新载入？」，**不替用户选**；无论选哪一边，**重载后撤销栈清空**（§5.8）；
- 只重载被改的那一张标签页（按路径匹配）。

## 7. 决定五：图与库的衔接

**从库里上图（2026-11-12 改：入口在图视图内）**

原设计写「实体详情页 / 实体面板右键 → 加入关系图」。`07` 已定稿**下架实体页签**、且明确「本轮不给详情页补入口」，面板与详情页都失去入口（`entity-panel.tsx` 的生产接线只有 `workspace-entry.tsx` 一处，页签摘掉即断）。故入口改由本视图自带：

- 图工具栏「**从库加入**」→ 弹出选择器：搜索框（**名称 / 别名**）+ 结果列表（名称、类型、细类、可信态、关联数）+ **多选** →「加入当前图」；
- **搜索口径照服务端能力走**：`GET /openhive/case/entities` 的 `q` 只匹 `canonical_value` 与 `aliases`（`case-entity-list.ts:143-150` 实读），**不匹类型**。故「按类型找」不做成搜索条件，而是把**类型当结果列表的一列 + 前端筛选**——零服务端改动（改那段 SQL 属高频文件，与「最小化上游冲突」相悖）；
- 选择器复用 `entity-api.ts` 的 `list`（字段刚好够这四列：`type` / `subtype` / `trust_state` / `关联数`），该模块 `07` §3.2 已定**不删、不改契约**，不新写后端接口；
- 加入瞬间拍快照：值、类型、细类、可信态、**首末时间**、**出处**（`get_citation` 的 entity 分支，取不到就在节点上写明「未取到出处」，不假装有）；
- 关系同理：选择器可切「关系」页，勾选后加边，带 `证据`（关系与出处成对，§4.2 规则 5）、`方向`、`时间`；
- **「以此为中心展开一圈」仍不做按钮**（§2.2、§10）：一圈由 AI 用 `query_relations` + `graph_add` 代劳，人工只做「挑人/挑关系」。

**快照拿不到时（当前阶段的常态）**：表格来源今天不建实体，属性写入属 `01` P2（`01` §12.1）。所以本阶段能被选中的实体多半来自文本材料，`attrs` 与出处常为空——节点照建，写明「未取到出处」「库中无记录属性」，**不拦、不伪造**。

**从图上回库**

- 点检查器「打开档案」，或 `Alt + 双击` 绑库节点 → 实体详情页（伪路径 `case://<项目>/entity/<id>`，页面仍在）。**这等于给详情页补了一个入口**，与 `07` 不冲突：`07` 只是不恢复"浏览清单"，而这里的入口始终有上下文（从图上某个具体节点进去）。双击本身是重命名（§5.7.4），不跳页。
- 检查器里的出处可点 → 跳到材料那一行。

**库里变了，图不变**

- 打开图时拿节点快照与当前库对一遍：值被改、实体被合并、被排除，都在节点上加角标；
- 点角标能看见差异（「文件里记的是张三，库里现在叫张三丰」），但**文件内容一个字不改**；
- 用户可手动「刷新此节点」把快照更新到最新。

## 8. 决定六：导出图片

- 图文件右键或工具栏「导出 PNG」；
- 导出内容 = 当前画布所见（含图例、文字块、线的粗细与虚实），白底；
- **尺寸两档**（2026-11-15 补）：`屏幕（2 倍像素）` 默认；`A3 打印（300 DPI）`——办案单位把图打出来贴墙是常态，2 倍像素打到 A3 会糊；
- 不做 SVG 导出（第一版），不做 PDF。但**记一条**：SVG 是同时绕开中文字体掉字（§13.5）与保证打印清晰的自然解，等"真的有人提打印需求"时，优先于 PDF；
- **标题块**（2026-11-15 补，第一版）：可选一行标题块（项目名 / 图名 / 导出时间 / 导出人），默认关闭、汇报与归档时打开；
- **`tEXt` 元数据【后置】**：PNG 里写机器可读的同样四项 + 证据附录哈希。等归档流程真的需要机器读再补，不影响第一版；
- 导出的图**不带**交互态（选中高亮、悬停提示）。

### 8.1 授权与留痕（2026-11-12 定，收口 `01` §14.3 Q23）

图里全是明文（`01` §10.1），而导出的 PNG 落到项目目录**之外**，会脱离项目的归属边界。所以导出不是"点一下就下载"：

| 项 | 口径 |
|---|---|
| **谁能导** | 项目成员；路径必须落在本项目目录内、后缀 `.hgraph`（复用统一下载权限与路径闸） |
| **怎么导** | 前端先调 `POST /openhive/hgraph/export`（服务端校验归属 + 留痕 + 记账），返回许可后才渲染下载；**先授权、后出图**，不是先下载再补记 |
| **留痕** | 一条：人 + 项目 + 图路径 + 时间 + 文件名；写内核日志（目前无独立审计表，`01` §13 Q8 的"查询审计"落地时并入同一处） |
| **文件名** | `<项目名>-<图名>-<YYYYMMDD-HHmm>.png`，多张图多次导出不互相覆盖 |
| **界面提示** | 导出后一行「已记录本次导出」——不是解释给用户听，是让"被记录"这件事能被感知（明文前提下这条不能省） |

> **这道闸的定位（2026-11-15 澄清）**：它是**可追溯**，不是**控制**。前端手里本来就有一整张图（它就是本地文件），不调接口直接 canvas 导出、或者截图/打印，都绕得过去。所以 `hgraph/export` 只承诺「归属校验 + 留痕」，不要当成"禁止导出"的技术保证；内核日志是滚动文件、不是持久审计表，轮转后不留——验收 7 只验"留了一条"，不承诺"永久可查"。

**不做的**：不加水印、不加掩码（用户拍板：本项目一律明文）；不做"禁止导出"开关（导出是汇报的刚需，闸口放在"可追溯"而不是"不准"）。

### 8.2 证据附录【第一版】

图的全部价值在出处，而 PNG 把出处抹掉了。归档与汇报需要「图 + 清单」：

- 导出时可选**附一份证据附录**：节点表（名称 / 类型 / 来源 / 出处）与边表（两端 / 标签 / 性质 / 方向 / 次数 / 金额 / 证据），按 `出现序` 排序；
- 附录格式：同名 `.md`，与 PNG 同一次下载、落在同一位置，**不写回项目目录**——写回会变成第二条写路径，破坏 §6.1 的"唯一写入者"；
- **这不是讲稿**：它不解释思路、不写结论，只是把图里已有的数据摊平，与 §0 第 1 条的用户裁定不冲突。

## 9. 出错的时候

| 情形 | 表现 |
|---|---|
| **JSON 解析失败** | 打开即报「这份图打不开，第几个节点缺了什么」，提供「以文本方式打开」；**禁止一切写回**，包括 AI 工具 |
| **保存失败** | 明确报「没存上」，改动留在页面可重试；**绝不假装成功** |
| **文件被外部删除** | 标签页提示「文件已不存在」，**禁止保存**（否则一存就"复活"成空图） |
| **同路径两个标签页** | 复用现有「同路径只开一个 tab」，从根上不产生两份编辑态 |
| **外部编辑器改了文件** | 保存时版本不一致 → 按 §6.7 处理 |
| **写入中断** | 临时文件 + `rename` 原子替换，不留半截文件。**Windows 上目标被占用**（用户在编辑器里开着这个文件）时 `rename` 会 EPERM/EBUSY——重试 3 次（50/150/450ms），仍失败则明说「文件被其他程序占用，没存上」，不静默失败 |
| **0 字节 `.hgraph`** | 打开时视为空骨架，自动调 `/openhive/hgraph/init`（幂等）。不能只靠"新建那一刻调一次"——create 成功、init 失败会留下一个永远打不开的空文件 |
| **外部重载后** | 撤销栈清空并提示（§5.8），否则 `Ctrl+Z` 会把旧版本写回 |

3. 指针模式拖动只移动；连线模式 A 拖到 B 成边，拖到空白不成边；
4. `Ctrl+Z` 能撤 20 步，含 AI 的一整批删除；
5. AI 加节点带出处成功；标"事实"却没出处被工具**拒绝**，错误话术正确；
6. **「从库加入」选择器**能按**名称/别名**搜到库中实体，结果列表按类型**在前端筛选**（类型不是搜索条件，§7），多选加入 → 节点带属性与出处；单击出浮层，「打开档案」可点并跳回实体详情；**未绑库节点该按钮灰显不可点**。⚠️ 取不到时如实显示：库实体本身没有属性/出处时，节点显示「库中无记录属性」/「未取到出处」——**这就是通过**，不得为了验收造假数据（属性写入与表→实体属 P2，本轮不验）；
7. 导出 PNG，画面与画布一致，含图例与文字块；`A3 300 DPI` 档与标题块各实测一次；文件名符合 §8.1（`<项目名>-<图名>-<YYYYMMDD-HHmm>.png`）；文件树右键与工具栏两个入口都走 `POST /openhive/hgraph/export`，**内核日志留一条含人/项目/图路径/时间/文件名**的记录；非项目成员调用该接口被拒；
8. 库里把某实体排除后再开图：节点带角标，**文件字节不变**；
9. 手工把 JSON 改坏 → 打开报错、不覆盖、AI 工具也拒绝写；
10. 图文件随项目一起被备份/拉回；
11. 面板里改名称 / 类型 / 外环颜色 / 档位 → 失焦或点选即存，关闭重开仍在；模拟保存失败时**字段回滚并提示「没存上」**；属性与出处**没有输入框**，只有跳转；手写节点「绑定到库实体」后来源与出处被填上、属性转只读（§5.7.2.1）；
12. **版本 CAS**：两个标签页开同一张图，A 加节点保存成功 → B 再保存被 409 拒绝并提示可选「重新载入」；**选则重载且撤销栈清空，不选则 B 的改动不落盘、A 的不被覆盖**。
13. **合并两个节点**：边端点重指向保留者、备注/出处并入、`Ctrl+Z` 一步完整还原；合并不改库。
14. **双向资金**：A→B 与 B→A 存两条边、画成两条带箭头的平行边，各自金额正确；把两者合成一条无向线判为不合格。
15. **演示模式**：全屏隐藏工具栏与检查器，按空格依 `出现序` 逐步揭示、`Backspace` 回退，`Esc` 退出。
16. **查找路径**：选中两个不相邻节点 → 高亮最短路径并列出跳数与途经节点（本地计算，不调 AI）。
17. **拖动只在 `dragend` 落盘**：一次拖拽只产生一次保存（看服务端写入次数或版本变化次数）。
18. **外部重载后的撤销**：外部改动重载后提示「撤销记录已清空」，且 `Ctrl+Z` 不会把旧内容写回。

## 13. 风险与实现期参数

> 设计层面**已无待拍板事项**（2026-11-11）。以下都是实现时定、或已知会长期存在的风险，不阻塞开工。
>
> **2026-11-12 补充**：实现前审计发现的六处空缺已全部定案，不再列为待拍板——① 人与库的接缝改为图视图内「从库加入」选择器（`07` 下架实体页签后原右键入口不可用，§7）；② 导出授权、留痕、文件名（§8.1）；③ 写路径唯一 + 版本 CAS（§6.1）；④ 空骨架怎么落地（§5.11.3）；⑤ 落点清单补齐真实路径与五处漏项（§11）；⑥ 验收降级与新增加两条（§12）。下面的条目仍是真风险。
>
> **2026-11-15 补充**：第 9–13 条是复审新增的风险。其中与「后置」有关的是第 9 条（演示编号）与第 12 条的第三步（canvas/WebGL），触发条件见 §0.1.3，**不阻塞第一版**；第 10 条（`链接` 只存不跳）与第 13 条（附录阈值）是第一版内的取舍，照做即可。

1. **AI 批量上限 50** 是拍脑袋的第一版值，真实使用后再调。注意它和撤销粒度的关系：一张 200 节点的图会分 4 次调用写入，靠 `批次` 合并成一步撤销（§6.2），**不能靠提高上限来省调用次数**。
2. **属性快照会过期**：库里补了开户行，图上还是旧的，只有角标与「刷新此节点」这条人工路径。是否要做"打开图时自动更新快照"——不做，理由同 §3.2（产物不能自己变）。
3. **图的体积**：出处已按区间压缩（§4.2 规则 3），几百节点的图预计仍在几百 KB 以内；真要大了再考虑出处去重与按需加载。
4. **撤销栈是内存态**：关闭标签页即丢；不做持久化撤销。
5. **导出 PNG 的中文字体**：SVG 转 canvas 时字体不回退会掉字。定下来的顺序：先按当前字体栈导出一次并用真栈截图比对（含中文节点名、金额、图例）；**只要有一个字掉就内联字体**（base64 `@font-face` 写进 SVG），不走 `foreignObject`（跨浏览器与 canvas 兼容性更差）。实测结果写进实现报告，不能只写「已处理」。
6. **类型映射表**（库大类 → 图类型）首版按一对一直译（人→人员、账户→账户、号码→电信、公司/组织→组织，其余落"其他"），真实使用后再调。
7. **多人/多设备**：图放在项目文件树里，天然跟备份走；但两人同时开同一张图不在本设计范围。
8. **自动布局在无中心图上的映射**（BFS 分层 + 度数最高者为临时中心）是实现细节，可能与旧图的观感不同，需实测。
9. **演示编号（后置）是展示态、不入文件**：将来做的时候，要固化只能转成自由文字块；用户若要求"编号永久在图上"，按文字块实现，不改格式。
10. **`链接` 字段第一版只存不跳**（§10）：总图 → 细节图的跳转等真正有多图需求时再做，字段现在只保证不被丢弃。
11. **合并后与库的绑定**以保留者的 `来源.实体` 为准，被并入的实体 id 只记在 `来源.并入` 供追溯，**不做双绑**——双绑会在实体再次被合并时产生两份互相矛盾的来源。
12. **1000 节点渲染未达 30fps 的处理顺序**：先标签降级 → 再边简化 → 最后才考虑 canvas/WebGL。第一版只做前两步；前两步做完仍不达标，如实写进实现报告，不要用"已提示性能风险"结案。
13. **证据附录在超大图上会变慢**：1000 节点 / 数千条出处时，序列化与渲染 `.md` 可能卡住导出。实现时先实测，超过可接受时长（如 3s）就只给计数 + 前若干条明细并注明"完整明细见材料"，具体阈值实现期定。
