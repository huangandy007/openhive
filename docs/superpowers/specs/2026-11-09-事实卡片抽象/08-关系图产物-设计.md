# 关系图产物 · 设计与口径

> **状态**：设计定稿，待实现（2026-11-11）
> **日期**：2026-11-11
> **定位**：回答一件事——**AI 交互的产物为什么是图、图存在哪、谁怎么改、怎么讲给人听。**
> 上游是 `01-事实卡片与数据翻译-设计.md` 的事实卡片层与 §2.3 出处铁律；`05` 管实体属性、`06` 管交易语义，本文管**它们最终被组织成一张图的样子**。
> **结论先行**：**图是一份 `.hgraph` 文件，文件是唯一真相，库里不建图表。** 节点和边分「事实」与「推断」两态；每条必须能回答"凭什么在图上"；AI 与人都通过同一套「操作」写入，不整份覆盖。
> **过程**：本文按讨论顺序组织，含三处被用户当场纠正的初稿：类型词表写死、移动与连线抢同一次拖拽、AI 删除权限。

## 0. 一页结论

1. **产物就是图本身**，不配讲稿。讲稿用户自己另记（2026-11-11 用户裁定）。
2. **文件是唯一真相**：一张图 = 一个 `.hgraph` 文件，库只供料，不建图表、不双写（`LEARNINGS #007-02`：一份数据两处存，两处一起写没有任何单项断言看得出来）。
3. **图必须自包含**：绑库节点把值、类型、可信态、属性、出处抄进文件；库里改了什么，图不变，只加角标提示。
4. **混合口径**：节点/边分「事实」与「推断」，事实必须带行级出处，推断必须写依据。AI 想标事实却没有出处，**工具直接拒绝**。
5. **AI 不整份重写文件**，只提交操作：读最新 → 应用 → 校验 → 原子写回。人拖坐标与 AI 加节点因此不相交。
6. **多张图并行**：每张图一个标签页，撤销栈各算各的，AI 工具必须点名路径。
7. **视觉用两个独立通道**：边粗 = 关系强弱（金额/次数），节点外环粗 = 该节点在图上的分量（连接数）；都可手动覆盖。
8. **图不写回库**，单向。这条写进"不做"，防止以后有人顺手做双向同步。

## 1. 问题是什么

用户的原话：

> 「日常工作中，用户是通过对信息的了解、梳理获取清晰的关系信息，理清思路。我们前期所做的是让 AI 能够查询……交互后要形成产物，这个产物的形态我希望是关系图。这个过程就是案件侦破推进的过程。最后通过关系图用户可以清晰地讲述他的思路。」

拆开是三层意思：

- **现在缺的不是查询**，查询已经有了（实体、关系、事件、明细行）；
- **缺的是"把查到的组织成自己的理解"**：AI 查完，结果散在对话里，用户脑子里的那张图没有落点；
- **产物要能讲**：图的形态本身就是汇报材料，别人看着图能听懂办案逻辑。

所以这不是"加一个可视化"，而是**给"查"接上一个"结论"**：查询是过程，图是产物。

## 2. 与现有能力的关系

### 2.1 现有的「关系图」是放大镜，不是产物

`packages/app/src/center/case-views/graph.tsx`（1773 行）与 `packages/opencode/src/server/openhive/case-graph.ts`（440 行）已经有一张图，但它是**只读的实体邻域视图**：

| | 现有邻域图 | 本文的关系图产物 |
|---|---|---|
| 数据来源 | 库里实时查出来的 1～2 跳 | 一份文件 |
| 谁决定画什么 | SQL（以某实体为中心，上限 50，`case-graph.ts:94`） | 人 + AI 主动挑选 |
| 能不能改 | 只读，换中心 = 换一张图 | 可增删改，位置留得住 |
| 是不是产物 | 不是，关了就没 | 是，落项目文件树，可备份、可导出 |
| 出处 | 天然有（就是库里那条边） | 要设计：哪些有出处、哪些是推断 |

**结论：两者并存，互不改动。** 邻域图继续做"看一圈"，新图做"讲一件事"。邻域图的四套布局算法（`自动位置`，`graph.tsx:219`）直接复用，不另写。

### 2.2 AI 手上已有什么

`case-mcp-server.ts` 已注册：`query_entities` / `query_relations` / `query_events` / `get_citation`。其中 `query_relations(实体=…)` 就是"拉一圈"（`case-mcp-tools.ts:273-306`），`get_citation` 支持 `entity` / `relation` / `event` / `row` 四类事实。

所以"把张三这一圈加到我的图里"不需要新按钮——AI 用现有查询拿到邻域，再用本文新增的 `graph_add` 一次画上去。

### 2.3 视图注册表只认最后一个点

`view-registry.ts:73-92` 的 `extensionOf` 语义对齐 `path.extname`：取 basename 最后一个点之后。故：

- `.graph.json` ⇒ 扩展名是 `.json`，会被 JSON 的视图（若有）抢走；
- 必须有自己的后缀 ⇒ **`.hgraph`**，内容是 JSON。

## 3. 决定一：文件是唯一真相

### 3.1 三个方案

| 方案 | 真相在哪 | 好处 | 为什么不选 |
|---|---|---|---|
| **文件为真相**（采纳） | `.hgraph` 文件 | 产物可直接交付、备份、归档；AI 与人共用一条写路径 | — |
| 库里建表，文件只是导出 | `case_graph` 表 | 可查询、可做权限 | 一份数据两处存，读者分流时没有任何单项断言看得出来（`#007-02`）；"AI 改库"与"人拖文件"必然打架 |
| 双写 | 两边 | 看似兼容 | 同上，且多一套同步逻辑要维护 |

### 3.2 自包含

绑库的节点/边，把**当时看到的**抄进文件：

- 节点：值、库类型、细类、可信态、属性（开户行/卡号/证件号…）、出处；
- 边：次数、金额、出处、关系 id 列表；
- 同时保留库 id，用于"跳回实体详情"。

理由：实体会被改名、被合并、被排除；**产物不能随库漂**。半年后打开这张图，它必须还是当时那张。

### 3.3 单向

库 → 图，只能单向。图上加的东西**不**变库里的实体或关系。想知道"这条线索为什么在图上"，答案在图文件自己的出处与依据里。

### 4.2 四条钉死的规则

1. **`id` 文件内唯一、永不变。** 节点的 `id` 是 `n1`，不是库 id；库 id 放在 `来源.实体`，可以没有。实体被合并/删除时图不崩，只是"跳转"失效并提示。
2. **每个节点/边必须能回答"凭什么在图上"。** `来源.kind` 四值：`实体` / `关系` / `推断` / `手写`。边的 `性质` 两值：`事实`（实线）/ `推断`（虚线）。
3. **出处是行级的**：`材料#工作表#行号`，与 `case_citation` 同形（`case-store.ts:423-432`：工作表名可含 `#`，按首末 `#` 解析）。
4. **坐标落盘**：`x` / `y` 是图的一部分，拖完即存。

### 4.3 类型是开放词表，不是枚举

初稿写死七类（人/账户/号码/公司/车辆/地址/其他），被用户当场否掉：i2 的常用类型有二十来类（车辆、电信、犯罪、活动、资金、军事、人员、商品、社交媒体、网络犯罪、位置、文档、武器、医疗、组织、其他…），实际办案远不止七个。

改定：

- `类型` 存**字面字符串**，读取时**不校验白名单**；
- 认识的类型给专属颜色/形状；不认识的用默认形状 + 名字照显示，**不报错、不丢节点**；
- 第一版内置一套基础类型；**类型导入后置**，但字段现在就留好：`类型` + 可选 `样式: { 颜色, 形状 }` 快照。类型表以后怎么变，老图的观感不跟着变；
- 库实体大类（人/账户/号码/公司）与图上类型（犯罪/电信/社交媒体）**不是一套**。绑库节点两个都存（`来源.库类型` + 外层 `类型`），加入时按映射表给初值，用户改了就按用户的。
- i2 的类型**名称**是通用词，可照用；**图标是商业资产**，不抄，用自有形状与颜色。

### 4.4 版本与兼容

- `格式: 1`。将来不兼容的改动加一，读到更高版本**只读打开**并提示"请升级"；
- 未知字段**保留原样写回**，不许静默丢弃（AI 或新版本写入的字段，旧版本不能吃掉）。

## 5. 决定三：图上的手动操作

判据：**民警用鼠标能不能把脑子里那张图完整画出来，并且画错能收回。**

### 5.1 工具栏与控制

- 全图标，悬停 300ms 出文字说明，说明里**带快捷键**（「删除（Delete）」「撤销（Ctrl+Z）」）；
- 图标复用 `graph-icons.tsx`，不新画一套；
- 分三组，分隔线隔开：**选择｜画**（指针、连线、加节点、文字）、**排**（对齐、等距、自动布局）、**整**（缩放适配、导出、撤销重做）。

### 5.2 连线是一个模式，不是一次拖拽

初稿把"拖到另一个节点上松手 = 连线"与"拖动摆位"放在同一次拖拽里，用户当场指出会打架。改定：

- 工具栏两个模式：**指针** / **连线**；
- 连线模式下，在节点上按下并拖动，有一根线跟随鼠标，落到另一个节点上松手即成边，落到空白处不成边；
- 指针模式下拖动只移动，永远不建边；
- 双击空白 = 新增节点（指针模式），与工具栏「加节点」等价。

### 5.3 选区与多选

- **Shift + 点击**：加入/移出选中；
- **框选**：指针模式在空白处拖出选框；按住 `Shift` 框选 = 追加，不按 = 替换；
- **高亮**：选中节点描边加粗 + 外圈光晕；选中边加粗提亮；检查器顶部显示「已选 N 个」；
- 点空白 / `Esc` 取消；
- 多选后可做：整体拖动、对齐、等距、删除。

### 5.4 对齐与等距

- 选中 ≥2 才亮：左 / 水平居中 / 右 / 顶 / 垂直居中 / 底；
- 以**选中范围的边界**为准（最外侧那个不动）；
- 选中 ≥3 才亮：水平等距 / 垂直等距，两端不动、中间均分；
- 每一步进撤销栈。

### 5.5 自由文字

用户要的不是节点标签，是**能在图上写话并排版**：

- 「文字」按钮 → 点画布落一个文本框，直接敲；
- 可排版：字号（小/中/大）、加粗、颜色（预设色）、对齐（左/中/右）、框宽可拖、自动换行；
- 可拖动、可删除、可撤销，导出 PNG 时一起导出；
- **不做**：斜体/下划线/字体族/旋转/从 Word 粘贴富文本。中文办案记录用不上，加了只会让人把图当文档写。

### 5.6 视觉的两个独立通道

| 通道 | 表达什么 | 默认怎么算 |
|---|---|---|
| **边的粗细** | 这一条关系有多强 | 按关系类型选度量：资金类按金额，通信类按次数，其他按次数 |
| **节点的外环粗细** | 这个节点在图上的分量 | 按它在图上的连接条数，4 档 |

**为什么强弱不能跨类型比**：转账比次数没意义（一笔 50 万 vs 五十笔 1 万），话单比金额更是胡说。所以度量按关系类型定。

**为什么用固定阈值而不是分位数**：分位数会让"每加一条边，全图粗细重排"，同一张图今天讲和明天讲不一样，汇报时会被问住。固定阈值写进 `设置`，改了就固定。

默认档位：

- 次数：1 / 2～4 / 5～9 / 10～49 / 50+
- 金额：1 万以下 / 1～5 万 / 5～20 万 / 20～100 万 / 100 万以上
- 外环：1 条 / 2～3 条 / 4～7 条 / 8 条以上

**手动覆盖**：选中边可设「自动 / 1～5 档」（5 档即加粗强调）；选中节点可设外环档位与颜色（预设色）。覆盖值写文件（`线宽档` / `外环`），没写就按规则自动算。外环颜色默认按类型，手动改色用于"红环 = 重点对象"这类标记。

**节点连线多时**（"毛线球"）三层叠加：

1. **弱线淡化**：1～2 档的边降低不透明度，强边自然跳出来；
2. **强度过滤**：工具栏档位滑块「只看 ≥3 档」，隐藏弱边，画布角落明说「已隐藏 12 条较弱关系」——**不能悄悄藏**；
3. **外环加粗**：一圈细边汇到一个粗环上，"这个人是核心"一眼看得出。

**不做边捆绑**（多条线拧成一股）：好看但难解释，民警讲图时说不清"这一股到底几条"。

**图例常驻**，两组刻度分开画：「线粗 = 关系强弱」「环粗 = 连接多少」，另标「实线 = 事实 / 虚线 = 推断」。

### 5.7 检查器：点节点后显示什么

单击选中，右侧检查器分**两段**，界线必须清楚，否则过两天分不清哪个数是文件里的、哪个是库里的：

**图上记的**（来自文件，稳定不变）

- 名称、类型 · 细类、来源（事实/推断/手写）与快照里的库可信态（已确认/存疑/已排除）；
- **属性**：开户行、银行卡号、证件号……每条挂出处，点一下跳到材料那一行；库里没有属性时明写「库中无记录属性」，不空着让人猜；
- **备注**：用户自己写的话，可编辑；
- 绑库节点显示「在库中查看 →」。

**库里现在**（不自动刷，点「查看库中最新」才查）

- 关联数、首次/末次出现时间、涉及金额合计；
- 图里连了哪几条（列前 5 条，点一条高亮对应边）；
- 「库中还有 N 条关系未上图」——只报数量，要加请让 AI 加。

双击绑库节点 = 跳实体详情（`case://<项目>/entity/<id>`）；未绑库节点双击只展开检查器，并标明「这条不在库里」。

### 5.8 撤销

- `Ctrl+Z` 撤回最近 20 步，`Ctrl+Shift+Z` 重做；
- 新增、删除、连线、改字、移动、对齐、自动布局，各算一步；
- **AI 的一整批变更也算一步**（见 §6.5）；
- 撤销栈**按标签页独立**，切换标签页不串。

### 5.9 自动布局

- 力导向 / 环形 / 分层 / 网格，复用 `graph.tsx` 的 `自动位置`（`:219`）；
- 新图没有"中心/跳数"，映射成大图时按 BFS 分层、度数最高者为临时中心；
- 自动布局会覆盖手动摆位，**必须弹确认**，且这次操作可撤销。

### 5.10 规模

- 不设硬上限；
- >300 节点提示「这张图已经偏大，建议拆成多张」；
- >1000 节点只提示性能风险，**不拦、不截断**——截断一张图等于骗人。

## 6. 决定四：AI 怎么改图

### 6.1 不整份重写

AI 若整份重写文件，用户正在拖的节点坐标会被覆盖，而且没人会发现坐标变了。所以**一切都走"操作"**：

```
读最新文件 → 应用这一小批操作 → 校验 → 原子写回（临时文件 + rename）
```

人拖坐标、AI 加节点，都是同一个入口，只是操作不同。两者不相交，因此不会互相覆盖。

**服务端按路径串行化**（进程内一把锁），同一张图不并发写。

### 6.2 五个工具

| 工具 | 入参要点 | 干什么 |
|---|---|---|
| `graph_list` | — | 列出本项目所有图：路径、标题、节点数、更新时间 |
| `graph_read` | 路径 | 读节点与边（含出处），改前先看 |
| `graph_add` | 路径 + 一批节点/边 | 批量新增（**单次 ≤50**，超出拒绝并建议分批） |
| `graph_update` | 路径 + 目标 id + 字段 | 改名称/类型/标签/备注/性质/位置 |
| `graph_remove` | 路径 + 目标 id | 删节点或边，返回连带删掉的条数 |

路径必须：落在项目目录内、后缀 `.hgraph`。校验复用现有路径闸（`file.ts` 的归属与穿越判定）。

### 6.3 出处是硬闸

`graph_add` 收到一条标「事实」的节点或边却没有 `出处`，**工具直接报错拒绝**，原文告诉 AI：

> 这条标了事实但没给出处：要么补出处，要么改成推断并写明依据。

这条不写在提示词里求模型自觉——**它必须是代码里的判据**，否则模型换个写法就绕过去了。

同理：`性质: "推断"` 必须同时有 `来源.依据`，空依据也拒绝。

### 6.4 同名复用

AI 加节点时，若图上已有**同名且同类型**的节点，复用它并连到它上面，返回里明说「复用了已有节点 张三」。否则图上会出现两个"张三"，用户还得自己合并。同名不同类型（人张三 / 账户张三）不算重复，新建。

### 6.5 AI 可以删，但可撤销

用户裁定：AI 可以删任何节点（不止自己加的）。

配套两条，不是限制是保护：

1. AI 每次删除**必须回话说明删了什么**（几个节点、哪几条边）；
2. 这一整批删除在前端**算一步可撤销的操作**——`Ctrl+Z` 能整批退回。模型一次删错，用户至少能完整还原。

### 6.6 多张图并行

- 每张 `.hgraph` 一个标签页，可同时开多张；
- AI 工具**必须点名路径**，不做"项目当前图"这种隐式状态（多张并行时它一定猜错）；
- 只有项目里**恰好一张**图时，路径可省略；
- 有多张而 AI 拿不准，调 `graph_list` 列出来问用户，**不许瞎猜往最近改的那张写**。

### 6.7 前端怎么看到 AI 的改动

- 每次操作即时发出（防抖 500ms），本地几乎没有"未保存"的东西；
- 页面每 10 秒对一次文件版本，发现变了且本地无未发出改动 → 静默重载；
- 本地刚拖完还没发出去、AI 恰好也改了 → 弹「图已被更新，重新载入？」，**不替用户选**；
- 只重载被改的那一张标签页（按路径匹配）。

## 7. 决定五：图与库的衔接

**从库里上图**

- 实体详情页 / 实体面板右键 →「加入关系图」，选目标：当前打开的，或新建一张；
- 加入瞬间拍快照：值、类型、细类、可信态、**出处**（走 `get_citation` 的 entity 分支，取不到就在节点上写明「未取到出处」，不假装有）；
- 关系同理，加边时带 `关系们` 与出处；
- 边上右键「以此为中心展开」**不在本设计内**——那是邻域图的事，两图分工不混。

**从图上回库**

- 双击绑库节点 → 实体详情页；
- 检查器里的出处可点 → 跳到材料那一行。

**库里变了，图不变**

- 打开图时拿节点快照与当前库对一遍：值被改、实体被合并、被排除，都在节点上加角标；
- 点角标能看见差异（「文件里记的是张三，库里现在叫张三丰」），但**文件内容一个字不改**；
- 用户可手动「刷新此节点」把快照更新到最新。

---

## 8. 决定六：导出图片

- 图文件右键或工具栏「导出 PNG」；
- 导出内容 = 当前画布所见（含图例、文字块、线的粗细与虚实），2 倍分辨率、白底；
- 不做 SVG 导出（第一版），不做 PDF；
- 导出的图**不带**交互态（选中高亮、悬停提示）。

## 9. 出错的时候

| 情形 | 表现 |
|---|---|
| **JSON 解析失败** | 打开即报「这份图打不开，第几个节点缺了什么」，提供「以文本方式打开」；**禁止一切写回**，包括 AI 工具 |
| **保存失败** | 明确报「没存上」，改动留在页面可重试；**绝不假装成功** |
| **文件被外部删除** | 标签页提示「文件已不存在」，**禁止保存**（否则一存就"复活"成空图） |
| **同路径两个标签页** | 复用现有「同路径只开一个 tab」，从根上不产生两份编辑态 |
| **外部编辑器改了文件** | 保存时版本不一致 → 按 §6.7 处理 |
| **写入中断** | 临时文件 + `rename` 原子替换，不留半截文件 |

## 13. 未决与风险

1. **AI 批量上限 50** 是拍脑袋的第一版值，真实使用后再调。
2. **外环默认自动**（按连接数）已定，但"自动 + 手动覆盖"如何并存（手动后是否还随连接数变）需实现时定：倾向"手动值一旦写入就不再自动变"。
3. **属性快照会过期**：库里补了开户行，图上还是旧的，只有角标与"刷新此节点"这条人工路径。是否要做"打开图时自动更新快照"——不做，理由同 §3.2（产物不能自己变）。
4. **图的体积**：几百节点 + 出处数组，文件可能到几百 KB；目前无压力，真要大了再考虑出处去重。
5. **撤销栈是内存态**：关闭标签页即丢；不做持久化撤销。
6. **导出 PNG 的中文字体**：SVG 转 canvas 时字体不回退会掉字，实现时必须实测，必要时内联字体或走 `foreignObject` 之外的路径。
7. **类型映射表**（库大类 → 图类型）首版内容待定，按现有实体类型先给一版。
8. **多人/多设备**：图放在项目文件树里，天然跟备份走；但两人同时开同一张图不在本设计范围。
