# 备注

## Spec-kit 拆分：F1–F10 推荐执行顺序

> 依据 `tmp/specify_make.md` 拆分 openhive-PRD §5.1 的 10 个功能模块，全部纳入本轮（F7/F9/F10 亦为必须有）。

### 目录编号映射（F 编号 = 目录序号，固定）

- 001-platform-foundation ← F1 平台底座
- 002-auth-account ← F2 认证与账号
- 003-multi-tenant-isolation ← F3 多用户隔离
- 004-access-control ← F4 权限控制
- 005-project-management ← F5 项目管理
- 006-ai-session ← F8 AI 会话
- 007-fund-analysis ← F6 资金分析
- 008-call-analysis ← F7 话单分析
- 009-ai-assets ← F9 AI 资产
- 010-governance-console ← F10 治理后台

### 推荐执行顺序（依赖拓扑排序）

1. F1 平台底座（无依赖，一切基础）
2. F2 认证与账号（依赖 F1，登录后进入三栏主界面）
3. F3 多用户隔离（依赖 F2，先有用户身份才谈隔离）
4. F4 权限控制（依赖 F2 认证 + F3 隔离，权限基于用户与数据范围）
5. F5 项目管理（依赖 F1 三栏入口 + F3 隔离边界）
6. F8 AI 会话（依赖 F1 右栏 + F4 越权拦截）
7. F6 资金分析（依赖 F1 三栏 + F3/F4 数据轴授权 + F5 产物落工作空间 + F8 右栏 AI）
8. F7 话单分析（依赖 F6，同构资金，复用四视图 + 三栏 + 加载面板）
9. F9 AI 资产（依赖 F1 入口 + F4 授权 + F8 指令卡机制）
10. F10 治理后台（依赖 F2 账号 + F4 权限 + F9 资产治理）

### 两个关键差异点（相对 PRD 的 F 编号顺序）

1. F8 AI 会话排在 F6 资金分析之前：F6 右栏「AI 驱动清洗 / 研判 / 报告」依赖 F8 的指令卡 + 会话机制，故 AI 会话先落地。
2. F9 / F10 殿后：F9 资产治理依赖 F8 指令卡机制，F10 治理后台依赖 F2 账号 + F4 权限 + F9 资产治理，均为横向能力，最后收敛。
