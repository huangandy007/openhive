# 研判工作台设计：中栏多形态内容区 + 交付层

- **日期**：2026-09-05
- **状态**：待审阅
- **主题**：把 openhive 中栏从「代码编辑器」翻转为「多形态内容区」，并新增「交付层」让 AI 一键产出研判产物
- **关联**：`2026-08-17-多用户多租户改造-design.md`（§8/§9/§10）、`2026-08-30-前端落地策略-opencode换皮-design.md`、`2026-09-05-竞品差距分析-workbuddy与千问办公-design.md`

---

## 1. 背景与目标

openhive 沿用了 opencode 的「AI 编程 IDE」形态：三栏中栏 50% 宽度给了代码编辑器，而真实用户是**民警**，最高频处理的是 Word / Excel / PPT / 思维导图 / 图文混排文件，以及话单 / 资金数据分析。

本设计纠正这一范式错位：**中栏从「单一代码编辑器」变成「多形态内容区」，并新增「交付层」让 AI 一键产出研判产物（报告 / 图谱 / 报表）**，二者闭环，民警全程不离开平台、不用管排版、不用手抄结论。

---

## 2. 已确认的设计决策

| 决策项 | 结论 |
|---|---|
| Office 文档（Word/Excel/PPT）编辑方式 | **AI 生成 + 在线预览 + 拖拽到本地编辑 + 拖拽回**（不部署 OnlyOffice，不自研重编辑器） |
| 思维导图 / 图文混排（轻格式） | 中栏**在线编辑**（轻量编辑器） |
| 文档定位 | **文件树的一等公民**，不是独立「工作区」 |
| 交付物范围 | **一次性做完**：研判报告 + 关系图谱 + 资金流向图 + 统计报表 |
| 「项目」→「案件」 | 一级对象对齐到公安语境（案件聚合话单/资金/证据/产物） |

## 3. 中栏多形态内容区

### 3.1 内容类型清单与视图路由

| 内容类型 | 格式 | 中栏视图 | 能力等级 |
|---|---|---|---|
| Word 文档 | `.docx` | 文档预览 | 在线预览 + 拖拽到本地编辑 |
| Excel 表格 | `.xlsx` | 表格预览 | 在线预览 + 拖拽到本地编辑 |
| PPT 演示 | `.pptx` | 幻灯片预览 | 在线预览 + 拖拽到本地编辑 |
| PDF | `.pdf` | 翻页预览 | 在线预览 |
| 思维导图 | `.xmind` / `.md` | 导图视图 | **在线编辑** |
| 图文混排 | `.md` / 富文本 | 富文本编辑器 | **在线编辑** |
| 图片 | `.png` / `.jpg` | 图片预览 | 在线预览 |
| 话单数据 | 数据表 | 明细表 + 关系图谱 | 查询 + 可视化 |
| 资金数据 | 数据表 | 明细表 + 桑基图 | 查询 + 可视化 |
| 代码 | 源码 | 代码编辑器 | 保留（降级为可选） |

- **视图路由**：一个「内容视图注册表」`扩展名 → 视图组件`。文件树点文件 → 查注册表 → 中栏渲染对应视图。新增格式只需注册新视图，框架零改动（复用 specs §9.4「工作区注册」思路，下沉为「视图注册」）。

### 3.2 文档编辑方式：拖拽到本地 ↔ 拖拽回

这是本设计的核心交互，复用 specs §10.3 已有上传/下载能力，以「拖拽」形式呈现：

```
文件树里的 .docx/.xlsx/.pptx
   →（拖拽出浏览器到本地桌面/文件夹）= 下载到本地
   → 本地用 WPS/Office 编辑
   →（拖拽回资源管理区）= 上传
   → 覆盖原文件（项目是 git 仓库，自动 commit 留痕）
```

- **拖拽出**：浏览器 drag-out 能力，文件树条目可拖出到桌面，触发下载。
- **拖拽回**：drag-in 上传（specs §8.13 已有拖拽上传），拖回同名文件 = 覆盖 + git commit 留痕。
- **版本留痕**：不搞额外版本系统，靠 git 历史天然留痕（符合 CLAUDE.md「最小侵入 + 复用 opencode 原生能力」）。
- **AI 生成优先**：多数报告由 AI 生成，民警只需拖出去微调，再拖回来归档。

### 3.3 与「案件」工作区的衔接

- 文档是「文件树里的一等公民」，不是独立工作区。
- 「案件」作为一级对象，天然聚合：**话单数据 + 资金数据 + 证据文件（docx/pdf/图片）+ 研判产物（报告/图谱/报表）**，全部在中栏统一查看。
- specs §9 的「工作区抽象」保留（代码/话单/资金），但**权重反转**：话单/资金是主角，代码是配角；文档作为通用文件能力横跨所有工作区。

## 4. 交付层

### 4.1 交付物清单（一次性做完）

| 交付物 | 格式 | 说明 |
|---|---|---|
| 研判报告 | Word / PDF | 民警最高频交付物 |
| 话单关系图谱 | 交互图 / 图片 | 谁和谁通话、频率、聚类、核心人员 |
| 资金流向图 | 桑基图 / 图片 | 来源 → 中转 → 去向、分层转移 |
| 统计报表 | Excel | 汇总指标、趋势图 |

### 4.2 研判报告生成链路

```
民警勾选数据 / 结束一段分析
   → 点右栏「生成报告」
   → AI 汇总会话上下文 + 选中数据 → 产出结构化内容
        （案情摘要 / 数据来源 / 分析过程 / 结论与建议）
   → 套用「报告模板」（单位抬头、字体、段落、落款）
   → 生成 .docx（可另存 PDF）
   → 中栏自动打开预览
   → 一键存回案件空间（文件树可见，随案件归档）
```

- **报告结构模板**（管理员可配置）：标题 → 案情摘要 → 数据来源 → 分析过程 → 结论与建议 → 附件（图谱/报表）。
- **生成方式**：模板 + 结构化字段填充（而非 AI 自由排版），保证全单位格式统一，对标千问「PPT 保留母版」。

### 4.3 关系图谱 / 资金流向图

- AI 从话单/资金数据**抽取实体关系**（人、号码、账户、交易往来），产出结构化关系数据。
- 中栏用图可视化库渲染**可交互图谱**（拖拽、缩放、筛选、钻取核心节点），可导出图片插入报告。

### 4.4 统计报表

- AI 从话单/资金数据汇总关键指标（总量、趋势、分布），产出结构化报表数据。
- 套用「报表模板」生成 `.xlsx`（带公式、带样式），中栏预览 + 拖拽到本地编辑。

### 4.5 模板体系

- 管理员后台配「报告模板」「图谱样式」「报表口径」，全单位统一。
- 民警只需「勾选数据 + 一句话」，格式由模板兜底。

---

## 5. 闭环数据流

```
民警勾数据 → AI 出报告/图谱/报表 → 中栏预览 → 存回案件
                ↑ 拖出本地微调 → 拖回归档 ↓
```

民警全程不离开平台、不用管排版、不用手抄结论。

## 6. 技术选型（建议，实现时验证）

| 能力 | 建议方案 | 说明 |
|---|---|---|
| Word 预览 | docx-preview（纯前端） | 浏览器渲染 docx 为 HTML |
| Excel 预览 | SheetJS / LuckySheet | 前端渲染 xlsx |
| PPT 预览 | pptx → 图片/PDF（pdf.js） | 后端 LibreOffice headless 转换 |
| PDF 预览 | pdf.js | 前端翻页 |
| 思维导图 | markmap（Markdown → 导图） | 与图文混排 Markdown 统一 |
| 图文混排 | TipTap（富文本） | 支持图片粘贴 |
| 关系图谱 | AntV G6 | 中文文档好、图布局成熟 |
| 桑基图/统计图 | ECharts | 桑基、时序、柱状、饼图 |
| 报告生成 | docx 模板 + docxtemplater 填充 | AI 产结构化 JSON → 填充模板 → 出 docx |
| PDF 导出 | LibreOffice headless | docx → pdf |

> 全部为内网可自建的开源方案，无外部 SaaS 依赖。

## 9. 待决策点（剩余）

1. **「案件」命名与结构**：是否正式把「项目」重命名为「案件」？案件字段（案件编号、性质、承办人）何时补齐？
2. **拖拽回的文件冲突**：拖回同名文件默认「覆盖 + commit」，是否够用？是否需要「另存为新版本」的选项？
3. **思维导图格式**：用 `.md`（markmap）还是 `.xmind`（导入导出）？markmap 最轻但生态弱，xmind 通用但需导入导出。
4. **图谱数据抽取**：实体关系抽取靠「大模型直接抽取」还是「规则 + 大模型校验」？涉及准确率与内网模型能力。
