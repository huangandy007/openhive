## 2. 项目背景与目标

### 2.1 背景

公安日常工作覆盖「情报研判、内勤文字、方案制作、考核督导、专项行动、案件办理、审讯取证、报捕起诉」等多个环节，每个环节都有大量重复性的文档与研判工作。当前民警面对的是**「几十个手工按钮的传统重型工具」**（如传统资金分析工具），操作门槛高、效率低。

与此同时，以大模型为核心的 AI 编程工具（如 opencode）已经成熟，但其「代码编辑器 + 程序员心智」与民警「不懂代码、要的是分析结论和文档」的实际需求严重错位——民警用不起来，觉得「这是给程序员用的」。

OpenHive 要做的是：**把成熟的 AI 能力内核（opencode）改造为「公安全流程 AI 工作平台」**——界面只做「浏览 + 操作」，分析能力由「方法资产（skill）」承载，民警用自然语言驱动 AI 干活，最终产出研判报告、关系图谱、资金流向图、统计报表、分析记录等**有形产物**。

### 2.2 目标（Goals）

- **业务目标**：让一线民警在公安全流程的各个环节都能用 AI 提效，实现「个人提效、组织增智」。
- **产品目标**：把「一次研判 / 一份文书」的完成时间从小时级缩短到分钟级；把海量涉案数据（高峰日 200 万条流水）的浏览从「卡顿、看不懂」变成「秒级、看得清」。
- **组织目标**：让领域专家的「分析思路 / 方法」能沉淀为可复用的 skill，供新人学习、全单位复用（组织增智）。

### 2.3 非目标（Non-Goals）

- **不是单纯的「研判平台」**：情报研判只是全流程的一环，平台要覆盖公安全流程，研判降级为其中一环。
- **不是「代码编辑器」**：代码编辑器降级为少数技术用户的可选功能，不是默认、不是主角。
- **不做数据脱敏 / 加密存储**：分析数据（含身份证号、联系电话）本身就是要研判的对象，始终明文可见，合规靠权限控制而非对数据本身做处理。
- **不做旧系统云端流转**：MVP 阶段数据靠手动上传，不做与旧系统的数据流转对接。

### 2.4 战略对齐

对齐「公安全流程 AI 工作平台」的长期定位：先以「资金分析 → 话单分析」两个研判环节作为「AI 优先重构」的落地示范，验证「薄界面 + 厚 skill」范式，再横向铺开到全流程其余环节。

## 3. 目标用户与画像

### 3.1 主要画像 P1：一线民警（研判员 / 办案人员）

- **背景**：一线实战民警，不懂代码、不关心技术，关心「这个案子怎么查、结论怎么出、文书怎么写」。
- **目标**：快速完成一次研判（话单 / 资金）、快速产出研判报告和文书。
- **痛点**：
  1. 传统工具几十个按钮，不会用、不敢用；
  2. 海量流水 / 话单数据看不懂、看不过来；
  3. 分析结论不知道怎么写、怎么沉淀；
  4. 跨数据源（话单 + 资金）串并案困难。
- **使用频次**：工作日每天多次。
- **设备**：PC（内网）。

### 3.2 次要画像 P2：业务专家 / 管理员

- **背景**：法制骨干 / 业务专家（管 skill 内容审核、模板口径）、科信 IT（管账号、组织、运维、技术合规）。
- **目标**：把领域经验沉淀为 skill、管理资产、管控权限与审计。
- **痛点**：领域经验无法规模化复用；资产权限和审核缺统一治理；账号和成本缺统一看板。

### 3.3 反画像（明确不服务的对象）

- **程序员**：不是给开发者用的 IDE，代码编辑是边缘功能。
- **外部互联网用户**：仅公安内网、管理员录入账号，无自助注册。

## 4. 用户故事

### US-01 完成一次资金研判
作为研判民警，我希望把上传的银行流水交给 AI 清洗入库、按账户和资金流向分析，以便快速锁定跑分卡主和资金归集账户、出研判报告。

### US-02 完成一次话单研判
作为研判民警，我希望上传话单后，让 AI 找出新出现/消失号码、共同关系人和通话关系网络，以便锁定核心涉案人和团伙结构。

### US-03 在一个项目里专注工作
作为民警，我希望一眼看清「我在哪个项目、这个项目有哪些文件和会话」，以便专注正确的工作单元、不串案。

### US-04 复用组织里的方法资产
作为民警，我希望浏览和调用单位已审核发布的 skill（如「资金链路分析」），以便用领域专家的成熟方法干活，而非从零摸索。

### US-05 管控账号与权限
作为管理员，我希望录入/停用账号、管控谁能看什么数据、审计谁调了什么，以便守住数据安全底线。

## 5. 功能列表与范围

### 5.1 In-Scope（本版本必须有）

| ID | 功能模块 | 一句话描述 | 优先级 |
|---|---|---|---|
| F1 | 平台底座（三栏工作台） | 左栏导航 / 中栏浏览 / 右栏 AI 会话的三栏统一框架 | P0 |
| F2 | 认证与账号 | 管理员录入 + 警号登录 + 首次强制改密 | P0 |
| F3 | 多用户隔离 | 每用户独立工作沙箱与数据，互不可见 | P0 |
| F4 | 权限控制 | 谁能看什么数据、AI 不能越权调工具 | P0 |
| F5 | 项目管理（工作空间轴） | 项目列表、成员协作、文件树、云端备份、归档 | P0 |
| F6 | 资金分析（数据轴示范） | 明细/聚合/关注清单/桑基图四视图 + 图谱研判画布 | P0 |
| F7 | 话单分析（数据轴，同构资金） | 同构三栏 + 通话关系图 + 新出现/消失号码、共同关系人、串码分析 | P0 |
| F8 | AI 会话（右栏指令卡） | 自然语言驱动 AI 干活，指令卡降低使用门槛 | P0 |
| F9 | AI 资产（Skill/MCP/知识库） | 资产分类浏览、收藏、生命周期、授权 | P0 |
| F10 | 治理后台 | 账号/组织/用量/审计/AI 资产治理/数据项目权限 | P0 |

### 5.2 Out-of-Scope（本版本不做）

- ❌ 轨迹分析等情报研判之外的环节深度落地 → 留到后续横向铺开。
- ❌ 移动端 → 暂不考虑，内网 PC 为主。
- ❌ 数据脱敏 / 加密存储 → 明确不做（分析数据明文可见）。
- ❌ 旧系统数据流转对接 → 本版本只手动上传。
- ❌ 短信内容分析 → 话单 MVP 只分析通话记录，短信后手。
- ❌ 多单位模型路由 → 后手（先统一本单位模型）。

### 5.3 优先级定义

- P0 = 必须有（缺了平台不能上线）
- P1 = 应该有（缺了体验大打折扣）
- P2 = 可以有（锦上添花）

## 6. 详细功能描述

> 说明：以下为「做什么」层面的功能描述。技术实现（数据表结构、分区策略、渲染库、队列选型）不在此展开，见后续技术方案（TRD）。

### F1 平台底座（三栏工作台 + 共享中栏）

**触发**：民警登录后进入主界面。

**核心流程**：
1. 左侧图标栏提供五个入口：项目管理 / AI 资产 / AI 会话 / 话单分析 / 资金分析；
2. 点某入口 → 左栏切换为该模块的导航，中栏切换为对应内容；
3. 中栏是「共享中栏」：各模块打开的 tab 跨模块累积保留，切换模块不清空、不打扰已打开的 tab，tab 按模块着色区分来源。

**输出**：统一的三栏框架，用户始终知道「我在哪、在干什么」。

**业务规则**：
- 左栏 = 导航（定位项目 / 数据对象），中栏 = 浏览（看和改产物），右栏 = AI 会话（让 AI 干活）。
- 中栏 tab 跨模块共享、累积保留、按模块着色、切模块不打扰。

### F2 认证与账号

**触发**：用户访问系统。

**核心流程**：
1. 管理员后台录入用户（警号 + 默认密码）；
2. 用户用警号 + 密码登录；
3. 首次登录强制修改默认密码。

**边界条件**：
- 无自助注册入口；
- 账号停用后登录被拒；
- 超期未活跃账号可被识别并停用（防僵尸账户）。

**业务规则**：
- 用户名 = 警号，唯一；
- 密码重置后下次登录强制改密。

### F5 项目管理（工作空间轴）

**触发**：点图标栏「项目管理」。

**核心流程**：
1. 左栏展示项目列表（最近 / 全部 / 已归档）与当前项目的文件树 / 会话；
2. 新建私有 / 共享项目、切换当前项目；
3. 成员协作：owner 邀请 / 移除成员，member 可退出；
4. 文件树操作：新建 / 重命名 / 删除 / 复制 / 移动 / 上传 / 下载；
5. 文件与云端备份之间拖拽互移；
6. 项目归档（手动或超期自动）与手动找回。

**业务规则**：
- 谁建项目谁是 owner；owner 与 member 均可邀请；仅 owner 能移除成员；不设只读角色；
- 项目是唯一的隔离边界与版本边界；
- 文件删除需二次确认；
- 归档后成员失权、owner 保留找回权。

### F6 资金分析（数据轴）

**触发**：点图标栏「资金分析」。

**核心流程**：
1. 左栏资金项目树（项目 → 节点 → 账户）定位数据；
2. 点节点 → 弹出「数据加载面板」，显示该节点资金数据的**时间跨度**，用户选「全部 / 指定时间段」加载明细；
3. 中栏四个固定数据视图：明细（含账户对聚合）、聚合统计、关注清单、桑基图；
4. 图谱作为「研判画布」落沙箱，可拖入真实账户 / 手画假设节点、自由增删改；
5. 右栏 AI 驱动清洗、持有人研判、关联分析、资金链追踪、生成报告。

**边界条件**：
- 海量流水（高峰日 200 万条）必须快速加载、按时间段精准过滤；
- 单笔资金的「下游拆分」无法精确追踪（资金同质混合），走 AI 辅助推断 + 人确认，不做确定性按钮。

**业务规则**：
- 数据与工作空间解耦：业务数据走数据轴，产物落到当前 openhive 项目（工作空间轴）；
- 涉案数据只做「转换 + 标记」，不「删除 + 自动语义判断」，关键判断必须人确认；
- 关注状态是账户的全局属性，跨视图自动同步。

### F7 话单分析（数据轴，同构资金）

**触发**：点图标栏「话单分析」。

**核心流程**：与资金分析同构（三栏 + 加载面板 + 四视图 + 右栏 AI），差异在数据对象（号码 + 通话记录）与特有视图/能力。中栏四个固定数据视图为明细 / 聚合统计 / 关注清单 / 通话关系图（号码级通话关系网络汇总，替代资金的桑基图，确定性查询直接出）。

**特有分析能力（走 skill，AI 推断 + 人确认）**：
- 新出现 / 消失号码：对比两个时间段找集合差；
- 共同关系人：找多个号码共同通话的关系人；
- 串码分析：通过设备串号（IMEI）关联不同号码；
- 关系分析：深度分析号码间的通话关系网络。

**边界条件**：MVP 只分析通话记录，短信内容不纳入。

### F8 AI 会话（右栏指令卡）

**触发**：用户在任何模块的右栏输入或点指令卡。

**核心流程**：
1. 右栏顶部「常用操作」指令卡 + 随中栏选中动态浮现的「上下文指令」卡；
2. 点卡片 = 填入一句话，AI 执行并展示过程；
3. 输入框 + 「更多 skill」抽屉（按分组 + 最近使用 + 收藏加权排序）。

**业务规则**：
- AI 只执行「确定性查询 / 统计」与「需要专家经验的研判」，不滥用 AI 做确定性的事；
- 高风险动作（删除数据、判定涉案）必须人确认。

### F9 AI 资产（Skill / MCP / 知识库）

**触发**：点图标栏「AI 资产」。

**核心流程**：
1. 左栏纯导航：空间筛选 + 三 Tab（Skill/MCP/知识库）+ 业务分类折叠（分类名 + 数量角标）；
2. 中栏浏览：全局搜索框 + 卡片网格 + 详情 tab（介绍 / 注意事项 / 评价 / 版本）；
3. 收藏（个人偏好）与授权（RBAC 读权限）分离；
4. 资产生命周期：草稿 → 审核中 → 已发布 → 迭代中 → 已下线 → 已归档（审核权分离：业务专家审内容、IT 审技术）。

**业务规则**：
- 资产统一抽象（Skill/MCP/知识库一套元数据、权限、生命周期）；
- 授权范围 = 三级空间（全局/部门/个人）∪ 授权组（跨部门定向）；
- 左栏不堆资产列表，浏览与搜索在中栏。

### F10 治理后台

**触发**：管理员从顶栏用户下拉进入。

**核心流程**：账号管理、组织架构、用量/成本、审计、AI 资产治理、模板库、数据源配置、数据项目权限，八大类管理动作。

**业务规则**：
- 系统管理员（科信 IT）与业务专家（法制骨干）分权；
- 后台只承载「配置 + 审核 + 查看」，不承载民警的日常分析。

## 7. 非功能需求（NFR）

### 7.1 性能
- 海量明细加载：高峰日 200 万条入库的规模下，指定时间段的明细查询与统计在秒级完成；
- 首屏加载与常规操作响应在可感知的流畅范围内（具体阈值待基线测量）。

### 7.2 安全
- 用户间数据严格隔离，用户 A 不能访问用户 B 的数据；
- AI 只能调用「系统授权范围内的工具」，越权调用被拒绝并留审计；
- 数据库层面按用户数据范围过滤（最小权限）。

### 7.3 合规
- 分析数据（含身份证号、联系电话）明文可见，合规边界由 RBAC 权限控制，不做脱敏 / 加密；
- 审计日志完整记录「谁、何时、调了什么」。

### 7.4 数据
- 涉案原始数据保留、不删除（涉案数据是证据）；
- 分析判断（结论、理由）与原始数据分离存储。

### 7.5 可扩展性
- 新增业务模块 / 中栏视图 / 资产类型，走「注册式扩展」，不重构框架；
- 持续跟进上游内核更新，改造最小化以降低合并冲突。

## 9. 验收标准

### AC-F2-01 登录与改密
**Given** 管理员已录入账号且该账号未改密
**When** 用户用警号 + 默认密码登录
**Then** 进入主界面后强制弹出改密，改密成功后正常进入

### AC-F3-01 用户隔离
**Given** 用户 A 和用户 B 各自有沙箱和数据
**When** 用户 A 尝试访问用户 B 的数据
**Then** 系统拒绝访问，且无法绕过

### AC-F4-01 AI 越权拦截
**Given** 某工具不在用户 A 的授权范围内
**When** AI 尝试调用该工具
**Then** 调用被拒绝并记录审计，AI 拿不到无权数据

### AC-F6-01 资金数据加载
**Given** 某资金项目包含海量流水
**When** 用户点节点并选择「指定时间段」加载明细
**Then** 只加载该时间段的明细，在秒级返回，且顶部显示「时间跨度 / 涉及账户数 / 流水条数」

### AC-F6-02 关注清单跨视图同步
**Given** 用户在聚合统计视图关注了某账户
**When** 用户切到关注清单视图
**Then** 该账户自动出现在关注清单，状态一致

### AC-F7-01 话单数据加载（同构资金）
**Given** 某话单项目包含海量通话记录
**When** 用户点节点并选择「指定时间段」加载明细
**Then** 只加载该时间段，秒级返回，顶部显示「时间跨度 / 涉及号码数 / 记录条数」

### AC-F8-01 指令卡触发
**Given** 用户选中若干账户
**When** 用户点右栏「关联分析」指令卡
**Then** AI 填入对应一句话并执行关联分析

### AC-NFR-01 性能验收
**Given** 高峰规模数据量
**When** 用户加载指定时间段明细
**Then** 查询与统计在可接受时间内完成（阈值待基线）

## 11. 度量指标（成功标准）

> 以下为成功衡量维度，具体量化阈值需在 MVP 上线前基线测量后确定。

### 11.1 研判效率
民警完成一次资金 / 话单研判的平均时长显著缩短（需基线：从小时级 → 分钟级）。

### 11.2 数据性能
海量明细（高峰日 200 万条）的加载 / 查询在秒级完成，无明显卡顿。

### 11.3 使用覆盖
目标民警群体的采纳率：一定比例的民警每周至少主动使用一次（具体比例待定）。

### 11.4 产物质量
AI 生成的研判报告 / 分析记录「可直接采用、无需大改」的比例（减少返工）。

### 11.5 度量频率
- 上线初期：按周跟踪使用覆盖与研判效率；
- 稳定期：按月跟踪全部四项。
