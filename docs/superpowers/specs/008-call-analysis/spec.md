## User Scenarios & Testing

### User Story 1 - 话单项目树与数据加载（Priority: P1）

左栏话单项目树（四 tab：最近 / 全部 / 已归档 / 当前；「当前」tab 展示项目 → 节点 → 号码树）。单击节点/号码仅选中；点击弹出「数据加载面板」（时间跨度 + 全部/指定时间段）加载明细。

**Why this priority**: 与资金分析同构，项目树是数据轴定位入口，选中加载分离 + 时间段过滤是海量话单「快速定位、精准加载」的前提。

**Independent Test**: 选话单项目 → 展开节点/号码 → 点节点弹加载面板 → 选时间段加载，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 民警进入话单分析，**When** 在左栏四 tab 选一个话单项目，**Then** 切到「当前」tab 展示项目 → 节点 → 号码树
2. **Given** 单击某节点/号码，**When** 选中，**Then** 高亮 + 更新面包屑，不加载
3. **Given** 点击某节点，**When** 弹加载面板，**Then** 显示该节点话单数据时间跨度，默认「全部数据」、可切「指定时间段」

---

### User Story 2 - 四个固定数据视图 + 通话关系图（Priority: P1）

中栏四个固定数据视图：明细（含号码对聚合）、聚合统计（对方号码维度 GROUP BY）、关注清单（已框定号码 + 调取状态）、**通话关系图**（号码级通话关系网络汇总，确定性查询直接出，替代资金的桑基图）。

**Why this priority**: 通话关系图是话单特有的确定性汇总视图，让民警一眼看清「号码之间的通话网络」，是话单分析的核心浏览界面。

**Independent Test**: 加载数据后切到通话关系图，看到号码间关系网络，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 已加载某节点明细，**When** 切到明细视图，**Then** 每行含持有人（优先展示研判查明的实际持有人）+ 号码对聚合
2. **Given** 切到聚合统计视图，**When** 查看，**Then** 按对方号码维度统计（通话次数/主叫/被叫/短信数/通话总时长等）
3. **Given** 切到通话关系图，**When** 查看，**Then** 展示号码 → 号码关系网络（可交互钻取 + 导出图片）
4. **Given** 在聚合统计勾选某号码「关注」，**When** 切到关注清单，**Then** 该号码自动出现，状态一致

---

### User Story 3 - 数据入库闭环（Priority: P1）

上传话单文件 → AI 清洗 → 「清洗对比 + 问题清单」→ 民警点「确认入库」→ 写入业务库。涉案数据只「转换 + 标记」，不「删除 + 语义判断」。

**Why this priority**: 与资金分析同构，数据入库是起点，清洗红线是涉案数据安全底线。

**Independent Test**: 上传话单文件 → 清洗对比 → 确认入库 → 数据可查询，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 民警上传话单文件，**When** AI 清洗，**Then** 展示「清洗对比」+「问题清单」
2. **Given** 民警点「确认入库」，**When** 完成，**Then** 数据写入业务库可查询；删除数据行、判定涉案必须人做

---

### User Story 4 - 话单项目权限（微信群模型）（Priority: P1）

话单项目权限遵循微信群模型（谁建谁 owner；owner/member 均可邀请；仅 owner 撤销；member 退群），数据轴自主授权。

**Why this priority**: 与资金分析同构，数据轴权限决定「谁能看哪些话单数据」，是数据安全核心。

**Independent Test**: owner 邀请/撤销成员、member 退群，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 民警新建话单项目，**When** 创建，**Then** 自己成为 owner
2. **Given** 被撤销成员访问项目，**When** 查询，**Then** 项目不出现、数据不可见（权限过滤铁律）

---

### User Story 5 - 右栏 AI 驱动 + 特有分析能力（Priority: P1）

右栏「话单分析 skill」承载清洗、持有人研判、统计、标注、出产物，以及话单特有分析能力——**新出现/消失号码、共同关系人、串码分析、关系分析**（均走 skill，AI 推断 + 人确认）。

**Why this priority**: 特有能力是话单分析相对资金分析的差异化价值（锁定团伙结构、串并案），走 skill 而非确定性按钮。

**Independent Test**: 选中号码触发「共同关系人」，AI 分析并需人确认，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 民警选中若干号码，**When** 触发「共同关系人」，**Then** AI 找出共同通话的关系人（需人确认）
2. **Given** 民警触发「新出现/消失号码」，**When** 指定两个时间段，**Then** AI 对比出集合差（新出现 / 消失号码）
3. **Given** 民警触发「串码分析」，**When** 执行，**Then** AI 通过设备串号（IMEI）关联不同号码
4. **Given** 民警触发「关系分析」，**When** 执行，**Then** AI 深度分析号码间通话关系网络

---

### User Story 6 - 图谱研判画布与产物落沙箱（Priority: P2）

图谱是项目级研判画布（`.graph` 思路层，落沙箱），AI 产物分门别类落沙箱。事实层（entity/relation）与思路层分离。

**Why this priority**: 与资金分析同构，图谱画布是理清思路的工具，产物落沙箱是交付，非首屏必需故列 P2。

**Independent Test**: 新建图谱、拖入号码节点、保存到沙箱，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 民警新建图谱，**When** 从明细拖入号码节点，**Then** 画布出现号码节点（带数据轴引用）
2. **Given** AI 生成分析记录，**When** 完成，**Then** 落沙箱 `分析记录/`，中栏自动开 tab

---

### Edge Cases

- MVP 只分析通话记录，短信内容不纳入（短信后手）。
- 新出现/消失号码是对比两个时间段找集合差，时间段由用户手动指定。
- 通话关系图是确定性查询（号码级汇总），深度关系分析（共同关系人/串码/关系网络）走 skill。
- 原始话单数据一律留在数据轴（PG），永不落地工作空间。

## Requirements

### Functional Requirements

- **FR-001**: 左栏 MUST 提供话单项目树（四 tab + 项目 → 节点 → 号码多级自关联，≤10 级），同构资金。
- **FR-002**: 选中与加载 MUST 分离——单击选中不加载，点击弹「数据加载面板」（时间跨度 + 全部/指定时间段）。
- **FR-003**: 中栏 MUST 提供四个固定数据视图：明细 / 聚合统计 / 关注清单 / 通话关系图。
- **FR-004**: 通话关系图 MUST 为号码级通话关系网络汇总（确定性查询，替代资金的桑基图，可交互钻取 + 导出图片）。
- **FR-005**: 关注状态 MUST 是号码全局属性（待调取 / 已调取待导入 / 已导入），跨视图自动同步。
- **FR-006**: 数据入库 MUST 走「上传 → AI 清洗 → 清洗对比 + 问题清单 → 人确认入库」，涉案数据只转换 + 标记。
- **FR-007**: 话单项目权限 MUST 遵循微信群模型（数据轴自主授权），同构资金。
- **FR-008**: 右栏 MUST 提供「话单分析 skill」，承载清洗 / 持有人研判 / 统计 / 标注 / 出产物。
- **FR-009**: 话单特有分析能力 MUST 走 skill（AI 推断 + 人确认）——新出现/消失号码（集合差）、共同关系人（交集）、串码分析（IMEI 关联）、关系分析（关系网络）。
- **FR-010**: 图谱 MUST 为项目级研判画布（`.graph` 思路层落沙箱），事实层（entity/relation）分离。
- **FR-011**: 数据与工作空间 MUST 解耦——原始记录留在数据轴（PG），永不落地工作空间。
- **FR-012**: 话单记录表 MUST 支持海量规模（高峰日可超百万条）——按月分区 + 批量导入，指定时间段秒级。
- **FR-013**: MVP MUST 只分析通话记录，短信内容不纳入。

### Key Entities

- **话单项目（call_project）**：数据轴一级组织单元。
- **话单项目成员（call_project_member）**：数据轴权限（微信群模型）。
- **节点（call_node）**：多级自关联（≤10 级）。
- **号码（call_number）**：本方号码（号码角色/运营商/持有人/归属地 + 关注状态）。
- **通话/短信记录（call_record）**：通信事实（日期/时间/对方号码/时长/基站）。
- **号码→人映射（account_identity）**：复用全局，对方号码 → 实际持有人。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 高峰日超百万条记录，指定时间段明细查询秒级返回（AC-F7-01）。
- **SC-002**: 关注状态跨视图自动同步。
- **SC-003**: 通话关系图确定性查询直接出；深度关系分析（共同关系人/串码/关系网络）走 skill + 人确认。
- **SC-004**: 涉案数据只转换 + 标记，删除 / 判定涉案 100% 需人确认。

---

## Assumptions

- 与资金分析（F6）同构，复用其整套模式（三栏 / 四视图 / 权限 / 入库 / 图谱 / 指令卡机制）。
- 号码→人身份映射复用全局 `account_identity`，不新造表。
- MVP 只分析通话记录，短信内容不纳入（design-v2 / PRD §5.2 明确）。
- 本模块待决策点已全部收敛（`2026-09-12-话单分析模块-design.md` §8 明确「已全部收敛，无遗留」）。
- 技术选型（话单查询 MCP、AntV G6、ECharts 等）留 plan，与资金分析一致。
