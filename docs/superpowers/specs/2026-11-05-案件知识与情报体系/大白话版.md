# 案件知识与情报体系 · 大白话版

> 2026-11-05。这是 [`design.md`](./design.md) 的通俗版，讲「一个案子从头到尾怎么走」。
> 两者冲突时以 `design.md` 为准；这一份是给不看技术细节的人读的。

---

## 先说要解决的问题

张警官手上有个电诈案：20 个嫌疑人、几百个电话号码、几十个银行账户、上千个 Excel 流水，还有笔录、视频、扣押物品清单。

这些东西他记不住，也看不完。他要做的事情有三件：**把事情串起来、把谁干了什么说清楚、写成能交上去的文书**。

这套系统就是帮他把前两件中的「记忆」和「查找」部分接过去。

---

## 一、开一个项目

新建一个项目，叫「0912 电诈案」。系统里**只有项目，没有「案件」这个层级**——一个项目可以是一个案子，也可以是一串案子（0912、1015、1021 是同一伙人干的，就放在一个项目里）。

项目分**私有**和**共享**两种：一个人办的用私有，专案组一起干的开共享。谁能进来、谁看得见，跟现在一样。

---

## 二、把文件拖进去（最关键的一步）

把 1000 个 Excel、一堆 PDF、几段视频**拖进项目**——可以一次拖完，也可以**今天拖一部分、明天再拖一部分、抓到人之后再补一批**。系统不要求一次导齐。

拖完就完事，**不用守着等**。文件在后台慢慢处理，民警该干什么干什么：已经入库的数据随时能看、能问，文件树顶上只多一行「已解析 987 / 1000 · 3 个有问题」——剩下那 10 份还在排队。

也不用做任何配置——没有「请选择文件类型」、没有「请配置列映射」、没有「请确认」。

系统在背后干六件事：

**1. 原样收好**
文件进项目文件夹，算一个「内容指纹」（相当于给文件按个手印）。

**2. 认这是什么**
是话单？是流水？是笔录？是视频？看表头、看内容判断。

**3. 拆开**

- 表格：一行一行拆出来。**哪一列是主叫、哪一列是金额，系统自己猜**——先查常见表头（「主叫」「交易金额」这种），猜不出就看内容（一整列 11 位数字就是手机号，一整列带小数点就是钱），还猜不出就交给 AI 看表头加三行样例。
- PDF / 图片：文字识别出来。
- 视频：先登记，后台慢慢转写出文字。

**4. 抽实体、连关系**
从每一行里抽出「谁、什么号码、什么账户、什么时间、多少钱」，并把它们连起来：这个号打给那个号、这个账户转给那个账户。

**5. 记出处**
每一条抽出来的事实，都记着「来自哪个文件、第几行」。

**6. 跑规则**
后台一批固定规则过一遍：同一个账户进出金额高度对称、通话双方和转账双方完全重合……命中就形成一条「提醒」。

**系统记的「事实」分三种，别混：**

- **谁是什么**——「这个号登记在张三名下」「这个账户是工行的」；
- **谁在何时对谁做了什么**——「张三 3 月 2 日给李四转了 28 万」；
- **谁说了什么**——「李四在讯问里说『钱是张三让我收的』」。

第三种要单独拎出来：**它记的是李四的话，不是这件事本身**。「数据表明两人通话 37 次」和「李四说他们不熟」摆在一起，谁站得住正是要审的地方。把「某人说」直接当成「事实是」，报告就站不住。

**有两件事最容易栽跟头，系统先把住。**

**一、号码登记在谁名下，不等于谁在用。**
运营商数据只说「这个号登记在张三名下」，没说张三在使。买卡、租卡、冒名开卡是电诈案的常态，所以这两件事系统分开记：「登记」是数据说的，「实际使用」得靠人认定——供述指认、扣押了那部手机、技侦、登录记录、资金闭环，至少得有一样。拿不出的就先空着，图上显示成灰色，别写进结论。

**为什么非要分开？** 不分开，报告上就会冒出「张三名下号码」这种话；庭上一句「实名登记不等于实际使用」，整条链就断了。更糟的是，无辜的户主会被标成核心人物，错误顺着关系图往外扩散。

**二、不同材料上的钟，走得不一样快。**
银行流水上的是记账时间，跨行可能差一天；监控摄像头的时间快慢几分钟很常见；笔录上的时间是事后回忆着说的。所以每段时间系统存两份：**一份原样不动**，一分不差地照抄；**一份统一换算过**。凡是跨材料比「同一时刻」，一律用换算过的那份，界面上还会写明「按分钟对齐」还是「只到天」。

**不校准就比，会得出「两个人同时在现场」这种站不住的结论。**

**哪个文件处理到哪一步，一眼就能看见。** 文件名后面跟一个小标记：

| 标记 | 意思 |
|---|---|
| ○ 空心圈 | 排着队，还没轮到 |
| ◐ 转着的圈 | 正在处理 |
| ✓ 对勾 | 处理完了，事实已经入库 |
| ! 黄三角 | 处理了但有几处没搞定，或者整份跑挂了，点开能看原因 |
| 什么都不显示 | 系统不打算解析它（报告这类产物、无关文件），或者你让它跳过了 |

**大部分文件不带标记。** 带标记本身就表示「这份进了流程」——要是全都标，等于全都没标。文件夹那一行显示「3/12」，树顶上还有一条总数。

**系统没想到要解析的，你可以让它解析。** 在文件上点右键，菜单里只多一项「**解析 ▸**」，点开是二级菜单：

```
解析 ▸  ✓ 已解析
  ├ 解析入库      系统漏了的，你手动塞进去
  ├ 重新解析      不满意再来一遍；你打的 ✓ ✗ ？ 不会被冲掉
  ├ 取消解析      不排队了
  ├ 跳过解析      这份确实不用管，别再黄着提醒我
  └ 查看解析结果  看看它到底抽出了什么
```

**为什么不把五条直接铺在右键菜单里？** 一级菜单本来就有十几项，再塞五条就翻不到底了。收进二级菜单，一眼还看得见当前状态。

**为什么非要留这个口子？** 系统按规则判断「这份不用解析」，可规则不懂案子。你觉得这条线索重要，就该能自己按下去；反过来，系统觉得要解析、你觉得不用，也能跳过。**默认值管大多数情况，右键管例外。**

**猜错了怎么办？** 认不出的列**原样留着**，不丢。以后发现有错，改一次规则，**一键重算**——文件不动，事实重新生成，而且**之前打过「对 / 错 / 存疑」的标记不会被冲掉**。

**认一次就够。** 同一家银行导出的表，格式一样，系统记住指纹，以后同类文件零成本。

**所以 1000 个 Excel，通常只有 3～5 种格式，也就是机器只需要猜 3～5 次。**

## 三、笔录、PDF 这些机器看不懂的东西怎么办

Excel 有表头有列，机器照着列拆就行。可笔录、PDF、扫描件、录音转写**没有列**——机器不知道哪句是人名、哪句是金额。这类材料只能交给 AI 读。

**但「交给 AI」不等于「把文件扔给 AI」。** 直接把一份 200 页的笔录丢进去，结果一定是漏一半、编一半。所以中间要隔一层东西，行话叫 harness，说白了就是**给 AI 套上缰绳**。

**第一步：切小。**
一份笔录切成几十段，一段一段交给 AI，每段都是一个独立的小任务。这样它不用一边记着前 199 页、一边看第 200 页。

**第二步：只许填表，不许自由发挥。**
我们不是问 AI「你看出什么了」，而是给它一张**固定的表**：这一段里有哪些人、哪些号码、哪些账户，谁跟谁说了什么，这句在第几段第几行。它只能往表里填，格式不对当场打回重填。**这是和「随便聊两句 AI」最大的区别**——它没法交一篇读后感糊弄过去。

**第三步：说出来的数，得回原文对得上。**
AI 说「张三转了 28 万」，系统就回那一段原文里找——有没有「280000」「28万」「280,000」这些写法，找得到才算数。找不到的，这条不认，标出来交给人。

**为什么非要回原文找一遍？** 因为**表填得再规范，数也可能是编的**。格式对不对，和数真不真，是两回事。

**第四步：填不出来就说填不出来。**
人名、号码、金额这三样，AI 拿不准的必须标「存疑」，不许猜。**猜出来的数字比没有数字更害人。**

**第五步：留底。**
每次用的哪个模型、什么版本的提示词、重试了几次，全都存着。将来这条数据出问题，能查到是哪一环出的错，而不是只剩一句「AI 说的」。

**第六步：人抽检。**
系统按比例把抽出来的结果拿去给人看，看错了就改，改了还能反过来修规则。

**所以 AI 抽出来的东西，身份是「自动抽取」，不是「已确认」。**
「已确认」只能由人按（见第九节那三个按钮）。**AI 负责把活干到七成，最后那一下必须是人。**

有一条最重要的边界：**AI 只碰机器搞不定的那部分。** Excel 那种有列有表头的东西用不着 AI，也不该用——一千万行流水让模型一行行读，又慢又贵还容易错。**能用笨办法算准的，就别用聪明办法猜。**

**某一段实在填不对呢？** 那一段单独标出来（文件后面亮黄三角），点开能看到「第 3 段，连续 3 次没填对」。其他段照常入库——**能用的先用，不为了十分之一让整份文件卡住。**

## 四、打开左栏，看看这个案子有什么

左栏有四个视图：**文件 / 实体 / 会话 / 能力**，点哪个就换哪个。

- **文件**：项目里的材料，还是文件树；每份文件处理到哪一步，看名字后面那个小标记（第二节讲过），右键还有「解析 ▸」；
- **实体**：人、号码、账户这些（下面细讲）；
- **会话**：这案子里的对话记录；
- **能力**：这个项目能用哪些技能、MCP、知识库——技能和 MCP 已经能用；**知识库目前只能看清单和授权，还不能发布、上下架**，这块本设计不碰，等知识库那一摊单独做。

**实体视图**分两级，因为左栏只有 280px 宽，放不下一屏幕东西。

**第一级**——按类型列一遍，带数量：

```
人      128
号码    436
账户    211
车辆     23
...
```

**第二级**——点「人」，列表原地换成人的名单，按「涉案程度」排序（谁出现得最多排最前）：

```
← 人 128
★ 张三    关联 37
  李四    关联 12
  ...
```

要找「张三」，直接在搜索框打名字，**不用先选类型**。

**没有展开、没有折叠、没有树。** 左栏是目录，不是地图。

## 五、在右栏问问题

这是民警用得最多的地方。右栏是 AI 会话，可以直接问：

> 「张三和李四什么关系？」

AI 不会凭印象答，它去**查库**（查的是本项目的数据，权限跟民警自己查一样）。

**它是怎么查的？** AI 不能直接连数据库——把库的钥匙交给模型太危险。做法是：后端把这些查询做成一台 **MCP 服务**（远程 HTTP 的那一种，不是每台电脑上装个本地程序），AI 只拿到「查人」「查流水」「查关系」这几个工具，每次调用都带着**当前民警的身份**，后端按这个身份去查。这样查出来的东西和民警自己查的一模一样，越权也是不可能的。

**谁有这组工具？** 管理员**授权一次**就行——可以给全员、给某个部门、或指定几个人。**不是每个项目配一遍，项目里不点任何「授权」按钮。**

授权之后，民警在哪个项目里干活就能用，但**只能查到那个项目的数据**：工具跟着人走，数据跟着项目走。

只有个别项目要收紧时，才需要单独处理——默认放开，例外才管。

然后这样回答：

> 两人共同出现在 3 个号码的通话记录中，累计通话 37 次；名下账户互相转账 12 笔，合计 86.4 万元。
> 〔出处〕话单-移动.xlsx 第 3 个工作表第 2041 行 …

**每一句后面挂着出处。**

回答格式固定三句话：**结论 → 依据 → 缺口**（哪些还没查到）。查不到就说查不到。

**还有些话没人问，系统自己会说。** 后台有一批固定规则一直跑着：同一个账户进出金额高度对称、通话双方和转账双方完全重合、一个号码短期内连着好几个不搭界的账户……命中了就在右栏顶上亮一条「新提醒 3 条」，点开在中栏看详情。**提醒只摆事实现象，认定还是人来下。**

AI 还能干这些：

- 「这个账户钱从哪来的？」→ 算进出、找异常
- 「这个号还在别的案子里出现过吗？」→ 拿它在**本项目所有材料**里比对（**串并案的活**；别的项目里的数据查不到）
- 「明天审张三，列个问题清单」→ 找事实缺口，指出哪里对不上

## 六、在中栏看

中栏是「看」的地方，可以开多个标签页，还能分屏。

默认是**文字和表格**：点一个人，出他的档案——基本信息、关联号码、关联账户、关联的人、出现在哪些事里。

想看结构就切到**关系图**，但有硬规矩：

- 只画这个人加他一两层的邻居；
- 节点最多 50 个；
- 边上直接标次数、金额。

**为什么不画全量图？** 400 个实体画在一张图里就是一团毛线，看不出东西。图是用来看「谁在中心、分几层、有没有闭环」的，不是用来看细节的。

点图上一个点，右栏出这个人的档案。

除了档案和关系图，中栏还能开另外两个：**事件时间线**（什么时候发生了什么，按时间排成一条线）和**资金流向**（钱从哪儿来、到哪儿去）。

## 七、写文书

> 「按现有证据起草提请批准逮捕书的事实部分。」

AI 从已经核实的事实里按时间顺序成文，**每一句都带出处**；证据不够的地方标黄，提示「此处缺材料支撑」。

民警的工作从「从零写」变成「改稿」。

**报告、文书这些产物不进数据库的事实层**——它们是结论，不是证据。但产物里的每一句，都链回它引用的那条事实，那条事实再链回原始材料。

**为什么这么设计？** 如果报告本身也变成「证据」，下次 AI 就可能引用「某份报告说……」来支撑结论，形成自我循环。这在办案上是硬伤。

---

## 八、抓获之后还要补

「张三还交代了一台手机，扣押了。」

这类没有文件的信息，直接在右栏说一句，AI 把它整理成一条待入库的记录，署名民警本人，系统走同一条流水线落库。

**注意界限**：AI 只能「新增」，**不能改已有数据**。要改，只有民警能改。

## 九、发现数据错了怎么办

点开任何一条事实，底下有三个按钮：

**✓ 对　✗ 错　？存疑**

选「错」，写一句话说明原因，再选是哪一类错：

- 列认错了（修映射）
- 人认错了（修规则）
- 原件本身有问题（标材料）

**系统不删数据，只打状态。** 被排除的数据不进统计、不进 AI 回答，但还留着——因为「这里曾经判错过」本身就是信息。

同一个人有两个名字、同一个账户两种写法，可以**合并**；并错了，**一键拆开**。

改完之后，引用它的事实会标「依据已变更」，引用它的报告会提示「依据有更新，请复核」——**不能让一份写着旧结论的报告安安静静躺在文件夹里**。

所有修改留痕：改前、改后、谁改的、为什么。法制和领导随时能查。

**AI 自己提的建议也记账。** 它说「这两个账户可能是一个人的」，这条会记下：提了什么、为什么提、你最后是采纳了还是否了、为什么否。

将来复盘「这个错为什么一直没改」，查得到是谁在什么时候做了什么决定——**而不是只剩一句吵架：我当时以为 AI 是对的**。

## 十、整套东西背后是怎么存的

用仓库打个比方：

| 层 | 是什么 | 类比 |
|---|---|---|
| **原始层** | 文件原样放着 | 进货的箱子，一个都不扔 |
| **事实层** | 五张表：材料、实体、关系、事件、引用，外加一张明细行表 | 仓库的货架，按品种分类摆好 |
| **判断层** | 报告、文书 | 出货，交给客户的成品 |

箱子永远在，货架可以重新摆。**这就是「错了能重算」的底气。**

1000 个 Excel 约上千万行，用 PostgreSQL 分区存、批量写入、单队列慢慢消化，够用。

## 十一、一句话总结

**民警做的事只有三件：把文件拖进来、用大白话问、改 AI 写好的稿。**

系统做的事是：把文件里的东西拆成人、号、账户、时间、金额，记住它们之间的连线，记住每句话出自哪一行；然后随时准备被问，并且每一句答话都指得回原件。

**收益不在图表好看**，在于：少翻十次 Excel、关联不会漏、串并案一眼看得出来、写文书有出处、换人接手不用重新翻卷宗。
