## 0. 一句话

**把案子里的证据材料变成系统能记住、能查、能引用的东西，让民警用大白话问，AI 用本项目的真实数据答，每一句都指得回原件。**

---

## 1. 业务背景

### 1.1 案件研判信息

前期收集的证据——话单、资金流水、视频资料、人员背景、团伙结构——加上加工出的情报；抓获嫌疑人之后还会继续补充：提取的物品、涉案信息。

这批信息有三个特点：

1. **多**，人记不住；
2. **内部有关联**（谁给谁打电话、谁给谁转钱、谁和谁同时出现在同一地点），关联藏在数据里，不在任何一个人的脑子里；
3. **一直在长**，不是一次性录完。

办案的本质，是拿这些信息去印证审讯和询问，**还原事实真相、确定谁有罪、谁罪重谁罪轻**。

系统的价值就是：**人记不住的部分由系统记住，人看不出来的关联由 AI 接线，人负责判断。**

## 2. 设计原则

| # | 原则 | 落到哪 |
|---|---|---|
| P1 | **项目是唯一的边界** | 权限、检索、备份、清理全按 `project_id` |
| P2 | **导入永不阻塞** | 没有任何「请先配置」的关卡；认不出来也照样入库 |
| P3 | **原始数据永不丢，事实可以重算** | 原始层原样留存，事实层可整批重放 |
| P4 | **每一句结论都带出处** | 事实必带引用；AI 回答必带引用 |
| P5 | **导入环节人的动作只有两个** | 把文件拖进来、看汇总报告。其余全自动 |
| P6 | **不新增聊天入口** | 沿用现有三栏会话 |
| P7 | **业务数据独立 PostgreSQL** | 不进每用户 SQLite；按项目做行级隔离 |

## 3. 边界模型：项目

**系统里只有「项目」，没有「案件」这一层实体。**

- 一个项目可以是一次案件/事件，也可以是一串案件/事件；
- `project_id` 是权限、检索、清理的唯一依据；
- 实体（人、号码、账户、物证）**不跨项目共享**，每个项目自成一套事实图。

**协作边界由项目本身承担**：项目分**私有**与**共享**两种（现有能力，`type: private | shared`，共享项目带成员与成员数）。本设计**不新增协作模型**——谁能进项目、谁看得见，沿用它；项目内的每一次修改都按 §9.6 留痕，可回溯到人。

## 4. 数据分层

```
原始层  材料原样存（文件 + 原文）
   ↓ 解析 / 抽取（可重放）
事实层  五张事实表（材料/实体/关系/事件/引用）＋ 明细行表
   ↓ 分析
判断层  结论、报告、文书 → 落回项目文件树（产物）
```

### 4.1 原始层

项目文件树里放什么，就原样留什么：Excel、PDF、图片、音视频、Word。文件本身 + 抽取出的文本（OCR / ASR 结果）一起保存。

**原始层只增不改。** 它是一切事实的来源，也是重算的底本。

**引用不按路径走**：事实指向「材料 ID ＋ 内容指纹」，不指向文件路径。文件被移动、改名，按指纹重新定位，事实不受影响（判据 A5）。

### 4.2 事实层（五张事实表 ＋ 明细行表）

| 表 | 一条记录是什么 | 关键字段 |
|---|---|---|
| `material` 材料 | 一份文件 / 一份笔录 | `project_id`、文件名、材料类型（话单/资金/笔录/视频/物证照/产物/其他）、指纹、当前路径、文本、入库时间 |
| `entity` 实体 | 一个具体对象 | `project_id`、类型（人/号码/账户/虚拟身份/车辆/物品/地点/组织）、规范值、别名、属性、可信状态 |
| `relation` 关系 | 两个实体之间的一条连边 | `project_id`、主体、客体、关系类型（通话/转账/**实名登记**/**实际使用**/同案/持有/同行）、首末时间、次数或金额汇总、**认定依据**、来源引用 |
| `event` 事件 | 时间点上的一个动作 | `project_id`、类型、发生时间、参与实体、摘要 |
| `citation` 引用 | 一条事实的原始出处 | `project_id`、事实类型+事实 ID、材料 ID、定位（表名/行号/页码/时间段）、抽取方式（机器/人工）、置信度 |

**每张事实表都带可信状态**（§9.1），新建时默认「自动抽取」。

#### 明细行表（分区表）

五张之外的第六张，也是量最大的一张：`fact_row` **明细行**——表格类材料拆出来的每一行。字段：`project_id`、`material_id`、工作表名、行号、标准字段（主叫 / 被叫 / 时间 / 时长 / 金额 / 余额 / 对方账号……）、`extras`（没认出来的列原样存 jsonb）、指纹。

它按 `project_id` 分区，量级在千万行，是事实层的原料：不直接给民警看，只供抽取与统计。

#### 时间的四个字段

每一行明细、每一条事实的时间，都存成四件东西：

| 字段 | 内容 |
|---|---|
| **原始值** | 原文照抄，**永不改写** |
| **规范值** | 统一换算到 UTC+8 |
| **精度** | 到日 / 到分 / 到秒 |
| **时间类型** | 发生时间 / 记录时间 / 入库时间 |

**为什么必须分开**：不同材料的钟不是同一个钟。银行流水记的是**记账时间**（跨行 T+1，可能与实际发生差一天）；监控是**设备时间**，偏移可达几分钟；笔录是**叙述时间**，由人回忆给出。不区分就拿来比，会得出站不住的结论。

规则：

- 跨源比对（同时出现、同行、同案时间线）**只用规范值**，界面必须标明「基于规范值，精度到分」。
- 设备时钟有偏移的，在 `material` 上记一个 `时钟偏移` 修正量：**修正量只参与规范值的计算，不动原始值**。
- 精度不同的不能混着比：到日的与到秒的只能算「同日」，界面不许把它说成「同时」。

**引用是这张图的地基**：任何一条事实都能顺着它回到「哪个文件、哪一行、哪一段」。

#### 三类事实

| 类型 | 是什么 | 例 | 落在哪 |
|---|---|---|---|
| **存在事实** | 谁 / 什么是什么 | 138****1234 登记在张三名下 | 实体属性 |
| **行为事实** | 谁在何时对谁做了什么 | 张三向李四转账 28 万 | 事件 ＋ 关系 |
| **陈述事实** | **谁说了什么** | 李四在讯问中说「钱是张三让我收的」 | 事件（类型=陈述，参与实体=说话人）＋ 引用 |

陈述事实必须带说话人，**不等于客观事实**。「数据表明两人通话 37 次」与「李四说他们不熟」是两条不同的事实，两者的冲突本身就是审查要点。

#### 关系：数据说的与人说的

**号码登记在张三名下，不等于张三在用。** 这条必须落进模型，不能靠人记得。

| 关系 | 谁说的 | 依据 |
|---|---|---|
| **通话 / 转账** | 数据直接记录 | 引用即依据 |
| **实名登记** | 数据直接记录 | 引用即依据——但它**只证明「登记」，不证明「在用」** |
| **实际使用** | 人认定 | **必填**，缺依据不入库 |
| **同案 / 持有 / 同行** | 人认定 | **必填** |

认定依据取值：`供述指认` / `扣押实物` / `技侦` / `登录或使用日志` / `资金闭环` / `推断`。

规则：

- **「实际使用」缺依据不入库**，进「待补依据」清单，界面上是灰色的「待认定」，不参与关系图的主体排序。
- **认定强度可比较**：数据直接记录 > 人认定＋实物/技侦 > 人认定＋供述 > 推断。默认按强度排序与着色，档案页和关系图**必须一眼分得出「数据说的」和「人说的」**。
- AI 只能提「疑似实际使用」并附**建议的依据类型**，采纳与否由人（§9.5）。

#### 与公安六类要素的对应

| 六类 | 在本方案里 | 常见内容 |
|---|---|---|
| **人** | 实体（类型=人） | 嫌疑人、证人、受害人、关联人；身份、绰号、别名 |
| **事** | 事件 | 一笔转账、一次通话、一次同行、一次抓获 |
| **地** | 实体（类型=地点） | 住址、场所、基站、卡口 |
| **物** | 实体（类型=物品） | 手机、车辆、银行卡、扣押物品 |
| **网** | 实体（类型=号码 / 账户 / 虚拟身份） | 手机号、银行账号、微信/QQ、IP、设备串号 |
| **组织** | 实体（类型=组织） | 团伙、公司、家庭 |

**关系不属于任何一类**——它把六类串起来。六类各自建库是「档案」，串起来才是「案子」。

### 4.3 判断层

结论、分析报告、法律文书**不进事实层**，作为**产物落回项目文件树**——这是 openhive「能力内核 → skill → 产物」三层架构的自然延伸。产物带版本，可回溯、可下载、可交付。

产物在 `material` 表登记一条（类型=产物），**不解析成事实**；正文里的引用标记（如 `[[fact:<id>]]`）在保存时解析回 `citation`，形成「产物 → 事实 → 原始材料」的单向链条。

## 5. 数据怎么进表

### 5.1 三条入库路径

| 路径 | 进来的是什么 | 谁触发 |
|---|---|---|
| **文件拖入** | 书面材料、PDF、图片、音视频 | 民警拖文件 |
| **表格导入** | 话单、资金流水等批量 Excel/CSV | 民警拖文件 |
| **对话录入** | 没有文件的口头补充、物证信息、抓获后新增 | 民警在右栏说，AI 结构化成待入库记录 |

三条路走**同一套流水线**，出口都是事实层。

### 5.2 流水线六步（后台异步）

六步全程在后台跑，**不占用民警的时间**。

1. **落库**：文件原样进项目文件树，算指纹（内容哈希）。
2. **识别**：判断材料类型与格式（按文件头、表头、内容特征）。
3. **结构化**：文本抽取（OCR/ASR）；表格按自动识别出的列映射拆成明细行。
4. **抽事实**：从明细行与文本中抽出实体与关系。表格走**确定性抽取**（列映射 → 实体/关系）；笔录、PDF、图片、纪要这类**没有列的材料**走 **AI 抽取流水线**，见 §7.4。
5. **建引用**：每一条事实写一条 `citation`，指向具体行号或段落。
6. **跑比对**：触发规则集，命中就形成提醒。

#### 文件的处理状态（§8.1 的标记就取这里的值）

状态落在 `material.parse_status` 上，**文件级**，不是前端状态——换人、换机器打开都一致。

| 状态 | 什么情况 | 界面上 |
|---|---|---|
| 未入队 | 系统判定不进事实层（§5.5），或刚落库还没排进队列 | 不标 |
| 排队中 | 已进 `ingest_job`，还没轮到 | ○ |
| 解析中 | 正在跑 | ◐ |
| 已解析 | 抽完了，没有待处理的问题 | ✓ |
| 有问题 | 跑完了但没抽干净（字看不清、格式不认、AI 反复校验不过），或任务失败 | ! |
| 已跳过 | 民警明确说不用解析 | 不标（悬停说明「你跳过的」） |

四条规则：

- **「已完成类」状态只由作业推进**：点了「解析入库」不会立刻变「已解析」，得等作业真跑完——界面要说真话。人只能直接改**意图**（入队 / 取消 / 跳过），改不了「已完成」。
- **「有问题」必须能点开看原因、能重试**；做不到这两点的黄色标记等于没有。
- **「未入队」与「已跳过」视觉上都不标**，区别在悬停文案和右键菜单项——跳过是人的意志，系统不再问。
- 这一列是**文件处理到哪一步**，与 §5.4 的「解析进度」（数据行级）、§9.1 的「可信状态」（对不对）是三件事，不合并。

**「未入队」有两种成分，要分开看**：**系统判定不解析**（等民警用右键把它推进去）、**刚落库、马上就要排队**（不用人管）。后者不给「解析入库」入口——它本来就会自己动。区别就是「有没有进队列」这件事本身，不新增状态。

**队列位次不进状态枚举**：悬停文案里的「前面还有 N 个」取自 `ingest_job` 的排队序号，`material.parse_status` 里没有这个值。

### 5.3 幂等与重放

- **幂等**：文件指纹 + 行号做唯一键。同一个文件重复拖入**不产生重复数据**。
- **重放**：解析器升级、列映射修正、抽取规则调整之后，**一条命令重跑事实层**——原始层不动，引用重写。修正的代价是分钟级。
- **重放不丢人工结论**：按事实主键（材料 ＋ 行号 ＋ 实体规范值）比对，人工打的「已确认 / 已排除 / 存疑 / 修正值」原样保留；只有取值真的变了的才标「依据已变更」。

### 5.4 每条数据带三个维度

| 维度 | 取值 | 用途 |
|---|---|---|
| **来源** | 哪个文件、哪一行 | 可追溯、可举证 |
| **解析进度** | 原始 / 已解析 / 已归并 / 待补 | 知道**这一行**还没进事实层 |
| **出处方式** | 机器抽取 / 人工录入 | 分得清「数据说的」和「人说的」 |

> 三种「状态」不要混用：**文件级**处理状态在 §5.2 末（`material.parse_status`，界面上的 ○◐✓! 就是它）；本节是**数据行级**进度；§9.1 的「可信状态」说的是这条数据**对不对**。

「解析进度」四个值的含义：**原始**＝只落了库、还没拆；**已解析**＝已拆成事实；**已归并**＝并进了别的实体或事实（§9.3）；**待补**＝缺关键字段，等人补。

### 5.5 哪些文件进事实层

| 类别 | 例子 | 处理 |
|---|---|---|
| **外部证据材料** | 话单、资金流水、笔录、视频、书证 | **解析进事实层**，每条事实带引用 |
| **我们生产的产物** | 分析报告、法律文书、图表、草稿 | **只登记不解析**（`material` 一条，类型=产物）；保留「引用了哪几条事实」的回链 |
| **探索中间文件** | 临时导出、脚本输出、截图、对照表 | **默认不解析**；可手动「提升为材料」 |

判断标准：**这是别人给我们的原始材料，还是我们自己生产出来的东西？**

**默认判定可以被人工覆盖，但产物不行。** 系统判为「不解析」的**探索中间文件**，民警在文件上右键「解析 ▸ 解析入库」即强制入队，并记下是谁让它入的队；判为要解析的，也能「解析 ▸ 跳过解析」。**默认值负责大多数情况，右键负责例外**——不让一条默认规则把用户钉死。入口见 §8.1。

**产物那一格不是默认值，是硬边界**：报告、文书一旦进了事实层，下一轮就会被当成「证据」引用回去，形成自我循环。所以「解析入库」对产物不亮，也不给绕路。产物只保留回链，链条的另一端永远是原始材料。

解析深度按材料类型分级：表格 → 明细行；文字类 → 文本抽取 ＋ 全文检索；音视频 → 先登记，后台转写后再补。

### 5.6 分批导入，不阻塞

- **可以分多次、不同时间拖进来**：今天导话单，明天导流水，抓到人之后补扣押清单。系统不要求一次导完，也不催人「一次拖齐」。
- **导入在后台队列里跑**（`ingest_job`），民警不用等：已经入库的数据随时能看、能问，界面上只给一个进度提示（文件树顶那条，逐文件的状态见 §8.1）。
- **新数据只做增量**：只处理新文件，已入库的不重算；新抽出的事实参与规则比对，形成新提醒。
- **重复拖同一个文件不会重复入库**（幂等，见 §5.3）。

## 6. 表格数据的自动识别（零配置）

**列映射不由人配置。** 人只负责把文件拖进来。

### 6.1 三层识别，逐层兜底

1. **表头词典**：`主叫/被叫/对方号码/通话时间/时长/基站`、`交易时间/金额/余额/对方账号/摘要` 等固定说法直接对上。
2. **数据特征**：整列 11 位数字 → 手机号；整列 `yyyy-mm-dd hh:mm:ss` → 时间；整列带两位小数的正负数 → 金额。
3. **模型兜底**：前两层都对不上时，把「表头 + 三行样例 + 目标字段清单」交给模型给出映射建议。

### 6.2 认一次，以后全自动

用列名集合 + 数据特征算出**格式指纹**，认过的格式连同映射**沉淀在系统里**。同一家银行、同一家运营商导出的表指纹相同——第一次靠模型猜，第二次开始零成本。

> 1000 个 Excel 通常只有 3–5 种格式，也就是**一共只需要机器猜 3–5 次**。

### 6.3 认不出来也入库

没认出来的列**原样作为扩展列保存**，事实层只建认得出的部分。导入照常完成，**不弹窗、不阻断**。

### 6.4 事后看报告，不事前审批

导入结束后给一张**汇总表**：成功多少、有几个文件需要注意、点开看详情。报告是事后查阅，不是事前关卡。

### 6.5 量级

1000 个 Excel 的资金数据约在千万行级。方案：

- `fact_row` 明细行表按 `project_id` 分区（§4.2）；
- `COPY` 批量写入；
- 导入任务进 `ingest_job` 表，**单 worker 顺序消费**，断点可续；
- PostgreSQL 单库即可承载，读写分离与归档留到数据量增长后再加。

## 7. AI 怎么用这些数据

### 7.1 走工具，不走裸查

AI 通过一组**只读工具**访问事实层，以**民警本人身份**执行（权限与手工查询完全一致）。

| 工具 | 回答什么问题 |
|---|---|
| `search_materials` | 材料里有没有提到某人/某号/某词 |
| `query_entities` | 本项目有哪些账户/号码/人，属性如何 |
| `query_relations` | 谁和谁之间发生了什么，多久、多少次、多少钱 |
| `query_events` | 某时间段内发生了什么 |
| `aggregate_money` | 某个账户的进出、余额走势、异常点 |
| `find_crossings` | 两人/两账户的共同号码、共同账户、共同时空 |
| `get_citation` | 这条事实的原始出处 |

**只读的边界**：AI 不能修改事实层。唯一的写动作是「对话录入」——民警口述、AI 结构化成一条**待入库记录**（署名民警本人），由系统走同一条流水线落库。这不算「改已有数据」，改数据仍然只有民警能做（§9.5）。

#### 这组工具怎么送到 AI 手里

AI **不直连数据库**——那等于把库的凭据和权限交给模型。做法是把上面这组工具做成**一台 MCP 服务**，挂在 openhive 后端：

| 项 | 定法 | 理由 |
|---|---|---|
| **形态** | **独立服务**，以 `remote`（HTTP）MCP 暴露，**不是 `local`** | local 要在每台机器上起进程、还得把数据库凭据放本机，安全和运维都过不去 |
| **下发** | 由内核监督器把这一条 upsert 进**全局**配置（同治理 server 的做法，`server/openhive/governance-mcp-supervisor.ts`），不是人手装一份、也不是按用户各发一份 | 与 `2026-11-02-ai资产MCP全流程-design.md` 的「配置由服务端权威生成」一致。⚠️ `buildUserMcpConfig()`（`packages/asset-service/src/downlink.ts`）**生产上没有调用点**，且它产的是按用户的 stdio 条目，与本条形态不符，不沿用 |
| **谁能用** | 走现成的资产可见范围（`global` / `department` / `targeted` / `personal`）＋ capability「可见即可用」，**一次授权，不是每个项目配一次** | 项目不是授权单位，是数据边界 |
| **身份** | 每次调用由内核注入 `_meta["openhive/user"]` 与 `_meta["openhive/directory"]`（`mcp/openhive-identity.ts`） | 网关按这个身份取数，PG 的受限账号 / RLS 兜底；不信任客户端传参，不读会话字段 |
| **留痕** | 每次调用记一条使用记录 | 与现有 MCP 使用记录同一口径 |
| **写** | 只读；`对话录入` 走单独的后端入口 | 见上「只读的边界」 |

**两层分开，别混：**

| 层 | 决定什么 | 谁配、配几次 |
|---|---|---|
| **工具授权**（资产可见范围） | 谁**能用**这组工具 | 管理员配**一次**：全员 / 某部门 / 指定几个人 |
| **数据边界**（项目） | 用的时候**能看哪些数据** | 不用配。身份里带当前项目目录，网关只返回这个项目的数据 |

所以：**项目里不需要点任何「授权」按钮**。民警进到哪个项目，工具就在那儿，查的也只有那个项目的数据。只有个别项目要收紧（不让用这组工具）时，才需要单独处理——**默认放开，例外才收紧**。

#### 代码放哪：独立服务，放在工作区的 `mcp\` 下

这台 MCP **不写进主仓库的 `packages/`**，而是与已有的 GoNavi 并列，放在工作区：

```
D:\project\study\openhive\
├── openhive\                 主仓库（内核 + 前端 + 资产服务）
└── mcp\
    ├── GoNavi\               已有的 MCP server（独立 git 仓库）
    └── openhive-case-mcp\    本设计的数据网关（新建，独立 git 仓库）
```

约定：

| 项 | 定法 |
|---|---|
| **一个服务一个目录** | 与 GoNavi 同级、同形状，便于统一管理 |
| **独立 git 仓库** | 自己的 `origin`（私有），不跟主仓库的发布节奏绑定 |
| **独立部署** | 自己的启动方式与端口；崩了不影响内核 |
| **内核只认一条配置** | `mcp.openhive-case-mcp = { type: "remote", url }`，由 supervisor 写入（同治理 server 的做法） |
| **身份不靠进程边界** | 仍走每次调用的 `_meta`，与它是不是独立进程无关 |

> 这偏离了「项目产物一律放内层仓库」的一般约定，理由是它与其他 MCP server 同属**独立交付物**；版本化由它自己的仓库承担。

### 7.2 回答的固定格式

**结论 → 依据（引用到材料/行/时间段）→ 缺口（哪些还没查到）。**

不允许「凭印象」回答。查不到就说查不到。

### 7.3 主动提醒

一批**固定的比对规则**常驻运行，命中即形成提醒（例：同一账户短期内进出金额高度对称、通话双方与转账双方完全重合、某个号码在短期内关联了多个互不相干的账户）。

提醒落入 `alert` 表（规则 ID、命中的事实、时间、已读/已处理状态）；右栏会话顶部给一个「新提醒 N 条」的入口，点开在中栏看详情。

提醒只陈述数据事实，结论由人下。

### 7.4 非结构化材料：AI 抽取与 harness

§6 的三层识别管的是**表格**——表头、数据类型、样例，全是确定性的。笔录、PDF、图片、录音转写这类**没有列的材料**，只能交给模型读。

**交给模型 ≠ 把文件丢给模型。** 中间那层就是 harness。

#### 复用内核的哪几样

| 内核能力 | 代码位置 | 在这里的作用 |
|---|---|---|
| **skill** | `packages/opencode/src/skill/index.ts`、`tool/skill.ts` | 抽取口径写成 SKILL.md（抽哪几类、什么算一件事、怎么给出处、抽不出怎么说）；**可按项目覆盖**——项目级技能优先级档位最高（`TIER.project = 4`） |
| **task 子代理** | `tool/task.ts` | 一段材料一个子会话，上下文互不污染；`background=true` 后台跑；失败可凭 `task_id` 续跑 |
| **tool ＋ Schema** | `tool/tool.ts`（Effect Schema 定义入参）、`tool/json-schema.ts` | 子会话只拿得到一个「**提交事实**」工具，形状写死；吐不出合法结构当场报错重来 |
| **会话存档** | session / message 存储 | 每次抽取的输入、模型、重试次数自动留痕，直接就是审计链 |
| **后台作业** | `background/job.ts` | 长跑批处理与完成通知 |

内核给的是「能可靠跑完**一个**子任务」的能力，**不是**「能可靠抽完**一千份**文件」的产品。后者要自己写，就是下面五层。

#### 五层 harness

| 层 | 做什么 | 省掉会怎样 |
|---|---|---|
| **任务壳** | `ingest_job`：文件指纹 → 切片 → 每片一个子任务；幂等、可重放、可取消 | 重跑就重复入库 |
| **上下文装配** | 只喂这一片 ＋ 抽取口径 ＋ 几条已确认样例（few-shot）；200 页笔录**不能整份塞** | 塞整卷宗 ⇒ 漏抽、串号、成本失控 |
| **结构约束** | 只能调「提交事实」工具；实体类型、关系类型走枚举；出处字段必填 | 吐自由文本 ⇒ 下游没法比对上表 |
| **校验与重试** | **两层**：先校形状（Schema），再校内容（回读原文，见下）；不过就重来（上限 N 次）；人名 / 号码 / 金额缺失 ⇒ 标**存疑**转人工，**不硬猜** | 直接写库 ⇒ 错数据静默流入 |
| **留痕与抽检** | 存模型名 ＋ 版本、prompt 版本、重试次数；按比例人工抽检；同一片换模型重跑比对 | 出问题说不清是哪一环 |

#### 两层校验：先校形状，再校内容

只做结构校验挡不住幻觉——**「张三向李四转账 28 万」Schema 完全合法，28 万可能是编的**。

| 层 | 校什么 | 不过怎么办 |
|---|---|---|
| **结构校验** | 字段齐全、类型对、枚举值合法、出处字段非空 | 把错误回给模型重来 |
| **回读校验** | 抽出的每个原子值必须能在**这一段原文**里定位到 | 该原子值**置空**（不进正式字段）、这条事实的可信状态置**存疑**（§9.1），并在切片上记一次「无法回读」 |

回读怎么比：

- **号码**：去掉分隔符后逐位比对。
- **金额**：先归一（千分位、`万` / `亿`、大小写数字、括号负数），再比数值。
- **时间**：按精度比，到分的不会去比秒。
- **人名**：允许「张叁 / 张三」这类形近差异，但必须命中同段落相邻文本。

回读通过率是**抽取质量的公开指标**，进导入报告（§6.4）。定位不到的数值宁可空着交给人——**错数字比没数字害人**。

#### 三条不能破的边界

1. **AI 只做确定性方法做不了的部分。** 表格走 §6，第三层兜底才调模型；**只有非结构化材料进 AI 流水线**。绝不让模型逐行读千万行流水。
2. **归一化不交给模型。** 同一个「张三」在五个切片里各被抽一次，由实体解析（规则 ＋ 相似度 ＋ §9.3 人工合并）收口，不靠 prompt 里叮嘱「别忘了张三」。
3. **AI 抽出来的一律是「自动抽取」状态**，不是「已确认」。✓ 只能由民警按（§9.1）——这正是 §9 那三个按钮存在的理由。

#### 校验不过怎么办

- 同一片重试 N 次仍不过（结构或回读）⇒ 该片标 `有问题`，**文件级状态跟着变**（§5.2），界面黄三角，点开显示「第 3 段（第 1201–1400 行）：2 处无法回读、连续 3 次未通过结构校验」。
- **部分成功照常入库，不整份回滚**——能用的先能用，缺的那段标出来让人补。
- 换模型或改 prompt 之后，用同一批切片重跑抽样比对，差异进抽检清单，不静默覆盖已确认结果。

## 8. 界面

**沿用现有三栏，不新增聊天入口。**

| 栏 | 是什么 | 干什么 |
|---|---|---|
| 左栏 | 项目导航 | 项目切换 ＋ 文件 / 实体 / 会话 / 能力四个视图 |
| 中栏 | **展示区** | 标签页：打开的文件、表格、文档，也能把某场会话摊开来看；可分屏 |
| 右栏 | **AI 会话本体** | 提问、输入、AI 调工具干活 |

**会话发生在右栏，内容展示在中栏。** 中栏是「看」的地方，右栏是「问」的地方。

民警的日常动作：拖文件 → 看导入报告 → 在右栏问 → 中栏看图 / 看表 → 点引用回到原始行 → 让 AI 起稿 → 自己改定。

**左栏四个视图**：**文件 / 实体 / 会话 / 能力**，切换即替换整栏内容，不并排。能力视图已有（技能、MCP、知识库的清单与授权），**本设计不改它**。⚠️ 其中知识库只到「清单 ＋ 可见性授权」，**发布与上下架的生命周期还没实现**（`packages/asset-service/src/service.ts:667` 抛 `unsupported_asset_type`，前端也因此不画启用按钮），本设计不补这一块。下面讲两处新增：文件视图加**处理状态标记 ＋ 右键解析入口**（§8.1），以及新增的**实体视图**（§8.2）。

### 8.1 左栏：文件视图（状态标记与右键菜单）

左栏最宽 280px（窄时可收到 160px，见 §8.2），按 280px 算，一行只放得下「缩进 ＋ 图标 ＋ 名字 ＋ 一个标记」。名字那格已经是 `flex-1 truncate`（`packages/app/src/project/file-tree.tsx:860`），标记追加在右端、`shrink-0`，代价只是长文件名早 14px 出省略号。

#### 状态标记

```
📄 话单-移动.xlsx        ◐
📄 笔录-张三.pdf          ✓
📄 会议纪要.docx          ○
📄 影像-案发现场.mp4
```

| 标记 | 状态（§5.2） | 悬停文案 |
|---|---|---|
| ○ 空心圈 | 排队中 | 「排队中，前面还有 37 个」 |
| ◐ 加载圈 | 解析中 | 「正在识别，约 2 分钟」 |
| ✓ 对勾 | 已解析 | 「已抽出 1 人、3 号码、2 账户」 |
| ! 三角 | 有问题 | 「3 段未通过校验，点击查看」 |
| —— 不标 | 未入队 / 已跳过 | 说清是「系统不解析」还是「你跳过的」 |

| 规则 | 为什么 |
|---|---|
| **默认不标，只有进过流程的才带标记** | 1000 个文件里大多数是产物和无关材料；满屏标记等于没有标记 |
| **形状与颜色同时变**，每行带 `aria-label` | 只靠颜色 = 色盲用户看不见（同这个文件树用 `aria-expanded` 而不是箭头朝向的做法） |
| **目录行显示汇总**（如 `3/12`） | 不展开也知道这堆里还有多少没解析 |
| **树顶部一条总进度**：`已解析 987 / 1000 · 3 个有问题` | §5.6 说的「文件树顶那条进度提示」落在这里 |
| 标记只表达**文件处理进度**，不表达数据对不对 | 对不对看 §9.1，一件图标不背两件事 |

**状态从 `material.parse_status` 读**（§5.2），不是前端本地状态。

#### 右键菜单：解析收进二级菜单

文件树右键菜单现有六组（`file-tree.tsx:910`）。解析相关动作直接铺开会让菜单长到看不清，所以**只加一个一级项「解析 ▸」，其余全收进二级菜单**，位置在「打开」之后自成一组。

```
打开
────────────────────
解析 ▸  ✓ 已解析        ← 一级项右端显示当前状态
────────────────────
新建文件 / 新建文件夹
────────────────────
重命名 / 复制 / 移动 / 删除
────────────────────
上传 / 上传文件夹 / 下载
────────────────────
备份到 MinIO / 从 MinIO 拉回
────────────────────
文件路径 / 刷新
```

展开「解析 ▸」：

| 二级项 | 什么时候亮 | 点了怎样 |
|---|---|---|
| 解析入库 | 系统判定不解析（§5.5）/ 已跳过；**产物、刚落库待排队的都不亮** | 强制入队，置顶优先；记下是谁让它入队的 |
| 重新解析 | 已解析 / 有问题 | 提示「将重建这份文件的全部事实；你打的 ✓ / ✗ / ？ 标记会保留」（§5.3） |
| 取消解析 | 排队中 / 解析中 | 排队中 → 回「未入队」；解析中 → 停下，**已提交的切片保留**，状态转「有问题」并注明「用户取消」 |
| 跳过解析 | 未入队 / 有问题 | 标「已跳过」，不再出现在待办里 |
| 查看解析结果 | 已解析 / 有问题 | 中栏开「抽取结果」标签页 |

**「解析入库」对产物不亮**——那一格不是默认值，是硬边界（§5.5）。「落地即排队」的文件也不亮：它本来就会自己动，给了按钮反而让人以为要手动推。

| 规则 | 为什么 |
|---|---|
| **人工优先于系统判定**（§5.5） | 默认值是默认值，不是禁令；用户比系统清楚哪份材料重要。**唯一的例外是产物**，那一格不开放 |
| **记「谁让它入队的」** | 以后「这条事实哪来的」要能答成「张三 10 月 12 日手动指定解析」 |
| **必须给「跳过解析」** | 没有这个口子，用户看着一个永远黄着的文件没办法，最后学会无视黄色 |
| 目录右键**先弹确认**：「将解析这个文件夹下的 47 个文件」 | 不能一点就炸 |
| 重复点**不重复入库** | 人工触发也走同一条队列、同一套幂等（§5.3） |

### 8.2 左栏：实体清单（两级下钻）

左栏宽 160–280px，**一屏只放得下一列**。所以用**两级下钻**：横向筛选条放不下，平铺全量列表滚不到头，都不用。

**第一级 —— 类型导航**

```
│ [🔍 搜人/号码/账户 ]  │
│                       │
│ 👤 人            128  │
│ 📱 号码          436  │
│ 💳 账户          211  │
│ 🚗 车辆           23  │
│ 📦 物品           67  │
│ 📍 地点           89  │
│ 🏢 组织            6  │
└───────────────────────┘
```

**第二级 —— 点进去，列表原地替换**

```
┌ 左栏 280px ──────────┐
│ ← 人 128              │
│ [🔍 搜索 ]            │
│ ───────────────────── │
│ ★ 张三      关联 37   │
│   李四      关联 12   │
│   王五      关联  8   │
│   …                   │
└───────────────────────┘
```

**是「替换」，不是「展开」**——同一时间只有一列，不嵌套、不叠加，所以它不是手风琴。

| 规则 | 为什么 |
|---|---|
| 搜索永远在最上面，**跨类型直接搜** | 民警日常是「找张三」，不该先选类型；输入直接出结果，行首标类型 |
| 第二级默认按**涉案程度**排序（出现次数、关联事实条数），可切名称 / 时间 | 436 个号码不至于滚到崩溃，关心的几个在最上面 |
| 支持虚拟滚动 | 大类型不卡 |
| **星标**两级都置顶 | 民警盯的几个人永远第一屏能点到 |
| 数量为 0 的类型不显示；新类型自动出现 | 类型是字典，可扩展 |

### 8.3 中栏：多种视图，按需打开

| 视图 | 回答什么 |
|---|---|
| 文件 / 表格 | 原件长什么样 |
| 实体档案（文字＋表格） | 这个人具体是什么情况——**默认视图** |
| 事件时间线 | 什么时候发生了什么 |
| 关系图 | 结构是什么（谁在中心、分几层、有没有闭环） |
| 资金流向 | 钱从哪儿来、到哪儿去 |

**默认是文字与表格，图是按需打开的视图。** 图适合看结构，不适合看细节；实体一多，全量图会糊成一团。

关系图的硬限制：只画**当前选中实体 ＋ 1～2 跳邻居**，节点上限约 50，可按关系类型筛选，边上直接标次数 / 金额。点节点 → 右栏出档案。

档案页顶部先给一句文字结论（例：「张三是本项目核心节点：3 个号码、2 个账户、与 5 人有过资金往来」），**图用来验证这句话，不替代它**。

## 9. 纠错与可信度

**不删除，只打状态。** 错误本身也是信息——它说明材料有歧义，或这里曾经判错过。

### 9.1 可信状态

| 状态 | 含义 | 谁打的 |
|---|---|---|
| 自动抽取 | 机器抽出，无人看过 | 系统 |
| 已确认 | 有人看过并认可 | 民警 |
| 已修正 | 改过值，保留原值 | 民警 |
| 已排除 | 判定为错，不参与计算与回答 | 民警 |
| 存疑 | 拿不准，先标着 | 民警；**回读或结构校验不过时由系统自动置**（§7.4），不是「无人看过」 |

已排除的数据不删，只是不进统计、不进 AI 回答，可切换查看。

### 9.2 纠正入口

详情页底部三个按钮：**✓ 对 / ✗ 错 / ？存疑**。选「错」时写一句话并选原因：

| 原因 | 例 | 该修哪一层 |
|---|---|---|
| 识别错 | 列映射把「对方号码」认成了「本机号码」 | 列映射 |
| 抽取错 | 把「张叁」错认成「张三」 | 抽取规则 |
| 材料本身有问题 | 原件错、伪造、重复报送 | 材料 |

### 9.3 合并与拆分

同一人两个名字、同一账户两种写法 → **合并**：被并入者成为别名，关系一并转移；并错了 → **拆分**，原样恢复。合并本身留记录（谁、何时、依据什么），可撤销。

### 9.4 传播

改了事实之后：引用它的事实标「依据已变更」；引用它的报告标「依据有更新，请复核」；规则命中结果重算。

### 9.5 AI 只提议、不改数

AI 发现「这两条可能是同一账户」只能提交提议，进待处理列表，不阻断使用；改数据只有民警能做。

**提议本身也要留痕**，落 `ai_proposal`：提议内容、AI 给的理由与依据、状态（**待处理 / 已采纳 / 已否决**）、处置人、处置时间、否决理由。将来复盘「AI 说这两人可能是同一人，是谁决定不合并的」，能答得上；这串记录同时是评价 AI 提议质量的数据来源。

「对话录入」是新增数据、不是改已有数据，边界见 §7.1。

### 9.6 留痕

改前值、改后值、人、时间、原因全部留存。法制与领导可查「改过几次、改了什么」——这是可信度的加分项。

## 12. 风险与兜底

| 风险 | 兜底 |
|---|---|
| 自动识别猜错列 | 原始层在、事实可重放；错误会在数据自身露馅（余额为负、时长为零、账户数翻倍） |
| 模型抽取漏人或错并 | 每条事实带置信度与出处；关键结论由人复核后才进产物；切片级校验不过标黄，不整份回滚 |
| 换模型或改 prompt 后抽取结果漂移 | 存模型名＋版本＋prompt 版本；同批切片重跑做抽样比对，差异进抽检清单，不静默覆盖已确认结果 |
| AI 抽取成本失控 | 只有非结构化材料进模型；切片带预算上限；单 worker 顺序消费，可随时取消 |
| 数据量增长 | 分区 + 批量写 + 单 worker；后续再谈归档 |
| 材料涉密 | 沿用项目级权限与行级隔离；AI 调用全程记录 |
| MCP 独立仓库与主仓库版本脱节 | 镜像打 tag、部署 pin 版本；契约（工具清单与返回格式）变更走版本号 |
