# 项目能力面板（左栏「能力」Tab）· 设计

- **日期**：2026-10-27
- **状态**：设计已与用户逐节谈定（形态 / 三态 / 数量口径 / 取数顺序），待评审
- **关联**：`2026-09-11-项目管理-design.md` §2（本设计**修订**其「只有会话/文件两个 tab」）、`2026-09-12-AI资产-design.md` §4（MCP 分发）、`2026-10-26-governance-mcp-single-process-design.md` §9（业务 MCP 下发器延后）
- **不在本文件**：资产中心本身的浏览/启用流程、治理后台的审核上架

## 0. 一句话

在项目左栏加第三个 tab「能力 N」，回答民警一个问题：**「我在这个项目里现在能用什么？」** 面板按 技能 / 知识库 / MCP 三组纵向排列，收起的组压成横条贴在底部，点哪条哪条就上移展开。

## 1. 为什么要做（以及为什么不是别的方案）

用户在项目里装了 skill，回到项目却看不见——文件 tab 里不会出现 `.opencode/skill/` 下的东西（`FileSystem.list` 只保留 file/directory，链接被丢弃，`packages/core/src/filesystem.ts:87-113`）。而资产中心回答的是「有什么可装」，不是「我这个项目装了什么」。

此前评估过的三个方案都被否掉：资产中心中栏（与项目上下文脱节）、`/skills` 斜杠命令（要用户先知道有这个命令）、单开「技能」tab（将来加 MCP / 知识库时要改 tab 结构）。

## 2. 现状事实（决定设计边界）

| 资源 | 项目级事实 | 内核能否报出 | 证据 |
|---|---|---|---|
| 技能 | `auth.project_asset_enablement` 记账 ＋ `.opencode/skill/<assetId>` 链接 | 能：`GET /skill` | `0021_project_asset_enablement.sql:29-35`；`project-skill-link.ts:29` |
| MCP | 项目目录 `opencode.json` / `.opencode/opencode.json` 的 `mcp` 段（按目录作用域隔离） | 能：`GET /mcp` → `Record<string, MCP.Status>` | `config.ts:420-447`；`groups/mcp.ts:32-54` |
| 知识库 | **无**：只有类型枚举与目录名映射 | **不能**：`rbac.ts:117` 明确「knowledge_base 零工具映射」 | `metadata.ts:8-15`；`storage.ts:15` |

三条推论：

1. **统一判据只能是「内核报得出来什么」**。库视角会骗人（库里记着、实际加载不到），内核视角会如实少一条——那正是排障线索。
2. **MCP 一旦落地即可接入**，不需要改 tab 结构：数据源现成，只需滤掉系统内置的 `openhive-governance`（`governance-mcp-supervisor.ts:408-415`）。
3. **知识库进不来**，因为内核没有它的任何落地事实。今天不写数字、不给空列表。

## 3. 交互形态：三档手风琴

```
┌──────────────────────────┐
│ [会话] [文件] [能力 3]     │
├──────────────────────────┤
│ ◆ 技能 · 3 个           ⌄ │ ← 展开中
│   ┌────────────────────┐ │
│   │ ● 资金流向分析      │ │
│   └────────────────────┘ │
├──────────────────────────┤
│ ◆ 知识库     即将支持    › │ ← 收起，贴底
│ ◆ MCP · 0 个            › │ ← 收起，贴底
│ ☁ MinIO 备份 · 2 项      ▸ │ ← 原有常驻条，不动
└──────────────────────────┘
```

**规则（用户逐条确认）**：

1. **永远恰好一组展开**，不会出现三组全收起的空面板。
2. **组序固定**：技能 → 知识库 → MCP。展开组**之前**的组收在顶部，**之后**的组滑到底部贴住。
3. 点**已展开**的那一条 ⇒ 它收起，回到「技能展开」的默认态。这条是给手风琴加的兜底，保证永远有退路，而且退路是最常用的那一组。
4. 展开中的组头箭头是 `⌄`（点了会收起），收起的是 `›`。**不能用错**——用 `›` 会让用户以为「再展开一层」。
5. **不做位移动画**：展开内容整体换掉，位移动画让人多等 150ms 换不来理解，且布局过渡在 happy-dom 里量不出来，只能靠肉眼（等于「测不了的写成已覆盖」）。瞬时切换，与切 tab 一致。

**无数据的三条边界**（同守 `undefined ≠ 0`）：

- 还没取到数 ⇒ tab 只写「能力」，**不写 0**。
- 没有选中项目 ⇒ 面板显示「先选一个项目」，不显示三个空组。
- 不是该项目成员（接口 403）⇒ 显示「你不是这个项目成员」，与文件 tab 的口径一致。

**视觉语言借自 MinIO 条**（`minio-bar.tsx:130-154`）：13px 字号、`muted → base` 的 hover、右侧箭头、`· N 个` 计数。不借它的**默认收起**与**底部浮层位置**——那套是为拖拽服务的，面板没有第二个内容区要同时可见。

**三条横条全显**（用户裁定）。但数字口径三分：

| 横条 | 今天 | 显示 |
|---|---|---|
| 技能 | 真的有 | `技能 · 3 个` |
| MCP | 内核能报，业务 MCP 确实是 0 | `MCP · 0 个` |
| 知识库 | 内核**报不出来**——不是 0 | `知识库 · 即将支持`（**不写数字**） |

依据 `minio-bar.tsx:32-35` 的纪律：`undefined`（不知道）与 `0`（明确没有）必须分开；不知道时不许替后端回答。

## 4. 条目：按「能不能用」分三态

| 态 | 判据 | 外观 | 操作 |
|---|---|---|---|
| ① 正常 | 库里有 ＋ 内核加载到 | `●` 绿点 + 中文名 + `📦 资产库` | 悬停「停用」 |
| ② 没生效 | 库里有 − 内核没看见（且对账已跑过） | `▲` 琥珀 + 说明「已启用，但 AI 没加载到——项目里的快捷方式可能丢了」 | 「停用」「去资产中心重新启用」 |
| ③ 本项目自带 | 内核有 − 库里没有 | `●` + `📝 本项目自带` | **无操作** |

- 中文名取库里资产标题；内核返回的 `name` 只在没有资产记录时兜底。
- 一句话能力取 SKILL.md 的 `description`（`/skill` 直接返回）。
- ③ **不能有「停用」按钮**：它不是装来的，点下去会变成「删用户的文件」。

## 5. 数据源与取数顺序（顺序本身是设计）

打开「能力」tab 时**只发一个请求**：`GET /openhive/project/assets?projectId=`。它在服务端依次做三件事：

1. **对账**（`project-assets.ts:200-276`）：把当前用户沙箱缺的链接补齐
2. **读库**：`enabled`（我可用的 id）、`enabledCount`（项目真相）、`limit`
3. **读内核**：在算好的项目目录上取 `Skill.Service.available()`，返回 `skills: { name, description, path }[]`

返回体因此新增长 `skills` 字段。

三种关系（前端纯函数合并）：

- `enabled ∩ 内核` → ①
- `enabled − 内核` → ②（**对账已跑过**，所以这是真问题，不是「还没同步」）
- `内核 − enabled` → ③

反查靠路径：`path` 形如 `<沙箱>/.opencode/skill/<assetId>/SKILL.md`，目录名即 assetId。

**为什么必须由服务端读内核**：前端不知道沙箱路径（`CurrentProject` 只有 id / name / memberCount；`useSDK()` 只在右栏挂过 provider），`client.app.skills()` 是按 `directory` 作用域的，前端无从传入。

**为什么合成一个请求**：库侧与内核侧在同一请求内读出，中间没有时间窗；「先对账、再读内核」的顺序由服务端保证，不依赖前端记得按序发；用户恰在两次请求之间点停用也不会让两边打架。

**为什么必须先对账**：项目目录是 `{userId}/{projectId}`，每人一份；启用记录是项目级的。新成员第一次进项目时沙箱里没有任何链接，先读内核会把全部技能误报成「没生效」。

## 6. 数量口径

- **tab 上的 `能力 N` = 列表里的条数**（我能用的，即 ① + ② 的合计）。将来 MCP 有数据时并入同一总和。
- 项目真相多于我能用时，组头补一行小字：`项目共启用 4 个，其中 1 个不在你的授权范围`（= `enabledCount − enabled.length`）。
- **20 个配额只数资产库装的**（① + ②），**不含** ③ 自带。自带的本来就不在账上，算进去会出现「3/20」却只能再装 18 个。

## 7. 停用语义

- 复用资产中心同一接口（`POST …/toggle` 的 disable 分支，`project-assets.ts:359-376`），判据完全一致：**项目成员即可**（`:303`），不看类型与归属。
- 幂等：库里没有这条也回 200 并记审计（`:360-361`）。
- 顺序：**先删库行 → 再摘链接 → 最后丢缓存**。
- 停用后卡片从面板消失——**有一个例外**：`unlinkSkill` 遇真目录抛 `NotALinkError`，被 `:364-366` 接住只记日志，接口仍回 200。于是「库里有 → 真目录」的那条停用后会变成 ③ 本项目自带，**不会消失**。这是保护（绝不删用户真文件），不是缺陷；界面文案不得承诺「一定消失」。

## 8. 取不到时

- 任一接口失败 ⇒ 面板显示「暂时读不到，点这里重试」，**不显示空列表**。空列表等于说「你一个都没装」，那是假话。
- `/skill` 失败时即使库侧成功也不下结论：没有内核侧数据，三态判断不成立。
- 不做轮询、不订阅事件。切到 tab 取一次、启停之后取一次。

## 9. 最终一致，不是实时一致

启用记录是项目级的，链接是每人一份的。同事 A 停用后，B 已打开的面板不会立刻变；B 下次打开该 tab 时对账会摘掉他的链接。界面不承诺「对方马上看到」。

## 11. 不做的事

- **不做知识库的任何界面**（连空列表都不给），等内核有了它的落地事实再说。
- **不做 MCP 分组的数据源**，等第一条业务 MCP 连接出现；落地时接 `GET /mcp` 并滤掉 `openhive-governance`。
- 不做位移动画、不做轮询/推送、不做「已停用」历史列表（要找回来去资产中心）。
- 不改资产中心、不改后端任何接口。
- 不做**面板级**的「去资产中心装更多」入口按钮——第一版先不加，避免与停用后的找回路径混在一起；若验收时用户觉得找不到，再补一行文字链接。② 条目上的「去资产中心重新启用」不在此列，它属于单条目排障。

## 12. 测试策略

| 层 | 用例 |
|---|---|
| 后端（`project-assets` 的 GET） | 返回体带 `skills`；对账后沙箱里有链接的 skill 一定出现在 `skills` 里；`skills` 的 `path` 目录名等于 assetId；**`store` 缺席时 `skills` 整个字段缺席（不是 `[]`）**且不报 500——不知道与没有是两件事（`#002-02`） |
| 纯函数（`capability-source.test.ts`） | 三态合并：交集/差集正确；路径反查取到 assetId；自带项无 assetId 时用内核 name；任一输入缺失时不产出「空」结论 |
| 组件（`capability-panel.test.tsx`，happy-dom） | 三态各自渲染；tab 数字 = 列表条数；知识库横条不出现数字；未取到数时 tab 不写 0；无项目 / 非成员各自的说法；折叠交互（点收起组展开、点展开组回默认）；③ 无停用按钮；两接口任一失败显示「读不到」而非空列表 |
| 几何 | 三 tab 在 160px 下不溢出（happy-dom 量不了布局 ⇒ 记为真机验证项） |
| 真栈验收（用户操作） | 启用一个 → 面板出现 → 停用 → 面板消失 |

**缺口（本机验不了，据实记录）**：左栏 160px 的三 tab 实际排布；真机上 `⌄/›` 的辨识度；同事 B 的对账时机。

## 13. 决策记录

| 问题 | 结论 | 理由 |
|---|---|---|
| 内核清单由谁读 | 服务端，合成一个请求 | 前端不知道沙箱路径，`skills()` 按 directory 作用域；合成后天然一致 |
| 单 tab 内分组 vs 一类一 tab | 单 tab | 五个 tab 在 280px 勉强、拖到 160px 必溢出；三类回答同一个问题 |
| 分组形态 | 三档手风琴，收起贴底 | 用户提出，优于「组头 + 列表」：三组都直接可达 |
| 空组是否显示 | 三条全显 | 用户裁定：结构一眼看全 |
| 知识库数字 | 不写数字，写「即将支持」 | `undefined ≠ 0`，不替后端回答 |
| 条目不生效的解释 | 先对账再读内核 | 否则把「还没同步」误报成故障 |
| tab 数字口径 | 数「我能用的」 | 与列表条数永远一致 |
| 移行动画 | 不做 | 换不来理解，且量不出来 |
