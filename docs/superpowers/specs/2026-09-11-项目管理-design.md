# OpenHive 项目管理模块设计（左栏）

- **日期**：2026-09-11
- **状态**：待审阅
- **主题**：图标栏「项目管理」入口 + 左栏布局 + 项目列表 + 共享项目成员管理 + 文件 ↔ MinIO 拖拽 + 项目归档/找回 + 文件树工具栏
- **关联**：`2026-09-06-openhive-design-v2.md`（§2 一级对象、§5.3 沙箱、§8 前端、§9.2 拖拽出/回、§13 共享项目）

## 0. 定位与范围

**项目管理**是 openhive 一级对象「项目」在左栏的承载。项目是**工作单元容器**（design-v2 §2），技术载体是「独立 git 仓库 + 沙箱子目录 `/workspaces/{userId}/{project}/`」（§5.3），是唯一的隔离边界。

本模块只覆盖**工作空间轴**的「项目」管理（`project` / `project_member`），**不覆盖数据轴**的资金项目/话单项目（`fund_project` / `call_project`，见 §14.1 两条轴的区分）。两者不互相绑定。

## 1. 图标栏（五入口）

图标栏（rail，最左侧竖条）共五个入口 + 底部设置：

| 入口 | 作用 | 对应早期 spec 图标 |
|---|---|---|
| **项目管理** | 呼出左栏（项目列表 / 会话 / 文件树 / MinIO） | 📁 |
| **AI 资产** | 进入 AI 资产工作区（左栏分类导航 + 中栏展示，三栏） | 🧩 |
| **AI 会话** | 呼出/收起右栏 | 💬 |
| **话单分析** | 切到话单工作区 | 📞 |
| **资金分析** | 切到资金工作区 | 💰 |

- 底部「⚙ 系统设置」。
- **命名**：早期「资源管理 / 资源面板」统一改为「**AI 资产** / **AI 资产工作区**」，与 design-v2 §11「AI 资产治理」术语对齐，避免「资产管理」与固定资产（设备/车辆）混淆。

## 2. 左栏整体布局（tab 方式）

图标栏「项目管理」入口呼出的左栏，采用「**顶部项目锚点 + tab + 底部 MinIO 窄条**」三层：

```
┌──────────────────────┐
│ 📁 8·17专案  👥3  ▾ ＋ │ ← ① 项目管理一行置顶（上下文锚点）
├──────────────────────┤
│ [会话] [文件]          │ ← ② tab（默认「文件」）
├──────────────────────┤
│ （文件树 / 会话列表）   │ ← ③ 主体内容区（占最大空间）
│                      │
├──────────────────────┤
│ ⬆ MinIO 备份 · 2 项 ▸ │ ← ④ 底部常驻窄条
└──────────────────────┘
```

- **① 项目管理一行**：`项目名 + 👥 成员数 + ▾（下拉项目列表）+ ＋（新建）`。这是左栏的**上下文锚点**——民警必须先看清「我在哪个项目干活」。
- **② tab**：只有「会话 / 文件」两个（「备份」不占 tab，改到底部常驻窄条，理由见 §5）。
- **④ MinIO 窄条**：常驻，拖拽时源与目标始终可见（§5）。

**左栏是「项目管理 / AI 资产」两入口共用、互斥切换**（前端 spec FR-025「与文件树互斥共享左栏位置」）：点图标栏「项目管理」→ 左栏显示本节布局；点「AI 资产」→ 进入 AI 资产工作区（左栏分类导航 + 中栏展示，三栏，详见 `2026-09-12-AI资产-design.md`）。本设计只展开「项目管理」这一侧。

**布局取向**：在「四块纵向堆叠 / 项目管理置顶+tab / 文件树主导」三种方案中，选「**项目管理置顶 + tab**」并扩展——项目管理始终可见，会话/文件用 tab 收纳，文件树空间更大。

## 3. 项目列表（点项目名 ▾ 滑出）

点项目名 `▾` 滑出「项目面板」，结构：

```
＋ 新建项目（私有 / 共享）      ← 置顶
[最近] [全部] [已归档]         ← 三 tab
 最近：8·17专案（当前）、专项行动·夏季整治、👥串并案…
 全部：我的项目 / 共享项目（两组）
 已归档：📦 已归档项目（可找回）
```

- **＋新建**：区分「私有（我的）/ 共享」两种，置顶最易达。
- **三 tab**：复用资金分析四 tab 心智（design-v2 §9.6「最近/全部/已归档/当前」），**去掉「当前」**——因为当前项目已常驻左栏顶部，再放「当前」tab 就冗余了。
- **「最近」**：按 `project.last_accessed_at`（最近访问时间）倒序，点一下直达。
- **「全部」下分两组**：我的项目 / 共享项目；共享项目带 👥 + 成员数（前端 spec FR-015）。
- **「已归档」**：归档项目列表（§8），点「找回」恢复为活跃项目。

## 4. 共享项目成员管理（点 👥 侧滑）

共享项目在项目名旁显示 `👥 N`，点开**侧滑「成员面板」**（不占左栏常驻空间，成员管理是低频动作）：

```
👥 成员管理 · 8·17 专案
＋ 邀请成员（输入警号）
── 成员（3）──
👤 张三（本人）        owner
👤 李四               member  [移除]
👤 王五               member  [移除]
[退出项目]
```

- **权限模型**（微信群模型，design-v2 §13.1/§9.6）：
  - 谁建项目谁是 **owner**；owner 与 member 都能邀请（role=member）。
  - **只有 owner 能移除某人**；member 只能**退群**（删自己）；owner 不能退群。
  - 不设 viewer「只读旁观」角色（§13.1）。
- **邀请**：输入警号邀请成员（复用管理员录入的警号体系）。
- **前端 spec FR-036**：共享项目 owner 可查看成员列表、邀请新成员、移除成员。

## 5. 文件 ↔ MinIO 备份拖拽（上下双树，文件级）

**核心矛盾**：拖拽移动文件必须「源树」和「目标树」**同时可见且都能看到文件明细**——所以 MinIO 不能只做一条「备份 N 项」的窄条，点开后要展开成**第二个完整文件树**。

> **范围界定**：本节是「**文件级**备份/拉回」（单个/多个文件在沙箱与 MinIO 之间移动）。**项目级**的整项目归档/找回见 §8，两者粒度不同，勿混。

### 5.1 交互流程

1. **默认态**：底部 MinIO 窄条只显示「⬆ MinIO 备份 · N 项」（不占文件区空间，符合「较大空间留给文件」）。
2. **点窄条**：① 若当前在「会话」tab，**自动切到「文件」tab**（MinIO 是文件操作，不该停在会话视图）；② 展开**上下双树**。
3. **拖拽**：从上树拖到下树 = **备份**；从下树拖回上树 = **拉回沙箱**。
4. **收起**：点树标题「✕」回到默认窄条态。

### 5.2 双树结构

```
📁 沙箱目录（当前项目）      ✕
  ▾ 📁 8·17专案
    ▾ 📁 资金流水
      📄 支付宝.xlsx        ← 拖出（备份）
      📄 财付通.xlsx
━━━━━━━ 可拖分隔条 ━━━━━━━
⬆ MinIO 备份（镜像沙箱路径） ✕
  ▾ 📁 8·17专案
    ▾ 📁 资金流水
      📄 支付宝.xlsx ✓      ← 拖入（已备份标 ✓）
```

- 上树 = **沙箱目录**（当前项目文件）；下树 = **MinIO 备份**（**镜像沙箱路径结构**，前端 spec FR-033）。
- 中间**可拖分隔条**按需调整两树比例。
- 已备份文件标 ✓；拖拽落点精确到具体文件夹。
- **默认收起、按需展开**（不常驻双树，避免挤占文件区）。

## 6. 文件树（工具栏 + 右键菜单 + 拖拽语义 + 控件）

### 6.1 工具栏（高频图标）

文件 tab 标题栏一排图标入口：

| 图标 | 功能 | 说明 |
|---|---|---|
| 🔍 | 搜索文件名 | 输入即过滤，只留匹配项，关键词高亮，父级路径自动展开 |
| ⊟ | 全部收缩 | 一键折叠所有层级 |
| ⊞ | 全部展开 | 一键展开所有层级 |
| ＋ | 新增 | 点开下拉「📄 新建文件 / 📁 新建文件夹」 |
| ✏️ | 重命名 | **选中文件/文件夹后点亮**，未选中置灰 |
| 🗑 | 删除 | **选中后点亮**（红色），未选中置灰 |

- **删除/重命名「选中后点亮」**：二者作用于「当前选中项」，未选中时置灰，防止误删。
- **新增用「＋」下拉**而非两个独立图标：工具栏图标已较多，下拉收纳「新建文件/新建文件夹」更省空间。
- 悬停给 tooltip 提示动作名。
- 文件删除须二次确认（前端 spec FR-017）。

### 6.2 右键菜单（低频/完整操作兜底）

工具栏图标空间有限，**复制/移动/上传/下载/备份/拉回**等低频操作收敛到**右键菜单**（前端 spec US5）：

| 右键菜单项 | 说明 |
|---|---|
| 新建文件 / 新建文件夹 | 同工具栏「＋」 |
| 重命名 / 复制 / 移动 / 删除 | 完整文件操作（FR-016「复制、移动」在此补全） |
| 上传 / 下载 | 沙箱 ↔ 本地电脑（§6.3） |
| 备份到 MinIO / 从 MinIO 拉回 | 沙箱 ↔ MinIO（§5，作为拖拽的替代入口） |

### 6.3 拖拽语义（两类拖拽，勿混）

| 拖拽 | 方向 | 说明 | 出处 |
|---|---|---|---|
| **拖拽 A** | 沙箱 ↔ **本地电脑** | 拖出浏览器到桌面 = 下载；从桌面拖回 = 上传（含文件选择器上传） | design-v2 §9.2、FR-044 |
| **拖拽 B** | 沙箱 ↔ **MinIO** | 双树之间拖拽 = 备份/拉回 | FR-033、本设计 §5 |

- 拖拽 A 是「导入导出」——民警把本地 Excel 数据文件拖进项目，或把生成结果拖回本地。
- 拖拽 B 是「云端备份」——在 MinIO 上留一份，与本地电脑无关。
- **两者方向不同、目的不同**，UI 上用不同的落点提示区分（拖出浏览器 vs 拖入 MinIO 树）。

### 6.4 控件选型

**复用 opencode 原生 SolidJS 文件树**，不引入新树控件：

- openhive 走「opencode 原生换皮」路线（design-v2 §8.1），opencode 自带文件树（展开/收起/高亮/右键）。
- 引入 Antd Tree 等 React 控件会与 SolidJS 冲突，违背最小侵入原则。
- 在原生树基础上补：**搜索过滤、全部折叠/展开、拖到 MinIO**，再做品牌换皮。

**「美观」落点**（呼应视觉规范）：线性图标（借 Cloudflare 风格）+ 13px 紧凑小字 + 16px 层级缩进 + 选中态浅金底（`#F59E0B` 10% 透明度）+ 文件类型图标区分（📁 文件夹 / 📄 文档 / 📊 表格 / 🖼 图片）。

## 7. 会话列表（与右栏联动）

- 会话 tab 标题行右侧「**＋**」= 新增会话（前端 spec FR/US4「＋新建会话」）。
- 会话列表：当前会话浅金高亮。
- **与右栏 AI 会话联动**：左栏「会话」tab 是「当前项目下的会话列表」，右栏是「当前会话」。**点左栏某会话 → 右栏切换到该会话的消息流**；右栏「＋新建会话」→ 左栏列表新增并选中。这与「选中即切换」一致（复用 opencode 原生会话管理，§8.1）。
- 会话的**重命名 / 删除 / 导出**在右栏 AI 会话的「⋯」菜单（前端 spec FR-041），**不在左栏会话列表重复放图标**（左栏只放高频的「新增」）。

## 8. 项目归档与找回（项目级，手动 + 3 个月自动）

> 本节是「**项目级**」归档——整项目存档到 MinIO 并释放沙箱空间，区别于 §5 的「文件级」备份。
>
> **术语界定**：工作空间项目归档后用「**找回**」（含文件从 MinIO 下载回沙箱的搬移动作）；design-v2 §9.6 数据项目（资金/话单）归档后的「恢复」仅改 `archived` 状态、数据不搬移——两者对象不同、动作不同，分别用「找回」/「恢复」。

### 8.1 归档触发

- **手动**：owner 在项目上执行「归档」（项目列表「全部」tab 内，或项目名右键）。
- **自动**：项目 `last_accessed_at` 超过 **3 个月无操作** → 自动进入待归档（或自动归档，待实现时定阈值提醒 vs 直接归档）。

### 8.2 归档流程

1. 选定项目 → 执行「归档」。
2. 该项目沙箱目录内**全部文件上传到 MinIO 对应目录**（镜像沙箱路径 `/minio/{userId}/{projectId}/`）。
3. **删除沙箱内的文件**（释放 `/workspaces/{userId}/{projectId}/` 空间）。
4. 项目状态变更：`archived = 1`。
5. 项目从「最近 / 全部」tab 移到「已归档」tab，此后只能在归档区域找到。

### 8.3 找回流程（手动）

1. 在「已归档」tab 找到项目 → 执行「**找回**」。
2. 项目状态变更：`archived = 0`。
3. MinIO 对应目录中的文件**全部下载回沙箱目录**。
4. 项目回到「最近 / 全部」tab。

- **恢复 = 手动**（明确不自动拉回；前端 spec FR-034「访问时自动恢复」修订为「手动找回」）。
- 归档/找回全程留痕（git commit + 审计）。

## 9. 数据模型（引用 design-v2 §13.3 + 补字段）

```sql
project          -- opencode 原生表，openhive 加字段
  + type（private/shared）
  + project_type（单案/串并/专项行动/考核督导/内勤文字…）
  + shared_directory（→ /shared/{projectId}/）
  + last_accessed_at（最近访问时间：「最近」tab 排序 + 3 个月无操作归档判断）
  + archived（归档状态：0 活跃 / 1 已归档）
  + archived_at（归档时间，可选）

project_member   -- 项目成员（工作空间轴）
  project_id, user_id, role（owner/member）
  唯一约束 (project_id, user_id)

case / project_case  -- 案件实体 + 项目↔案件多对多（一个项目 0/1/N 起案件）
```

> **补字段说明**：design-v2 §13.3 只列了 `type / project_type / shared_directory`，本设计补 `last_accessed_at`（§3「最近」排序 + §8「3 个月无操作」判断）与 `archived / archived_at`（§8 归档状态）。需同步回 design-v2 §13.3。

## 11. 待决策点

- **自动归档的形态**：`last_accessed_at` 超 3 个月是「先提醒、owner 确认后归档」，还是「直接自动归档」？（倾向先提醒，避免误归档仍在用的项目。）
- **归档后 member 的权限**：项目归档后，共享项目 member 是否失权？（参照资金项目 §9.6「归档后 member 失权、owner 保留查看+恢复权」，倾向一致。）
- **文件树搜索在大文件量下的性能**：必要时虚拟滚动（实现时验证）。
