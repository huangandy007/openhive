## 0. 定位与范围

### 0.1 目标

1. 左栏文件树里**打开一个文件 ⇒ 在中栏看到它**；
2. 每个打开的文件**占一张中栏 Tab**，可**像浏览器标签页一样关闭**；
3. 中栏**分屏**：**左右** / **上下**两种，**每栏独立一套 Tab**；
4. 打开**大文件前先提醒**（保护服务端与客户端内存）。

### 0.2 非目标（本次不做，登记为缺口）

- 服务端 **Range / 流式读**、对象存储（MinIO）**预签名直读**、每用户**并发 / 总量配额**；
- 中栏 Tab 的**拖拽重排**、**拖拽跨栏**；
- 弹窗的「**以后别再问我**」记忆开关（理由见 §4.4）。

### 0.3 一个必须先说清的结论

**目标 2、3 已经建好并且接线了。** 本次真正要建的只有**两件事**：

- **缺口 A：接通链**（文件树 → 中栏开 Tab → 取数 → 渲染）；
- **缺口 B：分屏**（唯一从零新建的界面能力）。

依据见 §1。

## 3. 分屏：`tab-store` 的新结构与交互

### 3.1 数据结构

```ts
/** 一栏（pane）的内容。 */
export interface PaneState {
  tabs: ContentTab[]
  /** 本栏当前激活 tab 的 key（`contentTabKey` 形态）。 */
  active?: string
}

export interface CenterTabState {
  /** 恒两栏（`panes[0]` 左/上，`panes[1]` 右/下）；未分屏时右栏为空且不露。 */
  panes: [PaneState, PaneState]
  /** 右栏露不露。**显式存**，不从 panes 长度推。 */
  split: boolean
  /** 排列方向。左右 = 并排（竖隔板）；上下 = 叠放（横隔板）。 */
  排列: "左右" | "上下"
  /** 新开的文件落哪一栏 ＝ 哪个栏「受焦」。未分屏时恒 0。 */
  activePane: 0 | 1
  /** 当前**停留**的模块（FR-006 语义一字不动）。 */
  module?: string
}
```

**三个刻意的决定**：

1. **`ContentTab` 与 `contentTabKey` 一字不动。** 内容身份（`module\npath`）不变；栏内去重靠「本栏自己的 `tabs` 列表」**天然隔离** ⇒ **同一文件能左右各开一份**，不需要给 key 加「哪一栏」，也就不会波及 `tab-bar.tsx` 与既有测试。
2. **`split` 显式存**（不从 `panes.length` 推）：这样「收起」只是**不露**，右栏的 tab **不丢**，下次分屏原样还在——避免「合并两栏列表 / 去重排序」那一堆规则。
3. **`!split` 时右栏不销毁，用 `display:none` 常驻** —— 与 page 层同一手法（`center-content.tsx:160` 的 `display: 内容() || !露页() ? "none" : "contents"`）。这是 `001` T013 的教训：摘掉再挂回会把文件重读一遍、PDF 回到第一页。
   > **（2026-10-12 实现后收窄 · T11 落地偏差）右栏「挂过一次才常挂」**：**从未分屏**时右栏节点**压根不挂**（未分屏路径的 DOM 与今天**逐字相同**，既有那批「只有一条 tab 栏」的用例因此一条不红）；**分屏过一次之后**才进入上面那条「收起只 `display:none`、节点不摘」的常挂态。⇒ T013 那条教训只在**用户真的用过右栏之后**才需要防；首次分屏前不挂节点，换来未分屏路径的上游 DOM 面**零变化**。

### 3.2 reducer

| 函数 | 语义 |
|---|---|
| `openContentTab(state, tab, pane = state.activePane)` | 栏内按 key 去重 → 追加 → 激活该栏该项；并 `activePane = pane` |
| `activateContentTab(state, key, pane)` | 只动那一栏的 `active`，并 `activePane = pane` |
| `closeContentTab(state, key, pane)` | 接替者**仍是**左邻居优先（既有语义**一字不改**） |
| `switchModule(state, module)` | 不变（FR-006） |
| **`splitPane(state, 排列)`** / **`unsplitPane(state)`** | 只翻 `split` / 设 `排列`，**不碰任何 tab** |
| **`focusPane(state, pane)`** | 点某一栏 ⇒ 它受焦 |

⚠️ **`!split` 时 `activePane` 强制回 0**：否则新文件会开进**看不见的右栏**，用户会觉得「我点了，怎么什么都没发生」——`#006-27` 那类「静默不发」缺陷的温床。

> **注入形状（2026-10-12 实现后补 · T5 落地偏差）**：§2 表 ② 只写到「`打开文件(path)`：先 stat → 超阈值弹窗 → 确认才开 Tab」。实现里 `createOpenFile` 的依赖收成 **`受焦栏: () => 栏操作`**（`栏操作 = { 已有, 切到, 开 }`，`packages/app/src/center/open-file.ts:47-64`），而不是散着注入 `center` 的那三个并列函数——**一次调用里 `受焦栏()` 只读一次**，于是判定「已经在栏里开着」/ 切过去 / 开一张三件事落在**同一栏**。若写成三个函数各自去读一次 `activePane()`，读到两次就可能落在两栏，而那种缺陷**不报错、不变红**（`LEARNINGS #002-06`）。

### 3.3 交互

**默认不分屏。**

**分屏入口：左/上栏标签条最右端一颗「分屏」钮**（未分屏时中栏只有这一条标签条，钮就长在它的右端），点开一个小菜单两项：**「左右分屏」「上下分屏」**（做法照抄标签条上现有那本 `⋯` 溢出菜单，不引新组件）。

**前提：中栏至少已打开 2 个 Tab。** 不足 2 个时该钮**置灰 ＋ 悬停提示「至少打开两个文件才能分屏」**——置灰而非藏起来，否则民警永远不知道有这功能。

**分哪两张（规则 A，已裁定）：** 以「你看的东西**不跳**」为核心——

> 你正在看的那张**留在左/上**；标签条上**紧挨着它的一张**去右/下；其余留在左/上栏。

**双击**一个文件 ＝「打开」（开在受焦栏）。

**取消分屏**：**右/下栏**标签条端一颗「收起」（与分屏钮同族做法），点了即 `unsplitPane`（**右栏 tab 留着**）。收起后再分屏，**记得上次的排列方向**。

**受焦与它的可见指示**：点任一栏的标签条 / 内容区 ⇒ 该栏受焦（`focusPane`）。受焦栏**必须有可见指示**——否则「双击开在哪一栏」对用户是**不可预测**的。做法沿用 `tab-bar.tsx` 已有的视觉语言（同族 `data-slot="tab-active-bar"`），在**受焦栏的标签条上**加一道区分（如顶边强调条 / 底色档位，取 DESIGN 现有 token），**不新造视觉符号**。

### 3.4 接线（谁改）

- `CenterContent` 加 `pane?: 0 | 1`（默认 0），改读 `panes()[pane]` 那一栏的 `tabs`/`active`（现在它读的是 `center.active()`/`center.tabs()`，`center-content.tsx:86-88`）；**右栏不承载 `children`（上游路由页面）**——页面只在左栏露；
- `workspace-entry.tsx`：从「一条 `TabBar` ＋ 一个 `CenterContent`」→「两条 `TabBar` ＋ 两个 `CenterContent`」，中间夹一个 `ResizeHandle`；
- `CenterTabs` 接口（`tab-context.tsx`）：`tabs()` / `active()` → **换成** `panes()` ＋ `activePane()` ＋ `split()` ＋ `排列()`（不保留旧名做兼容——少一份会漂移的重复 API，`LEARNINGS #002-06`）。

## 4. 闸门与弹窗

### 4.1 后端：新增一条「问大小」的出口

`GET /openhive/file/stat?path=…` → 回 `{ size: 数字 }`，**只读元信息、不读内容**。

落在**我们自己的** `packages/opencode/src/server/openhive/file.ts`（第 8 条出口，与既有 7 条同模块 ⇒ `server.ts` 一行不动，先例是 `archive.ts`），**复用已有的全套安全判据**：`gate()`（项目 / 沙箱判定）、`inside()`（路径不可逃逸）、`lstat`（不吃链接）、`realInside`（防中间层链接）。**上游 0 改动。**

> **为什么必须新开一条**：上游文件组只有 `findText / findFile / findSymbol / list / content / status`——**没有一个回大小**；其中 `content` 会 `readFile`（正是我们要躲开的那一下）。我们 fork 的 `download`（`server/openhive/file.ts:608`）同样 `readFile`。⇒ 「只问大小」这条出口**今天不存在**。

### 4.2 闸门流程

```
点「打开」（右键菜单 或 双击）
   ├─ ① 这张 Tab 已经在中栏开着？ ── 是 ─→ 直接切过去，不 stat、不弹窗（内容早读过）
   ├─ ② stat(path) 问大小
   │        ├─ 拿到，且 ≤ 阈值 ──→ 直接开 Tab
   │        └─ 拿到，且 > 阈值 ──→ 【弹窗】「仍然打开」→ 开 Tab ／「取消」→ 什么都不做
   └─ ③ stat 失败（网络 / 权限）──→ 直接开 Tab（放行）
```

**③ 为什么失败要放行**：闸门是**提醒**，不是**关卡**。网络抖一下就打不开文件，比偶尔多打开一个大文件更糟。放行的代价只是「少弹一次窗」；读取环节真出错时另有出口说清楚（`degraded` / `load-failed`，001 已有）。

> **③ 的落地口径（2026-10-12 实现后补 · T2 落地偏差）**：客户端 `statProjectFile` 在**非 200 时返回 `undefined`（不抛）**，而 `undefined` 与「很小」在闸门里走**同一条路**（`packages/app/src/center/open-file.ts:64-66,93-95`）⇒ 「问不到就放行」这一支是靠**返回值**实现的，不是靠捕获异常。抛异常会逼每一个调用点包 `try/catch`，反而把「问不到」与「有 bug」混成一条路。对闸门**可观测的行为相同**（都在「放行」那一支）。

### 4.3 阈值：两档，单一来源

```ts
/** 打开前弹窗提醒的大小闸门（字节）。 */
const 闸门 = {
  表格: 5 * 1024 * 1024,   // .xls / .xlsx / .csv —— SheetJS 整份解析，最脆
  其余: 10 * 1024 * 1024,
}
```

**「表格」这个集合不另写一份**：从 `center/views/index.ts` 把 `sheet-view` 那组扩展名（现为内联的 `[".xls", ".xlsx", ".csv"]`）提成一个**导出常量**，注册与闸门**都引它**（`LEARNINGS #002-06`：同一个判断在两处各写一份，将来必然漂移）。⚠️ 该文件有一条「读源码看守动态 import」的测试（`views/index.test.tsx`），提常量不碰它，但改完要跑一遍确认。

**两档的推导**（不是拍脑袋）：服务端瞬时 ≈ 文件 × **2.3**（`readFile` 一份 ＋ base64 字符串一份，base64 = 原文 × 1.33）；客户端 ≈ × **3.3**（JSON 一份 ＋ atob 一份 ＋ `Uint8Array` 一份）。**表格更低**，因为它的「难受点」比 PDF / 图片早得多：SheetJS 是**整份建工作簿模型**（`sheet-view.tsx` 的 `1000 × 64` 只是**铺 DOM** 的上界，不是解析的上界）；PDF 逐页渲染、图片浏览器原生解码。用户 2026-10-12 裁定：**表格 5 MB / 其余 10 MB**。

⚠️ 阈值**只决定弹不弹窗，不决定能不能开** ⇒ 数字定错代价很小（多弹/少弹一次），将来拿真实文件统计再校准。

### 4.4 弹窗

照 `project/file-create-dialog.tsx` 的做法（`useDialog().show()` ＋ `DialogV2` 那套；`workspace-entry.test.tsx:53-64` **已经挂 `DialogProvider`** ⇒ 放在这一层不新增测试前提）。范式依据：`file-delete-dialog.tsx`（2026-10-11 删除确认改弹窗，理由「内联条在真栈上是钉在栏底的整栏宽横幅、与刚点的那一行隔了整棵树」）。

内容极简：

> **这个文件较大**
> 「卷宗扫描件.pdf」有 **87 MB**，直接打开可能要等一会儿。仍然打开吗？
> 　　[ 取消 ]　[ 仍然打开 ]

三个刻意的决定：

1. **写真实数字**（「87 MB」），不写形容词（「很大」）——数字才是民警判断「要不要现在开」的依据；
2. **按钮是「仍然打开」不是「确定」**——它明说「我知道大，但我要开」；
3. **不做「以后别再问我」**——一加这个选项，等于给忘了自己勾过的人留一条「怎么不提醒了」的坑；阈值本身就是「偶尔提醒一次」，不值当。

## 6. 术语

⚠️ **「左右 / 上下」与 `horizontal` / `vertical` 会打架**：业界这两个词有人按隔板方向、有人按排列方向。本设计**代码里一律用中文 `"左右" | "上下"`**（与用户的话一字对上），**只在交给 `ResizeHandle` 时翻译一次**：左右 → `horizontal`、上下 → `vertical`，该处写注释钉住。

| 本设计 | 含义 | `ResizeHandle.direction` |
|---|---|---|
| 左右分屏 | 两栏**并排**，竖隔板，拖宽度 | `"horizontal"` |
| 上下分屏 | 两栏**叠放**，横隔板，拖高度 | `"vertical"` |
