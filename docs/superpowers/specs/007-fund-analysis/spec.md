**Status**: Draft

**Input**: PRD §6 F6 资金分析 + design-v2 §9.6（资金分析落地）+ `2026-09-09-资金分析模块-design.md`

## User Scenarios & Testing

### User Story 1 - 资金项目树与数据加载（Priority: P1）

左栏资金项目树（四 tab：最近 / 全部 / 已归档 / 当前；「当前」tab 展示项目 → 节点 → 账户多级树）。单击节点/账户仅选中（高亮 + 面包屑，不加载）；点击弹出「数据加载面板」，显示该节点数据的时间跨度，选「全部 / 指定时间段」加载明细。

**Why this priority**: 项目树是数据轴的定位入口，选中与加载分离 + 时间段过滤是海量数据「快速定位、精准加载」的前提。

**Independent Test**: 选项目 → 展开节点/账户 → 点节点弹加载面板 → 选时间段加载明细，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 民警进入资金分析，**When** 在左栏四 tab 选一个资金项目，**Then** 切到「当前」tab 展示其项目 → 节点 → 账户树
2. **Given** 民警单击某节点/账户，**When** 选中，**Then** 高亮 + 更新面包屑，但不加载数据
3. **Given** 民警点击某节点，**When** 弹出数据加载面板，**Then** 显示该节点资金数据的时间跨度，默认「全部数据」、可切「指定时间段」
4. **Given** 民警选「指定时间段」加载，**When** 完成，**Then** 中栏切到明细视图，顶部常驻「当前范围」条（节点名 · 时间段 · 账户数 · 流水条数）

---

### User Story 2 - 四个固定数据视图（Priority: P1）

中栏提供四个固定数据视图：明细（含账户对聚合）、聚合统计（对方账户维度 GROUP BY）、关注清单（已框定账户 + 调取状态）、桑基图（账户级资金流向）。关注状态是账户的全局属性，跨视图自动同步。

**Why this priority**: 四视图是民警「看清海量流水」的核心浏览界面，是资金分析的确定性查询/展示骨架。

**Independent Test**: 加载数据后，四个视图可切换查看，关注某账户后跨视图同步，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 已加载某节点明细，**When** 切到明细视图，**Then** 每行交易含持有人（优先展示研判查明的实际持有人）+ 账户对聚合
2. **Given** 切到聚合统计视图，**When** 查看，**Then** 按对方账户维度统计（交易次数/进账/出账/金额合计/最早最晚时间等）
3. **Given** 在聚合统计勾选某账户「关注」，**When** 切到关注清单视图，**Then** 该账户自动出现在关注清单，状态一致
4. **Given** 切到桑基图，**When** 查看，**Then** 展示账户间资金流向（可交互钻取）

---

### User Story 3 - 数据入库闭环（Priority: P1）

上传数据文件 → AI 清洗 → 中栏展示「清洗对比 + 问题清单」→ 民警点「确认入库」→ 数据写入业务库。涉案数据只「转换 + 标记」，不「删除 + 语义判断」，关键判断必须人确认。

**Why this priority**: 数据入库是资金分析的起点，且清洗红线（不删数据、判定留给人）是涉案数据安全的底线。

**Independent Test**: 上传一个流水文件 → 看到清洗对比 → 确认入库 → 数据可查询，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 民警上传流水文件，**When** AI 清洗，**Then** 展示「清洗对比」（逐行清洗前 vs 清洗后）+「问题清单」（需人拍板的异常行）
2. **Given** 清洗产物含疑似重复/字段缺失等异常，**When** 民警查看，**Then** 异常被标记待确认，不自动删除
3. **Given** 民警点「确认入库」，**When** 完成，**Then** 数据写入业务库，可被查询；「判定涉案」「删除数据行」必须人做，AI 不做

---

### User Story 4 - 资金项目权限（微信群模型）（Priority: P1）

资金项目权限遵循微信群模型：谁建谁 owner；owner 与 member 均可邀请（被邀者 role=member）；仅 owner 能撤销；member 可退群、owner 不能退群。这是数据轴的自主拉人授权，不需要管理员逐条配。

**Why this priority**: 数据轴权限决定「谁能看哪些资金数据」，是数据安全的核心；自主拉人授权让一线协作高效。

**Independent Test**: owner 邀请/撤销成员、member 退群，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 民警新建资金项目，**When** 创建，**Then** 自己成为 owner
2. **Given** owner 邀请成员，**When** 提交，**Then** 被邀者 role=member
3. **Given** member 尝试撤销他人，**When** 操作，**Then** 被拒（仅 owner 能撤销）
4. **Given** 被撤销的成员访问项目，**When** 查询，**Then** 项目在列表不出现、数据不可见（权限过滤铁律）

---

### User Story 5 - 右栏 AI 驱动分析（Priority: P1）

右栏「资金分析 skill」承载清洗、持有人研判、关联、资金链、统计、标注、出产物等能力，通过指令卡（上下文指令随选中动态 + 常用操作固定）引导民警用自然语言驱动 AI。

**Why this priority**: AI 驱动是「薄界面 + 厚 skill」范式的核心——界面只浏览+操作，分析能力由 skill 承载。

**Independent Test**: 选中账户点指令卡「关联分析」，AI 填入一句话并执行，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 民警选中若干账户，**When** 点右栏「关联分析」指令卡，**Then** AI 填入对应一句话并执行关联分析
2. **Given** 民警点「生成资金流向图」，**When** AI 执行，**Then** 产出流向图并落沙箱
3. **Given** 民警需要研判持有人，**When** 触发「持有人研判」，**Then** AI 提取线索→查证→给多候选+置信度，民警确认后才建档

---

### User Story 6 - 图谱研判画布与产物落沙箱（Priority: P2）

图谱是项目级研判画布（`.graph` 文件，思路层），落沙箱；可拖入真实账户/手画假设节点、自由增删改。AI 产物（分析记录/报告/图谱/导出图）分门别类落沙箱。事实层（全局实体库 entity/relation）与思路层（沙箱 .graph）分离。

**Why this priority**: 图谱画布是民警理清思路的工具，产物落沙箱是「产物即完成」的交付，但相对数据浏览非首屏必需，故列 P2。

**Independent Test**: 新建图谱画布、拖入账户、保存到沙箱，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 民警新建图谱，**When** 从明细拖入账户节点，**Then** 画布出现该账户节点（带数据轴引用）
2. **Given** 民警手画假设节点，**When** 右键添加，**Then** 出现临时假设节点，自由连线布局
3. **Given** AI 生成分析记录，**When** 完成，**Then** 落沙箱 `分析记录/` 文件夹，中栏自动开 tab 打开

---

### Edge Cases

- 海量流水（高峰日 200 万条）必须快速加载、按时间段精准过滤。
- 单笔资金的「下游拆分」无法精确追踪（资金同质混合），走 AI 辅助推断 + 人确认，不做确定性按钮。
- 原始业务数据一律留在数据轴（PG），永不复制到工作空间 SQLite；落地工作空间的只有「提取后的涉案关系」和「分析产物」。
- 关注状态是账户全局属性，无论哪个视图改了，其他视图读到同一字段。

## Requirements

### Functional Requirements

- **FR-001**: 左栏 MUST 提供资金项目树（四 tab：最近 / 全部 / 已归档 / 当前；「当前」tab 展示项目 → 节点 → 账户多级自关联，≤10 级）。
- **FR-002**: 选中与加载 MUST 分离——单击节点/账户仅选中（高亮 + 面包屑，不加载）；点击弹出「数据加载面板」，显示该节点数据时间跨度，支持「全部 / 指定时间段」加载。
- **FR-003**: 中栏 MUST 提供四个固定数据视图：明细 / 聚合统计 / 关注清单 / 桑基图。
- **FR-004**: 明细视图 MUST 附带账户对聚合（本方账户 ↔ 对方账户的交易次数/金额合计），聚合范围 = 当前加载范围。
- **FR-005**: 关注状态 MUST 是账户全局属性（待调取 / 已调取待导入 / 已导入状态机），跨视图自动同步。
- **FR-006**: 数据入库 MUST 走「上传 → AI 清洗 → 清洗对比 + 问题清单 → 人确认入库」闭环。
- **FR-007**: 涉案数据 MUST 只「转换 + 标记」，不「删除 + 自动语义判断」；删除数据行、判定是否涉案只能人做。
- **FR-008**: 资金项目权限 MUST 遵循微信群模型（谁建谁 owner；owner/member 均可邀请；仅 owner 撤销；member 退群），数据轴自主授权。
- **FR-009**: 右栏 MUST 提供「资金分析 skill」，承载清洗 / 持有人研判 / 关联 / 资金链 / 统计 / 标注 / 出产物，通过指令卡（上下文指令 + 常用操作）引导。
- **FR-010**: 图谱 MUST 为项目级研判画布（`.graph` 思路层，落沙箱），事实层（全局 entity/relation）与之分离。
- **FR-011**: 数据与工作空间 MUST 解耦——原始业务数据留在数据轴（PG），永不落地工作空间；产物落沙箱（工作空间轴）。
- **FR-012**: 流水表 MUST 支持海量规模（高峰日 200 万条）——按月分区 + 批量导入，指定时间段查询秒级。

### Key Entities

- **资金项目（fund_project）**：数据轴一级组织单元 + 归档标记 + 最后访问时间。
- **资金项目成员（fund_project_member）**：数据轴权限（owner/member + 邀请人 + 状态）。
- **节点（fund_node）**：多级自关联（≤10 级），项目 → 节点 → 账户树。
- **账户（fund_account）**：开户信息 + 关注状态（track_status）。
- **交易明细（fund_transaction）**：流水事实（金额/借贷/对方账户/备注）。
- **账户→人映射（account_identity）**：对方账户 → 实际持有人（研判查明）。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 高峰日 200 万条流水，指定时间段明细查询秒级返回（AC-F6-01）。
- **SC-002**: 关注状态跨视图自动同步（AC-F6-02）。
- **SC-003**: 涉案数据只转换 + 标记，删除 / 判定涉案 100% 需人确认。
- **SC-004**: 原始流水永不落地工作空间，产物落沙箱。
