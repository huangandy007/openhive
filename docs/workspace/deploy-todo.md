# 部署侧待办（部署文档的雏形）

**这份文件是什么**：代码侧做不了、**只能在部署环境里关上**的事项总目。每条都注明来源任务、
为什么必须由部署侧做、以及**怎么验**。

**为什么单开一份**：多个任务都有「写进部署文档」的待办（002 的密钥长度、003 的身份门网络策略、
003 的 OS 级磁盘配额），而仓库里**此前没有部署清单**（T007 也记过同一处境：仓库无部署文档，
`0700` 权限位没有落点）。条目散在各 feature 的 `tasks.md` 里迟早会丢——那份 tasks 收尾后就冻结了。
**各任务落地时把条目「移」进来，不要抄**：抄两份就是两个真相，早晚漂（`LEARNINGS #002-06`）。

| # | 来源 | 事项 | 为什么代码侧做不了 | 怎么验 |
|---|---|---|---|---|
| D-01 | 003 T011（D4-3 丙） | **沙箱磁盘的 OS 级强制**：给 `/workspaces`（或其所在卷）配容器卷配额 / 文件系统 quota，使**每个用户的沙箱**有硬上限 | 应用层那半（`DiskQuota`，落在 `FSUtil.writeWithDirs`）只管**经 opencode 工具**的写入；`shell` 工具里 `cat > 大文件`、沙箱内进程自己落盘**都不走这条漏斗**，一律绕得过。本机 win32、`docker: command not found`、无 quota 工具 ⇒ 写得出配置、**测不了效果** | 在目标环境里建一个沙箱，**绕开 opencode 工具**（例如 `shell` 里 `dd` 或 `fallocate` 灌一个大文件）灌到超过上限，**应当被 OS 拒绝**而不是把卷写满。⚠️ 只验「应用层拒绝写入」**不算过**——那半已经由 `packages/core/test/disk-quota.test.ts` 覆盖了 |
| D-02 | 003 T014（**应用层已落地，网络那半待办**） | 内核端口**只对网关可达**（回环绑定 / 网络策略） | 是网络策略，不是代码 | 内核端口从非网关主机不可达；带伪造 `X-User-ID` 直连内核端口应被拒（那一跳没有网关剥头，门看到「头与凭证矛盾」即 401） |
| D-03 | 002（`packages/auth/src/token.ts` 的 `jwtSecret`）→ 执行点 003 T014（**代码侧已落地**） | `AUTH_JWT_SECRET` 的**长度地板 ≥32 字符**（RFC 7518 §3.2）与轮转方式 | 是部署时的密钥管理。① 已在代码侧闭上：T014 的网关在**层构造期**调 `jwtSecret`，缺 / 短于 32 字符抛出去 ⇒ 进程起不来（不是「能登录但登录接口 500」）。② **轮转方式仍是部署纪律**——代码侧没有任何轮转机制，改密钥即全体已签发会话立即失效 | 配上 ≥32 字符的密钥再置 `OPENHIVE_REQUIRE_USER_ID=1`；配一个 <32 字符的，走网关启动路径应当**起不来**。⚠️ **不设开关时不复现**（网关整体不注册、也不调 `jwtSecret`，这是刻意的零回归设计）——验的时候开关与密钥**要一起配** |

| D-04 | 003 T019（**代码侧已落地**） | **引导首个管理员**：首次部署时设 `OPENHIVE_BOOTSTRAP_ADMIN_POLICE_NO=<警号>`，跑通后**撤掉**该变量 | 这个变量只在「`auth.user` 里一个 `is_admin = 1` 的行都没有」时生效，是**一次性**的；长驻在环境里没有意义（逻辑上也无害，但留着会让「谁被引导过」这件事变得看不出来）。而「什么时候撤」是部署流程的节奏，代码管不了 | 配上该变量 + `PG_*` 启动一次 ⇒ 该警号成为管理员，用 `admin@123456` 登录**应被要求改密**；**再启动一次** ⇒ 表里已是 1 个管理员，**不应多出第二个**（判据是表级的）。⚠️ **撤掉变量后再启动，不再有任何迁移被应用**——见 D-05 |
| D-05 | 🆕 003 T019 暴露（**尚无接收方，待裁决**） | **新迁移由谁应用到生产库**：定一条可执行的路径（部署流程里的一个命令 / 一个独立于引导的启动开关） | `packages/auth` 的 `migrate()` 在生产里**唯一**的调用点是 T019 的引导（`gateway.ts` 的 `bootstrap()`），而引导是**一次性**的、跑通就该撤变量 ⇒ **撤掉之后新迁移没人应用**。002 写的是「幂等——部署可无脑重复调」，但仓库里**没有那个「调」**：无 CLI 命令、无脚本 | ⚠️ **本条目前没有落点**——它是 003 `state.md`「阻塞项」第 3 条那笔账的部署侧记法。在那条裁定之前，**不得声称「迁移已闭合」**（`LEARNINGS #002-02`）。⚠️ **T021 不覆盖它**：T021 管 `migrate()` **内部**的事务与并发锁，不管「谁调它」 |
