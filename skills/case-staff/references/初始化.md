# 初始化：在空项目里建案件工作区

本文件是 SKILL.md「入口一」的展开。初始化只发生在**新建 openhive 项目**内，产物是固定的目录树、台账、规则文件与模板，
不预建具体人员目录、单文件与协同台账（FR-005）。

## 触发与入场判断

- 触发话术：「建一个案件工作区」「初始化案件」「把这里建成案件目录」。
- 先读目标项目的 `AGENTS.md`（若存在）；已存在 `案件信息.md` + `AGENTS.md` 说明它已是案件工作区，按幂等补建处理。
- 判断解释器：`command -v python3 || command -v python`。有解释器用 `scripts/init_case.py`；没有就按本文「无脚本步骤」手工落地。
- 初始化只写目标项目目录内；路径一律项目相对、分隔符 `/`，不写项目根以外。

## 预检

初始化前逐项检查，任一失败都**零写入**并说明原因（FR-007）：

1. 目标目录存在且可写。
2. 只接受空目录，或仅含项目基础项：`.git/`、`.gitignore`、`.opencode/`、`opencode.json`。
3. 已是案件工作区（`案件信息.md` + `AGENTS.md` 为标志）时按幂等补建，不覆盖、不重置。
4. 含其他文件且不是案件工作区 → 失败，不半途写入。
5. 目标路径含非法字符或保留字 → 失败。
6. 目标内存在指向项目外的符号链接 → 拒绝写入并报路径越界。
7. `--dry-run` 只输出「将创建 / 将保留」，磁盘零改动。

## 幂等与非覆盖

- 重复运行：已存在文件一律**保留**，记入 `kept_files`，不覆盖、不改内容（FR-006）。
- 二次运行时 `created_directories` 与 `created_files` 为空；已有文件内容哈希不变。
- 缺项补建：只补缺的目录与文件，不动已存在内容的其余部分。
- 结果输出：`created_directories`、`created_files`、`kept_files`、`warnings`；失败时输出 `errors` 并非零退出（FR-009）。
- 不联网、不调用外部服务（FR-011）。

## 只预演

- `--dry-run` 只读盘、不写盘（FR-008）：列出将创建与将保留的目录/文件。
- 预检失败时同样零写入。
- 预演与真实执行的判定逻辑必须一致，区别只在「是否落盘」。

## 无脚本步骤

没有 `python3` / `python` 时，不假装脚本可用，按以下顺序用文件工具落地（FR-091）：

1. **预检**：列出目标目录内容；只允许空目录或 `.git/`、`.gitignore`、`.opencode/`、`opencode.json`；发现其他文件即停。
2. **顶层目录**：先建 7 个顶层目录。
3. **二级目录**：按「目录清单」逐个创建；`法律适用/` 不建分类子目录。
4. **三级目录**：`侦查/收网抓捕/` 下 4 个 + `专案协同/07-抓捕筹备/04-对象资料/`，共 5 个。
5. **台账与规则文件**：从 `assets/*.template.md` 复制到目标路径（**已存在则跳过**，不覆盖；可用 `cp -n` 或先判断存在），逐份核对「文件清单」22 项；`案件信息.md` 按用户提供的案名/案号填写（无编号可留空）；其余模板不改写。
6. **占位文件**：为「文件清单」之外的每个空叶子目录放 `.gitkeep`，共 27 份。
7. **自检**：按「完成自检」逐项核对集合；缺一份就补一份，不报告「已建好」。
