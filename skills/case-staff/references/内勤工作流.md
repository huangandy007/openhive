# 内勤工作流（骨架）

本文件是 SKILL.md「入口二」的展开。本任务是**骨架**：只固定处理顺序与各节职责，
「口述入账」「原始记录整理」两节的详细步骤由后续任务在同一文件内顺序补齐，**不得并行编辑本文件**。

## 入口与固定顺序

每次内勤事务（无论人说「记录今日动态」「归档」「整理原始记录」还是「校验一下」）固定按以下顺序处理：

1. 读项目根 `AGENTS.md`，确认编号、命名与边界。
2. 扫 `材料/00-待归档/`：为新文件分配 M 编号、登记为「待归档」；这是自动档，不需要人确认。
3. 按本次输入性质分流：口述汇报走「口述入账」；会议、碰头、转写稿走「原始记录整理」；
   人说「归档」「把材料放到对应目录」走「归档：材料入来源目录」。
4. 先出「编号 + 一句摘要 + 来源」的入账建议与受影响文档，人确认后才写台账。
5. 收尾按「收尾：校验与看板」执行校验；需要指挥员视图时再生成协同台账。

硬性约束：

- 推断只能记为线索或研判输入，不得写成已证实事实。
- 编号取同前缀当前最大值 +1；写入前重读台账，冲突重取。
- 人未确认前，不改台账、不新建 A/C/T/L/V 文件。

## 口述入账

适用：民警口头/语音汇报一段情况（「记录一下」「刚收到…」「明天让…」）。固定两段：
**先回执，人确认后才入账**。一次会话里先做收件箱扫描（自动档），再把口述拆成 E/L/T。

### 扫收件箱、分 M（自动档，不需要人确认）

1. 列 `材料/00-待归档/` 下的文件（排除 `.gitkeep`），按文件名排序逐份处理。
2. 每份取 M 号：用 `scripts/lib/ids.py` 的 `next_id("M", 登记表全文)`，
   写入前用 `allocate_id("M", 重读)` 再取一次（见下节「编号」）。
3. 在 `材料/00-材料登记表.md` 追加一行，8 列字段按 data-model §3.1：
   - `当前路径` = `材料/00-待归档/<原文件名>`，`状态` = `待归档`；
   - `材料类型` = `待定`（未见内容不猜类别），`上传时间` = 今天；
   - `备注` = `建议：<目标二级目录>`；疑似证据再追加 `；证据候选`。
4. 目标目录只从初始化白名单的二级目录里选；拿不准落 `材料/99-其他`，状态写 `待归类` 并在备注写原因。
   话单与资金材料先记到 `材料/06-话单与资金`，细分到 `资金/话单` 的人名目录在「归档」时确定。
5. 疑似证据的材料**只出「E 草稿」建议**（建议编号 + 一句话证明内容 + 来源 M），
   不因扫描收件箱就写证据索引——E 仍要等人确认。
6. M 登记是唯一「不需要确认」的自动档；文件本身不改名、不移动（移动走平台接口）。
   扫描完把「新登记 M 号 / 建议目录 / 证据候选」一并写进回执。

### 口述拆 E / L / T

先分性质，再填字段。三类落点固定：

| 口述内容 | 落点 | 台账 | 状态初值 |
|---|---|---|---|
| 已发生、能回溯到某份材料的具体事实 | E 草稿 | `证据/证据索引.md` | `草稿` |
| 推断、怀疑、待查方向、下一步核查 | L 线索 | `专案协同/04-线索流转/00-线索台账.md` | `待核查` |
| 谁在何时前完成什么 | T 任务 | `专案协同/03-任务盯办/00-任务台账.md` | `待办` |

- **推断不得写成 E**：没有材料支撑、只是人猜的内容只能进 L 的「线索内容」，
  不得进 E 的「证明内容」「待证事实」；「怀疑」「可能」「应该」开头的句子默认归 L。
- E 的法定种类、待证事实受控类别、证明内容禁写罪名：全按 `references/证据规则.md`。
- 线索与研判的边界、结论不得写罪名：按 `references/研判规则.md`。
- 台账表头与字段：E 见 data-model §3.2（18 列），L 见 §3.6（8 列），T 见 §3.5（8 列）；
  本文件不重复列字段，也不另造列。
- 一条口述可拆成多行：事实→E、由事实引出的推断→L、落实动作→T，各占一行，不合并成一行。
- `来源`：
  - E 的 `来源M` 只填 M 编号；
  - L 的 `来源` 写 `E`/`A` 编号、`日报-YYYY-MM-DD`、会议 `C编号`、`现场` 或 `技术`；
  - T 的 `来源` 写 `口头部署`，或对应的 `C`/`L`/`A` 编号。
- 状态初值只取上表；`已确认`/`已证实` 不在入账时写，由人复核后另行更新。

### 编号：写入前重读

- 一律用 `scripts/lib/ids.py`：`next_id(prefix, 台账全文)` 取同前缀 max+1；
  写入前再用 `allocate_id(prefix, read_text)` **重读**一次，以第二次结果为准（FR-042）。
- 并发写入（另一窗口/另一会话同时入账）时，重读会看到已被占用的号 ⇒ 自动跳过，不撞号。
- **禁止**按页面显示、对话记忆或上次回执手填编号；编号只由台账当前内容推导
  （`references/命名与编号.md`）。已分配号不回收、不复用；跳号允许。

### 确认前不动台账（先出回执）

口述处理完，先给人一份**回执**，此阶段不写任何 E/L/T 台账、不新建 L/T/V 文件
（M 自动登记见上节）。回执上半部分列本次自动登记的 M（编号 / 原文件名 / 建议目录），
下半部分才是待确认的 E/L/T：

| 类型 | 编号（暂定） | 摘要 | 目标台账 |
|---|---|---|---|
| E | E002 | 一句话证明内容 | `证据/证据索引.md` |
| L | L006 | 一句话线索 | `专案协同/04-线索流转/00-线索台账.md` |
| T | T004 | 一句话任务 | `专案协同/03-任务盯办/00-任务台账.md` |

- 回执里的编号是**暂定**；人确认后写入前重新取号（见上节），撞号就换新号再报一次。
- 只写人确认过的部分：只确认 E 就只写 E 行，L/T 留在回执里等下一次确认。
- 人对拆分有异议或未确认时，除已完成的 M 自动登记外不改台账、不建文件；按人的修正重出回执。
- 写入顺序 E → L → T（L 可能引用 E）；每行按对应台账表头逐列写，不留半行。
- 收尾把本次口述按四段（今日工作 / 发现 / 问题 / 明日计划）追加到当天日报
  `专案协同/01-每日动态/YYYY-MM-DD-每日动态.md`；同一天多次汇报追加到同一份，不新建文件
  （FR-041 / FR-051），命名见 `references/命名与编号.md`。日报是视图：只引用编号，不复制台账内容。

## 归档：材料入来源目录

适用：人说「归档」「把材料放到对应目录」。资金流水与话单**必须**落到
`材料/06-话单与资金/{资金,话单}/<人名>/`，不允许在 `06-话单与资金` 根下平铺。

### 先分类：资金还是话单

| 材料 | 分类目录 |
|---|---|
| 银行流水、支付记录、审计报告、涉案资金明细 | `材料/06-话单与资金/资金/` |
| 通话记录、短信记录、基站/漫游清单 | `材料/06-话单与资金/话单/` |
| 两类都有或无法判断 | 留 `材料/99-其他/`，状态 `待归类`，回执问人 |

### 再定人名目录

- **资金**：取流水文件封面/表头的「户名」或「账户名称」；对公账户用单位名称。
  同一人的多个账户、多家银行流水放同一个目录，不按银行或账号再分层。
- **话单**：取机主姓名；只有被查询人姓名时用被查询人姓名，并在回执注明「机主未核实」。
- **一份文件含多人**：落 `多人/`（如 `材料/06-话单与资金/资金/多人/`）。
- **户名或机主确实无法确定**：落 `待确认/`，回执列明需要补正的信息；不猜、不拿手机号/账号当人名。

### 落地步骤（逐份）

1. 重读 `材料/00-材料登记表.md`，确认该文件在 `材料/00-待归档/` 且已有 M 行。
2. 按上两节定 `分类目录` 与人名；拿不准就停在 `99-其他/` 或 `待确认/`，先问人。
3. 建目标目录：`mkdir -p "材料/06-话单与资金/资金/<人名>"`（或 `话单/...`）。
   **只建目录**，不建文件、不复制、不改名。
4. **先确认平台移动工具在位**：工具清单里必须有 `move_material`。没有就**停止归档**，
   报告「当前平台版本没有 move_material，继续归档会让材料记录与文件分家」，
   请人升级或重启平台后重试。**禁止**改用 shell `mv`/`cp` 兜底——文件动了、材料行没动，
   文件树会把已入库的文件显示成「未入队」。
5. 调平台 `move_material` 一份一次，`目标目录` 填第 3 步的目录。
   失败按工具返回原因报告；**禁止**用 shell 移动或复制文件。
   移动成功后平台会自动删除 `材料/00-待归档/` 里被搬空的子目录（含嵌套）：有文件或
   `.gitkeep` 的保留，收件箱本身恒留。回执不必单列；若人问起，按这条说明即可
   （`摘要` 末尾会带「收件箱清掉 N 个空目录」）。
6. **回链复核入库标志**：调 `sync_material_path`，`路径` 填第 5 步的新路径。
   它按文件内容指纹找回材料记录，只改记录路径，不搬文件、不改解析状态、不重解析。按返回：
   - `数据[0].解析状态` 原样写进回执——这就是「是否已入库」的标志；
   - `已变更=true`：平台路径此前没跟上，现已修好；
   - `已变更=false`：路径本来就一致，无需处理；
   - `空原因` 非空：平台没有这份内容的入库记录（从未入队，或不是可解析材料），
     回执写「未入库」；需要入库时请人在文件树右键「解析」。
7. 更新登记表该 M 行：`当前路径` = 新路径，`状态` = `已归档`；备注保留来源信息。
8. 回执写清「M 号 / 分类 / 人名 / 新路径 / 入库状态」，一次多份就逐份列。

### 为什么归档后还要复核「解析状态」

文件树的「已解析」徽标不是按文件名猜的，而是按材料记录的 `path` 精确匹配盘上文件。
平台移动（`move_material` 或文件管理器移动）会同步这条路径，所以归档后标志仍在；
平台外移动（shell、脚本、旧版客户端）只动了文件、没动记录，标志就会消失。

`sync_material_path` 是这种情形的修复入口：按内容指纹把记录改指新路径，解析状态原样保留。
**不要用「重新解析」来找回标志**——那会重跑作业，白费时间；已有材料行也不需要重建。

### 边界

- 已平铺在 `材料/06-话单与资金/` 根下的旧文件不自动批量搬；人要求纠正时逐份移动、逐行改登记表。
- 人名目录只放该人的资金流水或话单；其他材料仍按来源类别归档。
- 人名目录的命名与创建白名单见 `references/命名与编号.md`；校验器只放行
  `材料/06-话单与资金/{资金,话单}/<人名>/` 这一层，再往下建目录会报 `NAME_ILLEGAL`。

## 原始记录整理

适用：会议、碰头、电话通报的转写稿，或民警的手记（`专案协同/00-原始记录/`）。
与「口述入账」的区别：这里**先有原文文件**，整理是给原文分流、落台账，**不改写原文**；
「口述入账」处理的是没有原文的口头汇报。

### 原文只读：正文不改，只在末尾追加

1. 我方手记按 `YYYY-MM-DD-沟通记录-主题.md` 命名（`references/命名与编号.md`）；
   转写稿与外部来件**保留原文件名**，不改名（FR-061 / FR-082）。
2. 整理时只读原文：**不删、不改正文**，不重写、不合并段落、不调整顺序，
   也不把推断补进原文。
3. 整理结果**只在末尾追加**（data-model §6.4）：

   ```text
   已整理：L001 / T001（2026-11-27）
   ```

   - 标记固定以 `已整理：` 开头，编号用 ` / ` 分隔，括号内写整理日期；
   - 只列本次实际落账的 C / T / L / V 编号，没有落账的不写；
     E 草稿在证据索引另行确认，不进原文标记；
   - 本次没有 C / T / L / V 落账时（例如只是把外部来件归档），标记为
     `已整理：（YYYY-MM-DD）`；
   - 括号与日期写法（`（YYYY-MM-DD）`）是本节落地时定的格式，data-model §6.4
     只规定「末尾追加编号 + 时间」，不规定括号写法；
   - 追加段与原正文之间空一行，原文其余部分一字不动。
4. **可读文本一律追加**：手记、转写稿、外部文本文档（`.md` / `.txt` 等）整理后
   都只在末尾追加标记，正文与文件名不改（FR-060 / FR-062）。
   PDF、图片等二进制文件无法追加标记，保持「原始记录缺已整理」的积压提示，
   由人另行处理（如登记为 M 材料后按平台接口移动）；本工作流不自行改名、移动，
   也不伪造标记。

### 分流：新增 C / V，E / L / T 同口述入账

**E / L / T 的分流、状态初值与撰写规则同「口述拆 E / L / T」**，本文件不重复。
本情境额外两类落点：

| 原文内容 | 落点 | 状态初值 | 规则 |
|---|---|---|---|
| 正式会议（有议题、有部署、需留档） | C 会议文件 | — | `references/专案协同规则.md` |
| 核实结果 | V 印证（`00-印证台账.md`） | — | `references/专案协同规则.md` |

- 编号取号、写入前重读、确认前不动台账：同「口述入账」的「编号」「确认前不动台账」两节。
- 台账表头只按 data-model 对应章节，本文件不另造列；不写罪名。

### 幂等：已标记的不重复追加

- 原文已含 `已整理` 标记 ⇒ 视为已整理：**不重复追加标记，也不重复写台账行**。
- 同一份内容重复整理不产生重复台账行（`references/专案协同规则.md`）。
- 确有新增内容时，人确认后按新编号另起一行续写，不覆盖旧标记。
- 收尾按「收尾：校验与看板」跑 `validate_case.py`：整理过的可读文本不再报
  「原始记录缺已整理」；未整理的原文与无法追加的二进制来件仍留在积压提示里。

## 收尾：校验与看板

每次内勤会话结束前：

1. 运行 `scripts/validate_case.py --root <项目根>`；有错误先报告，不擅自改主数据。
2. 需要给指挥员看时运行 `scripts/digest.py`，生成 `专案协同/00-协同台账.md`；该过程只读台账、不写主数据。
3. 向人报告：本次入账了什么、影响了哪些文档、还剩哪些待确认/待决策事项。
4. 未解决项写清「待确认」，不猜、不硬塞进某个台账。
