# 专案协同规则

## 定位

`专案协同/` 是**协同层**，不是又一个材料柜。它管「谁在做什么、定了什么、落实没有、下一步是什么」，
不重复存放材料、证据与文书；引用一律用编号，不复制内容。

## 子目录与产物

| 目录 | 作用 | 关键产物 |
|---|---|---|
| `00-原始记录/` | 未整理的转写稿、手记、外部来件 | 原文保留；整理后末尾标「已整理：C/T/L/V 编号」 |
| `01-每日动态/` | 每天各岗位的汇报 | `YYYY-MM-DD-每日动态.md` |
| `02-专案会议/` | 会议纪要、议定事项、部署 | `C001-日期-主题.md` |
| `03-任务盯办/` | 任务编号、责任人、期限、状态、反馈 | `00-任务台账.md` + 按需 `T001-任务简称.md` |
| `04-线索流转/` | 线索发现、来源、核查、确认/排除、转研判 | `00-线索台账.md` + 按需 `L001-线索简称.md` |
| `05-印证核实/` | 研判线索落地结果 | `00-印证台账.md` + 按需 `V001-对象-核实.md` |
| `06-人员与组织/` | P/O 主数据 | `00-人员台账.md` + `01-组织架构.md` |
| `07-抓捕筹备/` | 对象清单、方案、编组、资料发放、对象资料 | `00-抓捕对象清单.md` 等 |

- 台账文件初始化时创建；T/L/V 单文件按需生成，不预建空文件。
- L 线索文件统一放 `04-线索流转/`，研判区只引用编号。
- `00-协同台账.md` 由 `digest.py` 首次运行生成，不手改、不预建。

## 闭环

```text
发现 ──▶ 汇聚 ──▶ 研判 ──▶ 部署 ──▶ 落地 ──▶ 印证 ──▶ 确认
 │         │         │         │         │         │         │
日报/会议   线索台账    A 研判   会议决定   落地记录    V 印证    主数据更新
现场/技术   T 任务     L 线索    T 任务     E/M 回填   证实/证伪   P/O/E/F
```

关键规则：

- 每个「新线索」必须有 L 编号；每个「部署」必须有 T 编号；每个「落地核实」必须有 V 记录；每次「确认」必须回写主数据。
- 日常性工作只进日报/任务，不强行编号。
- 没有回写的，不算闭环。
- 低风险、可回溯的自动入账；高风险、不可逆的找人确认。
- 同一信息只落一处，其余引用编号；不重复存正文。

## 每日动态与会议

- 每日动态与会议纪要统一**半结构化四段**：今日工作 / 发现 / 问题 / 明日计划；缺项只提示，不拒绝录入。
- 会议纪要多一节「议定事项与责任人」。
- 同一天多次汇报追加到同一份日报，不按每件事新建文件。
- 不足「正式会议」（有议题、有部署、需留档）的碰头，不建 C 文件，只更新日报与台账。
- 每日动态文件名 `YYYY-MM-DD-每日动态.md`；会议文件名 `C001-YYYY-MM-DD-主题.md`。

## 任务台账

8 列固定：

```markdown
| T编号 | 任务 | 责任人 | 期限 | 状态 | 来源 | 反馈 | 备注 |
```

- 状态：`待办` / `进行中` / `已完成` / `已取消`；`逾期` 是派生（期限 < 今日且未完成），不写入状态列。
- 期限：`YYYY-MM-DD` 或 `当日` / `持续`；后者不参与逾期判定。
- 来源：写会议 C 编号、线索 L 编号、研判 A 编号或「口头部署」。
- 跨天、多步骤、要附件才建 T 单文件；否则一行台账足够。
- 案后处理清单事项必须进任务台账，带责任人与期限。

## 线索台账

8 列固定：

```markdown
| L编号 | 发现日期 | 线索内容 | 来源 | 状态 | 下一步 | 转研判A | 备注 |
```

- 状态：`待核查` / `核查中` / `已证实` / `已排除` / `转研判`。
- 来源：`A` / `E` / `日报` / `会议` / `现场` / `技术` + 编号；不得留空。
- 每条 L 必须有来源、状态、下一步；转研判后回填 A 编号。
- 推断只能写进线索内容，不得写成已证实事实。
- 需长期跟踪才建 L 单文件；否则台账一行足够。

## 印证台账

8 列固定：

```markdown
| V编号 | 日期 | 对应L | 核实内容 | 结果 | 依据E | 回写 | 备注 |
```

- 结果：`证实` / `证伪` / `部分证实`。
- 对应 L 必须存在；依据 E 必须存在。
- 回写列记 `A00x` / `E00x` / `P00x`；没有回写的核实不算闭环。
- V 不能替代 E；证实结论要落到证据或事实记录。

## 人员与组织

人员台账 8 列：

```markdown
| P编号 | 姓名 | 身份 | 角色/层级 | 单位 | 状态 | 关联L/E | 备注 |
```

组织架构 6 列：

```markdown
| O编号 | 名称 | 类型 | 上级O | 涉及人员P | 备注 |
```

- P 状态：`在逃` / `已到案` / `已处理` / `待定`。
- 角色/层级由办案人/法制确认，AI 只引用已确认内容，不自行认定。
- 只给需要跨文档引用的人/组织编号；普通证人、被害人、办案民警写姓名。
- 人员目录 `P001-姓名/` 在该人第一次出现时创建；初始化不预建具体人。
- 同一人在人员台账与抓捕对象清单中的姓名/角色冲突由校验器报 `X_CONFLICT`。

## 抓捕筹备

抓捕对象清单 12 列固定（主表不加列）：

```markdown
| 序号 | P编号 | 抓捕对象 | 角色/层级 | 涉嫌罪名 | 主要证据 | 抓捕单位 | 抓捕人 | 情报支撑 | 技术支撑 | 法制支撑 | 风险 |
```

- 「主要证据」填 E 编号；「涉嫌罪名」「角色/层级」由办案人/法制确认，AI 只引用。
- 时间、地点、编组、通信、车辆、押解、看管放《抓捕方案》与《编组与保障》，不进主表。
- 从主表派生：按抓捕单位分组的任务单、一人一页对象资料（`04-对象资料/P001-姓名.md`）、按支撑角色分组的保障清单、资料发放清单、收网会议纪要。
- 发放版命名 `YYYY-MM-DD-名称-发放版.md`，是只读快照；会后变更写 `变更日志.md`，不改发放版。

## 原始记录

- `00-原始记录/` 只存**未整理原文**：转写稿、手记、别人发来的文档。
- 手记按 `YYYY-MM-DD-沟通记录-主题.md` 命名；转写稿与外部文档保留原文件名。
- 原始记录**只读**：AI 不删、不改正文；整理完成后在末尾追加一行「已整理：C003 / T012 / L008」，并写整理时间。
- 整理产物按性质分流：

| 信息性质 | 落到哪 |
|---|---|
| 正式会议（有议题、有部署、需留档） | `02-专案会议/C001-日期-主题.md` |
| 当天的一般情况 | `01-每日动态/YYYY-MM-DD-每日动态.md` |
| 明确部署的事 | 任务台账 T（必要时加 T 文件） |
| 新发现、待核实 | 线索台账 L（必要时加 L 文件） |
| 核实结果 | 印证台账 V |
| 人员/角色变化 | 人员台账 P、组织架构 O |

- 同一信息只落一处，其余引用编号；区分不了就先标「待归类」，人确认后再落账。
- 与 `侦查/沟通对接/` 的分工：那里放**对外**往来材料（协作函、跨区请求、回复）；内部碰头与电话通报的原始记录放这里。
- 同一份内容重复整理不产生重复台账行；原文的「已整理」标记可续写。
