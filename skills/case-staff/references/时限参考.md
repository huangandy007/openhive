# 时限参考

## 边界说明

- 本文件**不写死任何法定期限、不内置法条**；具体期限由办案人按当地现行规定填写，或从 `法律适用/` 引用的依据中取值。
- 本项目只做两件事：记录「哪个程序节点、谁负责、期限字段填了什么」，以及在逾期时提醒。
- 不复制法条、不给出「必须几日内完成」的结论；拿不准的写「待办案人确认」。

## 程序性节点

以下是做提醒锚点用的**程序节点名称**，不含期限数值；实际用不用、叫什么，以办案人确认的流程为准：

| 节点 | 提醒时点（相对节点） | 需要留痕的产物 |
|---|---|---|
| 到案 / 人身检查 / 体检 | 到案时 | 到案经过、检查记录（入 `材料/02-调取与扣押/`） |
| 第一次讯问 | 到案后首次 | 讯问笔录、同步录音录像（入 `材料/07-讯问询问/`） |
| 拘留 | 作出拘留决定前后 | 拘留文书（D 登记，法制审核人/时间） |
| 送押 / 家属通知 | 拘留后 | 送押记录、通知书（D 登记） |
| 报捕 | 呈报前 | 报捕文书草稿、法制审核记录 |
| 批准 / 不批准逮捕 | 收到结果后 | 相关文书（D 登记），阶段看板更新 |
| 侦查羁押期间 | 羁押期内 | 阶段看板「法定期限或节点」、任务台账 |
| 移送起诉 | 移送前 | 移送前自检清单、起诉类文书（D 登记） |
| 补充侦查 | 收到补充侦查要求后 | 补充侦查任务（T）、新增证据（E） |
| 涉案财物处置 | 扣押、移交、返还时 | 扣押/移交清单（`材料/02-调取与扣押/`） |
| 在逃人员处置 | 发现与变更时 | 人员台账 P、线索台账 L、任务台账 T |

节点名称与先后顺序由办案人确认；本表不是程序法依据。

## 期限字段

期限只写在三个位置，格式受控：

1. **任务台账 T** 的「期限」列：`YYYY-MM-DD`，或 `当日`、`持续`。
2. **阶段看板** 的「法定期限或节点」列：日期或节点名称；不写「尽快」「抓紧」这类无判据词。
3. **案后处理清单** 的「期限」列：`当日`、`法定时限`、`持续`、`YYYY-MM-DD`。

填写规则：

- 具体日期由办案人按当地规定填写；AI 不自行换算「几天后」。
- 不确定的写「待办案人确认」，并在会话里列出待确认项，不猜日期。
- `持续` 与节点名称不参与逾期判定。

## 逾期判定

- 仅对任务台账判定：状态为 `待办` 或 `进行中`，且「期限」是 `YYYY-MM-DD` 且早于当天 ⇒ `T_OVERDUE`（警告）。
- `当日`、`持续`、空值、非日期文本不参与逾期判定。
- `逾期` 是**派生**状态，不写回状态列；状态列仍只取 `待办` / `进行中` / `已完成` / `已取消`。
- 逾期不改写文书、不改阶段状态；只在校验与看板中提示。

## 提醒机制

- 会话内提醒：每次内勤收尾跑 `scripts/validate_case.py`，输出逾期与阻塞项。
- 指挥员视图：需要时跑 `scripts/digest.py`，在「待办与逾期任务」「风险」段列出。
- 本技能不常驻、不主动推送、不打电话催办；把提醒发到群里仍由人做（v2 平台能力，不在本期）。
- 提醒只陈述「哪个编号、谁的、期限已过」，不替代人做决定。
